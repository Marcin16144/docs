Producenci routerow i switchy

Cisco

Standard enterprise od dekad. System operacyjny IOS / IOS XE / IOS XR / NX-OS / FXOS w zaleznosci od linii. Najwiecej certyfikacji (CCNA, CCNP, CCIE), bogata dokumentacja. Drogie, ale niezawodne.

  • Catalyst (switche enterprise)
  • Nexus (data center)
  • ASR (access service routers, ISP)
  • Meraki (cloud-managed, kupione w 2012)

MikroTik

Polski/lotewski (Ryga) producent z RouterOS - bardzo zaawansowany, tani. Popularny w Europie Wschodniej, Azji, Ameryce Lacinskiej. Krzywa nauki bardziej stroma niz Cisco, ale za to ogromne mozliwosci za niska cene.

  • hEX - male SOHO routery (~300 PLN)
  • RB5009 - srednia klasa
  • CCR2004/CCR2216 - cloud core router
  • CRS - cloud router switche

Ubiquiti UniFi

Nowoczesne, dobrze wygladajace UI. Cala ekosystema (gateway, switche, AP, kamery, telefony) zarzadzana z jednego kontrolera UniFi. Popularne w SMB i prosumer market.

  • UniFi Dream Machine (UDM-Pro / UDM SE)
  • UniFi Switch (USW)
  • UniFi AP (U6, U7 series)
  • EdgeRouter / EdgeMAX (linia stara)

Juniper Networks

Carrier-grade, JunOS oparty na FreeBSD. Mocne w sieciach ISP i duzych enterprise. Kupione przez HPE w 2025.

Inni

  • TP-Link Omada - tansza alternatywa dla UniFi
  • Aruba (HPE) - enterprise switche i AP
  • Fortinet FortiGate - firewall + router + UTM
  • Huawei - mocne w Azji i Afryce

Open source / soft routery

pfSense

Bazuje na FreeBSD, popularny od 2004. Stabilny, dobrze udokumentowany. Netgate (firma za pfSense) ma wlasny hardware i licencjonuje pfSense+ z dodatkowymi funkcjami.

OPNsense

Fork pfSense z 2015. Bardziej nowoczesne UI (MVC framework, JSON API), szybsze cykle wydawnicze. W 2026 popularnosc OPNsense jest porownywalna lub wyzsza od pfSense w swiecie self-hosted.

VyOS

Open source enterprise routing OS, bazuje na Debianie. Konfiguracja przez CLI w stylu Junos. Doskonaly do BGP, OSPF, MPLS, IPsec w wirtualizacji.

OpenWrt

Linux dla konsumenckich routerow. Pozwala odzyskac stary sprzet i dodac mu nowe funkcje. Wspiera setki modeli TP-Link, Asus, Netgear, GL.iNet itp.

# OpenWrt - przykladowe komendy:
opkg update
opkg install nano htop tcpdump

# Konfiguracja sieci - /etc/config/network
config interface 'lan'
    option type 'bridge'
    option proto 'static'
    option ipaddr '192.168.1.1'
    option netmask '255.255.255.0'

# Restart sieci:
service network restart

Managed vs unmanaged switches

  • Unmanaged - plug & play, brak konfiguracji. Tanie (od 50 PLN za 5 portow). OK do prostych setupow domowych.
  • Smart / Web-managed - podstawowe zarzadzanie przez przegladarke (VLAN, port security, basic QoS). Cena srednia.
  • Fully managed - pelne CLI, SNMP, RADIUS auth, port mirroring, QoS, STP, LACP. Drozsze, dla profesjonalistow.

VLAN - Virtual LAN

VLAN dzieli fizyczny switch na logiczne segmenty. Hosty w roznych VLAN-ach nie widza sie bezposrednio (bez routera). Standard 802.1Q dodaje 4-bajtowy tag z VLAN ID (1-4094) do ramki.

PojecieOpis
Access portPort nalezacy do jednej VLAN, ramki bez tagu (untagged)
Trunk portPort przenoszacy wiele VLAN-ow, ramki tagowane (z wyjatkiem native VLAN)
Native VLANDomyslna VLAN trunka, ramki nieoznakowane. Z definicji 1, ale powinno sie zmienic ze wzgledow security
Voice VLANDedykowana dla telefonow VoIP, automatyczne wykrywanie po LLDP-MED/CDP
Default VLANVLAN 1 - nigdy nie usuwac, ale unikac uzycia produkcyjnego

Cisco - konfiguracja VLAN

! Tworzenie VLAN:
Switch(config)# vlan 10
Switch(config-vlan)# name PRACOWNICY
Switch(config-vlan)# exit

Switch(config)# vlan 20
Switch(config-vlan)# name GOSCIE
Switch(config-vlan)# exit

! Access port:
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10

! Voice VLAN (telefon + komputer na jednym kablu):
Switch(config-if)# switchport voice vlan 30

! Trunk port (do innego switcha lub routera):
Switch(config)# interface GigabitEthernet0/24
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,20,30
Switch(config-if)# switchport trunk native vlan 999

! Sprawdzenie:
Switch# show vlan brief
Switch# show interfaces trunk

MikroTik - konfiguracja VLAN

# Bridge z VLAN filtering:
/interface bridge add name=bridge1 vlan-filtering=yes

# Dodanie portow:
/interface bridge port add bridge=bridge1 interface=ether2 pvid=10
/interface bridge port add bridge=bridge1 interface=ether3 pvid=20
/interface bridge port add bridge=bridge1 interface=ether24

# VLAN ID per port:
/interface bridge vlan add bridge=bridge1 vlan-ids=10 \
  tagged=bridge1,ether24 untagged=ether2
/interface bridge vlan add bridge=bridge1 vlan-ids=20 \
  tagged=bridge1,ether24 untagged=ether3

# IP na VLAN interface:
/interface vlan add name=vlan10 vlan-id=10 interface=bridge1
/ip address add address=192.168.10.1/24 interface=vlan10

STP - Spanning Tree Protocol

STP (IEEE 802.1D) zapobiega petlom warstwy 2 w przelacznikach. Jesli sa redundantne polaczenia, STP wybiera root bridge i blokuje porty tworzace petle. Bez STP broadcast storm wylaczy siec.

WersjaStandardKonwergencja
Classic STP802.1D (1990)30-50 sekund
RSTP (Rapid)802.1w (2001)1-3 sekundy
MSTP (Multiple)802.1s (2002)Per VLAN groups
PVST+ / Rapid PVST+CiscoPer VLAN STP
# Cisco - sprawdzenie STP:
Switch# show spanning-tree
Switch# show spanning-tree vlan 10

! Konfiguracja root bridge:
Switch(config)# spanning-tree vlan 10 priority 4096

! BPDU Guard (zabezpieczenie portow access):
Switch(config-if)# spanning-tree bpduguard enable

! PortFast (skip listening/learning na access):
Switch(config-if)# spanning-tree portfast

LACP - Link Aggregation Control Protocol

LACP (IEEE 802.3ad / 802.1AX) pozwala laczyc wiele kabli w jeden logiczny - sumowanie bandwidth + redundancja. Czesto nazywane EtherChannel (Cisco), bonding (Linux), LAG.

# Cisco EtherChannel z LACP:
Switch(config)# interface range gi0/1 - 2
Switch(config-if-range)# channel-group 1 mode active
Switch(config-if-range)# exit

Switch(config)# interface port-channel 1
Switch(config-if)# switchport mode trunk

# Linux bonding (mode 4 = LACP 802.3ad):
modprobe bonding mode=4 miimon=100
ip link add bond0 type bond mode 802.3ad
ip link set eth0 master bond0
ip link set eth1 master bond0
ip link set bond0 up

# MikroTik bonding:
/interface bonding add name=bond1 mode=802.3ad slaves=ether1,ether2

PoE - Power over Ethernet

PoE pozwala zasilac urzadzenia (telefony VoIP, AP, kamery IP) tym samym kablem co dane. Bardzo praktyczne - jeden kabel do AP zamiast kabla zasilajacego + ethernetowego.

StandardNazwaMocTyp
802.3af (2003)PoE15.4 W (12.95 W na urzadzeniu)Type 1
802.3at (2009)PoE+30 W (25.5 W)Type 2
802.3bt (2018) Type 3PoE++60 W (51 W)4-pair
802.3bt (2018) Type 4Hi-PoE / 4PPoE90-100 W (71.3 W)4-pair

SDN - Software-Defined Networking

SDN oddziela control plane (decyzje routingu) od data plane (forwarding). Centralnym kontrolerem mozna dynamicznie reprogramowac switche / routery przez API (np. OpenFlow, P4).

  • OpenFlow - klasyczny SDN protocol
  • P4 - jezyk programowania data plane
  • Cisco ACI - SDN dla data center
  • VMware NSX - SDN w wirtualizacji
  • ONOS, OpenDaylight - open source kontrolery

# Backup:

QoS - Quality of Service

QoS zapewnia priorytetyzacje krytycznego ruchu (VoIP, video) nad mniej istotnym (downloads, P2P).

  • DSCP (Differentiated Services Code Point) - 6-bitowe pole w naglowku IP, rozne klasy (EF, AF11-43, CS0-7)
  • Classification - rozpoznawanie typu ruchu (porty, DPI, DSCP)
  • Marking - oznaczanie pakietow DSCP/CoS
  • Queuing - PQ (Priority Queue), WFQ, CBWFQ, LLQ
  • Shaping vs policing - ksztaltowanie (buforowanie) vs odrzucanie nadmiaru
Praktyczna rada - dla domu/SOHO wystarczy MikroTik hEX (~400 PLN) lub UniFi Dream Router (~700 PLN). Dla srednich firm UniFi UDM-Pro lub MikroTik RB5009. Dla enterprise Cisco Catalyst 9000 series + Meraki dla cloud management.
