VPN i tunelowanie

WireGuard, OpenVPN, IPsec, Tailscale, ZeroTier - kompletny przewodnik po VPN 2026

Co to jest VPN

VPN (Virtual Private Network) tworzy szyfrowany tunel przez publiczna siec (internet) miedzy dwoma lub wiecej punktami. Sluzy do bezpiecznego dostepu zdalnego, laczenia oddzialow firmy, prywatnosci i obejscia ograniczen geograficznych.

Glowne zastosowania

  • Remote access VPN - pracownik laczy sie z siecia firmy z domu
  • Site-to-site VPN - laczenie biur w jedna logiczna siec
  • Privacy / anonimizacja - ukrycie IP, ochrona w niezaufanym WiFi
  • Geo-bypass - dostep do tresci niedostepnych w naszym regionie
  • Bezpieczne polaczenie do cloud - AWS, Azure, GCP via VPN

Protokoly VPN

WireGuard - standard 2026

WireGuard (RFC nieoficjalny, kernel od Linux 5.6) jest nowoczesny, szybki i prosty - tylko 4000 linii kodu w kernelu. Stworzony przez Jasona Donenfelda, oparty na Noise protocol framework.

  • Cryptographic primitives: ChaCha20-Poly1305, Curve25519, BLAKE2s
  • UDP only - efektywniejszy niz TCP-over-TCP
  • Cross-platform - kernel Linux, klienci na Windows, macOS, iOS, Android
  • Konfiguracja w 10-20 liniach
  • Przepustowosc na nowoczesnym hardware: 5-10+ Gbps

OpenVPN - klasyk

Bardzo dojrzaly (od 2001), elastyczny. Dziala na TCP lub UDP. Uzywa SSL/TLS dla key exchange, OpenSSL dla kryptografii. Wolniejszy od WireGuard, ale bardziej elastyczny i lepiej przedostaje sie przez firewally (TCP 443).

IPsec - enterprise

IPsec (RFC 4301) to suite protokolow Layer 3. Standard w sprzecie enterprise (Cisco ASA, FortiGate, Juniper). Konfiguracja moze byc skomplikowana.

  • IKE (Internet Key Exchange) - faza 1, ustanawia bezpieczny kanal kontrolny
  • ESP (Encapsulating Security Payload) - szyfruje i chroni dane
  • AH (Authentication Header) - tylko integralnosc (nie szyfruje, rzadziej uzywane)
  • IKEv2 - nowsza wersja, mobile-friendly (MOBIKE)

L2TP/IPsec - legacy

L2TP sam nie szyfruje, dlatego polaczony z IPsec. Wbudowany w Windows, macOS. Powolny ze wzgledu na podwojna enkapsulacje, dzis raczej zastapowany przez IKEv2.

SSTP - Microsoft

SSTP (Secure Socket Tunneling Protocol) uzywa TCP 443, latwo przechodzi przez firewall. Wbudowany w Windows. Mniej popularny poza ekosystemem MS.

PPTP - DEPRECATED

Stary, niebezpieczny (zlamany 1998, MS-CHAPv2 cracking). NIE UZYWAC.

Site-to-site vs Remote access

Site-to-site VPN

Dwie sieci (np. biuro Warszawa i biuro Krakow) polaczone tunelem. Routery na obu koncach utrzymuja stale polaczenie. Pracownik nie musi nic konfigurowac - traffic do drugiego biura idzie automatycznie.

# Topologia:
[LAN Warszawa]---[Router/FW WAW]===VPN===[Router/FW KRK]---[LAN Krakow]
192.168.1.0/24                                              192.168.2.0/24

Remote access VPN

Pojedynczy uzytkownik laczy sie z siecia firmy z laptopem/telefonem. Klient uruchamia aplikacje VPN, ktora tworzy tunel do koncentratora.

Split tunneling

Tylko czesc ruchu idzie przez VPN (np. tylko sieci firmy 10.0.0.0/8), reszta przez normalne lacze. Lepsze dla wydajnosci, gorsze dla prywatnosci.

Self-hosted VPN

WireGuard server

# Instalacja na Ubuntu/Debian:
sudo apt install wireguard

# Generacja kluczy serwera:
wg genkey | tee server.key | wg pubkey > server.pub

# Plik konfiguracji /etc/wireguard/wg0.conf:
[Interface]
Address = 10.10.0.1/24
ListenPort = 51820
PrivateKey = SERVER_PRIVATE_KEY
PostUp = iptables -A FORWARD -i %i -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i %i -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

[Peer]
PublicKey = CLIENT_PUBLIC_KEY
AllowedIPs = 10.10.0.2/32

# IP forwarding:
echo "net.ipv4.ip_forward=1" >> /etc/sysctl.conf
sysctl -p

# Start:
sudo systemctl enable --now wg-quick@wg0

# Status:
sudo wg show

# Klient WireGuard config (wg-client.conf):
[Interface]
Address = 10.10.0.2/24
PrivateKey = CLIENT_PRIVATE_KEY
DNS = 1.1.1.1

[Peer]
PublicKey = SERVER_PUBLIC_KEY
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0       # cala siec przez VPN (full tunnel)
# AllowedIPs = 10.10.0.0/24, 192.168.1.0/24    # split tunnel
PersistentKeepalive = 25

WireGuard - generacja konfiguracji szybciej

# Bash one-liner do generacji par kluczy:
PRIV=$(wg genkey)
PUB=$(echo $PRIV | wg pubkey)
echo "Private: $PRIV"
echo "Public:  $PUB"

# Pre-shared key (dodatkowe zabezpieczenie):
PSK=$(wg genpsk)

# QR code dla telefonu (na serwerze):
sudo apt install qrencode
qrencode -t ansiutf8 < client.conf

OpenVPN server

# Latwa instalacja przez angristan/openvpn-install:
curl -O https://raw.githubusercontent.com/angristan/openvpn-install/master/openvpn-install.sh
chmod +x openvpn-install.sh
sudo ./openvpn-install.sh

# Wybierz: UDP, port 1194, AES-256-GCM, ECDSA cert, prime256v1
# Generuje plik klienta .ovpn z wszystkimi cert i kluczami

# Klient:
openvpn --config client.ovpn

# Manualna konfiguracja /etc/openvpn/server/server.conf:
port 1194
proto udp
dev tun
ca ca.crt
cert server.crt
key server.key
dh dh2048.pem
server 10.8.0.0 255.255.255.0
push "redirect-gateway def1 bypass-dhcp"
push "dhcp-option DNS 1.1.1.1"
keepalive 10 120
cipher AES-256-GCM
auth SHA256
user nobody
group nogroup
persist-key
persist-tun

Outline / Shadowsocks

Outline (przez Jigsaw, dawniej Google) tworzy serwery Shadowsocks - protokol stworzony do obejscia Chinskiego firewalla. Maskuje sie jako zwykly ruch HTTPS.

Mesh / overlay VPN - 2026 trend

Tradycyjny VPN = hub-and-spoke (wszyscy klienci przez serwer centralny). Mesh VPN tworzy bezposrednie polaczenia P2P miedzy wszystkimi nodami.

Tailscale

Najpopularniejsze rozwiazanie 2026 - WireGuard pod spodem + automatyczna wymiana kluczy + NAT traversal + zero-config. Free dla 100 urzadzen.

# Instalacja Linux:
curl -fsSL https://tailscale.com/install.sh | sh

# Login:
sudo tailscale up

# Status:
tailscale status

# Subnet routing (siec 192.168.1.0/24 dostepna przez node):
sudo tailscale up --advertise-routes=192.168.1.0/24

# Exit node (caly traffic przez ten node):
sudo tailscale up --advertise-exit-node

# SSH przez Tailscale:
sudo tailscale up --ssh
ssh user@nazwa-w-tailnet

Headscale

Self-hosted alternatywa dla Tailscale control plane. Zero-trust networking bez wynajmowania trzeciej strony.

ZeroTier

Cross-platform mesh VPN. Dzialal przed Tailscale (od 2014). UDP-based, free dla 25 nodow.

Nebula

Stworzony przez Slack. Bardzo szybki, certyfikatowo-bazowy. Wymaga wiecej konfiguracji niz Tailscale, ale fully self-hosted.

Netbird, Twingate, Cloudflare Access

Komercyjne alternatywy do Tailscale, kazda z wlasnym pomyslem na zero-trust.

IPsec basics - faza 1 i 2

# Faza 1 (IKE) - ustanawia ISAKMP SA:
- Authentication (PSK lub certyfikaty)
- Encryption: AES-256
- Hash: SHA-256, SHA-384
- DH group: 14, 15, 19, 20, 21
- Lifetime: 28800 sekund (8 godzin)

# Faza 2 (IPsec) - ustanawia IPsec SA:
- ESP encryption: AES-256-GCM
- ESP authentication (jesli AES-CBC): SHA-256
- PFS group: 14+
- Lifetime: 3600 sekund (1 godzina)

# strongSwan (Linux IPsec) - przyklad /etc/swanctl/conf.d/site.conf:
connections {
    site-to-site {
        version = 2
        local_addrs = 1.2.3.4
        remote_addrs = 5.6.7.8
        proposals = aes256-sha256-modp2048
        local {
            auth = psk
            id = 1.2.3.4
        }
        remote {
            auth = psk
            id = 5.6.7.8
        }
        children {
            net {
                local_ts = 192.168.1.0/24
                remote_ts = 192.168.2.0/24
                esp_proposals = aes256gcm16-modp2048
                start_action = trap
            }
        }
    }
}

NAT-T - NAT Traversal

IPsec ESP nie ma portow - NAT nie wie co z nim zrobic. NAT-T (RFC 3947) pakuje ESP w UDP 4500, dzieki czemu przechodzi przez NAT.

DNS leak, kill switch, multi-hop

DNS leak

Niewlasciwie skonfigurowany VPN moze wysylac DNS zapytania przez normalny interface (nie przez tunel) - to "DNS leak". Pomimo zaszyfrowanego ruchu, ISP widzi co odwiedzasz. Test: dnsleaktest.com

Kill switch

Mechanizm odcinajacy caly internet jesli VPN sie rozlaczy. Iptables rules: tylko interfejs VPN moze wysylac, reszta DROP.

# Kill switch z iptables (gdy uzywasz wg0):
iptables -A OUTPUT -o lo -j ACCEPT
iptables -A OUTPUT -o wg0 -j ACCEPT
iptables -A OUTPUT -d VPN_SERVER_IP -p udp --dport 51820 -j ACCEPT
iptables -A OUTPUT -m addrtype --dst-type LOCAL -j ACCEPT
iptables -A OUTPUT -j DROP

Multi-hop VPN

Lancuch 2+ serwerow VPN. Pierwszy widzi tylko twoje IP, ostatni widzi cel ruchu. Trade-off: wieksza prywatnosc, mniejsza predkosc.

Rekomendacja 2026: dla pracy zdalnej - Tailscale (free, automatyczne, mesh). Dla prywatnosci - Mullvad WireGuard. Dla self-hosted serwera VPS - WireGuard (server kosztuje $5/mc na DigitalOcean/Vultr/Hetzner).
