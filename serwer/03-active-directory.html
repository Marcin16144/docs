Active Directory Domain Services

Centralny katalog tozsamosci, uwierzytelniania i autoryzacji w srodowisku Windows.

Architektura AD - struktura logiczna

AD opiera sie na hierarchii: las (forest) zawiera domeny, domeny zawieraja jednostki organizacyjne (OU), a OU zawieraja obiekty (uzytkownicy, komputery, grupy). Repliki wezlow nazywane sa kontrolerami domeny (Domain Controllers, DC).

ElementOpisPrzyklad
ForestNajwyzsza granica bezpieczenstwa, wspolny schemat i Global Catalogcontoso.local
DomainGranica administracyjna i replikacji, zbior obiektoweurope.contoso.local
OU (Organizational Unit)Kontener do delegacji uprawnien i przypiecia GPOOU=Sales,OU=Users
SiteReprezentacja fizycznej lokalizacji (subnet), kontroluje replikacjeWarszawa, Krakow
Domain ControllerSerwer trzymajacy kopie bazy NTDS.ditDC01.contoso.local

Promocja serwera do Domain Controller

Proces tworzenia pierwszego DC w nowym lesie wymaga instalacji roli AD DS i wywolania Install-ADDSForest. Serwer staje sie DC + serwerem DNS dla domeny.

# 1. Instalacja roli AD DS + narzedzi
Install-WindowsFeature -Name AD-Domain-Services `
                       -IncludeManagementTools

# 2. Promocja na pierwszy DC nowego lasu
$pwd = ConvertTo-SecureString "P@ssw0rd-DSRM!" -AsPlainText -Force
Install-ADDSForest `
    -DomainName "contoso.local" `
    -DomainNetbiosName "CONTOSO" `
    -ForestMode "WinThreshold" `
    -DomainMode "WinThreshold" `
    -InstallDns:$true `
    -DatabasePath  "C:\Windows\NTDS" `
    -SysvolPath    "C:\Windows\SYSVOL" `
    -LogPath       "C:\Windows\NTDS" `
    -SafeModeAdministratorPassword $pwd `
    -Force:$true

# Po restarcie weryfikacja stanu
Get-ADDomain
Get-ADForest
dcdiag /v

DSRM password: Haslo Directory Services Restore Mode jest niezbedne do bootu w trybie ratunkowym. Trzymac w sejfie - bez niego odtworzenie z backupu bazy NTDS jest niemozliwe.

DNS - krytyczna zaleznosc

Active Directory wymaga DNS - klienci szukaja kontrolerow domeny przez rekordy SRV (_ldap._tcp.dc._msdcs.contoso.local). Bez dzialajacego DNS klienci nie znajda DC i logowanie zawodzi.

  • Strefa DNS dla domeny powinna byc AD-Integrated (replikuje sie razem z AD, nie osobnym mechanizmem)
  • Klienci AD musza miec ustawiony DNS na DC, nie na publicznych serwerach (8.8.8.8, 1.1.1.1)
  • Forwardery DNS w DC ustawia sie na zewnetrzne resolvery dla rozwiazywania internetu

Group Policy - centralna konfiguracja

Group Policy Objects (GPO) pozwalaja administratorom centralnie konfigurowac ustawienia komputerow i uzytkownikow. GPO sa linkowane do site, domeny lub OU. Kolejnosc stosowania: Local -> Site -> Domain -> OU (LSDOU).

# Otwarcie konsoli zarzadzania GPO
gpmc.msc

# Edytor lokalnego GPO
gpedit.msc

# Wymuszenie aktualizacji polityki na kliencie
gpupdate /force

# Sprawdzenie zastosowanych polityk
gpresult /h C:\report.html

# Tworzenie nowego GPO przez PowerShell
New-GPO -Name "BlokujUSB-PC" -Comment "Blokada nosnikow USB"
New-GPLink -Name "BlokujUSB-PC" -Target "OU=Workstations,DC=contoso,DC=local"

Zarzadzanie obiektami AD przez PowerShell

# Modul ActiveDirectory (RSAT lub na DC)
Import-Module ActiveDirectory

# Tworzenie OU
New-ADOrganizationalUnit -Name "Sales" -Path "DC=contoso,DC=local" `
                        -ProtectedFromAccidentalDeletion $true

# Nowy uzytkownik
$pwd = ConvertTo-SecureString "Welcome2025!" -AsPlainText -Force
New-ADUser -Name "Jan Kowalski" `
           -SamAccountName "jkowalski" `
           -UserPrincipalName "jkowalski@contoso.local" `
           -Path "OU=Sales,DC=contoso,DC=local" `
           -AccountPassword $pwd `
           -Enabled $true `
           -ChangePasswordAtLogon $true

# Wyszukiwanie uzytkownikow
Get-ADUser -Filter 'Department -eq "Sales"' -Properties Department,Manager
Get-ADUser -Identity jkowalski -Properties *

# Tworzenie i czlonkostwo grup
New-ADGroup -Name "GG-Sales-FileShare" -GroupScope Global -GroupCategory Security `
            -Path "OU=Groups,DC=contoso,DC=local"
Add-ADGroupMember -Identity "GG-Sales-FileShare" -Members jkowalski

# Bulk import z CSV
Import-Csv users.csv | ForEach-Object {
    New-ADUser -Name $_.Name -SamAccountName $_.Sam -Enabled $true `
               -AccountPassword (ConvertTo-SecureString $_.Pass -AsPlainText -Force)
}

Replikacja - KCC i topologia

Knowledge Consistency Checker (KCC) automatycznie buduje topologie replikacji miedzy DC w obrebie sitea (intra-site, co 15s) i miedzy sitami (inter-site, wg harmonogramu). Replikacja w AD jest multi-master - kazdy DC moze przyjmowac zmiany.

# Diagnostyka replikacji
repadmin /showrepl
repadmin /replsummary
repadmin /syncall /AdeP

# Wymuszenie replikacji
repadmin /replicate DC02 DC01 "DC=contoso,DC=local"

# Sprawdzenie kondycji DC
dcdiag /v /c /e

Best practices i model warstw (tier model)

Microsoft promuje Enterprise Access Model rozdzielajacy konta na warstwy by uniemozliwic ruch lateralny:

  • Tier 0 - DC, ADCS, kontroler PKI - tylko konta dedykowane, nigdy nie loguja sie na nizszych poziomach
  • Tier 1 - serwery aplikacyjne, baz danych, plikow
  • Tier 2 - stacje robocze, helpdesk
  • Nie uzywac konta Domain Admin do codziennych zadan - oddzielne konto admina
  • Wlaczyc Protected Users group dla VIP (uniemozliwia cache hasel)
  • Wdrozyc LAPS (Local Administrator Password Solution) - unikalne hasla local admin
  • Audit krytycznych grup (Domain Admins, Enterprise Admins, Schema Admins)
  • Backup System State DC co najmniej dziennie
  • Monitorowac zdarzenia 4624 (logon), 4768/4769 (Kerberos), 4625 (failed logon)
  • Wyeliminowac NTLM gdzie tylko mozliwe, monitorowac uzycie
