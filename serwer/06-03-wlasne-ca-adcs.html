Wlasne CA - Active Directory Certificate Services

Wlasne PKI w organizacji - ADCS, certificate templates, auto-enrollment i revocation.

Po co wlasne CA

Publiczne CA (Let's Encrypt, DigiCert) wydaja certyfikaty tylko dla domen publicznych. ADCS (Active Directory Certificate Services) jest implementacja PKI od Microsoftu pozwalajaca wystawiac certyfikaty dla zasobow wewnetrznych.

Typowe zastosowania

ZastosowanieOpis
Wewnetrzne HTTPSAplikacje intranet bez publicznej domeny
Domain ControllersLDAPS (LDAP over TLS) - wymagane dla nowoczesnych aplikacji
Smart card / Windows Hello for BusinessUwierzytelnianie certyfikatami zamiast hasla

Best practice w produkcji: Two-tier hierarchy - Standalone Offline Root CA + Enterprise Issuing CA. Root jest fizycznie odlaczony (offline) - jego klucz prywatny nigdy nie opuszcza chronionego serwera. Issuing CA on-line wystawia codzienne certyfikaty.

Instalacja Enterprise Root CA

# 1. Instalacja roli ADCS
Install-WindowsFeature -Name AD-Certificate `
                       -IncludeManagementTools

# 2. Instalacja roli services dodatkowych
Install-WindowsFeature -Name ADCS-Cert-Authority,ADCS-Web-Enrollment `
                       -IncludeManagementTools

# 3. Konfiguracja CA
Install-AdcsCertificationAuthority `
    -CAType EnterpriseRootCA `
    -CACommonName "Contoso-RootCA" `
    -CADistinguishedNameSuffix "DC=contoso,DC=local" `
    -KeyLength 4096 `
    -HashAlgorithmName SHA256 `
    -ValidityPeriod Years `
    -ValidityPeriodUnits 10 `
    -DatabaseDirectory "C:\Windows\system32\CertLog" `
    -LogDirectory "C:\Windows\system32\CertLog" `
    -Force

# 4. Web Enrollment (interfejs https://server/certsrv)
Install-AdcsWebEnrollment -Force

Auto-enrollment przez GPO

Auto-enrollment automatycznie wydaje i odnawia certyfikaty domenowych komputerow/uzytkownikow bez interakcji uzytkownika.

# GPO konfiguracja:
# Computer Configuration -> Policies -> Windows Settings
#   -> Security Settings -> Public Key Policies
#       -> Certificate Services Client - Auto-Enrollment
#          [x] Enroll certificates automatically
#          [x] Renew expired certificates
#          [x] Update certificates that use templates

# Dla uzytkownikow:
# User Configuration -> Policies -> ... -> Certificate Services Client - Auto-Enrollment

# Wymuszenie auto-enrollment na konkretnym hoscie
gpupdate /force
certutil -pulse  # wymusza ponowna analize templates

# Sprawdzenie wystawionych certyfikatow
Get-ChildItem Cert:\LocalMachine\My
Get-ChildItem Cert:\CurrentUser\My

Manualne wydanie certyfikatu (CSR)

# 1. Generacja CSR z PowerShell
$inf = @"
[Version]
Signature="`$Windows NT`$"

[NewRequest]
Subject = "CN=app.contoso.local, O=Contoso, OU=IT, L=Warsaw, S=PL, C=PL"
KeySpec = 1
KeyLength = 4096
Exportable = TRUE
MachineKeySet = TRUE
SMIME = FALSE
PrivateKeyArchive = FALSE
UserProtected = FALSE
UseExistingKeySet = FALSE
ProviderName = "Microsoft RSA SChannel Cryptographic Provider"
ProviderType = 12
RequestType = PKCS10
KeyUsage = 0xa0

[EnhancedKeyUsageExtension]
OID=1.3.6.1.5.5.7.3.1 ; Server Authentication

[Extensions]
2.5.29.17 = "{text}"
_continue_ = "DNS=app.contoso.local&"
_continue_ = "DNS=www.contoso.local&"
_continue_ = "IP=10.0.1.50"
"@

$inf | Out-File -Encoding ASCII C:\temp\req.inf
certreq -new C:\temp\req.inf C:\temp\req.csr

# 2. Submit CSR do CA
certreq -submit -config "ca-server.contoso.local\Contoso-RootCA" `
        -attrib "CertificateTemplate:WebServer" `
        C:\temp\req.csr C:\temp\cert.cer

# 3. Akceptacja (instalacja w Personal store)
certreq -accept C:\temp\cert.cer

# 4. Eksport do PFX
$cert = Get-ChildItem Cert:\LocalMachine\My |
    Where-Object { $_.Subject -like "*app.contoso.local*" }
$pwd = ConvertTo-SecureString "Pass!" -AsPlainText -Force
Export-PfxCertificate -Cert $cert -FilePath "C:\export\cert.pfx" -Password $pwd

Revocation - CRL i OCSP

Gdy certyfikat zostaje skompromitowany lub przestaje byc potrzebny, mozna go uniewaznic. Klienci sprawdzaja status przez Certificate Revocation List (CRL) lub Online Certificate Status Protocol (OCSP).

CRL (Certificate Revocation List)

# Konfiguracja punktow CRL Distribution Point (CDP)
# certsrv.msc -> Properties -> Extensions tab -> Select extension: CRL Distribution Point
# Dodanie URL np. http://pki.contoso.com/CertEnroll/<CaName><CRLNameSuffix>.crl

# Manualne wystawienie nowej CRL
certutil -CRL

# Ogladanie CRL
certutil -dump C:\Windows\system32\CertSrv\CertEnroll\*.crl

# Czas zycia CRL: domyslnie 7 dni - dla srodowisk produkcyjnych zmienic na 1-2 dni
# Delta CRL: czas zycia 1 dzien - tylko nowe revokacje od ostatniej Base CRL

# Revoke certyfikatu
certutil -revoke "<serial number>" "Reason"
# Reasons: 0=Unspecified, 1=KeyCompromise, 2=CACompromise, 3=AffiliationChanged,
#          4=Superseded, 5=CessationOfOperation, 6=CertificateHold

Online Responder (OCSP)

Online Responder publikuje status certyfikatow przez HTTP - klient pyta o pojedynczy certyfikat, dostaje podpisana odpowiedz "Good", "Revoked", "Unknown". Bardziej efektywne niz pobieranie pelnej CRL.

# Instalacja Online Responder
Install-WindowsFeature ADCS-Online-Cert -IncludeManagementTools
Install-AdcsOnlineResponder -Force

# Konfiguracja wymagana w certsrv:
# 1. Wystawienie certyfikatu OCSP Response Signing dla serwera Online Responder
# 2. AIA extension w wystawianych certyfikatach ->
#    URL OCSP: http://pki.contoso.com/ocsp

# Verifikacja statusu OCSP konkretnego certyfikatu
certutil -url "C:\path\to\cert.cer"

Two-tier hierarchy - production setup

  • Standalone Root CA (offline):
    • Workgroup, nie czlonek domeny
    • Po instalacji wylaczyc serwer, wlaczac tylko dla wystawienia subordinate / nowej CRL
    • Klucz min. RSA 4096 bit, SHA256
    • Waznosc: 10-20 lat
    • CRL publishing: rocznie (Root CA wystawia rzadko)
    • Backup klucza prywatnego na HSM lub Smart Card
  • Enterprise Issuing CA (online):
    • Czlonek domeny AD - integracja
    • Subordinate od Root - certyfikat wystawiony przez Root
    • Klucz RSA 2048-4096
    • Waznosc: 5-10 lat (krotsze niz Root)
    • CRL publishing: 1-7 dni
    • Auto-enrollment dla domeny przez GPO

Distrybucja Root CA na klientow

# Enterprise CA - automatycznie przez AD (NTAuth store, Trusted Root Cert Authorities)
# Standalone Root - trzeba recznie pushnac przez GPO

# Eksport Root cert (bez klucza prywatnego)
$root = Get-ChildItem Cert:\LocalMachine\Root |
    Where-Object { $_.Subject -like "*Contoso-RootCA*" }
Export-Certificate -Cert $root -FilePath "C:\export\contoso-root.cer"

# Push przez GPO:
# Computer Configuration -> Policies -> Windows Settings -> Security
#   -> Public Key Policies -> Trusted Root Certification Authorities
#      -> Import: contoso-root.cer

# Lub manualnie:
Import-Certificate -FilePath "C:\export\contoso-root.cer" `
                   -CertStoreLocation Cert:\LocalMachine\Root

Best practices

  • Two-tier hierarchy: offline Root + online Issuing
  • Klucz Root chroniony przez HSM lub Smart Card
  • SHA256 minimum (NIE SHA1, MD5)
  • Klucze RSA min. 2048 bit, najlepiej 4096 dla CA
  • Validity period: Root 10-20 lat, Issuing 5-10 lat, leaf 1-2 lata
  • CRL publishing 1-7 dni dla Issuing CA
  • OCSP Responder dla wydajnego sprawdzania revocation
  • Audyt loggingu CA (Event ID 4886, 4888 - request, issued)
  • Backup CA database (certsrv.mdb) i klucza prywatnego (po HSM)
  • Disaster recovery: dokumentacja procedury restore CA
  • Monitoring waznosci subordinate (alarm 90 dni przed)
