Rootless Docker

Standardowy daemon dziala jako root. Rootless mode — dziala jako zwykly user. Eliminuje calkowicie ryzyko escape-to-root.

# Setup (Ubuntu)
sudo apt-get install -y dbus-user-session uidmap
sudo systemctl disable --now docker.service docker.socket

dockerd-rootless-setuptool.sh install
systemctl --user enable docker
loginctl enable-linger $(whoami)

export DOCKER_HOST=unix:///run/user/$(id -u)/docker.sock

docker info | grep -i rootless
# rootless

Zalety rootless

  • Daemon i kontenery dzialaja jako user, nie root
  • Container escape NIE daje roota na hoscie
  • Per-user docker daemon — izolacja miedzy uzytkownikami
  • Brak ryzyka eskalacji przez grupe docker

Limitacje rootless

  • Porty < 1024 wymagaja CAP_NET_BIND_SERVICE lub setcap
  • Brak --net=host (uzywa slirp4netns) — wolniejsza siec
  • Niektore storage drivers nie dzialaja (overlay2 wymaga niedawnego kernela)
  • cgroups v2 wymagane

User namespaces remap

Alternatywa dla rootless — daemon nadal root, ale UID 0 w kontenerze mapuje sie na nie-roota hosta.

# /etc/docker/daemon.json
{
  "userns-remap": "default"
}

# Po restarcie:
# UID 0 w kontenerze == UID 100000 na hoscie
# Container escape jako "root" w kontenerze = uzytkownik 100000 na hoscie

USER w Dockerfile

NIE uzywaj root-a wewnatrz kontenera, nawet jesli daemon dziala jako root.

FROM alpine:3
RUN addgroup -S app && adduser -S app -G app
WORKDIR /app
COPY --chown=app:app . .
USER app
CMD ["./entrypoint.sh"]

# Sprawdz
docker run myimage whoami    # app, nie root

Capabilities — granularne uprawnienia

Linux ma 38 capabilities. Default Docker daje 14. Najlepsza praktyka: cap-drop ALL + cap-add tylko potrzebne.

# Niebezpieczne (default)
docker run nginx
# Ma m.in. CAP_NET_RAW, CAP_AUDIT_WRITE, CAP_MKNOD itp.

# Bezpieczne
docker run \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  nginx

# Kompletnie bez uprawnien (gdy nie potrzeba)
docker run --cap-drop ALL myapp

# Compose
services:
  api:
    cap_drop: ["ALL"]
    cap_add: ["NET_BIND_SERVICE"]
CapabilityCo pozwalaDefault?
NET_BIND_SERVICEBind portow < 1024Tak
CHOWNchown plikowTak
NET_RAWraw sockets — potrzebne dla pingTak (RYZYKO)
SYS_ADMINPelne admin uprawnienia — UWAGANie
SYS_PTRACEptrace, debuggeryNie
AUDIT_WRITEauditd zapisyTak (rzadko potrzebne)

--security-opt no-new-privileges

Wylacza setuid — kontener nie moze podniesc swoich uprawnien (np. przez sudo, setuid binary).

docker run --security-opt no-new-privileges:true myapp

# Compose
services:
  api:
    security_opt:
      - no-new-privileges:true

Read-only root filesystem

docker run --read-only --tmpfs /tmp myapp

# Aplikacja nie moze pisac do /, /usr, /var ... z wyjatkiem /tmp w RAM
# Eliminuje class atakow (drop binary, modify config)

Image scanning

Skanuj obrazy na CVE przed deploymentem. Najlepsze tools 2026:

Trivy (Aqua, OSS)

brew install aquasecurity/trivy/trivy

# Skan obrazu
trivy image nginx:alpine

# Skan z severity threshold (CI gate)
trivy image --severity CRITICAL,HIGH --exit-code 1 myapp:latest

# Skan filesystema (Dockerfile, repo)
trivy fs .

# SBOM
trivy image --format cyclonedx --output sbom.json myapp:latest

Grype (Anchore, OSS)

brew tap anchore/grype
brew install grype

grype myapp:latest
grype dir:./project

Snyk

npm i -g snyk
snyk auth
snyk container test myapp:latest --severity-threshold=high

Docker Scout

# Wbudowany w Docker Desktop / CLI
docker scout cves myapp:latest
docker scout recommendations myapp:latest
docker scout compare --to myapp:1.0 myapp:1.1

Supply chain security

Signed images — Sigstore / Cosign

# Podpisz obraz
cosign generate-key-pair
cosign sign --key cosign.key user/myapp:1.0

# Weryfikacja
cosign verify --key cosign.pub user/myapp:1.0

# Keyless (OIDC, GitHub Actions)
COSIGN_EXPERIMENTAL=1 cosign sign user/myapp:1.0

SBOM (Software Bill of Materials)

# syft — generator SBOM
syft myapp:latest -o cyclonedx-json > sbom.json
syft myapp:latest -o spdx-json > sbom.spdx

# Dolacz SBOM do obrazu (cosign attest)
cosign attest --key cosign.key --predicate sbom.json --type cyclonedx user/myapp:1.0

Notary v2 / OCI artifacts

Notary v2 to nowy standard signinowania OCI — rozszerza signing na artefakty (manifest, SBOM, vulnerability scan results).

Secrets management

NIE rob

  • Hardcoded sekrety w Dockerfile (ENV API_KEY=...)
  • Sekrety jako build args (sa w historii warstw)
  • Sekrety w docker-compose.yml commitowane
  • Sekrety jako environment variables (docker run -e API_KEY=... — widoczne w docker inspect)

Docker Swarm secrets

# Init swarm i stworz secret
docker swarm init
echo "supersecret" | docker secret create api_key -

# Uzyj
docker service create --secret api_key --name api myapp
# W kontenerze /run/secrets/api_key

Compose secrets

services:
  api:
    image: myapp
    secrets:
      - db_password
    environment:
      DB_PASSWORD_FILE: /run/secrets/db_password

secrets:
  db_password:
    file: ./secrets/db_password.txt

BuildKit secrets (build-time)

# syntax=docker/dockerfile:1
FROM alpine
RUN --mount=type=secret,id=npmrc,target=/root/.npmrc \
    npm install @private/pkg

# Build
docker build --secret id=npmrc,src=$HOME/.npmrc .

CIS Docker Benchmark

Center for Internet Security publikuje hardening guide dla Dockera. Sprawdz automatycznie przez docker-bench-security:

docker run --rm -it --net host --pid host --userns host --cap-add audit_control \
  -e DOCKER_CONTENT_TRUST=$DOCKER_CONTENT_TRUST \
  -v /etc:/etc:ro \
  -v /usr/bin/containerd:/usr/bin/containerd:ro \
  -v /usr/bin/runc:/usr/bin/runc:ro \
  -v /usr/lib/systemd:/usr/lib/systemd:ro \
  -v /var/lib:/var/lib:ro \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  --label docker_bench_security \
  docker/docker-bench-security

Bezpieczna konfiguracja kontenera — pelny przyklad

docker run -d \
  --name api \
  --restart unless-stopped \
  --user 1000:1000 \
  --read-only \
  --tmpfs /tmp:size=64m \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  --security-opt no-new-privileges:true \
  --security-opt apparmor=docker-default \
  --pids-limit 100 \
  --memory 512m --cpus 1 \
  -p 127.0.0.1:8080:8080 \
  --health-cmd "wget -qO- http://localhost:8080/health" \
  myapp:1.0.0

Compose — bezpieczna sluzba

services:
  api:
    image: ghcr.io/user/api:1.0.0
    user: "1000:1000"
    read_only: true
    tmpfs:
      - /tmp:size=64m
    cap_drop: ["ALL"]
    cap_add: ["NET_BIND_SERVICE"]
    security_opt:
      - no-new-privileges:true
    pids_limit: 100
    deploy:
      resources:
        limits:
          memory: 512M
          cpus: '1'
    ports:
      - "127.0.0.1:8080:8080"
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:8080/health"]
      interval: 30s

Production checklist

  • Rootless mode lub user namespaces remap
  • USER nie-root w Dockerfile
  • --cap-drop ALL + tylko potrzebne
  • no-new-privileges:true
  • read_only z tmpfs gdzie trzeba
  • Resource limits (memory, cpus, pids)
  • Image scanning w CI (Trivy/Grype/Snyk) z gate na CRITICAL/HIGH
  • Signed images (Cosign + OIDC)
  • SBOM generowany i archiwizowany
  • Secrets przez Vault / Compose secrets — nie env
  • Pinned wersje obrazow (sha256 digest, nie :latest)
  • Network: bind 127.0.0.1 + reverse proxy
  • Regularne aktualizacje base images (Dependabot dla Dockerfile)
  • CIS Docker Benchmark audyt
  • Logging do central system (Loki, ELK)
