Docker na Linux

Native install, rootless mode, Podman, kernel features

Linux — native srodowisko Dockera

Docker pierwotnie powstal dla Linuxa i tutaj dziala natywnie. Brak VM, brak emulacji — kontenery to procesy hosta izolowane przez kernel.

+------------------+
|   Linux host     |
+------------------+
|   dockerd        |  <- daemon
|     |            |
|     v            |
|  containerd      |
|     |            |
|     v            |
|   runc           |  <- runtime
|   (namespaces, cgroups, capabilities)
|                  |
|  Container       |  <- po prostu proces!
+------------------+

Instalacja na Ubuntu / Debian

Oficjalny sposob — przez apt repository Dockera (zawsze najnowsza wersja).

# Usun stare wersje
sudo apt-get remove docker docker-engine docker.io containerd runc

# Pre-req
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg

# Klucz repo
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# Repo
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Instalacja
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Test
sudo docker run hello-world

# Bez sudo — dodaj usera do grupy docker
sudo usermod -aG docker $USER
newgrp docker

docker run hello-world  # bez sudo

Fedora / RHEL

sudo dnf -y install dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/fedora/docker-ce.repo

sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

sudo systemctl enable --now docker
sudo usermod -aG docker $USER

# Test
docker run hello-world

Arch Linux

sudo pacman -S docker docker-buildx docker-compose
sudo systemctl enable --now docker.service
sudo usermod -aG docker $USER

docker run hello-world

Alpine Linux

sudo apk add docker docker-cli-compose
sudo rc-update add docker default
sudo service docker start
sudo addgroup $USER docker

Rootless Docker

Rootless mode — daemon i kontenery dzialaja jako zwykly user (nie root). Wieksze bezpieczenstwo: nawet jesli kontener zostanie skompromitowany, atakujacy nie ma roota na hoscie.

# Instalacja (Ubuntu)
sudo apt-get install -y dbus-user-session uidmap

# Wylacz system docker (jesli zainstalowany)
sudo systemctl disable --now docker.service docker.socket

# Setup rootless
dockerd-rootless-setuptool.sh install

# Wlaczenie auto-start dla usera
systemctl --user enable docker
loginctl enable-linger $(whoami)

# DOCKER_HOST per user
export DOCKER_HOST=unix:///run/user/$(id -u)/docker.sock
echo 'export DOCKER_HOST=unix:///run/user/$(id -u)/docker.sock' >> ~/.bashrc

# Test
docker run hello-world

# Limitations rootless:
# - cgroup v2 wymagane
# - Brak portow < 1024 bez setcap
# - Brak overlay storage driver na niektorych FS — uzywa fuse-overlayfs
# - Brak --net=host (workaround: slirp4netns)

Podman — daemonless alternatywa

Podman (Red Hat) — OSS alternatywa Dockera. CLI kompatybilne (alias docker=podman dziala). Glowne roznice:

  • Daemonless — brak dlugo zyjacego procesu, kazdy kontener to fork
  • Rootless first — default jest bezpieczny user-mode
  • Pod jako koncept (jak w Kubernetes) — grupa kontenerow ze wspolna siecia
  • Generowanie systemd unit files dla kontenerow (Quadlet)
  • Brak swarmu — uzywa Kubernetes
# Instalacja
sudo apt-get install -y podman      # Ubuntu/Debian
sudo dnf install -y podman          # Fedora/RHEL
sudo pacman -S podman               # Arch

# Uzycie identyczne
podman run hello-world
podman ps -a
podman build -t myapp .

# Pod (grupa kontenerow)
podman pod create --name webapp -p 8080:80
podman run -d --pod webapp nginx
podman run -d --pod webapp redis

Systemd integration (Quadlet)

Zamiast pisac wlasne service files, Podman/systemd ma Quadlet — .container files automatycznie konwertowane na .service.

# ~/.config/containers/systemd/myapp.container
[Unit]
Description=Moja aplikacja
After=network-online.target

[Container]
Image=ghcr.io/user/myapp:latest
PublishPort=8080:80
Volume=/var/data:/data:Z
Environment=NODE_ENV=production

[Service]
Restart=always

[Install]
WantedBy=default.target

# Reload + start
systemctl --user daemon-reload
systemctl --user start myapp.service
systemctl --user enable myapp.service

Docker w systemd (klasycznie)

# /etc/systemd/system/myapp.service
[Unit]
Description=Myapp container
After=docker.service
Requires=docker.service

[Service]
Restart=always
ExecStartPre=-/usr/bin/docker stop myapp
ExecStartPre=-/usr/bin/docker rm myapp
ExecStart=/usr/bin/docker run --rm --name myapp \
  -p 8080:80 \
  -v /var/data:/data \
  -e NODE_ENV=production \
  ghcr.io/user/myapp:latest
ExecStop=/usr/bin/docker stop myapp

[Install]
WantedBy=multi-user.target

sudo systemctl daemon-reload
sudo systemctl enable --now myapp

Kernel features — jak dziala kontener

Namespaces

Kazdy kontener ma wlasne namespaces — izolowane widoki zasobow:

NamespaceCo izoluje
PIDProcesy — wlasny PID 1, niewidoczne procesy hosta
NETInterfejsy sieciowe, routing, firewall
MNTPunkty montowania — wlasny widok filesystemu
UTSHostname, domena
IPCSysV IPC, kolejki POSIX
USERMapowanie UID/GID — wewnatrz root, na hoscie nie-root
CGROUPWidok hierarchii cgroup

cgroups v2

cgroups (control groups) limituja zasoby per proces:

  • CPU — udzial procesora, throttling
  • Memory — max RAM, swap, OOM behavior
  • I/O — przepustowosc dysku, IOPS
  • PIDs — max liczba procesow
docker run --cpus 0.5 --memory 512m --pids-limit 100 myapp

Capabilities

Linux ma capabilities — granularne uprawnienia roota. Domyslnie kontener ma 14 z 38, ale dla bezpieczenstwa zrzucaj wszystkie i dodawaj tylko potrzebne.

# Domyslne capabilities (czesc):
CAP_NET_BIND_SERVICE   # bind portow < 1024
CAP_CHOWN              # zmiana wlasciciela
CAP_DAC_OVERRIDE       # ignoruj DAC

# Bezpieczne podejscie
docker run --cap-drop ALL --cap-add NET_BIND_SERVICE myapp

Bezpieczenstwo grupy "docker"

UWAGA — user w grupie docker = root

Dodanie usera do grupy docker daje mu efektywny dostep root do hosta. Dlaczego?

# User moze wykonac
docker run -v /:/host -it alpine sh
# I edytowac dowolny plik na hoscie jako root!

Zalecenia:

  • Na produkcji NIE dodawaj userow do grupy docker
  • Uzywaj rootless mode jesli potrzebujesz user-friendly
  • Dla CI/CD — dedykowany user lub Podman rootless
  • Audytuj kto jest w grupie: getent group docker

Setup produkcyjny — checklist

  • Latest stable Docker (apt repo, nie distro package)
  • cgroups v2 wlaczone (Ubuntu 22.04+ default)
  • overlay2 storage driver
  • Logi konfiguracja: /etc/docker/daemon.json z log-driver json-file + max-size
  • Live restore wlaczony — daemon update bez restartu kontenerow
  • Rootless dla bezpieczenstwa lub Podman
  • Firewall (ufw/firewalld) — uwaga, Docker domyslnie bypass'uje iptables UFW
  • Auto-update obrazow (Watchtower / Diun)
