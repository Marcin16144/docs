Multi-stage builds — obowiazek 2026

Najwazniejsza technika. Buildujesz w jednym stage, kopiujesz tylko artefakty do drugiego. Wynik: maly obraz produkcyjny bez narzedzi build.

# Node.js — przyklad
# === Stage 1: builder ===
FROM node:20-alpine AS builder
WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .
RUN npm run build

# === Stage 2: runtime ===
FROM node:20-alpine AS runtime
WORKDIR /app

# Tylko produkcyjne deps
COPY package*.json ./
RUN npm ci --omit=dev && npm cache clean --force

# Tylko zbudowane artefakty
COPY --from=builder /app/dist ./dist

USER node
EXPOSE 3000
CMD ["node", "dist/server.js"]

# Wynik: ~150 MB zamiast ~1 GB

Go — przyklad ekstremalny

# Stage 1: build
FROM golang:1.22 AS builder
WORKDIR /src

COPY go.mod go.sum ./
RUN go mod download

COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o /app ./cmd/api

# Stage 2: minimalny runtime
FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=builder /app /app
USER nonroot:nonroot
EXPOSE 8080
ENTRYPOINT ["/app"]

# Final image: ~10 MB!

Skutki braku .dockerignore

  • Build wolniejszy (gigabajty wysylane do daemona)
  • Wieksze obrazy (np. .git z historia 500 MB)
  • Wycieki sekretow (.env trafia do obrazu)
  • Cache invalidation przez kazda zmiane lokalna (np. .vscode/)

Layer caching

Docker buduje warstwami. Kazdy RUN, COPY, ADD to nowa warstwa. Jesli nic sie nie zmienilo, Docker re-uzyva cache. Strategia: najpierw to co rzadko sie zmienia.

# ZLE — cache invalidation przy kazdej zmianie kodu
FROM node:20-alpine
WORKDIR /app
COPY . .                  # zmiana JEDNEGO pliku → cache padl
RUN npm ci                # ...wiec npm ci zostanie powtorzony
CMD ["node", "index.js"]

# DOBRZE — package.json osobno
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./     # zmiana tylko gdy deps sie zmienia
RUN npm ci                # cache do tego momentu
COPY . .                  # zmiana kodu nie unieksztalca npm ci
CMD ["node", "index.js"]

Alpine

FROM node:20-alpine
# ~50 MB — musl libc, busybox, malo narzedzi
# Uwaga: niektore biblioteki C nie kompiluja na musl (rzadko)

Distroless (Google)

FROM gcr.io/distroless/nodejs20-debian12:nonroot
# Tylko runtime — brak shella, package managera, busybox
# Bezpieczne, male (~80 MB), ale debug trudniejszy
# Wersja "debug" ma busybox: gcr.io/distroless/.../debug

Chainguard Images

FROM cgr.dev/chainguard/node:latest
# Hardened obrazy — minimalne, signed, zero CVE
# Komercyjne support, free dla wielu obrazow
# Najczystszy security stance w 2026

# ~120 MB, glibc, dpkg/apt — latwe instalacje

BuildKit features

BuildKit to nowoczesny backend buildu. Default w nowoczesnym Dockerze. Daje:

  • Parallel builds (multi-stage paralelnie)
  • Mount cache (npm, pip, go cache)
  • Mount secrets (bez wlasnoscia w warstwie)
  • SSH agent forwarding
  • Inline cache export
# syntax=docker/dockerfile:1.7
FROM node:20-alpine AS builder
WORKDIR /app

# Cache npm
COPY package*.json ./
RUN --mount=type=cache,target=/root/.npm \
    npm ci

# Secret — nie ma w final image
RUN --mount=type=secret,id=npm,target=/root/.npmrc \
    npm install @private/package

COPY . .
RUN npm run build

# SSH dla git private
RUN --mount=type=ssh \
    git clone git@github.com:user/private.git
# Build z secret
docker build --secret id=npm,src=$HOME/.npmrc .

# Build z SSH
docker build --ssh default .

RUN — lacz komendy

# ZLE — trzy warstwy + apt cache w obrazie
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get clean

# DOBRZE — jedna warstwa, cache wyczyszczony
RUN apt-get update && \
    apt-get install -y --no-install-recommends curl ca-certificates && \
    rm -rf /var/lib/apt/lists/*

# Alpine
RUN apk add --no-cache curl ca-certificates

CMD vs ENTRYPOINT

# CMD — default command, latwo override przy run
CMD ["node", "index.js"]
# docker run image  -> node index.js
# docker run image bash -> bash

# ENTRYPOINT — sztywny "wykonawca", argumenty doklejane
ENTRYPOINT ["node"]
CMD ["index.js"]
# docker run image -> node index.js
# docker run image other.js -> node other.js

# Przyklad — wrapper init
ENTRYPOINT ["/usr/local/bin/dumb-init", "--"]
CMD ["node", "dist/server.js"]

FROM node:20-alpine

# Stworz usera
RUN addgroup -g 1001 -S app && \

Pelny przyklad — Next.js produkcyjny

# syntax=docker/dockerfile:1.7
ARG NODE_VERSION=20

FROM node:${NODE_VERSION}-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN --mount=type=cache,target=/root/.npm \
    npm ci

FROM node:${NODE_VERSION}-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build

FROM node:${NODE_VERSION}-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production NEXT_TELEMETRY_DISABLED=1

RUN addgroup -g 1001 -S nodejs && \
    adduser -u 1001 -S nextjs -G nodejs

# Standalone output Next.js
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static
COPY --from=builder --chown=nextjs:nodejs /app/public ./public

USER nextjs
EXPOSE 3000
ENV PORT=3000 HOSTNAME="0.0.0.0"

HEALTHCHECK --interval=30s --timeout=3s CMD wget -qO- http://localhost:3000 || exit 1

CMD ["node", "server.js"]

Best practices — checklist

  • Multi-stage build (builder + runtime)
  • .dockerignore z node_modules, .git, .env
  • COPY package.json — RUN npm ci — COPY . (kolejnosc dla cache)
  • Maly base image (alpine / distroless / chainguard)
  • USER nonroot (nie root)
  • HEALTHCHECK
  • Tag wersji (nie tylko :latest)
  • Pin wersji base (FROM node:20.11-alpine, nie :20)
  • BuildKit (cache mounts, secrets)
  • Single process per container (uzywaj init jak dumb-init)
  • NIE rob: COPY .env, hardcoded secrets, ADD url (uzyj curl)
