Bind mounts

Mapuje konkretna sciezke hosta do kontenera. Idealne dla dev (kod), config, socketow.

# Skladnia -v
docker run -v /host/absolute/path:/container/path nginx
docker run -v $(pwd):/app node:20

# Read-only
docker run -v $(pwd)/config:/etc/app:ro myapp

# Skladnia --mount (bardziej explicit, polecane)
docker run --mount type=bind,source=$(pwd),target=/app,readonly nginx

# Compose
services:
  api:
    volumes:
      - ./src:/app/src                    # bind, RW
      - ./config:/etc/app:ro              # bind, RO
      - /var/run/docker.sock:/var/run/docker.sock  # socket

Named volumes

Wolumen zarzadzany przez Dockera. Trwaly miedzy uruchomieniami kontenerow, latwy do backupu, lepsza wydajnosc na Mac/Win.

# Tworzenie
docker volume create mydata

# Uzycie
docker run -v mydata:/var/data postgres
docker run --mount type=volume,source=mydata,target=/var/data postgres

# Inspekcja
docker volume ls
docker volume inspect mydata
# Mountpoint: /var/lib/docker/volumes/mydata/_data

# Compose — auto tworzony
services:
  db:
    image: postgres
    volumes:
      - db-data:/var/lib/postgresql/data

volumes:
  db-data:               # Docker tworzy projekt_db-data

Anonymous volumes

# Wolumen bez nazwy — przy uzyciu Dockerfile VOLUME albo run -v /path
VOLUME /data            # w Dockerfile
docker run -v /data myapp   # tworzy anonymous volume

# Pulapka: kazde uruchomienie tworzy nowy — sieroty po --rm
docker volume ls -q --filter dangling=true
docker volume prune

tmpfs — tylko RAM

Mount w pamieci hosta, znika gdy kontener stop. Idealne dla sekretow, scratch.

docker run --tmpfs /tmp:size=100m alpine
docker run --mount type=tmpfs,destination=/tmp,tmpfs-size=100m alpine

# Compose
services:
  app:
    tmpfs:
      - /tmp:size=100m
      - /run:size=10m

Volume drivers

Domyslny driver to local (lokalny FS hosta). Mozna uzywac plugins dla NFS, CIFS, S3, RBD.

NFS

docker volume create --driver local \
  --opt type=nfs \
  --opt o=addr=10.0.0.1,nfsvers=4,rw \
  --opt device=:/exports/data \
  shared-nfs

docker run -v shared-nfs:/data alpine ls /data

CIFS / SMB

docker volume create --driver local \
  --opt type=cifs \
  --opt o=username=user,password=pass,uid=1000,gid=1000 \
  --opt device=//server/share \
  shared-smb

Plugins (Docker plugin install)

# Plugin S3 (rclone)
docker plugin install rclone/docker-volume-rclone

# Vieux/sshfs
docker plugin install vieux/sshfs

# REX-Ray (multi-cloud)
docker plugin install rexray/ebs

Backup wolumenow

Najpopularniejsza technika — "sidecar container" z tar.

# Backup
docker run --rm \
  -v mydata:/data:ro \
  -v $(pwd):/backup \
  alpine tar czf /backup/mydata-$(date +%F).tar.gz -C /data .

# Restore
docker run --rm \
  -v mydata:/data \
  -v $(pwd):/backup \
  alpine tar xzf /backup/mydata-2026-05-07.tar.gz -C /data

# Postgres — preferuj pg_dump zamiast tar plikow live'owych
docker exec -t postgres-db pg_dumpall -U user > backup.sql
cat backup.sql | docker exec -i postgres-db psql -U user

# Z compose
docker compose run --rm db pg_dump -U user app > backup.sql

Volume migration miedzy hostami

# Na zrodlowym hoscie — backup
docker run --rm -v mydata:/data -v $(pwd):/b alpine tar czf /b/v.tar.gz -C /data .

# Skopiuj plik do nowego hosta
scp v.tar.gz newhost:~/

# Na nowym hoscie — restore
docker volume create mydata
docker run --rm -v mydata:/data -v $(pwd):/b alpine tar xzf /b/v.tar.gz -C /data

Wydajnosc per platforma

Mac & Windows — bind mounts SA WOLNE

Dlaczego: kontenery dzialaja w VM Linux, a bind mount musi przekazywac IO przez most VM<->host. Praktyczna konsekwencja:

  • node_modules w bind mount: 10-100x wolniejsze niz natywnie
  • Hot reload moze laggowac
  • Aplikacje IO-heavy (scaffolding, kompilacja) bardzo cierpia

Rozwiazania:

  • Uzywaj named volumes dla node_modules:
volumes:
  - .:/app
  - /app/node_modules     # named volume (anonymous)
  - /app/.next
  • Mac: VirtioFS (Docker Desktop) lub OrbStack — sa znacznie szybsze
  • Mac: Mutagen sync (alternatywa — sync poza Dockerem)
  • Windows: WSL2 + projekt w /home/... (NIE w /mnt/c/)

Linux — bind mounts natywne

Na Linuxie bind mount to tylko mount --bind — brak narzutu. Mozesz korzystac wszedzie. Named volumes maja identyczna wydajnosc.

Permissions — klasyczne pulapki

# Problem: kontener pisze jako root, hosting widzi pliki "owned by root"
docker run -v $(pwd):/app node:20 npm install
ls -la node_modules
# drwxr-xr-x 1 root root ...   <- ZLE

# Rozwiazanie: uzytkownik
docker run -v $(pwd):/app -u $(id -u):$(id -g) node:20 npm install

# Compose
services:
  api:
    user: "${UID:-1000}:${GID:-1000}"
    volumes:
      - .:/app

# Lub Dockerfile — createuser i USER
# I pamietaj o COPY --chown

SELinux na RHEL/Fedora

Z SELinux musisz oznaczyc bind mount — :Z lub :z

docker run -v $(pwd):/data:Z fedora        # private
docker run -v /shared:/data:z fedora        # shared

Wzorce

Volumes-from — backup container

docker run --rm \
  --volumes-from mycontainer \
  -v $(pwd):/backup \
  alpine tar czf /backup/full.tar.gz /var/data /etc

Init container z volume

services:
  init:
    image: alpine
    command: sh -c "wget -O /shared/data.json http://api/seed"
    volumes:
      - shared:/shared

  app:
    image: myapp
    depends_on:
      init:
        condition: service_completed_successfully
    volumes:
      - shared:/data:ro

volumes:
  shared:

Storage — konserwacja

# Sprawdz co zajmuje miejsce
docker system df
docker system df -v          # szczegolowe per object

# Lista wolumenow nieuzywanych
docker volume ls --filter dangling=true

# Cleanup — UWAGA, USUWA DANE
docker volume prune
docker volume prune -a       # rowniez te z labels

# Selektywnie
docker volume rm old-test-data

Best practices

  • Dev kod → bind mount
  • Produkcja, baza danych, dane uzytkownika → named volume
  • Mac/Win — node_modules itp. → named volume w bind
  • Sekrety, /tmp, scratch → tmpfs
  • Backupy — cron z tar przez sidecar; dla DB — native dump (pg_dump)
  • Permissions — USER w Dockerfile + --chown w COPY
  • SELinux — pamietaj o :Z
