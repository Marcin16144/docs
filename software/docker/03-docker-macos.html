Docker na macOS

Docker Desktop, Colima, OrbStack — co wybrac w 2026

Architektura Dockera na macOS

macOS nie ma natywnego kernela Linux, a kontenery Linuxowe wymagaja kernela Linux. Dlatego kazde rozwiazanie uruchamia lekka VM Linux w tle. To w niej dzialaja kontenery, a CLI docker komunikuje sie z daemonem przez socket.

+------------------------+        +----------------------+
|     macOS host         |        |   Linux VM           |
|                        |        |                      |
|  docker CLI    --------|-->|----| dockerd (daemon)     |
|  & Docker Desktop UI   | sock   | + containerd         |
|                        |        | + Twoje kontenery    |
+------------------------+        +----------------------+

Docker Desktop dla Mac

Docker Desktop — oficjalna aplikacja Docker Inc. Dla M1/M2/M3/M4 (Apple Silicon) jest natywna ARM — brak emulacji.

Glowne funkcje

  • VirtioFS — szybki file sharing host <-> VM (zastapil osxfs)
  • Rosetta x86 emulation — uruchamiaj obrazy x86_64 na Apple Silicon (od macOS 13+)
  • Docker Compose, Kubernetes (single-node), Extensions
  • Docker Scout (skanowanie obrazow)
  • Resource Saver (zmniejsza RAM/CPU gdy idle)

Instalacja Docker Desktop

# Pobierz z docker.com (DMG)
# https://www.docker.com/products/docker-desktop/

# Lub przez Homebrew
brew install --cask docker

# Po instalacji uruchom Docker Desktop z Applications
open /Applications/Docker.app

# Pierwsze uruchomienie zaakceptuje warunki, skonfiguruje VM (~2 min)
# Sprawdz
docker --version
docker info
docker run hello-world

Wlaczenie Rosetta dla x86

Apple Silicon natywnie ARM64. Niektore obrazy sa tylko x86_64 — potrzebna emulacja.

# Pre-req: Rosetta 2
softwareupdate --install-rosetta --agree-to-license

# Docker Desktop > Settings > General > Use Rosetta for x86_64/amd64 emulation on Apple Silicon
# (zaznacz)

# Test
docker run --platform linux/amd64 alpine uname -m
# x86_64

Colima (free, OSS)

Colima (CONtainers in LIma MAchine) — bezplatna alternatywa OSS. Lima pod spodem (lekkie VM Linux na macOS). Idealna gdy nie chcesz/nie mozesz uzywac Docker Desktop.

# Instalacja
brew install colima docker docker-compose

# Start (default config)
colima start

# Z konfiguracja
colima start --cpu 4 --memory 8 --disk 60 --vm-type vz --mount-type virtiofs

# Sprawdz
docker info
docker run hello-world

# Stop / restart / delete
colima stop
colima restart
colima delete

Wieloma profilami Colima

# Profil "work" z duzymi zasobami
colima start --profile work --cpu 6 --memory 12

# Profil "test" maly
colima start --profile test --cpu 2 --memory 2

# Switch
colima list
colima start --profile work
docker context use colima-work

OrbStack (premium, najszybszy)

OrbStack — najszybsza opcja Docker dla Mac w 2026. Komercyjna, ale ma generous free tier dla osobistego uzycia. Buduja od podstaw, brak Docker Desktop / Lima — wlasna implementacja w Swift + Rust.

Cechy OrbStack

  • Najszybszy start — 2 sekundy do pelnej gotowosci
  • Najmniejszy zuzycie RAM (idle ~150 MB vs Docker Desktop ~2 GB)
  • Native Mac UI (SwiftUI), zero VM — uzywa Apple Virtualization framework
  • Kubernetes single-node (k3s)
  • Linux machines — oddzielne VM Linux z gotowymi distrami (Ubuntu, Fedora, Arch)
  • Rosetta x86 emulation
  • Sieci: SSH/HTTP do kontenerow przez .orb.local
# Instalacja
brew install --cask orbstack

# Po instalacji wszystko dziala — CLI Dockera podpiete automatycznie
docker run hello-world

# Linux machine (pelna VM)
orb create ubuntu my-ubuntu
orb -m my-ubuntu
# (jestes w VM Ubuntu)

Cennik OrbStack

  • Personal — FREE dla osobistego, edukacyjnego, open source
  • Pro — ~8 USD/miesiac dla komercyjnego (per uzytkownik)

Lima (Colima underneath)

Lima — "Linux Machines" — baza pod Colima. Mozesz uzywac bezposrednio dla pelnej kontroli (yaml config), ale Colima daje lepszy DX out-of-the-box.

brew install lima
limactl start template://docker
docker context use lima-docker
docker run hello-world

Apple Silicon vs Intel

Apple Silicon (M1/M2/M3/M4)

  • Architektura ARM64 / aarch64 — obrazy linux/arm64 dzialaja natywnie
  • x86_64 — przez Rosetta 2 (10-30% wolniej, dla wiekszosci OK)
  • Wiele oficjalnych obrazow ma multi-arch (manifest list) — auto wybor
  • Niektore stare obrazy tylko x86_64 — oznaczaj --platform linux/amd64

Intel Mac

  • x86_64 natywnie
  • ARM64 przez QEMU (znaczne spowolnienie — do 90% wolniej)
  • Apple konczy wsparcie Intel Mac w MacOS — powoli legacy

Praktyczne tipy

# Sprawdz architekture obrazu
docker inspect node:20 --format '{{.Architecture}}'

# Wymus konkretna platforme w build
docker build --platform linux/amd64 -t myimg .

# Multi-arch build (potrzebuje buildx + emulacji)
docker buildx create --use
docker buildx build --platform linux/amd64,linux/arm64 -t user/img:latest --push .

# Performance: bind mounts SA WOLNE na macOS (przez VM)
# Dla node_modules itp uzywaj NAMED VOLUMES zamiast bind
volumes:
  - .:/app
  - /app/node_modules    # named volume — szybkie

Rekomendacja 2026

  • Daily dev na M-series Mac → OrbStack (najszybszy, ladny UI)
  • Free / OSS / korporacja unika commercial → Colima
  • Standard z extensions, K8s → Docker Desktop
  • Server / CI / automation → Colima w trybie headless
