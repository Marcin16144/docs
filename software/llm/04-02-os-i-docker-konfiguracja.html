Porownanie narzedzi (2026)

Ollama ★ (rekomendowany dla wiekszosci)

Co to: Najprostszy serwer LLM. CLI + API + biblioteka modeli.

Plusy:

  • Zero konfiguracji — ollama run llama3.3 i dziala
  • Auto-download modeli z biblioteki
  • API kompatybilne z OpenAI
  • Dziala na wszystkich OS (Mac, Win, Linux)
  • Auto GPU detection (CUDA, Metal, ROCm)
  • Aktywny rozwoj, ogromna spolecznosc

Minusy:

  • Mniej kontroli niz llama.cpp
  • Mniej parametrow konfiguracji niz vLLM
  • Brak tensor parallelism (multi-GPU dla jednego modelu)
# Instalacja
brew install ollama              # Mac
# Pobierz instalator z ollama.com  Windows
curl -fsSL https://ollama.com/install.sh | sh   # Linux

# Uzycie
ollama pull llama3.3:70b
ollama run llama3.3:70b
ollama serve                    # API on localhost:11434

LM Studio ★ (najlepszy GUI)

Desktop GUI z chatem, biblioteka modeli, lokalnym serwerem API.

Plusy: najlepsze GUI dla niezaawansowanych, wbudowane wyszukiwanie modeli z HuggingFace, visual chat (jak ChatGPT), API OpenAI-compat, profile inferencji, wsparcie multi-modal.

Minusy: closed-source (free, ale nie open), ciezszy niz Ollama, mniej elastyczny dla automatyzacji.

Najlepszy dla: osob ktore chca "kliknac i dziala".

llama.cpp (najwiecej kontroli)

Niskopoziomowy serwer w C++. Ollama uzywa llama.cpp pod spodem.

Plusy: najszybszy CPU inference, pelna kontrola, najmniejsze zuzycie pamieci, wsparcie Vulkan/Metal/CUDA/ROCm.

Minusy: wymaga kompilacji, steeper learning curve.

git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp
cmake -B build -DGGML_CUDA=ON   # NVIDIA
# lub: -DGGML_METAL=ON           # Mac
cmake --build build --config Release -j

vLLM ★ (produkcja)

Wysokowydajny serwer LLM od UC Berkeley.

Plusy: najwyzszy throughput (2-10x szybszy niz Ollama dla wielu requestow), PagedAttention, continuous batching, OpenAI-compat API, tensor parallelism (multi-GPU), speculative decoding.

Minusy: tylko Linux (oficjalnie), tylko NVIDIA, wymaga Pythona, wiecej setupu.

pip install vllm
vllm serve meta-llama/Llama-3.3-70B-Instruct \
    --gpu-memory-utilization 0.9 \
    --quantization awq

Porownanie systemow operacyjnych

macOS (Apple Silicon M1-M4)

Plusy

  • Unified memory — calosc RAM dla GPU bez transferu
  • 24-192 GB "VRAM" (zaleznie od modelu)
  • Natywny Metal backend → swietna wydajnosc per Watt
  • MLX framework — najszybszy na Apple Silicon
  • Cichy, niski pobor energii (~30W idle)

Minusy

  • Brak CUDA — niektore biblioteki niedostepne
  • Wolniejsze pure throughput vs RTX 4090/5090
  • Wiekszosc poradnikow zaklada NVIDIA
  • Trening duzych modeli (>13B) wolny

Wydajnosc Llama 3.1 8B Q4_K_M:

HardwareTokens/s
M1 (16GB)~20 t/s
M2 Pro (32GB)~30 t/s
M3 Max (64GB)~45 t/s
M4 Max (128GB)~55 t/s
M4 Ultra Studio (256GB)~70 t/s

Windows

Plusy

  • Natywne CUDA, najszybsze na NVIDIA
  • Najlepszy hardware-to-price (RTX 4090 ~$1500)
  • Gaming-tier sprzet dziala
  • Dobry support narzedzi GUI

Minusy

  • vLLM nie ma natywnego support (tylko WSL2)
  • Path issues, Python issues
  • Antywirus moze spowalniac
# Opcja A: Natywnie (Ollama)
# Pobierz z ollama.com, run installer

# Opcja B: WSL2 dla Linux-only tools (vLLM)
wsl --install -d Ubuntu
# W Ubuntu:
curl -fsSL https://ollama.com/install.sh | sh
nvidia-smi   # sprawdz GPU access

WSL2 tipy: Trzymaj pliki w /home/user/, nie /mnt/c/. Zwieksz pamiec w ~/.wslconfig:

[wsl2]
memory=64GB
processors=12

Linux

Plusy

  • Najlepsze wsparcie ML — wszystko dziala
  • vLLM, Triton, TensorRT-LLM tylko tu
  • Pelna kontrola nad systemem
  • Najszybszy Docker (kontenery natywnie)

Minusy

  • Wymaga doswiadczenia z Linuxem
  • Driver issues (NVIDIA, CUDA versions)
  • Setup zajmuje wiecej czasu

Setup Ubuntu 24.04 + NVIDIA:

sudo ubuntu-drivers autoinstall
sudo reboot

wget https://developer.download.nvidia.com/compute/cuda/repos/ubuntu2404/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i cuda-keyring_1.1-1_all.deb
sudo apt update && sudo apt install -y cuda-toolkit-12-6

curl -fsSL https://ollama.com/install.sh | sh

Dlaczego Docker na Mac to ZLY pomysl dla LLM?

Mac (Apple Silicon)
Docker Desktop:
← Tu jest problem
Linux VM (x86_64 emulation)
← LLM tutaj
Container
↑
Brak dostepu do Apple GPU/Metal!
Brak unified memory!

Konsekwencje: brak Metal (GPU) → wszystko na CPU, emulacja x86 → kolejna degradacja, brak access do unified memory, 2-5x wolniej niz natywnie.

Wyjatek: Docker na Mac OK dla...

  • Vector DB (Qdrant, Postgres) — lekki workload
  • API serwery (twoja aplikacja, nie LLM)
  • Web UI (Open WebUI laczace sie z natywnym Ollama)
# Praktyka na Mac:
brew install ollama       # natywnie
ollama serve

# Web UI w Docker, laczy sie z natywnym Ollama:
docker run -d -p 3000:8080 \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  ghcr.io/open-webui/open-webui:main

Docker na Linux ★

Tu Docker shines. Marginalny overhead, pelny dostep do GPU.

# NVIDIA Container Toolkit
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | \
    sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
sudo apt update && sudo apt install -y nvidia-container-toolkit
sudo systemctl restart docker

# Test
docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu24.04 nvidia-smi

# Ollama w Docker
docker run -d --gpus=all -v ollama:/root/.ollama \
    -p 11434:11434 --name ollama ollama/ollama

# vLLM w Docker
docker run --gpus all \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    -p 8000:8000 --ipc=host \
    vllm/vllm-openai:latest \
    --model meta-llama/Llama-3.3-70B-Instruct

Docker Compose dla pelnego stacka (Linux + GPU)

version: '3.8'
services:
  ollama:
    image: ollama/ollama:latest
    ports: ["11434:11434"]
    volumes: [ollama:/root/.ollama]
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]

  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    ports: ["3000:8080"]
    environment:
      - OLLAMA_BASE_URL=http://ollama:11434
    depends_on: [ollama]

  qdrant:
    image: qdrant/qdrant:latest
    ports: ["6333:6333"]

volumes:
  ollama:
  qdrant:

Praktyczne setupy

Setup #1: Mac dla developera (M2/M3/M4)

# 1. Ollama natywnie
brew install ollama

# 2. Open WebUI (chat) - via Docker
docker run -d -p 3000:8080 \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  ghcr.io/open-webui/open-webui:main

# 3. Modele
ollama pull llama3.3:70b      # ~40GB, 64GB+ Mac
ollama pull qwen2.5-coder:7b  # do kodu
ollama pull deepseek-r1:8b    # reasoning

# 4. Use:
open http://localhost:3000

Setup #2: Windows + RTX 4090

# Opcja A: Ollama natywnie (najprostsze)
# Pobierz z ollama.com
ollama pull llama3.1:8b
ollama run llama3.1:8b

# Opcja B: WSL2 dla pelnego Linux stacka
wsl --install -d Ubuntu
# W Ubuntu:
curl -fsSL https://ollama.com/install.sh | sh
nvidia-smi   # GPU access via WSL CUDA

Setup #3: Linux serwer produkcyjny (vLLM)

sudo apt install -y docker.io nvidia-container-toolkit
sudo systemctl restart docker

docker run -d --gpus all \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    -p 8000:8000 --ipc=host \
    --name vllm --restart unless-stopped \
    -e HUGGING_FACE_HUB_TOKEN=$HF_TOKEN \
    vllm/vllm-openai:latest \
    --model meta-llama/Llama-3.3-70B-Instruct-AWQ \
    --quantization awq \
    --max-model-len 8192

Czeste bledy konfiguracji

  • ✗ Docker dla LLM na Macu — 2-5x wolniej, brak GPU
  • ✗ WSL1 zamiast WSL2 — brak GPU access
  • ✗ Modele w /mnt/c/ w WSL2 — wolny disk I/O
  • ✗ Brak NVIDIA drivers przed Docker
  • ✗ Antywirus skanujacy modele — wylacz exclusion
  • ✗ CPU model na laptop dla 70B — 0.5 t/s, nieuzywalne
  • ✗ Mac Mini 16GB dla 70B — OOM
  • ✗ Cudnn/CUDA mismatch — uzywaj nvidia-docker

Stack rekomendacje 2026

Solo dev, M3 Max 64GB

  • Ollama (natywnie)
  • Open WebUI (Docker)
  • Qdrant (Docker)
  • Continue.dev w VS Code

Solo dev, RTX 4090 Win

  • Ollama (natywnie) lub LM Studio
  • Continue / Cursor / Claude Code
  • WSL2 + vLLM jesli multi-GPU

Male biuro, Linux serwer

  • vLLM w Docker, Llama 3.3 70B AWQ
  • Open WebUI dla zespolu
  • Qdrant dla RAG
  • nginx + Authentik (SSO)
  • Langfuse (observability)

Privacy-first, no internet

  • Mac Studio M4 Ultra 256GB
  • lub Linux + RTX 6000 Ada 48GB
  • Ollama z 70B modelami
  • LlamaIndex + Chroma RAG
