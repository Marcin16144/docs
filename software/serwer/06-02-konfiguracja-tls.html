Schannel - rejestrowa konfiguracja

Windows uzywa Schannel jako natywna implementacja TLS. Konfiguracja przez rejestr w HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols. Wymaga restartu po zmianach.

# Skrypt PowerShell wylaczajacy stare protokoly
$base = "HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols"

$disable = @("SSL 2.0","SSL 3.0","TLS 1.0","TLS 1.1")
foreach ($p in $disable) {
    foreach ($side in "Client","Server") {
        $path = "$base\$p\$side"
        if (-not (Test-Path $path)) { New-Item -Path $path -Force | Out-Null }
        Set-ItemProperty -Path $path -Name "Enabled" `
                          -Value 0 -Type DWord -Force
        Set-ItemProperty -Path $path -Name "DisabledByDefault" `
                          -Value 1 -Type DWord -Force
    }
}

$enable = @("TLS 1.2","TLS 1.3")
foreach ($p in $enable) {
    foreach ($side in "Client","Server") {
        $path = "$base\$p\$side"
        if (-not (Test-Path $path)) { New-Item -Path $path -Force | Out-Null }
        Set-ItemProperty -Path $path -Name "Enabled" `
                          -Value 0xFFFFFFFF -Type DWord -Force
        Set-ItemProperty -Path $path -Name "DisabledByDefault" `
                          -Value 0 -Type DWord -Force
    }
}

# RESTART SERWERA - zmiany Schannel wymagaja reboot
Write-Warning "Restart serwera wymagany - Restart-Computer"

Cipher Suites

Cipher suite definiuje kombinacje algorytmow uzywanych w sesji TLS - key exchange + authentication + encryption + MAC. Mozilla SSL Configuration Generator (ssl-config.mozilla.org) jest standardem branzowym.

Trzy poziomy Mozilla

ProfilWsparcie klientowCipher suites
ModernFirefox 63+, Chrome 70+, iOS 12.1+Tylko TLS 1.3, ECDHE z AEAD
Intermediate (zalecany)Firefox 27+, Chrome 31+, IE 11+, Android 4.4+TLS 1.2 + 1.3, ECDHE-RSA/ECDHE-ECDSA z AES-GCM, ChaCha20
OldIE 6+, WinXP+, Java 6+Pelne wsparcie legacy - NIE dla nowych systemow

# Ustawienie listy w Group Policy / rejestrze
$key = "HKLM:\SOFTWARE\Policies\Microsoft\Cryptography\Configuration\SSL\00010002"

HTTP Security Headers

HSTS (HTTP Strict Transport Security)

Header instruujacy przegladarke aby przez okreslony czas nigdy nie laczyla sie po HTTP. Eliminuje atak SSL stripping (downgrade do HTTP).

<system.webServer>
  <httpProtocol>
    <customHeaders>
      <add name="Strict-Transport-Security"
           value="max-age=63072000; includeSubDomains; preload" />

      <!-- Inne security headers -->
      <add name="X-Content-Type-Options" value="nosniff" />
      <add name="X-Frame-Options" value="SAMEORIGIN" />
      <add name="Referrer-Policy" value="strict-origin-when-cross-origin" />
      <add name="Permissions-Policy"
           value="geolocation=(), microphone=(), camera=()" />
      <add name="X-XSS-Protection" value="0" />  <!-- deprecated, ale niektore tools wymagaja -->

      <!-- Usuniecie naglowkow ujawniajacych technology -->
      <remove name="X-Powered-By" />
      <remove name="X-AspNet-Version" />
      <remove name="Server" />
    </customHeaders>
  </httpProtocol>
</system.webServer>

HSTS preload

Dodanie domeny do listy Chrome HSTS Preload List (preloaded w przegladarkach) - przegladarka nigdy nie probuje HTTP. Wymaga: max-age >= 31536000, includeSubDomains, preload directive. Submit: hstspreload.org.

Uwaga: HSTS preload jest quasi-trwala decyzja - usuniecie z listy zajmuje wiele miesiecy. Stosowac dopiero po dokladnym testowaniu. Wszystkie subdomeny musza obslugiwac HTTPS poprawnie.

Content Security Policy (CSP)

CSP definiuje skad przegladarka moze ladowac zasoby (scripts, styles, images). Obrona przed XSS, clickjacking, mixed content.

<add name="Content-Security-Policy"
     value="default-src 'self';
            script-src 'self' https://www.googletagmanager.com;
            style-src 'self' 'unsafe-inline';
            img-src 'self' data: https:;
            font-src 'self';
            connect-src 'self' https://api.example.com;
            frame-ancestors 'self';
            base-uri 'self';
            form-action 'self';
            upgrade-insecure-requests;" />

<!-- Tryb report-only do testowania nowej polityki -->
<add name="Content-Security-Policy-Report-Only"
     value="default-src 'self'; report-uri /csp-report" />

OCSP Stapling

Bez stapling: klient sam pyta CA o status certyfikatu (OCSP query) - dodatkowy hop, prywatnosc. Z stapling: serwer dolacza podpisany OCSP response do certyfikatu - klient nie potrzebuje pytac CA.

# Sprawdzenie czy IIS uzywa OCSP stapling (default w nowych wersjach)
$cert = Get-ChildItem Cert:\LocalMachine\WebHosting | Select -First 1
$cert.Extensions | Where-Object { $_.Oid.FriendlyName -eq "Authority Information Access" }

# Test ze strony klienta
openssl s_client -connect example.com:443 -status < nul

Diagnostyka po stronie serwera

# Wersje protokolu wlaczone na serwerze (przez registr)
$base = "HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols"
Get-ChildItem $base | ForEach-Object {
    $proto = $_.PSChildName
    foreach ($side in "Client","Server") {
        $val = Get-ItemProperty "$($_.PSPath)\$side" -ErrorAction SilentlyContinue
        if ($val) {
            "{0,-15} {1,-8} Enabled={2}  DisabledByDefault={3}" -f $proto, $side, $val.Enabled, $val.DisabledByDefault
        }
    }
}

# Sprawdzenie aktywnych cipher suites

Best practices checklist

  • Wylaczyc SSLv2, SSLv3, TLS 1.0, TLS 1.1
  • Wlaczyc TLS 1.2 i TLS 1.3 (Server 2022+)
  • Cipher suites Mozilla Intermediate (lub Modern jezeli klienci na to pozwalaja)
  • Klucze RSA min. 2048 bit, ECDSA P-256/P-384
  • HSTS z max-age >= 1 rok, preload na produkcji
  • Security headers: X-Content-Type-Options, X-Frame-Options, Referrer-Policy
  • CSP - od report-only do enforce
  • OCSP stapling wlaczone
  • Server header / X-Powered-By usuniete
  • Test ssllabs.com/ssltest - cel A+
  • Regularne re-testy (raz na kwartal) - standardy ewoluuja
