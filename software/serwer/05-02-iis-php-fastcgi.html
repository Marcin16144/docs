PHP w IIS via FastCGI

Hosting PHP w IIS - instalacja, konfiguracja FastCGI, OPcache i tuning produkcyjny.

Architektura

PHP w IIS dziala przez modul FastCgiModule. Kazdy request *.php trafia do procesu php-cgi.exe uruchomionego osobno od w3wp.exe. FastCGI utrzymuje pulu instancji php-cgi (warm), recyclujac je co X requestow.

Instalacja CGI w IIS

# 1. Wlaczenie CGI feature
Install-WindowsFeature -Name Web-CGI

# 2. Pobranie PHP z windows.php.net (NTS x64)
$phpVer = "8.3.13"
$url = "https://windows.php.net/downloads/releases/php-$phpVer-nts-Win32-vs16-x64.zip"
Invoke-WebRequest -Uri $url -OutFile "$env:TEMP\php.zip"

Expand-Archive "$env:TEMP\php.zip" -DestinationPath "C:\PHP" -Force

# 3. Kopia php.ini
Copy-Item "C:\PHP\php.ini-production" "C:\PHP\php.ini"

# 4. Sprawdzenie
& "C:\PHP\php.exe" -v
& "C:\PHP\php.exe" -m  # lista zaladowanych modulow

Rejestracja PHP w FastCGI

# Rejestracja aplikacji FastCGI
& "$env:windir\system32\inetsrv\appcmd.exe" set config `
    -section:system.webServer/fastCgi `
    /+"[fullPath='C:\PHP\php-cgi.exe']" /commit:apphost

# Mapowanie *.php do handlera FastCGI
& "$env:windir\system32\inetsrv\appcmd.exe" set config `
    -section:system.webServer/handlers `
    /+"[name='PHP_via_FastCGI', `
        path='*.php', `
        verb='*', `
        modules='FastCgiModule', `
        scriptProcessor='C:\PHP\php-cgi.exe', `
        resourceType='Either', `
        requireAccess='Script']" /commit:apphost

# Dodanie index.php do listy default documents
& "$env:windir\system32\inetsrv\appcmd.exe" set config `
    -section:system.webServer/defaultDocument `
    /+"files.[value='index.php']" /commit:apphost

# Restart IIS
iisreset

Tuning FastCGI

# Konfiguracja parametrow FastCGI
& "$env:windir\system32\inetsrv\appcmd.exe" set config `
    -section:system.webServer/fastCgi `
    /[fullPath='C:\PHP\php-cgi.exe'].instanceMaxRequests:10000 `
    /[fullPath='C:\PHP\php-cgi.exe'].maxInstances:0 `
    /[fullPath='C:\PHP\php-cgi.exe'].idleTimeout:300 `
    /[fullPath='C:\PHP\php-cgi.exe'].activityTimeout:30 `
    /[fullPath='C:\PHP\php-cgi.exe'].requestTimeout:90 `
    /[fullPath='C:\PHP\php-cgi.exe'].queueLength:1000 `
    /commit:apphost
ParametrDefaultZalecane (produkcja)Opis
instanceMaxRequests20010000Recycling procesu po N requestach (chroni przed memory leakami)
maxInstances40 (auto)0 = automatyczne skalowanie wg obciazenia
idleTimeout300300Sek. nieaktywnosci przed terminacja procesu
activityTimeout3030-60Maks. czas oczekiwania na odpowiedz od PHP
requestTimeout9090-300Maks. czas obslugi requestu
queueLength10001000Bufor kolejki requestow gdy wszystkie procesy zajete

Tuning php.ini

; Ogolna wydajnosc
memory_limit = 256M               ; Limit pamieci per request (zwykle 128M-512M)
max_execution_time = 60           ; Sek. maks. dla requestu
max_input_time = 60               ; Sek. maks. parsowania danych
post_max_size = 32M               ; Maks. POST request size
upload_max_filesize = 32M         ; Maks. plik upload (musi byc <= post_max_size)
max_file_uploads = 20             ; Liczba plikow w jednym uploadzie

; Sesje
session.save_handler = files
session.save_path = "C:\inetpub\temp\PHP-Sessions"
session.gc_maxlifetime = 1440     ; Sek. waznosci sesji
session.cookie_httponly = 1
session.cookie_secure = 1         ; Tylko HTTPS
session.cookie_samesite = "Lax"
session.use_strict_mode = 1

; Timezone
date.timezone = "Europe/Warsaw"

; Bezpieczenstwo
expose_php = Off                  ; Ukrycie X-Powered-By PHP
allow_url_fopen = Off             ; Wylaczenie HTTP fopen (RCE prevention)
allow_url_include = Off           ; Wylaczenie include z URL (zawsze!)
display_errors = Off              ; Brak bledow do klienta
log_errors = On
error_log = "C:\inetpub\logs\PHP\error.log"

; OPcache - krytyczny dla wydajnosci
opcache.enable = 1
opcache.enable_cli = 0
opcache.memory_consumption = 256  ; MB
opcache.interned_strings_buffer = 16  ; MB
opcache.max_accelerated_files = 20000
opcache.revalidate_freq = 60      ; Co ile sek. sprawdzac mtime plikow
opcache.fast_shutdown = 1
opcache.validate_timestamps = 1   ; W produkcji = 0 + reset przy deploy
opcache.save_comments = 1         ; Wymagane dla niektorych frameworkow (Doctrine)

OPcache - dramatic performance

OPcache cache'uje skompilowane bytecode PHP w pamieci - bez niego kazdy request odswieza plik z dysku i kompiluje. Z OPcache aplikacja moze byc 5-10x szybsza.

Produkcja: Ustaw opcache.validate_timestamps = 0 i czysc cache po deployu (np. opcache_reset() via dedykowany endpoint, lub restart pool). Bez sprawdzania timestamps PHP omija sprawdzenie mtime - ogromne przyspieszenie ale wymaga manualnego resetu po updaecie kodu.

<?php
// status_opcache.php - diagnostyka
$status = opcache_get_status();
echo "Memory used:    " . round($status['memory_usage']['used_memory'] / 1024 / 1024, 2) . " MB\n";
echo "Memory free:    " . round($status['memory_usage']['free_memory'] / 1024 / 1024, 2) . " MB\n";
echo "Hits:           " . $status['opcache_statistics']['hits'] . "\n";
echo "Misses:         " . $status['opcache_statistics']['misses'] . "\n";
echo "Hit ratio:      " . round($status['opcache_statistics']['opcache_hit_rate'], 2) . "%\n";
echo "Cached scripts: " . $status['opcache_statistics']['num_cached_scripts'] . "\n";

// Reset (po deployu)
// opcache_reset();

WinCache (Microsoft Cache Extension)

WinCache to rozszerzenie Microsoftu dla PHP cachujace dane w pamieci wspoldzielonej (file system cache, user objects, sesje). Komplementarne do OPcache.

  • File cache - eliminuje stat() na popularnych plikach
  • Session cache - sesje w pamieci zamiast plikow
  • User cache - API podobne do APCu
  • Pobranie z github.com/microsoft/wincache

web.config - typowa aplikacja PHP

<configuration>
  <system.webServer>
    <defaultDocument>
      <files>
        <clear />
        <add value="index.php" />
        <add value="index.html" />
      </files>
    </defaultDocument>

    <rewrite>
      <rules>
        <!-- Pretty URLs - kierowanie wszystkiego do index.php (Laravel/Symfony pattern) -->
        <rule name="Pretty URLs">
          <match url="^(.*)$" />
          <conditions>
            <add input="{REQUEST_FILENAME}" matchType="IsFile"      negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          </conditions>
          <action type="Rewrite" url="index.php?{R:1}" />
        </rule>
      </rules>
    </rewrite>

    <security>
      <requestFiltering>
        <hiddenSegments>
          <add segment=".env" />
          <add segment="vendor" />
          <add segment="storage" />
        </hiddenSegments>
      </requestFiltering>
    </security>

    <httpProtocol>
      <customHeaders>
        <remove name="X-Powered-By" />
        <add name="X-Content-Type-Options" value="nosniff" />
        <add name="X-Frame-Options" value="SAMEORIGIN" />
      </customHeaders>
    </httpProtocol>
  </system.webServer>
</configuration>

Best practices produkcja

  • Tylko NTS x64 build PHP
  • Dedykowany App Pool z "No Managed Code" + ApplicationPoolIdentity
  • OPcache wlaczony, validate_timestamps=0 + reset po deployu
  • display_errors=Off, log_errors=On do dedykowanego logu
  • expose_php=Off, X-Powered-By usuniety
  • open_basedir restrykcja per witryna (chroni przed path traversal)
  • Folder sesji niedostepny przez HTTP (przeniesc poza wwwroot)
  • Regularna aktualizacja PHP - kazdy minor brings security fixes
