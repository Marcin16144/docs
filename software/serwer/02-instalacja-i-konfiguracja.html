Instalacja i konfiguracja Windows Server 2025

Kompletny przewodnik instalacji od pobrania ISO po wstepna konfiguracje serwera produkcyjnego.

Wymagania sprzetowe Windows Server 2025

Microsoft definiuje minimalne i zalecane wymagania sprzetowe. W srodowiskach produkcyjnych nalezy projektowac z wieksza rezerwa.

Dysk systemowy32 GB120 GB SSD/NVMe (system + log + crash dump)
SieciowkaGigabit Ethernet, PXE2x 10 GbE, NIC teaming dla redundancji

Uwaga: Windows Server 2025 wymaga procesora z instrukcjami POPCNT i SSE4.2. Starsze CPU (sprzed 2009 roku, np. niektore Xeony 5500) nie sa wspierane.

Pobieranie ISO i przygotowanie nosnika

Pobranie pliku ISO

Oficjalne zrodlo pobrania ISO Windows Server 2025:

  • Evaluation Center - 180-dniowa wersja testowa: microsoft.com/evalcenter
  • Volume Licensing Service Center (VLSC) - klienci z licencja Volume
  • Visual Studio / MSDN Subscriptions - dla deweloperow i partnerow
  • Azure Marketplace - obrazy gotowe do uruchomienia w chmurze

Tworzenie bootowalnego USB (Rufus)

Rufus to najpopularniejsze narzedzie do nagrywania ISO na USB. Nalezy uzyc nosnika minimum 8 GB.

# Etapy konfiguracji w Rufus:
# 1. Device:        Wybor nosnika USB
# 2. Boot selection: Plik ISO Windows Server 2025
# 3. Image option:   Standard Windows installation
# 4. Partition:      GPT (UEFI) lub MBR (legacy BIOS)
# 5. File system:    NTFS (lub FAT32 dla UEFI)
# 6. Cluster size:   Default
# 7. Start          Potwierdzenie nadpisania danych USB

Instalacja w maszynie wirtualnej

Hyper-V (rola Windows), VMware Workstation/ESXi oraz VirtualBox sa najpopularniejszymi hyperwizorami dla labow i produkcji.

# Tworzenie VM Hyper-V przez PowerShell
New-VM -Name "WS2025-LAB" -MemoryStartupBytes 4GB -Generation 2 `
       -NewVHDPath "D:\VMs\WS2025.vhdx" -NewVHDSizeBytes 80GB `
       -SwitchName "External"

# Wlaczenie Secure Boot i TPM (Generation 2)
Set-VMFirmware -VMName "WS2025-LAB" -EnableSecureBoot On
Set-VMSecurity -VMName "WS2025-LAB" -EncryptStateAndVmMigrationTraffic $true
Add-VMTPM -VMName "WS2025-LAB"

# Podlaczenie ISO i start
Set-VMDvdDrive -VMName "WS2025-LAB" -Path "D:\ISO\WS2025.iso"
Start-VM -Name "WS2025-LAB"

Wstepna konfiguracja po instalacji

Hostname, strefa czasowa, IP

# Zmiana nazwy serwera
Rename-Computer -NewName "SRV-AD01" -Restart

# Strefa czasowa (Polska)
Set-TimeZone -Id "Central European Standard Time"

# Statyczny adres IP
$idx = (Get-NetAdapter -Name "Ethernet").ifIndex
New-NetIPAddress -InterfaceIndex $idx -IPAddress 192.168.10.10 `
                 -PrefixLength 24 -DefaultGateway 192.168.10.1
Set-DnsClientServerAddress -InterfaceIndex $idx `
                           -ServerAddresses 192.168.10.5,8.8.8.8

# Wlaczenie zdalnego pulpitu
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' `
                 -Name "fDenyTSConnections" -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"

sconfig (Server Core menu)

W Server Core narzedzie sconfig uruchamiane z PowerShell daje menu tekstowe do podstawowych zadan. Opcje obejmuja: Domain/Workgroup, Computer Name, Remote management, Update settings, Network, Date/Time, Telemetry, Logoff, Restart, Shutdown.

Server Manager (GUI)

Centralny dashboard do zarzadzania lokalnym i zdalnymi serwerami w Desktop Experience. Pozwala dodawac role, instalowac funkcje, monitorowac zdarzenia, uruchamiac konsole MMC. Server Manager pozostaje, ale Microsoft rekomenduje migracje do Windows Admin Center.

Windows Admin Center (WAC)

Nowoczesne GUI w przegladarce zastepujace Server Manager i wiele konsol MMC. Dziala jako lokalny serwer HTTPS na porcie 6516 lub 443. WAC zarzadza serwerami fizycznymi, klastrami, Azure VM, kontenerami i Azure Stack HCI z jednego miejsca.

# Pobranie i instalacja WAC
$url = "https://aka.ms/WACDownload"
Invoke-WebRequest $url -OutFile "$env:TEMP\WAC.msi"
msiexec /i "$env:TEMP\WAC.msi" /qn /L*v wac-install.log `
        SME_PORT=443 SSL_CERTIFICATE_OPTION=generate

# Otwarcie w przegladarce
Start-Process "https://localhost:443"

PowerShell DSC - wprowadzenie

Desired State Configuration (DSC) to mechanizm konfiguracji infrastruktury jako kodu (IaC) wbudowany w PowerShell. Definiujemy stan docelowy w pliku .ps1, kompilujemy do .mof, a Local Configuration Manager (LCM) utrzymuje wezel w tym stanie.

# Prosta konfiguracja DSC instalujaca IIS
Configuration WebServerConfig {
    Import-DscResource -ModuleName PSDesiredStateConfiguration

    Node "localhost" {
        WindowsFeature IIS {
            Ensure = "Present"
            Name   = "Web-Server"
        }
        WindowsFeature ASP {
            Ensure    = "Present"
            Name      = "Web-Asp-Net45"
            DependsOn = "[WindowsFeature]IIS"
        }
        File DefaultPage {
            Ensure          = "Present"
            DestinationPath = "C:\inetpub\wwwroot\index.html"
            Contents        = "<h1>Hello DSC</h1>"
        }
    }
}

WebServerConfig -OutputPath "C:\DSC"
Start-DscConfiguration -Path "C:\DSC" -Wait -Verbose

Wskazowka: W nowych projektach Microsoft zaleca Azure Automanage Machine Configuration (nastepca Azure Policy Guest Configuration), ktory zastepuje klasyczne DSC w hybrydowych srodowiskach Azure Arc.

Pierwsze kroki bezpieczenstwa

  • Zaktualizowac system: Install-Module PSWindowsUpdate; Get-WindowsUpdate -Install -AcceptAll -AutoReboot
  • Wlaczyc BitLocker na dysku systemowym
  • Zalozyc konto admin (nie korzystac z wbudowanego Administrator)
  • Skonfigurowac firewall (zablokowac niepotrzebne porty)
  • Wlaczyc audit logging (auditpol)
  • Dolaczyc do domeny lub ustawic silne haslo lokalne
