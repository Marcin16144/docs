Firewall i bezpieczenstwo sieci

Windows Defender Firewall, IPSec, NPS, segmentacja i ochrona przed atakami DDoS.

Windows Defender Firewall with Advanced Security

Wbudowany firewall Windows obsluguje stateful packet inspection na warstwie Layer 3-4, profilowanie polaczen oraz integracje z IPSec. Konsola: wf.msc.

Profile sieci

ProfilKontekstDomyslne reguly
DomainPC dolaczony do domeny ADBardziej liberalny - GPO push regul, sharing dozwolony
PrivateSieci zaufane (dom, biuro)Network discovery i sharing dozwolone
PublicHotspoty, kawiarnieRestrykcyjny - blokowanie discovery

Reguly inbound i outbound

Firewall analizuje ruch w obu kierunkach. Domyslnie inbound jest blokowany (allowlist), outbound dozwolony (denylist). Reguly oceniane sa wedlug priorytetu: Block > Allow > Default.

# Tworzenie reguly inbound przez PowerShell
New-NetFirewallRule -DisplayName "HTTPS-Public" `
                    -Direction Inbound `
                    -Protocol TCP `
                    -LocalPort 443 `
                    -Action Allow `
                    -Profile Public,Private,Domain

# Reguly z ograniczeniem do konkretnego IP
New-NetFirewallRule -DisplayName "Mgmt-Allow-RDP" `
                    -Direction Inbound `
                    -Protocol TCP `
                    -LocalPort 3389 `
                    -RemoteAddress 10.0.0.0/8 `
                    -Action Allow

# Listing i wylaczanie regul
Get-NetFirewallRule -DisplayName "HTTPS-Public" |
    Get-NetFirewallPortFilter

Disable-NetFirewallRule -DisplayName "File and Printer Sharing*"

# Eksport / import zestawu regul (backup)
netsh advfirewall export "C:\backup\firewall.wfw"
netsh advfirewall import "C:\backup\firewall.wfw"

Best practice: Wszystkie zmiany regul firewall produkcyjnego nalezy robic przez GPO (Computer Configuration -> Windows Settings -> Security Settings -> Windows Defender Firewall with Advanced Security), nie lokalnie. Daje to wersjonowanie, audytowalnosc i jednolitosc.

IPSec - polityki uwierzytelniania i szyfrowania

IPSec dziala na warstwie Layer 3 i pozwala wymusic uwierzytelnianie/szyfrowanie ruchu IP miedzy komputerami niezaleznie od aplikacji. W Windows IPSec definiuje sie przez Connection Security Rules w wf.msc.

Typ regulyZastosowanie
IsolationKompletna izolacja - tylko zaufane komputery komunikuja sie ze soba
Authentication ExemptionWyjatki dla okreslonych adresow (DC, urzadzenia bez IPSec)
Server-to-ServerTylko miedzy konkretnymi serwerami (np. SQL <-> App)
TunnelSite-to-site VPN miedzy gateway-ami
# Tworzenie reguly bezpieczenstwa polaczen IPSec
New-NetIPsecRule -DisplayName "Require-AuthN-Internal" `
                 -InboundSecurity Require `
                 -OutboundSecurity Request `
                 -Profile Domain `
                 -KeyModule IKEv2 `
                 -Phase1AuthSet (Get-NetIPsecPhase1AuthSet -DisplayName "Default")

# Sprawdzenie aktywnych SA
Get-NetIPsecMainModeSA
Get-NetIPsecQuickModeSA

Network Policy Server (NPS)

NPS to implementacja serwera RADIUS/Diameter w Windows Server. Pozwala scentralizowac uwierzytelnianie urzadzen sieciowych - WiFi z 802.1x, VPN, switche z port-based access control.

Typowe scenariusze NPS

  • WiFi 802.1x z EAP-TLS - logowanie do WiFi za pomoca certyfikatow uzytkownika/maszyny
  • WiFi 802.1x z PEAP-MSCHAPv2 - logowanie haslem AD (mniej bezpieczne, latwiejsze wdrozenie)
  • VPN RADIUS - centralne uwierzytelnianie dla VPN/SSL VPN
  • Switche dostepowe (NAC) - dynamiczny VLAN, MAB (MAC Authentication Bypass)

Segmentacja sieci

Dobre architektury sieciowe rozdzielaja warstwy zaufania na osobne segmenty (VLAN, subnet, VPC). Limituje to wplyw kompromitacji - atakujacy w jednym segmencie nie ma swobodnego dostepu do innych.

StrefaCelFiltrowanie
Public / DMZSerwery widoczne z Internetu (web, mail, DNS)Tylko porty uslugi (80,443,25,53)
Application TierLogika biznesowa, APITylko z DMZ na port aplikacji
Database TierSQL, NoSQL, redisTylko z App Tier na port DB
ManagementRDP, SSH, monitoringWhitelist IP adminow, MFA
Active Directory / Tier 0DC, ADCSNajsilniejsze restrykcje, brak dostepu Internetu

Microsegmentacja - Zero Trust

Klasyczny perimeter (jeden firewall na brzegu) nie wystarcza w zlozonych srodowiskach. Zero Trust zaklada brak ufnosci wewnetrznej - kazdy ruch (tez wewnatrz LAN) wymaga autoryzacji.

  • Firewall Windows na kazdej maszynie (host-based) - wymuszony przez GPO
  • IPSec dla wymuszenia AuthN miedzy hostami
  • Azure Network Security Groups (NSG) na kazdej karcie VM w chmurze
  • Virtual Network Service Endpoints / Private Endpoints zamiast publicznych IP
  • Identity-based segmentation - dostep wg konta, nie tylko IP

Ochrona przed DDoS

Ataki DDoS przekraczaja mozliwosci pojedynczego serwera - rozwiazaniem jest filtrowanie ruchu jeszcze przed dotarciem do infrastruktury. Glowne kategorie:

WarstwaAtakMitygacja
L3/L4 (volumetric)UDP flood, SYN flood, NTP/DNS amplificationCloudflare, Azure DDoS Protection, AWS Shield, scrubbing centers
L7 (application)HTTP flood, slowloris, low & slowWAF (rate limiting, captcha, fingerprinting)
ReflectionAmplifikowane odpowiedzi przez UDPFiltrowanie odpowiedzi z amplifierow, ingress filtering BCP38

Azure DDoS Protection

  • Basic - automatyczne, darmowe, chroni infrastrukture Azure (jest zawsze aktywne)
  • Standard / IP Protection - dedykowana ochrona zasobow, ML-based detection, telemetria, raporty post-attack

Cloudflare

  • Anycast network - 300+ POP rozproszonych globalnie
  • Free tier oferuje juz solidna ochrone L7
  • WAF z OWASP CRS, bot management, rate limiting
  • "I am Under Attack" mode - JavaScript challenge dla wszystkich requestow

Dynamic IP Restrictions w IIS

Wbudowany w IIS modul ograniczajacy liczbe requestow z IP - prosta ochrona aplikacyjna.

<system.webServer>
  <security>
    <dynamicIpSecurity>
      <denyByConcurrentRequests
        enabled="true" maxConcurrentRequests="20" />
      <denyByRequestRate
        enabled="true"
        maxRequests="50"
        requestIntervalInMilliseconds="1000" />
    </dynamicIpSecurity>
  </security>
</system.webServer>

Best practices

  • Default deny inbound - reguly tylko dla potrzebnych portow
  • Outbound rowniez restrykcyjny (egress filtering) na serwerach krytycznych
  • Logging firewalla wlaczony - log do %SystemRoot%\System32\LogFiles\Firewall
  • Audit firewallowy w Event Viewer 5152, 5157 (drop), 5156 (allow)
  • Dla aplikacji wystawionych do Internetu zawsze WAF + DDoS protection przed IIS
  • Regularne testy penetracyjne i sprawdzanie poprawnosci regul
