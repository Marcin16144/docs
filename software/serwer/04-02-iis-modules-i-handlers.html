IIS Modules i Handlers

Pipeline przetwarzania requestu - kluczowe modules i handlers w IIS.

Pipeline IIS - przeglad

Kazdy HTTP request przechodzi przez sekwencje events w pipeline IIS. Modules reaguja na te events (np. logowanie, autoryzacja, kompresja). Handler generuje odpowiedz (np. wykonanie skryptu, serwowanie pliku).

Etapy pipeline (HTTP events)

EventCo sie dzieje
BeginRequestRozpoczecie obslugi requestu
AuthenticateRequestIdentyfikacja uzytkownika (Anonymous, Basic, Windows, Forms)
AuthorizeRequestSprawdzenie czy ma dostep do zasobu
ResolveRequestCacheSprawdzenie cache - moze omijac dalsze etapy
MapRequestHandlerWybor handlera do wygenerowania odpowiedzi
AcquireRequestStateZaladowanie session/state
PreRequestHandlerExecutePrzed wykonaniem handlera
ExecuteRequestHandlerWlasciwe wykonanie handlera (generacja odpowiedzi)
PostRequestHandlerExecutePo wykonaniu
ReleaseRequestStateZwolnienie state
UpdateRequestCacheAktualizacja cache
LogRequestZapis do logu
EndRequestKoniec obslugi

Native vs Managed modules

TypJezykWydajnoscPrzyklady
NativeC++ (DLL kompilowane do nativecode)Bardzo wysokaHttpLoggingModule, StaticCompressionModule, RequestFilteringModule
Managed.NET (CLR)Wolniejsze (CLR overhead)FormsAuthenticationModule, OutputCacheModule, RoleManager

Wskazowka wydajnosciowa: Im mniej modulow, tym szybszy pipeline. Dla aplikacji prostych (np. statyczna strona, reverse proxy) mozna wylaczyc niepotrzebne managed modules na poziomie web.config przez <remove name="..."/>.

Kluczowe wbudowane modules

RequestFilteringModule

Filtruje requesty na podstawie URL, naglowkow, rozmiaru. Pierwsza linia obrony przed atakami.

<system.webServer>
  <security>
    <requestFiltering removeServerHeader="true">
      <requestLimits maxAllowedContentLength="30000000"
                      maxUrl="4096"
                      maxQueryString="2048" />

      <denyUrlSequences>
        <add sequence=".." />
        <add sequence=":" />
        <add sequence="\" />
      </denyUrlSequences>

      <fileExtensions allowUnlisted="true">
        <add fileExtension=".config" allowed="false" />
        <add fileExtension=".cs"     allowed="false" />
        <add fileExtension=".vb"     allowed="false" />
        <add fileExtension=".bak"    allowed="false" />
        <add fileExtension=".log"    allowed="false" />
      </fileExtensions>

      <hiddenSegments>
        <add segment="App_Data" />
        <add segment="bin" />
        <add segment=".git" />
        <add segment="node_modules" />
      </hiddenSegments>

      <verbs allowUnlisted="false">
        <add verb="GET"     allowed="true" />
        <add verb="POST"    allowed="true" />
        <add verb="PUT"     allowed="true" />
        <add verb="DELETE"  allowed="true" />
        <add verb="OPTIONS" allowed="true" />
      </verbs>
    </requestFiltering>
  </security>
</system.webServer>

HttpLoggingModule

Generuje logi W3C Extended w C:\inetpub\logs\LogFiles. Standard formatu wspierany przez wszystkie analizatory logow.

<system.webServer>
  <httpLogging dontLog="false" selectiveLogging="LogAll" />
</system.webServer>

<system.applicationHost>
  <sites>
    <siteDefaults>
      <logFile logFormat="W3C"
               directory="%SystemDrive%\inetpub\logs\LogFiles"
               period="Daily"
               truncateSize="20971520"
               localTimeRollover="true"
               logExtFileFlags="Date,Time,ClientIP,UserName,SiteName,
                                ComputerName,ServerIP,Method,UriStem,UriQuery,
                                HttpStatus,Win32Status,BytesSent,BytesRecv,
                                TimeTaken,ServerPort,UserAgent,Cookie,
                                Referer,ProtocolVersion,Host,HttpSubStatus" />
    </siteDefaults>
  </sites>
</system.applicationHost>

StaticCompressionModule i DynamicCompressionModule

Kompresja gzip/brotli odpowiedzi. Static dla plikow statycznych (cached), Dynamic dla generowanych.

<system.webServer>
  <httpCompression directory="%SystemDrive%\inetpub\temp\IIS Temporary Compressed Files">
    <scheme name="br" dll="%Windir%\system32\inetsrv\iisbrotli.dll" />
    <scheme name="gzip" dll="%Windir%\system32\inetsrv\gzip.dll" />

    <staticTypes>
      <add mimeType="text/*"               enabled="true" />
      <add mimeType="application/javascript" enabled="true" />
      <add mimeType="application/json"     enabled="true" />
      <add mimeType="image/svg+xml"        enabled="true" />
      <add mimeType="*/*"                  enabled="false" />
    </staticTypes>
  </httpCompression>

  <urlCompression doStaticCompression="true" doDynamicCompression="true" />
</system.webServer>

WindowsAuthenticationModule

Wbudowane uwierzytelnianie domenowe (Kerberos/NTLM) - typowe dla intranetowych aplikacji.

<system.webServer>
  <security>
    <authentication>
      <anonymousAuthentication enabled="false" />
      <windowsAuthentication enabled="true">
        <providers>
          <add value="Negotiate" />
          <add value="NTLM" />
        </providers>
      </windowsAuthentication>
    </authentication>
  </security>
</system.webServer>

UrlMappings / RewriteModule

Statyczne mapowanie URL przez built-in module. Dla bardziej zlozonego: instalacja URL Rewrite Module.

OutputCache

Cache pelnych odpowiedzi (HTML, JSON) na poziomie IIS - bardzo wydajne dla zasobow rzadko sie zmieniajacych.

aspNetCoreModuleV2 (.NET Core / .NET 5+)

<system.webServer>
  <handlers>
    <add name="aspNetCore"
         path="*"
         verb="*"
         modules="AspNetCoreModuleV2"
         resourceType="Unspecified" />
  </handlers>

  <aspNetCore processPath="dotnet"
              arguments=".\MyApp.dll"
              hostingModel="inprocess"
              startupTimeLimit="120"
              requestTimeout="00:02:00">
    <environmentVariables>
      <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
    </environmentVariables>
  </aspNetCore>
</system.webServer>

FastCgiModule (PHP)

<system.webServer>
  <handlers>
    <add name="PHP_via_FastCGI"
         path="*.php"
         verb="*"
         modules="FastCgiModule"
         scriptProcessor="C:\PHP\php-cgi.exe"
         resourceType="Either"
         requireAccess="Script" />
  </handlers>

  <fastCgi>
    <application fullPath="C:\PHP\php-cgi.exe"
                 instanceMaxRequests="10000"
                 idleTimeout="300"
                 activityTimeout="30"
                 requestTimeout="90">
      <environmentVariables>
        <environmentVariable name="PHP_FCGI_MAX_REQUESTS" value="10000" />
        <environmentVariable name="PHPRC" value="C:\PHP" />
      </environmentVariables>
    </application>
  </fastCgi>
</system.webServer>

Kolejnosc handlerow

Handlery oceniane sa po kolei wedlug deklaracji w applicationHost.config / web.config. Pierwszy pasujacy handler obsluguje request. Dlatego custom handlery nalezy umieszczac przed StaticFileModule.

# Listing handlerow przez PowerShell
Get-WebHandler | Select Name, Path, Verb, ScriptProcessor, Modules

# Listing modulow
Get-WebGlobalModule
Get-WebManagedModule

# Wylaczenie modulu (per site)
Remove-WebConfigurationProperty -PSPath "IIS:\Sites\Default Web Site" `
                                 -Filter "system.webServer/modules" `
                                 -Name "." `
                                 -AtElement @{name='WindowsAuthenticationModule'}

Failed Request Tracing (FREB)

FREB pokazuje pelny przebieg requestu przez pipeline z czasem kazdego eventu. Niezastapiony przy debugowaniu - zwlaszcza dla URL Rewrite, autoryzacji, ARR.

# Wlaczenie tracingu (raz)
Install-WindowsFeature Web-Http-Tracing
& "$env:windir\system32\inetsrv\appcmd.exe" set config "Default Web Site" `
    -section:system.webServer/tracing/traceFailedRequests `
    /+"[path='*',customActionExe='',statusCodes='400-599']"

# Logi FREB w
# C:\inetpub\logs\FailedReqLogFiles\W3SVC{SiteId}\

Best practices

  • Wylaczac niepotrzebne managed modules dla wydajnosci
  • RequestFilteringModule skonfigurowany restrykcyjnie (whitelist verbs, deny extensions)
  • Static + Dynamic compression wlaczone na poziomie serwera
  • Dla .NET Core - poole z "No Managed Code", aspNetCoreModuleV2 in-process
  • Dla PHP - FastCGI z dedykowanym poolem
  • Logi W3C z minimum: ClientIP, Method, UriStem, HttpStatus, TimeTaken, UserAgent
  • Failed Request Tracing wlaczone na czas debugowania, wylaczone produkcyjnie (wydajnosc)
