Aktualizacje i patchowanie

Strategie patch managementu - od WSUS po Hot Patching w Windows Server 2025.

Patch Tuesday i cykl wydan

Microsoft publikuje aktualizacje bezpieczenstwa w drugi wtorek miesiaca (Patch Tuesday) - zwykle ok. 18-19 UTC. Dodatkowe aktualizacje out-of-band (OOB) sa rzadkie i dotycza krytycznych podatnosci.

Typ aktualizacjiCzestotliwoscCharakterystyka

Cumulative Update (C/D)Trzeci/czwarty tydzienPreview - opcjonalne, do testowania
Out-of-band (OOB)Ad-hocPilne CVE, np. wormable
Servicing Stack Update (SSU)Wraz z LCUPoprawki samego mechanizmu update

Windows Update for Business (WUfB)

WUfB pozwala kontrolowac timing aktualizacji bez wlasnej infrastruktury - serwery dalej pobieraja z Microsoft Update, ale z opoznieniem konfigurowalnym przez GPO/Intune.

# Konfiguracja WUfB przez PowerShell (rejestr)
$key = "HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate"

# Defer Quality Updates (security) o 7 dni
Set-ItemProperty -Path $key -Name "DeferQualityUpdates" -Value 1 -Type DWord
Set-ItemProperty -Path $key -Name "DeferQualityUpdatesPeriodInDays" -Value 7 -Type DWord

# Defer Feature Updates o 30 dni
Set-ItemProperty -Path $key -Name "DeferFeatureUpdates" -Value 1 -Type DWord
Set-ItemProperty -Path $key -Name "DeferFeatureUpdatesPeriodInDays" -Value 30 -Type DWord

# Pause na 35 dni (max)
Set-ItemProperty -Path $key -Name "PauseQualityUpdatesStartTime" `
                 -Value (Get-Date -Format "yyyy-MM-ddTHH:mm:ssZ") -Type String

WSUS - Windows Server Update Services

WSUS jest tradycyjnym rozwiazaniem on-premises - serwer pobiera aktualizacje z Microsoft Update, a klienci wewnetrzni pobieraja z WSUS-a. Pozwala oszczedzac pasmo i zatwierdzac patche manualnie.

Status WSUS: W Windows Server 2025 WSUS jest deprecated (oznaczony jako "feature in maintenance"). Microsoft rekomenduje migracje do Microsoft Intune lub Microsoft Endpoint Configuration Manager + cloud attach.

# Instalacja WSUS (mimo deprecation, wciaz wspierane)
Install-WindowsFeature -Name UpdateServices `
                       -IncludeManagementTools

# Post-install dla content path
& "C:\Program Files\Update Services\Tools\WsusUtil.exe" `
    postinstall CONTENT_DIR=D:\WSUS

# Synchronizacja z Microsoft Update (initial)
$wsus = Get-WsusServer
$sub  = $wsus.GetSubscription()
$sub.StartSynchronization()

# Konfiguracja klientow przez GPO
# Computer Configuration -> Administrative Templates
#   -> Windows Components -> Windows Update
#       -> Specify intranet Microsoft update service location:
#          http://wsus.contoso.local:8530

Microsoft Endpoint Configuration Manager (MECM/SCCM)

MECM (kiedys SCCM) jest enterprise platforma do zarzadzania aktualizacjami, oprogramowaniem, konfiguracja i deploymentem OS. Wspiera setki tysiecy hostow w jednej infrastrukturze.

  • Software Update Point (SUP) - integracja z WSUS
  • Update groups - organizacja patchy w kolekcje
  • Maintenance windows - okna serwisowe per kolekcja
  • Compliance reporting - raporty zgodnosci
  • Co-management - integracja z Intune (cloud attach)

Microsoft Intune (cloud-based)

Intune (cze Microsoft 365 / Endpoint Manager) to chmurowa platforma MDM/MAM. Oferuje rownoleznie zarzadzanie aktualizacjami przez Update Rings, Driver Update Profiles i Quality Update Profiles.

ProfilCel
Update RingPolityka deferral i restart dla grupy urzadzen
Feature Update ProfileWymuszenie konkretnej wersji Windows (np. 24H2)
Quality Update ProfileWymuszenie konkretnego LCU (mass deployment)
Driver Update ProfileAkceptacja sterownikow Windows Update
Expedite Quality UpdatePilny deployment poza standardowym ringiem

Hot Patching - Windows Server 2025

Game changer: Windows Server 2025 (Datacenter: Azure Edition) wspiera Hot Patching - aktualizacje krytyczne instalowane bez restartu! Funkcja wczesniej dostepna tylko w Azure, teraz dostepna szerzej.

Jak dziala Hot Patch

  • Patche kernel/binary loadowane do pamieci procesu w czasie pracy systemu
  • Co 3 miesiace baseline reboot (cumulative cold patch)
  • Pomiedzy baselineami 2 miesiace hot patches (bez restartu)
  • Wymaga: WS 2025 Datacenter: Azure Edition lub Windows Server 2025 Hot Patching service
  • Wlaczenie: Azure Update Manager + Hot Patch enrollment
# Sprawdzenie aktualnego stanu Hot Patch
Get-WindowsCapability -Online | Where-Object Name -like "*HotPatch*"

# Status Azure Edition
$os = Get-ComputerInfo
$os.OsName  # "Windows Server 2025 Datacenter: Azure Edition"

# Wlaczenie hot patching przez Azure Update Manager (preferowane)
# Azure Portal -> Update Manager -> Maintenance Configuration
# -> Reboot setting: Never reboot
# -> Patch type: Hotpatch

Strategia patchingu - test/pilot/production

Bezposrednie wdrozenie patchy na produkcji to ryzyko. Standardowy proces ringi:

RingSkalaCelTiming
Insider/Preview1-3 maszyny dev/testWczesna detekcja problemow z C/D releasesD-7
Pilot5-10% maszyn (dev, IT)Walidacja kompatybilnosci aplikacjiD+1 (Patch Tuesday)
Production - Wave 130% (low-criticality)Stopniowy roll-outD+7
Production - Wave 240% (mid-criticality)Po pozytywnej Wave 1D+14
Production - Wave 330% (mission-critical)Krytyczne serwery na koniecD+21

Maintenance windows

Okna serwisowe powinny byc:

  • Zaplanowane i komunikowane min. 7 dni wczesniej
  • W godzinach najmniejszego obciazenia (zwykle nocne, weekendy)
  • Ograniczone czasowo (max 4-6h, potem rollback)
  • Z assigned operatorem (kto pilnuje)
  • Z planem rollback (snapshot, backup pre-patch)
  • Dla klastrow - rolling update (jeden node po drugim)

PSWindowsUpdate

# Modul PowerShell dla Windows Update
Install-Module PSWindowsUpdate -Force -AllowClobber
Import-Module PSWindowsUpdate

# Lista oczekujacych aktualizacji
Get-WindowsUpdate

# Lista aktualizacji z konkretnej kategorii
Get-WindowsUpdate -Category 'Security Updates'

# Instalacja wszystkich
Install-WindowsUpdate -AcceptAll -AutoReboot

# Instalacja konkretnej KB
Install-WindowsUpdate -KBArticleID KB5001234 -AcceptAll

# Historia patchy
Get-WUHistory | Select Date, Title, Result | Format-Table -AutoSize

# Odinstalowanie KB
Remove-WindowsUpdate -KBArticleID KB5001234 -NoRestart

Patch validation post-install

  • Sprawdzenie zainstalowanej wersji: winver lub systeminfo
  • Lista zainstalowanych KB: wmic qfe list lub Get-HotFix
  • Walidacja: ping, RDP, kluczowe uslugi (IIS, SQL), API health endpoints
  • Sprawdzenie Event Viewer (System log) na bledy bootu/uslug
  • Zewnetrzny monitoring (Pingdom, Nagios, Datadog) musi raportowac OK

Best practices

  • Test patchy w srodowisku staging zanim trafia na produkcje
  • Snapshot/backup przed zaaplikowaniem patcha (zwlaszcza na DC, SQL)
  • Klastry: rolling update, nigdy wszystkie nody jednoczesnie
  • Monitoring po patchu: 24-48h obserwacji (niektore problemy ujawniaja sie pozniej)
  • Subskrypcja na MSRC (Microsoft Security Response Center) i CVE feeds
  • Inwentaryzacja - kazdy serwer w CMDB/ITSM, znana wersja OS, role, ostatni patch
  • Automatyczna detekcja "drift" - serwery bez patcha wiekszego niz X dni
