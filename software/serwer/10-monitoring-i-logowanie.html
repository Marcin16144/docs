Monitoring i logowanie

Event Viewer, Performance Monitor, Sysmon i centralne SIEM - od logow lokalnych po wykrywanie zagrozen.

Event Viewer

Event Viewer (eventvwr.msc) to centralna konsola logow Windows. Logi rozdzielone sa na kilka glownych kategorii.

LogZawartosc
ApplicationZdarzenia generowane przez aplikacje (np. .NET, IIS, SQL)
SystemKomponenty systemu (sterowniki, uslugi, kernel)
SecurityLogon/logoff, audit policy, zmiany kont, sukces/porazka uwierzytelniania
SetupInstalacje, aktualizacje
Forwarded EventsLogi otrzymane z innych serwerow (Event Forwarding)
Applications and Services LogsSpecyficzne logi (PowerShell, Sysmon, IIS, AppLocker, Defender)

Audit Policy (auditpol)

Domyslna polityka audytu jest skromna. Microsoft Security Baseline rekomenduje wlaczenie szczegolowych kategorii.

# Lista aktualnych ustawien audytu
auditpol /get /category:*

# Ustawienie audytu Logon (success+failure) globalnie
auditpol /set /subcategory:"Logon" /success:enable /failure:enable
auditpol /set /subcategory:"Special Logon" /success:enable
auditpol /set /subcategory:"Process Creation" /success:enable
auditpol /set /subcategory:"Account Lockout" /success:enable /failure:enable
auditpol /set /subcategory:"Sensitive Privilege Use" /success:enable /failure:enable

# Wlaczenie zapisu CommandLine w Process Creation Event 4688
# (musi byc tez ustawione w GPO: Administrative Templates -> System -> Audit Process Creation)
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" `
    /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f

Windows Event Forwarding (WEF)

WEF pozwala scentralizowac zbieranie zdarzen z wielu serwerow do jednego kolektora bez agentow trzecich. Dziala przez WS-Management (WinRM) - protokol oparty na HTTP/HTTPS.

# Konfiguracja kolektora
wecutil qc /q

# Konfiguracja zrodla (kazdy klient)
winrm quickconfig -q
winrm set winrm/config/client/auth '@{Kerberos="true"}'
# Dodanie kolektora do uprawnien Network Service na log Security
# (rece lub przez GPO: Configure target Subscription Manager)

# Tworzenie subskrypcji w XML / GUI
wecutil cs subscription.xml

Data Collector Set

# Tworzenie data collector set z PowerShell
$dc = New-Object -ComObject "Pla.DataCollectorSet"
$dc.SetCredentials($null, $null)

# Wczytanie z XML (eksport z perfmon GUI)
$xml = Get-Content "C:\PerfTemplates\BaselineWindows.xml" -Raw
$dc.SetXml($xml)
$dc.Commit("Baseline_Windows", $null, 0x0003)

# Uruchomienie / zatrzymanie z linii polecen
logman start "Baseline_Windows"
logman stop  "Baseline_Windows"

Sysmon (Sysinternals)

System Monitor (Sysmon) to darmowy, bardzo zaawansowany agent loggingu od Sysinternals/Microsoft. Wzbogaca standardowe logi Windows o szczegoly nieosiagalne z pudelka - hash plikow, parent process, sciezki sieciowe, DNS queries, manipulacje rejestrem.

Kluczowe Event ID Sysmon

Event IDZnaczenie
1Process creation (z hash, command line, parent)
3Network connection
7Image loaded (DLLs)
8CreateRemoteThread (process injection)
10ProcessAccess (np. dostep do lsass = mimikatz)
11FileCreate
22DNSEvent (DNS queries)
24ClipboardChange
# Instalacja Sysmon z konfiguracja SwiftOnSecurity
Invoke-WebRequest -Uri "https://download.sysinternals.com/files/Sysmon.zip" `
                  -OutFile "$env:TEMP\Sysmon.zip"
Expand-Archive "$env:TEMP\Sysmon.zip" "$env:TEMP\Sysmon"

# Pobranie cenionej konfiguracji bazowej
Invoke-WebRequest `
  "https://raw.githubusercontent.com/SwiftOnSecurity/sysmon-config/master/sysmonconfig-export.xml" `
  -OutFile "C:\Sysmon\sysmonconfig.xml"

# Instalacja
& "$env:TEMP\Sysmon\Sysmon64.exe" -accepteula -i C:\Sysmon\sysmonconfig.xml

# Aktualizacja konfiguracji bez reinstalacji
& sysmon64 -c C:\Sysmon\sysmonconfig.xml

Centralizacja - SIEM

SIEM (Security Information and Event Management) zbiera logi z wielu zrodel, normalizuje je, koreluje i alertuje na anomalie. Bez SIEM logi sa rozproszone i nie sa praktyczne do detekcji.

Microsoft Sentinel (cloud SIEM)

Cloud-native SIEM Microsoftu zbudowany na Log Analytics. Integruje sie natywnie z Defender XDR, Azure resources, M365.

  • Data connectors: AAD logs, Defender, IIS, Windows Security Events, Syslog, Common Event Format
  • Analytic rules - zapytania KQL (Kusto Query Language) wykrywajace anomalia
  • Workbooks - dashboardy
  • Playbooks - automatyzacja przez Azure Logic Apps (SOAR)
  • UEBA (User and Entity Behavior Analytics)

Azure Monitor (telemetria)

Platforma do zbierania i analizy metryk i logow Azure resources i hybrydowych. Wykorzystuje Log Analytics jako backend - to samo zaplecze co Sentinel.

Splunk Enterprise

Lider rynku komercyjnego, bardzo elastyczny - moze chlonac dowolne formaty logow. Splunk SPL (Search Processing Language) bardzo bogaty.

Wazuh / OSSEC (open source)

Darmowy SIEM/EDR oparty na agencie OSSEC + ElasticSearch + Kibana. Wbudowane reguly OWASP, CIS, MITRE ATT&CK mappings. Dobre dla mniejszych srodowisk i labow.

Best practices loggingowe

  • Logi krytyczne (Security, PowerShell, Sysmon) zawsze do centralnego SIEM (lokalna kompromitacja kasuje logi)
  • Retencja zdarzen audytowych: minimum 90 dni (zgodne z GDPR/NIS2 nawet dluzej)
  • Wlaczyc PowerShell logging: Module Logging + Script Block Logging + Transcription
  • IIS logs w formacie W3C, parsowane do SIEM (np. fail2ban dla IIS)
  • Alerty na: 1102 (audit log cleared), 4625 burst, 4720 (admin creation), 7045 (new service)
  • Synchronizacja czasu (NTP) - bez tego korelacja zdarzen z roznych serwerow nie dziala
  • Regularne sprawdzanie poprawnosci alertow (false positive review)
