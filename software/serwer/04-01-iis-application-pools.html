IIS Application Pools

Izolacja aplikacji, recycling, identity i tryby pipeline - serce konfiguracji IIS.

Czym jest Application Pool

Application Pool (pula aplikacji) to granica izolacji aplikacji webowych w IIS. Kazdy app pool to osobny proces robotniczy w3wp.exe (Worker Process). Aplikacje w roznych poolach nie wplywaja na siebie - crash, memory leak czy CPU spike w jednej puli nie zatrzymuje pozostalych.

Zasada: Jedna witryna (lub grupa logicznie powiazanych aplikacji) = jeden Application Pool. Nigdy nie hostowac niepowiazanych aplikacji w tym samym poolu - jezeli jedna padnie, padaja wszystkie.

Architektura: w3wp.exe

Zarzadzanie poolami przez PowerShell

Import-Module WebAdministration

# Tworzenie poola
New-WebAppPool -Name "MyApp-Pool"

# Konfiguracja
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" -Name "managedRuntimeVersion" -Value "v4.0"
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" -Name "managedPipelineMode" -Value "Integrated"
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" -Name "enable32BitAppOnWin64" -Value $false

# Identity
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" -Name "processModel.identityType" -Value "ApplicationPoolIdentity"

# Listing wszystkich pool
Get-ChildItem IIS:\AppPools | Select-Object Name, State, ManagedRuntimeVersion

# Restart i stop
Restart-WebAppPool -Name "MyApp-Pool"
Stop-WebAppPool    -Name "MyApp-Pool"
Start-WebAppPool   -Name "MyApp-Pool"

# Stan procesow w3wp na zywo
Get-IISAppPool | ForEach-Object {
    [PSCustomObject]@{
        Pool   = $_.Name
        State  = $_.State
        PID    = (Get-IISAppPool -Name $_.Name).WorkerProcesses.ProcessId
    }
}

Recycling - kontrolowany restart

Recycling tworzy nowy proces w3wp.exe, przelacza nowe requesty na nowy proces, a stary konczy obsluge biezacych requestow przed terminacja. Cel: ograniczenie skutkow memory leakow, zwolnienie pamieci, zaladowanie nowej konfiguracji.

Triggery recyclingu

Specific Times (Schedule)brakWlaczyc o stalej godzinie nocnej
Private Memory Limit0 (unlimited)1500-2000 MB dla 32-bit, 4-8 GB dla 64-bit
Virtual Memory Limit0Tylko jezeli aplikacja ma znana górne wartosc

Configuration ChangetrueZostaw - zmiana web.config = recycle
# Recycling po przekroczeniu 1500 MB pamieci prywatnej
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" `
    -Name "recycling.periodicRestart.privateMemory" -Value 1500000

# Recycling o staej godzinie 03:00 (zamiast Regular Time Interval)
Clear-ItemProperty "IIS:\AppPools\MyApp-Pool" `
    -Name "recycling.periodicRestart.time"
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" `
    -Name "recycling.periodicRestart.time" -Value "00:00:00"
Add-WebConfiguration "/system.applicationHost/applicationPools/add[@name='MyApp-Pool']/recycling/periodicRestart/schedule" `
    -Value @{value="03:00:00"}

Idle Timeout

Idle timeout zatrzymuje proces w3wp gdy aplikacja nie ma ruchu przez X minut (domyslnie 20). Oszczedza pamiec, ale nastepny request bedzie wolny (cold start).

  • Aplikacje krytyczne / always-running: idleTimeout = 0 (nigdy)
  • + startMode = AlwaysRunning
  • + Application Initialization Module dla preloadu

ApplicationPoolIdentity jest wirtualnym kontem (SID) tworzonym dynamicznie. Mozna mu nadawac uprawnienia jak normalnemu kontu: icacls C:\AppData /grant "IIS APPPOOL\MyApp-Pool:(OI)(CI)RX". Dla dostepu do zasobow sieciowych (np. SMB share) trzeba uzywac konta domenowego (gMSA - Group Managed Service Account).

gMSA - Group Managed Service Account

Konto domenowe z automatycznie rotowanym haslem (kazde 30 dni). Idealne dla app pool wymagajacych dostepu do zasobow sieciowych (SMB, SQL Windows auth) bez recznego zarzadzania haslem.

# Na DC: utworzenie gMSA
New-ADServiceAccount -Name "gMSA-WebApp" `
                      -DNSHostName "gMSA-WebApp.contoso.local" `
                      -PrincipalsAllowedToRetrieveManagedPassword "WebServers"

# Na serwerze IIS:
Install-ADServiceAccount -Identity "gMSA-WebApp"
Test-ADServiceAccount     -Identity "gMSA-WebApp"

# Konfiguracja w app pool
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" -Name "processModel.identityType" -Value "SpecificUser"
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" -Name "processModel.userName"     -Value "CONTOSO\gMSA-WebApp$"
Set-ItemProperty "IIS:\AppPools\MyApp-Pool" -Name "processModel.password"     -Value ""

Wildcard application pools - hosting masowy

W shared hosting standardem jest jeden pool per witryna z osobna identity dla izolacji uzytkownikow. Skrypt automatyczny:

# Dla kazdej witryny, jezeli nie ma poola, utworz dedykowany
Get-ChildItem IIS:\Sites | ForEach-Object {
    $site     = $_.Name
    $poolName = "Pool-$site"

    if (-not (Test-Path "IIS:\AppPools\$poolName")) {
        New-WebAppPool -Name $poolName
        Set-ItemProperty "IIS:\AppPools\$poolName" -Name "managedRuntimeVersion" -Value "v4.0"
        Set-ItemProperty "IIS:\AppPools\$poolName" -Name "processModel.identityType" -Value "ApplicationPoolIdentity"

        # Limity zabezpieczajace
        Set-ItemProperty "IIS:\AppPools\$poolName" -Name "cpu.limit"          -Value 50000  # 50% CPU max
        Set-ItemProperty "IIS:\AppPools\$poolName" -Name "cpu.action"         -Value "Throttle"
        Set-ItemProperty "IIS:\AppPools\$poolName" -Name "recycling.periodicRestart.privateMemory" -Value 500000
    }
    Set-ItemProperty "IIS:\Sites\$site" -Name "applicationPool" -Value $poolName
}

Monitoring poola

# Aktywne worker processes
Get-IISAppPool | ForEach-Object {
    foreach ($wp in $_.WorkerProcesses) {
        $proc = Get-Process -Id $wp.ProcessId -ErrorAction SilentlyContinue
        [PSCustomObject]@{
            Pool      = $_.Name
            PID       = $wp.ProcessId
            CPU_Sec   = if ($proc) { $proc.CPU } else { 0 }
            Memory_MB = if ($proc) { [math]::Round($proc.PrivateMemorySize64/1MB, 0) } else { 0 }
            State     = $wp.State
        }
    }
} | Format-Table -AutoSize

# Aktywne requesty w poolu
Import-Module WebAdministration
Get-WebRequest | Where-Object {$_.AppPoolName -eq "MyApp-Pool"}

Best practices

  • Jeden pool per aplikacja (lub grupa powiazanych)
  • ApplicationPoolIdentity zawsze gdy mozliwe (gMSA tylko dla zewnetrznych zasobow)
  • Recycling oparty na private memory limit, nie na regular interval
  • Schedule recycling o stalej godzinie nocnej zamiast losowych intervalow
  • Aplikacje krytyczne: idleTimeout=0, startMode=AlwaysRunning, App Initialization
  • Monitoring rozmiaru w3wp.exe - alarmy na zblizajace sie limity
  • Logging Failed Request Tracing dla problemow startowych
