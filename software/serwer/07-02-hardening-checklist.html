Wylaczanie protokolow legacy

SMBv1 - krytyczne

SMBv1 jest podatny na EternalBlue / WannaCry / NotPetya. Nieuzywany od Windows 8 / Server 2012 - wylaczyc bezwzglednie.

# Sprawdzenie i wylaczenie SMBv1
Get-WindowsOptionalFeature -Online -FeatureName SMB1Protocol
Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol -NoRestart

# Lub przez registr
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\LanmanServer\Parameters" `
                 -Name SMB1 -Value 0 -Type DWord
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\LanmanWorkstation\Parameters" `
                 -Name SMB1 -Value 0 -Type DWord

# Wymuszenie SMB signing (chroni przed relay attacks)
Set-SmbServerConfiguration -RequireSecuritySignature $true -EnableSecuritySignature $true -Confirm:$false
Set-SmbClientConfiguration -RequireSecuritySignature $true -EnableSecuritySignature $true -Confirm:$false

NTLMv1 / LM

# LMCompatibilityLevel
# 0 - LM & NTLM
# 1 - LM & NTLM, use NTLMv2 if negotiated
# 2 - NTLM only
# 3 - NTLMv2 only (klient)
# 4 - NTLMv2 only (DC accept), refuse LM
# 5 - NTLMv2 only (DC accept), refuse LM & NTLM (zalecane!)

Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
                 -Name LmCompatibilityLevel -Value 5 -Type DWord

# Brak hash LM w SAM
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
                 -Name NoLMHash -Value 1 -Type DWord

LLMNR i NetBIOS

LLMNR (Link-Local Multicast Name Resolution) i NetBIOS sa wykorzystywane do Responder.py / NTLM relay attacks. Wylaczyc bezwzglednie.

# LLMNR
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\DNSClient" `
                 -Name "EnableMulticast" -Value 0 -Type DWord -Force

# NetBIOS over TCP/IP - per adapter
Get-CimInstance -Class Win32_NetworkAdapterConfiguration |
    Where-Object { $_.IPEnabled -eq $true } |
    ForEach-Object {
        $_.SetTcpipNetbios(2)  # 2 = Disabled
    }

Credential protection

Credential Guard (Windows Defender Credential Guard)

Credential Guard izoluje LSA (lsass.exe) w wirtualnym kontenerze opartym na Hyper-V (VBS - Virtualization-Based Security). Atakujacy z SYSTEM nie moze wyciagnac hashy/biletow z lsass nawet z mimikatz.

Windows Server 2025: Credential Guard jest domyslnie wlaczony na supportowanych systemach (TPM 2.0 + UEFI Secure Boot + Hyper-V). To wielki krok naprzod w bezpieczenstwie domeny.

# Sprawdzenie statusu Credential Guard
$dgs = Get-CimInstance -ClassName Win32_DeviceGuard `
                       -Namespace "root\Microsoft\Windows\DeviceGuard"
"Required Security: $($dgs.RequiredSecurityProperties)"
"Available:         $($dgs.AvailableSecurityProperties)"
"Running:           $($dgs.SecurityServicesRunning)"
# Running musi zawierac 1 (Credential Guard) i 2 (HVCI)

# Wlaczenie GPO:
# Computer Configuration -> Administrative Templates -> System -> Device Guard
#   Turn On Virtualization Based Security:
#     Platform Security Level:        Secure Boot and DMA Protection
#     Credential Guard Configuration: Enabled with UEFI lock

LSA Protection

# RunAsPPL = 1 oznacza ze lsass.exe jest Protected Process Light
# inne procesy (nawet z Local System) nie moga wstrzyknac kodu do lsass

Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
                 -Name "RunAsPPL" -Value 1 -Type DWord

Protected Users group

Czlonkowie grupy Protected Users w AD maja:

  • Brak NTLM authentication
  • Brak Kerberos pre-auth z DES/RC4 (tylko AES)
  • Krotsze TGT (4 godziny zamiast 10)
  • Brak default delegation
  • Brak credentials cached na maszynie
# Dodanie konta admina do Protected Users
Add-ADGroupMember -Identity "Protected Users" -Members "DomainAdmin1"

# WAZNE: Przed dodaniem przetestowac! Niektore aplikacje legacy moga przestac dzialac
# (np. Schedule Task ze stalym haslem - wymaga NTLM)

BitLocker

# Wlaczenie BitLocker na C: z TPM
Enable-BitLocker -MountPoint "C:" `
                 -EncryptionMethod XtsAes256 `
                 -UsedSpaceOnly `
                 -TpmProtector

# Backup recovery key do AD
Add-BitLockerKeyProtector -MountPoint "C:" -RecoveryPasswordProtector

$bl = Get-BitLockerVolume -MountPoint "C:"
$rk = $bl.KeyProtector | Where-Object { $_.KeyProtectorType -eq "RecoveryPassword" }
Backup-BitLockerKeyProtector -MountPoint "C:" -KeyProtectorId $rk.KeyProtectorId

# Sprawdzenie statusu
manage-bde -status

# Status wszystkich wolumenow
Get-BitLockerVolume | Format-Table MountPoint, EncryptionMethod, EncryptionPercentage, ProtectionStatus

Account policy

# Account lockout
net accounts /lockoutthreshold:5    # 5 nieudanych prob
net accounts /lockoutwindow:30      # liczone w ciagu 30 min
net accounts /lockoutduration:30    # blokada na 30 min

# Password policy (lub przez Default Domain Policy GPO)
net accounts /minpwlen:14           # min 14 znakow
net accounts /maxpwage:90           # zmiana co 90 dni
net accounts /minpwage:1            # nie czesciej niz raz na dzien
net accounts /uniquepw:24           # historia 24 haseł
net accounts /forcelogoff:0         # wymuszenie wylogowania po expiracji

# CIS rekomenduje:
# - Min 14 znakow (NIST 2017+ dopuszcza dlugie passphrase bez complexity)
# - Brak wymogu zmiany cyklicznej (NIST SP 800-63B) - tylko po podejrzeniu kompromitacji
# - MFA jako fundament zamiast czestych zmian hasla

Application Control - WDAC / AppLocker

# WDAC (Windows Defender Application Control) - wbudowany w Windows
# Zalecane dla nowych deployment
# AppLocker - starsze, ale szeroko uzywane w GPO

# Tworzenie polityki AppLocker (GUI: secpol.msc -> Application Control Policies)
# Domyslne reguly + konkretne whitelist:
#   - Allow: %WINDIR%\* (Windows binaries)
#   - Allow: %PROGRAMFILES%\* (apps installed by admin)
#   - Deny:  %TEMP%\*, %APPDATA%\* (writable by user)
#   - Deny:  PowerShell ISE (uzytkownicy bez admina)

# Skanowanie biezacych binarek do polityki
Get-AppLockerFileInformation -Directory "C:\Program Files" -Recurse -FileType Exe |
    New-AppLockerPolicy -RuleType Publisher,Hash -User "Everyone" |
    Set-AppLockerPolicy -Merge -Force

Defender for Endpoint (EDR)

  • Microsoft Defender Antivirus - wbudowany, free
  • Defender for Endpoint Plan 1/2 - cloud EDR, behavioral analytics, SIEM integration
  • Attack Surface Reduction (ASR) rules - blokowanie zachowan typowych dla malware
  • Tamper Protection - ochrona Defendera przed wylaczeniem
  • Cloud-delivered protection (MAPS) wlaczona
  • Real-time protection wlaczone na wszystkich serwerach
# Konfiguracja Defendera
Set-MpPreference -CloudBlockLevel High `
                  -CloudExtendedTimeout 50 `
                  -PUAProtection Enabled `
                  -EnableNetworkProtection Enabled `
                  -SubmitSamplesConsent SendSafeSamples `
                  -DisableRealtimeMonitoring $false

# ASR rules - kluczowe dla Office attack chains
$asrRules = @{
    "BE9BA2D9-53EA-4CDC-84E5-9B1EEEE46550" = "Block executable content from email"
    "D4F940AB-401B-4EFC-AADC-AD5F3C50688A" = "Block all Office apps from creating child processes"
    "3B576869-A4EC-4529-8536-B80A7769E899" = "Block Office apps from creating executable content"
    "75668C1F-73B5-4CF0-BB93-3ECF5CB7CC84" = "Block Office apps from injecting code into other processes"
    "D3E037E1-3EB8-44C8-A917-57927947596D" = "Block JavaScript or VBScript from launching downloaded executables"
    "5BEB7EFE-FD9A-4556-801D-275E5FFC04CC" = "Block execution of potentially obfuscated scripts"
}
$asrRules.GetEnumerator() | ForEach-Object {
    Set-MpPreference -AttackSurfaceReductionRules_Ids $_.Key -AttackSurfaceReductionRules_Actions Enabled
}

Hardening checklist - one-page summary

  • SMBv1 wylaczone, SMB signing required
  • NTLMv1 / LM wylaczone (LMCompatibilityLevel = 5)
  • LLMNR + NetBIOS wylaczone
  • Credential Guard wlaczony (default w 2025)
  • LSA Protection (RunAsPPL = 1)
  • BitLocker na wszystkich woluminach
  • TPM 2.0, UEFI Secure Boot wlaczone
  • Account lockout policy (5 prob, 30 min)
  • Password policy: min 14 znakow, NIST guidelines
  • MFA dla wszystkich admin accounts
  • PowerShell logging: Module + Script Block + Transcription
  • Constrained Language Mode dla nieadminow
  • Defender for Endpoint z ASR rules
  • WDAC / AppLocker - whitelisting aplikacji
  • Print Spooler wylaczony na serwerach nie-print
  • Remote Registry wylaczony
  • Audit Policy - pelne kategorie zgodnie z baseline
  • Sysmon wlaczony z konfiguracja SwiftOnSecurity
  • Logi do centralnego SIEM
  • Patche aktualne (max 30 dni opoznienia dla critical)
  • Firewall: default deny inbound, log dropped packets
  • Tier model wdrozony, separate admin accounts
  • LAPS dla local admin passwords
  • gMSA dla service accounts
  • Backup System State + test restore co miesiac
