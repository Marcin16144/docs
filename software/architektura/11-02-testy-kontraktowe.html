Testy kontraktowe

Consumer-driven contracts, Pact framework, weryfikacja providera i integracja z CI/CD.

Problem

User Service zmienia odpowiedz:
  Przed: { "name": "Jan", "email": "jan@ex.com" }
  Po:    { "fullName": "Jan", "emailAddress": "jan@ex.com" }

Order Service sie lamie — oczekuje "name" i "email"!

E2E testy sa wolne i kruche. Mocki moga byc nieaktualne. Testy kontraktowe weryfikuja kompatybilnosc bez uruchamiania obu serwisow.

Consumer-Driven Contracts

Konsument definiuje czego oczekuje. Provider musi spelnic oczekiwania wszystkich konsumentow.

Consumer A (oczekuje: name, email)
  ↓ publikuje kontrakt
Pact Broker (przechowuje kontrakty)
  ↓ provider weryfikuje
Provider (musi spelnic A + B)
  ↑ provider weryfikuje
Pact Broker
  ↑ publikuje kontrakt
Consumer B (oczekuje: name, phone)

Pact — Consumer Test

const provider = new PactV3({
  consumer: 'OrderService',
  provider: 'UserService'
});

describe('User Service Contract', () => {
  it('returns user details by ID', async () => {
    provider
      .given('user 123 exists')
      .uponReceiving('a request for user 123')
      .withRequest({
        method: 'GET',
        path: '/api/users/123',
        headers: { Accept: 'application/json' }
      })
      .willRespondWith({
        status: 200,
        body: {
          id: '123',
          name: like('Jan Kowalski'),
          email: like('jan@example.com'),
          role: term({
            generate: 'user',
            matcher: 'user|admin|editor'
          })
        }
      });

    await provider.executeTest(async (mockServer) => {
      const client = new UserApiClient(mockServer.url);
      const user = await client.getUser('123');
      expect(user.name).toBe('Jan Kowalski');
    });
  });
});

Pact — Provider Verification

const verifier = new Verifier({
  providerBaseUrl: 'http://localhost:3000',
  provider: 'UserService',
  pactBrokerUrl: 'https://pact.example.com',
  publishVerificationResult: true,
  providerVersion: process.env.GIT_SHA,

  stateHandlers: {
    'user 123 exists': async () => {
      await db.users.create({
        id: '123',
        name: 'Jan Kowalski',
        email: 'jan@example.com'
      });
    },
    'user 999 does not exist': async () => {
      await db.users.deleteAll();
    }
  }
});

await verifier.verifyProvider();

Pact Broker

Centralny serwer przechowujacy kontrakty i wyniki weryfikacji.

can-i-deploy

Sprawdzenie czy wersja serwisu moze byc bezpiecznie wdrozona:

npx pact-broker can-i-deploy \
  --pacticipant=UserService \
  --version=$(git rev-parse --short HEAD) \
  --to-environment=production

# ✓ OrderService (v3.1.0) — verified
# ✓ PaymentService (v2.0.1) — verified
# → Mozna wdrozyc!

Integracja z CI/CD

# Consumer CI:
- run: npm test                    # generuje kontrakty
- run: npx pact-broker publish ./pacts
    --consumer-app-version=$SHA

# Provider CI:
- run: npm run test:pact           # weryfikuj kontrakty
- run: npx pact-broker can-i-deploy
    --pacticipant=UserService
    --version=$SHA
    --to-environment=production
- run: ./deploy.sh
- run: npx pact-broker record-deployment
    --pacticipant=UserService
    --version=$SHA
    --environment=production

Pact Matchers

// like — ten sam typ, dowolna wartosc
body: { name: like('Jan') }

// eachLike — tablica tego samego ksztaltu
body: { orders: eachLike({
  id: like('ord-1'),
  total: decimal(99.99)
}) }

// term — regex
body: { status: term({
  generate: 'active',
  matcher: 'active|inactive'
}) }

// integer, decimal, boolean, string
body: {
  count: integer(5),
  price: decimal(19.99),
  active: boolean(true)
}

Kontrakty asynchroniczne

Pact wspiera kontrakty dla komunikacji event-driven (message-based):

new MessageConsumerPact({
  consumer: 'NotificationService',
  provider: 'OrderService'
})
.expectsToReceive('an order created event')
.withContent({
  orderId: like('ord-123'),
  customerEmail: like('jan@example.com'),
  total: decimal(299.99),
  items: eachLike({
    name: like('Product'),
    quantity: integer(1)
  })
})
.verify(async (message) => {
  await new OrderCreatedHandler().handle(message);
});
