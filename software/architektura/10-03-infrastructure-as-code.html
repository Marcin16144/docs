Terraform — podstawy

terraform {
  required_version = ">= 1.5"
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
  backend "s3" {
    bucket         = "my-terraform-state"
    key            = "prod/terraform.tfstate"
    region         = "eu-central-1"
    dynamodb_table = "terraform-locks"
  }
}

provider "aws" { region = var.aws_region }

resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  tags = { Name = "${var.project}-vpc" }
}

resource "aws_subnet" "public" {
  count             = 2
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.${count.index + 1}.0/24"
  availability_zone = data.aws_availability_zones.available.names[count.index]
}

Komendy Terraform

terraform init          # inicjalizacja
terraform plan -out=p   # dry run
terraform apply p       # zastosuj zmiany
terraform show          # aktualny stan
terraform destroy       # zniszcz infrastrukture
terraform fmt           # formatowanie
terraform validate      # walidacja

State Management

State mapuje zasoby w kodzie na rzeczywiste zasoby w chmurze.

Developer A: terraform apply
  → Lock state (DynamoDB)
  → Zmien infrastrukture
  → Update state → Unlock

Developer B: terraform apply (rownoczesnie)
  → Proba lock — ZABLOKOWANE
  → Czeka az A zakonczy
  1. Nigdy nie edytuj state recznie
  2. Remote state — S3/GCS/Azure Blob
  3. State locking — DynamoDB/Consul
  4. Encrypt state — zawiera wrazliwe dane
  5. State per srodowisko — oddzielne pliki

Pulumi — IaC w jezyku programowania

// index.ts — Pulumi w TypeScript
import * as aws from "@pulumi/aws";
import * as pulumi from "@pulumi/pulumi";

const config = new pulumi.Config();
const env = config.require("environment");

const vpc = new aws.ec2.Vpc("main-vpc", {
  cidrBlock: "10.0.0.0/16",
  enableDnsHostnames: true,
  tags: { Name: `${env}-vpc` }
});

// Petla — pelna moc TypeScript!
const azs = aws.getAvailabilityZones({ state: "available" });
const subnets = azs.then(zones =>
  zones.names.slice(0, 2).map((az, i) =>
    new aws.ec2.Subnet(`public-${i}`, {
      vpcId: vpc.id,
      cidrBlock: `10.0.${i + 1}.0/24`,
      availabilityZone: az
    })
  )
);

export const vpcId = vpc.id;

GitOps z ArgoCD

Git jako jedyne zrodlo prawdy. ArgoCD monitoruje repo i automatycznie synchronizuje klaster.

Developer → Git Push → Repo (manifesty K8s)
                           ↑
                     ArgoCD monitoruje
                           ↓
                    Kubernetes Cluster
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
spec:
  source:
    repoURL: https://github.com/org/k8s-manifests.git
    targetRevision: main
    path: apps/my-app/overlays/production
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  syncPolicy:
    automated:
      prune: true       # usun zasoby ktorych nie ma w repo
      selfHeal: true    # napraw reczne zmiany
