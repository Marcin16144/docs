Skalowalnosc i wydajnosc

Jak budowac systemy, ktore radza sobie z rosnacym obciazeniem.

Aktualizacja: 2026 — OpenTelemetry jako standard tracingu, edge computing (Cloudflare Workers KV, Fly.io, Vercel Edge) jako naturalna warstwa cache i obliczen blisko uzytkownika.

Typy skalowania

Wertykalne (Scale Up)

Zwiekszenie zasobow jednego serwera (CPU, RAM, dysk).

  • Prostsze w implementacji
  • Ma fizyczny limit
  • Jeden punkt awarii

Horyzontalne (Scale Out)

Dodanie kolejnych instancji serwera.

  • Teoretycznie nieograniczone
  • Wymaga load balancera
  • Zlozonosc przy stanie wspoldzielonym

Load Balancing

Algorytmy

  • Round Robin — po kolei do kazdej instancji
  • Least Connections — do instancji z najmniejsza liczba polaczen
  • IP Hash — staly serwer dla danego klienta
  • Weighted — proporcjonalnie do wagi/mocy serwera

Narzedzia: Nginx, HAProxy, AWS ALB/NLB, Traefik

Caching (Buforowanie)

Poziomy cache

  1. Przegladarka — HTTP cache headers (Cache-Control, ETag)
  2. CDN / Edge — Cloudflare CDN, Fastly, AWS CloudFront, Vercel Edge Network, Bunny CDN
  3. Edge KV / Edge runtime (2026): Cloudflare Workers KV / Durable Objects / Cache API, Vercel Edge Config / KV, Fly.io (regionalne instancje), Deno Deploy, AWS Lambda@Edge
  4. API Gateway — cache odpowiedzi API
  5. Aplikacja — Redis / Valkey, Memcached, Dragonfly, in-process cache (Caffeine, BigCache, ristretto)
  6. Baza danych — query cache, materialized views, indexed views

Strategie cache

StrategiaOpisUzycie
Cache-AsideAplikacja zarzadza cacheOgolne zastosowanie
Read-ThroughCache sam pobiera z bazyCzesty odczyt
Write-ThroughZapis do cache i bazy jednoczesnieSpojnosc wazna
Write-BehindZapis do cache, async do bazyWydajnosc zapisu

Cache Invalidation

  • TTL (Time To Live) — automatyczne wygasniecie
  • Event-based — invalidacja przy zmianie danych
  • Version-based — nowa wersja = nowy klucz cache

Wzorce wydajnosciowe

Async Processing

Przetwarzanie zadan w tle — nie blokuj odpowiedzi API.

POST /api/reports → 202 Accepted { "jobId": "abc123" }
GET  /api/reports/abc123/status → { "status": "processing" }
GET  /api/reports/abc123/status → { "status": "completed", "url": "..." }

Pagination

Nigdy nie zwracaj wszystkich rekordow.

  • Offset-based: ?page=3&limit=20
  • Cursor-based: ?after=abc123&limit=20 (wydajniejsze)

Connection Pooling, Indexing, Sharding, Read Replicas

  • Connection Pooling — pula polaczen do bazy danych
  • Database Indexing — indeksy na kolumnach w WHERE, JOIN, ORDER BY
  • Sharding — podzial danych miedzy wiele instancji bazy
  • Read Replicas — kopie bazy do odczytu

Monitoring wydajnosci

Kluczowe metryki

  • Latency — czas odpowiedzi (p50, p95, p99)
  • Throughput — zadania na sekunde (RPS)
  • Error rate — procent blednych odpowiedzi
  • Saturation — wykorzystanie zasobow

Narzedzia (2026)

  • Standard instrumentacji: OpenTelemetry (OTel) — jednolite SDK i protokol (OTLP) dla traces, metrics, logs. Eliminuje vendor lock-in.
  • APM: Datadog, New Relic, Honeycomb, Dynatrace, Grafana Cloud
  • Metryki: Prometheus + Grafana, Mimir, VictoriaMetrics
  • Logi: Grafana Loki, ELK Stack, OpenSearch, Vector (router logow)
  • Tracing: Grafana Tempo, Jaeger, Zipkin, AWS X-Ray, Datadog APM
  • Continuous profiling: Grafana Pyroscope, Polar Signals, Datadog Continuous Profiler

Edge computing dla wydajnosci

Edge runtimes (Cloudflare Workers, Vercel Edge, Deno Deploy) pozwalaja wykonywac kod w setkach lokalizacji bliskich uzytkownikom — krytyczne dla aplikacji globalnych:

  • Mniej hopow sieciowych = nizsze RTT
  • Cache stanu (Workers KV, Durable Objects) blisko uzytkownika
  • Personalizacja na edge bez round-tripa do origin
  • WASM jako format dla edge functions (Fastly Compute, Fermyon Spin)
