Chaos Engineering

Celowe wprowadzanie awarii, steady state hypothesis, Chaos Monkey, Litmus, game days i blast radius.

Dlaczego Chaos Engineering?

Tradycyjne podejscie:
  "Pewnie bedzie OK" → Awaria o 3 w nocy → 4h diagnostyki

Chaos Engineering:
  "Co sie stanie gdy baza padnie?" → Eksperyment
  → Odkrycie: brak circuit breakera → Naprawa PRZED incydentem

Zasady

  1. Zdefiniuj steady state — metryki normalnego dzialania
  2. Sformuluj hipoteze — co powinno sie stac
  3. Wprowadz awarie — realistyczne scenariusze
  4. Probuj obalic hipoteze — czy steady state jest utrzymany
  5. Minimalizuj blast radius — zacznij od malego zakresu

Steady State Hypothesis

Steady State:
  - Czas odpowiedzi API < 200ms (p99)
  - Error rate < 0.1%
  - Throughput > 1000 req/s
  - Health checki zielone

Hipoteza:
  "Jesli jeden Node K8s ulegnie awarii,
   system nadal odpowiada < 500ms
   z error rate < 1%"

Game Days

Zaplanowana sesja, podczas ktorej zespol celowo wprowadza awarie i obserwuje reakcje systemu i ludzi.

1. PLANOWANIE (1-2 tygodnie przed)
   Wybierz scenariusz, zdefiniuj hypothesis
   Okresl blast radius, przygotuj rollback

2. PRZED EKSPERYMENTEM
   Sprawdz steady state, uruchom monitoring
   Przygotuj kanal komunikacji (Slack)

3. EKSPERYMENT
   Wprowadz awarie, obserwuj metryki
   Jesli blast radius rosnie → rollback

4. PO EKSPERYMENCIE
   Retrospektywa: co odkrylismy?
   Tickety na poprawki, zaplanuj nastepny

Blast Radius

Poziom 1: Development     — pelna swoboda
Poziom 2: Staging         — realistyczne dane
Poziom 3: Production (1-5%) — canary, monitoring
Poziom 4: Production (100%) — po sukcesie na nizszych

Dojrzalosc Chaos Engineering

Kluczowe wnioski

  1. Steady state hypothesis — zdefiniuj co znaczy "normalnie"
  2. Zacznij od malego — dev/staging, jeden pod, niski blast radius
  3. Miej rollback plan — natychmiastowe przywrocenie
  4. Game Days buduja kulture odpornosci
  5. Automatyzuj eksperymenty — powtarzalne, regularne
  6. Chaos odkrywa niewiadome — problemy niewidoczne w unit testach
  7. Blast radius kontroluj starannie — eskaluj powoli
