OWASP Top 10

Dziesiec najkrytyczniejszych zagrozen bezpieczenstwa aplikacji webowych — ataki, zapobieganie i przyklady kodu.

A01: Broken Access Control

Uzytkownik moze wykonywac akcje lub widziec dane, do ktorych nie powinien miec dostepu.

# IDOR (Insecure Direct Object Reference)
GET /api/users/123/orders   # Moje zamowienia
GET /api/users/456/orders   # Cudze — brak weryfikacji!

Zapobieganie

app.get('/api/users/:userId/orders', auth, async (req, res) => {
  if (req.params.userId !== req.user.id
      && req.user.role !== 'admin') {
    return res.status(403).json({ error: 'Forbidden' });
  }
  const orders = await orderService.getByUserId(req.params.userId);
  res.json(orders);
});

Zasada: deny by default — biala lista dozwolonych akcji.

A02: Cryptographic Failures

Brak szyfrowania lub uzycie slabych algorytmow dla danych wrazliwych.

Hashowanie hasel

// ZLE: MD5, SHA256 bez salt
const hash = md5(password);

// DOBRZE: bcrypt
const bcrypt = require('bcrypt');
const hash = await bcrypt.hash(password, 12);
const valid = await bcrypt.compare(password, hash);

// JESZCZE LEPIEJ: Argon2
const argon2 = require('argon2');
const hash = await argon2.hash(password, {
  type: argon2.argon2id,
  memoryCost: 65536,
  timeCost: 3,
  parallelism: 4
});

A03: Injection

Wstrzykniecie zloslliwego kodu do zapytan — SQL, NoSQL, OS commands.

SQL Injection i obrona

// ZLE: konkatenacja stringow
const q = `SELECT * FROM users WHERE email = '${email}'`;
// Atak: email = "' OR '1'='1' --"
// → Zwraca WSZYSTKICH uzytkownikow!

// DOBRZE: parametryzowane zapytania
const result = await db.query(
  'SELECT * FROM users WHERE email = $1',
  [email]
);

// DOBRZE: ORM (Prisma)
const user = await prisma.user.findUnique({
  where: { email: email }
});

NoSQL Injection

// ZLE: MongoDB — operator injection
const user = await db.users.findOne({
  email: req.body.email,         // moze byc {"$gt": ""}
  password: req.body.password
});

// DOBRZE: walidacja typow
if (typeof req.body.email !== 'string' ||
    typeof req.body.password !== 'string') {
  return res.status(400).json({ error: 'Invalid input' });
}

A04: Insecure Design

Bledy projektowe — brak rate limiting, threat modeling, limitow. Nie da sie naprawic kodem — wymaga zmiany architektury.

const rateLimit = require('express-rate-limit');

const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,  // 15 minut
  max: 5,                     // max 5 prob
  message: 'Zbyt wiele prob logowania'
});

app.post('/login', loginLimiter, loginHandler);

A05: Security Misconfiguration

Domyslne hasla, stack trace na produkcji, brak naglowkow bezpieczenstwa.

Security Headers (Helmet)

const helmet = require('helmet');
app.use(helmet());
// → X-Content-Type-Options: nosniff
// → X-Frame-Options: DENY
// → Strict-Transport-Security: max-age=15552000
// → Content-Security-Policy: ...

// Wylacz stack trace na produkcji
app.use((err, req, res, next) => {
  res.status(err.status || 500).json({
    error: process.env.NODE_ENV === 'production'
      ? 'Internal Server Error'
      : err.message
  });
});

A07: Authentication Failures

Slabe hasla, brak MFA, podatnosc na brute force.

function validatePassword(password) {
  const errors = [];
  if (password.length < 12) errors.push('Min. 12 znakow');
  if (!/[A-Z]/.test(password)) errors.push('Wielka litera');
  if (!/[a-z]/.test(password)) errors.push('Mala litera');
  if (!/[0-9]/.test(password)) errors.push('Cyfra');
  if (!/[^A-Za-z0-9]/.test(password)) errors.push('Znak specjalny');
  if (COMMON_PASSWORDS.has(password.toLowerCase())) {
    errors.push('Haslo zbyt popularne');
  }
  return errors;
}

// Timing-safe porownanie (zapobiega timing attacks)
const crypto = require('crypto');
function safeCompare(a, b) {
  const bufA = Buffer.from(a);
  const bufB = Buffer.from(b);
  if (bufA.length !== bufB.length) return false;
  return crypto.timingSafeEqual(bufA, bufB);
}

A09: Logging Failures

Brak logowania zdarzen bezpieczenstwa — ataki pozostaja niewykryte.

const securityLogger = {
  loginSuccess: (userId, ip) =>
    log.info('AUTH_SUCCESS', { userId, ip }),
  loginFailure: (email, ip, reason) =>
    log.warn('AUTH_FAILURE', { email, ip, reason }),
  accessDenied: (userId, resource) =>
    log.warn('ACCESS_DENIED', { userId, resource }),
  suspiciousActivity: (userId, action) =>
    log.error('SUSPICIOUS', { userId, action })
};

A10: SSRF

Serwer wykonuje zapytanie do URL podanego przez uzytkownika — dostep do zasobow wewnetrznych.

// Atak:
POST /api/fetch-image
{ "url": "http://169.254.169.254/latest/meta-data/" }

// Zapobieganie:
async function validateUrl(inputUrl) {
  const parsed = new URL(inputUrl);

  // Tylko HTTPS
  if (parsed.protocol !== 'https:')
    throw new Error('Only HTTPS');

  // Zablokuj prywatne IP
  const addrs = await dns.resolve4(parsed.hostname);
  for (const ip of addrs) {
    if (isPrivateIP(ip))
      throw new Error('Private IPs blocked');
  }

  // Biala lista domen (najlepsze)
  const ALLOWED = ['cdn.example.com', 'images.example.com'];
  if (!ALLOWED.includes(parsed.hostname))
    throw new Error('Domain not allowed');
}

Content Security Policy (CSP)

Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-abc123';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https://cdn.example.com;
  connect-src 'self' https://api.example.com;
  frame-ancestors 'none';

const Joi = require('joi');

const createUserSchema = Joi.object({
  name: Joi.string().min(2).max(100).required()

app.post('/api/users', async (req, res) => {
  const { error, value } = createUserSchema.validate(

    errors: error.details.map(d => d.message)

Kluczowe wnioski

  1. Waliduj wszystkie dane wejsciowe — uzytkownik to niezaufane zrodlo
  2. Parametryzowane zapytania zawsze — nigdy konkatenacja stringow
  3. Defense in depth — wiele warstw obrony
  4. Security headers — latwi do wdrozenia, duzy efekt
  5. Loguj i monitoruj — nie obronisz sie przed tym, czego nie widzisz
  6. Aktualizuj zaleznosci — znane podatnosci to najlatwiejszy wektor ataku
