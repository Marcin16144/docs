Spis tresci / 08 — Bezpieczenstwo

Bezpieczenstwo w architekturze

Ochrona systemu od poziomu projektu po wdrozenie.

Fundamenty bezpieczenstwa (CIA Triad)

  • Confidentiality (Poufnosc) — dane dostepne tylko dla uprawnionych
  • Integrity (Integralnosc) — dane nie moga byc nieautoryzowanie zmienione
  • Availability (Dostepnosc) — system dostepny gdy potrzebny

Uwierzytelnianie (Authentication)

Mechanizmy

  • Hasla — hashowane (bcrypt, Argon2), nigdy w plaintext
  • MFA — TOTP, klucze sprzetowe (YubiKey)
  • OAuth 2.0 / OpenID Connect — delegowane uwierzytelnianie
  • JWT — bezstanowe tokeny z podpisem
  • API Keys — dla komunikacji machine-to-machine

JWT — struktura

Header.Payload.Signature

Header:  { "alg": "RS256", "typ": "JWT" }
Payload: { "sub": "user123", "role": "admin", "exp": 1700000000 }
Signature: RSASHA256(header + "." + payload, privateKey)

Uwagi: Krotki czas waznosci (15 min), refresh tokeny, walidacja podpisu, nie przechowuj wrazliwych danych w payload.

Autoryzacja (Authorization)

  • RBAC — uprawnienia przypisane do rol
  • ABAC — decyzje na podstawie atrybutow
  • PBAC — centralne polityki (Open Policy Agent)
  • ReBAC — uprawnienia na podstawie relacji (Google Zanzibar)

Zasada najmniejszych uprawnien: Kazdy uzytkownik/serwis powinien miec minimalny zestaw uprawnien potrzebnych do dzialania.

OWASP Top 10

  1. Broken Access Control — brak weryfikacji uprawnien
  2. Cryptographic Failures — slabe szyfrowanie, wycieki danych
  3. Injection — SQL injection, XSS, command injection
  4. Insecure Design — brak threat modelingu
  5. Security Misconfiguration — domyslne hasla, otwarte porty
  6. Vulnerable Components — nieaktualne zaleznosci
  7. Authentication Failures — slabe mechanizmy logowania
  8. Data Integrity Failures — brak weryfikacji integralnosci
  9. Logging Failures — brak logow bezpieczenstwa
  10. SSRF — Server-Side Request Forgery

Bezpieczenstwo w praktyce

Szyfrowanie

  • At rest — dane w bazie (AES-256)
  • In transit — komunikacja (TLS 1.3)
  • End-to-end — tylko nadawca i odbiorca moga odczytac

Zarzadzanie sekretami

Nigdy nie przechowuj sekretow w kodzie. Uzywaj: HashiCorp Vault, AWS Secrets Manager, Azure Key Vault. Rotuj sekrety regularnie.

Threat Modeling (STRIDE)

  • Spoofing — podszywanie sie
  • Tampering — manipulacja danymi
  • Repudiation — zaprzeczanie akcjom
  • Information disclosure — wyciek informacji
  • Denial of service — odmowa uslugi
  • Elevation of privilege — eskalacja uprawnien

Zero Trust Architecture

"Nigdy nie ufaj, zawsze weryfikuj" — kazde zadanie wymaga uwierzytelnienia i autoryzacji, niezaleznie od sieci.
