CI/CD Pipelines

Etapy pipeline, GitHub Actions, quality gates, artefakty i strategie wdrozeniowe.

CI vs CD

CI                        CD (Delivery)       CD (Deployment)
Code → Build → Test → → Stage → Approval → → Production
                        (artefakt gotowy)     (automatycznie)
  • CI — automatyczne budowanie i testowanie po kazdym uaktualnieniu
  • CD (Delivery) — artefakt gotowy do wdrozenia (reczne zatwierdzenie)
  • CD (Deployment) — automatyczne wdrozenie na produkcje

Etapy pipeline

1. Build

- uses: actions/setup-node@v4
  with:
    node-version: '20'
    cache: 'npm'
- run: npm ci        # deterministyczna instalacja
- run: npm run build

2. Test

- run: npm test -- --coverage     # Unit tests
- run: npm run test:integration   # Integration
- run: npx playwright test        # E2E

3. Quality Gates

- run: npm run lint               # Lint
- run: npx tsc --noEmit           # Type check
- run: npm audit --audit-level=high  # Security

4. Docker Build & Push

- uses: docker/build-push-action@v5
  with:
    push: true
    tags: |
      ghcr.io/org/app:${{ github.sha }}
      ghcr.io/org/app:latest
    cache-from: type=gha
    cache-to: type=gha,mode=max

5. Deploy

- name: Deploy to staging
  run: kubectl set image deployment/my-app
    my-app=ghcr.io/org/app:${{ github.sha }}

- name: Smoke tests
  run: curl -f https://staging.example.com/healthz

- name: Deploy to production
  run: kubectl set image deployment/my-app
    my-app=ghcr.io/org/app:${{ github.sha }}

- name: Verify
  run: kubectl rollout status deployment/my-app
    --timeout=300s

Zarzadzanie artefaktami

Pipeline Build → Artefakt (Docker image)
  → Container Registry
  → Deploy (staging → production)

Zasady:
  Buduj artefakt RAZ, wdrazaj WIELOKROTNIE
  Taguj: git SHA, semver, timestamp
  Nigdy nie buduj ponownie na staging/prod

CanaryNowa wersja na malym % ruchuNajnizsze
RecreateZatrzymaj stara, uruchom nowaDowntime

Dobre praktyki

  1. Pipeline jako kod — YAML w repozytorium, wersjonowany z kodem
  2. Szybki feedback — pipeline < 10 minut (cache, rownolegle joby)
  3. Fail fast — lint → unit → integration → e2e
  4. Immutable artifacts — buduj raz, wdrazaj wielokrotnie
  5. Sekrety w secret manager — nigdy w kodzie ani YAML
  6. Branch protection — main wymaga pipeline + code review
  7. Rollback plan — zawsze mozliwosc szybkiego powrotu

Kluczowe wnioski

  1. CI = automatyczne testy po kazdym uaktualnieniu
  2. CD = automatyczne wdrozenie — staging auto, prod z zatwierdzeniem
  3. Quality gates zapewniaja minimalny standard jakosci
  4. Artefakt budowany raz — ten sam obraz na staging i produkcji
  5. Canary/Blue-Green minimalizuja ryzyko wdrozenia
