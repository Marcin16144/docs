Bazy danych i persystencja

Dobor technologii przechowywania danych do wymagan systemu.

Aktualizacja: 2026 — uwzglednia PostgreSQL 17+ (parallel query, native partitioning), Supabase, Neon, Turso, SurrealDB, vector search w pgvector.

Typy baz danych

Relacyjne (SQL)

Przyklady: PostgreSQL, MySQL, SQL Server, Oracle, CockroachDB (rozproszony, kompatybilny z Postgres).

PostgreSQL 17+ (2026): znaczaco ulepszony parallel query, dojrzale native partycjonowanie (range/list/hash, partition pruning, partition-wise joins), logical replication z DDL replication, JSON/JSONB konkurujace z dokumentowymi DBs, pgvector dojrzaly (HNSW/IVFFlat).

Postgres pelni czesto role "one database to rule them all" (relacyjne + JSON + vector + full-text + time-series przez TimescaleDB).

Serverless / managed Postgres: Supabase (Postgres + Auth + Storage + Realtime + Edge Functions), Neon (separacja compute/storage, branching jak w Git), Crunchy Bridge, Aiven, AWS Aurora Serverless v2/v3.

Kiedy stosowac: dane ze zlozonymi relacjami, transakcje ACID, zlozone zapytania, spojnosc jako priorytet.

SQLite na edge'u

Turso (oparty o libSQL) i Cloudflare D1 — replikowany SQLite blisko uzytkownika. Bardzo niskie opoznienia odczytu, idealne dla aplikacji edge / globalnych. SQLite pozostaje popularny w aplikacjach desktopowych, mobilnych i SaaS per-tenant.

Dokumentowe

MongoDB, CouchDB, DynamoDB, Firestore

Schemat zmienia sie czesto, dane naturalne jako JSON.

Uwaga: Postgres z JSONB czesto wystarcza.

Klucz-Wartosc

Redis / Valkey, Memcached, KeyDB, Dragonfly

Edge KV: Cloudflare Workers KV, Vercel KV, Upstash Redis.

Grafowe

Neo4j, Amazon Neptune, ArangoDB

Sieci spolecznosciowe, rekomendacje.

Kolumnowe i analityczne

Przyklady: Apache Cassandra, ScyllaDB, HBase, ClickHouse, Apache Doris, DuckDB (embedded analityczna).

Kiedy stosowac: zapis duzych ilosci danych, dane szeregow czasowych (TimescaleDB, InfluxDB), analityka OLAP.

Wielomodelowe / nowsze

SurrealDB — wielomodelowa (dokument + graf + relacja), live queries, wbudowane auth; w 2026 rosnie jako alternatywa dla laczenia kilku DB.

EdgeDB — relacyjna z mocnym schematem i jezykiem EdgeQL na bazie Postgres.

Wektorowe (Vector DBs) — era AI / RAG

  • pgvector — rozszerzenie Postgres, najczestszy wybor jesli juz uzywasz Postgresa
  • Qdrant — open source, Rust, swietna wydajnosc i filtrowanie
  • Pinecone — managed, prosty start, dobry SLA
  • Turbopuffer — serverless, bardzo niski koszt (object storage)
  • Weaviate, Milvus, Chroma, LanceDB

Indeksy: HNSW (najpopularniejszy), IVF, ScaNN. Metryki: cosine, dot product, L2.

Twierdzenie CAP

W systemie rozproszonym mozesz miec tylko 2 z 3:

  • C (Consistency) — kazdy odczyt zwraca najnowsze dane
  • A (Availability) — kazde zadanie otrzymuje odpowiedz
  • P (Partition Tolerance) — system dziala mimo podzialu sieci

Poniewaz partycje sieciowe sie zdarzaja, wybor to: CP (spojnosc) lub AP (dostepnosc).

Wzorce persystencji

Database per Service

Kazdy mikroserwis ma wlasna baze danych — pelna izolacja.

Shared Database

Wiele serwisow korzysta z jednej bazy — prostsze, ale tworzy coupling.

Event Sourcing

Zamiast przechowywac aktualny stan, przechowuj strumien zdarzen.

Zdarzenia dla zamowienia #123:
1. OrderCreated { items: [...], customer: "Jan" }
2. ItemAdded { item: "Laptop" }
3. PaymentReceived { amount: 5000 }
4. OrderShipped { trackingId: "XYZ" }

Stan aktualny = odtworzenie ze zdarzen

Zalety: Pelna historia zmian, audyt, mozliwosc odtworzenia stanu z dowolnego momentu.

Wady: Zlozonosc, potrzeba snapshotow dla wydajnosci.

Migracje bazy danych

Narzedzia (2026): Flyway, Liquibase, Atlas (HCL/SQL, multi-DB), Prisma Migrate, Drizzle Kit, Knex migrations, sqlx migrate (Rust), EF Migrations, Goose (Go).

  • Migracje powinny byc idempotentne
  • Backward-compatible zmiany (expand-and-contract)
  • Strategia blue-green dla migracji zero-downtime
  • Testuj migracje na kopii produkcyjnych danych
  • Branching baz (Neon, Supabase) dla testowania migracji per Pull Request
