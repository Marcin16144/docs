Spis tresci / 05 — Domain-Driven Design

Domain-Driven Design (DDD)

Model domeny biznesowej jako centralny element architektury.

Czym jest DDD?

Podejscie do tworzenia oprogramowania, w ktorym model domeny biznesowej jest centralnym elementem architektury. Wprowadzone przez Erica Evansa w 2003 roku.

Pojecia strategiczne

Ubiquitous Language (Jezyk wszechobecny)

Wspolny jezyk uzywany przez programistow i ekspertow biznesowych. Terminy biznesowe sa bezposrednio odzwierciedlone w kodzie.

// Zle — techniczny zargon
class DataProcessor {
    processRecord(record) { ... }
}

// Dobrze — jezyk domeny
class OrderFulfillment {
    shipOrder(order) { ... }
}

Bounded Context (Kontekst ograniczony)

Wyrazna granica, w ktorej dany model ma spojne znaczenie.

Przyklad: "Klient" oznacza co innego w kontekscie:

  • Sprzedaz — potencjalny nabywca z budzetem
  • Wysylka — adres dostawy i preferencje
  • Rozliczenia — dane do faktury i historia platnosci

Context Map (Mapa kontekstow)

Diagram relacji miedzy kontekstami ograniczonymi:

  • Partnership — oba zespoly wspolpracuja
  • Shared Kernel — wspolna czesc modelu
  • Customer-Supplier — jeden zespol dostarcza, drugi konsumuje
  • Conformist — konsument dostosowuje sie do dostawcy
  • Anti-Corruption Layer — warstwa tlumaczaca miedzy kontekstami
  • Open Host Service — dostawca udostepnia protokol
  • Published Language — wspolny format wymiany danych

Pojecia taktyczne

Entity (Encja)

Obiekt z unikalna tozsamoscia, istotny przez cykl zycia.

Przyklad: Zamowienie (identyfikowane przez OrderId).

Value Object

Obiekt bez tozsamosci, definiowany przez swoje atrybuty. Niemutowalny.

Przyklad: Adres, Pieniadze, Zakres dat.

class Money {
    constructor(readonly amount: number, readonly currency: string) {}

    add(other: Money): Money {
        if (this.currency !== other.currency)
            throw new Error("Currency mismatch");
        return new Money(this.amount + other.amount, this.currency);
    }

    equals(other: Money): boolean {
        return this.amount === other.amount
            && this.currency === other.currency;
    }
}

Aggregate (Agregat)

Klaster powiazanych obiektow traktowanych jako jednostka do celow zmian danych. Ma korzen agregatu (Aggregate Root).

  • Zewnetrzne obiekty moga odwolywac sie tylko do korzenia agregatu
  • Korzen odpowiada za spojnosc calego agregatu
  • Agregaty powinny byc male

Domain Service

Operacja, ktora nie nalezy naturalnie do zadnej encji ani obiektu wartosci.

Domain Event

Fakt, ktory sie wydarzyl w domenie.

Przyklady: OrderPlaced, PaymentReceived, ShipmentDispatched

Kiedy stosowac DDD?

Stosuj gdy:

  • Domena jest zlozona
  • Eksperci biznesowi sa dostepni
  • System bedzie dlugo rozwijany

Nie stosuj gdy:

  • Prosta domena (CRUD)
  • Brak dostepu do ekspertow
  • Prototyp / MVP
