Wzorce architektoniczne

Sprawdzone podejscia do strukturyzacji systemow oprogramowania.

1. Architektura monolityczna

Caly system jako jedna jednostka wdrozeniowa.

Zalety

  • Prostota wdrozenia i debugowania
  • Latwa komunikacja miedzy komponentami (wywolania w procesie)
  • Proste transakcje

Wady

  • Trudna skalowalnosc poszczegolnych modulow
  • Ryzyko "big ball of mud" przy braku dyscypliny
  • Dlugi czas budowania i wdrazania przy duzym systemie

Kiedy stosowac: Male/srednie projekty, MVP, maly zespol.

2. Architektura warstwowa (Layered / N-Tier)

Podzial na warstwy: prezentacja → logika biznesowa → dostep do danych.

Logika biznesowa
Dostep do danych

Zasada: Warstwa moze komunikowac sie tylko z warstwa bezposrednio ponizej.

3. Mikroserwisy (Microservices)

System podzielony na male, niezaleznie wdrazane uslugi.

Zalety

  • Niezalezne wdrazanie i skalowanie
  • Autonomia zespolow
  • Izolacja bledow

Wady

  • Zlozonosc operacyjna (siec, monitoring, wdrozenia)
  • Transakcje rozproszone (saga pattern)
  • Debugowanie trudniejsze

Kiedy stosowac: Duze systemy, wiele zespolow, potrzeba niezaleznego skalowania.

4. Architektura sterowana zdarzeniami (Event-Driven)

Komponenty komunikuja sie przez zdarzenia (events).

Modele:

  • Event Notification — powiadomienie, ze cos sie stalo
  • Event-Carried State Transfer — zdarzenie niesie pelne dane
  • Event Sourcing — stan systemu odtwarzany ze strumienia zdarzen

Technologie: Apache Kafka, RabbitMQ, AWS EventBridge, NATS

7. Architektura serverless

Logika w funkcjach uruchamianych na zadanie (FaaS).

Technologie: AWS Lambda, Azure Functions, Google Cloud Functions

Zalety: Brak zarzadzania infrastruktura, platnosc za uzycie

Wady: Cold start, ograniczenia czasu wykonania, vendor lock-in

8. Architektura modularna (Modular Monolith)

Monolit z wyraznymi granicami modulow — kompromis miedzy monolitem a mikroserwisami.

Zasady:

  • Moduly komunikuja sie przez zdefiniowane interfejsy
  • Kazdy modul ma wlasna baze/schemat danych
  • Brak bezposrednich zaleznosci miedzy modulami

Kiedy stosowac: Gdy mikroserwisy to za duzo zlozonosci, ale potrzebujesz granic modulow.
