DRY, KISS, YAGNI

Zasady prostoty i pragmatyzmu — unikaj duplikacji wiedzy, zbednej zlozonosci i implementowania na zapas.

DRY — Don't Repeat Yourself

Kazda porcja wiedzy powinna miec jedna, jednoznaczna, autorytatywna reprezentacje w systemie. Uwaga: DRY dotyczy duplikacji wiedzy, nie duplikacji kodu.

Przypadkowa zbieznosc vs prawdziwa duplikacja

// PRZYPADKOWA ZBIEZNOSC — wyglada identycznie, ale to ROZNA wiedza

// Zmienia sie gdy zmienia sie logistyka
function validateShippingAddress(addr: Address): boolean {
    return addr.street.length > 0
        && addr.city.length > 0
        && addr.zip.length === 5;
}

// Zmienia sie gdy zmienia sie prawo podatkowe
function validateBillingAddress(addr: Address): boolean {
    return addr.street.length > 0
        && addr.city.length > 0
        && addr.zip.length === 5;
}

// Wygladaja identycznie, ale za miesiac billing moze wymagac NIP.
// Polaczenie ich w jedna = zle zastosowane DRY.
// PRAWDZIWA DUPLIKACJA — ta sama wiedza w wielu miejscach

// ZLE — logika podatku powtorzona
class CartService {
    calcTax(amount: number) { return amount * 0.23; }
}
class InvoiceService {
    calcTax(amount: number) { return amount * 0.23; }
}
class ReportService {
    calcTax(amount: number) { return amount * 0.23; }
}

// DOBRZE — jedna reprezentacja wiedzy
class TaxCalculator {
    private static readonly VAT_RATE = 0.23;
    static calculate(amount: number): number {
        return amount * TaxCalculator.VAT_RATE;
    }
}

        # ... 20 linii specyficznych dla usera

# DOBRZE — oddzielne funkcje, nawet jesli koncowka sie powtarza
def process_user(user: User):
    validate_email(user.email)
    # logika specyficzna
    user.updated_at = datetime.now()
    user.version += 1
    db.save(user)

def process_product(product: Product):
    validate_sku(product.sku)
    # logika specyficzna
    product.updated_at = datetime.now()
    product.version += 1
    db.save(product)

Rule of Three

  1. Pierwsze uzycie — napisz kod
  2. Drugie uzycie — skopiuj i zanotuj
  3. Trzecie uzycie — refaktoryzuj, bo widzisz wzorzec

KISS — Keep It Simple, Stupid

Systemy dzialaja najlepiej, gdy sa proste. Prostota powinna byc kluczowym celem projektowania.

Accidental vs Essential Complexity

interface IStringFormatterStrategy {
    format(input: string): string;
}

    format(input: string): string {
        return input.toUpperCase();

YAGNI — You Aren't Gonna Need It

Nie implementuj funkcjonalnosci, dopoki nie jest faktycznie potrzebna. Pochodzi z Extreme Programming i walczy z tendencja do przewidywania przyszlych potrzeb.

DRY vs KISS

// DRY moze prowadzic do zbytniej zlozonosci

// Sztywne DRY — skomplikowane generyki
function formatEntity<T extends Record<string, any>>(
    entity: T,
    fields: (keyof T)[],
    formatters: Partial<Record<keyof T, (v: any) => string>>
): string {
    return fields.map(f => (formatters[f] || String)(entity[f])).join(', ');
}

// KISS — proste, nawet z lekka powtarzalnoscia
function formatUser(user: User): string {
    return `${user.name} (${user.email})`;
}
function formatProduct(product: Product): string {
    return `${product.name} — ${product.price} PLN`;
}
