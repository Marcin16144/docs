Nowoczesny Python (3.13/3.14)

Free-threaded mode (no GIL!), JIT compiler, pattern matching, structural typing, taskgroups, dataclasses with slots.

Free-threaded Python (PEP 703) - bez GIL!

Python 3.13 wprowadza opcjonalny tryb bez GIL (Global Interpreter Lock). Po raz pierwszy w 30-letniej historii Pythona thread-y moga sie naprawde wykonywac rownolegle (CPU-bound).

# Instalacja free-threaded buildu
# Linux/macOS:
uv python install 3.13t           # 't' = threaded
uv venv --python 3.13t

# Lub recznie z python.org - "free-threaded build"

# Sprawdzenie GIL
import sys
print(sys._is_gil_enabled())   # False na free-threaded build

# CPU-bound kod teraz dziala rownolegle
import threading
import time

def cpu_intensive(n):
    s = 0
    for i in range(n):
        s += i * i
    return s

threads = []
start = time.time()
for _ in range(8):
    t = threading.Thread(target=cpu_intensive, args=(10_000_000,))
    threads.append(t)
    t.start()
for t in threads:
    t.join()
print(f"Czas: {time.time() - start:.2f}s")

# Bez GIL: szybsze ~ 8x na 8-rdzeniowym CPU

Ostrzezenie: Free-threaded mode w 3.13 jest experimental. Wiele paczek C-extensions wymaga adaptacji. Stabilne API spodziewane w 3.14/3.15. Single-threaded perf moze byc nieco gorsze (~5%).

JIT compiler (PEP 744)

Python 3.13 dostaje wbudowany experimentalny JIT compiler oparty na "copy-and-patch" technologii (krotki, lekki).

# Wlaczenie JIT (compile-time flag)
./configure --enable-experimental-jit
make

# Albo dla wybranych dystrybucji - flag PYTHON_JIT=1

# Stan: ~5% szybciej w benchmarkach 3.13. W 3.14/3.15 spodziewane wieksze gainy.

Pattern matching (3.10+)

# Match/case - zaawansowane wzorce
def opisz_punkt(punkt):
    match punkt:
        case (0, 0):
            return "Punkt zerowy"
        case (0, y):
            return f"Na osi Y, y={y}"
        case (x, 0):
            return f"Na osi X, x={x}"
        case (x, y) if x == y:
            return f"Na przekatnej, ({x}, {y})"
        case (x, y):
            return f"Punkt ({x}, {y})"
        case _:
            return "Nie punkt"

# Class patterns
@dataclass
class Krag:
    promien: float

@dataclass
class Kwadrat:
    bok: float

def pole(figura):
    match figura:
        case Krag(promien=r):
            return 3.14 * r ** 2
        case Kwadrat(bok=b):
            return b * b
        case _:
            raise ValueError("Nieznana figura")

# Sequence patterns
match komenda.split():
    case ["go", direction]:
        ruszaj_w(direction)
    case ["go", *directions]:
        for d in directions:
            ruszaj_w(d)
    case ["pickup", item, "from", location]:
        podnies(item, location)

ParamSpec (3.10+)

from typing import ParamSpec, TypeVar
from collections.abc import Callable

P = ParamSpec("P")
R = TypeVar("R")

def loguj(fn: Callable[P, R]) -> Callable[P, R]:
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        print(f"Wywolanie {fn.__name__}")
        return fn(*args, **kwargs)
    return wrapper

@loguj
def dodaj(a: int, b: int) -> int:
    return a + b

Generic syntax (PEP 695, 3.12+)

# Stary styl
from typing import TypeVar, Generic

T = TypeVar("T")
class Stack(Generic[T]):
    def push(self, item: T) -> None: ...
    def pop(self) -> T: ...

# Nowy styl (3.12+)
class Stack[T]:
    def push(self, item: T) -> None: ...
    def pop(self) -> T: ...

def first[T](items: list[T]) -> T:
    return items[0]

Structural typing (Protocol)

from typing import Protocol

class Drawable(Protocol):
    def draw(self) -> None: ...

class Krag:           # nie dziedziczy z Drawable!
    def draw(self) -> None:
        print("Rysuje krag")

class Kwadrat:        # tez bez dziedziczenia
    def draw(self) -> None:
        print("Rysuje kwadrat")

def render(obj: Drawable) -> None:    # struktur. typing
    obj.draw()

render(Krag())        # OK - Krag ma draw()
render(Kwadrat())     # OK

Dataclasses z slots

from dataclasses import dataclass

# slots=True - znacznie mniejsze zuzycie pamieci, szybszy dostep do atrybutow
@dataclass(slots=True, frozen=True)
class Point:
    x: float
    y: float

p = Point(1.0, 2.0)
# p.z = 3.0   # AttributeError - nie ma dynamicznych atr.

# Porownanie pamieci:
# Bez slots: ~280 bytes
# Ze slots:  ~80 bytes
# Az 70% mniej pamieci dla typowego DTO!

# kw_only - tylko keyword arguments
@dataclass(kw_only=True, slots=True)
class User:
    name: str
    email: str
    age: int = 0

u = User(name="Anna", email="a@b.pl")
# User("Anna", "a@b.pl")  # Error - kw_only

TaskGroups (asyncio, 3.11+)

import asyncio

async def pobierz(url: str) -> str:
    await asyncio.sleep(1)
    return f"data from {url}"

async def main():
    # Stary styl - latwo zapomniec o handle errors
    results = await asyncio.gather(
        pobierz("a.pl"),
        pobierz("b.pl"),
    )

    # Nowy styl - TaskGroup (3.11+)
    async with asyncio.TaskGroup() as tg:
        t1 = tg.create_task(pobierz("a.pl"))
        t2 = tg.create_task(pobierz("b.pl"))
    # Po wyjsciu z bloku wszystkie taski sa wykonane
    # Jesli ktorys rzucil exception - wszystkie inne sa anulowane
    # Wszystkie exceptions sa zebrane w ExceptionGroup

    print(t1.result(), t2.result())

asyncio.run(main())

ExceptionGroup (3.11+)

def proces():
    raise ExceptionGroup("multiple errors", [
        ValueError("bad value"),
        TypeError("bad type"),
        OSError("io error"),
    ])

try:
    proces()
except* ValueError as eg:
    print(f"Caught {len(eg.exceptions)} ValueError(s)")
except* (TypeError, OSError) as eg:
    print(f"Caught {len(eg.exceptions)} I/O errors")

Generic Self type (3.11+)

from typing import Self

class Builder:
    def with_name(self, name: str) -> Self:
        self.name = name
        return self

    def with_age(self, age: int) -> Self:
        self.age = age
        return self

# Subclasses dziedzicza poprawne typy
class UserBuilder(Builder):
    def with_email(self, email: str) -> Self:
        self.email = email
        return self

# Mozemy chainowac
ub = UserBuilder().with_name("Anna").with_age(30).with_email("a@b.pl")
# Type checker wie ze 'ub' to UserBuilder, nie Builder
