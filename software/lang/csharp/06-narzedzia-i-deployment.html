dotnet CLI - workflow

# Tworzenie projektow
dotnet new sln -n MyApp
dotnet new webapi -o src/MyApp.Api
dotnet new classlib -o src/MyApp.Core
dotnet new xunit -o tests/MyApp.Tests

# Solution
dotnet sln add src/MyApp.Api
dotnet sln add src/MyApp.Core
dotnet sln add tests/MyApp.Tests

# Reference
dotnet add src/MyApp.Api reference src/MyApp.Core
dotnet add tests/MyApp.Tests reference src/MyApp.Core

# Build
dotnet build
dotnet build -c Release

# Test
dotnet test
dotnet test --collect:"XPlat Code Coverage"

# Run + watch
dotnet run --project src/MyApp.Api
dotnet watch run --project src/MyApp.Api

# Format / lint
dotnet format
dotnet format --verify-no-changes  # CI

Native AOT - kompilacja do natywnego binary

Native AOT (Ahead-of-Time) eliminuje JIT — aplikacja jest skompilowana do prawdziwego natywnego kodu. Plusy: szybki start (10x), maly footprint, brak zaleznosci od .NET runtime. Minusy: brak refleksji w czasie runtime, ograniczenia na biblioteki.

<!-- .csproj -->
<PropertyGroup>
    <TargetFramework>net9.0</TargetFramework>
    <PublishAot>true</PublishAot>
    <StripSymbols>true</StripSymbols>
    <InvariantGlobalization>true</InvariantGlobalization>
</PropertyGroup>

# Publish
dotnet publish -c Release -r linux-x64

# Wynik:
# bin/Release/net9.0/linux-x64/publish/MyApp     (single binary, ~10 MB)
# Zaden runtime nie jest potrzebny!

Single-file publish

# Jeden plik .exe z runtime'em w srodku
dotnet publish -c Release -r win-x64 \
    --self-contained \
    -p:PublishSingleFile=true \
    -p:IncludeNativeLibrariesForSelfExtract=true

# Trimming - usuwanie nieuzywanego kodu
dotnet publish -c Release -r win-x64 \
    --self-contained \
    -p:PublishSingleFile=true \
    -p:PublishTrimmed=true

Ready-to-Run (R2R)

Pre-kompilacja IL do natywnego kodu — szybszy start aplikacji. Mniej restrykcji niz AOT.

dotnet publish -c Release -r linux-x64 \
    -p:PublishReadyToRun=true

Docker dla .NET - multi-stage

# syntax=docker/dockerfile:1.7
# Stage 1: SDK build
FROM mcr.microsoft.com/dotnet/sdk:9.0-alpine AS build
WORKDIR /src

# Cache restore
COPY ["src/MyApp.Api/MyApp.Api.csproj", "MyApp.Api/"]
COPY ["src/MyApp.Core/MyApp.Core.csproj", "MyApp.Core/"]
COPY ["Directory.Packages.props", "."]
COPY ["nuget.config", "."]
RUN dotnet restore "MyApp.Api/MyApp.Api.csproj"

# Build + publish
COPY src/ .
RUN dotnet publish "MyApp.Api/MyApp.Api.csproj" \
    -c Release \
    -o /app/publish \
    --no-restore \
    /p:UseAppHost=false

# Stage 2: runtime
FROM mcr.microsoft.com/dotnet/aspnet:9.0-alpine AS runtime
WORKDIR /app

# Non-root user
RUN adduser -D -u 1000 appuser
USER appuser

COPY --from=build --chown=appuser:appuser /app/publish .

ENV ASPNETCORE_URLS=http://+:8080 \
    DOTNET_RUNNING_IN_CONTAINER=true \
    DOTNET_USE_POLLING_FILE_WATCHER=false

EXPOSE 8080
ENTRYPOINT ["dotnet", "MyApp.Api.dll"]

Chiseled images (.NET 8+)

Microsoft oferuje "chiseled" images — ultra-male, distroless. Bez shell, bez package managera, ~30 MB.

FROM mcr.microsoft.com/dotnet/aspnet:9.0-noble-chiseled AS runtime
# vs ~210 MB dla normalnego aspnet image

Kubernetes - Helm chart

# Chart.yaml
apiVersion: v2
name: myapp
version: 1.0.0
appVersion: "1.0"

# values.yaml
replicaCount: 3
image:
  repository: myapp
  tag: "1.0"
  pullPolicy: IfNotPresent

resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 100m
    memory: 256Mi

# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}
spec:
  replicas: {{ .Values.replicaCount }}
  template:
    spec:
      containers:
        - name: app
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          livenessProbe:
            httpGet:
              path: /health/live
              port: 8080
          readinessProbe:
            httpGet:
              path: /health/ready
              port: 8080

GitHub Actions - CI/CD

name: CI/CD

on:
  push:
    branches: [main]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: 9.0.x

      - name: Cache NuGet
        uses: actions/cache@v4
        with:
          path: ~/.nuget/packages
          key: nuget-${{ hashFiles('**/packages.lock.json') }}

      - name: Restore
        run: dotnet restore

      - name: Format check
        run: dotnet format --verify-no-changes

      - name: Vulnerable packages
        run: |
          dotnet list package --vulnerable --include-transitive 2>&1 | tee output.txt
          ! grep -q "has the following vulnerable" output.txt

      - name: Build
        run: dotnet build --no-restore -c Release

      - name: Test
        run: dotnet test --no-build -c Release \
          --logger "trx;LogFileName=test-results.trx" \
          --collect:"XPlat Code Coverage"

      - name: Publish
        if: github.ref == 'refs/heads/main'
        run: dotnet publish src/MyApp.Api -c Release -o publish

      - name: Build Docker
        if: github.ref == 'refs/heads/main'
        run: |
          docker build -t myapp:${{ github.sha }} .
          docker tag myapp:${{ github.sha }} myapp:latest

Production checklist

  • Logging strukturalne (Serilog + Seq/Elastic)
  • Health checks (/health/live, /health/ready)
  • Metrics (OpenTelemetry, Prometheus)
  • Distributed tracing (OTel + Jaeger/Tempo)
  • Graceful shutdown (handle SIGTERM)
  • Resource limits w K8s
  • HPA / VPA dla autoscaling
  • Vault dla secrets, nie env vars
