Bezpieczenstwo aplikacji Rust

Co Rust gwarantuje na poziomie kompilatora, gdzie sa pulapki i jak chronic produkcyjne aplikacje przed atakami.

Memory safety guarantees

Rust gwarantuje na poziomie kompilatora wiekszosc bledow, ktore stanowily 60-70% CVE w C i C++ przez ostatnie 30 lat. Microsoft Security Response Center zglosil w 2019, ze 70% bledow security w produktach MS to memory safety bugs. Google podal podobne dane dla Chrome.

unsafe — kiedy i jak ostroznie

unsafe blok wylacza niektore checki kompilatora w celu umozliwienia operacji niskopoziomowych. To NIE oznacza "dowolny kod" — wciaz dziala typing, lifetimes i wiekszosc analiz.

Kiedy unsafe jest konieczny

  • FFI — wywolywanie funkcji C/C++ (np. systemowe API, OpenSSL)
  • Raw pointers — implementacja kontenerow data structures (np. Vec, HashMap)
  • SIMD / intrinsics — instrukcje CPU bezposrednio (AVX, NEON)
  • Embedded — dostep do MMIO registers, peripheriow
  • Optymalizacja — gdy compiler nie umie udowodnic, ze bezpieczne
// FFI — wywolanie C
extern "C" {
    fn abs(input: i32) -> i32;
}

fn main() {
    unsafe {
        println!("|{}| = {}", -3, abs(-3));
    }
}

// Dereferencja raw pointer
let mut x = 10;
let r1 = &x as *const i32;       // OK, tylko tworzenie
let r2 = &mut x as *mut i32;     // OK
unsafe {
    println!("r1: {}", *r1);     // unsafe — dereferencja
    *r2 = 20;
}

Dyscyplina unsafe

  1. Zrob blok unsafe jak najmniejszy
  2. Zawiniaj go w bezpieczny API ("safe abstraction over unsafe")
  3. Dokumentuj inwarianty komentarzami // SAFETY: ...
  4. Audit przez kogos drugiego (peer review obowiazkowy)
  5. Uruchamiaj Miri dla wykrywania UB
  6. Rozwaz fuzzing (cargo-fuzz) dla niskopoziomowych funkcji

Typowe bledy mimo Rust

Rust nie chroni przed wszystkim. Logic bugs, blad w validacji wejscia, race condition na poziomie aplikacji — to wciaz problem programisty.

Integer overflow

W debug build Rust panicuje przy przepelnieniu. W release domysnie wraps (jak C). Trzeba byc swiadomym i uzywac dedykowanych metod:

let a: u8 = 200;
let b: u8 = 100;

// W release: a + b = 44 (wrap), w debug: panic
let suma = a + b;

// Bezpieczne warianty:
let suma = a.checked_add(b);              // Option (None gdy overflow)
let suma = a.wrapping_add(b);             // explicit wrap
let suma = a.saturating_add(b);           // 255 (clamp do max)
let (suma, overflow) = a.overflowing_add(b); // (44, true)

SQL injection — uzywaj parametryzacji

// ZLE — vulnerable
let q = format!("SELECT * FROM users WHERE id = {}", user_input);

// DOBRZE — sqlx z compile-time check
let user = sqlx::query_as!(

XSS — uzywaj template engines z auto-escape

  • askama — Jinja-inspired, compile-time templates, auto-escape HTML domyslnie
  • tera — runtime templates (jak Liquid), auto-escape
  • maud — type-safe HTML jako Rust macro
// askama — auto-escape
use askama::Template;

#[derive(Template)]
#[template(path = "user.html")]
struct UserTpl<'a> {
    imie: &'a str,
    bio: &'a str,  // automatycznie escape gdy {{ bio }}
}

Deserialization attacks

Serde domyslnie jest bezpieczny — nie pozwala na deserializacje arbitrarnych typow z prymitywem (jak Java/Python pickle). Ale walidacja pol pozostaje obowiazkiem.

use serde::Deserialize;
use validator::{Validate, ValidationError};

#[derive(Deserialize, Validate)]
struct RejestracjaForm {
    #[validate(email)]
    email: String,

    #[validate(length(min = 8, max = 128))]
    haslo: String,

    #[validate(range(min = 18, max = 120))]
    wiek: u8,
}

Narzedzia bezpieczenstwa

cargo-audit — skanowanie CVE

Sprawdza zaleznosci pod katem znanych podatnosci z bazy RustSec Advisory Database (rustsec.org).

# Instalacja
cargo install cargo-audit

# Skan projektu
cd moj_projekt
cargo audit

# Output:
# Crate:     openssl
# Version:   0.10.55
# Title:     Use-after-free in openssl
# Date:      2026-01-15
# ID:        RUSTSEC-2026-0001
# Severity:  HIGH
# Solution:  Upgrade to >=0.10.62

# W CI/CD:
cargo audit --deny warnings

cargo-deny — polityki dla zaleznosci

Pozwala na enforcing licenses, blokowanie konkretnych crates, sprawdzanie duplikatow, polityki source.

# Cargo.toml deny.toml
[bans]
multiple-versions = "warn"
deny = [
    { name = "openssl", reason = "uzywaj rustls" },
]

[licenses]
allow = ["MIT", "Apache-2.0", "BSD-3-Clause"]
deny = ["GPL-3.0"]

[advisories]
ignore = []
vulnerability = "deny"

cargo-fuzz — fuzzing

Generowanie losowych inputow do wykrywania crashes i UB. Bazuje na libFuzzer (LLVM).

cargo install cargo-fuzz
cargo fuzz init
cargo fuzz add parsuj_dane

# fuzz/fuzz_targets/parsuj_dane.rs
#![no_main]
use libfuzzer_sys::fuzz_target;

fuzz_target!(|data: &[u8]| {
    if let Ok(s) = std::str::from_utf8(data) {
        let _ = moja_lib::parsuj(s);  // szukamy crash
    }
});

cargo fuzz run parsuj_dane

Miri — Undefined Behavior detection

Interpreter MIR (Mid-level IR Rust). Wykrywa UB w unsafe code: out-of-bounds, uninitialized memory, alignment violations, data races.

rustup +nightly component add miri
cargo +nightly miri test

rustls — TLS bez OpenSSL

rustls stanowi modern alternative dla OpenSSL. Memory-safe (Rust), audytowane, brak gigantycznej historii CVE jaka ma OpenSSL. Uzywany przez Cloudflare, AWS, NPM, hyperium.

// Cargo.toml
[dependencies]
reqwest = { version = "0.12", default-features = false, features = ["rustls-tls", "json"] }

// Kod — TLS dziala automatycznie
let resp = reqwest::get("https://api.example.com/data")
    .await?
    .json::<serde_json::Value>()
    .await?;

Web app security — typowe wzorce

Password hashing — argon2

use argon2::{Argon2, password_hash::{
    PasswordHasher, PasswordVerifier, SaltString, rand_core::OsRng
}};
use argon2::PasswordHash;

fn hashuj_haslo(haslo: &str) -> Result<String, argon2::password_hash::Error> {
    let salt = SaltString::generate(&mut OsRng);
    let argon2 = Argon2::default();
    let hash = argon2.hash_password(haslo.as_bytes(), &salt)?.to_string();
    Ok(hash)
}

fn weryfikuj_haslo(haslo: &str, hash: &str) -> bool {
    let parsed = match PasswordHash::new(hash) {
        Ok(h) => h,
        Err(_) => return false,
    };
    Argon2::default().verify_password(haslo.as_bytes(), &parsed).is_ok()
}

JWT

Crate jsonwebtoken — najpopularniejsza biblioteka. Wspiera HS256, RS256, ES256, EdDSA. Uwaga: nigdy nie uzywaj algorithm: "none".

OAuth2

Crate oauth2 implementuje wszystkie flow (authorization code z PKCE, client credentials, device code). Bezpieczny i type-safe.

Supply chain security

Crates.io ma okolo 160 000 paczek (2026), co tworzy powaznae powierzchnie ataku. Najwazniejsze narzedzia obronne:

  • cargo-vet — Mozilla tool do weryfikacji audytow zaleznosci (kto sprawdzil daty?)
  • cargo-crev — distributed code review system
  • cargo-supply-chain — pokazuje, ktorzy autorzy stoja za zaleznosciami
  • crates.io malicious package detection — automatyczne skanowanie nowych releaseow
  • Cargo.lock commit do git — reproducible builds, locked versions
  • --locked flag w CI

Praktyczna zasada

Kazdy nowy projekt powinien miec w CI: cargo audit, cargo deny check, cargo clippy -- -D warnings, cargo test --locked. To 4 polecenia, ktore eliminuja 80% problemow.
