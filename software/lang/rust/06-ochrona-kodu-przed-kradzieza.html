Ochrona kodu Rust przed kradzieza

Rust kompiluje sie do native binary. Co to oznacza w praktyce dla reverse engineering, anti-piracy i ochrony wartosci intelektualnej.

Dlaczego Rust juz jest dobrze chroniony

Rust kompiluje sie bezposrednio do native machine code przez LLVM, podobnie jak C i C++. To stanowi znaczna ochrone w porownaniu do platform takich jak .NET (IL bytecode) czy Java (JVM bytecode).

Strip symbols — pierwsza linia obrony

Domyslnie Rust release builds zawieraja symbole debug, ktore znaczaco ulatwiaja reverse engineering. Pierwsze co nalezy zrobic to wylaczyc je w Cargo.toml.

Optymalna konfiguracja release

# Cargo.toml
[profile.release]
strip = true              # usuwa symbole z binary
lto = "fat"               # link-time optimization (cross-crate)
codegen-units = 1         # jedna jednostka = lepsze optimization
panic = "abort"           # brak unwinding code
opt-level = 3             # maksymalne optymalizacje
overflow-checks = false   # brak checks dla wydajnosci

# Dla maksymalnej ochrony:
[profile.release.package."*"]
opt-level = 3
strip = true

Manualny strip command

# Linux / macOS
strip -s target/release/moja_aplikacja

# z dodatkowymi opcjami
strip --strip-all --remove-section=.comment --remove-section=.note \
    target/release/moja_aplikacja

# Windows (mingw)
strip --strip-all moja_aplikacja.exe

# Sprawdz rozmiar i symbole
ls -lh target/release/moja_aplikacja
nm target/release/moja_aplikacja | head    # powinien byc pusty

Disassembly — jakie sa limity

Po stripie binary wciaz mozna zdezasemblowac (IDA Pro, Ghidra, radare2, Binary Ninja). Ale dezasembler pokazuje assembly, nie oryginalny Rust. Roznica jest ogromna:

  • Generic types znikaja (monomorphization rozprasza je w wielu funkcjach)
  • Wszystkie inline closures, iteratory, async transformations sa zdejmowane
  • LTO + opt-level=3 agresywnie inlinuje i usuwa "martwy" kod
  • Names mangling (Rust ABI v0) — funkcje nie maja czytelnych nazw
  • Borrow checker informacje znikaja calkowicie

Praktycznie reverse engineering Rust binary wymaga:

  1. Glebokiej wiedzy assembly (x86-64 / ARM64)
  2. Plynnosci w IDA Pro lub Ghidra
  3. Znajomosci wzorcow Rust runtime (panic, format, drop)
  4. Czesto setek godzin pracy dla nieoczywistych algorytmow

To znaczy: dla typowego komercyjnego software nie jest to oplacalna inwestycja czasu — chyba ze chodzi o kradziez konkretnego algorytmu.

Code signing — wymog dla dystrybucji

Windows — EV Code Signing Certificate

Bez podpisu Windows SmartScreen blokuje kazdy nowy executable. Cena okolo USD 400/rok za EV cert (Sectigo, DigiCert, GlobalSign).

signtool sign /tr http://timestamp.sectigo.com /td sha256 /fd sha256 ^
    /a moja_aplikacja.exe

macOS — Apple Developer ID Application

Wymagane Developer Account (USD 99/rok) + notarization process. Bez tego macOS Gatekeeper blokuje aplikacje.

# Podpisanie
codesign --deep --force --options runtime \
    --sign "Developer ID Application: Twoja Nazwa (TEAMID)" \
    moja_aplikacja.app

# Notarization (od macOS 10.15+)
xcrun notarytool submit moja_aplikacja.zip \
    --apple-id email@example.com --team-id TEAMID \
    --password app-specific-password --wait

# Stapling
xcrun stapler staple moja_aplikacja.app

Linux

Brak centralnego mechanizmu signing. AppImage moze byc podpisany GPG. Snap i Flatpak maja wlasne signing przez store.

License management

Native binary nie chroni przed kopiowaniem samego pliku — kazdy moze go uruchomic. Aplikacje komercyjne potrzebuja systemu licencjonowania.

License keys

  • Online activation — aplikacja loguje sie do serwera przy pierwszym uruchomieniu
  • JWT-based offline licenses — RSA / Ed25519 signed tokeny z expiry
  • Hardware fingerprinting — link do CPU ID, MAC address, dysku (sha256 z kombinacji)
  • License files — RSA-signed pliki konfiguracyjne

JWT-based offline license — przyklad

use jsonwebtoken::{decode, DecodingKey, Validation, Algorithm};
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize)]
struct Licencja {
    sub: String,        // user id
    exp: i64,           // expiry timestamp
    features: Vec<String>,
    fingerprint: String,
}

fn weryfikuj_licencje(token: &str) -> Result<Licencja, String> {
    let public_key = include_bytes!("../keys/license_public.pem");
    let key = DecodingKey::from_ed_pem(public_key)
        .map_err(|e| e.to_string())?;
    let validation = Validation::new(Algorithm::EdDSA);

    let token_data = decode::<Licencja>(token, &key, &validation)
        .map_err(|e| e.to_string())?;

    let aktualny_fp = wygeneruj_fingerprint();
    if token_data.claims.fingerprint != aktualny_fp {
        return Err("Licencja niezgodna z urzadzeniem".to_string());
    }
    Ok(token_data.claims)
}

Komercyjne rozwiazania

  • Keygen.sh — popular API-driven licensing service
  • Cryptolens — license management with Rust SDK
  • LicenseSpring — enterprise focus
  • Paddle — sklep + licensing

Anti-debug techniques

Wykrywanie czy aplikacja jest uruchomiona pod debuggerem. To opozni atak ale nie zatrzyma zdeterminowanego reverse engineera.

Linux — ptrace detection

// Cargo.toml: nix = "0.27"
use nix::sys::ptrace;
use std::process;

fn jestem_pod_debug() -> bool {
    match ptrace::traceme() {
        Ok(_) => false,
        Err(_) => true,  // ktos juz traceuje
    }
}

fn main() {
    if jestem_pod_debug() {
        eprintln!("Wykryto debugger");
        process::exit(1);
    }
}

Windows — IsDebuggerPresent

use windows::Win32::System::Diagnostics::Debug::IsDebuggerPresent;

fn debugger_obecny() -> bool {
    unsafe { IsDebuggerPresent().as_bool() }
}

// Bardziej zaawansowane: CheckRemoteDebuggerPresent, NtQueryInformationProcess

Checksum sekcji kodu

fn weryfikuj_integralnosc() -> bool {
    // Wczytanie wlasnej sekcji .text z obecnego procesu
    // Hash SHA-256 i porownanie z oczekiwana wartoscia
    // Jezeli ktos modyfikuje code (np. patch JNE -> JMP), zmieni sie hash
    let hash_obecny = oblicz_hash_sekcji_text();
    let oczekiwany = include_bytes!("../checksums/text_section.sha256");
    hash_obecny.as_bytes() == oczekiwany
}

Hardening compiler flags

Rust kompilator wspiera wiele flag wzmacniajacych bezpieczenstwo. Niektore sa domyslne, inne trzeba wlaczyc.

# Zmienna srodowiskowa
export RUSTFLAGS="-C link-arg=-pie \
                  -C relocation-model=pic \
                  -C link-arg=-Wl,-z,relro,-z,now \
                  -C link-arg=-Wl,-z,noexecstack \
                  -C overflow-checks=on"

cargo build --release
FlagCo robi
-C link-arg=-piePosition Independent Executable (ASLR)
-C relocation-model=picPosition-Independent Code
-Wl,-z,relro,-z,nowRead-only relocations (anti GOT-overwrite)
-Wl,-z,noexecstackNX stack (DEP)
-C overflow-checks=onWlaczone runtime checks dla integer overflow
-C panic=abortBrak unwinding code (mniej attack surface)
-Z sanitizer=addressAddressSanitizer (tylko nightly)

Code virtualization — VMProtect dla Rust

VMProtect, Themida i podobne narzedzia tworza wlasna mikro-VM ktora interpretuje przelozony kod. Reverse engineer musialby najpierw zrozumiec architekture VM, potem analizowac wirtualny kod.

  • VMProtect dziala tak samo dobrze dla Rust jak dla C++ binary
  • Koszt: USD 600-3000 za licencje (zaleznie od features)
  • Spowalnia kod chronionych funkcji 10-100x — chronisz tylko critical paths
  • Themida ma podobne mozliwosci, jest niemiecka
  • Obniza false positive ratio antywirusow tylko gdy kupisz dodatkowo "anti-AV" feature
  • W Rust ekosystemie rzadko spotykane (drogie, niche)

Real example — Cloudflare Pingora

Cloudflare Pingora to proxy server zastepujacy Nginx w infrastrukturze CDN — obsluguje ponad bilion request dziennie. Czesc kodu jest open-source (MIT/Apache 2.0), ale critical optimizations i specyficzne integracje pozostaly proprietary.

Strategia ochrony:

  • Open-source core — daje credibility i enables wsparcie spolecznosci
  • Proprietary plugins — kompilowane jako native binary z LTO i strip
  • Server-side execution only — kod nigdy nie opuszcza datacenter Cloudflare
  • Hardware-bound — niektore funkcje wymagaja specyficznego hardware

To pokazuje typowy wzorzec: open-source generic functionality, proprietary optimization layer. Native binary Rust + LTO + strip = wystarczajaca ochrona dla tego modelu.

Praktyczna rekomendacja

Dla 95% komercyjnych Rust applications: strip = true + lto = "fat" + code signing wystarczy. Kombinacja jest bezplatna (poza certyfikatami signing) i podnosi koszt reverse engineering powyzej wartosci dla atakujacego.

Dodaj license server i fingerprint hardware, jezeli sprzedajesz desktop SaaS. VMProtect dopiero gdy masz konkretny algorytm warty grube tysiace dolarow ochrony.
