1. Systems Programming

Co mozesz zbudowac

  • Kernel modules — Linux kernel akceptuje Rust od 2022, Windows kernel components od 2024
  • Drivers — graphics, network, storage drivers
  • Operating systems — Redox OS (eksperymentalny OS w Rust), Theseus, Tock
  • Hypervisors / VMMs — Firecracker (Amazon, microVM dla Lambda), Cloud Hypervisor
  • Container runtimes — youki (low-level container runtime)
  • File systems — bcachefs (next-gen Linux fs)
  • Bootloaders — bootloaders dla embedded systems

Realny przyklad: Firecracker (Amazon)

Firecracker to microVM hypervisor uzywany przez AWS Lambda do izolacji funkcji. Napisany w Rust, ~50k linii kodu. Boots w ~125ms, memory overhead ~5MB. Zastapil Docker dla Lambdy w 2018.

Frameworki / biblioteki

  • nix — bezpieczne POSIX bindings
  • rust-bindgen — generuje Rust bindings z C headers
  • libloading — dynamic library loading
  • uefi-rs — UEFI applications w Rust

Realny przyklad: Pingora (Cloudflare)

Pingora to HTTP proxy framework Cloudflare ktory zastapil Nginx w produkcji. Obsluguje 1+ trillion requestow dziennie. Po migracji:

  • 70% mniej zuzycia CPU
  • 67% mniej zuzycia pamieci
  • Zero-downtime upgrades
  • P99 latency redukcja

Open source od 2024 (github.com/cloudflare/pingora).

Hello World w Axum

use axum::{routing::get, Router, Json};
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
struct User { id: u32, name: String }

async fn list_users() -> Json<Vec<User>> {
    Json(vec![
        User { id: 1, name: "Alice".to_string() },
        User { id: 2, name: "Bob".to_string() },
    ])
}

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/users", get(list_users));

    let listener = tokio::net::TcpListener::bind("0.0.0.0:3000")
        .await.unwrap();
    axum::serve(listener, app).await.unwrap();
}

3. CLI Tools

Dlaczego Rust dla CLI

  • Single binary — distribuujesz jeden plik, dziala wszedzie
  • Fast startup — ~5ms vs Node.js ~50-200ms vs Python ~100-300ms
  • Cross-platform — Windows, macOS, Linux z jednego codebase
  • Memory efficient — male obrazy, low memory footprint
  • Beautiful CLI — clap framework jest world-class

4. Embedded / IoT

Co mozesz zbudowac

  • Microcontroller firmware — ESP32, RP2040 (Raspberry Pi Pico), STM32, nRF52
  • Real-time control systems — robotics, industrial automation
  • IoT devices — sensors, actuators, smart home
  • Drone autopilots
  • Wearables
  • Automotive — Volvo i Mercedes uzywaja Rust w in-car systems

Dlaczego Rust dla embedded

  • no_std — Rust bez stdlib, maly footprint (<10 KB binary mozliwy)
  • Zero-cost abstractions — wysokie poziomy konstrukty bez overhead
  • Memory safety — krytyczne w safety-critical systemach
  • No GC — predykcyjne timing
  • Async w no_std — embassy framework wprowadzil async/await dla MCU
  • Hardware abstraction — embedded-hal trait

Frameworki embedded

  • embassy — modern async embedded framework (2024+ standard)
  • RTIC — Real-Time Interrupt-driven Concurrency
  • embedded-hal — hardware abstraction layer
  • probe-rs — debugging i flashing toolkit
  • defmt — efficient logging dla embedded

Przyklad: blink LED na ESP32

#![no_std]
#![no_main]

use embassy_executor::Spawner;
use embassy_time::{Duration, Timer};
use esp_hal::{gpio::{Io, Level, Output}, prelude::*};

#[esp_hal_embassy::main]
async fn main(_spawner: Spawner) {
    let peripherals = esp_hal::init(esp_hal::Config::default());
    let io = Io::new(peripherals.GPIO, peripherals.IO_MUX);
    let mut led = Output::new(io.pins.gpio2, Level::Low);

    loop {
        led.toggle();
        Timer::after(Duration::from_millis(500)).await;
    }
}

5. Blockchain / Cryptocurrency

Co mozesz zbudowac

  • Layer 1 blockchains — Solana, Polkadot, NEAR, Aptos (caly stack w Rust)
  • Smart contracts — ink! dla Polkadot, anchor dla Solana
  • Crypto wallets — Ledger firmware components, hardware wallets
  • Crypto exchanges — backend high-frequency trading
  • DeFi protocols
  • Zero-knowledge proof systems — zk-SNARKs, zk-STARKs
  • MEV bots

Dlaczego Rust dla crypto

  • Memory safety — bug w crypto = utrata milionow $
  • Performance — high-frequency trading wymaga <1ms latency
  • Cryptographic primitives — ekosystem RustCrypto jest bogaty
  • Determinizm — kazda noda dostaje ten sam wynik

Biblioteki

  • RustCrypto — comprehensive crypto primitives (AES, RSA, ECDSA, etc.)
  • ring — fast cryptographic primitives
  • arkworks — zero-knowledge proofs
  • solana-sdk — Solana smart contracts
  • substrate — Polkadot blockchain framework
  • ethers-rs — Ethereum bindings

6. Game Engines / Graphics

Stan w 2026

Rust w gaming jest rosnacy ale wciaz niche. Unity (C#) i Unreal (C++) dominuja komercyjnie. Rust jest popularny dla indie dev z preferencja do clean architecture.

Engines

  • Bevy — Entity-Component-System (ECS) engine, najpopularniejszy Rust engine 2026
  • Fyrox — pelnoprawny game engine z editorem (jak Unity)
  • Ambient — multiplayer-first runtime (kompiluje do WASM)
  • Macroquad — proste 2D, latwiejsze niz Bevy

Graphics / rendering

  • wgpu — implementacja WebGPU API (cross-platform graphics)
  • vulkano — Vulkan bindings (wysokopoziomowe)
  • ash — Vulkan bindings (niskopoziomowe)
  • winit — cross-platform window management

Slynne gry w Rust

  • Veloren — open-world multiplayer, najwiekszy Bevy game
  • Tunnet — networking puzzler (komercyjny)
  • Hytopia — block-based MMO
  • Roblox — Hyperion anti-cheat w Rust

8. WebAssembly

Co mozesz zbudowac

  • Browser apps — alternatywa do React/Vue (Yew, Leptos)
  • Edge functions — Cloudflare Workers, Vercel Edge, Fastly Compute
  • Plugins / extensions — sandboxowane plugins dla aplikacji
  • Serverless WASM — wasmCloud, Spin (Fermyon)
  • Game logic w przegladarce — np. Figma uses WASM
  • Image / video processing w przegladarce
  • ML inference w browser

Dlaczego Rust dla WASM

  • Najmniejszy bundle size (vs Go ~2MB minimum, Rust ~50KB minimum)
  • Najszybsze wykonanie
  • Pelne wsparcie WASM od dawna
  • wasm-bindgen dla bridge JS ↔ Rust

Frameworki web frontend (Rust → WASM)

  • Yew — React-inspired
  • Leptos — fine-grained reactivity (popularny 2026)
  • Dioxus — full-stack (web/mobile/desktop)
  • Sycamore — reactive bez VDOM
  • Trunk — build tool dla WASM apps

9. ML / AI Inference

Co mozesz zbudowac

  • Edge AI inference — modele AI na urzadzeniach mobile/IoT
  • Server-side LLM hosting — alternatywa do Python serving
  • Real-time ML pipelines
  • Computer vision — image processing w real-time
  • Model conversion / quantization tools

Frameworki ML 2026

  • candle (HuggingFace) — minimalist ML framework, ~1MB binary, no Python deps
  • tch-rs — PyTorch bindings
  • burn — modern ML framework (multi-backend: WGPU, Candle, ndarray)
  • ort — ONNX Runtime bindings
  • llama.cpp Rust bindings — LLM inference
  • polars — DataFrames, alternative do pandas (10-100x szybszy)

Realny przyklad: Hugging Face candle

Hugging Face wydalo candle w 2023 jako alternatywe dla PyTorch w deployment. W 2026 candle jest popularny w:

  • Edge AI inference (mobile, IoT)
  • Serverless ML (mniejsze cold start)
  • WASM ML w browser
  • Embedded LLM inference

12. Czego NIE pisac w Rust

Rust jest zly wybor dla:

  • Quick prototypes / MVP — Python/JavaScript szybsze do iteracji
  • Data science / Jupyter notebooks — Python ekosystem (pandas, scikit-learn) ma wszystko
  • Simple CRUD web apps — Django/Rails/Laravel produktywniejsze
  • Mobile apps z native UI — Swift/Kotlin lepsi dla iOS/Android
  • Office plugins / VSTO — C# is required
  • Unity games — C# is required
  • SharePoint / Microsoft 365 dev — C# / TypeScript
  • Scripting — Python/Bash
  • Junior-friendly projects — krzywa uczenia za stroma

Decision tree: czy Rust jest dla mojego projektu?

Czy projekt wymaga performance < 10ms p99 latency?
  TAK → Rust strong fit
  NIE → idz dalej

Czy targetujesz embedded / IoT?
  TAK → Rust (z embassy)
  NIE → idz dalej

Czy budujesz CLI tool?
  TAK → Rust dobry fit (single binary, fast)
  NIE → idz dalej

Czy WASM jest priorytetem (browser/edge)?
  TAK → Rust optimal
  NIE → idz dalej

Czy masz zespol z C++ background lub chcesz inwestowac w upskill?
  TAK → Rust mozliwy
  NIE → uzyj C# / Go / Python

Czy memory safety jest critical (security/compliance)?
  TAK → Rust (najsilniejsze gwarancje)
  NIE → idz dalej

Czy budujesz dlugo-running service (years) gdzie GC pauzy boli?
  TAK → Rust dobry fit
  NIE → uzyj C#/Go (szybszy development)

Czy team to seniorzy?
  TAK → Rust mozliwy
  NIE → C#/Go safer choice

Stack rekomendacje per use case (2026)

Web API z high performance

Rust + Axum + sqlx + Postgres + Redis. Deploy: Docker (~20MB image), Kubernetes lub Fly.io.

CLI tool open source

Rust + clap + tokio (async I/O). Distribute: cargo install, GitHub Releases binaries cross-platform via cargo-dist.

Embedded device

Rust + embassy + embedded-hal + defmt. Hardware: ESP32 / RP2040 / STM32.

Cross-platform desktop app

Rust + Tauri 2 + (React/Vue/Svelte frontend). Single binary, ~10-30MB.

WASM module dla browser

Rust + wasm-bindgen + Trunk. Output: optimized WASM ~50-200KB.

Edge function

Rust → WASM. Deploy: Cloudflare Workers, Fastly Compute, Spin (Fermyon).

Smart contract / blockchain app

Rust + anchor (Solana) lub ink! (Polkadot/Substrate).

Game (indie)

Rust + Bevy + custom assets. Lub Fyrox jesli chcesz editor.
