Narzedzia i deployment

Pelne wykorzystanie ekosystemu Cargo, IDE rust-analyzer, cross-compilation, Docker, CI/CD i deploy do nowoczesnych platform.

Cargo — gleboko

Workspaces — projekty multi-crate

Workspace pozwala miec jeden projekt skladajacy sie z wielu crates ktore wspoldziela Cargo.lock i target/. Idealne dla dzielenia kodu pomiedzy backend, CLI i bibliotekami.

# Cargo.toml (root)
[workspace]
resolver = "3"
members = [
    "core",        # biblioteka wspoldzielona
    "api",         # web server
    "cli",         # narzedzie linii polecen
    "worker",      # background jobs
]

[workspace.dependencies]
tokio = { version = "1.40", features = ["full"] }
serde = { version = "1.0", features = ["derive"] }
sqlx = { version = "0.8", features = ["postgres", "runtime-tokio-rustls"] }

# core/Cargo.toml
[dependencies]
tokio = { workspace = true }
serde = { workspace = true }

Features — conditional compilation

# Cargo.toml
[features]
default = ["json"]
json = ["dep:serde_json"]
yaml = ["dep:serde_yaml"]
full = ["json", "yaml", "metrics"]
metrics = ["dep:prometheus"]

[dependencies]
serde_json = { version = "1.0", optional = true }
serde_yaml = { version = "0.9", optional = true }
prometheus = { version = "0.13", optional = true }

# Build z konkretnym feature
cargo build --features yaml --no-default-features
cargo build --features full

Code formatting i linting

rustfmt

Wbudowane w toolchain. Konfigurowalne przez rustfmt.toml:

# rustfmt.toml
edition = "2024"
max_width = 100
hard_tabs = false
tab_spaces = 4
newline_style = "Unix"
imports_granularity = "Crate"
group_imports = "StdExternalCrate"
reorder_imports = true

# uzycie
cargo fmt           # formatuj
cargo fmt -- --check   # tylko sprawdz (CI)

clippy — must-have linter

Clippy zawiera ponad 600 lintow podzielonych na kategorie. Bez clippy programowanie w Rust traci polowe wartosci feedback loop.

# Instalacja (zwykle juz jest)
rustup component add clippy

# Standardowe uzycie
cargo clippy

# Warning jako error (CI)
cargo clippy -- -D warnings

# Ze wszystkimi pedantic + nursery
cargo clippy -- -W clippy::pedantic -W clippy::nursery

# Tylko konkretna kategoria
cargo clippy -- -W clippy::correctness

Kategorie clippy:

  • correctness — kod prawie na pewno blad
  • suspicious — kod ktory wyglada na blad
  • style — naruszenia idiomatycznego stylu
  • complexity — kod ktory mozna uproscic
  • perf — wzorce z przewidywalnym narzutem
  • pedantic — bardzo restrykcyjne (opt-in)
  • nursery — eksperymentalne
  • cargo — problemy z metadanami Cargo.toml

IDE i edytory

rust-analyzer — LSP standard

rust-analyzer jest oficjalnym LSP serverem rozwijanym przez Rust Foundation. Dziala wszedzie gdzie jest LSP: VS Code, Vim/Neovim, Emacs, Helix, Sublime, JetBrains.

  • Inline type hints, parametry, lifetimes
  • Autocomplete z trait method resolution
  • Refaktor: extract function, inline, rename, change signature
  • Code actions: derive, fill match arms, expand macro
  • Quick fix dla compiler errors
  • Run/debug single test from gutter

JetBrains RustRover

Komercyjne IDE dedykowane Rust (rebrand wczesniejszego pluginu IntelliJ Rust). Cena okolo USD 99/rok personal, USD 269/rok commercial. Free dla studentow i open-source.

Dokumentacja — rustdoc

Wbudowany generator dokumentacji. Komentarze /// nad pozycjami sa parsowane i staja sie HTML.

/// Oblicza pole prostokata.
///
/// # Argumenty
///
/// * `szerokosc` - dlugosc boku poziomego
/// * `wysokosc` - dlugosc boku pionowego
///
/// # Przyklad
///
/// ```
/// let p = moja_lib::pole_prostokata(3.0, 4.0);
/// assert_eq!(p, 12.0);
/// ```
///
/// # Panic
///
/// Funkcja nie panickuje dla wartosci dodatnich. Dla ujemnych zwraca
/// wartosc niefizyczna (matematyczne pole).
pub fn pole_prostokata(szerokosc: f64, wysokosc: f64) -> f64 {
    szerokosc * wysokosc
}
# Generuj i otworz w przegladarce
cargo doc --open

# Bez deps (szybciej)
cargo doc --no-deps

# Sprawdz czy wszystkie publiczne items maja docs (CI!)
RUSTDOCFLAGS="-D missing-docs" cargo doc

# Run doctests (kod w komentarzach)
cargo test --doc

cross — Docker-based cross-compilation

Tool cross rozwiazuje problem braku linkers i shared libraries dla docelowej platformy uzywajac dedykowanych Docker images.

cargo install cross

# Compilacja Linux ARM64 z Linux x64
cross build --release --target aarch64-unknown-linux-gnu

# Static binary musl (idealne dla containerow)
cross build --release --target x86_64-unknown-linux-musl

Docker — multi-stage builds

Rust binaries sa native, ktore znaczy ze obrazy moga byc bardzo male. Multi-stage build z distroless final image to standard.

# Dockerfile
FROM rust:1.86-alpine AS builder
WORKDIR /app

# Cache dla deps (osobny layer)
COPY Cargo.toml Cargo.lock ./
RUN mkdir src && echo "fn main() {}" > src/main.rs && \
    cargo build --release && \
    rm -rf src

# Faktyczny build
COPY src ./src
RUN cargo build --release && \
    strip target/release/moja_aplikacja

# Final image — distroless
FROM gcr.io/distroless/cc-debian12
COPY --from=builder /app/target/release/moja_aplikacja /

ENTRYPOINT ["/moja_aplikacja"]

Typowe rozmiary:

  • FROM scratch + static musl: 5-15 MB
  • FROM gcr.io/distroless/cc: 25-30 MB (potrzebuje libc dynamic)
  • FROM alpine: 15-20 MB
  • FROM debian:slim: 80 MB+
  • Porownanie: typowy obraz Node.js 200-400 MB, JVM 250+ MB

CI/CD — GitHub Actions

Pelny przyklad workflow z cache, matrix testing i build artifactow:

# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  CARGO_TERM_COLOR: always

jobs:
  test:
    name: Test (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        rust: [stable]

    steps:
      - uses: actions/checkout@v4

      - name: Install Rust
        uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy

      - name: Cache cargo
        uses: Swatinem/rust-cache@v2

      - name: Format check
        run: cargo fmt --all -- --check

      - name: Clippy
        run: cargo clippy --all-targets --all-features -- -D warnings

      - name: Test
        run: cargo test --all-features --workspace

      - name: Build release
        run: cargo build --release

  audit:
    name: Security audit
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: rustsec/audit-check@v1
        with:
          token: ${{ secrets.GITHUB_TOKEN }}

  release:
    name: Release binaries
    needs: [test, audit]
    if: startsWith(github.ref, 'refs/tags/v')
    strategy:
      matrix:
        include:
          - target: x86_64-unknown-linux-musl
            os: ubuntu-latest
          - target: x86_64-pc-windows-msvc
            os: windows-latest
          - target: aarch64-apple-darwin
            os: macos-latest
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.target }}
      - run: cargo build --release --target ${{ matrix.target }}
      - uses: actions/upload-artifact@v4
        with:
          name: binary-${{ matrix.target }}
          path: target/${{ matrix.target }}/release/moja_aplikacja*

Benchmarking — criterion

# Cargo.toml
[dev-dependencies]
criterion = "0.5"

[[bench]]
name = "moje_benchmarki"
harness = false

# benches/moje_benchmarki.rs
use criterion::{black_box, criterion_group, criterion_main, Criterion};
use moja_lib::sortuj;

fn bench_sortowanie(c: &mut Criterion) {
    let mut grupa = c.benchmark_group("sortowanie");
    for rozmiar in [100, 1000, 10000].iter() {
        grupa.bench_with_input(format!("size_{}", rozmiar), rozmiar, |b, &n| {
            let dane: Vec<i32> = (0..n).rev().collect();
            b.iter(|| sortuj(black_box(dane.clone())));
        });
    }
}

criterion_group!(benches, bench_sortowanie);
criterion_main!(benches);

# Uruchomienie:
cargo bench

Praktyczna checklist

  • cargo fmt + cargo clippy + cargo test w pre-commit hook
  • cargo audit + cargo deny w CI
  • Multi-stage Dockerfile z distroless final image
  • GitHub Actions matrix testing (Linux + Win + macOS)
  • Workspaces dla projektow ponad 2-3 crate
  • cargo-release lub release-plz dla automatycznego releasu
  • rust-analyzer + clippy w VS Code minimum
