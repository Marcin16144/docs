Podstawy Rust

Wprowadzenie do jezyka, ktory zmienil sposob mysleniaa o systems programming. Ownership, borrowing, lifetimes — i dlaczego sa wazne.

Historia w pigulce

Rust narodzil sie w 2010 roku jako personalny projekt Grayodona Hoare, inzyniera Mozilla Research. W 2010 firma Mozilla zaczela oficjalnie sponsorowac jego rozwoj, widzac w nim potencjal zastapienia C++ w niskopoziomowych komponentach przegladarki. Pierwsza wersja stabilna 1.0 ukazala sie w maju 2015 roku.

Punktem zwrotnym byl luty 2021, gdy powstala niezalezna Rust Foundation, do ktorej dolaczyly Mozilla, Microsoft, Google, AWS, Meta i Huawei jako platinum sponsors. Od tego czasu Rust rozwija sie szybko i niezaleznie od pojedynczego sponsora.

W 2026 dominujaca specyfikacja jezyka to Rust 2024 edition (oficjalnie wydana w lutym 2025), ktora wprowadzila let-else stabilization, async closures, RPITIT (return position impl trait in trait) i ulepszony lifetime elision.

Ownership, Borrowing, Lifetimes — serce Rusta

To kluczowy koncept, ktory rozni Rust od wszystkich innych mainstream languages. Kompilator wymusza w czasie kompilacji zasady, ktore zapobiegaja use-after-free, double-free, data race i wycieki pamieci — bez garbage collectora.

Trzy zasady ownership

  1. Kazda wartosc ma jednego wlasciciela (variable)
  2. W danej chwili moze byc tylko jeden wlasciciel
  3. Gdy wlasciciel wychodzi ze scope, wartosc jest automatycznie zwalniana (drop)

Move semantics

let s1 = String::from("witaj");
let s2 = s1;           // MOVE — s1 juz nie istnieje!
// println!("{}", s1); // BLAD kompilacji!
println!("{}", s2);    // OK

Borrowing — referencje

fn dlugosc(s: &String) -> usize {
    s.len()           // immutable borrow
}

fn main() {
    let s = String::from("witaj");
    let dl = dlugosc(&s);   // pozyczamy, nie movujemy
    println!("'{}' ma {} znakow", s, dl);  // s nadal istnieje!
}

Mutable borrow — tylko jeden na raz

fn dodaj_wykrzyknik(s: &mut String) {
    s.push('!');
}

let mut s = String::from("witaj");
dodaj_wykrzyknik(&mut s);   // mutable borrow
println!("{}", s);          // "witaj!"

Structs i enums

struct Punkt {
    x: f64,
    y: f64,
}

impl Punkt {
    fn new(x: f64, y: f64) -> Self {
        Punkt { x, y }
    }

    fn dystans_od_zera(&self) -> f64 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}

enum Figura {
    Kwadrat(f64),
    Prostokat { szerokosc: f64, wysokosc: f64 },
    Kolo(f64),
}

impl Figura {
    fn pole(&self) -> f64 {
        match self {
            Figura::Kwadrat(a) => a * a,
            Figura::Prostokat { szerokosc, wysokosc } => szerokosc * wysokosc,
            Figura::Kolo(r) => std::f64::consts::PI * r * r,
        }
    }
}

Option i Result — error handling

Rust nie ma null. Zamiast tego uzywa enums Option<T> i Result<T, E>. Kompilator wymusza obsluge wszystkich wariantow.

fn znajdz_wiek(imie: &str) -> Option<u32> {
    match imie {
        "Anna" => Some(28),
        "Marek" => Some(35),
        _ => None,
    }
}

fn dziel(a: f64, b: f64) -> Result<f64, String> {
    if b == 0.0 {
        Err(String::from("Dzielenie przez zero"))
    } else {
        Ok(a / b)
    }
}

Operator ? — error propagation

use std::fs;
use std::io;

fn wczytaj_konfiguracje() -> Result<String, io::Error> {
    let zawartosc = fs::read_to_string("config.toml")?;  // ? propaguje blad
    Ok(zawartosc)
}

Pelny przyklad — kalkulator

use std::io::{self, Write};

#[derive(Debug)]
enum BladKalkulatora {
    DzielenieprzezZero,
    NieprawidloweDane(String),
}

fn parsuj(s: &str) -> Result<f64, BladKalkulatora> {
    s.trim().parse::<f64>()
        .map_err(|_| BladKalkulatora::NieprawidloweDane(s.to_string()))
}

fn oblicz(a: f64, op: char, b: f64) -> Result<f64, BladKalkulatora> {
    match op {
        '+' => Ok(a + b),
        '-' => Ok(a - b),
        '*' => Ok(a * b),
        '/' if b == 0.0 => Err(BladKalkulatora::DzielenieprzezZero),
        '/' => Ok(a / b),
        _ => Err(BladKalkulatora::NieprawidloweDane(op.to_string())),
    }
}

fn main() {
    let mut wejscie = String::new();
    print!("Podaj wyrazenie (np. 3 + 4): ");
    io::stdout().flush().unwrap();
    io::stdin().read_line(&mut wejscie).unwrap();

    let czesci: Vec<&str> = wejscie.split_whitespace().collect();
    if czesci.len() != 3 {
        eprintln!("Format: liczba operator liczba");
        return;
    }

    let a = parsuj(czesci[0]).unwrap();
    let op = czesci[1].chars().next().unwrap();
    let b = parsuj(czesci[2]).unwrap();

    match oblicz(a, op, b) {
        Ok(wynik) => println!("Wynik: {}", wynik),
        Err(e) => eprintln!("Blad: {:?}", e),
    }
}

Modules i crates

Crate = jednostka kompilacji (binary lub library). Module = przestrzen nazw wewnatrz crate.

// src/main.rs
mod matematyka;          // ladowanie modulu z src/matematyka.rs
mod uzytkownik {         // inline module
    pub fn pozdrow() {
        println!("Czesc!");
    }
}

use matematyka::dodaj;   // import

fn main() {
    let s = dodaj(3, 4);
    println!("{}", s);
    uzytkownik::pozdrow();
}

Standardowa struktura projektu:

moj_projekt/
├── Cargo.toml          # manifest (zaleznosci, metadane)
├── Cargo.lock          # zablokowane wersje (commit do git!)
├── src/
│   ├── main.rs         # entry point binary
│   ├── lib.rs          # entry point library
│   └── matematyka.rs   # modul
├── tests/              # integration tests
├── benches/            # benchmarki
├── examples/           # przyklady uzycia
└── target/             # output kompilacji (NIE commit!)
