Composer - best practices

composer.lock - zawsze w repo

composer.lock jest obowiazkowy w repozytorium aplikacji (nie bibliotek). Dzieki niemu wszyscy developerzy i CI/CD instaluja te same wersje.

# Production install - tylko na podstawie lock file
composer install --no-dev --optimize-autoloader --classmap-authoritative

# Dev environment
composer install

# Aktualizacja - z rozwaga
composer update                     # wszystko (rzadko!)
composer update vendor/package      # konkretna paczka
composer update --prefer-stable     # tylko stable wersje

Deployer - zero-downtime deployment

Deployer to PHP-native deployment tool inspirowany Capistrano (Ruby). Wykonuje deploy via SSH, robi atomic switch.

# Instalacja
composer require --dev deployer/deployer
vendor/bin/dep init

# deploy.php - przyklad
namespace Deployer;

require 'recipe/symfony.php';

set('repository', 'git@github.com:user/app.git');
set('keep_releases', 5);

host('production')
    ->set('hostname', 'app.example.com')
    ->set('remote_user', 'deploy')
    ->set('deploy_path', '/var/www/app');

// Uruchomienie
// vendor/bin/dep deploy production

FrankenPHP - nowoczesna alternatywa dla PHP-FPM

FrankenPHP (Caddy + PHP) oferuje znaczne zalety dla nowoczesnych deployments:

  • Single binary — PHP wbudowany w serwer
  • HTTP/2, HTTP/3 (QUIC) — out of the box
  • Automatic HTTPS — Let's Encrypt zintegrowany
  • Worker mode — aplikacja w pamieci miedzy requestami
  • Early Hints (103) — preload zasobow
  • Mercure — real-time updates wbudowane
# Docker - najprostsza droga
FROM dunglas/frankenphp:latest

COPY . /app/public
RUN install-php-extensions \
    pdo_mysql \
    redis \
    opcache

# Worker mode w Caddyfile
{
    frankenphp {
        worker /app/public/index.php 4
    }
}

example.com {
    root * /app/public
    php_server
}

OPcache - obowiazkowy w produkcji

OPcache cachuje skompilowany bytecode w pamieci - bez tego PHP parsuje pliki przy kazdym request.

; php.ini - production settings
opcache.enable=1
opcache.enable_cli=0
opcache.memory_consumption=256          ; MB
opcache.interned_strings_buffer=16
opcache.max_accelerated_files=20000
opcache.validate_timestamps=0           ; PROD: nie sprawdzaj zmian
opcache.preload=/app/preload.php        ; PHP 7.4+
opcache.preload_user=www-data

; JIT (PHP 8+)
opcache.jit_buffer_size=128M
opcache.jit=tracing

opcache_compile_file - preload

// preload.php
$files = glob(__DIR__ . '/src/**/*.php');
foreach ($files as $file) {
    opcache_compile_file($file);
}

PHP-FPM tuning

Dobor parametrow zalezy od pamieci RAM i obciazenia.

; /etc/php/8.4/fpm/pool.d/www.conf

pm = dynamic                    ; albo 'static' dla stalego obciazenia
pm.max_children = 50            ; Max liczba procesow
pm.start_servers = 10           ; Startowa liczba
pm.min_spare_servers = 5
pm.max_spare_servers = 15
pm.max_requests = 500           ; Restart workera po N requestach (memory leaks)

; Slow log - logowanie wolnych requestow
slowlog = /var/log/php-fpm-slow.log
request_slowlog_timeout = 5s

; Status page
pm.status_path = /fpm-status
ping.path = /fpm-ping

Wzor: pm.max_children

pm.max_children = (Total RAM - System RAM - Database RAM) / Process RAM

Przyklad: 4 GB RAM, system 500 MB, MySQL 1 GB, jeden proces PHP ~80 MB
pm.max_children = (4096 - 500 - 1024) / 80 = ~32

Docker dla PHP - multi-stage Alpine

# syntax=docker/dockerfile:1.7
FROM composer:2 AS deps
WORKDIR /app
COPY composer.json composer.lock ./
RUN composer install \
    --no-dev \
    --no-scripts \
    --no-autoloader \
    --prefer-dist

# Stage 2: aplikacja
FROM dunglas/frankenphp:php8.4-alpine
WORKDIR /app

# Rozszerzenia produkcyjne
RUN install-php-extensions \
    pdo_mysql \
    opcache \
    redis \
    intl

COPY --from=deps /app/vendor ./vendor
COPY . .
RUN composer dump-autoload --optimize --classmap-authoritative

# OPcache config
COPY docker/php/opcache.ini $PHP_INI_DIR/conf.d/

ENV SERVER_NAME=:80
EXPOSE 80 443

USER www-data

GitHub Actions - CI dla PHP

name: CI
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        php: ['8.3', '8.4']

    steps:
      - uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ matrix.php }}
          extensions: mbstring, pdo, intl
          coverage: pcov
          tools: composer:v2

      - name: Cache Composer
        uses: actions/cache@v4
        with:
          path: vendor
          key: composer-${{ hashFiles('composer.lock') }}

      - name: Install
        run: composer install --no-progress --prefer-dist

      - name: PHPStan
        run: vendor/bin/phpstan analyse --no-progress

      - name: Code style
        run: vendor/bin/pint --test

      - name: Tests
        run: vendor/bin/pest --coverage --min=80

Production checklist

  • display_errors=Off, log_errors=On
  • OPcache enabled, validate_timestamps=0
  • composer install --no-dev --optimize-autoloader
  • Secrets w env vars / vault, nie w repo
  • HTTPS only + HSTS
  • Atomic deploy (Deployer / symlinks)
  • Monitoring (Sentry, Datadog, NewRelic)
  • Backup automatyczny + recovery test
