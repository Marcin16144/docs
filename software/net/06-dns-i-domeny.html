DNS i domeny

System nazw domenowych - hierarchia, rekordy, DNSSEC, DoH, DoT, email auth

Hierarchia DNS

DNS (Domain Name System, RFC 1034/1035, 1987) tlumaczy nazwy ludzkie (example.com) na adresy IP. Jest hierarchiczny - kazda czesc nazwy odpowiada za inny poziom zarzadzania.

# Czytanie nazwy od prawej do lewej:
www.example.com.
 |    |     |  |
 |    |     |  +--- root (domyslnie .)
 |    |     +------ TLD (.com, .pl, .org)
 |    +------------ SLD (Second Level Domain)
 +----------------- subdomena

Rola serwerow DNS

TypFunkcja
Root servers13 logicznych serwerow (a.root-servers.net do m.root-servers.net), w praktyce setki fizycznych przez anycast. Odpowiadaja na zapytania o TLD.
TLD serversSerwery dla .com, .pl, .org itp. Wskazuja na authoritative serwery dla konkretnej domeny.
AuthoritativeWlasciwe serwery domeny - wlasciciel rekordow. Tu trzymaja sie A, MX, TXT itp.
Recursive resolverSerwer ktory dla klienta wykonuje pelne odpytywanie hierarchii i cache'uje wyniki. Cloudflare 1.1.1.1, Google 8.8.8.8, ISP DNS.

Proces resolucji nazwy

# Klient pyta "www.example.com":
1. Klient -> Recursive Resolver (1.1.1.1)
2. Recursive -> Root Server: "kto wie o .com?"
3. Root -> "Spytaj a.gtld-servers.net (TLD .com)"
4. Recursive -> .com TLD: "kto wie o example.com?"
5. TLD -> "Spytaj ns1.example.com (authoritative)"
6. Recursive -> Authoritative: "jaki A dla www.example.com?"
7. Authoritative -> "93.184.216.34"
8. Recursive cache'uje wynik (TTL) i zwraca klientowi

Rekordy DNS

Rekord A i AAAA

A mapuje nazwe na adres IPv4, AAAA na IPv6.

example.com.       3600  IN  A     93.184.216.34
example.com.       3600  IN  AAAA  2606:2800:220:1:248:1893:25c8:1946

# Wiele rekordow A = round-robin DNS:
example.com.       3600  IN  A     1.2.3.4
example.com.       3600  IN  A     1.2.3.5
example.com.       3600  IN  A     1.2.3.6

CNAME - Canonical Name

CNAME tworzy alias - nazwa wskazuje na inna nazwe (nie IP). NIE moze byc na apex (sama domena), tylko na subdomene.

# OK:
www.example.com.   3600  IN  CNAME  example.com.
shop.example.com.  3600  IN  CNAME  shopify.com.

# ZLE - nie wolno na apex:
example.com.       3600  IN  CNAME  www.example.com.    ! BLAD

# Alternatywa: ALIAS / ANAME (nie standard, niektorzy DNS providers):
example.com.       3600  IN  ALIAS  shopify.com.

MX - Mail Exchange

MX wskazuje serwer pocztowy odpowiedzialny za odbieranie maili dla domeny. Kazdy MX ma priority - mniejsza wartosc = wyzszy priorytet.

example.com.    3600  IN  MX  10  mail1.example.com.
example.com.    3600  IN  MX  20  mail2.example.com.    # backup
example.com.    3600  IN  MX  30  mail3.backup.com.

# Google Workspace przyklad:
example.com.    3600  IN  MX   1  smtp.google.com.

TXT - Text records

Generyczne pole tekstowe. Uzywane do SPF, DKIM, DMARC, weryfikacji wlasnosci domeny przez Google/Microsoft, etc.

example.com.            IN  TXT  "v=spf1 ip4:1.2.3.4 include:_spf.google.com -all"
default._domainkey.example.com.  IN  TXT  "v=DKIM1; k=rsa; p=MIGfMA0..."
_dmarc.example.com.     IN  TXT  "v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com"

# Google verification:
example.com.   IN  TXT  "google-site-verification=abc123..."

NS - Name Server

NS wskazuje delegacje na inne serwery DNS odpowiedzialne za podstrefe lub cala domene.

example.com.            IN  NS  ns1.example.com.
example.com.            IN  NS  ns2.example.com.

# Subdelegacja:
sub.example.com.        IN  NS  ns1.subprovider.com.
sub.example.com.        IN  NS  ns2.subprovider.com.

SOA - Start of Authority

SOA opisuje "wlasciciela" strefy - master serwer, email administratora, parametry replikacji.

example.com.   IN  SOA  ns1.example.com. admin.example.com. (
                       2026050701  ; serial (yyyymmddNN)
                       3600        ; refresh (1 godzina)
                       1800        ; retry (30 min)
                       604800      ; expire (7 dni)
                       300         ; minimum TTL (5 min - dla NXDOMAIN)
                       )

CAA - Certificate Authority Authorization

CAA mowi ktora CA moze wystawiac certyfikaty dla domeny. Zabezpieczenie przed bledna CA wystawiajaca cert.

example.com.    IN  CAA  0 issue "letsencrypt.org"
example.com.    IN  CAA  0 issue "digicert.com"
example.com.    IN  CAA  0 iodef "mailto:security@example.com"

# Brak CAA = kazda CA moze wystawic cert

SRV - Service Locator

SRV pozwala znalezc serwer dla konkretnej uslugi. Format: _service._proto.name.

_xmpp-server._tcp.example.com.  IN  SRV  10 5  5269  xmpp.example.com.
_sip._tcp.example.com.          IN  SRV  10 60 5060  sip.example.com.
_minecraft._tcp.example.com.    IN  SRV  0  5  25565 mc.example.com.

# Format: priority weight port target

PTR - reverse DNS

PTR mapuje IP na nazwe (odwrotnosc A). Wymagany dla niektorych aplikacji (mail server reverse DNS check przez SPF).

# Dla 93.184.216.34:
34.216.184.93.in-addr.arpa.  IN  PTR  example.com.

# IPv6 - dluzszy zapis (nibble format):
6.4.9.1.8.c.5.2.3.9.8.1.8.4.2.0.1.0.0.0.0.2.2.0.0.0.8.2.6.0.6.2.ip6.arpa.
                              IN  PTR  example.com.

DNSSEC - DNS Security Extensions

DNSSEC (RFC 4033-4035) podpisuje rekordy DNS cyfrowo. Klient moze sprawdzic czy odpowiedz nie zostala sfalszowana.

  • DNSKEY - klucz publiczny strefy
  • DS - Delegation Signer (w strefie nadrzednej, np. .com)
  • RRSIG - podpis rekordu
  • NSEC / NSEC3 - dowod nieistnienia rekordu
# Sprawdzenie DNSSEC:
dig example.com +dnssec

# Walidacja DNSSEC:
dig +dnssec +cd example.com    # CD = checking disabled
dig +dnssec example.com         # walidacja przez resolver

# Komenda DNSViz (online tool):
# https://dnsviz.net/d/example.com/dnssec/

DoH i DoT - szyfrowane DNS

DoH (DNS over HTTPS)

RFC 8484 (2018) - DNS zapakowany w HTTPS POST/GET. Port 443. Niemozliwy do filtrowania bez deep packet inspection.

# Cloudflare DoH endpoint:
https://cloudflare-dns.com/dns-query

# Test curl:
curl -H 'Accept: application/dns-json' \
  'https://cloudflare-dns.com/dns-query?name=example.com&type=A'

DoT (DNS over TLS)

RFC 7858 - DNS przez TLS na porcie 853. Latwiej go zablokowac niz DoH (port 853 mozna zfiltrowac).

Self-hosted DNS

BIND9

Najstarszy (z 1980), najczesciej uzywany. ISC BIND. Stabilny, dokumentowany, ale konfiguracja moze byc skomplikowana.

Unbound

Lekki, szybki recursive resolver. Idealne polaczenie z Pi-hole jako blocking resolver. Walidacja DNSSEC, DoT, DoH.

PowerDNS

Modularny, wspiera wiele backendow (MySQL, PostgreSQL, LDAP). Authoritative + Recursor.

dnsmasq

Mini DNS+DHCP+TFTP w jednym binarce. Idealne dla malych sieci, OpenWrt.

# dnsmasq - prosta konfiguracja /etc/dnsmasq.conf:
domain=lan.local
interface=eth0
listen-address=127.0.0.1,192.168.1.1
no-resolv
server=1.1.1.1
server=9.9.9.9
cache-size=10000

# Lokalne hosty:
address=/router.lan/192.168.1.1
address=/nas.lan/192.168.1.10

# DHCP:
dhcp-range=192.168.1.100,192.168.1.200,24h
dhcp-host=AA:BB:CC:DD:EE:FF,192.168.1.50,nas

Email authentication: SPF, DKIM, DMARC

SPF (Sender Policy Framework)

SPF lista dozwolonych serwerow wysylajacych mail dla danej domeny. Zapobiega spoofingowi.

example.com.   IN  TXT  "v=spf1 ip4:1.2.3.4 ip4:5.6.7.0/24 include:_spf.google.com ~all"

# Mechanizmy:
ip4:    konkretne IP/CIDR
mx:     uzyj rekordow MX
include: zalacz inny SPF rekord
all:    catch-all z modyfikatorem
        +all -> permit (NIE UZYWAC)
        ~all -> softfail (markuj jako podejrzany)
        -all -> hardfail (odrzuc)
        ?all -> neutral

DKIM (DomainKeys Identified Mail)

DKIM podpisuje cyfrowo wychodzace emaile. Odbiorca weryfikuje podpis kluczem publicznym z TXT rekordu.

default._domainkey.example.com.  IN  TXT  "v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb3DQEBAQUAA..."

# Multi-line dla dlugich kluczy 2048-bit (laczone):
"v=DKIM1; k=rsa; "
"p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQDU..."
"...AQAB"

DMARC (Domain-based Message Authentication, Reporting & Conformance)

DMARC laczy SPF + DKIM i mowi co robic z mailami ktore zawiodly weryfikacje.

_dmarc.example.com.   IN  TXT  "v=DMARC1; p=reject; rua=mailto:dmarc@example.com; ruf=mailto:dmarc@example.com; pct=100; aspf=s; adkim=s"

# Polityki:
p=none       -> tylko monitoring
p=quarantine -> spam folder
p=reject     -> odrzucaj

# rua  - aggregate reports
# ruf  - forensic reports
# pct  - procent zastosowania polityki
Zalecane minimum dla domen wysylajacych mail (2026): SPF (-all), DKIM 2048-bit, DMARC p=reject. Gmail i Outlook od 2024 wymuszaja DMARC dla mass senders.

Komendy diagnostyczne

# dig - szwajcarski scyzoryk DNS:
dig example.com                    # pelne wyniki
dig +short example.com             # tylko adresy
dig MX example.com                 # rekord MX
dig AAAA example.com               # IPv6
dig @1.1.1.1 example.com           # specyficzny resolver
dig +trace example.com             # sledz przez root, TLD, authoritative
dig -x 8.8.8.8                     # reverse lookup
dig ANY example.com                # wszystkie typy (wiele DNS odmawia)

# nslookup - klasyczny:
nslookup example.com
nslookup example.com 1.1.1.1
nslookup -type=MX example.com

# host - uproszczone:
host example.com
host -t TXT example.com
host -a example.com               # all records

# Windows PowerShell:
Resolve-DnsName example.com
Resolve-DnsName example.com -Type MX

# Sprawdzenie SPF/DKIM/DMARC online:
# https://dmarcian.com/dmarc-inspector/
# https://mxtoolbox.com

TTL i propagacja

TTL (Time To Live) okresla na ile sekund recursive resolver moze cache'owac odpowiedz. Wieksze TTL = mniej zapytan, ale zmiana zajmie wiecej czasu.

TTLCzasZastosowanie
601 minutaFailover, czesto zmienne
3005 minutDynamic DNS
36001 godzinaStandard dla wiekszosci
864001 dzienStabilne rekordy
6048001 tydzienNS, MX rzadko zmienne
Migrujesz domene? Obniz TTL do 300 sekund 24-48 godzin przed zmiana - resolver'y szybciej zauwaza zmiane. Po stabilizacji podnies z powrotem.
