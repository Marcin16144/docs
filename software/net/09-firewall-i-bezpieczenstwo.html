Firewall i bezpieczenstwo sieci

iptables, nftables, pfSense, IDS/IPS, WAF, DDoS protection, Zero Trust

Czym jest firewall

Firewall to system filtrujacy ruch sieciowy wedlug zdefiniowanych regul. Decyduje co przepuscic, co zablokowac, co przekierowac. Moze byc software (na hoscie) lub hardware (dedykowane urzadzenie). Firewall to pierwsza linia obrony w sieci.

Stateless vs Stateful

Stateless firewall

Sprawdza kazdy pakiet osobno - bez kontekstu. Decyzja na podstawie naglowkow (IP, port, flagi TCP). Szybki, prosty, ale slabszy w wykrywaniu ataku.

Stateful firewall

Sledzi stan polaczen (connection tracking). Wie ze pakiet RST nalezy do trwajacego ESTABLISHED polaczenia. Mocniejszy, ale wieksze zuzycie pamieci.

CechaStatelessStateful
PamiecBrak (per-packet)Tablica connections
WydajnoscWyzsza (single lookup)Nizsza (state lookup + update)
BezpieczenstwoSlabszeLepsze (TCP sequence checking)
NATTrudniejLatwo (sledzi flows)
PrzykladACL na switcheiptables, pf, FortiGate

Default policies

  • Default deny (whitelist) - blokuj wszystko, zezwol tylko na to co potrzebne. Bezpieczniejsze podejscie.
  • Default allow (blacklist) - zezwol wszystko, blokuj tylko zlosliwe. Latwiejsze do zarzadzania, mniej bezpieczne.
Zlote zasada - zawsze zaczynaj od default deny, otwieraj tylko to co konieczne. Lepiej zablokowac potrzebny ruch i naprawic regule, niz przepuscic atak.

Linux iptables

iptables (od 1998) to klasyczny linuksowy firewall. Bazuje na netfilter w kernelu. Konfiguruje sie poprzez tabele i lancuchy regul.

Tabele iptables

TabelaZastosowanie
filterDomyslna - filtrowanie pakietow (INPUT, OUTPUT, FORWARD)
natNAT - PREROUTING, POSTROUTING, OUTPUT
mangleModyfikacja pakietow (TTL, TOS, marking)
rawPre-NAT exemption od conntrack
securitySELinux marking

Lancuchy filter

  • INPUT - pakiety przychodzace do hosta
  • OUTPUT - pakiety wychodzace z hosta
  • FORWARD - pakiety przechodzace (router, NAT)

Praktyczne komendy iptables

# Wyswietl aktualne reguly (numerowane):
iptables -L -n -v --line-numbers
iptables -L INPUT -n -v

# Wyswietl tabele NAT:
iptables -t nat -L -n -v

# Default policy:
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# Akceptuj established + related (kluczowe!):
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# Akceptuj loopback:
iptables -A INPUT -i lo -j ACCEPT

# SSH (port 22):
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# HTTP/HTTPS:
iptables -A INPUT -p tcp -m multiport --dports 80,443 -j ACCEPT

# Z ograniczeniem rate (anti-bruteforce SSH):
iptables -A INPUT -p tcp --dport 22 -m state --state NEW \
  -m recent --set --name SSH
iptables -A INPUT -p tcp --dport 22 -m state --state NEW \
  -m recent --update --seconds 60 --hitcount 5 --name SSH -j DROP

# Tylko z konkretnego IP:
iptables -A INPUT -s 1.2.3.4 -p tcp --dport 22 -j ACCEPT

# Block country (z ipset):
ipset create cn_block hash:net
ipset add cn_block 1.2.3.0/24
iptables -A INPUT -m set --match-set cn_block src -j DROP

# Logging dropped packets:
iptables -A INPUT -j LOG --log-prefix "DROPPED: " --log-level 4
iptables -A INPUT -j DROP

# Save / restore:
iptables-save > /etc/iptables/rules.v4
iptables-restore < /etc/iptables/rules.v4

# Flush wszystkich regul:
iptables -F
iptables -X
iptables -Z

nftables - nowoczesny zamiennik

nftables (od 2014) zastapil iptables jako defaulta w wiekszosci dystrybucji od 2020. Jeden tool zamiast iptables/ip6tables/arptables/ebtables. Lepsza wydajnosc, czytelniejsza skladnia.

# Plik konfiguracji /etc/nftables.conf:
flush ruleset

table inet filter {
    chain input {
        type filter hook input priority 0; policy drop;

        iif lo accept
        ct state {established, related} accept
        ct state invalid drop

        # ICMP
        ip protocol icmp accept
        ip6 nexthdr icmpv6 accept

        # SSH z ograniczeniem
        tcp dport 22 ct state new limit rate 5/minute accept

        # HTTP/HTTPS
        tcp dport {80, 443} accept

        # Default drop (z log)
        log prefix "DROPPED: " drop
    }

    chain forward {
        type filter hook forward priority 0; policy drop;
    }

    chain output {
        type filter hook output priority 0; policy accept;
    }
}

# Zastosuj:
sudo nft -f /etc/nftables.conf

# Komendy:
sudo nft list ruleset                # caly ruleset
sudo nft list table inet filter      # konkretna tabela
sudo nft add rule inet filter input tcp dport 8080 accept
sudo nft delete rule inet filter input handle 5

ufw - Uncomplicated Firewall

ufw (Ubuntu) to wrapper na iptables/nftables. Latwe komendy do prostych zadan.

# Status:
sudo ufw status verbose

# Wlacz/wylacz:
sudo ufw enable
sudo ufw disable

# Default policy:
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Otworz porty:
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow ssh                   # alias dla 22

# Z konkretnego IP:
sudo ufw allow from 192.168.1.0/24 to any port 22

# Aplikacja-specyficzne (z definicji w /etc/ufw/applications.d/):
sudo ufw allow Nginx Full
sudo ufw allow OpenSSH

# Lista regul z numerami:
sudo ufw status numbered

# Usun regule:
sudo ufw delete 3                    # po numerze
sudo ufw delete allow 22/tcp         # po regule

# Limit (rate limiting):
sudo ufw limit ssh                   # max 6 polaczen w 30 sek

# Logging:
sudo ufw logging on
sudo ufw logging medium

firewalld - Red Hat zone-based

firewalld na RHEL/Fedora/CentOS - oparta na strefach (zones) i serwisach.

# Lista stref:
firewall-cmd --get-zones
firewall-cmd --get-default-zone

# Pokaz konfiguracje strefy:
firewall-cmd --list-all
firewall-cmd --zone=public --list-all

# Dodaj serwis (trwale):
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --reload

# Przeniesc interface do strefy:
firewall-cmd --permanent --change-interface=eth1 --zone=trusted

# Sprawdz aktywne reguly:
firewall-cmd --runtime-to-permanent

pfSense / OPNsense

FreeBSD-based, profesjonalne firewally z GUI. Ogromne mozliwosci - VPN, IDS/IPS, captive portal, multi-WAN, traffic shaping. Stosowane w SMB i nawet enterprise.

  • pfSense - klasyk od 2004, Netgate
  • OPNsense - fork od 2015, nowoczesniejszy UI, szybsze release
  • Hardware: dedicated appliance lub instalacja na PC z 2+ NIC
  • Minimum: 1 GB RAM, 8 GB disk

Windows Defender Firewall

# PowerShell - status:
Get-NetFirewallProfile

# Wlacz dla wszystkich profili:
Set-NetFirewallProfile -All -Enabled True

# Lista regul:
Get-NetFirewallRule | Select-Object DisplayName, Enabled, Direction, Action

# Dodaj regule:
New-NetFirewallRule -DisplayName "Allow HTTP" `
    -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow

# Blokuj IP:
New-NetFirewallRule -DisplayName "Block bad IP" `
    -Direction Inbound -RemoteAddress 1.2.3.4 -Action Block

# Usun regule:
Remove-NetFirewallRule -DisplayName "Allow HTTP"

Cloud firewalls

AWS Security Groups

Stateful, na poziomie instance. Tylko reguly allow (deny niejawne). Reguly per VPC/subnet. Mozna podpisac do EC2, RDS, Lambda, ELB.

# AWS CLI - utworz SG:
aws ec2 create-security-group \
  --group-name web-sg \
  --description "Web server SG" \
  --vpc-id vpc-12345678

# Dodaj inbound:
aws ec2 authorize-security-group-ingress \
  --group-id sg-abc123 \
  --protocol tcp --port 443 --cidr 0.0.0.0/0

Azure NSG

Network Security Groups - stateful, poziom subnet lub NIC. Reguly z priority (100-4096). Default deny inbound, allow outbound.

GCP Firewall Rules

Default na poziomie VPC, mozna stosowac do tagow lub service accounts. Ingress/egress, allow/deny.

IDS - Intrusion Detection System

IDS monitoruje ruch i alarmuje na podejrzane wzorce. Pasywny - nie blokuje, tylko logguje.

Suricata

Wieloskie, multi-threaded, najpopularniejszy. Kompatybilny z regulami Snorta. Wspiera 1+ Gbps na nowoczesnym sprzecie.

# Instalacja na Debian/Ubuntu:
sudo apt install suricata
sudo suricata-update

# Test:
sudo suricata -T -c /etc/suricata/suricata.yaml -v

# Run jako daemon:
sudo systemctl enable --now suricata

# Logi:
tail -f /var/log/suricata/eve.json
tail -f /var/log/suricata/fast.log

Snort

Klasyk od 1998, kupiony przez Cisco. Snort 3 - wspolczesny rewrite z lepsza wydajnoscia.

Zeek (Bro)

Network analysis framework. Nie traditionnal IDS - generuje protokol logs (HTTP, DNS, SSL, files). Sluzy do investigations i forensics.

IPS - Intrusion Prevention System

IPS to IDS + blokowanie. Aktywnie odrzuca podejrzane pakiety. Suricata moze pracowac w trybie IPS (inline mode).

WAF - Web Application Firewall

WAF chroni aplikacje webowe na warstwie 7 - filtruje ataki SQL injection, XSS, CSRF, RCE. Patrzy na payloady HTTP, nie tylko adresy IP/porty.

  • ModSecurity - klasyczny open source WAF, modul Apache/Nginx, OWASP Core Rule Set
  • Cloudflare WAF - cloud, free i platne plany
  • AWS WAF - dla CloudFront, ALB, API Gateway
  • Coraza - nowoczesny WAF w Go, kompatybilny z ModSecurity rules
  • NAXSI - learning-mode WAF dla Nginx

DDoS protection

DDoS (Distributed Denial of Service) zalewa siec/aplikacje ruchem z wielu zrodel. Obronie pomagaja CDN i specjalizowane uslugi.

Typy atakow

TypWarstwaMechanizm
SYN floodL4Niedokonczone TCP handshake
UDP floodL4Wysylanie UDP do losowych portow
ICMP floodL3Ping flood, smurf attack
DNS amplificationL4Zapytania DNS z spoofed src IP, odpowiedzi 50x wieksze
NTP amplificationL4Podobnie, NTP monlist (200x amplification)
HTTP floodL7Tysiace HTTP requestow
SlowlorisL7Wolne wysylanie naglowkow, blokuje workery

DDoS mitigation services

  • Cloudflare - free tier z DDoS protection. W 2024 absorbowali atak 5.6 Tbps
  • AWS Shield - Standard (free) lub Advanced ($3000/mc + traffic)
  • Akamai Prolexic - enterprise-grade
  • Imperva - dedicated WAF + DDoS

Rate limiting i GeoIP

# Nginx rate limiting:
limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;

server {
    location /login {
        limit_req zone=login burst=10 nodelay;
        proxy_pass http://backend;
    }
}

# Iptables - per IP rate limit:
iptables -A INPUT -p tcp --dport 80 -m hashlimit \
  --hashlimit-mode srcip --hashlimit-name http_limit \
  --hashlimit 10/sec --hashlimit-burst 30 -j ACCEPT

# GeoIP block (Linux z ipset):
wget https://www.ipdeny.com/ipblocks/data/aggregated/cn-aggregated.zone
ipset create china hash:net
for ip in $(cat cn-aggregated.zone); do ipset add china $ip; done
iptables -I INPUT -m set --match-set china src -j DROP

Zero Trust networking

"Never trust, always verify" - tradycyjnie firma trustowala wszystko za firewallem. Zero Trust: kazde polaczenie autentykowane i autoryzowane, niezaleznie od lokalizacji.

Najpopularniejsze rozwiazania 2026

  • Google BeyondCorp - pierwsza implementacja, dla pracownikow Google bez VPN
  • Cloudflare Access / Zero Trust - identity proxy, integracja z IdP
  • AWS Verified Access - bez VPN dla aplikacji
  • Tailscale ACLs - Tailnet z fine-grained permissions
  • Twingate - dedicated zero-trust networking
  • Microsoft Entra Private Access - dawniej Azure AD App Proxy

Mikrosegmentacja

Mikrosegmentacja dzieli siec na bardzo male strefy z wlasnymi politykami. Workload-to-workload, nie tylko subnet-to-subnet. Stosowane w VMware NSX, Cisco ACI, Illumio, Cilium.

Minimum 2026 dla malej firmy: ufw lub firewalld na hostach + Cloudflare WAF na publicznych aplikacjach + WireGuard/Tailscale dla remote access. Dla srednich/duzych - dedicated firewall (pfSense, FortiGate), Suricata IDS, SIEM (Wazuh, Graylog).
