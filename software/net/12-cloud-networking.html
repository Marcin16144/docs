VPC - Virtual Private Cloud

VPC to logicznie wydzielona, prywatna siec w chmurze. Definiujesz adresacje, subnetting, routing, firewall. To fundament cloud networkingu - kazdy zasob (VM, baza, kontener) zyje w VPC.

AWS VPC

Najpopularniejszy VPC. Region-bound (kazdy region ma swoje VPC), CIDR 16-28 (pojedynczy lub multiple).

ElementOpis
VPCGlowny kontener, np. 10.0.0.0/16 (65k adresow)
SubnetPodsiec w VPC, kazda w jednej AZ (Availability Zone)
Route TableReguly routingu - kazdy subnet ma jedna RT
Internet Gateway (IGW)Dostep do internetu, podlaczany do VPC
NAT GatewayWychodzacy internet dla private subnet
VPC EndpointPolaczenie do AWS services (S3, DynamoDB) bez internetu

Azure Virtual Network (VNet)

Podobny koncepcyjnie do AWS VPC. Region-bound, ale latwiej polaczyc cross-region (Global VNet Peering). Defaultnie outbound internet.

GCP VPC

Domyslnie global (w przeciwienstwie do AWS regional). Subnets per region, ale jeden VPC moze obejmowac caly swiat. Latwiejsza global architektura.

Subnets - public vs private

Public subnet

  • Route table ma trase 0.0.0.0/0 -> IGW (Internet Gateway)
  • Instancje moga miec public IP
  • Stosowane dla load balancers, bastion hosts, web servers

Private subnet

  • Route table ma trase 0.0.0.0/0 -> NAT Gateway/Instance
  • Brak public IP, brak inbound z internetu
  • Wychodzacy internet przez NAT
  • Stosowane dla baz danych, application servers, internal services
# Klasyczny 3-tier setup AWS VPC:
VPC: 10.0.0.0/16

Public subnets (per AZ):
  10.0.1.0/24   us-east-1a   -> ALB, NAT GW
  10.0.2.0/24   us-east-1b   -> ALB, NAT GW

Private app subnets:
  10.0.10.0/24  us-east-1a   -> EC2, ECS
  10.0.11.0/24  us-east-1b   -> EC2, ECS

Private DB subnets:
  10.0.20.0/24  us-east-1a   -> RDS
  10.0.21.0/24  us-east-1b   -> RDS

Route tables:
  Public RT:    0.0.0.0/0 -> IGW
  Private RT:   0.0.0.0/0 -> NAT Gateway

VPC Peering, Transit Gateway

VPC Peering

Direct connection 1-to-1 miedzy dwoma VPC. Brak transitive (A-B i B-C nie znaczy A-C). Skaluje sie zle przy wielu VPC (mesh).

AWS Transit Gateway

Hub-and-spoke topologia - jeden TGW polaczony z wieloma VPC i lokalnymi data centers. Skaluje sie do tysiecy VPC. Plus: cross-region peering.

Azure VNet Peering

Podobne do AWS, ale defaultnie miedzy regions = global peering.

Cross-region / cross-cloud connectivity

Site-to-site VPN

IPsec tunnel miedzy on-premise routerem a cloud VPN gateway. Najprostszy, najtanszy, ale ograniczony do 1.25 Gbps na tunel.

# AWS Site-to-Site VPN:
1. Customer Gateway (CGW) - reprezentacja routera on-prem
2. Virtual Private Gateway (VGW) - po stronie AWS
3. VPN Connection - 2 tunele IPsec dla redundancji
4. Route propagation w route tables

# Pricing (2026):
$0.05 / hour per tunnel
+ data transfer $0.09/GB out

Direct Connect / ExpressRoute / Cloud Interconnect

Dedykowane fizyczne lacze z cloud provider. Wieksza przepustowosc (do 100 Gbps), nizsza i przewidywalna latencja, taniejszy traffic out.

Load balancers

Layer 4 (TCP/UDP)

Forwarduje pakiety bez patrzenia na payload. Bardzo szybki, transparentny. Stosuje sie do gdzies, gdzie nie potrzeba L7 logiki.

CloudService
AWSNLB (Network Load Balancer)
AzureAzure Load Balancer (Basic / Standard)
GCPNetwork Load Balancer

Layer 7 (HTTP/HTTPS)

Decyzje na podstawie HTTP - URL, headers, cookies. Mozna robic path-based routing, A/B testing, sticky sessions.

CloudService
AWSALB (Application Load Balancer)
AzureApplication Gateway
GCPHTTPS Load Balancer (Global)

Open source alternatives

  • HAProxy - klasyk, super szybki, L4 + L7
  • Nginx - HTTP-focused, latwy, popularny
  • Traefik - cloud-native, auto-discovery z Docker/K8s, auto HTTPS
  • Envoy - foundation Istio service mesh, modern proxy
  • Caddy - HTTPS by default, bardzo prosta konfiguracja
# HAProxy prosty config:
frontend http_front
    bind *:80
    default_backend web_backend

backend web_backend
    balance roundrobin
    server web1 10.0.10.10:80 check
    server web2 10.0.10.11:80 check
    server web3 10.0.10.12:80 check

# Nginx upstream:
upstream backend {
    least_conn;
    server 10.0.10.10:80;
    server 10.0.10.11:80;
    server 10.0.10.12:80 backup;
}

server {
    listen 80;
    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

Cilium - eBPF revolution

Cilium uzywa eBPF w kernelu Linux zamiast sidecar proxy. Mniejsze opoznienie, mniejszy overhead pamieci, mozliwosci network observability na poziomie kernel.

Zero-trust networking w cloud

Cloudflare Access / Tunnel

Zastapienie tradycyjnego VPN. Cloudflared tworzy outbound-only tunnel z origin do Cloudflare. Klient laczy sie przez Cloudflare z autentykacja Google/Okta/AzureAD.

# Tworzenie Cloudflare Tunnel:
cloudflared tunnel login
cloudflared tunnel create my-app

# Konfiguracja /etc/cloudflared/config.yml:
tunnel: TUNNEL_UUID
credentials-file: /root/.cloudflared/TUNNEL_UUID.json

ingress:
  - hostname: app.example.com
    service: http://localhost:8080
  - hostname: ssh.example.com
    service: ssh://localhost:22
  - service: http_status:404

# DNS record:
cloudflared tunnel route dns my-app app.example.com

# Run:
cloudflared tunnel run my-app

AWS Verified Access

Aplikacje AWS dostepne bez VPN. Integracja z IdP (Okta, AzureAD), conditional access policies.

Tailscale + ACLs

Mesh VPN z fine-grained access control list. Per-user, per-device, per-port permissions.

DDoS protection

Cloud-native

  • AWS Shield Standard - free, Layer 3/4 protection automatycznie dla wszystkich AWS services
  • AWS Shield Advanced - $3000/mc + traffic, Layer 7, DDoS Response Team, cost protection
  • Cloudflare - free tier z DDoS automatycznie, Pro/Business/Enterprise z bardziej zaawansowana konfiguracja
  • Azure DDoS Protection - Standard ($2944/mc) z mitigation
  • GCP Cloud Armor - WAF + DDoS dla GCP LB

Cost optimization

Egress traffic - drogie

Najwiekszy generator kosztow - traffic out z chmury. AWS: $0.09/GB egress (us-east-1 to internet). Cross-AZ traffic: $0.01/GB. Cross-region: $0.02/GB.

NAT Gateway

AWS NAT Gateway: $0.045/hr + $0.045/GB. Dla srednich obciazen $30-100/mc per AZ. Alternatywa - NAT instance na EC2 (tansze, ale mniej HA).

Best practices

  • Minimalizuj cross-AZ traffic (data lokalne, replikacja inteligentna)
  • VPC Endpoints dla AWS services - brak NAT, free dla S3/DynamoDB
  • CloudFront cache - egress przez CDN tanszy ($0.085/GB)
  • Cloudflare przed AWS - wsparcie zewnetrznego CDN
  • Reserved capacity / Savings Plans - oszczedza 30-72% na compute

aws ec2 create-subnet --vpc-id vpc-12345 --cidr-block 10.0.1.0/24

# Azure CLI:
az network vnet list
az network vnet subnet list --vnet-name myvnet
az network nsg rule list --nsg-name mynsg --resource-group myrg

# GCP gcloud:
gcloud compute networks list
gcloud compute networks subnets list
gcloud compute firewall-rules list

# Terraform - tworzenie infrastruktury:
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
  enable_dns_hostnames = true
  tags = { Name = "production-vpc" }
}

resource "aws_subnet" "public" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.1.0/24"
  availability_zone = "us-east-1a"
  map_public_ip_on_launch = true
  tags = { Name = "public-1a" }
}
