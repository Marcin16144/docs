IP i adresacja IPv4 + IPv6

Adresacja sieci, CIDR, subnetting, NAT, IPv6, DHCP - kompletny przewodnik

IPv4 - format adresu

IPv4 (Internet Protocol version 4) z 1981 roku uzywa adresow 32-bitowych zapisywanych jako 4 oktety (bajty) w notacji decimal-dot. Daje to przestrzen 2^32 = ok. 4.3 miliarda adresow.

# Format binarny vs decimal:
11000000.10101000.00000001.00000001  (binarny, 4 oktety po 8 bitow)
192.168.1.1                          (decimal-dot)

# Maksymalny adres:
255.255.255.255 = 11111111.11111111.11111111.11111111

# Minimalny:
0.0.0.0 = 00000000.00000000.00000000.00000000

Klasy adresow (legacy)

Pierwotnie IPv4 byl podzielony na klasy A, B, C, D, E. To podejscie zostalo zastapione przez CIDR w 1993, ale nazewnictwo czasem nadal sie pojawia.

CIDR - Classless Inter-Domain Routing

CIDR (RFC 4632, 1993) zastapil sztywne klasy elastyczna maska prefiksowa. Notacja /N oznacza ile bitow z lewej strony to czesc sieci.

# Przyklady CIDR:
192.168.1.0/24    -> maska 255.255.255.0       (8 bitow hosta = 256 adresow)
10.0.0.0/8        -> maska 255.0.0.0           (24 bity hosta = 16M adresow)
172.16.0.0/12     -> maska 255.240.0.0         (20 bitow hosta = 1M adresow)
10.0.5.0/26       -> maska 255.255.255.192     (6 bitow hosta = 64 adresy)
10.0.5.0/30       -> maska 255.255.255.252     (2 bity hosta = 4 adresy)
10.0.5.0/32       -> pojedynczy adres (host route)

Network address i broadcast

W kazdej podsieci pierwszy adres to network address, ostatni to broadcast. Te dwa adresy nie moga byc przypisane hostom (z wyjatkiem /31 i /32).

# Przyklad: 192.168.10.0/24
Network address:    192.168.10.0    (sieciowy, nieuzywalny dla hosta)
Pierwszy host:      192.168.10.1
Ostatni host:       192.168.10.254
Broadcast:          192.168.10.255  (rozglosowy, nieuzywalny dla hosta)
Hosty uzyteczne:    254 (od .1 do .254)

# Przyklad: 10.20.30.64/26
Network:            10.20.30.64
Pierwszy host:      10.20.30.65
Ostatni host:       10.20.30.126
Broadcast:          10.20.30.127
Hosty uzyteczne:    62

Subnetting - przyklady praktyczne

Jak podzielic 10.0.0.0/16 na podsieci /24

# Sa 2^(24-16) = 256 podsieci /24:
10.0.0.0/24    (10.0.0.0 - 10.0.0.255)
10.0.1.0/24    (10.0.1.0 - 10.0.1.255)
10.0.2.0/24
...
10.0.255.0/24  (10.0.255.0 - 10.0.255.255)

# Standardowe przypisanie w firmie:
10.0.0.0/24    -> Management (administracja, switche, AP)
10.0.10.0/24   -> Pracownicy biuro
10.0.20.0/24   -> Goscie WiFi
10.0.30.0/24   -> VoIP
10.0.50.0/24   -> Serwery DMZ
10.0.100.0/24  -> Drukarki, IoT

VLSM - Variable Length Subnet Masking

VLSM pozwala stosowac rozne dlugosci masek w jednej duzej sieci - oszczedza adresow.

# Z bloku 192.168.0.0/22 (1024 adresow) dzielimy na nierowne czesci:
192.168.0.0/24    -> 256 adresow dla glownego biura (max 254 hostow)
192.168.1.0/25    -> 128 adresow dla oddzialu A (max 126 hostow)
192.168.1.128/26  -> 64 adresy dla oddzialu B (max 62 hostow)
192.168.1.192/27  -> 32 adresy dla VPN tunnel (max 30 hostow)
192.168.2.0/30    -> 4 adresy dla linku point-to-point (2 hosty)
... reszta wolna

NAT - Network Address Translation

NAT pozwala wielu urzadzeniom z prywatnymi adresami korzystac z internetu przez wspolny publiczny adres IP.

Typy NAT

  • SNAT (Source NAT) - zmiana adresu zrodlowego, klasyczny "wychodzacy" NAT z LAN do internetu
  • DNAT (Destination NAT) - zmiana adresu docelowego, np. port forwarding na serwer wewnetrzny
  • PAT (Port Address Translation) - wiele klientow LAN przez jeden publiczny IP poprzez mapowanie portow (NAT overload)
  • CGNAT (Carrier-Grade NAT) - operator ISP daje klientom adresy 100.64.0.0/10 i uzywa NAT zbiorczo
# Przyklad PAT (Linux iptables):
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

# Port forwarding (DNAT):
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 \
  -j DNAT --to-destination 192.168.1.100:80

# Hairpin NAT (LAN -> publiczny IP -> z powrotem do LAN):
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 \
  -d 192.168.1.100 -p tcp --dport 80 -j MASQUERADE
Wada NAT - lamie zasade end-to-end internetu, utrudnia P2P (gry, VoIP), wymaga NAT traversal (STUN/TURN/ICE). IPv6 mial sie tego pozbyc, ale NAT zostal jako defacto standard.

IPv6 - 128 bitow

IPv6 (RFC 8200) uzywa 128 bitow podzielonych na 8 grup po 16 bitow w notacji szesnastkowej. Daje to ok. 3.4 x 10^38 adresow - praktycznie nieskonczonosc.

# Pelny format:
2001:0db8:85a3:0000:0000:8a2e:0370:7334

# Skrocony (zero compression):
- pomin wiodace zera w grupie:    2001:db8:85a3:0:0:8a2e:370:7334
- raz zastap kolejne grupy zer ::  2001:db8:85a3::8a2e:370:7334

# Loopback IPv6:
::1                  (= 0:0:0:0:0:0:0:1)

# Unspecified address:
::                   (= 0:0:0:0:0:0:0:0)

# Adres z prefixem:
2001:db8::/32        (uzywany w dokumentacji)
fe80::1/64           (link-local)

Dual-stack vs IPv6-only

  • Dual-stack - host ma rownoczesnie IPv4 i IPv6, najpopularniejsze dzis (2026)
  • IPv6-only z NAT64/DNS64 - sieci nowsze (mobilne) gdzie polaczenia do IPv4-only zasobow przechodza przez tlumacz NAT64
  • 464XLAT - rozwiazanie hybrydowe na koncowkach klienckich

DHCP - Dynamic Host Configuration Protocol

DHCP automatycznie przydziela klientom adresy IP, maski, default gateway, DNS i inne parametry sieciowe.

DHCP DORA - 4 etapy

  1. Discover - klient broadcastuje "kto rozdaje IP?" (UDP 67 server, 68 client)
  2. Offer - serwer DHCP odpowiada propozycja IP, maski, gateway, DNS
  3. Request - klient akceptuje konkretna oferte (publicznie - inni serwery wiedza)
  4. Acknowledge - serwer potwierdza i finalizuje przypisanie wraz z lease time
# Konfiguracja DHCP server (isc-dhcp-server):
subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.1.100 192.168.1.200;
  option routers 192.168.1.1;
  option domain-name-servers 1.1.1.1, 9.9.9.9;
  option domain-name "lan.local";
  default-lease-time 86400;
  max-lease-time 604800;
}

# Static lease (rezerwacja DHCP):
host serwer-druku {
  hardware ethernet AA:BB:CC:DD:EE:FF;
  fixed-address 192.168.1.50;
}

DHCPv6 i SLAAC

W IPv6 sa dwa mechanizmy autokonfiguracji:

  • SLAAC (Stateless Address Autoconfiguration) - host sam tworzy adres na podstawie prefixu z routera + EUI-64 lub random
  • DHCPv6 - klasyczny serwer DHCP dla IPv6, przydatny w enterprise gdzie potrzebujemy logowania kto co dostal
