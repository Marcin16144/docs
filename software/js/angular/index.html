Angular 18+

TypeScript-first framework. Signals, standalone components, deferred views.

1. Co to Angular

Angular to kompletny framework stworzony przez Google (wersja 1.x jako AngularJS w 2010, przepisany i wydany jako Angular 2 w 2016). W odroznienieu od React (biblioteka) i Vue (progresywny framework), Angular to full-stack framework — dostarcza wszystko: routing, HTTP, formularze, DI, testowanie i narzedzia budowania.

Od wersji 14 Angular wprowadzil standalone components (bez NgModule), a od wersji 16 — Signals, nowy reaktywny system oparty na mechanizmie push/pull zamiast Zone.js. Angular 18 wprowadzil deferred views (@defer), a wersja 19 ustabilizowala Signals API.

2. Instalacja i Angular CLI

Angular CLI to podstawowe narzedzie do pracy z frameworkiem. Wymaga Node.js 18+.

# Instalacja Angular CLI globalnie
npm install -g @angular/cli

# Sprawdzenie wersji
ng version

# Nowy projekt (standalone by default w Angular 17+)
ng new moj-projekt --routing --style=scss

# Uruchomienie serwera developerskiego
cd moj-projekt
ng serve --open

# Generowanie komponentu, serwisu, pipe
ng generate component features/user-list
ng generate service core/api
ng generate pipe shared/truncate

# Build produkcyjny
ng build --configuration=production

3. Standalone Components

Od Angular 14 mozna tworzyc komponenty bez NgModule. Od Angular 17 jest to domyslne. Standalone components importuja bezposrednio zaleznosci, co upraszcza architekture.

// user-card.component.ts
import { Component, Input } from '@angular/core';
import { CommonModule } from '@angular/common';
import { RouterLink } from '@angular/router';

@Component({
  selector: 'app-user-card',
  standalone: true,
  imports: [CommonModule, RouterLink],
  template: `
    <div class="card">
      <h3>{{ user.name }}</h3>
      <p>{{ user.email }}</p>
      <a [routerLink]="['/users', user.id]">Szczegoly</a>
    </div>
  `,
  styles: [`
    .card { border: 1px solid #334155; padding: 16px; border-radius: 8px; }
  `]
})
export class UserCardComponent {
  @Input() user!: { id: number; name: string; email: string };
}

// Konfiguracja aplikacji (zamiast AppModule)
// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient, withInterceptors } from '@angular/common/http';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(withInterceptors([authInterceptor]))
  ]
};

4. Signals — nowy system reaktywnosci

Signals to synchroniczny reaktywny system wprowadzony w Angular 16 (stabilny w 17). Zastepuje Zone.js i async pipe w wielu scenariuszach. Dziala na zasadzie fine-grained reactivity — tylko komponenty zaleznie od zmieniajacego sie sygnalu sa przerysowywane.

signal(), computed(), effect()

import { Component, signal, computed, effect } from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true,
  template: `
    <p>Licznik: {{ count() }}</p>
    <p>Podwojony: {{ doubled() }}</p>
    <button (click)="increment()">+1</button>
    <button (click)="reset()">Reset</button>
  `
})
export class CounterComponent {
  // Podstawowy sygnal — wartosc z getterem ()
  count = signal(0);

  // computed() — automatycznie przelicza gdy count sie zmieni
  doubled = computed(() => this.count() * 2);

  constructor() {
    // effect() — side-effecty reagujace na zmiany sygnalow
    effect(() => {
      console.log(`Licznik zmieniony na: ${this.count()}`);
    });
  }

  increment() {
    // Aktualizacja przez .set() lub .update()
    this.count.update(v => v + 1);
  }

  reset() {
    this.count.set(0);
  }
}

// Signal z obiektem + mutate
interface User { name: string; age: number; }
const user = signal<User>({ name: 'Anna', age: 25 });
user.update(u => ({ ...u, age: 26 }));

// input() jako Signal (Angular 17.1+)
import { input, output } from '@angular/core';
@Component({ ... })
export class MyComponent {
  title = input<string>('default');         // InputSignal
  titleChange = output<string>();           // OutputEmitterRef
}

5. Component Lifecycle

Angular dostarcza hooki cyklu zycia. W komponentach ze Signals niektorych mozna unikac dzieki effect().

  • ngOnChanges — wywolywany gdy zmieniaja sie @Input() (przed OnInit)
  • ngOnInit — po pierwszej detekcji zmian (odpowiednik mounted)
  • ngDoCheck — przy kazdej rundzie detekcji zmian (ostroz: drogie)
  • ngAfterViewInit — po renderowaniu widoku i dzieci
  • ngOnDestroy — przed usunieciem komponentu (czyszczenie subscriptions)
import { Component, OnInit, OnDestroy, inject } from '@angular/core';
import { Subject, takeUntil } from 'rxjs';
import { DataService } from './data.service';

@Component({ standalone: true, ... })
export class MyComponent implements OnInit, OnDestroy {
  private destroy$ = new Subject<void>();
  private dataService = inject(DataService);

  data: string[] = [];

  ngOnInit(): void {
    this.dataService.getItems()
      .pipe(takeUntil(this.destroy$))
      .subscribe(items => this.data = items);
  }

  ngOnDestroy(): void {
    this.destroy$.next();
    this.destroy$.complete();
  }
}
Nowy sposob: toSignal()
Konwertuje Observable na Signal — nie trzeba recznie zarzadzac subscriptions:
data = toSignal(this.dataService.getItems(), { initialValue: [] });

6. Routing

Angular Router oferuje zaawansowane mozliwosci: lazy loading, guards, resolvers, nested routes. Od Angular 17 dziala natywnie z standalone components.

// app.routes.ts
import { Routes } from '@angular/router';
import { authGuard } from './guards/auth.guard';

export const routes: Routes = [
  { path: '', redirectTo: '/home', pathMatch: 'full' },
  {
    path: 'home',
    loadComponent: () =>
      import('./pages/home/home.component').then(m => m.HomeComponent)
  },
  {
    path: 'admin',
    canActivate: [authGuard],
    loadChildren: () =>
      import('./admin/admin.routes').then(m => m.ADMIN_ROUTES)
  },
  {
    path: 'users/:id',
    loadComponent: () =>
      import('./pages/user-detail/user-detail.component')
        .then(m => m.UserDetailComponent),
    resolve: { user: userResolver }
  },
  { path: '**', redirectTo: '/home' }
];

// Uzywanie w komponencie
import { ActivatedRoute, RouterLink, RouterOutlet } from '@angular/router';

@Component({
  standalone: true,
  imports: [RouterLink, RouterOutlet],
  template: `
    <nav>
      <a routerLink="/home">Home</a>
      <a [routerLink]="['/users', userId]">Moj profil</a>
    </nav>
    <router-outlet />
  `
})
export class AppComponent {
  private route = inject(ActivatedRoute);
  userId = this.route.snapshot.params['id'];
}

7. Formularze

Reactive Forms (zalecane)

Reactive Forms sa definiowane programowo w klasie TypeScript. Daja pelna kontorle i sa latwe do testowania.

import { Component, inject } from '@angular/core';
import { FormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';
import { CommonModule } from '@angular/common';

@Component({
  standalone: true,
  imports: [ReactiveFormsModule, CommonModule],
  template: `
    <form [formGroup]="loginForm" (ngSubmit)="onSubmit()">
      <input formControlName="email" type="email" placeholder="Email">
      <div *ngIf="email?.invalid && email?.touched">
        <span *ngIf="email?.errors?.['required']">Email jest wymagany</span>
        <span *ngIf="email?.errors?.['email']">Niepoprawny format</span>
      </div>
      <input formControlName="password" type="password" placeholder="Haslo">
      <button type="submit" [disabled]="loginForm.invalid">Zaloguj</button>
    </form>
  `
})
export class LoginFormComponent {
  private fb = inject(FormBuilder);

  loginForm = this.fb.group({
    email: ['', [Validators.required, Validators.email]],
    password: ['', [Validators.required, Validators.minLength(8)]]
  });

  get email() { return this.loginForm.get('email'); }

  onSubmit() {
    if (this.loginForm.valid) {
      console.log(this.loginForm.value);
    }
  }
}

Template-driven Forms (prostsze przypadki)

Uzywaja ngModel i sa definiowane w szablonie. Mniej kodu, ale trudniejsze do testowania i zarzadzania zlozonym stanem.

8. Services i Dependency Injection

Serwisy w Angular sa singleton-ami (domyslnie) dostarczanymi przez DI. Od Angular 14 mozna uzyc inject() zamiast konstruktora.

// api.service.ts
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';
import { map, catchError } from 'rxjs/operators';

export interface User {
  id: number;
  name: string;
  email: string;
}

@Injectable({
  providedIn: 'root'  // Singleton na poziomie aplikacji
})
export class ApiService {
  private http = inject(HttpClient);
  private baseUrl = 'https://api.example.com';

  getUsers(): Observable<User[]> {
    return this.http.get<User[]>(`${this.baseUrl}/users`).pipe(
      map(users => users.filter(u => u.id > 0)),
      catchError(err => {
        console.error('Blad API:', err);
        throw err;
      })
    );
  }

  createUser(user: Omit<User, 'id'>): Observable<User> {
    return this.http.post<User>(`${this.baseUrl}/users`, user);
  }
}

// Uzywanie w komponencie przez inject()
@Component({ ... })
export class UserListComponent {
  private api = inject(ApiService);
  users = toSignal(this.api.getUsers(), { initialValue: [] });
}

9. HTTP Client i Interceptory

Angular HttpClient to wbudowany klient HTTP oparty na RxJS. Interceptory pozwalaja na przeksztaltanie requestow i responsow (np. dodawanie tokenow JWT, globalna obsluga bledow).

// auth.interceptor.ts (funkcyjny — zalecany od Angular 15)
import { HttpInterceptorFn } from '@angular/common/http';
import { inject } from '@angular/core';
import { AuthService } from './auth.service';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const auth = inject(AuthService);
  const token = auth.getToken();

  if (token) {
    const authReq = req.clone({
      headers: req.headers.set('Authorization', `Bearer ${token}`)
    });
    return next(authReq);
  }

  return next(req);
};

// Rejestracja w app.config.ts
import { provideHttpClient, withInterceptors } from '@angular/common/http';
export const appConfig: ApplicationConfig = {
  providers: [
    provideHttpClient(withInterceptors([authInterceptor]))
  ]
};

10. Zarzadzanie stanem: NgRx Signals Store i NGXS

Dla wiekszych aplikacji Angular oferuje kilka podejsc do zarzadzania stanem globalnym:

NgRx Signals Store (nowe podejscie)

import { signalStore, withState, withMethods, patchState } from '@ngrx/signals';
import { inject } from '@angular/core';
import { ApiService } from './api.service';

interface UserState {
  users: User[];
  loading: boolean;
  error: string | null;
}

export const UserStore = signalStore(
  { providedIn: 'root' },
  withState<UserState>({ users: [], loading: false, error: null }),
  withMethods((store, api = inject(ApiService)) => ({
    async loadUsers() {
      patchState(store, { loading: true });
      try {
        const users = await firstValueFrom(api.getUsers());
        patchState(store, { users, loading: false });
      } catch (error) {
        patchState(store, { error: 'Blad ladowania', loading: false });
      }
    }
  }))
);

// Uzycie w komponencie
@Component({ ... })
export class UsersComponent {
  store = inject(UserStore);
  // Dostep: store.users(), store.loading(), store.error()
}
Klasyczny NgRx (Actions/Reducers/Effects) — sprawdza sie w bardzo duzych aplikacjach z rozbudowanymi side-effects, ale jest bardzo boilerplate-heavy. NgRx Signals Store jest zalecany dla nowych projektow.

11. Angular Universal (SSR)

Server-Side Rendering w Angular jest realizowany przez Angular Universal. Od Angular 17 SSR jest lepiej zintegrowane i konfigurowane podczas ng new.

# Nowy projekt z SSR
ng new moj-projekt --ssr

# Dodanie SSR do istniejacego projektu
ng add @angular/ssr

# Build SSR
ng build

# Uruchomienie serwera Node.js
node dist/moj-projekt/server/server.mjs

Angular Universal generuje HTML po stronie serwera (Node.js), co przyspiesza First Contentful Paint i poprawia SEO. Wersja 17+ zawiera Hydration — przejecie renderowanego HTML przez klienta bez ponownego renderowania DOM.

Uwaga: komponenty SSR musza byc swiadome braku window, document i innych API przegladarki. Uzyj isPlatformBrowser() lub PLATFORM_ID do warunkowego wykonania kodu po stronie klienta.

12. Kiedy wybrac Angular — decision tree

Wybierz Angular gdy:
  • Budujesz duza aplikacje enterprise (CRM, ERP, portal korporacyjny)
  • Twoj zespol preferuje TypeScript-first i konwencje nad konfiguracja
  • Potrzebujesz pelnego frameworka bez dobierania bibliotek
  • Masz duzy, wieloosobowy zespol (standaryzacja kodu jest priorytetem)
  • Wazna jest stabilnosc API i dlugoterminowe wsparcie (Google)
Rozważ inne opcje gdy:
  • Budujesz mala lub srednia aplikacje — React lub Vue moga byc prostsze
  • Potrzebujesz SSR z silnym routingiem — rozważ Next.js (React) lub Nuxt (Vue)
  • Priorytetem jest SEO i content-first — rozważ Astro
  • Twoj zespol nie zna TypeScript i nie chce sie go uczyc
