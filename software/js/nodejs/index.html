Server-side JavaScript runtime. Event loop, npm ecosystem.

1. Co to Node.js

Node.js to srodowisko uruchomieniowe JavaScript zbudowane na silniku V8 (Google Chrome) i bibliotece libuv (asynchroniczne I/O, event loop). Zostalo stworzone przez Ryana Dahla w 2009 roku i jest najstarszym, najbardziej dojrzalym serverside JS runtime.

Architektura Node.js

  • V8 — kompiluje JavaScript do kodu maszynowego (JIT). Odpowiada za wykonanie kodu JS.
  • libuv — wieloplatformowa biblioteka C dla asynchronicznego I/O. Implementuje event loop, thread pool (4 watki domyslnie), operacje na plikach, sieci, DNS.
  • Node.js bindings — pomost miedzy JS (V8) a libuv i systemem operacyjnym
  • npm ecosystem — ponad 2 miliony pakietow, najwiekszy rejestr pakietow na swiecie
Single-threaded, ale asynchroniczny: Node.js ma jeden watek glowny dla kodu JS, ale operacje I/O (pliki, siec, baza danych) sa realizowane asynchronicznie przez libuv i system operacyjny. Dzieki temu Node.js moze obslugiwac tysiace polaczen rownoczesnie bez blokowania.

6. Event Loop — fazy i kolejnosc

Event loop Node.js przetwarza operacje asynchroniczne w ustalonej kolejnosci faz. Zrozumienie tego jest kluczowe dla debugowania i optymalizacji aplikacji.

// Kolejnosc wykonania:
// 1. Synchroniczny kod (call stack)
// 2. process.nextTick() — najwyzszy priorytet mikrozadan
// 3. Promise callbacks (.then, .catch, async/await)
// 4. setImmediate() — faza "check" event loop
// 5. setTimeout(fn, 0) — faza "timers" (min. 1ms delay)
// 6. I/O callbacks

console.log('1 - synchroniczny');

setTimeout(() => console.log('5 - setTimeout 0ms'), 0);
setImmediate(() => console.log('4 - setImmediate'));

Promise.resolve().then(() => console.log('3 - Promise.then'));

process.nextTick(() => console.log('2 - nextTick'));

console.log('1b - synchroniczny (ciag dalszy)');

// Wynik: 1, 1b, 2, 3, 4, 5
// (kolejnosc setImmediate vs setTimeout moze byc rozna poza I/O callback)

// UWAGA: naduzywanie process.nextTick moze zablokowac event loop!
// Uzywaj go tylko gdy naprawde potrzebujesz wykonac cos przed I/O
Blokowanie event loop: Dlugie obliczenia synchroniczne (petla, obliczenia CPU) blokuja caly event loop i uniemozliwiaja obsluge innych zadan. Dla zadan CPU-intensive uzywaj worker_threads lub child_process.

7. Streams i piping

Streams sa kluczowym mechanizmem Node.js do przetwarzania duzych ilosci danych bez wczytywania wszystkiego do pamieci. Wystepuja 4 typy: Readable, Writable, Duplex, Transform.

import { createReadStream, createWriteStream } from 'node:fs';
import { createGzip } from 'node:zlib';
import { pipeline } from 'node:stream/promises';
import { Transform } from 'node:stream';

// Kompresja pliku przez pipeline (obsluguje backpressure i cleanup)
await pipeline(
  createReadStream('./duzy-plik.csv'),
  createGzip(),
  createWriteStream('./duzy-plik.csv.gz')
);

// Wlasny Transform stream
const upperCaseTransform = new Transform({
  transform(chunk, encoding, callback) {
    this.push(chunk.toString().toUpperCase());
    callback();
  }
});

// Przetwarzanie duzego pliku linia po linii
import readline from 'node:readline';

const rl = readline.createInterface({
  input: createReadStream('./large-file.txt'),
  crlfDelay: Infinity
});

let lineCount = 0;
for await (const line of rl) {
  lineCount++;
  // Przetworz linie bez wczytywania calego pliku
  if (line.includes('ERROR')) {
    console.log(`Blad w linii ${lineCount}: ${line}`);
  }
}
console.log(`Przetworzono ${lineCount} linii`);

8. Worker Threads

Worker Threads pozwalaja uruchamiac JavaScript w oddzielnych watkach. Idealne dla operacji CPU-intensive (przetwarzanie obrazow, parsowanie, obliczenia). Watki dziela pamieci przez SharedArrayBuffer i komunikuja sie przez postMessage.

// worker.ts — kod watku roboczego
import { workerData, parentPort } from 'node:worker_threads';

function heavyComputation(data: number[]): number {
  // Symulacja ciezkiego obliczenia
  return data.reduce((sum, n) => sum + Math.sqrt(n), 0);
}

const result = heavyComputation(workerData.numbers);
parentPort?.postMessage({ result });

// main.ts — tworzenie i zarzadzanie watkami
import { Worker } from 'node:worker_threads';
import { cpus } from 'node:os';

async function runInWorker(numbers: number[]): Promise<number> {
  return new Promise((resolve, reject) => {
    const worker = new Worker('./worker.ts', {
      workerData: { numbers },
      // Przekaz TypeScript przez ts-node/bun/deno
      execArgv: ['--experimental-strip-types']
    });

    worker.on('message', ({ result }) => resolve(result));
    worker.on('error', reject);
    worker.on('exit', code => {
      if (code !== 0) reject(new Error(`Worker zakonczyl sie z kodem ${code}`));
    });
  });
}

// Pool watkow — liczba rdzeni CPU
const CPU_COUNT = cpus().length;
console.log(`Dostepne rdzenie CPU: ${CPU_COUNT}`);

// Walidacja wejscia — ZAWSZE waliduj dane od uzytkownika
import { z } from 'zod';

const UserSchema = z.object({
  name: z.string().min(2).max(100).trim(),
  email: z.string().email().toLowerCase(),
  age: z.number().int().min(0).max(150).optional()
});

app.post('/users', async (req, res) => {
  const result = UserSchema.safeParse(req.body);
  if (!result.success) {
    return res.status(400).json({ errors: result.error.flatten() });
  }
  // Pracuj z result.data — zwalidowane i otypowane
});

// SSRF prevention — sprawdzaj docelowe URL-e
import { isPrivateIP } from 'is-private-ip';

async function safeFetch(url: string) {
  const parsed = new URL(url);
  if (isPrivateIP(parsed.hostname)) {
    throw new Error('Niedozwolony adres IP (SSRF prevention)');
  }
  return fetch(url);
}
