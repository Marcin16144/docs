Glowna / JS-TS / tsup / unbuild

tsup / unbuild

Najprostsze narzedzia do budowania npm packages. Zero config, dual ESM+CJS.

1. Co to tsup

tsup to narzedzie do budowania bibliotek npm oparte na esbuild. Zostalo stworzone przez Egois Zhang (tworca Vite plugin ekosystemu) i jest zoptymalizowane pod packages, nie aplikacje.

Glowna roznica: library bundler vs app bundler
Vite, Next.js, CRA — buduja aplikacje: optymalizuja pod przegladarke, code-splitting, lazy loading.
tsup, unbuild, rollup — buduja biblioteki: generuja ESM + CJS + deklaracje typow, nie bundluja dependencies.
  • Silnik: esbuild — kompilacja w Rust/Go, ekstremalnie szybka
  • TypeScript: natywna kompilacja + generowanie .d.ts
  • Zero config: sensowne domyslne ustawienia bez konfiguracji
  • Dual package: ESM + CJS z jednego polecenia
  • Watch mode: szybki rebuild w developmencie
  • Nie do aplikacji: brak HTML entry, code-splitting po stronach, PWA

Uzywany przez: Vite, Vitest, UnoCSS, Nuxt, i setki popularnych npm packages.

2. Instalacja i pierwsza konfiguracja

# instalacja
npm install -D tsup

# package.json — skrypty
{
  "scripts": {
    "build": "tsup",
    "build:watch": "tsup --watch",
    "dev": "tsup --watch"
  }
}

Najprostrza konfiguracja w tsup.config.ts:

// tsup.config.ts
import { defineConfig } from 'tsup';

export default defineConfig({
  // entry — plik(i) wejsciowe
  entry: ['src/index.ts'],

  // format — jakie formaty generowac
  format: ['esm', 'cjs'],

  // dts — generuj deklaracje TypeScript (.d.ts)
  dts: true,

  // sourcemap — mapy zrodel
  sourcemap: true,

  // clean — czys dist/ przed buildem
  clean: true,

  // splitting — code-splitting dla ESM (lazy imports)
  splitting: false,

  // minify — minifikacja (domyslnie false dla libraries)
  minify: false,

  // target — minimalna wersja JS
  target: 'es2020',
});
Wynik: tsup generuje dist/index.js (CJS), dist/index.mjs (ESM), dist/index.d.ts (typy).

3. Dual Package — ESM + CJS

Problem dual package: npm package powinien dzialac w srodowiskach CJS (stary Node.js, require()) i ESM (import, nowy Node.js, bundlery). tsup rozwiazuje to automatycznie.

// tsup.config.ts — dual package setup
import { defineConfig } from 'tsup';

export default defineConfig({
  entry: ['src/index.ts'],
  format: ['esm', 'cjs'],
  dts: true,
  clean: true,
  // outExtension — kontrola rozszerzen plikow wyjsciowych
  outExtension({ format }) {
    return { js: format === 'esm' ? '.mjs' : '.cjs' };
  },
});
// package.json — exports field (Node.js 12.7+)
{
  "name": "moja-biblioteka",
  "version": "1.0.0",
  "main": "./dist/index.cjs",       // CJS fallback (stary Node.js)
  "module": "./dist/index.mjs",     // ESM (bundlery: Vite, webpack)
  "types": "./dist/index.d.ts",     // TypeScript
  "exports": {
    ".": {
      "import": {
        "types": "./dist/index.d.mts",
        "default": "./dist/index.mjs"
      },
      "require": {
        "types": "./dist/index.d.cts",
        "default": "./dist/index.cjs"
      }
    }
  },
  "files": ["dist"],
  "sideEffects": false
}
sideEffects: false — informuje bundlery (webpack, Rollup, Vite), ze pakiet nie ma efektow ubocznych przy imporcie. Umozliwia skuteczny tree-shaking — nieuzywane eksporty sa eliminowane z finalnego bundla aplikacji.

4. Wiele punktow wejscia

Pakiety czesto eksportuja wiele "subpath imports" — np. osobny entrypoint dla CLI, osobny dla React hooks, osobny dla typow.

// tsup.config.ts — multiple entries
import { defineConfig } from 'tsup';

export default defineConfig({
  // obiektowa forma — kontrola nazw plikow wyjsciowych
  entry: {
    index: 'src/index.ts',          // dist/index.js
    cli: 'src/cli.ts',              // dist/cli.js
    'react/index': 'src/react.ts',  // dist/react/index.js
  },
  format: ['esm', 'cjs'],
  dts: true,
  clean: true,
});

// package.json — subpath exports dla kazdego entrypoint
{
  "exports": {
    ".": {
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs",
      "types": "./dist/index.d.ts"
    },
    "./react": {
      "import": "./dist/react/index.mjs",
      "require": "./dist/react/index.cjs",
      "types": "./dist/react/index.d.ts"
    },
    "./cli": "./dist/cli.mjs"
  },
  "bin": {
    "moja-lib": "./dist/cli.mjs"
  }
}

5. External Dependencies

Biblioteka nie powinna bundlowac swoich peer dependencies ani dependencies, ktore uzytkownik moze juz miec. Bundlowanie React w pakiecie React-component to klasyczny blad prowadzacy do duplikacji i konfliktow.

// tsup.config.ts — externals
import { defineConfig } from 'tsup';

export default defineConfig({
  entry: ['src/index.ts'],
  format: ['esm', 'cjs'],
  dts: true,
  // external — nie bundluj tych pakietow
  external: [
    'react',
    'react-dom',
    'react/jsx-runtime',
    '@tanstack/react-query',
  ],
  // noExternal — force-bundluj nawet jesli sa w node_modules
  // noExternal: ['lodash-es'],  // uzyteczne dla paczek bez ESM buildu
});

// package.json — deklaracja peer dependencies
{
  "peerDependencies": {
    "react": "^18.0.0 || ^19.0.0"
  },
  "peerDependenciesMeta": {
    "react": { "optional": false }
  },
  "dependencies": {
    "clsx": "^2.0.0"   // bundlowane — uzytkownik nie musi instalowac
  }
}

6. Watch Mode — development workflow

# uruchomienie watch mode
npx tsup --watch
# lub z bun
bun run tsup --watch

# watch z onSuccess — uruchom komende po kazdym rebuildie
# tsup.config.ts
export default defineConfig({
  entry: ['src/index.ts'],
  format: ['esm', 'cjs'],
  dts: true,
  watch: true,               // programatycznie przez config
  onSuccess: 'node dist/index.js',  // uruchom po rebuildie
});

# typowy workflow przy developmencie biblioteki:
# Terminal 1: tsup --watch
# Terminal 2: w projekcie testowym: npm link ../moja-lib
# lub uzyj Vite monorepo z workspace dependencies
Tip — szybszy feedback: W monorepo z Turborepo lub pnpm workspaces mozesz uzywac tsup --watch w pakiecie i miec hot-reload w aplikacji testowej bez npm link.

7. Co to unbuild (unjs)

unbuild to alternatywne narzedzie z ekosystemu unjs (UnifiedJS — tworca Nitro, H3, Nuxt 3). Jest uzywane wewnetrznie przez Nuxt i wiele pakietow unjs. Oparte na Rollup z integracja mkdist i jiti.

# instalacja
npm install -D unbuild

# build.config.ts — konfiguracja unbuild
import { defineBuildConfig } from 'unbuild';

export default defineBuildConfig({
  // entries — pliki wejsciowe
  entries: [
    'src/index',           // automatycznie dodaje .ts
    { input: 'src/cli', name: 'cli' },
  ],

  // declaration — generuj .d.ts
  declaration: true,

  // clean — czys przed buildem
  clean: true,

  // rollup — opcje przekazywane do Rollup
  rollup: {
    emitCJS: true,          // generuj CJS (domyslnie tylko ESM)
    esbuild: {
      target: 'es2020',
      minify: false,
    },
    resolve: {
      exportConditions: ['production', 'node'],
    },
  },

  // externals — nie bundluj
  externals: ['react', 'vue'],

  // hooks — przed/po buildzie
  hooks: {
    'build:done'(ctx) {
      console.log('Build ukonczony:', ctx.buildEntries);
    },
  },
});
# uruchomienie
npx unbuild
# lub w package.json
{
  "scripts": {
    "build": "unbuild",
    "stub": "unbuild --stub"  // stub mode — symlinki zamiast buildu (szybki dev)
  }
}
Stub mode (unbuild --stub) to unikalna cecha unbuild: zamiast kompilowac, tworzy proxy/stub ktory laduje kod bezposrednio z src/ przez jiti (just-in-time TypeScript). Eliminuje koniecznosc watch mode przy developmencie.

8. tsup vs unbuild vs rollup vs esbuild

Narzedzie Silnik Kiedy uzywac Zalety Wady
tsup esbuild Wiekszosc npm packages, TypeScript libraries Szybkosc, zero config, szeroka adopcja Mniej flexibilny niz Rollup
unbuild Rollup + esbuild Nuxt ekosystem, unjs packages, stub mode dev Stub mode, hooks, Rollup plugins Mniejsza spolecznosc, wolniejszy niz tsup
Rollup Rollup (JS) Skomplikowane budowania, wlasne plugins Najbardziej elastyczny, dojrzaly Wiecej konfiguracji, wolniejszy niz esbuild
esbuild (raw) esbuild (Go) Skrypty, CI pipelines, custom tooling Najszybszy, niski level kontroli Brak automatycznego .d.ts, mniej plugins
pkgroll Rollup Alternatywa dla tsup z Rollup backendem Czyta exports z package.json Mniejsza adopcja
microbundle Rollup Bardzo male biblioteki, zero config Minimalny setup Mniej aktywny development

9. Publikacja na npm — package.json exports field

// package.json — kompletna konfiguracja dla publikacji
{
  "name": "@moja-org/moja-biblioteka",
  "version": "1.0.0",
  "description": "Opis biblioteki",
  "license": "MIT",
  "author": "Jan Kowalski",
  "repository": {
    "type": "git",
    "url": "https://github.com/moja-org/moja-biblioteka"
  },

  // pliki do publikacji (bez tego idzie wszystko!)
  "files": ["dist", "README.md"],

  // stare bundlery i Node.js bez exports support
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",

  // nowoczesny exports (Node 12.7+, Webpack 5, Vite, Rollup)
  "exports": {
    ".": {
      "import": {
        "types": "./dist/index.d.mts",
        "default": "./dist/index.mjs"
      },
      "require": {
        "types": "./dist/index.d.cts",
        "default": "./dist/index.cjs"
      }
    },
    "./package.json": "./package.json"
  },

  "sideEffects": false,

  "scripts": {
    "build": "tsup",
    "prepublishOnly": "npm run build"
  },

  "devDependencies": {
    "tsup": "^8.0.0",
    "typescript": "^5.7.0"
  }
}

# publikacja
npm publish --access public      # publiczny pakiet
npm publish --access restricted  # prywatny (wymaga planu npm)
npm publish --dry-run            # symulacja bez faktycznej publikacji

10. Monorepo — tsup w workspace packages

W monorepo kazdy pakiet ma wlasny tsup. Turborepo lub nx koordynuja kolejnosc buildow i cachowanie.

# struktura monorepo (pnpm workspaces)
packages/
  ui/
    src/index.ts
    tsup.config.ts
    package.json
  utils/
    src/index.ts
    tsup.config.ts
    package.json
apps/
  web/
    package.json  # "dependencies": { "@moja-org/ui": "workspace:*" }

# pnpm-workspace.yaml
packages:
  - 'packages/*'
  - 'apps/*'

# turbo.json — pipeline buildow
{
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],  // buduj dependencies najpierw
      "outputs": ["dist/**"]    // cache output
    }
  }
}
// packages/ui/tsup.config.ts
import { defineConfig } from 'tsup';

export default defineConfig({
  entry: ['src/index.ts'],
  format: ['esm', 'cjs'],
  dts: true,
  clean: true,
  external: ['react'],  // peer dependency — nie bundluj
  // treeshake — lepsza eliminacja martwego kodu
  treeshake: true,
});

// packages/ui/package.json
{
  "name": "@moja-org/ui",
  "exports": {
    ".": {
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs",
      "types": "./dist/index.d.ts"
    }
  },
  "peerDependencies": { "react": "^18 || ^19" },
  "devDependencies": { "tsup": "^8.0.0" }
}
