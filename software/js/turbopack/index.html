Turbopack / Rspack

Rust-based bundlers. Turbopack (Vercel/Next.js), Rspack (ByteDance/webpack-compat).

1. Problem z webpack i dlaczego Rust bundlers

Webpack dominowal ekosystem JS przez dekade, ale jego architektura — napisana w JavaScript — ma fundamentalne ograniczenia wydajnosci przy duzych projektach.

Typowe problemy webpack w duzych projektach (2024):
  • Cold start (pierwszy dev build): 30–120 sekund dla 5000+ modulow
  • HMR (Hot Module Replacement): 2–10 sekund na zmiane pliku
  • Brak wielowatkowosci (JavaScript jest jednowatkowy)
  • Zlozonosc konfiguracji — setki linii dla sredniego projektu

Rozwiazanie: pisac bundlery w Rust — jezyk systemowy oferujacy:

  • Natywna wielowatkowosc — rownolegle przetwarzanie plikow
  • Zero overhead garbage collection — brak pauz GC
  • SIMD i niskopoziomowe optymalizacje
  • 10–100x szybszy niz ekwiwalentny kod JavaScript

Rezultat: cold start skraca sie z minut do sekund. HMR z sekund do milisekund.

2. Turbopack — Vercel, turbo engine, incremental compute

Turbopack zostal stworzony przez Vercel w 2022 r. Jego glownym architektem jest Tobias Koppers — tworca oryginalnego webpacka. Uzywa silnika Turbo — systemu incremental computation z agresywnym cachowaniem na poziomie funkcji.

Turbo Engine — jak dziala:
Kazda operacja (parsowanie pliku, transformacja, bundling fragmentu) jest traktowana jako funkcja z wejsciem i wyjsciem. Wyniki sa cachowane. Przy zmianie pliku przeliczane sa tylko funkcje, ktore zaleza od zmienionych wejsc — reszta pochodzi z cache.
  • Incremental: nie przebudowuje tego co sie nie zmienilo
  • Lazy: przetwarza tylko modul ktory jest aktualnie potrzebny przegladarce
  • Parallel: wielowatkowe przetwarzanie modulow
  • Persistent cache: cache przechowywany miedzy sesjami na dysku

Turbopack jest zintegrowany wylacznie z Next.js — nie jest standalone bundlerem (w odroznieniu od Rspack). Vercel ma plany na szersze API, ale na razie jest to internal tool dla Next.js.

3. Turbopack w Next.js 15

Next.js 15 (2024) wprowadzil Turbopack jako stabilny backend dla dev servera.

# Next.js 15 — uruchomienie z Turbopack
# next dev --turbopack jest STABILNE od Next.js 15
next dev --turbopack
# lub w package.json:
{
  "scripts": {
    "dev": "next dev --turbopack",
    "build": "next build"  // produkcja nadal uzywa webpack/Turbopack exp.
  }
}

# next build --turbopack — EKSPERYMENTALNE (Next.js 15.3+)
next build --turbopack
// next.config.ts — konfiguracja Turbopack
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  // Turbopack-specific config (Next.js 15+)
  turbopack: {
    // aliasy modulow
    resolveAlias: {
      '@components': './src/components',
      '@lib': './src/lib',
    },
    // niestandardowe rozszerzenia plikow
    resolveExtensions: ['.tsx', '.ts', '.jsx', '.js', '.mdx'],
    // reguly plikow (jak webpack loaders)
    rules: {
      '*.svg': {
        loaders: ['@svgr/webpack'],
        as: '*.js',
      },
      '*.mdx': {
        loaders: ['@mdx-js/loader'],
        as: '*.tsx',
      },
    },
  },
};

export default nextConfig;
Wyniki benchmarkow (Next.js blog, 2024): cold start 53% szybszy, HMR 94% szybszy niz webpack w typowej aplikacji Next.js z 1000 modulami. Dla wiekszych aplikacji roznica jest jeszcze wieksza.
Uwaga: next dev --turbopack jest stabilne. next build --turbopack jest eksperymentalne — nie uzywaj na produkcji bez testow. Niektorze webpack loadery/plugins nie maja jeszcze odpowiednikow w Turbopack.

4. Rspack — webpack-compatible, ByteDance open-source

Rspack zostal stworzony przez ByteDance (TikTok) jako wewnetrzne narzedzie do budowania ogromnych aplikacji. W 2023 zostal udostepniony jako open-source. Jego glowna obietnica: drop-in replacement dla webpack z 5–10x szybkoscia.

  • Napisany w Rust, wielowatkowy
  • Kompatybilny API z webpack 5 — minimalna migracja
  • Wspiera webpack plugins i loaders przez warstwo kompatybilnosci
  • Wbudowany TypeScript, JSX, CSS Modules bez loaderów
  • Uzywany przez: ByteDance, Microsoft, Amazon i inne firmy enterprise
# instalacja Rspack
npm install -D @rspack/core @rspack/cli

# package.json
{
  "scripts": {
    "dev": "rspack dev",
    "build": "rspack build"
  }
}

5. Rspack — konfiguracja (jak webpack)

// rspack.config.mjs — bardzo podobne do webpack.config.js
import { defineConfig } from '@rspack/cli';
import { rspack } from '@rspack/core';
import path from 'path';
import { fileURLToPath } from 'url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));

export default defineConfig({
  // entry — punkt wejsciowy
  entry: { main: './src/index.tsx' },

  // output
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
    clean: true,
  },

  // module — reguly transformacji
  module: {
    rules: [
      // TypeScript + React JSX — wbudowane, bez dodatkowych loaderów
      {
        test: /\.(ts|tsx)$/,
        use: { loader: 'builtin:swc-loader', options: { jsc: { parser: { syntax: 'typescript', tsx: true } } } },
        exclude: /node_modules/,
      },
      // CSS Modules
      {
        test: /\.module\.css$/,
        use: [rspack.CssExtractRspackPlugin.loader, 'css-loader'],
      },
      // zwykly CSS
      { test: /\.css$/, type: 'css' },
      // obrazy
      { test: /\.(png|jpg|gif|svg)$/, type: 'asset/resource' },
    ],
  },

  // resolve — aliasy, rozszerzenia
  resolve: {
    alias: { '@': path.resolve(__dirname, 'src') },
    extensions: ['.ts', '.tsx', '.js', '.jsx'],
  },

  // plugins — kompatybilne z webpack
  plugins: [
    new rspack.HtmlRspackPlugin({ template: './public/index.html' }),
    new rspack.CssExtractRspackPlugin(),
    new rspack.DefinePlugin({ 'process.env.NODE_ENV': JSON.stringify(process.env.NODE_ENV) }),
  ],

  // optimization
  optimization: {
    splitChunks: { chunks: 'all' },
    minimizer: [new rspack.SwcJsMinimizerRspackPlugin()],
  },

  // devServer
  devServer: {
    port: 3000,
    hot: true,
    historyApiFallback: true,
  },
});

6. Farm — kolejny Rust bundler

Farm to bundler Rust stworzony z mysla o ekstremalnej szybkosci. W odroznieniu od Rspack, nie jest ograniczony przez kompatybilnosc z webpack — ma wlasne API zaprojektowane od zera pod Rust.

# instalacja Farm
npm create farm@latest moja-aplikacja

# farm.config.ts
import { defineConfig } from '@farmfe/core';

export default defineConfig({
  plugins: ['@farmfe/plugin-react'],
  compilation: {
    input: { index: './index.html' },
    output: { path: './dist' },
    resolve: { alias: { '@': './src' } },
  },
  server: { port: 9000, hmr: true },
});
Farm benchmarki (2024): cold start ~20ms (vs Vite ~300ms, webpack ~3000ms) dla 1000 modulow. Jednak Farm jest jeszcze mniej dojrzaly niz Rspack pod wzgledem ecosystemu i stabilnosci.

7. Rolldown — Vite's upcoming Rust bundler

Rolldown to projekt Vite team i Void(0) — Rust-based bundler kompatybilny z Rollup API. Cel: zastapic Rollup (produkcja) i esbuild (dev pre-bundling) w Vite jednym szybkim Rust bundlerem.

  • Kompatybilne API z Rollup — istniejace Rollup plugins powinny dzialac
  • Planowana integracja z Vite 6/7 jako opcja produkcyjna
  • Oxc (Rust JS parser/transformer) jako silnik parsowania
  • Stan 2026: alpha/beta — nie do produkcji
# Rolldown (alpha — tylko do testow)
npm install -D rolldown

# rolldown.config.mjs
import { defineConfig } from 'rolldown';
export default defineConfig({
  input: 'src/index.ts',
  output: { dir: 'dist', format: 'esm' },
});

# Vite z Rolldown (eksperymentalnie, Vite 6.x)
# vite.config.ts
import { defineConfig } from 'vite';
export default defineConfig({
  experimental: { enableNativePlugin: true }  // Rolldown backend
});

9. Migracja Webpack → Rspack

Rspack jest zaprojektowany jako drop-in replacement — migracja zwykle zajmuje kilka godzin, nie tygodni.

# krok 1 — zainstaluj Rspack, odinstaluj webpack
npm uninstall webpack webpack-cli webpack-dev-server
npm install -D @rspack/core @rspack/cli

# krok 2 — przemianuj plik konfiguracji
mv webpack.config.js rspack.config.mjs  # lub .cjs

# krok 3 — zaktualizuj importy w konfiguracji
# PRZED (webpack):
# const HtmlWebpackPlugin = require('html-webpack-plugin');
# const MiniCssExtractPlugin = require('mini-css-extract-plugin');

# PO (rspack — wbudowane):
import { rspack } from '@rspack/core';
// rspack.HtmlRspackPlugin — wbudowany, nie wymaga instalacji
// rspack.CssExtractRspackPlugin — wbudowany

# krok 4 — zaktualizuj scripts w package.json
# "dev": "webpack serve" → "dev": "rspack dev"
# "build": "webpack build" → "build": "rspack build"

Checklist migracji Webpack → Rspack

  • Zamien webpack na @rspack/core w devDependencies
  • Wbudowane: TypeScript, JSX, CSS, asset modules — usun odpowiednie loadery
  • Zamien html-webpack-plugin na wbudowany HtmlRspackPlugin
  • Zamien mini-css-extract-plugin na CssExtractRspackPlugin
  • Sprawdz kompatybilnosc uzywanych webpack pluginow (wiekszosc dziala)
  • Przetestuj wszystkie loaders — niektore wymagaja Rspack-specyficznych alternatyw
  • Babel loader czesto mozna zastapic builtin builtin:swc-loader

10. Landscape 2026 — kto wygra

Prognoza

Nowe projekty: Vite pozostaje standardem dla SPA/SSR. Nowe projekty Next.js uzywaja Turbopack dev + webpack/Turbopack prod.

Enterprise migracje z webpack: Rspack jest oczywistym wyborem — zerowa zmiana mindset, dramatyczna poprawa szybkosci.

Perspektywa dlugodystansowa: Rolldown moze zjednoczyc Vite dev + prod w jednym Rust bundlerze, eliminujac roznice miedzy devem (esbuild) a prodem (Rollup). To bedzie przelamanie.

Farm: Ciekawy technicznie, zbyt maly ekosystem dla produkcji w 2026.
