TypeScript 5.7+

Statyczne typowanie JS. De facto standard dla nowych projektow w 2026.

1. Dlaczego TypeScript

TypeScript to nadzbiór JavaScript — kazdy poprawny kod JS jest poprawnym kodem TS. TypeScript dodaje system typow sprawdzany w czasie kompilacji, który jest nastepnie usuwany — wynikowy kod to czysty JavaScript.

Trzy glowne korzysci:
  1. Compile-time errors — bledy typow wykryte zanim kod dotrze na produkcje
  2. Editor support — autocompletion, refactoring, go-to-definition dzialaja dokladnie
  3. Dokumentacja w kodzie — sygnatury funkcji sa czytelna dokumentacja API
TypeScript — kiedy uzywacJavaScript — kiedy wystarczy
Projekty teamowe (2+ osob)Szybkie prototypy / skrypty jednorazowe
Biblioteki npm (public API)Proste skrypty Node.js (np. deploy scripts)
Projekty dlugodystansowe (>6 mies.)Glue code konfiguracyjny (vite.config.js)
Aplikacje ze zlozonymi modelami danychMicro-projekty bez dlugoterminowego maintainance
Wszelki kod produkcyjny backend/frontendJupyter-like data exploration (Deno + TS jest ok)

3. Podstawowe typy

// primitives
const name: string = 'Jan';
const age: number = 30;
const active: boolean = true;
const nothing: null = null;
const notDefined: undefined = undefined;

// arrays
const nums: number[] = [1, 2, 3];
const strs: Array<string> = ['a', 'b'];

// tuple — tablica o stalej dlugosci i typach
const pair: [string, number] = ['Jan', 30];
const rgb: readonly [number, number, number] = [255, 0, 128];

// enum — nazwane stale
enum Direction { Up, Down, Left, Right }
const dir: Direction = Direction.Up;

// const enum — inlinowany w kompilacji (zero runtime)
const enum Status { Active = 'active', Inactive = 'inactive' }

// any — wylaczy sprawdzanie typow (uzywaj sparingly!)
const data: any = fetchSomething();

// unknown — bezpieczna alternatywa dla any
const value: unknown = getInput();
if (typeof value === 'string') {
  console.log(value.toUpperCase()); // OK — zawezony typ
}

// never — typ ktory nigdy nie wystepuje
function throwError(msg: string): never {
  throw new Error(msg);
}

// void — funkcja nic nie zwraca
function log(msg: string): void {
  console.log(msg);
}

// object types
const user: { name: string; age: number; email?: string } = {
  name: 'Jan',
  age: 30
  // email jest opcjonalne
};

// union types
let id: string | number = 'abc';
id = 123;  // OK

// intersection types
type Admin = User & { role: 'admin'; permissions: string[] };

4. Interface vs Type — kiedy co

Cecha interface type alias
Obiekty / klasy Tak (preferowane) Tak
Prymitywy, union, tuple Nie Tak (jedyna opcja)
Declaration merging Tak — mozna rozszerzac przez redefinicje Nie — blad kompilacji
extends / implements Tak (naturalne) Tak (przez &)
Computed properties Ograniczone Pelne wsparcie
Error messages Czesciej pokazuje nazwe Czesciej rozwija structure
Zalecenie 2026 Public API, klasy, React props Union types, utility types, tuples 
// interface — preferowane dla obiektow/klas
interface User {
  id: number;
  name: string;
  email?: string;
}

// rozszerzanie interface
interface AdminUser extends User {
  role: 'admin';
  permissions: string[];
}

// type alias — konieczne dla union/intersection/tuple
type ID = string | number;
type Result<T> = { data: T; error: null } | { data: null; error: Error };
type Pair<T> = [T, T];
type EventName = `on${Capitalize<string>}`; // template literal type

5. Generics

// generic function
function identity<T>(value: T): T {
  return value;
}
identity<string>('hello');  // explicite
identity(42);               // inferowane — T = number

// generic z constraint
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
const user = { name: 'Jan', age: 30 };
getProperty(user, 'name');  // string
getProperty(user, 'age');   // number
// getProperty(user, 'email');  // BLAD — 'email' nie istnieje

// generic interface
interface Repository<T> {
  findById(id: string): Promise<T | null>;
  findAll(): Promise<T[]>;
  save(entity: T): Promise<T>;
  delete(id: string): Promise<void>;
}

// generic class
class Stack<T> {
  private items: T[] = [];
  push(item: T): void { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
  peek(): T | undefined { return this.items.at(-1); }
  get size(): number { return this.items.length; }
}

const stack = new Stack<number>();
stack.push(1);
stack.push(2);
const top = stack.pop(); // number | undefined

// conditional types
type IsArray<T> = T extends any[] ? true : false;
type NonNullable<T> = T extends null | undefined ? never : T;

// infer — wyodrebnianie typow
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;

type UnpackPromise<T> = T extends Promise<infer U> ? U : T;
type Result = UnpackPromise<Promise<string>>;  // string

6. Utility Types

interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  createdAt: Date;
}

// Partial<T> — wszystkie pola opcjonalne
type UserUpdate = Partial<User>;
// { id?: number; name?: string; ... }

// Required<T> — wszystkie pola wymagane
type StrictUser = Required<Partial<User>>;

// Readonly<T> — wszystkie pola readonly
type ImmutableUser = Readonly<User>;

// Pick<T, K> — wybierz pola
type UserPublic = Pick<User, 'id' | 'name' | 'email'>;
// { id: number; name: string; email: string }

// Omit<T, K> — usun pola
type UserWithoutPassword = Omit<User, 'password'>;

// Record<K, V> — slownik
type UserMap = Record<string, User>;
type StatusLabels = Record<'active' | 'inactive' | 'banned', string>;

// ReturnType<T> — typ zwracany funkcji
function createUser(name: string): User { /* ... */ return {} as User; }
type CreatedUser = ReturnType<typeof createUser>;  // User

// Awaited<T> — odwijanie Promise (TS 4.5+)
type FetchedUser = Awaited<ReturnType<typeof fetchUser>>;

// Parameters<T> — typy parametrow funkcji
type CreateParams = Parameters<typeof createUser>;  // [string]

// Extract / Exclude
type StringOrNumber = string | number | boolean;
type OnlyStrNum = Extract<StringOrNumber, string | number>;   // string | number
type NoBoolean = Exclude<StringOrNumber, boolean>;            // string | number

// NonNullable<T>
type MaybeString = string | null | undefined;
type DefinitelyString = NonNullable<MaybeString>;  // string

7. TypeScript 5.x — nowosci

// satisfies operator (TS 4.9) — sprawdz typ bez utraty wnioskowania
const palette = {
  red: [255, 0, 0],
  green: '#00ff00',
} satisfies Record<string, string | number[]>;

// TypeScript wie ze palette.red to number[], nie string | number[]
palette.red.map(v => v * 2);  // OK (bez satisfies byloby blad)

// using keyword (TS 5.2) — Explicit Resource Management
// automatyczne czyszczenie zasobow (jak finally, ale czytelniejsze)
class DatabaseConnection {
  [Symbol.dispose]() { this.close(); }
  close() { console.log('Zamknieto polaczenie'); }
  query(sql: string) { return []; }
}

function processData() {
  using db = new DatabaseConnection();  // auto-dispose po wyjsciu scope
  const results = db.query('SELECT * FROM users');
  return results;
  // db.close() wywolywane automatycznie tutaj
}

// const type parameters (TS 5.0)
function toArray<const T>(value: T): T[] {
  return [value];
}
const arr = toArray('hello');  // string[] zamiast "hello"[]
// const arr2 = toArray(['a', 'b'] as const);  // readonly ["a", "b"][]

// verbatimModuleSyntax (TS 5.0) — wymusza "import type" dla typow
import type { User } from './types';  // usuwane w kompilacji
import { createUser } from './user';  // pozostaje w output

// TS 5.5 — inferred type predicates
function isString(value: unknown) {
  return typeof value === 'string';
  // TS 5.5 automatycznie wnioskuje: value is string
}
const values: (string | number)[] = ['a', 1, 'b', 2];
const strings = values.filter(isString);  // string[] (bez as string[])

// TS 5.7 — Path rewriting dla ESM
// pozwala pisac .ts importy w source i miec .js w output

8. Discriminated Unions i Type Guards

// discriminated union — wspolne pole "type" rozroznia warianty
type ApiResult<T> =
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: string; code: number };

function handleResult<T>(result: ApiResult<T>) {
  switch (result.status) {
    case 'loading':
      return '<Spinner />';
    case 'success':
      return result.data;   // TypeScript wie ze data istnieje
    case 'error':
      return `Blad ${result.code}: ${result.error}`;
    // default nie potrzebny — TS sprawdza wyczerpanie
  }
}

// type guards — zawezanie typow
function isUser(value: unknown): value is User {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    'name' in value
  );
}

// assertion functions (TS 3.7)
function assertUser(value: unknown): asserts value is User {
  if (!isUser(value)) throw new Error('Not a user');
}

// instanceof guard
function processInput(input: string | Error) {
  if (input instanceof Error) {
    console.error(input.message);  // Error
  } else {
    console.log(input.toUpperCase());  // string
  }
}

// in operator guard
type Cat = { meow(): void };
type Dog = { bark(): void };

function makeSound(animal: Cat | Dog) {
  if ('meow' in animal) {
    animal.meow();  // Cat
  } else {
    animal.bark();  // Dog
  }
}

  export interface Options {
    strict?: boolean;
    encoding?: 'utf-8' | 'latin1';
  }
  export function process(data: object, options?: Options): string;
  export default parse;

11. TypeScript z runtime validators — Zod, Valibot, Arktype

TypeScript sprawdza typy w czasie kompilacji. Dane z zewnatrz (API, formularze, env vars) sa w runtime unknown — trzeba je walidowac. Biblioteki walidacyjne lacza runtime safety z TypeScript types.

// Zod — najpopularniejsza biblioteka walidacji (2026)
import { z } from 'zod';

// definiowanie schematu = typ + walidacja w jednym
const UserSchema = z.object({
  id: z.number().positive(),
  name: z.string().min(1).max(100),
  email: z.string().email(),
  age: z.number().int().min(0).max(150).optional(),
  role: z.enum(['user', 'admin', 'moderator']),
  createdAt: z.coerce.date(),  // konwertuje string na Date
});

// wyodrebnianie typu TypeScript ze schematu
type User = z.infer<typeof UserSchema>;

// walidacja w runtime
const result = UserSchema.safeParse(unknownData);
if (result.success) {
  const user: User = result.data;  // typescript wie ze to User
  console.log(user.email);
} else {
  console.error(result.error.flatten());
}

// Valibot — alternatywa z mniejszym bundle (tree-shakeable)
import * as v from 'valibot';

const PostSchema = v.object({
  title: v.pipe(v.string(), v.minLength(1), v.maxLength(200)),
  content: v.string(),
  tags: v.array(v.string()),
  published: v.boolean(),
});

type Post = v.InferOutput<typeof PostSchema>;

// Zod z tRPC — end-to-end type safety
// router.ts
const appRouter = router({
  getUser: publicProcedure
    .input(z.object({ id: z.string() }))
    .query(async ({ input }) => {
      return db.user.findUnique({ where: { id: input.id } });
      // zwracany typ jest automatycznie inferowany przez tRPC
    }),
});
Wzorzec "parse, don't validate": Zawsze parsuj zewnetrzne dane przez schemat Zod/Valibot na granicy systemu (API endpoint, form handler, env loading). Wewnatrz aplikacji mozesz ufac TypeScript typom — dane sa juz zwalidowane.
