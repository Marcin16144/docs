Nuxt 3

Vue framework. Auto-imports, Nitro server, hybrid rendering. Full-stack Vue.

1. Nuxt 3 vs Nuxt 2

Nuxt 3 to kompletne przepisanie frameworka wydane w 2022 roku. W porownaniu do Nuxt 2 wprowadza: serwer Nitro (zastepuje Express), Vite jako bundler (zastepuje webpack), natywny TypeScript, Vue 3 Composition API i radykalnie ulepszone auto-imports.

CechaNuxt 2Nuxt 3
VueVue 2 (Options API)Vue 3 (Composition API)
Bundlerwebpack 4Vite (dev) + Rollup (build)
SerwerExpress / ConnectNitro (ultra-fast, multi-target)
TypeScriptDodatkowa konfiguracjaNatywny (first-class)
Auto-importsOgraniczonePelne (komponenty, composables, utils)
Data fetchingasyncData, fetch hookuseFetch, useAsyncData, $fetch
SSR engineVue Server Renderer@vue/server-renderer (Vue 3)
Rendering modesSSR / SPASSR / SPA / ISR / Hybrid per route

Struktura katalogow Nuxt 3
pages/ — routing oparty na plikach (Vue Router)
components/ — auto-importowane komponenty Vue
composables/ — auto-importowane composables (useXxx)
layouts/ — szablony stron (default.vue, custom.vue)
middleware/ — middleware routingu
plugins/ — pluginy Nuxt (inicjalizacja bibliotek)
server/ — API routes, middleware serwerowe, utilities
utils/ — auto-importowane funkcje pomocnicze
public/ — pliki statyczne
nuxt.config.ts — konfiguracja projektu

4. Auto-imports

Nuxt 3 automatycznie importuje komponenty, composables, utils i wybrane funkcje Vue/Nuxt. Nie trzeba pisac zadnych import dla wiekszosci typowych uzytkow — Nuxt wykrywa i importuje automatycznie na podstawie nazwy.

<script setup lang="ts">
// Wszystkie ponizsze sa AUTO-IMPORTOWANE — zadnych import na gorze!

// Vue 3 reactivity
const count = ref(0);
const doubled = computed(() => count.value * 2);
watch(count, (val) => console.log('Zmiana:', val));

// Nuxt composables
const route = useRoute();
const router = useRouter();
const config = useRuntimeConfig();

// Nuxt data fetching
const { data: users } = await useFetch('/api/users');

// Nuxt head management
useHead({ title: 'Moja strona' });
useSeoMeta({ description: 'Opis SEO' });

// Twoje własne composables z composables/
// composables/useCounter.ts — auto-importowane jako useCounter()
</script>

// composables/useApi.ts — automatycznie dostepny w calej aplikacji
export function useApi() {
  const config = useRuntimeConfig();

  async function getUsers() {
    return $fetch(`${config.public.apiUrl}/users`);
  }

  return { getUsers };
}

5. Routing — oparty na plikach

// Struktura plikow i URL-e:
// pages/index.vue              → /
// pages/about.vue              → /about
// pages/blog/index.vue         → /blog
// pages/blog/[slug].vue        → /blog/:slug
// pages/users/[id]/index.vue   → /users/:id
// pages/[...slug].vue          → /dowolna/sciezka (catch-all)
// pages/(group)/login.vue      → /login (group nie wplywa na URL)

// pages/blog/[slug].vue — dynamiczny parametr
<template>
  <article>
    <h1>{{ post?.title }}</h1>
    <p>{{ post?.body }}</p>
  </article>
</template>

<script setup lang="ts">
const route = useRoute();
const slug = route.params.slug as string;

// useFetch z auto-generowanym kluczem
const { data: post, error } = await useFetch(`/api/posts/${slug}`);

if (error.value) throw createError({ statusCode: 404, message: 'Post nie znaleziony' });
</script>

// Middleware — pages/dashboard.vue
definePageMeta({
  middleware: 'auth',   // middleware/auth.ts
  layout: 'dashboard'  // layouts/dashboard.vue
});

6. Data fetching: useFetch, useAsyncData, $fetch

Nuxt 3 oferuje trzy sposoby pobierania danych. useFetch jest najwygodniejszy, useAsyncData daje wiecej kontroli, a $fetch to niskopoziomowy klient HTTP (oparty na ofetch).

<script setup lang="ts">
// useFetch — najwygodniejszy, auto-deduplikacja, SSR/klient
const { data, pending, error, refresh } = await useFetch('/api/users', {
  // Opcje:
  method: 'GET',
  query: { page: 1, limit: 20 },
  headers: { 'Authorization': 'Bearer token' },
  transform: (users) => users.map(u => ({ ...u, fullName: `${u.name}` })),
  watch: [page],           // odswiezaj gdy 'page' sie zmieni
  lazy: false              // czekaj na dane (domyslnie: blokuje nawigacje)
});

// useAsyncData — wiecej kontroli, wlasny klucz cache
const { data: posts } = await useAsyncData(
  'blog-posts',            // unikatowy klucz
  () => $fetch('/api/posts'),
  {
    server: true,          // wykonuj na serwerze (domyslnie true)
    lazy: false,
    default: () => []      // wartosc poczatkowa
  }
);

// $fetch — prosty klient HTTP (bez cache/SSR magic)
// Uzywaj w server-side, akcjach, event handlerach
async function deleteUser(id: string) {
  await $fetch(`/api/users/${id}`, { method: 'DELETE' });
  await refresh();  // odswiezenie danych po mutacji
}
</script>

7. Tryby renderowania

Nuxt 3 wspiera hybrydowe renderowanie — mozna ustawic rozny tryb dla kazdej trasy aplikacji.

// nuxt.config.ts — konfiguracja renderowania
export default defineNuxtConfig({
  routeRules: {
    // SSG — generuj statycznie przy buildzie
    '/': { prerender: true },
    '/blog/**': { prerender: true },

    // ISR — odswiezaj co 60 sekund
    '/products/**': { isr: 60 },

    // SSR — renderuj przy kazdym zadaniu
    '/dashboard/**': { ssr: true },

    // SPA — renderuj po stronie klienta
    '/admin/**': { ssr: false },

    // Cache HTTP z nagłowkami
    '/api/public/**': { cache: { maxAge: 60 * 60 } },

    // Przekierowanie
    '/old-page': { redirect: '/new-page' },

    // Naglowki CORS
    '/api/**': { cors: true }
  }
});

8. Nitro — serwer backendowy

Nitro to serwer wbudowany w Nuxt 3. Obsluguje API routes, middleware serwerowe i moze byc deployowany na rozne platformy bez zmian w kodzie.

// server/api/users/index.get.ts — GET /api/users
export default defineEventHandler(async (event) => {
  // Dostep do query params
  const query = getQuery(event);
  const page = Number(query.page ?? 1);

  // Dostep do headers, cookies
  const token = getHeader(event, 'authorization');

  // Odpowiedz JSON
  const users = await db.user.findMany({ skip: (page - 1) * 20, take: 20 });
  return users;  // automatycznie serializowane do JSON
});

// server/api/users/index.post.ts — POST /api/users
export default defineEventHandler(async (event) => {
  const body = await readBody(event);

  // Walidacja
  if (!body.name || !body.email) {
    throw createError({ statusCode: 400, message: 'Brak wymaganych pol' });
  }

  const user = await db.user.create({ data: body });
  setResponseStatus(event, 201);
  return user;
});

// server/api/users/[id].delete.ts — DELETE /api/users/:id
export default defineEventHandler(async (event) => {
  const id = getRouterParam(event, 'id');
  await db.user.delete({ where: { id } });
  return { deleted: true };
});

// server/middleware/auth.ts — globalny middleware
export default defineEventHandler((event) => {
  const token = getCookie(event, 'auth-token');
  if (event.path?.startsWith('/api/protected') && !token) {
    throw createError({ statusCode: 401, message: 'Nieautoryzowany' });
  }
});

9. Zarzadzanie stanem: useState i Pinia

// useState — prosty stan wspoldzielony (SSR-safe)
// composables/useCart.ts
export const useCart = () => {
  const items = useState<CartItem[]>('cart-items', () => []);

  function addItem(item: CartItem) {
    items.value.push(item);
  }

  function removeItem(id: string) {
    items.value = items.value.filter(i => i.id !== id);
  }

  const total = computed(() =>
    items.value.reduce((sum, item) => sum + item.price * item.qty, 0)
  );

  return { items, addItem, removeItem, total };
};

// Pinia — zaawansowane zarzadzanie stanem (zalecane dla wiekszych aplikacji)
// stores/userStore.ts
import { defineStore } from 'pinia';

export const useUserStore = defineStore('user', () => {
  const user = ref<User | null>(null);
  const isLoggedIn = computed(() => !!user.value);

  async function login(credentials: LoginCredentials) {
    const data = await $fetch('/api/auth/login', {
      method: 'POST',
      body: credentials
    });
    user.value = data.user;
  }

  function logout() {
    user.value = null;
    navigateTo('/login');
  }

  return { user, isLoggedIn, login, logout };
});

11. Deployment

# Build dla Node.js (domyslny)
npm run build
node .output/server/index.mjs

# Generowanie statyczne (SSG)
npm run generate
# Wyjscie w .output/public/ — serwuj jako static files

# Docker
FROM node:22-alpine
COPY .output .output
ENV PORT=3000 NODE_ENV=production
CMD ["node", ".output/server/index.mjs"]

# Vercel — auto-detect, zero konfiguracji
# Netlify — nuxt.config.ts: nitro: { preset: 'netlify' }
# Cloudflare — nitro: { preset: 'cloudflare-pages' }
# AWS Lambda — nitro: { preset: 'aws-lambda' }
