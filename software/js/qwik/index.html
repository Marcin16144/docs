Qwik

Resumability zamiast hydration. Instant page load. Builder.io.

1. Co to Qwik — resumability vs hydration

Qwik to framework stworzony przez Misko Hevery'ego (tworca AngularJS) i rozwijany przez Builder.io. Jego fundamentalna innowacja to koncepcja resumability — radykalnie odmienna od hydration stosowanej przez React, Vue, Angular i wszystkie inne frameworki.

Problem z hydration

Tradycyjny SSR dziala tak: serwer generuje HTML, przeglądarka go wyswietla, potem pobiera caly bundle JavaScript i uruchamia proces hydration — odtworzenie stanu aplikacji po stronie klienta, podpiecie event listenerow, re-renderowanie wirtualnego DOM. Ten proces moze trwac od setek milisekund do kilku sekund dla duzych aplikacji — strona wyglada gotowo, ale nie jest interaktywna (problem TTI — Time to Interactive).

Resumability — rozwiazanie Qwik

Qwik serializuje caly stan aplikacji i listenery zdarzen bezposrednio do HTML jako atrybuty. Przeglądarka nie pobiera zadnego JavaScript przy starcie. JS jest pobierany leniwie, tylko gdy uzytkownik wykona akcje (np. kliknie przycisk). To jest resumption — kontynuowanie stanu serwera zamiast jego odtwarzania.

Kluczowa roznica:
Hydration: pobierz caly JS → wykonaj → podepnij eventy → aplikacja gotowa
Resumability: wyswietl HTML → gotowe! JS pobierany dopiero gdy potrzebny

3. Skladnia Qwik — component$ i sufiks $

Qwik uzywa specjalnego sufiksu $ do oznaczania granic lazy loading. Funkcje z $ sa automatycznie wycinane do osobnych chunkow i pobierane tylko gdy potrzebne. To jest kluczowy mechanizm resumability.

// Podstawowy komponent Qwik
import { component$, useSignal } from '@builder.io/qwik';

// component$() — oznacza granice lazy loading komponentu
export const HelloWorld = component$(() => {
  const name = useSignal('Swiecie');

  return (
    <div>
      <h1>Witaj, {name.value}!</h1>
      <input
        value={name.value}
        onInput$={(e) => {
          // onInput$ — handler jest lazy, pobierany tylko gdy uzytkownik pisze
          name.value = (e.target as HTMLInputElement).value;
        }}
      />
    </div>
  );
});

// Props komponentu
interface ButtonProps {
  label: string;
  onClick$?: () => void;  // $ w nazwie propa = lazy handler
}

export const Button = component$<ButtonProps>(({ label, onClick$ }) => {
  return (
    <button onClick$={onClick$}>
      {label}
    </button>
  );
});

4. Resumability — szczegoly techniczne

Qwik serializuje stan do HTML przez specjalne atrybuty. Gdy uzytkownik kliknie element, Qwik pobiera tylko ten jeden chunk JS potrzebny do obslugi tego zdarzenia — nie cala aplikacje.

// To co generuje Qwik w HTML (uproszczone):
// <button on:click="./chunk-abc123.js#handleClick">Kliknij</button>
// <script type="qwik/json">{"state":{"count":0}}</script>

// Qwik Optimizer — plugin Vite ktory:
// 1. Wykrywa wszystkie funkcje z sufiksem $
// 2. Wycina je do osobnych plikow (chunks)
// 3. Generuje manifest mapujacy symbole na pliki
// 4. Wstrzykuje stan do HTML podczas SSR

// Przyklad serialization — co trafia do HTML
export const Counter = component$(() => {
  const count = useSignal(0);  // serializowany do HTML jako {"count":0}

  // Ten handler jest WYCIETY do osobnego pliku
  // Pobierany tylko gdy uzytkownik kliknie
  const increment = $(() => {
    count.value++;
  });

  return <button onClick$={increment}>{count.value}</button>;
});

// Miedzy server i klient — co jest serializowalne:
// - Prymitywy: string, number, boolean, null
// - Tablice i obiekty (JSON-serializable)
// - Sygnaly (useSignal, useStore)
// NIE: funkcje (chyba ze przez $), DOM elements, class instances

5. Signals — useSignal, useStore, useComputed$

import {
  component$,
  useSignal,
  useStore,
  useComputed$,
  useTask$
} from '@builder.io/qwik';

export const ShoppingCart = component$(() => {
  // useSignal — pojedyncza reaktywna wartosc
  const discount = useSignal(0);

  // useStore — reaktywny obiekt (deep reactive)
  const cart = useStore({
    items: [] as CartItem[],
    isOpen: false
  });

  // useComputed$ — obliczana wartosc reaktywna (lazy)
  const total = useComputed$(() => {
    const subtotal = cart.items.reduce(
      (sum, item) => sum + item.price * item.qty, 0
    );
    return subtotal * (1 - discount.value / 100);
  });

  // useTask$ — side effect (odpowiednik useEffect)
  // Uruchamiany na serwerze I na kliencie
  useTask$(({ track }) => {
    track(() => cart.items.length);  // sledz zmiany
    console.log(`Koszyk ma ${cart.items.length} elementow`);
  });

  return (
    <div>
      <p>Suma: {total.value} zl</p>
      <p>Produktow: {cart.items.length}</p>
      <button onClick$={() => (cart.isOpen = !cart.isOpen)}>
        {cart.isOpen ? 'Zamknij' : 'Otworz'} koszyk
      </button>
    </div>
  );
});

6. Event handlers — sufiks $ jest kluczowy

Kazdy event handler w Qwik musi uzywac sufiksu $. Bez niego handler nie zostanie prawidlowo wyciety i zbundlowany. Qwik optymizer sprawdza to podczas buildu.

import { component$, useSignal, $ } from '@builder.io/qwik';

export const EventDemo = component$(() => {
  const log = useSignal('');

  // Handler zdefiniowany inline z $() — wyciety do chunka
  const handleClick = $((event: MouseEvent) => {
    log.value = `Kliknieto: ${(event.target as HTMLElement).textContent}`;
  });

  return (
    <div>
      {/* Inline handler z sufixem $ */}
      <button onClick$={() => (log.value = 'Przycisk A')}>A</button>

      {/* Referencja do handlera przez $ */}
      <button onClick$={handleClick}>B</button>

      {/* Wiele handlerow (tablica) */}
      <button
        onClick$={[
          handleClick,
          $(() => console.log('Drugi handler'))
        ]}
      >C</button>

      {/* Formularze */}
      <form
        onSubmit$={(e) => {
          e.preventDefault();
          // obsluza submit
        }}
        preventdefault:submit  {/* alternatywny sposob */}
      >
        <input name="search" />
        <button type="submit">Szukaj</button>
      </form>

      <p>Log: {log.value}</p>
    </div>
  );
});

7. Routing z QwikCity

QwikCity to meta-framework dla Qwik (jak Next.js dla React). Oferuje file-based routing, loaders (dane po stronie serwera), actions (mutacje) i layouts.

// src/routes/products/[id]/index.tsx
import { component$ } from '@builder.io/qwik';
import {
  routeLoader$,
  routeAction$,
  Form,
  type DocumentHead
} from '@builder.io/qwik-city';
import { z } from 'zod';

// routeLoader$ — pobieranie danych po stronie serwera
// Wykonuje sie na serwerze, dane sa serializowane do HTML
export const useProductLoader = routeLoader$(async ({ params, status }) => {
  const product = await db.product.findUnique({
    where: { id: params.id }
  });

  if (!product) {
    status(404);
    return null;
  }

  return product;
});

// routeAction$ — mutacje (submit formularzy, POST requests)
export const useAddToCart = routeAction$(
  async (data, { cookie, redirect }) => {
    const cart = cookie.get('cart')?.json() ?? [];
    cart.push({ productId: data.productId, qty: 1 });
    cookie.set('cart', JSON.stringify(cart), { path: '/' });
    throw redirect(302, '/cart');
  },
  // Walidacja przez Zod
  z.object({ productId: z.string() })
);

export default component$(() => {
  // useProductLoader() — wywolanie loadera w komponencie
  const product = useProductLoader();
  const addToCart = useAddToCart();

  if (!product.value) return <div>Produkt nie istnieje</div>;

  return (
    <div>
      <h1>{product.value.name}</h1>
      <p>{product.value.price} zl</p>

      {/* Form z action — progressywne usprawnienie, dziala bez JS! */}
      <Form action={addToCart}>
        <input type="hidden" name="productId" value={product.value.id} />
        <button type="submit">Dodaj do koszyka</button>
      </Form>
    </div>
  );
});

// SEO metadata
export const head: DocumentHead = ({ resolveValue }) => {
  const product = resolveValue(useProductLoader);
  return {
    title: product?.name ?? 'Produkt',
    meta: [{ name: 'description', content: product?.description }]
  };
};

8. Speculative Module Fetching

Qwik 1.x wprowadzil Speculative Module Fetching — mechanizm prefetchowania modulow JS zanim uzytkownik je potrzebuje. Dziala przez Service Worker ktory pobiera i cache'uje chunki w tle, gdy przeglądarka jest bezczynna.

// vite.config.ts — konfiguracja prefetchowania
import { defineConfig } from 'vite';
import { qwikVite } from '@builder.io/qwik/optimizer';
import { qwikCity } from '@builder.io/qwik-city/vite';

export default defineConfig(() => ({
  plugins: [
    qwikCity(),
    qwikVite({
      // Strategie prefetchowania:
      // 'prefetch' — <link rel="prefetch"> w HTML
      // 'preload' — <link rel="preload"> w HTML
      // 'modulepreload' — <link rel="modulepreload"> w HTML
      // 'none' — bez prefetchowania
    })
  ]
}));
Efekt Speculative Module Fetching: Po zaladowaniu strony, Service Worker pobiera w tle chunki JS dla interakcji ktore uzytkownik prawdopodobnie wykona. Gdy uzytkownik kliknie — kod jest juz w cache, wiec wczytuje sie natychmiastowo. Laczy zyski resumability (szybki start) z szybkoscia SPA (blyskawiczne interakcje po prefetch).

9. Integracja z React przez qwik-react

// Uzywanie komponentow React wewnatrz Qwik
npm run qwik add react

// src/components/ReactChart.tsx — normalny komponent React
import { useState } from 'react';
export function ReactChart({ data }: { data: number[] }) {
  const [hovered, setHovered] = useState<number | null>(null);
  return (
    <div>
      {data.map((val, i) => (
        <div
          key={i}
          style={{ height: val }}
          onMouseEnter={() => setHovered(i)}
        />
      ))}
      {hovered !== null && <p>Zaznaczony: {data[hovered]}</p>}
    </div>
  );
}

// src/components/QwikWrapper.tsx — opakowanie dla Qwik
import { qwikify$ } from '@builder.io/qwik-react';
import { ReactChart } from './ReactChart';

// qwikify$ — konwertuje React component na Qwik component
export const QwikChart = qwikify$(ReactChart, {
  // Kiedy aktywowac hydratacje React:
  eagerness: 'visible' // | 'load' | 'hover' | 'idle'
});

// Uzycie w komponencie Qwik:
export const Dashboard = component$(() => (
  <QwikChart data={[10, 50, 30, 70, 20]} client:visible />
));
