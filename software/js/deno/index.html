Deno 2

Secure-by-default. TypeScript native. NPM compatibility z v2.0.

1. Co to Deno

Deno zostalo stworzone przez Ryana Dahla — tworcę Node.js — ktory w 2018 roku na konferencji JSConf EU wyglosil slynny talk "10 Things I Regret About Node.js". Deno jest jego odpowiedzia na te zale: bezpieczenstwo, TypeScript natywnie, standardowe Web API zamiast niestandardowego API Node.js.

Deno 2.0 (pazdziernik 2024) to przelomowa wersja — pelna kompatybilnosc z npm i Node.js, stabilne Deno KV, Deno Deploy v2 i Deno Cron. Deno jest napisane w Rust i uzywa silnika V8 (jak Node.js).

Czym Deno rozwiazuje problemy Node.js

  • Bezpieczenstwo — kod nie ma dostepu do systemu plikow, sieci, zmiennych srodowiskowych bez jawnej zgody
  • TypeScript bez konfiguracji — nie potrzeba tsconfig.json, ts-node, babel
  • Web standardy — fetch, Request, Response, URL, WebSocket bez polyfills
  • Brak node_modules — URL imports z cache lub npm: prefix (v2)
  • Wbudowane narzedzia — formatter, linter, test runner, bundler, dokumentacja

2. Instalacja

# Linux / macOS
curl -fsSL https://deno.land/install.sh | sh

# Windows (PowerShell)
irm https://deno.land/install.ps1 | iex

# Przez Homebrew
brew install deno

# Przez Cargo (Rust)
cargo install deno --locked

# Sprawdzenie wersji
deno --version

# Aktualizacja
deno upgrade

# Aktualizacja do konkretnej wersji
deno upgrade --version 2.1.0

# Uruchomienie pliku TypeScript
deno run main.ts

# Uruchomienie z URL (bez pobierania)
deno run https://deno.land/std/examples/welcome.ts

3. System uprawnien (Permissions)

To jedna z najbardziej charakterystycznych cech Deno. Domyslnie program nie ma zadnych uprawnien — kazdy dostep do zasobow wymaga jawnego zezwolenia. Bez flagi permissji program dostanie PermissionDeniedError.

# Uruchomienie z konkretnymi uprawnieniami
deno run --allow-read main.ts             # dostep do wszystkich plikow
deno run --allow-read=/tmp main.ts        # tylko katalog /tmp
deno run --allow-write=./output main.ts   # zapis tylko do ./output
deno run --allow-net main.ts             # dostep do sieci (wszystko)
deno run --allow-net=api.example.com main.ts  # tylko konkretny host
deno run --allow-env main.ts             # zmienne srodowiskowe
deno run --allow-env=API_KEY,PORT main.ts     # tylko wybrane zmienne
deno run --allow-run main.ts             # uruchamianie podprocesow
deno run --allow-hrtime main.ts          # wysoka precyzja czasu (fingerprinting)
deno run --allow-ffi main.ts             # Foreign Function Interface (natywne lib)

# Wszystkie uprawnienia naraz (nie zalecane w produkcji)
deno run --allow-all main.ts
deno run -A main.ts                      # skrot

# W deno.json mozna skonfigurowac uprawnienia
// deno.json
{
  "tasks": {
    "start": "deno run --allow-net --allow-read --allow-env src/main.ts"
  }
}

// Programowe sprawdzanie uprawnien w kodzie
const status = await Deno.permissions.query({ name: 'read', path: '/tmp' });
if (status.state === 'granted') {
  const data = await Deno.readTextFile('/tmp/data.txt');
}

// Prosba o uprawnienie w czasie dzialania
const { state } = await Deno.permissions.request({ name: 'read', path: '/data' });
console.log('Status uprawnienia:', state); // 'granted' | 'denied' | 'prompt'
Uprawnienia w Deno 2 — w v2 system uprawnien zostal rozszerzony o --allow-import (kontrola skad mozna importowac modul) oraz mozliwosc definiowania uprawnien w pliku deno.json przez klucz "permissions".

4. TypeScript natywnie

Deno wykonuje TypeScript bez zadnej konfiguracji. Nie trzeba instalowac typescript, konfigutowac tsconfig.json, ani uzywac ts-node. TypeScript jest pierwszorzednym jezykiem w Deno.

// types.ts — pelne wsparcie TypeScript
interface User {
  id: number;
  name: string;
  email: string;
  createdAt: Date;
}

type ApiResponse<T> = {
  data: T;
  error: null;
} | {
  data: null;
  error: string;
};

async function fetchUser(id: number): Promise<ApiResponse<User>> {
  try {
    const response = await fetch(`https://api.example.com/users/${id}`);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data: User = await response.json();
    return { data, error: null };
  } catch (err) {
    return { data: null, error: (err as Error).message };
  }
}

// Uzycie
const result = await fetchUser(1);
if (result.data) {
  console.log(`Uzytkownik: ${result.data.name}`);
} else {
  console.error(`Blad: ${result.error}`);
}

// Type checking bez uruchamiania
// deno check main.ts

5. Deno 2 i kompatybilnosc z NPM

Deno 2 wprowadzilo pelna kompatybilnosc z npm. Mozna uzywac pakietow npm przez prefix npm: — Deno pobiera je do globalnego cache, bez katalogu node_modules w projekcie.

// Import z npm przez prefix npm:
import express from 'npm:express@4';
import { z } from 'npm:zod';
import chalk from 'npm:chalk@5';

// Lub przez JSR (JavaScript Registry — nastepca deno.land/x)
import { assertEquals } from 'jsr:@std/assert';
import { serve } from 'jsr:@std/http/server';

// Import z URL (stary sposob, nadal dziala)
import { join } from 'https://deno.land/std@0.224.0/path/mod.ts';

// package.json jest teraz wspierany (interop z Node.js)
// Deno 2 czyta package.json i rozumie node_modules

// deno.json — konfiguracja importow (import map)
{
  "imports": {
    "zod": "npm:zod@3",
    "@std/assert": "jsr:@std/assert@^1",
    "express": "npm:express@4"
  }
}

// Po konfiguracji import map:
import { z } from 'zod';        // rozwiazywane przez import map
import express from 'express';  // rowniez przez import map

6. Web standard APIs

Deno implementuje standardowe Web API — te same, ktore sa dostepne w przegladarce. To oznacza, ze kod napisany dla Deno czesto dziala tez w przegladarce bez zmian.

// fetch — identyczny jak w przegladarce
const response = await fetch('https://api.github.com/users/denoland', {
  headers: { 'User-Agent': 'Deno/2.0' }
});
const data = await response.json();
console.log(data.public_repos);

// Request i Response
const req = new Request('https://example.com/api', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'test' })
});

// URL API
const url = new URL('https://example.com/path?query=1#hash');
console.log(url.hostname);   // example.com
console.log(url.pathname);   // /path
console.log(url.searchParams.get('query'));  // 1

// Streams API
const stream = new ReadableStream({
  start(controller) {
    controller.enqueue('Hello');
    controller.enqueue(' World');
    controller.close();
  }
});

// Crypto API
const hash = await crypto.subtle.digest(
  'SHA-256',
  new TextEncoder().encode('hello world')
);

// setTimeout / setInterval (identyczne jak w przegladarce)
const timerId = setTimeout(() => console.log('Po 1s'), 1000);
const intervalId = setInterval(() => console.log('Co 500ms'), 500);

7. Deno Deploy — edge functions

Deno Deploy to platforma edge computing od tworcow Deno. Kod jest uruchamiany blisko uzytkownika w ponad 35 regionach na swiecie (oparty na V8 Isolates, jak Cloudflare Workers).

// Prosty edge worker dla Deno Deploy
// Deployowany przez: deployctl deploy --project=moj-projekt main.ts

Deno.serve(async (req: Request): Promise<Response> => {
  const url = new URL(req.url);

  if (url.pathname === '/') {
    return new Response('Witaj z edge!', {
      headers: { 'Content-Type': 'text/plain' }
    });
  }

  if (url.pathname === '/api/time') {
    return Response.json({
      time: new Date().toISOString(),
      region: Deno.env.get('DENO_REGION') ?? 'unknown'
    });
  }

  // Serwowanie plikow statycznych
  if (url.pathname.startsWith('/static/')) {
    const file = await Deno.open(`.${url.pathname}`);
    return new Response(file.readable);
  }

  return new Response('404', { status: 404 });
});
Deno KV — wbudowana baza klucz-wartosc dostepna natywnie w Deno Deploy. Dane sa replikowane globalnie. Uzycie: const kv = await Deno.openKv(); — dziala lokalnie (SQLite) i na Deno Deploy (FoundationDB).

8. Fresh — framework webowy

Fresh to oficjalny full-stack framework dla Deno. Oparty na Preact i file-based routingu. Domyslnie zero JavaScript po stronie klienta — wyspy interaktywnosci jak w Astro.

// routes/index.tsx — strona glowna (server-rendered)
import { PageProps } from '$fresh/server.ts';

export default function Home({ data }: PageProps) {
  return (
    <main>
      <h1>Witaj w Fresh!</h1>
      <p>Serwer renderuje ten HTML bez zadnego JS po stronie klienta.</p>
    </main>
  );
}

// routes/api/users.ts — API route
import { Handlers } from '$fresh/server.ts';

export const handler: Handlers = {
  async GET(req) {
    const users = [{ id: 1, name: 'Anna' }];
    return Response.json(users);
  },
  async POST(req) {
    const body = await req.json();
    // zapisz uzytkownika...
    return Response.json({ created: true }, { status: 201 });
  }
};

// islands/Counter.tsx — wyspa interaktywnosci (Preact + JS)
import { useSignal } from '@preact/signals';

export default function Counter() {
  const count = useSignal(0);
  return (
    <div>
      <p>Licznik: {count}</p>
      <button onClick={() => count.value++}>+</button>
    </div>
  );
}

9. deno.json — konfiguracja projektu

{
  // deno.json
  "name": "moj-projekt",
  "version": "1.0.0",

  // Zadania (jak npm scripts)
  "tasks": {
    "dev": "deno run --watch --allow-net --allow-read --allow-env src/main.ts",
    "start": "deno run -A src/main.ts",
    "test": "deno test --allow-read tests/",
    "fmt": "deno fmt",
    "lint": "deno lint",
    "check": "deno check src/main.ts"
  },

  // Mapa importow
  "imports": {
    "@std/assert": "jsr:@std/assert@^1",
    "@std/http": "jsr:@std/http@^1",
    "zod": "npm:zod@3"
  },

  // Konfiguracja TypeScript
  "compilerOptions": {
    "strict": true,
    "lib": ["deno.window"]
  },

  // Uprawnienia dla zadan (Deno 2)
  "permissions": {
    "net": true,
    "read": ["./data"],
    "env": ["PORT", "DATABASE_URL"]
  },

  // Formatowanie kodu
  "fmt": {
    "lineWidth": 100,
    "indentWidth": 2,
    "singleQuote": true
  },

  // Linting
  "lint": {
    "rules": {
      "include": ["ban-untagged-todo", "no-console"]
    }
  }
}
