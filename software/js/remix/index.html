Remix → React Router 7

Web standards focused. Merged into React Router v7 (2024). Loaders + Actions.

1. Historia: Remix merguje z React Router 7

Remix zostal stworzony przez Ryana Florence i Michaela Jacksona — autorow React Router — i wydany publicznie w 2021 roku. W grudniu 2024 nastapil historyczny merge: Remix v3 stal sie React Router v7. Nie jest to porzucenie projektu — wrecz przeciwnie, to konsolidacja dwoch narzedzi w jedno.

Co sie zmienilo po merge

  • Pakiet remix jest teraz react-router (v7+)
  • Framework mode (z loaderami, actions, SSR) jest teraz czescia React Router
  • Migracja z Remix v2: minimalne zmiany, glownie aliasy importow
  • React Router mozna uzywac jako czysty router kliencki LUB jako pelny framework (Vite plugin)
  • Nadal oparty na Vite — szybki DX, HMR, TypeScript natywnie
React Router v7 = Remix v3
Jesli znasz Remix — znasz juz React Router 7 w trybie framework. Jesli znasz React Router 6 — framework mode to dla Ciebie nowosci: loaders, actions, SSR, file-based routing jako opcja.

Dwa tryby uzycia React Router v7

  • Library mode — klasyczny React Router (tylko client-side routing, jak dotychczas)
  • Framework mode — pelny SSR framework z loaderami i akcjami (to jest dawny Remix)

2. Filozofia Web Standards

Remix / React Router 7 jest zbudowany wokol standardowych Web API — tych samych, ktore dzialaja w przegladarkach. Zamiast wymyslac nowe abstrakcje, Remix uzywa: Request, Response, FormData, URL, Headers, fetch.

To oznacza, ze kod Remix jest bardziej przenosny i blizszy temu, co faktycznie dzieje sie w sieci. Znajomosc Web API przeklada sie bezposrednio na znajomosc Remix.

  • Form zamiast fetch — natywny HTML Form z progressywnym ulepszeniem
  • Loaders zamiast useEffect + fetch — dane ladowane po stronie serwera, przed renderowaniem
  • Actions zamiast API routes — mutacje przez standardowy POST
  • Cache headers — HTTP cache przez standardowe naglowki Cache-Control
  • cookies() — standardowe HTTP cookies bez sesji po stronie serwera

4. Loaders — dane z serwera

Loader to funkcja uruchamiana po stronie serwera przed wyrenderowaniem komponentu. Zwraca dane dostepne w komponencie przez loaderData. Wspiera pelne HTTP — mozna ustawiac naglowki cache, cookies, statusy.

// app/routes/products._index.tsx
import type { Route } from './+types/products._index';

export async function loader({ request, context }: Route.LoaderArgs) {
  // Dostep do URL i query params
  const url = new URL(request.url);
  const page = Number(url.searchParams.get('page') ?? '1');
  const q = url.searchParams.get('q') ?? '';

  // Dostep do cookies
  const session = await getSession(request.headers.get('Cookie'));
  const userId = session.get('userId');

  // Pobieranie danych
  const [products, total] = await Promise.all([
    db.product.findMany({
      where: q ? { name: { contains: q } } : {},
      skip: (page - 1) * 20,
      take: 20
    }),
    db.product.count()
  ]);

  // Zwrot z naglowkami cache (HTTP caching!)
  return Response.json(
    { products, total, page, q },
    {
      headers: {
        'Cache-Control': 'public, max-age=60, stale-while-revalidate=300'
      }
    }
  );
}

// Uzycie w komponencie
export default function ProductsPage({ loaderData }: Route.ComponentProps) {
  const { products, total, page } = loaderData;
  return (
    <div>
      <h1>Produkty ({total})</h1>
      {products.map(p => <ProductCard key={p.id} product={p} />)}
    </div>
  );
}

5. Actions — mutacje formularzy

Actions obsługują POST requesty — mutacje danych (tworzenie, aktualizacja, usuwanie). Sa uruchamiane po stronie serwera po submicie formularza lub wywolaniu fetcher.submit().

// app/routes/contacts.new.tsx
import type { Route } from './+types/contacts.new';
import { Form, redirect, useActionData } from 'react-router';
import { z } from 'zod';

const ContactSchema = z.object({
  name: z.string().min(2, 'Imie musi miec min. 2 znaki'),
  email: z.string().email('Niepoprawny email'),
  message: z.string().min(10, 'Wiadomosc zbyt krotka')
});

// Action — wywolywane przez POST do tej trasy
export async function action({ request }: Route.ActionArgs) {
  const formData = await request.formData();

  const result = ContactSchema.safeParse({
    name: formData.get('name'),
    email: formData.get('email'),
    message: formData.get('message')
  });

  // Zwrot bledow walidacji
  if (!result.success) {
    return { errors: result.error.flatten().fieldErrors };
  }

  // Zapis i przekierowanie
  await db.contact.create({ data: result.data });
  return redirect('/contacts?sent=true');
}

// Komponent z formularzem
export default function NewContact({ actionData }: Route.ComponentProps) {
  return (
    // Form — standardowy HTML form + Remix enhancement
    // Dziala bez JavaScript (progressywne usprawnienie)!
    <Form method="post">
      <div>
        <input name="name" placeholder="Imie" required />
        {actionData?.errors?.name && (
          <p className="error">{actionData.errors.name[0]}</p>
        )}
      </div>
      <div>
        <input name="email" type="email" placeholder="Email" required />
        {actionData?.errors?.email && (
          <p className="error">{actionData.errors.email[0]}</p>
        )}
      </div>
      <textarea name="message" placeholder="Wiadomosc" required />
      <button type="submit">Wyslij</button>
    </Form>
  );
}

6. Error Boundaries per route

Kazda trasa w React Router 7 moze miec wlasny error boundary. Blad w loaderze lub akcji jest "zlapany" przez najblizszy error boundary — reszta aplikacji dziala normalnie.

// app/routes/products.$id.tsx
export function ErrorBoundary({ error }: Route.ErrorBoundaryProps) {
  // Obsluguje bledy loader, action i renderowania dla tej trasy
  if (isRouteErrorResponse(error)) {
    // Bledy HTTP (np. throw new Response('Not Found', {status: 404}))
    return (
      <div>
        <h1>{error.status} — {error.statusText}</h1>
        <p>{error.data}</p>
      </div>
    );
  }

  // Nieoczekiwany blad JavaScript
  return (
    <div>
      <h1>Nieoczekiwany blad</h1>
      <p>{error instanceof Error ? error.message : 'Nieznany blad'}</p>
    </div>
  );
}

// Rzucanie bledow HTTP w loaderze
export async function loader({ params }: Route.LoaderArgs) {
  const product = await db.product.findUnique({ where: { id: params.id } });

  if (!product) {
    // Zostanie zlapany przez ErrorBoundary tej trasy
    throw new Response('Produkt nie znaleziony', { status: 404 });
  }

  return { product };
}

7. Progressive Enhancement

Progressive enhancement to jedna z glownych filozofii Remix / React Router 7. Aplikacja dziala nawet bez JavaScript — formularze wysylaja dane, nawigacja dziala. JavaScript tylko ulepsza doswiadczenie (pending states, optimistic UI, instant navigation).

import { Form, useNavigation, useOptimistic } from 'react-router';

// useNavigation — stan nawigacji / submitu formularza
export default function NewPostForm() {
  const navigation = useNavigation();
  const isSubmitting = navigation.state === 'submitting';

  return (
    <Form method="post">
      <input name="title" />
      <textarea name="body" />
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Zapisywanie...' : 'Zapisz post'}
      </button>
    </Form>
  );
}

// useFetcher — submity bez nawigacji (np. like button, delete)
import { useFetcher } from 'react-router';

export function LikeButton({ postId, liked }: { postId: string; liked: boolean }) {
  const fetcher = useFetcher();

  // Optimistic UI — natychmiastowa odpowiedz UI przed odpowiedzia serwera
  const optimisticLiked = fetcher.formData
    ? fetcher.formData.get('action') === 'like'
    : liked;

  return (
    <fetcher.Form method="post" action={`/posts/${postId}/like`}>
      <button
        name="action"
        value={optimisticLiked ? 'unlike' : 'like'}
        type="submit"
      >
        {optimisticLiked ? 'Polubiono' : 'Polub'}
      </button>
    </fetcher.Form>
  );
}

8. Streaming z defer i Suspense

React Router 7 wspiera streaming — mozna wyslac czesc HTML natychmiast, a wolne dane zaladowac pozniej przez Suspense bez blokowania calej strony.

import { Suspense } from 'react';
import { Await } from 'react-router';

export async function loader() {
  // Szybkie dane — czekamy (blokujace)
  const user = await db.user.findFirst();

  // Wolne dane — NIE czekamy, zwracamy Promise
  const recommendations = db.product.findMany({ take: 5 }); // bez await!

  return {
    user,                 // rozwiazane natychmiast
    recommendations       // Promise — rozwiazywany przez Await
  };
}

export default function Dashboard({ loaderData }: Route.ComponentProps) {
  const { user, recommendations } = loaderData;

  return (
    <div>
      <h1>Czesc, {user.name}!</h1>

      <Suspense fallback={<p>Ladowanie rekomendacji...</p>}>
        <Await resolve={recommendations}>
          {(items) => (
            <ul>
              {items.map(item => <li key={item.id}>{item.name}</li>)}
            </ul>
          )}
        </Await>
      </Suspense>
    </div>
  );
}

Wybierz Remix / React Router 7 gdy: budujesz aplikacje intensywnie korzystajaca z formularzy i mutacji, chcesz blisko Web standards bez nowych abstrakcji, deployujesz na rozne platformy (nie tylko Vercel), lub zalezy Ci na progressywnym ulepszeniu (dostepnosc, wolne polaczenia).
Wybierz Next.js gdy: korzytasz glownie z Vercel, zespol zna React Server Components, potrzebujesz duzego ekosystemu integracji (Auth.js, Prisma Accelerate, etc.) lub budujesz content-heavy e-commerce z ISR/PPR.
