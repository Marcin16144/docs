Vite

Lightning-fast dev server. ESM-native. Standard 2026 dla wiekszosci frameworkow.

1. Co to Vite

Vite (fr. "szybko") to narzedzie build stworzone przez Evana You (tworca Vue.js). Zostalo zaprojektowane od zera pod natywne ESM przegladarki, dzieki czemu dev server startuje niemal natychmiast niezaleznie od rozmiaru projektu.

Dwie warstwy Vite:
  • Dev server — natywne ESM + esbuild do pre-bundlingu node_modules. Pliki sa serwowane bezposrednio do przegladarki bez bundlowania.
  • Production build — Rollup. Dojrzaly bundler z doskonalym tree-shakingiem i code-splittingiem. (Przyszlosc: Rolldown)

Dlaczego Vite jest szybki w dev

  • No bundling in dev: kazdy plik jest osobnym ESM modulem. Przeglądarka robi import na zadanie.
  • esbuild pre-bundling: node_modules (CommonJS) sa pre-bundlowane raz przez esbuild (Go) — 10–100x szybciej niz webpack/Rollup.
  • On-demand transforms: plik jest transformowany (TypeScript, JSX) dopiero gdy przeglądarka o niego poprosi.
  • Instant HMR: HMR propaguje tylko zmieniony modul — czas niezalezny od rozmiaru aplikacji.

Uzywany przez: Vue 3, SvelteKit (opcja), Astro, Remix, QwikCity, SolidStart, Nuxt 3 (dev), Vitest i setki innych narzedzi.

2. Instalacja — wszystkie templates

# npm create vite@latest — interaktywny kreator
npm create vite@latest moja-aplikacja
# lub z bezposrednim wyborem template:
npm create vite@latest moja-app -- --template react-ts

# dostepne oficjalne templates:
# vanilla        vanilla-ts
# vue            vue-ts
# react          react-ts     react-swc    react-swc-ts
# preact         preact-ts
# lit            lit-ts
# svelte         svelte-ts
# solid          solid-ts
# qwik           qwik-ts

# Bun (szybszy install)
bun create vite moja-app --template react-ts

# po instalacji
cd moja-aplikacja
npm install
npm run dev     # dev server na http://localhost:5173
npm run build   # produkcja do dist/
npm run preview # podglad produkcji lokalnie
react-swc vs react: Template react-swc-ts uzywa SWC (Rust-based compiler) zamiast Babel do transformacji JSX — szybszy cold start i HMR. Zalecany dla nowych projektow React.

3. Dev server — ESM, HMR, Pre-bundling

Dev server Vite dziala fundamentalnie inaczej niz webpack-dev-server czy CRA. Nie tworzy bundla przy starcie — serwuje pliki jako native ESM.

// Jak to dziala pod spodem:
// 1. Przeglądarka robi: import App from '/src/App.tsx'
// 2. Vite otrzymuje zadanie, transformuje App.tsx → JS
// 3. Zwraca transformowany modul
// 4. App.tsx importuje './components/Button.tsx' — ten sam proces
// 5. node_modules? Pobrane z pre-bundlowanego cache

// Pre-bundling — jednorazowe przy pierwszym uruchomieniu
// Vite skanuje importy, pre-bundluje node_modules przez esbuild
// Wynik cachowany w node_modules/.vite/deps/
// Reinicjowany gdy zmieni sie package.json lub lockfile

// HMR — Hot Module Replacement
// Zmiana pliku → Vite wysyla update przez WebSocket
// Przeglądarka pobiera TYLKO zmieniony modul
// Framework (React/Vue) podmienia go bez przeladowania strony

// Zmienne srodowiskowe w dev
// .env
VITE_API_URL=http://localhost:3000
VITE_DEBUG=true

// dostep w kodzie (tylko VITE_ prefix jest eksponowany)
console.log(import.meta.env.VITE_API_URL);
console.log(import.meta.env.MODE);      // "development"
console.log(import.meta.env.DEV);       // true
console.log(import.meta.env.PROD);      // false

4. vite.config.ts — kluczowe opcje

// vite.config.ts — kompletna konfiguracja z aliasami i proxy
import { defineConfig, loadEnv } from 'vite';
import react from '@vitejs/plugin-react-swc';
import { resolve } from 'path';

export default defineConfig(({ command, mode }) => {
  // ladowanie .env dla aktualnego mode
  const env = loadEnv(mode, process.cwd(), '');

  return {
    // plugins
    plugins: [react()],

    // resolve — aliasy sciezek
    resolve: {
      alias: {
        '@': resolve(__dirname, 'src'),
        '@components': resolve(__dirname, 'src/components'),
        '@lib': resolve(__dirname, 'src/lib'),
        '@types': resolve(__dirname, 'src/types'),
      },
      // rozszerzenia plikow (kolejnosc ma znaczenie)
      extensions: ['.tsx', '.ts', '.jsx', '.js', '.json'],
    },

    // dev server
    server: {
      port: 3000,
      strictPort: true,         // blad jesli port zajety
      open: true,               // otworz przeglądarka przy starcie
      cors: true,

      // proxy — przekierowanie API calls (omija CORS w dev)
      proxy: {
        '/api': {
          target: 'http://localhost:8080',
          changeOrigin: true,
          rewrite: path => path.replace(/^\/api/, ''),
        },
        '/ws': {
          target: 'ws://localhost:8080',
          ws: true,             // WebSocket proxy
        },
      },
    },

    // preview server (npm run preview)
    preview: {
      port: 4173,
      proxy: {
        '/api': { target: env.API_URL, changeOrigin: true },
      },
    },

    // optimizeDeps — kontrola pre-bundlingu
    optimizeDeps: {
      include: ['lodash-es', 'date-fns'], // force pre-bundle (nawet jesli ESM)
      exclude: ['@moja-org/ui'],           // wylacz pre-bundle (np. workspace pkg)
    },

    // definiowanie globalnych stalych
    define: {
      __APP_VERSION__: JSON.stringify(process.env.npm_package_version),
    },
  };
});

6. Production Build — Rollup, code splitting, chunks

// vite.config.ts — zaawansowane opcje build
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react-swc';

export default defineConfig({
  plugins: [react()],

  build: {
    // cel output
    outDir: 'dist',
    assetsDir: 'assets',

    // minifikacja (domyslnie esbuild — szybki)
    // 'terser' daje mniejszy output, ale wolniejszy build
    minify: 'esbuild',

    // sourcemaps w produkcji (uwaga: duze pliki)
    sourcemap: false,

    // ostrzegaj przy chunk wiekszym niz X KB
    chunkSizeWarningLimit: 500,

    // CSS code splitting (domyslnie true)
    cssCodeSplit: true,

    rollupOptions: {
      // multiple entry points
      input: {
        main: 'index.html',
        admin: 'admin.html',
      },

      output: {
        // strategia nazewnictwa chunkow
        chunkFileNames: 'assets/[name]-[hash].js',
        entryFileNames: 'assets/[name]-[hash].js',
        assetFileNames: 'assets/[name]-[hash].[ext]',

        // reczny podzial na chunki — vendor splitting
        manualChunks(id) {
          // react + react-dom w osobnym chunку
          if (id.includes('node_modules/react') ||
              id.includes('node_modules/react-dom')) {
            return 'react-vendor';
          }
          // router w osobnym chunku
          if (id.includes('node_modules/react-router')) {
            return 'router';
          }
          // reszta node_modules → vendor
          if (id.includes('node_modules')) {
            return 'vendor';
          }
        },
      },

      // external — nie bundluj (np. dla library mode)
      // external: ['react', 'react-dom'],
    },

    // library mode — budowanie npm package przez Vite
    lib: {
      entry: 'src/index.ts',
      name: 'MojaLib',
      formats: ['es', 'cjs'],
      fileName: format => `moja-lib.${format}.js`,
    },
  },
});

7. Vite w monorepo

// monorepo z pnpm workspaces — typowa struktura
packages/
  ui/              # biblioteka komponentow (tsup/vite lib mode)
  utils/           # helper functions (tsup)
apps/
  web/             # aplikacja Vite + React
  admin/           # aplikacja Vite + React

// apps/web/vite.config.ts — konfiguracja ze wskazaniem na workspace packages
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react-swc';
import { resolve } from 'path';

export default defineConfig({
  plugins: [react()],
  optimizeDeps: {
    // workspace packages w stub/watch mode — wylacz pre-bundling
    exclude: ['@moja-org/ui', '@moja-org/utils'],
  },
  resolve: {
    // opcjonalnie: wskazanie bezposrednio na src zamiast dist
    alias: {
      '@moja-org/ui': resolve(__dirname, '../../packages/ui/src'),
    },
  },
});

// turbo.json — Turborepo pipeline
{
  "pipeline": {
    "dev": {
      "dependsOn": [],       // dev rownolegle
      "cache": false,
      "persistent": true     // long-running process
    },
    "build": {
      "dependsOn": ["^build"],  // najpierw packages, potem apps
      "outputs": ["dist/**"]
    }
  }
}

8. Vite + TypeScript

Vite uzywa esbuild do transpilacji TypeScript — jest to szybkie, ale nie sprawdza typow. Do sprawdzania typow potrzebny jest osobny krok lub plugin.

// Vite transpiluje TS przez esbuild — szybko, ale bez type checking
// Aby miec type checking, dodaj:

// 1. Reczny krok w CI/CD:
// "build": "tsc --noEmit && vite build"

// 2. vite-plugin-checker — sprawdzanie w tle podczas dev
import checker from 'vite-plugin-checker';

export default defineConfig({
  plugins: [
    checker({
      typescript: true,  // bledy TS w overlay przegladarki + terminal
    }),
  ],
});

// 3. vite-tsconfig-paths — aliasy z tsconfig.paths
import tsconfigPaths from 'vite-tsconfig-paths';
// po dodaniu pluginu, aliasy z tsconfig.json dzialaja w Vite automatycznie

// tsconfig.json dla projektu Vite + React
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "Bundler",  // Vite-specific (bundler resolution)
    "jsx": "react-jsx",
    "strict": true,
    "noEmit": true,                 // Vite produkuje output, nie tsc
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "include": ["src"],
  "references": [{ "path": "./tsconfig.node.json" }]
}

// tsconfig.node.json — dla vite.config.ts samego w sobie
{
  "compilerOptions": {
    "composite": true,
    "module": "ESNext",
    "moduleResolution": "Bundler"
  },
  "include": ["vite.config.ts"]
}

9. Vite 6 — Environment API i Rolldown

Vite 6 (2024) wprowadzil Environment API — fundamentalna zmiana architektury pozwalajaca na precyzyjna kontrole nad roznym srodowiskami (client, SSR, edge).

Environment API — co to znaczy w praktyce

  • Kazde srodowisko (browser, SSR Node.js, SSR Edge) moze miec inne ustawienia modulu
  • Meta-frameworki (Nuxt, SvelteKit, Remix) moga precyzyjniej kontrolowac bundle
  • Plugin API rozszerzone o informacje o aktualnym srodowisku
  • Lepsza izolacja miedzy client a server code podczas budowania
// vite.config.ts — Vite 6 Environment API (preview)
import { defineConfig } from 'vite';

export default defineConfig({
  environments: {
    client: {
      build: {
        outDir: 'dist/client',
        rollupOptions: { /* ... */ },
      },
    },
    ssr: {
      build: {
        outDir: 'dist/server',
        ssr: true,
      },
    },
    edge: {
      webCompatible: true,  // Edge runtime (Cloudflare Workers)
      build: {
        outDir: 'dist/edge',
      },
    },
  },
});

10. Vite vs CRA vs Webpack DevServer vs Turbopack

Narzedzie Cold Start HMR Prod Build Konfiguracja Ecosystem / Status
Vite 6 ~200-500ms ~10-50ms Rollup (dobry) Minimalna Ogromny, aktywny. Standard 2026.
CRA (Create React App) ~15-30s ~1-3s webpack (wolny) Ukryta (eject) Przestarzaly. Oficjalnie porzucony 2023.
webpack DevServer ~5-60s ~0.5-3s webpack (dojrzaly) Rozbudowana Ogromny ekosystem. Stary standard. Dla legacy.
Turbopack ~100-200ms ~5-15ms Eksperymentalny Minimalna (Next.js only) Tylko Next.js. Dev stable, build exp.
Rspack ~300-600ms ~20-50ms Rspack (szybki) Jak webpack Rosnacy. Idealne dla migracji z webpack.
Parcel 2 ~2-5s ~100ms Parcel (dobry) Zero config Maly. Dobry dla prototypow.

Kompletna konfiguracja: Vite + React + TypeScript + Alias + Proxy

// vite.config.ts — produkcyjna konfiguracja starter
import { defineConfig, loadEnv } from 'vite';
import react from '@vitejs/plugin-react-swc';
import checker from 'vite-plugin-checker';
import tsconfigPaths from 'vite-tsconfig-paths';
import { resolve } from 'path';

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '');
  const isProd = mode === 'production';

  return {
    plugins: [
      react(),
      tsconfigPaths(),
      !isProd && checker({ typescript: true }),
    ].filter(Boolean),

    resolve: {
      alias: {
        '@': resolve(__dirname, 'src'),
        '@components': resolve(__dirname, 'src/components'),
        '@hooks': resolve(__dirname, 'src/hooks'),
        '@stores': resolve(__dirname, 'src/stores'),
      },
    },

    server: {
      port: 3000,
      proxy: {
        '/api': {
          target: env.VITE_API_URL || 'http://localhost:8080',
          changeOrigin: true,
        },
      },
    },

    build: {
      outDir: 'dist',
      sourcemap: !isProd,
      rollupOptions: {
        output: {
          manualChunks: {
            'react-vendor': ['react', 'react-dom'],
            'router': ['react-router-dom'],
            'query': ['@tanstack/react-query'],
          },
        },
      },
    },

    test: {
      // Vitest — testowanie zintegrowane z Vite
      environment: 'jsdom',
      globals: true,
      setupFiles: ['./src/test/setup.ts'],
    },
  };
});
