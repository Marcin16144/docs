Astro 5

Multi-framework islands architecture. Content-first. Zero JS by default.

1. Co to Astro

Astro to framework do budowania stron internetowych skupiony na tresci (content-first). Jego glowna cecha to islands architecture — domyslnie generuje czysty HTML i CSS bez zadnego JavaScript. JS jest dolaczany tylko tam, gdzie jest faktycznie potrzebny (tzw. wyspy interaktywnosci).

Astro zostalo wydane w 2022 roku i szybko stalo sie pierwszym wyborem dla blogów, dokumentacji, stron marketingowych i portali z trescia. Wersja 5 (2024) wprowadzila Content Layer API, Server Islands i ulepszone Astro Actions.

Glowne zalety Astro

  • Zero JS by default — HTML jest wysylany bez zadnego runtime JavaScript
  • Islands Architecture — komponenty interaktywne laduja JS selektywnie
  • Multi-framework — mozna mieszac React, Vue, Svelte, Solid w jednym projekcie
  • Content Collections — type-safe zarzadzanie plikami Markdown/MDX
  • Swietne Core Web Vitals — minimalny JavaScript = szybkie strony

Typowe zastosowania

  • Blogi techniczne i osobiste
  • Dokumentacja projektow open-source
  • Strony marketingowe i landing pages
  • Portale z trescia (news, magazine)
  • Portfolio i strony prezentacyjne

2. Instalacja

# Kreator interaktywny (zalecany)
npm create astro@latest

# Lub z konkretnym templatem
npm create astro@latest -- --template blog
npm create astro@latest -- --template docs
npm create astro@latest -- --template minimal

# Uruchomienie serwera dev
cd moj-projekt
npm run dev

# Build produkcyjny
npm run build

# Podglad zbudowanej strony
npm run preview

# Dodanie integracji
npx astro add react
npx astro add vue
npx astro add tailwind
npx astro add mdx
Struktura katalogow Astro
src/pages/ — strony (routing oparty na plikach)
src/components/ — komponenty .astro i z innych frameworkow
src/content/ — kolekcje tresci (Markdown, MDX)
src/layouts/ — szablony stron
public/ — pliki statyczne (kopiowane bez zmian)
astro.config.mjs — konfiguracja projektu

3. Pliki .astro

Plik .astro sklada sie z trzech czesci: frontmatter (kod JavaScript/TypeScript), template HTML i opcjonalne scoped styles. Frontmatter wykonuje sie wylacznie na serwerze — nie trafia do przegladarki.

---
// Frontmatter — wykonuje sie na serwerze / build time
import Layout from '../layouts/BaseLayout.astro';
import ArticleCard from '../components/ArticleCard.astro';
import { getCollection } from 'astro:content';

// Pobieranie danych podczas buildu
const posts = await getCollection('blog');
const sortedPosts = posts.sort(
  (a, b) => b.data.pubDate.valueOf() - a.data.pubDate.valueOf()
);

const title = 'Moj Blog';
---

<!-- Template HTML z wrazeniami --- -->
<Layout title={title}>
  <h1>{title}</h1>
  <p>Lacznie postow: {sortedPosts.length}</p>

  <ul>
    {sortedPosts.map(post => (
      <ArticleCard
        title={post.data.title}
        slug={post.slug}
        date={post.data.pubDate}
      />
    ))}
  </ul>
</Layout>

<style>
  /* Style sa automatycznie scoped do tego komponentu */
  h1 {
    font-size: 2rem;
    color: #f97316;
  }
  ul {
    display: grid;
    grid-template-columns: repeat(auto-fill, minmax(300px, 1fr));
    gap: 1rem;
  }
</style>

4. Component Islands — React/Vue/Svelte w Astro

Dyrektywa client:* aktywuje hydratacje komponentu — bez niej komponent renderuje tylko HTML (bez interaktywnosci).

---
// Importy komponentow z roznych frameworkow
import ReactCounter from '../components/ReactCounter.jsx';
import VueSearch from '../components/VueSearch.vue';
import SvelteModal from '../components/SvelteModal.svelte';
---

<!-- Bez dyrektywy: tylko statyczny HTML, zero JS -->
<ReactCounter />

<!-- client:load — hydratacja od razu po zaladowaniu strony -->
<ReactCounter client:load />

<!-- client:idle — hydratacja gdy przeglądarka jest wolna -->
<VueSearch client:idle />

<!-- client:visible — hydratacja gdy element jest w viewport (lazy) -->
<SvelteModal client:visible />

<!-- client:only — renderuj tylko po stronie klienta (bez SSR HTML) -->
<ReactCounter client:only="react" />

<!-- client:media — hydratacja tylko dla okreslonego media query -->
<MobileMenu client:media="(max-width: 768px)" />
Wydajnosc Islands Architecture: Kazda wyspa laduje tylko swoj JS. Pozostala czesc strony to czysty HTML. Dzieki temu LCP (Largest Contentful Paint) jest bardzo krotki, a TTI (Time to Interactive) dotyczy tylko interaktywnych wysp.

5. Content Collections

Content Collections to type-safe system zarzadzania plikami tresci (Markdown, MDX, JSON, YAML). Definiujesz schemat przez Zod — Astro automatycznie waliduje pliki podczas buildu.

// src/content/config.ts
import { defineCollection, z } from 'astro:content';

const blogCollection = defineCollection({
  type: 'content', // 'content' dla .md/.mdx, 'data' dla .json/.yaml
  schema: z.object({
    title: z.string(),
    description: z.string(),
    pubDate: z.date(),
    author: z.string().default('Anonim'),
    tags: z.array(z.string()).default([]),
    image: z.object({
      url: z.string(),
      alt: z.string()
    }).optional(),
    draft: z.boolean().default(false)
  })
});

const authorsCollection = defineCollection({
  type: 'data',
  schema: z.object({
    name: z.string(),
    bio: z.string(),
    avatar: z.string()
  })
});

export const collections = {
  blog: blogCollection,
  authors: authorsCollection
};

// Uzycie w stronach
import { getCollection, getEntry } from 'astro:content';

// Wszystkie posty (bez draftow)
const posts = await getCollection('blog', ({ data }) => !data.draft);

// Konkretny post po slug
const post = await getEntry('blog', 'moj-pierwszy-post');
const { Content } = await post.render();

6. Routing — oparty na plikach

Pliki w src/pages/ automatycznie staja sie trasami. Dynamiczne trasy sa tworzone przez pliki z nazwami w nawiasach kwadratowych.

// Struktura plikow i odpowiadajace URL-e:
// src/pages/index.astro         → /
// src/pages/about.astro         → /about
// src/pages/blog/index.astro    → /blog
// src/pages/blog/[slug].astro   → /blog/dowolny-slug

// src/pages/blog/[slug].astro
---
import { getCollection } from 'astro:content';
import Layout from '../../layouts/Layout.astro';

// getStaticPaths() — generowanie tras statycznych
export async function getStaticPaths() {
  const posts = await getCollection('blog');
  return posts.map(post => ({
    params: { slug: post.slug },
    props: { post }
  }));
}

// Typowanie props
import type { CollectionEntry } from 'astro:content';
interface Props { post: CollectionEntry<'blog'>; }
const { post } = Astro.props;
const { Content } = await post.render();
---

<Layout title={post.data.title}>
  <article>
    <h1>{post.data.title}</h1>
    <time>{post.data.pubDate.toLocaleDateString('pl-PL')}</time>
    <Content />
  </article>
</Layout>

7. Tryb SSR z adapterami

Domyslnie Astro generuje strony statyczne (SSG). Wlaczenie output: 'server' aktywuje SSR — kazde zadanie jest renderowane na serwerze w czasie rzeczywistym.

// astro.config.mjs
import { defineConfig } from 'astro/config';
import node from '@astrojs/node';
import vercel from '@astrojs/vercel/serverless';

export default defineConfig({
  output: 'server', // lub 'hybrid' (SSG domyslnie + SSR per-page)
  adapter: node({ mode: 'standalone' }),
  // lub:
  // adapter: vercel()
});

// W trybie 'hybrid' — oznaczenie konkretnej strony jako SSR:
// src/pages/dashboard.astro
---
export const prerender = false; // Ta strona renderuje sie live
const user = Astro.locals.user;
if (!user) return Astro.redirect('/login');
---
<h1>Dashboard uzytkownika {user.name}</h1>
Dostepne adaptery: Node.js, Vercel, Netlify, Cloudflare Workers/Pages, Deno Deploy, AWS Lambda. Kazdy adapter optymalizuje build pod docelowe srodowisko deploymentu.

8. View Transitions API

Astro dostarcza natywna integracje z View Transitions API — przejscia miedzy stronami bez pelnego przeladowania (jak SPA), ale z zachowaniem architektury MPA.

---
// src/layouts/BaseLayout.astro
import { ViewTransitions } from 'astro:transitions';
---
<html>
  <head>
    <ViewTransitions />
    <!-- Wlacza animacje przejsc miedzy stronami -->
  </head>
  <body>
    <slot />
  </body>
</html>

<!-- Kontrolowanie animacji konkretnych elementow -->
<h1 transition:name="page-title">Tytul</h1>
<img transition:name="hero-image" src="/hero.jpg" />

<!-- Wylaczenie animacji dla elementu -->
<nav transition:persist>
  <!-- Ten element nie bedzie animowany przy przejsciach -->
</nav>

9. Astro DB (libSQL / Turso)

Astro DB to wbudowane rozwiazanie bazodanowe oparte na libSQL (fork SQLite od Turso). Idealne dla malych i srednich aplikacji z treścia dynamiczna.

// db/config.ts
import { defineDb, defineTable, column } from 'astro:db';

const Comment = defineTable({
  columns: {
    id: column.number({ primaryKey: true }),
    author: column.text(),
    body: column.text(),
    postSlug: column.text(),
    createdAt: column.date({ default: NOW })
  }
});

export default defineDb({
  tables: { Comment }
});

// Uzycie w Astro Actions lub API routes
import { db, Comment, eq } from 'astro:db';

// Pobieranie
const comments = await db
  .select()
  .from(Comment)
  .where(eq(Comment.postSlug, slug));

// Wstawianie
await db.insert(Comment).values({
  author: 'Jan',
  body: 'Swietny artykul!',
  postSlug: 'hello-world'
});

Wybierz Astro gdy: budujesz strone z przewaga statycznej tresci, priorytetem sa Core Web Vitals, lub chcesz mieszac komponenty z roznych frameworkow. Astro jest najlepsza opcja dla blogów, dokumentacji i stron marketingowych.
Wybierz Next.js gdy: aplikacja wymaga intensywnej interaktywnosci, uwierzytelniania, skomplikowanego stanu po stronie klienta, lub gdy korzytasz glownie z ekosystemu React/Vercel.
