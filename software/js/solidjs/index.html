SolidJS

Fine-grained reactivity. JSX bez Virtual DOM. Performance jak Svelte, DX jak React.

1. Co to SolidJS

SolidJS to biblioteka UI stworzona przez Ryana Carniato. Jej glowna cecha to fine-grained reactivity — system reaktywnosci sledzacy dokladnie, ktore fragmenty DOM zaleza od ktorych danych, i aktualizujacy tylko te konkretne fragmenty bez ponownego renderowania calego komponentu.

Bez Virtual DOM — React uzywa Virtual DOM do wyliczania roznic (diffing) i stosuje je w batchu. Svelte eliminuje VDOM przez kompilacje. SolidJS eliminuje VDOM przez fine-grained subscriptions — kazdy fragment DOM subskrybuje bezposrednio do sygnalu.

  • Dirty checking (Angular, stary Vue): framework co jakis czas sprawdza caly stan aplikacji — kosztowne
  • Virtual DOM diffing (React, Vue 3 default): porownuje drzewa — tanie per komponent, ale skaluje sie liniowo
  • Fine-grained (SolidJS, Svelte runes, Vue reactivity internals): tylko zalezsnosci — O(1) per aktualizacje

Komponenty SolidJS sa uruchamiane raz i nigdy nie sa re-renderowane. Zamiast tego reaktywne prymitywy (signals, memos, effects) subskrybuja sie do danych i aktualizuja DOM bezposrednio.

2. Instalacja

Najszybszy start to oficjalny template przez Vite:

# oficjalny kreator (pyta o template: bare, ts, router, tanstack-router)
npm create solid@latest moja-aplikacja
cd moja-aplikacja
npm install
npm run dev

# albo bezposrednio przez Vite z templatem
npm create vite@latest moja-app -- --template solid-ts

Wymagania: Node 18+. Template solid-ts daje TypeScript + Vite + vite-plugin-solid.

Zalecany stack 2026: SolidJS + TypeScript + Vite + SolidStart (full-stack) lub solid-router (SPA). 
# instalacja do istniejacego projektu Vite
npm install solid-js
npm install -D vite-plugin-solid

# vite.config.ts
import { defineConfig } from 'vite';
import solid from 'vite-plugin-solid';
export default defineConfig({ plugins: [solid()] });

3. Signals — createSignal()

Signal to reaktywna wartosc. createSignal zwraca tuple [getter, setter]. Getter to funkcja — nie wlasciwosc — co pozwala systemowi sledzic zalezsnosci podczas wywolania.

import { createSignal } from 'solid-js';

// [getter, setter] — getter jest FUNKCJA, nie wartoscia
const [count, setCount] = createSignal(0);
const [name, setName] = createSignal('Anna');

// odczyt (subskrybuje aktualny kontekst reaktywny)
console.log(count());   // 0
console.log(name());    // "Anna"

// zapis
setCount(1);
setCount(prev => prev + 1);   // updater function
setName('Jan');

// w JSX — automatyczna subskrypcja
function Counter() {
  const [count, setCount] = createSignal(0);
  return (
    <button onClick={() => setCount(c => c + 1)}>
      Kliknieto: {count()}   {/* tylko ten fragment DOM sie aktualizuje */}
    </button>
  );
}
Kluczowa roznica od React useState: ustawianie tego samego sygnalu wielokrotnie nie powoduje wielu renderow. Solid batchuje aktualizacje automatycznie. Kompontent nigdy sie nie re-renderuje — tylko konkretny fragment DOM.

4. Computed — createMemo()

createMemo tworzy obliczona wartosc, ktora automatycznie aktualizuje sie gdy jej zaleznosci (sygnaly) ulegna zmianie. Lazy — obliczany tylko gdy ktos go odczytuje. Cachowany — wielokrotne odczyty bez zmiany wejsc nie przeliczaja wartosci.

import { createSignal, createMemo } from 'solid-js';

const [firstName, setFirstName] = createSignal('Jan');
const [lastName, setLastName] = createSignal('Kowalski');

// memo jest obliczany tylko gdy firstName lub lastName sie zmieni
const fullName = createMemo(() => `${firstName()} ${lastName()}`);

// wielokrotne odczyty — obliczane raz
console.log(fullName());  // "Jan Kowalski"
console.log(fullName());  // "Jan Kowalski" — z cache, bez przeliczania

setFirstName('Adam');
console.log(fullName());  // "Adam Kowalski" — przeliczone po zmianie

// memo z wartoscia poczatkowa (przydatne dla typow)
const doubled = createMemo<number>((prev = 0) => {
  const n = count();
  return prev + n;
});

5. Effects — createEffect, onMount, onCleanup

createEffect uruchamia side effecty gdy reaktywne zaleznosci sie zmienia. Automatycznie slucha sygnali odczytywanych wewnatrz.

import { createSignal, createEffect, onMount, onCleanup } from 'solid-js';

const [query, setQuery] = createSignal('');

// effect uruchamia sie po kazdej zmianie query()
createEffect(() => {
  console.log('Szukam:', query());
  // cleanup poprzedniej operacji
  const timer = setTimeout(() => fetchResults(query()), 300);
  onCleanup(() => clearTimeout(timer));
});

// onMount — odpowiednik useEffect(fn, []) w React
function MyComponent() {
  onMount(() => {
    console.log('Komponent zamontowany');
    const unsub = subscribe();
    onCleanup(unsub);   // cleanup przy odmontowaniu
  });
  return <div>...</div>;
}

// createEffect z poprzednia wartoscia
createEffect<string>(prev => {
  const current = name();
  console.log(`Zmiana z "${prev}" na "${current}"`);
  return current;  // staje sie prev w nastepnym wywolaniu
}, 'poczatkowa');

6. Components — JSX, props przez Proxy

Komponenty SolidJS to zwykle funkcje zwracajace JSX. Kluczowa roznica: sa wywolywane raz podczas montowania. Props sa dostepne przez reaktywny Proxy — odczyt props.value wewnatrz reaktywnego kontekstu automatycznie subskrybuje sie do zmiany.

import { createSignal, mergeProps, splitProps } from 'solid-js';

// component wywolywany RAZ — nie re-renderuje sie
function Greeting(props) {
  // NIE destrukturyzuj props poza reactive context!
  // const { name } = props;  // ZLE — utrata reaktywnosci
  return <div>Czesc, {props.name}!</div>;  // OK
}

// mergeProps — domyslne wartosci
function Button(props) {
  const merged = mergeProps({ type: 'button', disabled: false }, props);
  return <button type={merged.type} disabled={merged.disabled}>{merged.children}</button>;
}

// splitProps — rozdzielenie na "własne" i "przekazywane dalej"
function StyledInput(props) {
  const [local, rest] = splitProps(props, ['class', 'style']);
  return <input class={`input ${local.class}`} style={local.style} {...rest} />;
}

// typowanie TypeScript
interface CounterProps {
  initialValue?: number;
  onIncrement?: (value: number) => void;
}

function Counter(props: CounterProps) {
  const [count, setCount] = createSignal(props.initialValue ?? 0);
  return (
    <button onClick={() => {
      setCount(c => c + 1);
      props.onIncrement?.(count());
    }}>{count()}</button>
  );
}

7. Control Flow — Show, For, Switch, Suspense

SolidJS dostarcza reaktywne komponenty do sterowania przeplywem — sa wydajniejsze niz zwykle wyrazenia warunkowe w JSX, bo optymalizuja re-rendering.

import { Show, For, Switch, Match, Suspense, ErrorBoundary } from 'solid-js';

// Show — warunkowe renderowanie z opcjonalnym fallback
<Show when={isLoggedIn()} fallback={<LoginButton />}>
  <Dashboard />
</Show>

// For — iteracja po tablicy (efektywna — minimalne aktualizacje DOM)
<For each={items()} fallback={<p>Brak elementow</p>}>
  {(item, index) => (
    <li>{index() + 1}. {item.name}</li>
  )}
</For>

// Switch / Match
<Switch fallback={<p>Nieznany status</p>}>
  <Match when={status() === 'loading'}><Spinner /></Match>
  <Match when={status() === 'error'}><ErrorMsg /></Match>
  <Match when={status() === 'success'}><Data /></Match>
</Switch>

// Suspense — lazy loading z fallback
<Suspense fallback={<Spinner />}>
  <LazyComponent />
</Suspense>

// ErrorBoundary
<ErrorBoundary fallback={(err, reset) => (
  <div>Blad: {err.message} <button onClick={reset}>Sprobuj ponownie</button></div>
)}>
  <RiskyComponent />
</ErrorBoundary>

8. Stores — createStore, produce()

createStore tworzy zagniezdzone reaktywne obiekty. W odrozneniu od sygnalu, store pozwala na granularne subskrypcje do poszczegolnych pol, nawet gleboko zagniezdonych.

import { createStore, produce, reconcile } from 'solid-js/store';

interface Todo {
  id: number;
  text: string;
  done: boolean;
}

interface State {
  todos: Todo[];
  filter: 'all' | 'done' | 'pending';
}

const [state, setState] = createStore<State>({
  todos: [],
  filter: 'all'
});

// proste ustawianie pola
setState('filter', 'done');

// sciezka do zagniezdzonego pola
setState('todos', 0, 'done', true);

// funkcja — immer-like mutations
setState(produce(state => {
  state.todos.push({ id: Date.now(), text: 'Nowe zadanie', done: false });
}));

// filtrowanie przez funktor
setState('todos', todo => !todo.done, 'text', t => t.toUpperCase());

// reconcile — pelna podmiana danych (np. z API) z minimalnymi aktualizacjami DOM
const data = await fetchTodos();
setState('todos', reconcile(data));

// odczyt w komponencie (fine-grained — tylko ten todo sie aktualizuje)
<For each={state.todos}>
  {todo => <li class:done={todo.done}>{todo.text}</li>}
</For>

9. SolidStart — meta-framework

SolidStart to oficjalny meta-framework dla SolidJS (jak Next.js dla React). Dostarcza routing oparty na plikach, server functions, SSR, SSG i streaming.

# instalacja
npm create solid@latest -- --template with-router
# lub
npm create solid@latest  # wybierz "SolidStart"

# struktura projektu
src/
  routes/
    index.tsx          # /
    about.tsx          # /about
    blog/
      [slug].tsx       # /blog/:slug
      index.tsx        # /blog
  app.tsx              # root layout

Server Functions

SolidStart umozliwia definiowanie funkcji serwerowych bezposrednio obok kodu klienta. Sa kompilowane i wykonywane wylacznie na serwerze — nie trafiaja do bundle klienta.

// server function — uruchamiana tylko na serwerze
"use server";
import { query, action } from '@solidjs/router';

// query — cachowane zapytanie (GET semantics)
const getUser = query(async (id: string) => {
  const user = await db.users.findById(id);
  return user;
}, 'user');

// action — mutacja (POST semantics)
const createPost = action(async (formData: FormData) => {
  const title = formData.get('title') as string;
  await db.posts.create({ title });
  return redirect('/posts');
});

// w komponencie
function UserProfile({ id }: { id: string }) {
  const user = createAsync(() => getUser(id));
  return <Show when={user()}>{u => <h1>{u.name}</h1>}</Show>;
}

Kompletny przyklad: Lista Zadan

import { createSignal, createMemo, For, Show } from 'solid-js';
import { createStore, produce } from 'solid-js/store';

interface Todo { id: number; text: string; done: boolean; }

function TodoApp() {
  const [input, setInput] = createSignal('');
  const [todos, setTodos] = createStore<Todo[]>([]);

  const remaining = createMemo(() => todos.filter(t => !t.done).length);

  const addTodo = () => {
    const text = input().trim();
    if (!text) return;
    setTodos(produce(t => t.push({ id: Date.now(), text, done: false })));
    setInput('');
  };

  const toggle = (id: number) =>
    setTodos(t => t.id === id, 'done', d => !d);

  const removeDone = () =>
    setTodos(todos.filter(t => !t.done));

  return (
    <div>
      <h2>Zadania ({remaining()} pozostalo)</h2>
      <input
        value={input()}
        onInput={e => setInput(e.target.value)}
        onKeyDown={e => e.key === 'Enter' && addTodo()}
        placeholder="Nowe zadanie..."
      />
      <button onClick={addTodo}>Dodaj</button>
      <For each={todos} fallback={<p>Brak zadan</p>}>
        {todo => (
          <div>
            <input type="checkbox" checked={todo.done}
              onChange={() => toggle(todo.id)} />
            <span style={{ 'text-decoration': todo.done ? 'line-through' : 'none' }}>
              {todo.text}
            </span>
          </div>
        )}
      </For>
      <Show when={todos.some(t => t.done)}>
        <button onClick={removeDone}>Usun ukonczone</button>
      </Show>
    </div>
  );
}
