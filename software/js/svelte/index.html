Svelte 5 / SvelteKit

Compile-time framework. Runes reactive primitives. Najmniejsze bundles w 2026.

1. Co to Svelte

Svelte to framework UI, ktory kompiluje sie do vanilla JavaScript w czasie budowania. Nie ma runtime'u — kod wynikowy to czyste operacje DOM bez biblioteki pomocniczej. To oznacza minimalne rozmiary bundla i maksymalna wydajnosc uruchomieniowa.

Kluczowa roznica od React/Vue: React i Vue sa bibliotekami uruchamianymi w przegladarce — framework jest czescią bundla. Svelte jest kompilatorem — "znika" po kompilacji, zostawia tylko Twoj kod.
  • React/Vue: wysyla framework + Twoj kod → przeglądarka interpretuje oba
  • Svelte: kompiluje .svelte do zoptymalizowanego JS → przeglada interpretuje tylko Twoj kod
  • Svelte 4 i wczesniejsze: reaktywnosc przez specjalne oznaczenia kompilatora ($: labels)
  • Svelte 5 (2024+): reaktywnosc przez Runes — nowe API oparte na sygnalach

2. Instalacja — SvelteKit

Zalecany sposob to SvelteKit — oficjalny meta-framework analogiczny do Next.js:

# nowy projekt SvelteKit
npm create svelte@latest moja-aplikacja
# opcje: Skeleton / Demo app / Library
# TypeScript: Yes (zalecane)
# Prettier + ESLint: Yes

cd moja-aplikacja
npm install
npm run dev

# standalone Svelte (bez SvelteKit, przez Vite)
npm create vite@latest moja-app -- --template svelte-ts
Wymagania: Node 18+. SvelteKit uzywa Vite wewnetrznie — masz HMR, TypeScript, CSS preprocessory out of the box. 
# dodanie do istniejacego projektu Vite
npm install -D svelte @sveltejs/vite-plugin-svelte

# vite.config.ts
import { svelte } from '@sveltejs/vite-plugin-svelte';
export default { plugins: [svelte()] };

3. Svelte 5 Runes — $state, $derived, $effect, $props

Runes to nowe API reaktywnosci w Svelte 5. Sa to symbole kompilatora — wyglądają jak wywolania funkcji, ale sa transformowane w czasie kompilacji do zoptymalizowanego kodu reaktywnego.

<script lang="ts">
  // $state — reaktywna zmienna (zastepuje stary "let" z reaktywnoscia)
  let count = $state(0);
  let name = $state('Swiat');
  let items = $state<string[]>([]);

  // $derived — obliczona wartosc (zastepuje $: label)
  let doubled = $derived(count * 2);
  let greeting = $derived(`Czesc, ${name}!`);
  let itemCount = $derived(items.length);

  // $derived.by — dla bardziej zlozonych obliczen
  let stats = $derived.by(() => ({
    total: items.length,
    long: items.filter(i => i.length > 5).length
  }));

  // $effect — side effecty (zastepuje onMount + reactive statements)
  $effect(() => {
    console.log('count zmieniony na:', count);
    // cleanup — zwroc funkcje
    return () => console.log('cleanup');
  });

  // $effect.pre — uruchamiany PRZED aktualizacja DOM
  $effect.pre(() => {
    console.log('przed renderem, count =', count);
  });

  // $props — deklaracja propsow komponentu
  let { title, description = 'brak opisu', onClose }: {
    title: string;
    description?: string;
    onClose?: () => void;
  } = $props();
</script>
Svelte 4 vs Svelte 5: Svelte 4 uzywal $: doubled = count * 2 (magiczny label JS). Svelte 5 uzywa $derived(count * 2) — bardziej explicite, latwiejsze do statycznej analizy i refaktoryzacji.

4. Struktura pliku .svelte

Kazdy plik .svelte to self-contained komponent z trzema sekcjami: script, template i style. Style sa automatycznie scoped do komponentu.

<!-- MyCard.svelte -->
<script lang="ts">
  let { title, body, variant = 'default' } = $props<{
    title: string;
    body: string;
    variant?: 'default' | 'warning' | 'success';
  }>();

  let isExpanded = $state(false);
  let charCount = $derived(body.length);
</script>

<!-- template — HTML z Svelte directives -->
<article class="card {variant}" class:expanded={isExpanded}>
  <h3>{title}</h3>
  <p>{body}</p>
  <small>{charCount} znakow</small>
  <button onclick={() => isExpanded = !isExpanded}>
    {isExpanded ? 'Zwiń' : 'Rozwiń'}
  </button>
</article>

<!-- style — automatycznie scoped, nie wyciekaja do rodzica -->
<style>
  .card { border: 1px solid #ccc; padding: 16px; border-radius: 8px; }
  .card.warning { border-color: orange; }
  .card.success { border-color: green; }
  /* :global(...) — jesli potrzeba wyjs ze scope */
  :global(.external-class) { color: red; }
</style>

5. Reaktywnosc — $state vs stary model Svelte 4

CechaSvelte 4 (stary)Svelte 5 Runes

Computed$: doubled = count * 2let doubled = $derived(count * 2)
Side effect$: console.log(count)$effect(() => { console.log(count) })

Storewritable(), readable(), derived()Rzadko potrzebne (runes zastepuja)

Runes dzialaja rowniez w plikach .svelte.ts / .svelte.js — mozna ekstrahorac logike do zewnetrznych plikow zachowujac reaktywnosc.

// counter.svelte.ts — reaktywna logika poza komponentem
export function createCounter(initial = 0) {
  let count = $state(initial);
  let doubled = $derived(count * 2);

  return {
    get count() { return count; },
    get doubled() { return doubled; },
    increment: () => count++,
    reset: () => count = initial
  };
}

6. Events i binding

Svelte 5 zmienil skladnie event handlerów — z on:click na onclick (zwykly atrybut HTML). Bindingi dwukierunkowe nadal dzialaja przez bind:.

<script lang="ts">
  let value = $state('');
  let checked = $state(false);
  let selected = $state('option1');
  let inputRef = $state<HTMLInputElement | null>(null);
</script>

<!-- Svelte 5: onclick zamiast on:click -->
<button onclick={() => console.log('klik')}>Kliknij</button>
<button onmouseenter={handleHover} onmouseleave={handleLeave}>Hover</button>

<!-- Binding dwukierunkowy -->
<input bind:value type="text" />
<input bind:checked type="checkbox" />
<select bind:value={selected}>
  <option value="option1">Opcja 1</option>
  <option value="option2">Opcja 2</option>
</select>

<!-- bind:this — referencja do elementu DOM -->
<input bind:this={inputRef} />
<button onclick={() => inputRef?.focus()}>Focus</button>

<!-- Svelte 4 way (nadal dziala) -->
<button on:click={handler}>Stary sposob</button>

7. Components — props, slots, snippets

Svelte 5 wprowadzil snippets jako nastepce slotow. Snippets sa bardziej elastyczne — mozna je przekazywac jako propsy i uzywac w wielu miejscach.

<!-- Card.svelte — komponent z snippetem -->
<script lang="ts">
  import type { Snippet } from 'svelte';
  let { title, children, footer }: {
    title: string;
    children: Snippet;
    footer?: Snippet<[{ close: () => void }]>;
  } = $props();

  let isOpen = $state(true);
</script>

<div class="card">
  <h3>{title}</h3>
  <div class="body">
    {@render children()}
  </div>
  {#if footer}
    {@render footer({ close: () => isOpen = false })}
  {/if}
</div>

<!-- uzycie -->
<Card title="Moja karta">
  <p>Zawartosc karty</p>
  {#snippet footer({ close })}
    <button onclick={close}>Zamknij</button>
  {/snippet}
</Card>

8. SvelteKit — routing oparty na plikach

SvelteKit uzywa systemu routingu opartego na strukturze katalogu src/routes/. Specjalne pliki definiuja roznymi aspekty trasy.

src/routes/
  +page.svelte        # strona (UI)
  +page.ts            # load function (dane dla strony)
  +layout.svelte      # layout wspolny dla dzieci
  +layout.ts          # load function dla layoutu
  +error.svelte       # strona bledu
  +server.ts          # API endpoint (GET, POST, PUT, DELETE)
  blog/
    +page.svelte      # /blog
    [slug]/
      +page.svelte    # /blog/:slug
      +page.ts        # load dla /blog/:slug
// src/routes/blog/[slug]/+page.ts
import type { PageLoad } from './$types';
import { error } from '@sveltejs/kit';

// load function — uruchamiana na serwerze (SSR) i/lub kliencie
export const load: PageLoad = async ({ params, fetch }) => {
  const res = await fetch(`/api/posts/${params.slug}`);
  if (!res.ok) error(404, 'Post nie znaleziony');

  const post = await res.json();
  return { post };   // dostepne jako data.post w +page.svelte
};

// src/routes/blog/[slug]/+page.svelte
<script lang="ts">
  import type { PageData } from './$types';
  let { data }: { data: PageData } = $props();
</script>

<h1>{data.post.title}</h1>
<article>{@html data.post.content}</article>
// src/routes/contact/+server.ts — API endpoint

Kompletny przyklad: SvelteKit Form Action

// src/routes/register/+page.server.ts
import { fail, redirect } from '@sveltejs/kit';
import type { Actions, PageServerLoad } from './$types';
import { z } from 'zod';

const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8)
});

export const load: PageServerLoad = async ({ locals }) => {
  if (locals.user) redirect(302, '/dashboard');
  return {};
};

export const actions: Actions = {
  default: async ({ request }) => {
    const formData = await request.formData();
    const parsed = schema.safeParse({
      email: formData.get('email'),
      password: formData.get('password')
    });

    if (!parsed.success) {
      return fail(400, {
        errors: parsed.error.flatten().fieldErrors,
        email: formData.get('email')
      });
    }

    await createUser(parsed.data);
    redirect(303, '/dashboard');
  }
};

// src/routes/register/+page.svelte
<script lang="ts">
  import { enhance } from '$app/forms';
  import type { ActionData } from './$types';
  let { form }: { form: ActionData } = $props();
</script>

<form method="POST" use:enhance>
  <input name="email" value={form?.email ?? ''} />
  {#if form?.errors?.email}
    <span class="error">{form.errors.email[0]}</span>
  {/if}
  <input name="password" type="password" />
  <button type="submit">Zarejestruj</button>
</form>
