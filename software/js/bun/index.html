Bun

JavaScript runtime + bundler + test runner + package manager. Zig-based. v1.x stable.

1. Co to Bun

Bun to kompleksowe narzedzie do JavaScript/TypeScript stworzone przez Jarveda Sumuna i wydane jako v1.0 stabilne we wrzesniu 2023. Napisane w jezyku Zig i zbudowane na silniku JavaScriptCore (WebKit), a nie V8 jak Node.js i Deno.

Bun rozwiazuje jeden z glownych problemow ekosystemu JS — fragmentacje narzedzi. Zamiast instalowac oddzielnie: Node.js + npm/yarn/pnpm + webpack/esbuild + Jest/Vitest, Bun dostarcza wszystko jako jeden, blazyko-szybki plik binarny.

Cztery role Bun w jednym narzedziu

  • Runtime JavaScript — wykonuje pliki .js, .ts, .jsx, .tsx bez transpilacji
  • Package manager — zastepuje npm/yarn/pnpm (bun install, bun add, bun remove)
  • Bundler — zastepuje webpack/esbuild/rollup (bun build)
  • Test runner — zastepuje Jest/Vitest (bun test)
Dlaczego Zig? Zig to jezyk systemowy (jak C/C++/Rust) oferujacy precyzyjna kontrole nad pamiecia bez garbage collectora. Dzieki temu Bun moze osiagac ekstremalnie niskie czasy startowania i wysokie throughput w operacjach I/O.

2. Instalacja

# Linux / macOS
curl -fsSL https://bun.sh/install | bash

# Windows (PowerShell — wymaga Windows 10+)
powershell -c "irm bun.sh/install.ps1 | iex"

# Przez npm (jesli masz juz Node.js)
npm install -g bun

# Sprawdzenie wersji
bun --version

# Aktualizacja
bun upgrade

# Inicjalizacja nowego projektu
bun init

# Inicjalizacja z package.json (bez promptow)
bun init -y

3. Bun jako runtime

Bun wykonuje TypeScript i JSX natywnie — bez zadnej konfiguracji, bez tsc, bez babel. Pliki sa transpilowane w locie dzieki wbudowanemu transpilerowi napisanemu w Zig.

# Uruchomienie pliku TypeScript bezposrednio
bun run server.ts
bun run app.tsx

# Bun rozumie shebang — skrypty mozna uruchamiac bezposrednio
#!/usr/bin/env bun
console.log('Hello from Bun!');

# chmod +x script.ts && ./script.ts

# Zmienne srodowiskowe z .env
bun run --env-file=.env.local server.ts

# Watch mode (restart po zmianach)
bun --watch run server.ts

# Hot reload (bez restartu — zachowuje stan)
bun --hot run server.ts

# Uruchamianie skryptow z package.json
bun run dev
bun run build
bun run test

# Skrot: bun dev = bun run dev
bun dev

Kompatybilnosc z Node.js

Bun implementuje wiekszosc API Node.js: fs, path, http, crypto, stream, Buffer, process, __dirname, __filename. Wiekszosc pakietow npm dziala bez modyfikacji.

4. Bun jako package manager

Bun install jest wielokrotnie szybszy niz npm/yarn/pnpm dzieki trzem mechanizmom: globalnemu cache na dysku, symlinkom zamiast kopiowania plikow, oraz rownoleglem pobieraniu paczek.

# Instalacja wszystkich zaleznosci (czyta package.json)
bun install

# Dodawanie pakietow
bun add express
bun add -d typescript @types/express  # devDependency
bun add -g nodemon                    # globalnie

# Usuwanie
bun remove express

# Aktualizacja
bun update
bun update express        # konkretny pakiet

# Uruchamianie binariow z node_modules/.bin
bun x tsc --init          # odpowiednik npx

# Workspaces (monorepo)
# package.json:
# { "workspaces": ["packages/*"] }
bun install               # instaluje dla calego workspace

# Plik blokowania: bun.lockb (binarny, szybszy od package-lock.json)
# Wersja tekstowa do przegladu:
bun install --frozen-lockfile  # blad jesli lockfile nieaktualny

5. Bun.serve() — serwer HTTP

Bun.serve() to wbudowany, wysokowydajny serwer HTTP. W benchmarkach osiaga znacznie wyzszy throughput niz Node.js http.createServer() dzieki niskopozimowej implementacji w Zig.

// server.ts
const server = Bun.serve({
  port: 3000,
  hostname: '0.0.0.0',

  // Glowny handler — zwraca Response (Web API standard)
  fetch(request: Request): Response | Promise<Response> {
    const url = new URL(request.url);

    // Router reczny
    if (url.pathname === '/') {
      return new Response('Witaj w Bun!', {
        headers: { 'Content-Type': 'text/plain' }
      });
    }

    if (url.pathname === '/api/users' && request.method === 'GET') {
      const users = [
        { id: 1, name: 'Anna' },
        { id: 2, name: 'Piotr' }
      ];
      return Response.json(users);
    }

    if (url.pathname === '/api/echo' && request.method === 'POST') {
      return new Response(request.body, {
        headers: { 'Content-Type': request.headers.get('Content-Type') ?? 'text/plain' }
      });
    }

    return new Response('404 Not Found', { status: 404 });
  },

  // Obsluga bledow serwera
  error(error: Error) {
    console.error('Blad serwera:', error);
    return new Response('Blad wewnetrzny', { status: 500 });
  }
});

console.log(`Serwer dziala na http://localhost:${server.port}`);

// WebSocket wsparcie
const wsServer = Bun.serve({
  port: 3001,
  fetch(req, server) {
    if (server.upgrade(req)) return; // Upgrade do WebSocket
    return new Response('Uzyj WebSocket');
  },
  websocket: {
    open(ws) { console.log('Polaczono'); },
    message(ws, message) { ws.send(`Echo: ${message}`); },
    close(ws) { console.log('Rozlaczono'); }
  }
});

6. Bun build — bundler

Bun build to szybki bundler oparty na JavaScriptCore. Obsluguje TypeScript, JSX, tree shaking, code splitting i rozne formaty wyjsciowe.

# Bundlowanie dla przegladarki
bun build src/index.ts --outdir dist --target browser

# Bundlowanie dla Node.js / Bun
bun build src/server.ts --outdir dist --target node
bun build src/server.ts --outdir dist --target bun

# Minifikacja
bun build src/index.ts --outdir dist --minify

# Code splitting (wiele entry pointow)
bun build src/index.ts src/worker.ts --outdir dist --splitting

# Watch mode
bun build src/index.ts --outdir dist --watch

// Programowe API
const result = await Bun.build({
  entrypoints: ['./src/index.ts'],
  outdir: './dist',
  target: 'browser',
  format: 'esm',
  minify: {
    whitespace: true,
    identifiers: true,
    syntax: true
  },
  splitting: true,
  sourcemap: 'external',
  define: {
    'process.env.NODE_ENV': '"production"'
  },
  plugins: [myBunPlugin]
});

if (!result.success) {
  console.error('Bledy buildu:', result.logs);
}

7. Bun test — framework testowy

Bun test jest kompatybilny z API Jest — mozna migrować testy bez zmian lub z minimalnymi zmianami. Jest znacznie szybszy od Jest dzieki natywnej implementacji.

// math.test.ts
import { describe, it, expect, beforeEach, mock, spyOn } from 'bun:test';

// Testowana funkcja
function add(a: number, b: number): number { return a + b; }
async function fetchUser(id: number) {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}

describe('Funkcje matematyczne', () => {
  it('dodaje dwie liczby', () => {
    expect(add(2, 3)).toBe(5);
    expect(add(-1, 1)).toBe(0);
  });

  it('zwraca liczbe', () => {
    expect(add(1, 2)).toBeNumber();
  });
});

describe('API calls', () => {
  it('pobiera uzytkownika', async () => {
    // Mock globalny fetch
    global.fetch = mock(() =>
      Promise.resolve(new Response(JSON.stringify({ id: 1, name: 'Anna' })))
    );

    const user = await fetchUser(1);
    expect(user.name).toBe('Anna');
    expect(fetch).toHaveBeenCalledWith('/api/users/1');
  });
});

// Uruchamianie
// bun test
// bun test --watch
// bun test src/math.test.ts
// bun test --coverage

8. Bun Shell

Bun Shell ($) to wbudowany, cross-platform interpreter polecen shellowych. Dziala tak samo na Linux, macOS i Windows — eliminuje potrzebe sh/bash dla skryptow.

import { $ } from 'bun';

// Proste polecenia
await $`echo "Witaj z Bun Shell!"`;
await $`ls -la`;

// Interpolacja zmiennych (bezpieczna — automatyczne escapowanie)
const filename = 'moj plik.txt';
await $`cat ${filename}`;    // bezpieczne, nawet ze spacjami

// Przechwytywanie wyjscia
const output = await $`git log --oneline -5`.text();
console.log(output);

// Jako JSON
const packageJson = await $`cat package.json`.json();
console.log(packageJson.version);

// Laczenie polecen
await $`cat package.json | head -5`;

// Zmienne srodowiskowe
await $`DATABASE_URL=${process.env.DATABASE_URL} node migrate.js`;

// Katalog roboczy
await $`ls`.cwd('/tmp');

// Obsluga bledow (domyslnie throw jesli exit code != 0)
try {
  await $`false`;
} catch (err) {
  console.log('Exit code:', err.exitCode);
}

// Wyciszenie bledow
await $`rm -f plik.txt`.nothrow();

9. Kompatybilnosc z Node.js

Co dziala w Bun

  • Wiekszosc pakietow npm (Express, Fastify, Prisma, drizzle-orm, etc.)
  • CommonJS (require) i ESM (import) — oba formaty
  • Modul node:fs, node:path, node:crypto, node:stream
  • Buffer, process, __dirname, __filename
  • Web APIs: fetch, Request, Response, FormData, WebSocket

Co moze nie dzialac lub byc inne

  • Niektore natywne addony (.node pliki) — czesc dziala, czesc nie
  • node:cluster — ograniczone wsparcie
  • Niektoré edge case'y V8-specific w bibliotekach niskopoziomowych
  • Stare pakiety CJS bez aktualizacji od lat

Kiedy wybrac Bun: skrypty CLI wymagajace szybkiego startu, projekty gdzie szybkosc instalacji zaleznosci ma znaczenie (CI/CD), nowe projekty serwerowe bez dziedzictwa Node.js, gdy chcesz jednego narzedzia zamiast wielu.
