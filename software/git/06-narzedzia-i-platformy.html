Klienty GUI

Mimo ze CLI jest najpotezniejszym sposobem pracy z Gitem, narzedzia graficzne ulatwiaja wizualizacje historii, rozwiazywanie konfliktow i staging interakcyjny. Sa szczegolnie przydatne dla osob zaczynajacych z Gitem oraz przy zlozonych operacjach jak interactive rebase.

GitHub Desktop

GitHub Desktop to darmowy klient od GitHub, dostepny dla Windows i macOS (brak oficjalnej wersji Linux). Idealny dla osob pracujacych glownie z GitHub.

CechaOpis
CenaCalkowicie darmowy, open source (MIT)
PlatformyWindows, macOS (Linux przez fork shiftkey)
Mocne stronyProsty UI, integracja z GitHub PR/Issues, Pull Request review w aplikacji
SlabosciBrak wsparcia dla submodulow, ograniczone do GitHub-style workflow
Idealny dlaPoczatkujacy, projekty na GitHub, quick contributions

Sourcetree

Sourcetree od Atlassian - darmowy klient z bardzo szczegolowa wizualizacja grafu commitow. Wspiera Git i Mercurial.

# Najwazniejsze funkcje Sourcetree:
# - Wizualny graf rozgalezien (najlepszy w klasie)
# - Interactive rebase z drag-and-drop
# - Git Flow integration (przyciski dla feature/release/hotfix)
# - Wbudowany terminal
# - Bookmarks dla repo
# - Wsparcie dla submodulow

# Mocne strony: bardzo dobry przy GitFlow, doskonaly dla Bitbucket
# Slabosci: brak wersji Linux, czasem wolny przy duzych repo
# Cena: darmowy, wymaga konta Atlassian

Narzedzia CLI

Power-user'zy czesto preferuja terminal nad GUI - jest szybszy, skryptowalny i dziala w SSH. Te narzedzia dodaja warstwy funkcjonalnosci ponad standardowy git.

gh - GitHub CLI

Oficjalne CLI od GitHub, omowione szczegolowo w rozdziale o zdalnych repozytoriach. Pozwala zarzadzac issues, PRs, releases i workflow Actions z terminala.

# Instalacja
sudo apt install gh
brew install gh
winget install GitHub.cli

# Najczesciej uzywane komendy
gh repo clone owner/repo
gh pr create
gh pr checkout 123
gh pr review --approve
gh issue list --label bug
gh release create v1.0.0
gh workflow run deploy.yml

glab - GitLab CLI

glab to oficjalne CLI dla GitLab, podobne w filozofii do gh.

# Instalacja
sudo apt install glab
brew install glab

# Logowanie
glab auth login

# Komendy podobne do gh
glab repo clone owner/repo
glab mr create -t "Title" -d "Description"
glab mr checkout 42
glab issue list
glab pipeline status
glab release create v1.0.0

lazygit - TUI dla Git

lazygit to terminal UI (TUI) napisany w Go. Pozwala wykonac wiekszosc operacji Git bez opuszczania terminala, z piekym interfejsem nawigowanym klawiatura.

# Instalacja
sudo apt install lazygit
brew install lazygit
go install github.com/jesseduffield/lazygit@latest

# Uruchomienie w katalogu repo
lazygit

# Najwazniejsze klawisze:
# h/j/k/l - nawigacja
# space   - stage/unstage plik
# c       - commit
# P       - push
# p       - pull
# b       - branche
# m       - menu
# q       - quit
# ?       - pomoc

# Funkcje:
# - Interactive rebase z drag-and-drop
# - Cherry-pick z visualnego selektora
# - Stash management
# - Log z grafem
# - Diff viewer
# - Konflikty rozwiazywane bezposrednio
# - Custom commands (definiowalne)

tig - Text mode interface for Git

tig to klasyczny TUI dla Git, lekki i szybki. Doskonale do przegladania historii, blame, statusu.

# Instalacja
sudo apt install tig
brew install tig

# Uruchomienie - rozne widoki:
tig                  # main view (history)
tig status           # jak git status, ale interactive
tig blame file.js    # interactive blame
tig log              # log
tig refs             # branche i tagi
tig stash            # stashed changes

# W aplikacji:
# Enter - szczegoly commita
# d     - diff
# /     - search
# t     - tree view
# u     - status changes
# q     - back/quit

delta - lepsze diffy

delta to syntax-highlighter dla diffow Git. Zastepuje brzydki domyslny output kolorowymi, czytelnymi diffami z liniami numerow.

# Instalacja
sudo apt install git-delta
brew install git-delta

# Konfiguracja w ~/.gitconfig
[core]
    pager = delta

[interactive]
    diffFilter = delta --color-only

[delta]
    navigate = true        # n / N do nastepnego/poprzedniego pliku
    light = false          # ciemny motyw
    side-by-side = true    # diff obok siebie
    line-numbers = true
    syntax-theme = Monokai Extended

[merge]
    conflictstyle = diff3

Self-hosted git platforms

Wlasny serwer git daje pelna kontrole nad danymi i zerowe miesieczne koszty (poza infrastruktura). Idealne dla firm wrazliwych na compliance i prywatnosci.

Gitea

Gitea to lekki self-hosted Git server napisany w Go. Bardzo male wymagania (1 CPU, 512MB RAM wystarczy). Interfejs przypominajacy GitHub.

# Instalacja przez Docker
docker run -d --name=gitea \
  -p 3000:3000 \
  -p 222:22 \
  -v /opt/gitea:/data \
  --restart=always \
  gitea/gitea:latest

# Dostep przez http://serwer:3000

# docker-compose.yml dla pelnej konfiguracji
version: "3"
services:
  gitea:
    image: gitea/gitea:latest
    container_name: gitea
    environment:
      - USER_UID=1000
      - USER_GID=1000
      - GITEA__database__DB_TYPE=postgres
      - GITEA__database__HOST=db:5432
      - GITEA__database__NAME=gitea
      - GITEA__database__USER=gitea
      - GITEA__database__PASSWD=gitea
    restart: always
    volumes:
      - ./gitea:/data
    ports:
      - "3000:3000"
      - "222:22"
    depends_on:
      - db

  db:
    image: postgres:16
    restart: always
    environment:
      - POSTGRES_USER=gitea
      - POSTGRES_PASSWORD=gitea
      - POSTGRES_DB=gitea
    volumes:
      - ./postgres:/var/lib/postgresql/data

Forgejo

Forgejo to community-driven fork Gitea, hostowany przez Codeberg e.V. Powstaly po komercjalizacji Gitea (2022). Ma identyczny API i konfiguracje co Gitea, ale skupia sie na FOSS i community.

# Instalacja podobna do Gitea
docker run -d --name=forgejo \
  -p 3000:3000 \
  -p 222:22 \
  -v /opt/forgejo:/data \
  --restart=always \
  codeberg.org/forgejo/forgejo:7

# Migracja z Gitea jest trywialna - kompatybilne dane

GitLab CE (Community Edition)

Pelnowartosciowa wersja GitLab self-hosted - wszystkie podstawowe funkcje + CI/CD + container registry za darmo.

# Instalacja Omnibus (zalecana)
sudo apt install curl openssh-server ca-certificates tzdata perl
curl https://packages.gitlab.com/install/repositories/gitlab/gitlab-ee/script.deb.sh | sudo bash
sudo EXTERNAL_URL="https://gitlab.example.com" apt install gitlab-ce

# Pierwsze uruchomienie - reset hasla root
sudo gitlab-rake "gitlab:password:reset[root]"

# Wymagania: 4GB RAM minimum, 8GB zalecane
# Backup
sudo gitlab-backup create
# Restore
sudo gitlab-backup restore BACKUP=timestamp

VS Code i GitLens

Visual Studio Code ma najlepszy IDE-side support dla Git. Sam edytor pokazuje zmiany w gutterach, status w drzewie plikow i panelu Source Control. GitLens to extension, ktory dodaje supermoce.

GitLens features

# Instalacja w VS Code
code --install-extension eamodio.gitlens

# Co dodaje:
# - Inline blame przy kazdej linii (kto i kiedy)
# - File history (klik na plik -> historia zmian)
# - Line history (klik na linie -> historia tej linii)
# - Compare branches/files visually
# - Repository view z grafem
# - Pull request integration (GitHub, GitLab)
# - Keyboard shortcuts dla wszystkich operacji

# Najczestsze keyboard shortcuts:
# Ctrl+Shift+G G  - Source Control panel
# Alt+B           - blame current line
# Ctrl+Shift+P -> "GitLens: ..." - wszystkie komendy

# Konfiguracja w settings.json:
"gitlens.codeLens.enabled": true,
"gitlens.currentLine.enabled": true,
"gitlens.hovers.enabled": true,
"gitlens.statusBar.enabled": true

Inne przydatne VS Code extensions dla Git

  • Git Graph - wizualny graf historii w panelu
  • Git History - historia plikow i porownywanie
  • GitHub Pull Requests and Issues - oficjalne od Microsoft
  • GitLab Workflow - integracja z GitLab
  • Conventional Commits - prompty dla Conventional Commits
  • Git Blame - prosty blame inline

Konfiguracja globalna

# ~/.gitconfig - zalecana konfiguracja

[user]
    name = Imie Nazwisko
    email = kontakt@i4n.pl
    signingkey = YOUR_GPG_KEY_ID

[init]
    defaultBranch = main

[core]
    editor = code --wait
    autocrlf = input          # Linux/macOS
    # autocrlf = true         # Windows
    pager = delta

[pull]
    rebase = true             # rebase zamiast merge przy pull
    ff = only                 # tylko fast-forward, inaczej blad

[push]
    default = current
    autoSetupRemote = true    # auto -u przy pierwszym push
    followTags = true         # auto-push tagow

[fetch]
    prune = true              # auto-cleanup zdalnych galezi

[rebase]
    autosquash = true
    autostash = true          # auto-stash przed rebase

[commit]
    gpgsign = true            # GPG signing zawsze

[diff]
    algorithm = histogram     # lepszy algorytm diff

[merge]
    conflictstyle = diff3     # 3-way conflict markers

[alias]
    s = status -s
    co = checkout
    br = branch
    ci = commit
    last = log -1 HEAD
    visual = !gitk
    lol = log --graph --decorate --pretty=oneline --abbrev-commit
    lola = log --graph --decorate --pretty=oneline --abbrev-commit --all
    unstage = reset HEAD --
    amend = commit --amend --no-edit
