React 19 — nowoczesne features

Server Components, Server Actions, useOptimistic, use() hook i React Compiler

Co nowego w React 19?

React 19 to najwieksza zmiana paradygmatu od czasu Hookow. Najwazniejsze obszary:

  • React Server Components (RSC) — komponenty renderowane na serwerze, zero JS u klienta
  • Server Actions — funkcje serwerowe wywolywane z UI bez API endpointow
  • Nowe hooki — useFormStatus, useOptimistic, useActionState, use()
  • Asset i Document Metadata API — standardowy sposob na <title>, <meta>, preload
  • ref jako prop — koniec z forwardRef
  • React Compiler — automatyczna memoizacja (stable w 2026)

React Server Components (RSC)

RSC renderuja sie wylacznie na serwerze. Nie maja state, nie obsluguja eventow, nie sa wysylane do przegladarki jako JS — tylko ich opis. Dzieki temu bundle JS klienta jest mniejszy, a dane mozna pobierac bezposrednio (DB, fs, secret keys).

// app/page.jsx — Server Component (default w Next.js App Router)
import { db } from '@/lib/db';

export default async function Page() {
  const posts = await db.posts.findMany(); // direct DB access!

  return (
    <main>
      <h1>Posty</h1>
      {posts.map(p => <Post key={p.id} post={p} />)}
    </main>
  );
}

// app/components/Counter.jsx — Client Component (event handlers)
'use client';
import { useState } from 'react';

export default function Counter() {
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n + 1)}>Klikniecia: {n}</button>;
}

Server Actions

Funkcje oznaczone 'use server' wywolywane z formularzy lub przyciskow w client components. Eliminuja potrzebe pisania API endpointow.

// app/actions.js
'use server';

import { db } from '@/lib/db';
import { revalidatePath } from 'next/cache';

export async function createPost(formData) {
  const title = formData.get('title');
  const content = formData.get('content');
  await db.posts.create({ data: { title, content } });
  revalidatePath('/posts');
}

// app/posts/new/page.jsx — Server Component
import { createPost } from '@/app/actions';

export default function NewPost() {
  return (
    <form action={createPost}>
      <input name="title" required />
      <textarea name="content" required />
      <button type="submit">Utworz</button>
    </form>
  );
}

useFormStatus

Hook do statusu submitujacego sie formularza. Uzywany WEWNATRZ <form>.

'use client';
import { useFormStatus } from 'react-dom';

function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending}>
      {pending ? 'Wysylanie...' : 'Wyslij'}
    </button>
  );
}

// W form
<form action={createPost}>
  <input name="title" />
  <SubmitButton />
</form>

useActionState

Zarzadzanie state wyniku Server Action. Wczesniej znany jako useFormState.

'use client';
import { useActionState } from 'react';
import { login } from './actions';

const initial = { error: null, success: false };

export default function LoginForm() {
  const [state, formAction, isPending] = useActionState(login, initial);

  return (
    <form action={formAction}>
      <input name="email" type="email" required />
      <input name="password" type="password" required />
      {state.error && <p style={{color:'red'}}>{state.error}</p>}
      <button disabled={isPending}>{isPending ? 'Loguje...' : 'Zaloguj'}</button>
    </form>
  );
}

useOptimistic

Pokazanie optymistycznego state przed potwierdzeniem z serwera. Idealne dla like, follow, dodawania komentarzy.

'use client';
import { useOptimistic } from 'react';
import { sendMessage } from './actions';

export default function Chat({ messages }) {
  const [optimisticMessages, addOptimistic] = useOptimistic(
    messages,
    (state, newMessage) => [...state, { ...newMessage, sending: true }]
  );

  async function formAction(formData) {
    const text = formData.get('text');
    addOptimistic({ id: Date.now(), text });
    await sendMessage(text);
  }

  return (
    <>
      {optimisticMessages.map(m => (
        <p key={m.id} style={{ opacity: m.sending ? 0.5 : 1 }}>{m.text}</p>
      ))}
      <form action={formAction}>
        <input name="text" />
        <button>Wyslij</button>
      </form>
    </>
  );
}

use() hook

Specjalny hook ktory moze byc wywolany warunkowo. Czyta promise lub context. Z promise + Suspense daje czytelny data fetching.

// Server Component
import { Suspense } from 'react';

async function fetchUser(id) {
  const r = await fetch(`/api/users/${id}`);
  return r.json();
}

function UserDetails({ userPromise }) {
  const user = use(userPromise); // czeka na promise
  return <h2>{user.name}</h2>;
}

export default function Page({ params }) {
  const userPromise = fetchUser(params.id);
  return (
    <Suspense fallback={<p>Ladowanie...</p>}>
      <UserDetails userPromise={userPromise} />
    </Suspense>
  );
}

// use() z Context (jak useContext, ale moze byc warunkowo)
function Comp({ show }) {
  if (show) {
    const ctx = use(MyContext); // OK!
    return <p>{ctx.value}</p>;
  }
  return null;
}

}

Asset Loading API

Funkcje preload, preinit, preconnect z react-dom.

import { preload, preinit } from 'react-dom';

function App() {
  preload('/fonts/inter.woff2', { as: 'font', type: 'font/woff2', crossOrigin: '' });
  preinit('https://example.com/script.js', { as: 'script' });
  return ...;
}

ref jako prop — koniec forwardRef

W React 19 ref to zwykly prop. forwardRef nie jest juz potrzebny.

// Stary kod (React 18)
const Input = forwardRef(function Input(props, ref) {
  return <input ref={ref} {...props} />;
});

// React 19
function Input({ ref, ...props }) {
  return <input ref={ref} {...props} />;
}

// Uzycie identyczne
<Input ref={inputRef} />

React Compiler

React Compiler (build tool) automatycznie memoizuje komponenty i wartosci — eliminuje potrzebe recznego useMemo, useCallback, React.memo. Stable w 2026.

# Instalacja (Next.js 15)
npm i -D babel-plugin-react-compiler

// next.config.js
module.exports = {
  experimental: {
    reactCompiler: true,
  },
};

Korzysci z React Compilera

  • Mniej kodu — usuwasz wszystkie useMemo/useCallback
  • Lepsze performance — kompilator widzi caly graph i memoizuje optymalnie
  • Mniej pomylek — deweloper czesto memoizuje zle (pominiete deps)
  • Backward compatible — stary kod dziala
