Krajobraz w 2026

W 2026 dominuje Tailwind CSS. Trend "CSS-in-JS" (styled-components, Emotion) wyrazne upada — problemy z RSC, slabsza wydajnosc, wieksze bundle. Powraca vanilla CSS / CSS Modules oraz copy-paste components (shadcn/ui).

Tailwind CSS — #1

Tailwind to utility-first CSS framework. Zamiast pisac CSS, skladasz UI z gotowych klas (flex, p-4, bg-blue-500). Bundle CSS po purge to zwykle < 10 KB.

npm i -D tailwindcss postcss autoprefixer
npx tailwindcss init -p

// tailwind.config.js
module.exports = {
  content: ['./src/**/*.{js,ts,jsx,tsx}'],
  theme: {
    extend: {
      colors: { brand: '#06b6d4' },
    },
  },
  plugins: [],
};

// src/index.css
@tailwind base;
@tailwind components;
@tailwind utilities;
function Card({ title, children }) {
  return (
    <div className="bg-white dark:bg-slate-800 rounded-xl shadow-md p-6 hover:shadow-lg transition">
      <h3 className="text-xl font-semibold text-slate-900 dark:text-slate-100 mb-2">
        {title}
      </h3>
      <div className="text-slate-600 dark:text-slate-300">{children}</div>
    </div>
  );
}

Dlaczego Tailwind dominuje

  • Brak nazewnictwa klas — brak debat o BEM, brak konfliktow
  • Mocna IDE integration (autocomplete, prefiksy responsywne)
  • Konfiguracja design system w jednym pliku
  • Dziala z RSC bez problemu (zero JS, zero context)
  • Tailwind 4.0 (2025) — CSS-native config (zamiast JS), Oxide engine, 10x szybszy

CSS Modules

CSS Modules — lokalnie scoped CSS, klasy hashowane. Dziala out-of-the-box w Vite, Next.js.

/* Button.module.css */
.button { background: #06b6d4; color: white; padding: 8px 16px; }
.button:hover { background: #22d3ee; }
.large { font-size: 1.2rem; padding: 12px 24px; }

// Button.jsx
import styles from './Button.module.css';

export function Button({ size = 'normal', children }) {
  return (
    <button className={`${styles.button} ${size === 'large' ? styles.large : ''}`}>
      {children}
    </button>
  );
}

shadcn/ui — copy-paste komponenty

shadcn/ui to NIE biblioteka — to zestaw komponentow ktore kopiujesz do swojego projektu. Pod spodem Radix UI + Tailwind. Pelna kontrola, brak zaleznosci.

# Inicjalizacja
npx shadcn@latest init

# Dodanie komponentu (kopiuje do components/ui)
npx shadcn@latest add button dialog dropdown-menu

// components/ui/button.tsx (skopiowane do twojego repo)
// Mozesz zmodyfikowac dowolnie

import { Button } from '@/components/ui/button';

<Button variant="outline" size="lg">Klik</Button>

Radix UI

Radix UI dostarcza unstyled, accessible primitives (Dialog, Dropdown, Tooltip). Sam stylujesz. Ulubione partnerstwo z Tailwind. Podstawa shadcn/ui.

npm i @radix-ui/react-dialog

import * as Dialog from '@radix-ui/react-dialog';

<Dialog.Root>
  <Dialog.Trigger className="bg-blue-500 px-4 py-2 rounded">Otworz</Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Overlay className="fixed inset-0 bg-black/50" />
    <Dialog.Content className="fixed top-1/2 left-1/2 -translate-x-1/2 -translate-y-1/2 bg-white p-6 rounded-xl">
      <Dialog.Title>Tytul</Dialog.Title>
      <Dialog.Description>Tresc</Dialog.Description>
      <Dialog.Close>Zamknij</Dialog.Close>
    </Dialog.Content>
  </Dialog.Portal>
</Dialog.Root>

Mantine

Mantine — pelnej-funkcjonalnosci component library. 100+ komponentow, hooks, theming, accessibility. Konkurent Material UI.

npm i @mantine/core @mantine/hooks

import { MantineProvider, Button, TextInput, Card } from '@mantine/core';
import '@mantine/core/styles.css';

<MantineProvider>
  <Card shadow="sm" padding="lg">
    <TextInput label="Email" placeholder="ty@example.com" />
    <Button mt="md" fullWidth>Zapisz</Button>
  </Card>
</MantineProvider>

Material UI v6

Material UI implementuje Material Design Google. Solidny, dojrzaly, ale ciezki bundle. Wciaz popularny w korporacjach.

npm i @mui/material @emotion/react @emotion/styled

import { Button, TextField, Card, CardContent } from '@mui/material';

<Card>
  <CardContent>
    <TextField label="Email" variant="outlined" fullWidth />
    <Button variant="contained" color="primary">Submit</Button>
  </CardContent>
</Card>

Chakra UI

Chakra UI — component library z naciskiem na DX. Style props (p={4} bg="red.500"). Lekkie i przyjemne.

import { Box, Button, Input, ChakraProvider } from '@chakra-ui/react';

<ChakraProvider>
  <Box p={6} bg="white" rounded="md" shadow="md">
    <Input placeholder="Email" mb={4} />
    <Button colorScheme="blue">Submit</Button>
  </Box>
</ChakraProvider>

daisyUI — komponenty na Tailwind

daisyUI dodaje warstwe komponentow (button, modal, navbar) do Tailwinda. Klasy semantyczne (btn btn-primary) zamiast utility chains.

npm i -D daisyui

// tailwind.config.js
module.exports = {
  plugins: [require('daisyui')],
};

<button className="btn btn-primary">Klik</button>
<div className="card bg-base-100 shadow-xl">...</div>

styled-components / Emotion (legacy)

Niegdys hot, dzis w odwrocie. Powody: nie dzialaja w RSC (potrzebuja runtime), wieksze bundle, wolniejsze. Nowe projekty 2026 — nie uzywaj.

// styled-components — przyklad legacy
import styled from 'styled-components';

const Button = styled.button`
  background: ${props => props.$primary ? '#06b6d4' : 'gray'};
  padding: 8px 16px;
`;

<Button $primary>Klik</Button>

CSS-in-JS — krytyka 2026

  • Wymaga JS runtime — problem z React Server Components
  • Style generuja sie w runtime — FOUC i wolniejsze pierwsze renderowanie
  • Wieksze bundle (np. Emotion ~10 KB tylko biblioteka)
  • Problemy ze static extraction — rozwiazania (panda-css, vanilla-extract) sa bardzo "niche"
  • Tailwind / CSS Modules zalatwiaja te same potrzeby bez tych wad
