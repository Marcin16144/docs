State management

Context, Zustand, Redux Toolkit, Jotai, Valtio i Tanstack Query

Client state vs Server state

Wazne rozroznienie w 2026:

  • Client state — UI state (modale, formy, theme, koszyk). Zustand, Jotai, Context.
  • Server state — dane z API/DB. Cache, refetch, invalidacja. Tanstack Query, SWR.

Mieszanie tych dwoch to czesty blad — do server state nie uzywaj Reduksa, uzyj Tanstack Query.

Context API — ograniczenia

Context to wbudowany mechanizm, ale ma ograniczenia:

  • Brak selektorow — kazda zmiana wartosci powoduje rerender wszystkich konsumentow
  • Pisac duzo boilerplate (Provider, Context, hook)
  • Trudne dla zlozonego state

Dla prostych przypadkow (theme, lokalizacja, auth) Context wystarcza. Dla zlozonego state — biblioteka.

Zustand — #1 popularnosci 2026

Zustand to minimalistyczna biblioteka. Brak Providerow, malo boilerplate, dziala bez Reacta. Zastapila Redux dla wiekszosci projektow.

// store.js
import { create } from 'zustand';

export const useStore = create((set, get) => ({
  count: 0,
  user: null,
  todos: [],

  increment: () => set(state => ({ count: state.count + 1 })),
  setUser: (user) => set({ user }),
  addTodo: (text) => set(state => ({ todos: [...state.todos, { id: Date.now(), text }] })),
  removeTodo: (id) => set(state => ({ todos: state.todos.filter(t => t.id !== id) })),

  // get() — dostep do aktualnego state poza setterem
  doubleCount: () => get().count * 2,
}));

// Komponent
function Counter() {
  const count = useStore(s => s.count);          // selektor — rerender tylko przy zmianie count
  const increment = useStore(s => s.increment);
  return <button onClick={increment}>Count: {count}</button>;
}

Zalety Zustand

  • Mala paczka (1 KB gzip)
  • Brak Provider hell — nie trzeba opakowywac aplikacji
  • Selektory — tylko te komponenty rerendruja, ktore widza zmiane
  • Middleware: persist (localStorage), devtools (Redux DevTools), immer
  • Latwe slice pattern dla duzych aplikacji

Redux Toolkit (RTK)

Redux nadal popularny w korporacyjnych projektach. Redux Toolkit to oficjalny tooling — eliminuje stary boilerplate.

// store/cartSlice.js
import { createSlice } from '@reduxjs/toolkit';

const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] },
  reducers: {
    addItem: (state, action) => { state.items.push(action.payload); }, // immer pod spodem
    removeItem: (state, action) => {
      state.items = state.items.filter(i => i.id !== action.payload);
    },
  },
});

export const { addItem, removeItem } = cartSlice.actions;
export default cartSlice.reducer;

// store/index.js
import { configureStore } from '@reduxjs/toolkit';
import cart from './cartSlice';

export const store = configureStore({ reducer: { cart } });

// Komponent
import { useSelector, useDispatch } from 'react-redux';

function Cart() {
  const items = useSelector(s => s.cart.items);
  const dispatch = useDispatch();
  return (
    <ul>
      {items.map(i => (
        <li key={i.id}>{i.name}
          <button onClick={() => dispatch(removeItem(i.id))}>X</button>
        </li>
      ))}
    </ul>
  );
}

Jotai — atomic state

Jotai opiera sie na atomach — malych jednostkach state. Inspirowane Recoilem (od FB, ale porzucony). Idealne gdy state jest mocno granularny.

import { atom, useAtom } from 'jotai';

const countAtom = atom(0);
const doubleAtom = atom(get => get(countAtom) * 2);
const userAtom = atom({ name: '', email: '' });

function Counter() {
  const [count, setCount] = useAtom(countAtom);
  const [double] = useAtom(doubleAtom);
  return (
    <>
      <p>Count: {count}, double: {double}</p>
      <button onClick={() => setCount(c => c + 1)}>+</button>
    </>
  );
}

Valtio — proxy-based

Valtio uzywa Proxy — mutujesz obiekt jak normalny JS, a komponenty automatycznie widzia zmiany. Najprostsze API ze wszystkich.

import { proxy, useSnapshot } from 'valtio';

const state = proxy({ count: 0, user: { name: 'Anna' } });

// Mutacja gdziekolwiek
state.count++;
state.user.name = 'Jan';

function Comp() {
  const snap = useSnapshot(state); // immutable snapshot — rerender przy zmianie
  return <p>{snap.count} — {snap.user.name}</p>;
}

Tanstack Query — server state

Tanstack Query (dawniej React Query) to obowiazkowa biblioteka dla server state. Cache, deduplication, background refetch, optimistic updates — wszystko na pokladzie.

// main.jsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const queryClient = new QueryClient();

createRoot(document.getElementById('root')).render(
  <QueryClientProvider client={queryClient}>
    <App />
  </QueryClientProvider>
);

// Komponent
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';

function Posts() {
  const { data, isLoading, error } = useQuery({
    queryKey: ['posts'],
    queryFn: async () => (await fetch('/api/posts')).json(),
    staleTime: 60_000,
  });

  if (isLoading) return <p>Ladowanie...</p>;
  if (error) return <p>Blad: {error.message}</p>;
  return <ul>{data.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}

function NewPost() {
  const qc = useQueryClient();
  const mutation = useMutation({
    mutationFn: (post) => fetch('/api/posts', { method: 'POST', body: JSON.stringify(post) }),
    onSuccess: () => qc.invalidateQueries({ queryKey: ['posts'] }),
  });
  return <button onClick={() => mutation.mutate({ title: 'Nowy' })}>Dodaj</button>;
}

Co wybrac w 2026?

Rekomendacja

  • Server state → Tanstack Query (zawsze, niezaleznie od reszty)
  • Client state — nowy projekt → Zustand (najlepsza prostota/moc)
  • Korporacyjny projekt z time-travel → Redux Toolkit
  • Mocno granularny state → Jotai
  • Tylko theme/auth → Context
  • Server Components (Next.js 15) → data na serwerze, mniej client state
