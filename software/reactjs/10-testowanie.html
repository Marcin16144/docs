Vitest — #1 unit test runner

Vitest zastapil Jest jako standard w 2024+. Powody: 10x szybszy (Vite + esbuild), natywne ESM, TS bez konfiguracji, kompatybilny z Jest API.

npm i -D vitest @vitest/ui jsdom

// vite.config.ts
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: './src/test/setup.ts',
  },
});

// src/test/setup.ts
import '@testing-library/jest-dom/vitest';

// package.json
"scripts": {
  "test": "vitest",
  "test:ui": "vitest --ui",
  "coverage": "vitest run --coverage"
}

Pierwszy test

// src/utils/sum.ts
export const sum = (a: number, b: number) => a + b;

// src/utils/sum.test.ts
import { describe, it, expect } from 'vitest';
import { sum } from './sum';

describe('sum', () => {
  it('dodaje dwie liczby', () => {
    expect(sum(2, 3)).toBe(5);
  });

  it('obsluguje liczby ujemne', () => {
    expect(sum(-1, -2)).toBe(-3);
  });
});

React Testing Library

Testing Library testuje komponenty z perspektywy uzytkownika — nie wewnetrzne implementacji. Glowna zasada: testuj zachowanie, nie kod.

npm i -D @testing-library/react @testing-library/jest-dom @testing-library/user-event

import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect } from 'vitest';
import Counter from './Counter';

describe('Counter', () => {
  it('zaczyna od 0 i inkrementuje po kliknieciu', async () => {
    const user = userEvent.setup();
    render(<Counter />);

    expect(screen.getByText(/Count: 0/)).toBeInTheDocument();

    await user.click(screen.getByRole('button', { name: /\+/ }));
    expect(screen.getByText(/Count: 1/)).toBeInTheDocument();
  });

  it('pokazuje komunikat dla wartosci ujemnej', async () => {
    const user = userEvent.setup();
    render(<Counter initial={1} />);

    await user.click(screen.getByRole('button', { name: /-/ }));
    await user.click(screen.getByRole('button', { name: /-/ }));

    expect(screen.getByText('Wartosc ujemna!')).toBeInTheDocument();
  });
});

Zapytania — priorytet

PriorytetQueryCel
1getByRoleNajlepszy — tak widzi screen reader

4getByTextTekst widoczny
5getByTestIdLast resort — data-testid

Pulapki Testing Library

  • NIE testuj implementacji — nie sprawdzaj nazw funkcji wewnetrznych, state etc.
  • Uzywaj userEvent zamiast fireEvent — dokladniej symuluje uzytkownika
  • findBy* dla async (czeka), queryBy* dla "nie istnieje"
  • Nie testuj samego Reacta (props passes, state changes) — testuj UI

Playwright — E2E #1

Playwright (od Microsoftu) wyparl Cypressa od 2024. Powody: szybszy (paralelnie), wieloprzegladarkowy (Chrome, Firefox, Safari), lepszy debugger, native TypeScript, API bardziej intuicyjne.

npm init playwright@latest

// tests/login.spec.ts
import { test, expect } from '@playwright/test';

test('uzytkownik moze sie zalogowac', async ({ page }) => {
  await page.goto('/login');

  await page.getByLabel('Email').fill('test@example.com');
  await page.getByLabel('Haslo').fill('haslo123');
  await page.getByRole('button', { name: 'Zaloguj' }).click();

  await expect(page).toHaveURL('/dashboard');
  await expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible();
});

test('blad przy zlym hasle', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill('test@example.com');
  await page.getByLabel('Haslo').fill('zle');
  await page.getByRole('button', { name: 'Zaloguj' }).click();

  await expect(page.getByText('Bledne dane')).toBeVisible();
});

Playwright features

  • Codegen — npx playwright codegen generuje testy klikajac w UI
  • Trace viewer — nagrywa cala sesje dla debugu
  • Auto-wait — nie trzeba pisac sleepow
  • Web-first assertions — expect powtarza dopoki sie nie spelni
  • Component testing (eksperymentalne) — React/Vue komponenty

Storybook 8

Storybook — izolowane srodowisko dla komponentow. Dokumentacja, wizualne testy, design system. Wersja 8 (2024) — Vite-powered, szybsza, wsparcie RSC.

npx storybook@latest init

// src/components/Button.stories.tsx
import type { Meta, StoryObj } from '@storybook/react';
import { Button } from './Button';

const meta: Meta<typeof Button> = {
  title: 'UI/Button',
  component: Button,
  argTypes: {
    variant: { control: 'select', options: ['primary', 'secondary'] },
    size: { control: 'radio', options: ['sm', 'md', 'lg'] },
  },
};
export default meta;

type Story = StoryObj<typeof Button>;

export const Primary: Story = {
  args: { variant: 'primary', children: 'Klik' },
};

export const Disabled: Story = {
  args: { variant: 'primary', disabled: true, children: 'Nieaktywny' },
};

// Z play function — interakcja
export const Click: Story = {
  args: { variant: 'primary', children: 'Klik' },
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);
    await userEvent.click(canvas.getByRole('button'));
  },
};

MSW — Mock Service Worker

MSW mockuje requesty HTTP na poziomie sieci. Idealne dla testow i development — jeden zestaw mockow dla unit, integration, browser dev.

npm i -D msw

// src/mocks/handlers.ts
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/posts', () => {
    return HttpResponse.json([
      { id: 1, title: 'Pierwszy post' },
      { id: 2, title: 'Drugi post' },
    ]);
  }),
  http.post('/api/posts', async ({ request }) => {
    const body = await request.json();
    return HttpResponse.json({ id: 3, ...body }, { status: 201 });
  }),
];

// src/mocks/server.ts (Node)
import { setupServer } from 'msw/node';
import { handlers } from './handlers';
export const server = setupServer(...handlers);

// src/test/setup.ts
import { server } from '../mocks/server';
import { beforeAll, afterEach, afterAll } from 'vitest';

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
