Controlled vs Uncontrolled

Dwa podejscia do formularzy w Reakcie:

  • Controlled — React trzyma wartosc w state, kazda zmiana to setter (rerender)
  • Uncontrolled — DOM trzyma wartosc, czytasz przez ref lub FormData (mniej rerenderow)
// Controlled
function Controlled() {
  const [name, setName] = useState('');
  return (
    <input value={name} onChange={e => setName(e.target.value)} />
  );
}

// Uncontrolled
function Uncontrolled() {
  const ref = useRef(null);
  const submit = () => alert(ref.current.value);
  return (
    <>
      <input defaultValue="" ref={ref} />
      <button onClick={submit}>OK</button>
    </>
  );
}

// Z FormData (modern uncontrolled)
function Modern() {
  const submit = (e) => {
    e.preventDefault();
    const fd = new FormData(e.currentTarget);
    console.log(Object.fromEntries(fd));
  };
  return (
    <form onSubmit={submit}>
      <input name="email" />
      <input name="password" type="password" />
      <button>Login</button>
    </form>
  );
}

react-hook-form (#1 w 2026)

react-hook-form to najpopularniejsza biblioteka. Uzywa uncontrolled inputs — minimalne rerendery, doskonala wydajnosc.

# Instalacja
npm i react-hook-form

import { useForm } from 'react-hook-form';

function LoginForm() {
  const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm();

  const onSubmit = async (data) => {
    await api.login(data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input
        {...register('email', {
          required: 'Email wymagany',
          pattern: { value: /^.+@.+$/, message: 'Niepoprawny email' },
        })}
      />
      {errors.email && <p>{errors.email.message}</p>}

      <input
        type="password"
        {...register('password', {
          required: 'Haslo wymagane',
          minLength: { value: 8, message: 'Min 8 znakow' },
        })}
      />
      {errors.password && <p>{errors.password.message}</p>}

      <button disabled={isSubmitting}>
        {isSubmitting ? 'Loguje...' : 'Zaloguj'}
      </button>
    </form>
  );
}

Zod — schema validation

Zod to biblioteka do walidacji opartej na schematach z TypeScript inferencja. Zwykle lacza ja z react-hook-form.

# Instalacja
npm i zod @hookform/resolvers

import { z } from 'zod';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';

const schema = z.object({
  email: z.string().email('Niepoprawny email'),
  password: z.string().min(8, 'Min 8 znakow'),
  age: z.coerce.number().min(18, 'Min 18 lat'),
  terms: z.literal(true, { errorMap: () => ({ message: 'Musisz zaakceptowac' }) }),
});

type FormData = z.infer<typeof schema>; // { email: string; password: string; age: number; terms: true }

function Form() {
  const { register, handleSubmit, formState: { errors } } = useForm<FormData>({
    resolver: zodResolver(schema),
  });

  return (
    <form onSubmit={handleSubmit(data => console.log(data))}>
      <input {...register('email')} />
      {errors.email && <p>{errors.email.message}</p>}

      <input type="password" {...register('password')} />
      <input type="number" {...register('age')} />
      <input type="checkbox" {...register('terms')} />
      <button>Zapisz</button>
    </form>
  );
}

Valibot — lzejsza alternatywa Zoda

Valibot ma podobne API co Zod, ale jest zaprojektowany z modularnoscia. Tree-shakable — wynik bundle ~10x mniejszy.

npm i valibot

import * as v from 'valibot';

const schema = v.object({
  email: v.pipe(v.string(), v.email('Niepoprawny email')),
  age: v.pipe(v.number(), v.minValue(18)),
});

const result = v.safeParse(schema, data);
if (result.success) console.log(result.output);
else console.log(result.issues);

Tanstack Form

Tanstack Form — nowy gracz (2024). Type-safe od podstaw, framework agnostic (React, Vue, Solid).

import { useForm } from '@tanstack/react-form';

function App() {
  const form = useForm({
    defaultValues: { email: '', password: '' },
    onSubmit: async ({ value }) => { await api.login(value); },
  });

  return (
    <form onSubmit={(e) => { e.preventDefault(); form.handleSubmit(); }}>
      <form.Field
        name="email"
        validators={{
          onChange: ({ value }) => !value.includes('@') ? 'Niepoprawny email' : undefined,
        }}
        children={(field) => (
          <>
            <input
              value={field.state.value}
              onChange={e => field.handleChange(e.target.value)}
            />
            {field.state.meta.errors?.[0] && <p>{field.state.meta.errors[0]}</p>}
          </>
        )}
      />
      <button>Submit</button>
    </form>
  );
}

Formik (legacy)

Niegdys popularny, dzis legacy. Wolniejszy (controlled inputs, czeste rerendery), wiekszy bundle, slabszy DX. Nowe projekty — uzyj react-hook-form lub Tanstack Form.

Server Actions z React 19

Z React 19 + Next.js 15 mozesz tworzyc formularze z zerem JS po stronie klienta — akcje wykonuja sie na serwerze.

// app/actions.js
'use server';
import { z } from 'zod';
import { redirect } from 'next/navigation';

const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

export async function login(prevState, formData) {
  const parsed = schema.safeParse({
    email: formData.get('email'),
    password: formData.get('password'),
  });

  if (!parsed.success) {
    return { errors: parsed.error.flatten().fieldErrors };
  }

  const ok = await verifyCredentials(parsed.data);
  if (!ok) return { errors: { _form: ['Bledne dane logowania'] } };

  redirect('/dashboard');
}

// app/login/page.jsx
'use client';
import { useActionState } from 'react';
import { useFormStatus } from 'react-dom';
import { login } from '@/app/actions';

function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? 'Loguje...' : 'Zaloguj'}</button>;
}

export default function LoginForm() {
  const [state, action] = useActionState(login, { errors: {} });
  return (
    <form action={action}>
      <input name="email" />
      {state.errors?.email && <p>{state.errors.email[0]}</p>}
      <input name="password" type="password" />
      {state.errors?.password && <p>{state.errors.password[0]}</p>}
      {state.errors?._form && <p>{state.errors._form[0]}</p>}
      <SubmitButton />
    </form>
  );
}

Walidacja: Zod czy Valibot?

  • Zod — popularniejszy, wiecej integracji (Tanstack Query, tRPC, Hono)
  • Valibot — mniejszy bundle (kluczowe dla mobile), tree-shaking
  • Oba maja podobne API i TS inference
  • Wybierz Zod jesli ekosystem juz go uzywa, Valibot jesli zalezy ci na rozmiarze
