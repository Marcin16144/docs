1. Przegląd systemu

K2 CMS to wielodomenowy system zarządzania treścią napisany w PHP 8.1+. Jedna instalacja obsługuje wiele domen (tenantów) — każda ma własny prefiks tabel, konfigurację i panel administracyjny pod unikatowym, sekretnym adresem URL.

Panel oparty jest na szablonie AdminLTE 3 (Bootstrap 4 + jQuery 3.6), w całości zvendorowanym lokalnie — system działa bez dostępu do internetu, bez CDN.

DomenyKonfiguracja tenantów, snapshoty historii
NawigacjaWielozestawowe drzewa menu, historia migawkowa

DiagnostykaInformacje o systemie, połączeniu BD, PHP

4. Warstwa rdzenia (core/)

4.1 Config

core/Config.php — ładuje konfigurację jako tablicę PHP przy pierwszym żądaniu.

Config::load($_SERVER['HTTP_HOST']);   // ładuje _default.php + <host>.php (array_replace_recursive)
Config::get('tenant')['prefix'];       // zwraca prefix tabel, np. "def"
Config::get('admin_code');             // sekretny kod URL panelu
Config::get('db');                     // parametry połączenia z bazą

4.2 Connection

core/Connection.php — singleton PDO z wyborem sterownika:

MySQL  → MySqlDriver  → DSN: "mysql:host=…;dbname=…;charset=utf8mb4"
PgSQL  → PgSqlDriver  → DSN: "pgsql:host=…;dbname=…"
SQLite → SqliteDriver → DSN: "sqlite:<ścieżka>"

4.3 Logger

core/Log/Logger.php — ustrukturyzowany rejestrator. Poziomy: TRACE < DEBUG < INFO < WARN < ERROR < FATAL. Zapis do tabeli <tenant>_logs, fallback do var/logs/app.log.

Logger::get('Gallery')->info('Przesłano zdjęcie', properties: ['gallery_id' => $id, 'bytes' => $size]);
Logger::get('System')->warn('Backup bez sygnatury', properties: ['file' => $f]);
Logger::get('Auth')->warn('Nieudana próba logowania', properties: ['login' => $login, 'ip' => $ip]);

Dostępne kanały: Auth · Gallery · Navigation · Users · Domains · System

4.4 System migracji

Oparty na doctrine/migrations. TenantMigration dostarcza table(string $name): string wstrzykujące prefix tenanta. Każdy komponent (appdb, cms, shop) ma osobną tabelę śledzącą.

final class Version20260524100000 extends TenantMigration {
    public function up(Schema $schema): void {
        $this->addSql("ALTER TABLE `{$this->table('gallery_photos')}` ADD COLUMN …");
    }
}

7.4 Upload i cascade INSERT

Upload przez AJAX (dropzone). Warianty INSERT od bogatego do minimalnego — odporność na instalacje bez wszystkich migracji:

$variants = [
    [$sqlWithHashAndOrigName, $paramsWithBoth],   // GalPhotoHash + GalPhotoOrigName
    [$sqlWithOrigNameOnly,    $paramsWithOrig],   // tylko GalPhotoOrigName
    [$sqlMinimal,             $paramsMinimal],    // kolumny podstawowe
];
foreach ($variants as [$sql, $params]) {
    try { $pdo->prepare($sql)->execute($params); $inserted = true; break; }
    catch (\PDOException $e) {
        if (!str_contains($e->getMessage(), 'Unknown column')) { break; }
    }
}

8. System kopii zapasowych rozbudowane

8.1 Tryby kopii

backup_typeFormatZawartość
db.sql lub .sql.encDump SQL wszystkich tabel
full.zip lub .tar.gzdatabase.sql + media/originals/ + media/cache/
media.zip lub .tar.gzTylko media/originals/ + media/cache/

8.2 Wykrywanie metody archiwizacji

detectArchiver() → 'zip' | 'tar_gz' | 'none'

Priorytet:
  1. ZipArchive  (ext-zip)   → .zip    — standardowe rozszerzenie PHP
  2. PharData    (ext-phar)  → .tar.gz — wbudowane w PHP core (fallback dla shared hosting)
  3. brak                    → archiwa mediów niedostępne, tylko SQL

Archiwizacja katalogów używa iteratywnego stosu scandir() zamiast RecursiveIteratorIterator — niezawodne na Windows, brak konfliktów uchwytów SPL + ZipArchive.

8.3 Integralność i szyfrowanie

SHA-256 sidecar (.sha256) Tworzony po każdym backupie przez backupSign(). Format zgodny z sha256sum. Weryfikowany przez backupVerify() przed przywróceniem (blokujące) i pobieraniem (ostrzeżenie).
AES-256-CBC (.sql.enc) Aktywowany kluczem backup_encryption_key = 'base64:…' w konfiguracji. Format: [4B magic "K2BC"][16B IV][zaszyfrowane dane]. Dotyczy wyłącznie kopii SQL.

Pliki backupów nie są wersjonowane — katalog var/backups/ ma .gitignore z regułą * / !.gitignore / !.gitkeep.

10.1 Sekretny adres URL

Panel działa wyłącznie pod /admin/{admin_code}/. Każda inna ścieżka zwraca 404 bez wskazówki. hash_equals() eliminuje timing attack.

Zalecenie admin_code min. 20 losowych znaków: openssl rand -base64 18. Traktuj jak hasło — nie wpisuj do publicznego repo.

10.2 Uwierzytelnianie

Hasła przechowywane jako bcrypt hash. Konto bootstrap admin działa tylko gdy tabela <t>_users jest pusta. touchLastLogin() aktualizuje UseLastLogin po każdym udanym logowaniu (audyt).

10.3 Ochrona sesji

Session Fixation: session_regenerate_id(true) przed zapisem $_SESSION['admin']. Idle-timeout 3h. Ciasteczko: httponly, secure, SameSite=Strict, use_strict_mode=1.

10.4 Ochrona CSRF

Synchronizer Token Pattern — 64-znakowy hex per-sesja. Każdy formularz POST: <?= csrfToken() ?>. Weryfikacja przez hash_equals(). Niezgodność → HTTP 403 + log WARN.

10.5 Rate limiting logowania

Tabela <t>_login_attempts. Bucket = SHA-256(REMOTE_ADDR) — IP nie przechowywane. Okno: 15 min. Limit: 10 prób. Fail-open: brak tabeli → blokada wyłączona.

10.7 Honeypot

Ukryte pole CSS .a11y-offscreen (position: absolute; left: -9999px) w formularzu logowania. Boty je wypełniają → blokada bez licznika w login_attempts — oszczędza budżet rate limitera.

10.8 Kontrola dostępu (autoryzacja)

Sekcje wrażliwe (permissions, groups, domains, backup) wymagają canManageAccess:

$canManageAccess = $adminUser === 'admin'
    || (string)($currentUser['UseGroupID'] ?? '') === GroupsModel::ADMIN_GROUP_ID;
