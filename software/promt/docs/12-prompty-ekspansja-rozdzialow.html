12. Prompty per ekspansja rozdzialow

Tworzenie sub-pages, nazewnictwo NN-NN-temat.html, kiedy temat zasluguje na osobny plik, workflow rozszerzania.

Filozofia ekspansji

Glowny rozdzial to overview, sub-page to deep dive. Gdy temat w glownym pliku przekracza ~2000 slow lub 3 sekcje H2, wydziel sub-page. Czytelnik dostaje wybor: szybkie wprowadzenie lub pelne zanurzenie.

Wzorzec nazewnictwa NN-NN-temat.html

NN-NN-NN-temat.htmlSub-sub-page (rzadko)05-01-02-themes.html

Prompt: Rozwin temat X (sub-page)

Prompt — Sub-page 
Stworz sub-page NN-NN-temat.html ekspandujacy konkretny topic
z parent rozdzialu.

PRZYKLAD POLECENIA:
"Rozwin Catalyst (premium Tailwind UI) jako 05-01-catalyst.html.
Parent: 05-tailwind.html. Next: 05-02-headlessui.html."

STRUKTURA SUB-PAGE:
1. Topbar 4-poziomowy:
   Glowna / Kategoria / NazwaParent / NazwaSub

2. H1: nazwa subtematu (np. "Catalyst — premium Tailwind UI")

3. Subtitle: 1 zdanie kontekstu, link do parent

4. Sekcja "Co to jest" (200 slow):
   - Definicja, kontekst, kto stoi za tym
   - Cena, license

5. Sekcja "Co dostajesz" (komponenty, features)

6. Sekcja "Setup & instalacja" (code examples)

7. Sekcja "Customization & theming"

8. Sekcja "Vs konkurencja":
   - Comparison table (np. Catalyst vs shadcn/ui vs Park UI)

9. Sekcja "Real-world usage" (firmy, projekty)

10. Sekcja "Kiedy uzyc / Kiedy NIE" (green/red cards)

11. Linki

12. Nav-bottom:
    prev = parent (05-tailwind.html)
    next = 05-02 (kolejny sub-page) lub parent jesli ostatni

ROZMIAR: 8-12 KB (mniejszy niz parent)

Prompt: Ekspansja Tailwind sub-pages (przyklad)

Prompt — Tailwind expansion 
Wygeneruj 5 sub-pages dla 05-tailwind.html jako ekspansje:

05-01-catalyst.html: Catalyst (Tailwind UI) — premium components
$299/year, kontrast z shadcn (paid vs OSS), enterprise focus,
Tailwind Labs official, Headless UI under hood

05-02-headlessui.html: HeadlessUI — unstyled accessible primitives
od Tailwind Labs, React/Vue versions, kiedy uzyc nad shadcn
(jesli chcesz pelna kontrole nad stylingiem od zera)

05-03-shadcn.html: shadcn/ui — copy-paste components, "own your code"
philosophy, CLI add command, registry, kompatybilny z Radix UI,
najpopularniejszy w 2024-2026 (>30k GitHub stars)

05-04-daisy.html: DaisyUI — semantic class names dla Tailwind,
themes builtin (30+), latwy onboarding (najmniejsza krzywa nauki),
ograniczona elastycznosc vs shadcn

05-05-park.html: Park UI — Ark UI + Panda CSS, real-world enterprise,
multi-framework (React, Solid, Vue), styled vs unstyled wariant

KAZDA SUB-PAGE: 8-12 KB, code examples, screenshots opisane,
porownanie z konkurencja, "kiedy uzyc".

NAVIGACJA: prev=parent (05-tailwind.html), next=05-NN+1.html.
Ostatnia sub-page: next = parent (powrot do overview).

Prompt: Dodaj nowy rozdzial w istniejacym indeksie

Prompt — Add to index 
Wygeneruj nowy rozdzial w istniejacej kategorii i zaktualizuj
TOC.

KROKI:
1. Stworz nowy plik NN-temat.html w kategorii
   (NN = nastepny dostepny numer, np. 09-temat.html jesli ostatni byl 08)

2. Zaktualizuj kategoria/index.html:
   - Dodaj wpis w .breadcrumb <ul> w odpowiedniej pozycji
   - Pattern: <li><a href="NN-temat.html">NN. Tytul</a></li>

3. Zaktualizuj PREV file (NN-1):
   - Zmien link "next" w nav-bottom na nowy plik
   Dawniej: <a href="../index.html">Wroc do indeksu &rarr;</a>
   Teraz: <a href="NN-temat.html">NN. Tytul &rarr;</a>

4. Re-build search index (Pagefind / MiniSearch).

5. Test linkow (lychee, broken-link-checker).

PROMPT WERSJA AUTOMATYCZNA:
"Dodaj rozdzial 09-grpc.html w kategorii frontend.
Tytul: 'gRPC w przegladarce — grpc-web'.
Update: frontend/index.html i frontend/08-graphql.html (zmien next).
Wygeneruj cale 09-grpc.html (~ 12 KB) zgodnie z master promptem."

Prompt: Refaktor — split rozdzialu na sub-pages

Prompt — Split chapter 
Refaktor istniejacego rozdzialu (zbyt dluzny) na overview + sub-pages.

WHEN: rozdzial > 25 KB lub > 4000 slow lub 8+ sekcji H2.

KROKI:
1. Zidentyfikuj sekcje H2 ktore zasluguja na sub-page (>1000 slow,
   wlasna logika, czytelnik moze szukac sam).

2. Dla kazdej takiej sekcji:
   - Stworz NN-NN-temat.html z tym contentem
   - Rozszerz (1500-3000 slow z dodatkowymi przykladami)
   - Dodaj real-world, decision tree, comparison

3. W parent NN-temat.html zostaw:
   - 1-2 paragrafy intro per topic
   - Link "Zobacz pelny rozdzial: NN-NN-temat.html →"
   - Tabela porownawcza zostaje (overview-level)

PRZYKLAD:
Parent: 03-databases.html (50 KB, za duzy)
Split na:
- 03-01-postgres.html (deep dive PG)
- 03-02-mysql.html (deep dive MySQL)
- 03-03-mongo.html (deep dive Mongo)
- 03-04-redis.html (deep dive Redis)
- 03-05-clickhouse.html (deep dive CH)

Parent staje sie overview ~15 KB z linkami do sub-pages.

Co rozwijac — kryteria

ROZWIN gdy:

  • Temat zasluguje na 1500+ slow (deep dive)
  • Temat ma wlasna logike, instalacje, ekosystem
  • Czytelnik bedzie szukal samodzielnie ("jak skonfigurowac X")
  • Vendor / produkt z osobna stronka WWW
  • Sub-temat ma >5 unikalnych code examples
  • Parent przekracza 25 KB

NIE ROZWIJAJ gdy:

  • Temat to 2-3 paragrafy w kontekscie wiekszej calosci
  • Sub-temat ma sens TYLKO w polaczeniu z parent (nie samodzielny)
  • Parent < 15 KB (jeszcze duzo miejsca)
  • Temat to lista features bez deep dive (zostaw jako sekcje)
  • Brak materialu na 1500+ slow (rozcieczysz do bullet points)

Workflow ekspansji — pelny cykl

  1. Identyfikuj temat — przy review parent rozdzialu, znajdz sekcje "X to deeper topic worth its own page"
  2. Napisz prompt na sub-page — szczegolowo, ze struktura, wymaganiami, parent file reference
  3. Wygeneruj sub-page — Claude/GPT z master promptem + szczegoly
  4. Zaktualizuj parent — skroc sekcje do overview, dodaj link "Zobacz pelny rozdzial →"
  5. Zaktualizuj nav-bottom w parent — sub-pages w prev/next chain albo branch
  6. Zaktualizuj search index — re-build (Pagefind dla najnowoczesniej)
  7. Test — czytanie linearne (parent -> sub1 -> sub2 -> ...) musi byc plynne
  8. Commit — atomic commit per ekspansja, message "expand 05-tailwind: add sub-pages 05-01..05-05"

Przyklad: Tailwind expansion (struktura plikow)

frontend/
+- index.html                    (kategoria, .breadcrumb)
+- 04-react.html
+- 05-tailwind.html               (parent overview, ~15 KB)
+- 05-01-catalyst.html             (sub: premium UI, ~10 KB)
+- 05-02-headlessui.html           (sub: unstyled primitives, ~10 KB)
+- 05-03-shadcn.html               (sub: copy-paste, ~12 KB)
+- 05-04-daisy.html                (sub: semantic, ~8 KB)
+- 05-05-park.html                 (sub: Park UI, ~10 KB)
+- 06-bootstrap.html

NAVIGACJA W SUB-PAGES:
05-01-catalyst.html:
  prev = 05-tailwind.html
  next = 05-02-headlessui.html

05-05-park.html (ostatni sub):
  prev = 05-04-daisy.html
  next = 05-tailwind.html (powrot do parent overview)

LUB ALTERNATYWA — sub-pages NIE w main chain:
05-tailwind.html:
  prev = 04-react.html
  next = 06-bootstrap.html
  (sub-pages dostepne via linki w treści parent)

Anti-patterns ekspansji

Sub-page ktora to lista bullet pointow

Jesli sub-page ma 800 slow w 90% bullet points, to nie zasluguje na osobny plik. Zostaw w parent jako sekcja H2.

Sub-page bez kontekstu parent

Zaczyna sie "Catalyst to..." bez wzmianki ze to ekspansja Tailwind UI. Czytelnik z Google moze nie wiedziec. Zawsze 1 zdanie kontekstu + link do parent.

Duplikacja contentu parent <-> sub-page

Te same code examples w obu. Sub-page ma byc rozszerzeniem, nie kopia. Parent: overview. Sub: deep dive z DODATKOWYMI examples.

Glebokie zagniezdzenie (NN-NN-NN-NN-...)

Sub-sub-sub-page. Czytelnik gubi sie w hierarchii. Max 2 poziomy zaglebienia: parent (NN) + sub (NN-NN). Glebsze rozwazyc jako oddzielna kategoria.

Tipy do efektywnej ekspansji

Zacznij od overview, ekspansja later

Nie pisz wszystkiego od razu. Stworz parent overview (15 KB), zobacz co czytelnicy szukaja, ekspansja na podstawie data (analytics, GitHub issues, search queries).

Sub-pages w batchach (parallel agents)

Gdy chcesz rozwinac topic w 5 sub-pages, uzyj 5 parallel Claude agents (po jednym per sub). Master prompt + szczegoly per sub. Tanszej z prompt caching.

Cross-link sub-pages miedzy soba

05-01-catalyst.html mowi o uzyciu Headless UI -> link do 05-02-headlessui.html. To naturalny graf nawigacji, nie tylko hierarchical.
