02. Szablon HTML/CSS

Prompty generujace spojny dark-theme HTML template dla calej dokumentacji. Skopiuj CSS 1:1 do kazdego rozdzialu.

Filozofia szablonu

Caly stos dokumentacji uzywa jednego CSS theme (zmienne CSS, dark mode, accent kolor). Spojnosc daje czytelnikowi natychmiastowe poczucie "to ten sam projekt". Nie zmieniaj kolorow per rozdzial — zmieniaj akcenty (h2 colors, card variants).

Prompt 1: Generuj kompletny CSS theme

Prompt — CSS Theme 
Wygeneruj kompletny inline CSS dla dokumentacji HTML w dark theme.

WYMAGANIA:
- CSS variables w :root (--bg, --surface, --border, --text, --text-muted,
  --accent, --accent-hover, --green, --orange, --red, --blue, --pink, --code-bg)
- Bazowe kolory:
  --bg:#0f172a (slate-900)
  --surface:#1e293b (slate-800)
  --border:#334155 (slate-700)
  --text:#e2e8f0 (slate-200)
  --accent:#a78bfa (violet-400)
  --green:#4ade80, --red:#f87171, --orange:#fb923c, --blue:#60a5fa
- Topbar sticky z breadcrumbami (Glowna / Prompty / Tytul)
- Container max-width 920px, padding 40px 20px 80px
- H1 z gradient text (accent -> pink)
- H2 z accent color + bottom border
- Card variants: .card.green, .card.orange, .card.red, .card.blue
- Table styling z accent header
- Prompt-block z 2px accent border + label position absolute
- Nav-bottom z prev/next links

WYJSCIE: jeden <style> tag z minified CSS.

Prompt 2: Generuj index.html (TOC)

Prompt — Index page 
Stworz index.html dla kategorii X (np. "React 19 dokumentacja").

STRUKTURA:
- Topbar z breadcrumb "Glowna / NazwaKategorii"
- H1 + subtitle
- Sekcja "Co znajdziesz tutaj" (3-4 bullets)
- TOC z .breadcrumb pattern (lista linkow z numerami i tytulami)
- Sekcja "Kolejnosc czytania" (rekomendowana sciezka)
- Sekcja "Linki do innych kategorii" (cross-references)

UWAGA: na index uzywamy .breadcrumb (lista pionowa z numerami),
NIE .topbar — to glowna strona kategorii.

ROZMIAR: 6-10 KB

Prompt 3: Generuj rozdzial HTML

Prompt — Chapter page 
Stworz rozdzial NN-temat.html dla kategorii X.

STRUKTURA:
- Topbar z breadcrumb (Glowna / Kategoria / TytulRozdzialu)
- H1 + subtitle
- 5-12 sekcji H2
- Min. 2 code examples w <pre><code>
- Min. 1 tabela porownawcza
- 1-3 cards (green/orange/red/blue) dla wyrozniajacych info
- Nav-bottom z prev/next

CONTENT: [tu wpisz co ma byc]
ROZMIAR: 12-20 KB

Prompt 4: Generuj sub-page (NN-NN-temat.html)

Prompt — Sub-page 
Stworz sub-page NN-NN-temat.html (gdzie pierwszy NN to nadrzedny rozdzial).

PRZYKLAD: 05-01-catalyst.html (sub-page do 05-tailwind.html)

STRUKTURA:
- Topbar z 4-poziomowym breadcrumb (Glowna / Kategoria / Rozdzial / Subtemat)
- H1 z nazwa subtematu
- Krotki kontekst (2-3 zdania nawiazujace do parent)
- Glebsza analiza (pelny dive w temat)
- Code examples na realnych use-case
- Nav-bottom: prev=parent file, next=NN-NN+1.html

ROZMIAR: 8-12 KB

Kiedy uzywac .breadcrumb vs .topbar

ElementKiedy uzywacDlaczego
.breadcrumbIndex pages, glowne TOC, listy rozdzialowLista pionowa z numerami sugeruje strukture (1, 2, 3...). Czytelnik widzi cala mape.
.topbarWszystkie podstrony tresci, sub-pagesSticky bar daje stala nawigacje powrotna. Czytelnik moze szybko wrocic do parent.
Oba narazBardzo duze sekcje (10+ rozdzialow).topbar dla powrotu, .breadcrumb in-page dla skoku do innego rozdzialu w tej samej kategorii.

Wzorzec breadcrumb (na index pages)

<ul class="breadcrumb">
  <li><a href="01-podstawy.html">
    <span class="num">01</span>
    <span class="title">Podstawy React</span>
    <span class="meta">15 min czytania</span>
  </a></li>
  <li><a href="02-hooks.html">
    <span class="num">02</span>
    <span class="title">Hooks</span>
    <span class="meta">20 min</span>
  </a></li>
</ul>

Wzorzec topbar (na podstronach)

<div class="topbar">
  <a href="../../index.html">Glowna</a>
  <span class="sep">/</span>
  <a href="../index.html">React</a>
  <span class="sep">/</span>
  <span class="title">Hooks</span>
</div>

Card variants — kiedy ktorego uzywac

.card.green — pozytywna informacja, "kiedy uzywac", best practices, bezpieczne defaults.
.card.orange — ostrzezenie, edge case, "to dziala ale uwaga", performance pitfall.
.card.red — "kiedy NIE uzywac", anti-pattern, deprecated, security risk.
.card.blue — neutralna informacja, tip, "good to know", historical context.

Reguly konsystencji

ElementReguly
Tytul H1"NN. Tytul" (kropka po numerze, sentence case)
Subtitle1 zdanie, max 120 znakow, opisuje "co znajdziesz"
H2 sekcjeSentence case, bez kropki na koncu
Code blocksZawsze <pre><code> (nie sam <code> dla bloku)
TabelePierwsza kolumna to "klucz" (nazwa tech, wzorzec), reszta to atrybuty
LinkiWzgledne (../index.html), nigdy absolutne (file:///...)

Anti-patterns w szablonie

NIE rob tego:

  • Custom kolory per rozdzial (zlam spojnosci)
  • Inline style zamiast .card classes
  • Mieszanie <b> i <strong> (uzywaj tylko strong)
  • <br> do separacji bloku — uzywaj <p> lub margins
  • Roznych sizes h1 per plik
