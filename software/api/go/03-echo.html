Echo Framework

Minimalistyczny, wysokowydajny framework HTTP — czysty interfejs, rozbudowany middleware, swietna dokumentacja

echo.New() i podstawowa konfiguracja

Echo jest frameworkiem skupionym na prostocie i wydajnosci. Glowna roznica wzgledem Gin to bardziej konsekwentny interfejs echo.Context oraz wbudowany mechanizm obslugi bledow przez HTTPErrorHandler.

package main

import (
    "net/http"
    "github.com/labstack/echo/v4"
    "github.com/labstack/echo/v4/middleware"
)

func main() {
    e := echo.New()

    // Middleware globalne
    e.Use(middleware.Logger())
    e.Use(middleware.Recover())
    e.Use(middleware.CORS())

    // Trasy
    e.GET("/", func(c echo.Context) error {
        return c.JSON(http.StatusOK, map[string]string{"status": "ok"})
    })

    // Grupy
    api := e.Group("/api/v1")
    api.Use(middleware.JWT([]byte("secret")))

    api.GET("/users", listUsers)
    api.POST("/users", createUser)
    api.GET("/users/:id", getUser)

    // Uruchomienie z TLS
    // e.StartTLS(":443", "cert.pem", "key.pem")
    e.Logger.Fatal(e.Start(":8080"))
}

Router groups i middleware chain

Grupy w Echo pozwalaja na dodawanie prefiksow i middleware do zestawu tras. Metoda Echo.Use() rejestruje middleware globalnie, natomiast Group.Use() — tylko dla tras w danej grupie. Kolejnosc rejestracji ma znaczenie.

Lancuch middleware

Echo wykonuje middleware w kolejnosci rejestracji. Kazdy middleware wywoluje next(c) by przekazac sterowanie — podobnie jak w Gin c.Next(). Middleware moze modyfikowac zadanie i odpowiedz, zanim i po wykonaniu handlera.

Przypisywanie middleware do pojedynczych tras

Middleware mozna przekazac bezposrednio jako dodatkowe argumenty metod routingu: e.GET("/admin", handler, authMiddleware, rateLimitMiddleware). Echo wykona je w podanej kolejnosci przed handlerem.

Binder — echo.Bind i echo.Context

Echo automatycznie wykrywa typ danych na podstawie naglowka Content-Type i binduje je do struktury. Domyslny binder obsluguje JSON, XML, form data i query params.

type CreateProductRequest struct {
    Name        string  `json:"name"     form:"name"     validate:"required,min=2"`
    Price       float64 `json:"price"    form:"price"    validate:"required,gt=0"`
    Description string  `json:"description" validate:"max=500"`
    CategoryID  int     `json:"category_id" validate:"required"`
}

func createProduct(c echo.Context) error {
    var req CreateProductRequest

    // Bind parsuje body (JSON/XML/form) i query params
    if err := c.Bind(&req); err != nil {
        return echo.NewHTTPError(http.StatusBadRequest, err.Error())
    }

    // Walidacja po bindowaniu
    if err := c.Validate(&req); err != nil {
        return err // HTTPErrorHandler sam obsluzy blad walidacji
    }

    // Dostepu do parametrow sciezki
    // id := c.Param("id")
    // Query param z wartoscia domyslna
    // page := c.QueryParam("page")

    return c.JSON(http.StatusCreated, map[string]any{
        "id":   99,
        "name": req.Name,
    })
}

Custom Validator

Echo nie dolacza domyslnego walidatora — nalezy dostarczyc wlasny implementujac interfejs echo.Validator. Typowo uzywa sie go-playground/validator/v10, tak samo jak w Gin.

Rejestracja walidatora

Implementujesz interfejs Validate(i interface{}) error, tworzysz instancje i przypisujesz: e.Validator = &CustomValidator{validator: validator.New()}. Odtad c.Validate(req) uzywa Twojego walidatora.

HTTPErrorHandler — centralna obsluga bledow

Echo dostarcza zunifikowany mechanizm obslugi bledow. Kazdy handler moze zwrocic blad — Echo przekazuje go do HTTPErrorHandler, ktory decyduje o formacie i kodzie odpowiedzi. To eliminuje powielanie kodu obslugi bledow w handlerach.

Wlasny HTTPErrorHandler

Przypisujesz wlasna funkcje do e.HTTPErrorHandler. Mozesz rozroznic typy bledow: *echo.HTTPError (bledy jawnie zwracane), validator.ValidationErrors (bledy walidacji) i dowolne inne bledy (500).

echo.Context — rozszerzony interfejs

Interfejs echo.Context to jedno z wiekszych roznic miedzy Echo a Gin. Jest interfejsem (nie strukturą), co ulatwia mockowanie w testach jednostkowych.

  • c.Request() / c.Response() — dostep do HTTP primitywow
  • c.Param("name") — parametry sciezki
  • c.QueryParam("name") — query string
  • c.FormValue("name") — dane formularza
  • c.Set(key, val) / c.Get(key) — dane kontekstu
  • c.RealIP() — adres IP z uwzglednieniem proxy
  • c.Logger() — logger przypisany do zadania
  • c.NoContent(status) — odpowiedz bez ciala (np. 204)

Kiedy wybrac Echo zamiast Gin?

  • Chcesz centralnej obslugi bledow bez powielania kodu w handlerach
  • Testujesz handlery jednostkowo i chcesz mockowac Context
  • Potrzebujesz wbudowanej obslugi WebSocket
  • Cenisz bardziej idiomatyczne Go (interfejsy zamiast struktur)
