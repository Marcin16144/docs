Uwierzytelnianie w Go

JWT, OAuth2, Casbin RBAC, bcrypt i walidacja kluczy API — kompletny przewodnik po bezpieczenstwie API

JWT z golang-jwt/jwt v5

Pakiet github.com/golang-jwt/jwt/v5 to standardowa biblioteka JWT dla Go. Wersja 5 wprowadza poprawki bezpieczenstwa i bardziej rygorystyczna walidacje claimow (exp, nbf, iss, aud). Nigdy nie uzywaj starszych wersji w nowych projektach.

package auth

import (
    "errors"
    "time"

    "github.com/golang-jwt/jwt/v5"
)

var jwtSecret = []byte("super-tajny-klucz-min-32-znaki!!!")

// Wlasne claims — rozszerzamy jwt.RegisteredClaims
type Claims struct {
    UserID int    `json:"uid"`
    Role   string `json:"role"`
    jwt.RegisteredClaims
}

// GenerateToken tworzy podpisany token JWT
func GenerateToken(userID int, role string) (string, error) {
    claims := Claims{
        UserID: userID,
        Role:   role,
        RegisteredClaims: jwt.RegisteredClaims{
            Subject:   strconv.Itoa(userID),
            Issuer:    "myapi",
            Audience:  jwt.ClaimStrings{"web", "mobile"},
            IssuedAt:  jwt.NewNumericDate(time.Now()),
            ExpiresAt: jwt.NewNumericDate(time.Now().Add(24 * time.Hour)),
            NotBefore: jwt.NewNumericDate(time.Now()),
        },
    }
    token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
    return token.SignedString(jwtSecret)
}

// ParseToken weryfikuje token i zwraca claims
func ParseToken(tokenStr string) (*Claims, error) {
    claims := &Claims{}

    token, err := jwt.ParseWithClaims(tokenStr, claims,
        func(t *jwt.Token) (any, error) {
            // Sprawdzenie algorytmu — krytyczne dla bezpieczenstwa!
            if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
                return nil, fmt.Errorf("nieoczekiwany algorytm: %v", t.Header["alg"])
            }
            return jwtSecret, nil
        },
        jwt.WithExpirationRequired(),
        jwt.WithIssuedAt(),
        jwt.WithAudience("web"),
    )

    if err != nil {
        switch {
        case errors.Is(err, jwt.ErrTokenExpired):
            return nil, errors.New("token wygasl")
        case errors.Is(err, jwt.ErrTokenSignatureInvalid):
            return nil, errors.New("niepoprawny podpis")
        default:
            return nil, errors.New("niepoprawny token")
        }
    }
    if !token.Valid {
        return nil, errors.New("token niepoprawny")
    }
    return claims, nil
}

JWT Middleware dla Gin / Chi / Echo

Middleware przechwytuje zadanie, wyciaga token z naglowka Authorization: Bearer <token>, weryfikuje go i zapisuje claims w kontekscie. Handlery pobieraja claims przez c.Get("claims") (Gin) lub r.Context().Value(key) (Chi).

// Middleware dla Gin
func GinJWTMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        header := c.GetHeader("Authorization")
        if !strings.HasPrefix(header, "Bearer ") {
            c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{
                "error": "brak tokenu autoryzacji",
            })
            return
        }

        tokenStr := strings.TrimPrefix(header, "Bearer ")
        claims, err := ParseToken(tokenStr)
        if err != nil {
            c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{
                "error": err.Error(),
            })
            return
        }

        // Zapisz claims w kontekscie
        c.Set("userID", claims.UserID)
        c.Set("role", claims.Role)
        c.Set("claims", claims)
        c.Next()
    }
}

// Uzycie w routerze
protected := r.Group("/api/v1")
protected.Use(GinJWTMiddleware())
protected.GET("/profile", getProfile)

// W handlerze
func getProfile(c *gin.Context) {
    userID, _ := c.Get("userID")
    role, _ := c.Get("role")
    c.JSON(200, gin.H{"user_id": userID, "role": role})
}

OAuth2 z golang.org/x/oauth2

Pakiet golang.org/x/oauth2 implementuje klienta OAuth2. Obsluguje flow Authorization Code (dla uzytkownikow) i Client Credentials (dla serwisow). Dostarcza gotowe konfiguracje dla popularnych dostawcow: Google, GitHub, Facebook.

Casbin — RBAC i kontrola dostepu

Casbin (github.com/casbin/casbin/v2) to potezna biblioteka do kontroli dostepu. Obsluguje modele: RBAC (role-based), ABAC (attribute-based) i ACL. Reguly sa definiowane w plikach konfiguracyjnych lub w bazie danych.

Podstawowy wzorzec RBAC z Casbin

Definiujesz model (kto moze co robic z jakim zasobem), polityki (admin moze PUT /users, user moze GET /profile) i sprawdzasz: ok, _ := enforcer.Enforce(role, path, method). Polityki mozna ladowac z PostgreSQL przez adapter Casbin.

bcrypt — hashowanie hasel

Pakiet golang.org/x/crypto/bcrypt implementuje algorytm bcrypt do bezpiecznego przechowywania hasel. Bcrypt automatycznie dodaje sol (salt) i jest celowo wolny (koszt obliczeniowy), co utrudnia ataki brute-force.

import "golang.org/x/crypto/bcrypt"

// Hashowanie hasla przy rejestracji
func HashPassword(password string) (string, error) {
    // Cost 12 to dobry balans bezpieczenstwa i wydajnosci (ok 300ms)
    bytes, err := bcrypt.GenerateFromPassword([]byte(password), 12)
    return string(bytes), err
}

// Weryfikacja hasla przy logowaniu
func CheckPassword(password, hash string) bool {
    err := bcrypt.CompareHashAndPassword([]byte(hash), []byte(password))
    return err == nil
}

// Przyklad uzycia
func loginHandler(c *gin.Context) {
    var req struct {
        Email    string `json:"email"    binding:"required,email"`
        Password string `json:"password" binding:"required,min=8"`
    }
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(400, gin.H{"error": err.Error()})
        return
    }

    user, err := db.FindByEmail(c.Request.Context(), req.Email)
    if err != nil || user == nil {
        // Ten sam komunikat dla braku uzytkownika i zlego hasla (security)
        c.JSON(401, gin.H{"error": "niepoprawne dane logowania"})
        return
    }

    if !CheckPassword(req.Password, user.PasswordHash) {
        c.JSON(401, gin.H{"error": "niepoprawne dane logowania"})
        return
    }

    token, err := GenerateToken(user.ID, user.Role)
    if err != nil {
        c.JSON(500, gin.H{"error": "blad generowania tokenu"})
        return
    }

    c.JSON(200, gin.H{"token": token, "expires_in": 86400})
}

Walidacja kluczy API

Klucze API to prosta alternatywa dla JWT gdy klient jest serwisem (nie uzytkownikiem). Klucz przekazywany jest w naglowku X-API-Key lub Authorization: ApiKey <key>.

Dobre praktyki bezpieczenstwa API

  • Zawsze weryfikuj algorytm JWT — ustaw oczekiwany algorytm jawnie
  • Uzyj krotkich tokenow dostepu (15-60 min) i dluzszych refresh tokenow
  • Przechowuj refresh tokeny w bazie danych (mozliwosc unierwaznienia)
  • Nigdy nie loguj tokenow, hasel ani kluczy API
  • Uzyj HTTPS wsedzie — JWT w HTTP to jak zamkniete drzwi bez sciany
  • Klucze API hashuj przed zapisem w bazie (SHA-256), pokazuj uzytkownikowi tylko raz
  • Rotuj sekrety JWT przy podejrzeniu wycieku — uzyj versjonowanych kluczy
