gRPC w Go

Protocol Buffers, generowanie kodu, serwery i klienty, streaming oraz interceptory

Narzedzia i generowanie kodu

gRPC w Go wymaga dwoch narzedzi do generowania kodu z plikow .proto:

  • protoc-gen-go (google.golang.org/protobuf/cmd/protoc-gen-go) — generuje typy Go (struktury, enum, metody serializacji)
  • protoc-gen-go-grpc (google.golang.org/grpc/cmd/protoc-gen-go-grpc) — generuje interfejsy serwera i klienta gRPC

Instalacja i generowanie:

# Instalacja narzedzi
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest

# Generowanie kodu z pliku .proto
protoc \
  --go_out=. --go_opt=paths=source_relative \
  --go-grpc_out=. --go-grpc_opt=paths=source_relative \
  proto/user.proto

Definicja serwisu w .proto

Plik .proto definiuje kontrakt API: typy wiadomosci i metody serwisu. Jest jezyk-neutralny — ten sam plik generuje kod dla Go, Python, Java, Rust itd. To kluczowa zaleta gRPC nad REST w architekturze wielojezycznej.

// proto/user.proto
syntax = "proto3";

package user.v1;
option go_package = "github.com/myapp/proto/user/v1;userv1";

// Definicja serwisu
service UserService {
  // Unary RPC — jeden request, jedna odpowiedz
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  rpc CreateUser(CreateUserRequest) returns (CreateUserResponse);

  // Server-side streaming — jeden request, strumien odpowiedzi
  rpc ListUsers(ListUsersRequest) returns (stream User);

  // Client-side streaming — strumien requestow, jedna odpowiedz
  rpc BatchCreateUsers(stream CreateUserRequest) returns (BatchCreateResponse);

  // Bidirectional streaming
  rpc Chat(stream ChatMessage) returns (stream ChatMessage);
}

message User {
  int64  id         = 1;
  string name       = 2;
  string email      = 3;
  int64  created_at = 4; // Unix timestamp
}

message GetUserRequest  { int64 id = 1; }
message GetUserResponse { User user = 1; }

message CreateUserRequest {
  string name  = 1;
  string email = 2;
}
message CreateUserResponse { User user = 1; }

message ListUsersRequest {
  int32 page_size  = 1;
  string page_token = 2;
}

message BatchCreateResponse { int32 created = 1; }
message ChatMessage { string text = 1; int64 sender_id = 2; }

Implementacja serwera

Po wygenerowaniu kodu implementujesz interfejs UserServiceServer. Interfejs zawiera wszystkie metody zdefiniowane w .proto. Jesli nie implementujesz wszystkich metod, osadzasz UnimplementedUserServiceServer — zabezpiecza to przed bladami przy przyszlych rozszerzeniach proto.

package main

import (
    "context"
    "log"
    "net"

    "google.golang.org/grpc"
    "google.golang.org/grpc/codes"
    "google.golang.org/grpc/reflection"
    "google.golang.org/grpc/status"

    userv1 "github.com/myapp/proto/user/v1"
)

// Implementacja serwisu
type userServer struct {
    userv1.UnimplementedUserServiceServer
    db UserRepository
}

func (s *userServer) GetUser(ctx context.Context, req *userv1.GetUserRequest) (*userv1.GetUserResponse, error) {
    if req.Id <= 0 {
        return nil, status.Errorf(codes.InvalidArgument, "id musi byc > 0, got: %d", req.Id)
    }

    user, err := s.db.FindByID(ctx, req.Id)
    if err != nil {
        return nil, status.Errorf(codes.Internal, "blad bazy: %v", err)
    }
    if user == nil {
        return nil, status.Errorf(codes.NotFound, "uzytkownik %d nie istnieje", req.Id)
    }

    return &userv1.GetUserResponse{
        User: &userv1.User{Id: user.ID, Name: user.Name, Email: user.Email},
    }, nil
}

// Server-side streaming
func (s *userServer) ListUsers(req *userv1.ListUsersRequest, stream userv1.UserService_ListUsersServer) error {
    users, err := s.db.List(stream.Context(), int(req.PageSize))
    if err != nil {
        return status.Errorf(codes.Internal, "blad listowania: %v", err)
    }
    for _, u := range users {
        if err := stream.Send(&userv1.User{Id: u.ID, Name: u.Name}); err != nil {
            return err // klient rozlaczony
        }
    }
    return nil
}

func main() {
    lis, err := net.Listen("tcp", ":50051")
    if err != nil {
        log.Fatalf("listen: %v", err)
    }

    srv := grpc.NewServer(
        grpc.UnaryInterceptor(loggingInterceptor),
        grpc.MaxRecvMsgSize(16*1024*1024), // 16 MB
    )

    userv1.RegisterUserServiceServer(srv, &userServer{})

    // Reflection — umozliwia grpcurl i inne narzedzia
    reflection.Register(srv)

    log.Println("gRPC serwer na :50051")
    log.Fatal(srv.Serve(lis))
}

Polaczenie klienta

Klient gRPC laczy sie przez grpc.NewClient() (od v1.64, zastepuje przestarzaly grpc.Dial). Polaczenie jest leniwe — faktyczna komunikacja nastepuje przy pierwszym wywolaniu. Wazne jest skonfigurowanie TLS i timeoutow.

Interceptory — middleware gRPC

Interceptory to odpowiednik middleware HTTP w swiecie gRPC. Dzialaja na poziomie unary (jeden request) lub streaming. Typowe zastosowania: logowanie, metryki, autoryzacja, tracing, retry.

// UnaryServerInterceptor — logowanie i metryki
func loggingInterceptor(
    ctx context.Context,
    req any,
    info *grpc.UnaryServerInfo,
    handler grpc.UnaryHandler,
) (any, error) {
    start := time.Now()
    resp, err := handler(ctx, req)
    duration := time.Since(start)

    code := codes.OK
    if err != nil {
        code = status.Code(err)
    }

    log.Printf("gRPC | method=%s | code=%s | duration=%s",
        info.FullMethod, code, duration)
    return resp, err
}

// Lancuch interceptorow przez grpc.ChainUnaryInterceptor
srv := grpc.NewServer(
    grpc.ChainUnaryInterceptor(
        authInterceptor,
        loggingInterceptor,
        rateLimitInterceptor,
    ),
)

grpc_reflection — narzedzia deweloperskie

Wywolanie reflection.Register(srv) pozwala narzedziu grpcurl i GUI grpcui na automatyczne odkrycie dostepnych metod bez pliku .proto. Wlaczaj wylacznie w srodowiskach development/staging — w produkcji reflection moze ujawniac kontrakt API.

gRPC vs REST — kiedy co wybrac?

  • gRPC: komunikacja miedzy mikroserwisami, streaming danych, wielojezyczne systemy, niska latencja
  • REST: publiczne API, klienty przegladarkowe, prostota i szeroka kompatybilnosc
  • gRPC-Gateway: generuje REST proxy dla gRPC — mozna udostepniac oba protokoly jednoczesnie
