Database w Go

database/sql, pgx, GORM, sqlx — laczenie z baza danych, ORM, migracje i connection pooling

database/sql — standardowa biblioteka

Pakiet database/sql dostarcza generyczny interfejs do baz danych. Sam w sobie nie laczy sie z zadna baza — wymaga sterownika (driver), ktory implementuje interfejs sql.Driver. Dla PostgreSQL najczesciej uzywa sie lib/pq lub nowszego jackc/pgx.

package main

import (
    "context"
    "database/sql"
    "log"
    "time"

    _ "github.com/jackc/pgx/v5/stdlib" // rejestruje driver pgx jako "pgx"
)

type User struct {
    ID        int
    Name      string
    Email     string
    CreatedAt time.Time
}

func main() {
    dsn := "postgres://user:pass@localhost:5432/mydb?sslmode=disable"
    db, err := sql.Open("pgx", dsn)
    if err != nil {
        log.Fatal(err)
    }
    defer db.Close()

    // Konfiguracja connection pool
    db.SetMaxOpenConns(25)
    db.SetMaxIdleConns(10)
    db.SetConnMaxLifetime(5 * time.Minute)
    db.SetConnMaxIdleTime(1 * time.Minute)

    // Weryfikacja polaczenia
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    if err := db.PingContext(ctx); err != nil {
        log.Fatal("baza niedostepna:", err)
    }
}

// QueryRow — jeden wiersz
func getUser(db *sql.DB, id int) (*User, error) {
    u := &User{}
    err := db.QueryRowContext(context.Background(),
        "SELECT id, name, email, created_at FROM users WHERE id = $1", id,
    ).Scan(&u.ID, &u.Name, &u.Email, &u.CreatedAt)
    if err == sql.ErrNoRows {
        return nil, nil
    }
    return u, err
}

// Query — wiele wierszy
func listUsers(db *sql.DB) ([]User, error) {
    rows, err := db.QueryContext(context.Background(),
        "SELECT id, name, email, created_at FROM users ORDER BY id LIMIT 100")
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var users []User
    for rows.Next() {
        var u User
        if err := rows.Scan(&u.ID, &u.Name, &u.Email, &u.CreatedAt); err != nil {
            return nil, err
        }
        users = append(users, u)
    }
    return users, rows.Err()
}

// Exec — INSERT / UPDATE / DELETE
func createUser(db *sql.DB, name, email string) (int, error) {
    var id int
    err := db.QueryRowContext(context.Background(),
        "INSERT INTO users (name, email) VALUES ($1, $2) RETURNING id",
        name, email,
    ).Scan(&id)
    return id, err
}

pgx — natywny driver PostgreSQL

Pakiet github.com/jackc/pgx/v5 mozna uzywac bezposrednio (bez database/sql), co daje dostep do funkcji specyficznych dla PostgreSQL: typow pgtype, COPY protocol, listen/notify, large objects i batchow.

  • pgxpool.New(ctx, dsn) — pool polaczyc z automatyczna konfiguracja
  • pool.QueryRow(ctx, sql, args...) — jeden wiersz
  • pgx.CollectRows(rows, pgx.RowToStructByName) — mapowanie do struktury po nazwie kolumny
  • batch := &pgx.Batch{} — batch queries w jednym roundtrip

GORM — ORM dla Go

GORM to najpopularniejszy ORM dla Go. Oferuje model-first approach: definiujesz struktury Go i GORM generuje zapytania SQL. Wspiera PostgreSQL, MySQL, SQLite i SQL Server.

import (
    "gorm.io/driver/postgres"
    "gorm.io/gorm"
    "gorm.io/gorm/logger"
)

type Product struct {
    gorm.Model           // ID, CreatedAt, UpdatedAt, DeletedAt (soft delete)
    Name       string    `gorm:"not null;size:200"`
    Price      float64   `gorm:"not null"`
    CategoryID uint
    Category   Category  `gorm:"foreignKey:CategoryID"`
    Tags       []Tag     `gorm:"many2many:product_tags"`
}

type Category struct {
    gorm.Model
    Name     string    `gorm:"uniqueIndex;not null"`
    Products []Product `gorm:"foreignKey:CategoryID"`
}

func setupDB() *gorm.DB {
    dsn := "host=localhost user=admin password=secret dbname=shop port=5432"
    db, err := gorm.Open(postgres.Open(dsn), &gorm.Config{
        Logger: logger.Default.LogMode(logger.Info),
    })
    if err != nil {
        panic("nie mozna polaczyc z baza")
    }

    // AutoMigrate tworzy/aktualizuje tabele
    db.AutoMigrate(&Category{}, &Product{})
    return db
}

// CRUD z GORM
func gormExamples(db *gorm.DB) {
    // Create
    product := Product{Name: "Laptop", Price: 2999.99, CategoryID: 1}
    db.Create(&product)

    // Read z preloadingiem
    var products []Product
    db.Preload("Category").Preload("Tags").
        Where("price > ? AND deleted_at IS NULL", 100).
        Order("created_at DESC").
        Limit(20).Offset(0).
        Find(&products)

    // Update — tylko zmienione pola
    db.Model(&product).Updates(map[string]any{"price": 2499.99, "name": "Laptop Pro"})

    // Soft delete (ustawia DeletedAt)
    db.Delete(&product)

    // Hard delete
    db.Unscoped().Delete(&product)
}

sqlx — rozszerzenie database/sql

Connection Pooling

Tworzenie nowego polaczenia TCP + TLS + autentykacja zajmuje dziesiesilatki milisekund. Connection pool utrzymuje gotowe polaczenia i wydaje je handlerz na zadanie. Konfiguracja ma kluczowe znaczenie dla wydajnosci i stabilnosci.

  • MaxOpenConns — maks. laczna liczba polaczyc (open + idle). Ustaw na podstawie limitow DB serwera.
  • MaxIdleConns — polaczenia bezczynne utrzymywane w puli. Powinny byc mniejsze niz MaxOpenConns.
  • ConnMaxLifetime — maksymalny czas zycia polaczenia. Zapobiega uzyciu starych polaczyc po restarcie DB.
  • ConnMaxIdleTime — czas po ktorym bezczynne polaczenie jest zamykane.

Typowe wartosci dla serwisu produkcyjnego

Dla serwisu z 10 instancjami i PostgreSQL z limitem 100 polaczyc: MaxOpenConns=8, MaxIdleConns=4, ConnMaxLifetime=5min. Suma MaxOpenConns * liczba instancji powinna byc mniejsza niz limit DB.

Migracje bazy danych

W srodowiskach produkcyjnych nigdy nie uzywamy AutoMigrate GORM — zmiany schematu musza byc wersjonowane, testowalne i odwracalne. Do tego sluza dedykowane narzedzia migracyjne.

golang-migrate

Pakiet github.com/golang-migrate/migrate/v4 obsluguje migracje SQL z plikow. Kazda migracja to para plikow: 001_create_users.up.sql i 001_create_users.down.sql. Mozna uruchamiac z CLI lub z poziomu Go w testach integracyjnych.

goose

github.com/pressly/goose/v3 to alternatywa z obsuga migracji SQL i Go. Migracje Go pozwalaja na skomplikowane transformacje danych niemozliwe w czystym SQL.

Dobre praktyki pracy z baza danych w Go

  • Zawsze przekazuj context.Context do zapytan (obsluga timeoutow i anulowania)
  • Zamykaj rows.Close() przez defer natychmiast po Query()
  • Sprawdzaj rows.Err() po petli iteracji
  • Uzyj transakcji (db.Begin()) dla operacji wymagajacych atomowosci
  • Nie przechowuj *sql.DB w zmiennych globalnych — wstrzykuj przez DI
