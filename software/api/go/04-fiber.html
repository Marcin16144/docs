Fiber Framework

Express-inspirowany framework oparty na fasthttp — maksymalna wydajnosc i minimalne zuzycie pamieci

fiber.New() i konfiguracja

Fiber jest zbudowany na bibliotece fasthttp zamiast standardowego net/http. Dzieki temu osiaga znacznie wyzszy throughput i nizsze zuzycie pamieci niz Gin czy Echo. Interfejs API jest inspirowany Express.js, co sprawia, ze jest intuicyjny dla deweloperow Node.js.

Glowne zastrzezenie: Fiber nie jest kompatybilny z net/http — middleware napisane dla Gin/Echo nie beda dzialac bezposrednio. To wazna decyzja architektoniczna przy wyborze frameworka.

package main

import (
    "log"
    "time"

    "github.com/gofiber/fiber/v2"
    "github.com/gofiber/fiber/v2/middleware/cors"
    "github.com/gofiber/fiber/v2/middleware/helmet"
    "github.com/gofiber/fiber/v2/middleware/limiter"
    "github.com/gofiber/fiber/v2/middleware/logger"
)

func main() {
    app := fiber.New(fiber.Config{
        AppName:               "MyAPI v1.0",
        ReadTimeout:           10 * time.Second,
        WriteTimeout:          10 * time.Second,
        IdleTimeout:           30 * time.Second,
        BodyLimit:             4 * 1024 * 1024, // 4 MB
        EnablePrintRoutes:     true,
        ErrorHandler:          customErrorHandler,
    })

    // Middleware bezpieczenstwa
    app.Use(helmet.New())
    app.Use(cors.New(cors.Config{
        AllowOrigins: "https://example.com",
        AllowHeaders: "Origin, Content-Type, Accept, Authorization",
        AllowMethods: "GET,POST,PUT,DELETE,OPTIONS",
    }))

    // Rate limiting: 20 req/min per IP
    app.Use(limiter.New(limiter.Config{
        Max:        20,
        Expiration: 1 * time.Minute,
    }))

    app.Use(logger.New())

    // Routing
    api := app.Group("/api/v1")
    api.Get("/users", listUsers)
    api.Post("/users", createUser)
    api.Get("/users/:id", getUser)

    log.Fatal(app.Listen(":8080"))
}

Routing i parametry

Fiber uzywa podobnej skladni do Express. Parametry sciezki sa dostepne przez c.Params("name"), query params przez c.Query("name"), a naglowki przez c.Get("Header-Name").

Grupy i prefiksy

  • app.Group("/prefix") — tworzy grupe tras z prefiksem
  • app.Route("/path", func(r fiber.Router){ ... }) — zagniezdzona konfiguracja
  • Grupy dziedzicza middleware zarejestrowane przez group.Use()

Parametry i wildcards

  • /users/:id — wymagany parametr
  • /files/* — wildcard (wszystko po /files/)
  • /users/:id? — opcjonalny parametr
  • c.Params("*") — wartosc wildcard

ctx.BodyParser i ctx.JSON

ctx.BodyParser(v) automatycznie wykrywa format ciala na podstawie Content-Type i deserializuje do wskazanej struktury. Obsluguje JSON, XML, form-data i URL-encoded. ctx.JSON(data) serializuje odpowiedz do JSON z kodem 200.

type CreateOrderRequest struct {
    ProductID int     `json:"product_id" validate:"required"`
    Quantity  int     `json:"quantity"   validate:"required,min=1"`
    Address   string  `json:"address"    validate:"required"`
    Total     float64 `json:"total"`
}

func createOrder(c *fiber.Ctx) error {
    var req CreateOrderRequest

    if err := c.BodyParser(&req); err != nil {
        return c.Status(fiber.StatusBadRequest).JSON(fiber.Map{
            "error": "niepoprawny format danych",
        })
    }

    // Walidacja (np. go-playground/validator)
    if req.Quantity < 1 {
        return c.Status(fiber.StatusUnprocessableEntity).JSON(fiber.Map{
            "error": "ilosc musi byc wieksza od 0",
        })
    }

    // Dostep do naglowkow i metadanych
    userID := c.Locals("userID")
    ip := c.IP()
    _ = ip

    return c.Status(fiber.StatusCreated).JSON(fiber.Map{
        "order_id":   1234,
        "user_id":    userID,
        "product_id": req.ProductID,
        "status":     "pending",
    })
}

// Wlasny handler bledow
func customErrorHandler(c *fiber.Ctx, err error) error {
    code := fiber.StatusInternalServerError
    if e, ok := err.(*fiber.Error); ok {
        code = e.Code
    }
    return c.Status(code).JSON(fiber.Map{
        "error": err.Error(),
        "code":  code,
    })
}

fasthttp internals — dlaczego Fiber jest szybszy

Standardowe net/http alokuje nowy obiekt http.Request dla kazdego zadania. fasthttp uzywa puli obiektow — RequestCtx jest reuzywany miedzy zadaniami, co drastycznie redukuje presje na garbage collector.

Wazne ostrzezenie dotyczace goroutines

Poniewaz fiber.Ctx jest reuzywany po zakonczeniu handlera, nie mozna przekazywac go do goroutine bez wczesniejszego skopiowania danych. Uzyj c.Body() i skopiuj dane przed uruchomieniem goroutine, albo uzyj c.Context() ktory zwraca kontekst z dluzsza zywotnoscia.

WebSocket w Fiber

Fiber ma wbudowane wsparcie WebSocket przez pakiet github.com/gofiber/websocket/v2. Upgrade polaczenia odbywa sie przez middleware websocket.New().

Kiedy wybrac Fiber?

  • Budujesz API o bardzo wysokim ruchu gdzie kazda milisekunda ma znaczenie
  • Chcesz minimalizowac zuzycie pamieci (np. srodowiska kontenerowe z limitami)
  • Twoj zespol zna Express.js i chce podobnego interfejsu w Go
  • Nie potrzebujesz interoperacyjnosci z istniejacym ekosystemem net/http
