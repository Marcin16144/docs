Testowanie Go API

testing, httptest, testify, gomock, testcontainers — pełna strategia testow od jednostkowych do integracyjnych

Pakiet testing — podstawy

Go ma wbudowany framework testowy w standardowej bibliotece. Pliki testowe maja sufiks _test.go i sa kompilowane tylko przy go test. Funkcje testowe musza miec prefiks Test i przyjmowac *testing.T.

package handlers_test

import (
    "testing"
    "time"
)

// Test jednostkowy — konwencja nazewnictwa: TestNazwaFunkcji_Scenariusz
func TestParseToken_ValidToken(t *testing.T) {
    token, err := GenerateToken(42, "admin")
    if err != nil {
        t.Fatalf("GenerateToken zwrocil blad: %v", err)
    }

    claims, err := ParseToken(token)
    if err != nil {
        t.Fatalf("ParseToken zwrocil blad: %v", err)
    }

    if claims.UserID != 42 {
        t.Errorf("oczekiwano UserID=42, got=%d", claims.UserID)
    }
    if claims.Role != "admin" {
        t.Errorf("oczekiwano role=admin, got=%s", claims.Role)
    }
}

// t.Run — podtesty (table-driven tests)
func TestCalculateDiscount(t *testing.T) {
    cases := []struct {
        name     string
        price    float64
        discount float64
        want     float64
    }{
        {"bez rabatu", 100, 0, 100},
        {"10 procent", 100, 0.10, 90},
        {"pelny rabat", 100, 1.0, 0},
        {"ujemna cena", -50, 0.10, 0}, // przypadek brzegowy
    }

    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            t.Parallel() // rownolegly test podrzedny
            got := CalculateDiscount(tc.price, tc.discount)
            if got != tc.want {
                t.Errorf("CalculateDiscount(%v, %v) = %v, want %v",
                    tc.price, tc.discount, got, tc.want)
            }
        })
    }
}

// TestMain — setup i teardown dla calego pakietu testowego
func TestMain(m *testing.M) {
    // Setup przed testami
    setupTestDB()
    code := m.Run()
    // Teardown po testach
    teardownTestDB()
    os.Exit(code)
}

httptest — testowanie handlerow HTTP

Pakiet net/http/httptest pozwala testowac handlery HTTP bez uruchamiania prawdziwego serwera. httptest.NewRecorder() to implementacja http.ResponseWriter zapisujaca odpowiedz w pamieci. httptest.NewRequest() tworzy syntetyczne zadanie.

import (
    "bytes"
    "encoding/json"
    "net/http"
    "net/http/httptest"
    "testing"

    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/require"
)

func TestCreateUserHandler(t *testing.T) {
    // Przygotowanie — mock repozytorium
    mockRepo := &MockUserRepository{}
    mockRepo.On("Create", mock.Anything, "Jan Kowalski", "jan@example.com").
        Return(&User{ID: 1, Name: "Jan Kowalski"}, nil)

    handler := NewUserHandler(mockRepo)
    router := setupRouter(handler) // gin.Default() z zarejestrowanymi trasami

    tests := []struct {
        name       string
        body       any
        wantStatus int
        wantID     int
    }{
        {
            name:       "poprawne dane",
            body:       map[string]string{"name": "Jan Kowalski", "email": "jan@example.com"},
            wantStatus: http.StatusCreated,
            wantID:     1,
        },
        {
            name:       "brak email",
            body:       map[string]string{"name": "Jan"},
            wantStatus: http.StatusBadRequest,
        },
        {
            name:       "puste body",
            body:       nil,
            wantStatus: http.StatusBadRequest,
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            var bodyBytes []byte
            if tt.body != nil {
                bodyBytes, _ = json.Marshal(tt.body)
            }

            req := httptest.NewRequest(http.MethodPost, "/api/v1/users",
                bytes.NewReader(bodyBytes))
            req.Header.Set("Content-Type", "application/json")
            req.Header.Set("Authorization", "Bearer "+validToken)

            w := httptest.NewRecorder()
            router.ServeHTTP(w, req)

            assert.Equal(t, tt.wantStatus, w.Code)

            if tt.wantID > 0 {
                var resp map[string]any
                require.NoError(t, json.Unmarshal(w.Body.Bytes(), &resp))
                assert.Equal(t, float64(tt.wantID), resp["id"])
            }
        })
    }
}

gomock — generowanie mockow

Pakiet go.uber.org/mock/gomock (fork oryginalnego golang/mock) generuje mocki na podstawie interfejsow. Narzedzie mockgen tworzy kod automatycznie — nie trzeba pisac mockow recznie.

Testy integracyjne z testcontainers-go

Pakiet github.com/testcontainers/testcontainers-go uruchamia prawdziwe kontenery Docker w testach. Dzieki temu testy integracyjne uzywaja prawdziwej bazy PostgreSQL zamiast in-memory stub — co eliminuje cala klase fałszywych pozytywow.

Wzorzec testow integracyjnych z PostgreSQL

W TestMain uruchamiasz kontener PostgreSQL, stosujesz migracje, a po testach kontener jest automatycznie usuwany. Kazdy test dostaje czysta baze przez transakcje z rollbackiem po tescie — t.Cleanup(func() { tx.Rollback() }).

Benchmarki

Funkcje benchmarkow maja prefiks Benchmark i przyjmuja *testing.B. Uruchamiasz je przez go test -bench=. -benchmem. Go automatycznie dostosowuje liczbe iteracji (b.N) do uzyskania wiarygodnych wynikow.

func BenchmarkParseToken(b *testing.B) {
    token, _ := GenerateToken(1, "user")
    b.ResetTimer() // reset po kosztownym setup

    b.RunParallel(func(pb *testing.PB) {
        for pb.Next() {
            _, err := ParseToken(token)
            if err != nil {
                b.Fatal(err)
            }
        }
    })
}

// Wynik: BenchmarkParseToken-8   523048   2284 ns/op   1024 B/op   12 allocs/op
// -8 = liczba CPU, ns/op = czas na operacje, B/op = alokacje pamieci

Race detector

Go ma wbudowany detektor wyścigów danych (race conditions). Uruchom testy z flagą -race aby znalezc niepoprawny dostep wspolbiezny do pamieci. Race detector spowalnia program ok. 5-10x, ale jest niezbedny w testach CI.

Komendy testowe — sciagawka

  • go test ./... — wszystkie testy w projekcie
  • go test -v ./handlers/... — verbose, tylko pakiet handlers
  • go test -run TestCreate ./... — tylko testy pasujace do wzorca
  • go test -race ./... — z detektorem wyscigów danych
  • go test -cover ./... — pokrycie kodu
  • go test -coverprofile=cover.out ./... && go tool cover -html=cover.out — raport HTML
  • go test -bench=. -benchmem -benchtime=5s ./... — benchmarki 5 sekund
  • go test -count=3 ./... — powtorz 3 razy (eliminuje flaky tests)
