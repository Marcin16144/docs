Chi Router

Idiomatyczny, lekki router dla Go — w pelni kompatybilny z net/http, kompozycyjne middleware, zero zaleznosci zewnetrznych

Filozofia Chi — minimalizm i idiomatycznosc

Chi jest routerem, nie frameworkiem. Nie narzuca struktury projektu, nie dostarcza systemu szablonow, bazy danych ani walidacji. Robi jedno i robi to dobrze: routuje zadania HTTP do handlerow. Kazdy handler to zwykly http.HandlerFunc — standard Go bez owijania.

Ta zgodnosc z net/http oznacza, ze mozesz uzywac dowolnego middleware napisanego dla standardowej biblioteki, np. golang.org/x/net/http2 czy pakietow do obslugi sesji i CORS.

package main

import (
    "encoding/json"
    "net/http"

    "github.com/go-chi/chi/v5"
    "github.com/go-chi/chi/v5/middleware"
    "github.com/go-chi/cors"
)

func main() {
    r := chi.NewRouter()

    // Middleware globalne — kompozycja przez Use()
    r.Use(middleware.RequestID)
    r.Use(middleware.RealIP)
    r.Use(middleware.Logger)
    r.Use(middleware.Recoverer)
    r.Use(middleware.Timeout(60 * time.Second))

    // CORS (go-chi/cors)
    r.Use(cors.Handler(cors.Options{
        AllowedOrigins: []string{"https://*.example.com"},
        AllowedMethods: []string{"GET", "POST", "PUT", "DELETE"},
        AllowedHeaders: []string{"Accept", "Authorization", "Content-Type"},
        MaxAge:         300,
    }))

    // Trasy
    r.Get("/", homeHandler)
    r.Get("/health", healthHandler)

    // Sub-router dla /api/v1
    r.Mount("/api/v1", apiRouter())

    http.ListenAndServe(":8080", r)
}

func apiRouter() http.Handler {
    r := chi.NewRouter()
    r.Use(authMiddleware) // middleware tylko dla /api/v1

    r.Get("/users", listUsers)
    r.Post("/users", createUser)

    r.Route("/users/{id}", func(r chi.Router) {
        r.Get("/", getUser)
        r.Put("/", updateUser)
        r.Delete("/", deleteUser)
        r.Get("/orders", getUserOrders)
    })

    return r
}

chi.URLParam — parametry sciezki

Chi przechowuje parametry URL w kontekscie zadania. Dostep przez chi.URLParam(r, "name") lub chi.URLParamFromCtx(ctx, "name"). Parametry sa dostepne w handlerach i w middleware wywolywanych po routowaniu.

func getUser(w http.ResponseWriter, r *http.Request) {
    // Pobranie parametru sciezki
    idStr := chi.URLParam(r, "id")
    id, err := strconv.Atoi(idStr)
    if err != nil {
        http.Error(w, "niepoprawne ID", http.StatusBadRequest)
        return
    }

    // Pobranie danych z kontekstu (ustawionych przez middleware)
    userID, _ := r.Context().Value(userIDKey).(int)

    user, err := db.FindUser(r.Context(), id)
    if err != nil {
        if errors.Is(err, sql.ErrNoRows) {
            http.Error(w, "nie znaleziono", http.StatusNotFound)
            return
        }
        http.Error(w, "blad serwera", http.StatusInternalServerError)
        return
    }

    _ = userID
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(user)
}

// Middleware ustawiajace dane w kontekscie
type contextKey string
const userIDKey contextKey = "userID"

func authMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        token := r.Header.Get("Authorization")
        if token == "" {
            http.Error(w, "brak autoryzacji", http.StatusUnauthorized)
            return
        }
        // Weryfikacja tokenu...
        ctx := context.WithValue(r.Context(), userIDKey, 42)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

Sub-routery i chi.Mount

Chi pozwala na montowanie calych sub-routerow pod okreslonym prefiksem przez r.Mount("/prefix", handler). Sub-router to zwykly http.Handler — moze byc kolejnym chi.Router lub dowolnym innym handlerem.

Metoda r.Route(pattern, fn) to skrot pozwalajacy zdefiniowac sub-router inline za pomoca funkcji konfiguracyjnej — przydatne dla zasobow RESTful (wszystkie operacje na /users/{id} w jednym miejscu).

chi.RouteContext i introspekcja

chi.RouteContext(ctx) zwraca obiekt *chi.Context zawierajacy informacje o trasie: dopasowany wzorzec, parametry URL i liste middleware. Przydatne w middleware do inspekcji lub logowania.

Idiomatyczny design API w Go z Chi

Chi promuje wzorzec gdzie kazdy zasob API to oddzielny typ implementujacy metody handlerow. Dzieki temu zaleznosci (DB, logger, cache) sa wstrzykiwane przez konstruktor, a nie przez zmienne globalne.

Wzorzec Resource Handler

Definiujesz typ UserHandler struct { db *sql.DB; log *slog.Logger }, nastepnie metody (h *UserHandler) List(w, r), Create(w, r) itd. Rejestrujesz przez h := NewUserHandler(db, log); r.Get("/users", h.List). To czyste, testowalne i idiomatyczne Go.

Wbudowane middleware Chi

  • middleware.RequestID — generuje unikalny ID dla kazdego zadania
  • middleware.RealIP — wyciaga prawdziwy IP z X-Forwarded-For
  • middleware.Logger — strukturalny log kazdego zadania
  • middleware.Recoverer — lapie paniki i zwraca 500
  • middleware.Compress(level) — gzip/br kompresja odpowiedzi
  • middleware.Timeout(d) — timeout kontekstu dla zadania
  • middleware.StripSlashes — usuwanie trailing slasha
  • middleware.Throttle(limit) — ograniczanie wspolbieznosci
