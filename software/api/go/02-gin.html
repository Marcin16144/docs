Gin Framework

Najszybszy full-featured router HTTP dla Go — wydajnosc, binding i middleware w jednym pakiecie

gin.Default() vs gin.New()

gin.Default() tworzy silnik z domyslnymi middleware: Logger (loguje kazde zadanie) i Recovery (lapie paniki i zwraca 500). To punkt startowy dla wiekszosci projektow.

gin.New() tworzy silnik bez zadnych middleware — maksymalna kontrola. Uzywamy go gdy chcemy sami wybrac middleware lub w benchmarkach gdzie logowanie znieksztalca wyniki.

package main

import (
    "net/http"
    "github.com/gin-gonic/gin"
)

func main() {
    // Wariant z domyslnymi middleware
    r := gin.Default()

    // Trasy globalne
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"message": "pong"})
    })

    // Grupa tras z prefiksem /api/v1
    v1 := r.Group("/api/v1")
    {
        v1.GET("/users", listUsers)
        v1.POST("/users", createUser)
        v1.GET("/users/:id", getUser)
        v1.PUT("/users/:id", updateUser)
        v1.DELETE("/users/:id", deleteUser)
    }

    // Uruchomienie na porcie 8080
    r.Run(":8080")
}

Parametry sciezki i query

Gin obsluguje dwa rodzaje parametrow URL: parametry sciezki (:name — wymagane) i query params (?key=val — opcjonalne). Dostep przez metody gin.Context.

Path params

  • c.Param("id") — zwraca wartosc parametru sciezki jako string
  • c.FullPath() — zwraca wzorzec sciezki (np. /users/:id)

Query params

  • c.Query("page") — zwraca wartosc lub pusty string
  • c.DefaultQuery("limit", "20") — zwraca wartosc lub domyslna
  • c.QueryMap("filter") — parsuje filter[key]=val

Binding — ShouldBindJSON i ShouldBindQuery

Binding to automatyczne parsowanie i walidacja danych wejsciowych. ShouldBind* zwraca blad zamiast przerywac zadanie. MustBind* ustawia status 400 i przerywa przy bledzie.

type CreateUserRequest struct {
    Name     string `json:"name"     binding:"required,min=2,max=100"`
    Email    string `json:"email"    binding:"required,email"`
    Age      int    `json:"age"      binding:"gte=18,lte=120"`
    Role     string `json:"role"     binding:"oneof=admin user guest"`
}

type ListUsersQuery struct {
    Page   int    `form:"page"   binding:"min=1"`
    Limit  int    `form:"limit"  binding:"min=1,max=100"`
    Search string `form:"search"`
    Sort   string `form:"sort"   binding:"oneof=asc desc"`
}

func createUser(c *gin.Context) {
    var req CreateUserRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
        return
    }
    // req jest wypelniony i zwalidowany
    c.JSON(http.StatusCreated, gin.H{"id": 42, "name": req.Name})
}

func listUsers(c *gin.Context) {
    var q ListUsersQuery
    q.Page = 1   // wartosci domyslne przed bindingiem
    q.Limit = 20
    if err := c.ShouldBindQuery(&q); err != nil {
        c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
        return
    }
    c.JSON(http.StatusOK, gin.H{"page": q.Page, "limit": q.Limit})
}

Gin uzywa pakietu go-playground/validator/v10 do walidacji. Tagi binding w strukturach mapuja sie bezposrednio na reguly walidatora. Mozna rejestrowac wlasne reguly przez gin.Validator.

Middleware

Middleware w Gin to funkcje przyjmujace *gin.Context i wywolujace c.Next() aby przekazac sterowanie dalej. Mozna je rejestrowac globalnie (r.Use()), na grupie lub na pojedynczej trasie.

Logger i Recovery

gin.Logger() loguje metode, sciezke, czas odpowiedzi i kod statusu. gin.Recovery() lapie panic, loguje stack trace i zwraca 500. Oba sa dolaczone przez gin.Default().

CORS

Pakiet github.com/gin-contrib/cors dostarcza konfigurowalny middleware CORS. Alternatywnie mozna uzyc github.com/rs/cors agnostycznie wobec frameworka.

Wlasny middleware — przyklad autoryzacji JWT

Middleware pobiera token z naglowka Authorization: Bearer <token>, weryfikuje podpis, a nastepnie ustawia c.Set("userID", claims.Subject) do uzycia w handlerach. Przy bledzie wywoluje c.AbortWithStatusJSON(401, ...).

gin.Context — najwazniejsze metody

gin.Context to serce kazdego handlera — zawiera zadanie, odpowiedz, parametry i dane przekazane przez middleware.

  • c.Request — oryginalny *http.Request
  • c.Writer — rozszerzony http.ResponseWriter
  • c.Set(key, val) / c.Get(key) — przekazywanie danych miedzy middleware
  • c.Abort() — przerywa lancuch middleware bez wysylania odpowiedzi
  • c.ClientIP() — adres IP klienta (uwzglednia X-Forwarded-For)
  • c.GetHeader("name") — odczyt naglowka zadania

Response helpers

  • c.JSON(status, obj) — serializuje obj do JSON
  • c.XML(status, obj) — serializuje do XML
  • c.String(status, format, vals...) — plain text
  • c.File(filepath) — wysyla plik
  • c.FileAttachment(filepath, name) — wymusza pobranie
  • c.Stream(step, reader) — strumieniowanie SSE / chunked
  • c.Redirect(status, url) — przekierowanie HTTP
