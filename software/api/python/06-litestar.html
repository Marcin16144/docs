Litestar

Nowoczesna alternatywa dla FastAPI — Router, Controller, DTO, Guards, lifecycle hooks, OpenAPI

Czym jest Litestar

Litestar (poprzednio Starlite) to pelno-funkcjonalny framework ASGI dla Pythona, zaprojektowany jako bardziej rygorystyczna i funkcjonalnie bogatsza alternatywa dla FastAPI. Glowne roznice: wbudowany system DTO (Data Transfer Object), bogatsza kontrola nad OpenAPI, bardziej restrykcyjne typowanie oraz wbudowany layer danych z SQLAlchemy.

Instalacja

uv add litestar[standard] uvicorn
Opcjonalnie z SQLAlchemy: uv add litestar[sqlalchemy]
Uruchomienie: uvicorn app:app --reload

Router i Controller

Litestar uzywa Controller jako klasy grupujacej endpointy o wspolnym prefix URL — podobnie do ViewSet w DRF, ale bardziej zblizone do klasy. Router pelni role analogiczna do FastAPI APIRouter.

from litestar import Litestar, get, post, put, patch, delete, Router
from litestar.controller import Controller
from litestar.di import Provide
from litestar.params import Parameter
from litestar.status_codes import HTTP_201_CREATED, HTTP_204_NO_CONTENT
from pydantic import BaseModel, Field
from typing import Annotated
import uuid

# ---- Schematy danych ----
class ProduktTworz(BaseModel):
    nazwa: str = Field(min_length=1, max_length=200)
    cena: float = Field(gt=0)
    kategoria: str = "ogolne"

class ProduktOdpowiedz(ProduktTworz):
    id: uuid.UUID
    aktywny: bool = True

# ---- Controller grupuje endpointy zasobu ----
class ProduktController(Controller):
    path = "/produkty"
    tags = ["produkty"]

    @get("/")
    async def lista(
        self,
        skip: Annotated[int, Parameter(ge=0)] = 0,
        limit: Annotated[int, Parameter(ge=1, le=100)] = 20,
    ) -> list[ProduktOdpowiedz]:
        """Zwroc paginowana liste produktow."""
        return []

    @post("/", status_code=HTTP_201_CREATED)
    async def utworz(self, data: ProduktTworz) -> ProduktOdpowiedz:
        """Utworz nowy produkt."""
        return ProduktOdpowiedz(id=uuid.uuid4(), **data.model_dump())

    @get("/{produkt_id:uuid}")
    async def pobierz(self, produkt_id: uuid.UUID) -> ProduktOdpowiedz:
        """Pobierz produkt po UUID."""
        return ProduktOdpowiedz(
            id=produkt_id, nazwa="Przykladowy", cena=49.99, kategoria="elektronika"
        )

    @patch("/{produkt_id:uuid}")
    async def aktualizuj(
        self, produkt_id: uuid.UUID, data: ProduktTworz
    ) -> ProduktOdpowiedz:
        """Czesciowa aktualizacja produktu."""
        return ProduktOdpowiedz(id=produkt_id, **data.model_dump())

    @delete("/{produkt_id:uuid}", status_code=HTTP_204_NO_CONTENT)
    async def usun(self, produkt_id: uuid.UUID) -> None:
        """Usun produkt."""
        return None

# ---- Router z prefixem ----
v1_router = Router(
    path="/api/v1",
    route_handlers=[ProduktController],
    tags=["v1"],
)

app = Litestar(route_handlers=[v1_router])

DTO — Data Transfer Objects

System DTO w Litestar pozwala oddzielic model wewnetrzny (np. SQLAlchemy ORM) od schematu API bez recznego pisania serializatorow. Litestar automatycznie konwertuje miedzy DTO a modelem wewnetrznym.

from litestar.dto import DataclassDTO, DTOConfig
from litestar.contrib.pydantic import PydanticDTO
from dataclasses import dataclass, field
from datetime import datetime

# ---- Wewnetrzny model domenowy (np. z ORM) ----
@dataclass
class UzytkownikModel:
    id: int
    email: str
    haslo_hash: str  # NIGDY nie wyslac do klienta!
    imie: str
    nazwisko: str
    rola: str = "user"
    utworzono: datetime = field(default_factory=datetime.utcnow)
    ostatnie_logowanie: datetime | None = None

# ---- DTO do odczytu — wyklucz haslo_hash ----
class UzytkownikReadDTO(DataclassDTO[UzytkownikModel]):
    config = DTOConfig(
        exclude={"haslo_hash"},  # pole nie pojawi sie w odpowiedzi
        rename_fields={"ostatnie_logowanie": "lastLogin"},  # camelCase dla frontendu
    )

# ---- DTO do tworzenia — tylko wybrane pola ----
class UzytkownikCreateDTO(DataclassDTO[UzytkownikModel]):
    config = DTOConfig(
        include={"email", "imie", "nazwisko"},  # tylko te pola w body
        partial=False,
    )

# ---- Endpoint z DTO ----
@post(
    "/uzytkownicy/",
    dto=UzytkownikCreateDTO,       # DTO do parsowania body
    return_dto=UzytkownikReadDTO,  # DTO do serializacji odpowiedzi
    status_code=HTTP_201_CREATED,
)
async def utworz_uzytkownika(data: UzytkownikModel) -> UzytkownikModel:
    # data jest juz gotowym UzytkownikModel (bez haslo_hash od klienta)
    data.haslo_hash = "bcrypt_hash_tutaj"
    data.id = 1
    return data  # haslo_hash automatycznie usuniete przez return_dto

Guards — kontrola dostepu

Guards w Litestar to odpowiednik middleware autoryzacyjnego — funkcje sprawdzajace czy uzytkownik ma dostep do endpointu. Moga byc aplikowane na poziomie aplikacji, routera lub pojedynczego endpointu.

Lifecycle hooks

Litestar oferuje bogatszy system hooks niz FastAPI — mozna definiowac hooki na poziomie kazdego routera, nie tylko globalnie.

Litestar vs FastAPI — porownanie

Cecha FastAPI Litestar
Walidacja Pydantic (wbudowany) Pydantic, attrs, dataclasses
System DTO Brak — reczne schematy Wbudowany (DataclassDTO, PydanticDTO)
Dokumentacja OpenAPI Automatyczna, podstawowa Rozbudowana konfiguracja, wiele formatow
Warstwa danych Brak — samodzielna integracja SQLAlchemyPlugin wbudowany
Guards (autoryzacja) Depends() + custom logic Dedykowany system Guards
Middleware Starlette BaseHTTPMiddleware Middleware + Before/After hooks
Popularnosc (GitHub stars) ~75k+ (dominuje rynek) ~5k+ (nisza, rosnacy)
Ekosystem wtyczek Ogromny Ograniczony, ale rosnie
Rygorystycznosc typow Srednia Wysoka — wymaga pelnych typow
Krzywa uczenia Niska-srednia Srednia-wysoka

Kiedy wybrac Litestar

Litestar sprawdzi sie gdy: potrzebujesz wbudowanego systemu DTO bez pisania dodatkowych serializatorow, zalezy ci na scislym typowaniu w calym projekcie, chcesz wbudowanej integracji SQLAlchemy lub budujesz duzy system gdzie separacja modelu od schematu API jest krytyczna.

OpenAPI customization

Litestar pozwala na szczegolowa kontrole schematu OpenAPI: wiele serwerow, security schemes, external docs, tag metadata — wszystko przez obiekt OpenAPIConfig przekazywany do konstruktora Litestar().
