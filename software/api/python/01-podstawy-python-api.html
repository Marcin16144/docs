Srodowiska wirtualne — venv vs uv

Kazdy projekt Python powinien miec izolowane srodowisko wirtualne. Tradycyjnym narzedziem jest wbudowany modul venv, jednak w 2024 roku pojawil sie uv — nowoczesny menezer pakietow i srodowisk wirtualnych napisany w Rust, ktory jest drastycznie szybszy.

Cecha venv + pip uv
Jezyk implementacji Python Rust
Szybkosc instalacji 1x (baseline) 10-100x szybciej
Tworzenie venv python -m venv .venv uv venv
Instalacja pakietu pip install fastapi uv add fastapi
Lock file requirements.txt (reczny) uv.lock (automatyczny)
pyproject.toml czesto pomijany natywna integracja
Wersje Pythona wymaga zewnetrznego narzedzia uv python install 3.12
Zgodnosc z pip pelen standard zgodny (drop-in replacement)

Rekomendacja

Uzywaj uv do nowych projektow. Dla istniejacych projektow z requirements.txt mozesz uzyc uv pip install -r requirements.txt bez zadnych zmian w workflow.

Konfiguracja projektu — pyproject.toml

Type Hints w Python 3.12+

Type hints sa fundamentem nowoczesnego Python API. Pozwalaja na statyczna analize kodu, lepsza dokumentacje i integracje z Pydantic. Python 3.12 wprowadzil kilka usprawnien skladni.

Nowa skladnia generykow (Python 3.12)

# Python 3.12 — nowy styl (PEP 695)
type Vector[T] = list[T]
type Matrix[T] = list[list[T]]

def pierwsza[T](lista: list[T]) -> T:
    return lista[0]

def para[T, U](a: T, b: U) -> tuple[T, U]:
    return a, b

# Wbudowane typy jako generyki (od 3.9)
def przetworz(dane: list[int]) -> dict[str, int]:
    return {"suma": sum(dane), "max": max(dane)}

# Typy unii (od 3.10)
def parsuj(wartosc: int | str | None) -> str:
    if wartosc is None:
        return "brak"
    return str(wartosc)

# TypeVar dla zaawansowanych przypadkow
from typing import TypeVar, Protocol

class Porownywalne(Protocol):
    def __lt__(self, other: object) -> bool: ...

P = TypeVar("P", bound=Porownywalne)

def minimum(a: P, b: P) -> P:
    return a if a < b else b

Pydantic v2 — walidacja danych

Pydantic v2 to kompletna przepisanie biblioteki (rdzen w Rust), oferujace 5-50x wieksza wydajnosc niz v1. Jest fundamentem FastAPI i de facto standardem walidacji danych w Python API.

BaseModel i Field

from pydantic import BaseModel, Field, model_validator, computed_field
from pydantic import EmailStr, HttpUrl
from typing import Annotated
from datetime import datetime
import uuid

# Alias typow z walidacja
PositiveInt = Annotated[int, Field(gt=0)]
ShortStr = Annotated[str, Field(min_length=1, max_length=100)]

class Adres(BaseModel):
    ulica: ShortStr
    miasto: ShortStr
    kod_pocztowy: str = Field(pattern=r"^\d{2}-\d{3}$")
    kraj: str = Field(default="PL", max_length=2)

class Uzytkownik(BaseModel):
    id: uuid.UUID = Field(default_factory=uuid.uuid4)
    imie: ShortStr
    nazwisko: ShortStr
    email: EmailStr
    wiek: PositiveInt
    adres: Adres | None = None
    utworzono: datetime = Field(default_factory=datetime.utcnow)
    tagi: list[str] = Field(default_factory=list)

    # Walidator calego modelu
    @model_validator(mode="after")
    def sprawdz_wiek_email(self) -> "Uzytkownik":
        if self.wiek < 18 and self.email.endswith(".edu") is False:
            raise ValueError("Osoby niepelnoletnie moga uzyc tylko adresu .edu")
        return self

    # Pole obliczane (nie zapisywane do DB)
    @computed_field
    @property
    def pelne_imie(self) -> str:
        return f"{self.imie} {self.nazwisko}"

    model_config = {
        "str_strip_whitespace": True,
        "validate_assignment": True,
        "json_schema_extra": {
            "example": {
                "imie": "Jan",
                "nazwisko": "Kowalski",
                "email": "jan@example.com",
                "wiek": 30,
            }
        }
    }

# Uzycie
u = Uzytkownik(imie="Jan", nazwisko="Kowalski", email="jan@example.com", wiek=30)
print(u.pelne_imie)        # "Jan Kowalski"
print(u.model_dump())      # slownik
print(u.model_dump_json()) # JSON string

httpx — asynchroniczny klient HTTP

httpx to nowoczesny klient HTTP dla Pythona, wspierajacy zarowno synchroniczne jak i asynchroniczne uzycie. Jest naturalnym nastepca requests z pelnym wsparciem dla HTTP/2 i async/await.

requests vs httpx

Biblioteka requests nie obsluguje async/await. Jesli budujesz aplikacje FastAPI lub inne ASGI, uzywaj httpx — ma identyczne API dla czesci synchronicznej i dodaje AsyncClient dla async.

dataclasses vs Pydantic

Python oferuje wbudowane dataclasses jako lzejsza alternatywe. Wybor miedzy nimi zalezy od kontekstu:

  • dataclasses — brak walidacji, szybkie tworzenie instancji, brak zaleznosci zewnetrznych, dobre dla wewnetrznych struktur danych
  • Pydantic BaseModel — pelna walidacja, serializacja JSON, schematy OpenAPI, integracja z FastAPI — wybieraj dla danych z zewnatrz (API, bazy danych, pliki)
  • Pydantic dataclasses — polaczenie obu: skladnia dataclass + walidacja Pydantic, przydatne przy migracji kodu
