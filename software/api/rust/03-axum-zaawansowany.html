Axum — zaawansowany

Middleware z tower, obsluga bledow, WebSocket, multipart upload, tower-http i wspoldzielony stan aplikacji.

Middleware z tower — ServiceBuilder

Axum jest zbudowany na tower, wiec kazdy Service i Layer z ekosystemu tower dziala bezposrednio. ServiceBuilder pozwala laczyc warstwy middleware w czytelny lancuch. Kolejnosc ma znaczenie: pierwsza dodana warstwa jest najbardziej zewnetrzna (pierwsza przetwarza request, ostatnia odpowiedz).

use axum::Router;
use tower::ServiceBuilder;
use tower_http::{
    cors::CorsLayer,
    trace::TraceLayer,
    compression::CompressionLayer,
    timeout::TimeoutLayer,
    limit::RequestBodyLimitLayer,
};
use std::time::Duration;

let middleware_stack = ServiceBuilder::new()
    .layer(TraceLayer::new_for_http())
    .layer(CorsLayer::permissive())          // dev only!
    .layer(CompressionLayer::new())
    .layer(TimeoutLayer::new(Duration::from_secs(30)))
    .layer(RequestBodyLimitLayer::new(5 * 1024 * 1024)); // 5 MB

let app = Router::new()
    .route("/users", get(list_users))
    .layer(middleware_stack)
    .with_state(state);

CorsLayer — konfiguracja produkcyjna

W produkcji nie uzywaj CorsLayer::permissive(). Zdefiniuj dozwolone zrodla jawnie:

use tower_http::cors::{CorsLayer, Any};
use axum::http::{HeaderName, Method};

let cors = CorsLayer::new()
    .allow_origin(["https://app.example.com".parse().unwrap()])
    .allow_methods([Method::GET, Method::POST, Method::PUT, Method::DELETE])
    .allow_headers([
        HeaderName::from_static("content-type"),
        HeaderName::from_static("authorization"),
    ])
    .allow_credentials(true)
    .max_age(Duration::from_secs(3600));

Custom middleware — from_fn

Najprostszy sposob na wlasne middleware to axum::middleware::from_fn. Funkcja middleware otrzymuje request i Next — wywolujac next.run(req) przekazujemy request dalej w lancuchu.

use axum::{middleware::{self, Next}, extract::Request, response::Response};
use axum::http::StatusCode;

async fn auth_middleware(
    State(state): State<Arc<AppState>>,
    req: Request,
    next: Next,
) -> Result<Response, StatusCode> {
    let token = req
        .headers()
        .get("Authorization")
        .and_then(|v| v.to_str().ok())
        .and_then(|v| v.strip_prefix("Bearer "));

    match token {
        Some(t) if validate_token(t, &state.jwt_secret) => {
            Ok(next.run(req).await)
        }
        _ => Err(StatusCode::UNAUTHORIZED),
    }
}

// Rejestracja tylko dla wybranych tras:
let protected = Router::new()
    .route("/profile", get(profile_handler))
    .layer(middleware::from_fn_with_state(state.clone(), auth_middleware));

AppError implementing IntoResponse

Zamiast zwracac StatusCode z handlerow, zdefiniuj wlasny typ bledu ktory implementuje IntoResponse. Dzieki temu handlery zwracaja Result<T, AppError> i mozesz uzywac operatora ?.

Wariant AppErrorHTTP StatusOdpowiedz JSONZrodlo
NotFound(String)404{"error": "...", "code": "NOT_FOUND"}logika biznesowa
Unauthorized401{"error": "Unauthorized"}middleware / JWT
Forbidden403{"error": "Forbidden"}RBAC
Validation(String)422{"error": "...", "field": "..."}deserializacja / guard
Database(sqlx::Error)500{"error": "Internal error"}#[from] sqlx
Internal(anyhow::Error)500{"error": "Internal error"}catchall
 
use axum::{response::{IntoResponse, Response}, Json, http::StatusCode};
use thiserror::Error;
use serde_json::json;

#[derive(Debug, Error)]
pub enum AppError {
    #[error("{0}")]
    NotFound(String),
    #[error("Unauthorized")]
    Unauthorized,
    #[error("{0}")]
    Validation(String),
    #[error(transparent)]
    Database(#[from] sqlx::Error),
    #[error(transparent)]
    Internal(#[from] anyhow::Error),
}

impl IntoResponse for AppError {
    fn into_response(self) -> Response {
        let (status, message) = match &self {
            AppError::NotFound(m)    => (StatusCode::NOT_FOUND, m.clone()),
            AppError::Unauthorized   => (StatusCode::UNAUTHORIZED, "Unauthorized".into()),
            AppError::Validation(m)  => (StatusCode::UNPROCESSABLE_ENTITY, m.clone()),
            AppError::Database(e)    => {
                tracing::error!("DB error: {e}");
                (StatusCode::INTERNAL_SERVER_ERROR, "Database error".into())
            }
            AppError::Internal(e)    => {
                tracing::error!("Internal: {e}");
                (StatusCode::INTERNAL_SERVER_ERROR, "Internal error".into())
            }
        };
        (status, Json(json!({"error": message}))).into_response()
    }
}

Wspoldzielony stan — Arc<AppState>

Stan aplikacji jest tworzony raz i wspoldzielony miedzy wszystkimi handlerami. Arc<T> zapewnia thread-safe reference counting. Wewnetrzna mutowalnosc realizujemy przez RwLock lub Mutex z Tokio (nie blokuja watku OS).

#[derive(Clone)]
pub struct AppState {
    pub db: sqlx::PgPool,
    pub config: Arc<Config>,
    pub redis: redis::aio::ConnectionManager,
}

impl AppState {
    pub async fn new() -> anyhow::Result<Self> {
        let db = PgPoolOptions::new()
            .max_connections(20)
            .connect(&std::env::var("DATABASE_URL")?)
            .await?;
        Ok(Self {
            db,
            config: Arc::new(Config::from_env()?),
            redis: /* ... */,
        })
    }
}

// Uzycie w handlerze:
async fn handler(State(state): State<Arc<AppState>>) -> impl IntoResponse {
    // state.db, state.config, state.redis
}

WebSocket handler

Axum wspiera WebSocket przez WebSocketUpgrade extractor. Po upgrade, handler dostaje WebSocket — strumien wiadomosci.

use axum::extract::ws::{WebSocketUpgrade, WebSocket, Message};

async fn ws_handler(ws: WebSocketUpgrade) -> impl IntoResponse {
    ws.on_upgrade(handle_socket)
}

async fn handle_socket(mut socket: WebSocket) {
    while let Some(Ok(msg)) = socket.recv().await {
        match msg {
            Message::Text(t) => {
                if socket.send(Message::Text(format!("Echo: {t}"))).await.is_err() {
                    break;
                }
            }
            Message::Close(_) => break,
            _ => {}
        }
    }
}

Multipart upload

Do obslugi uploadow plikow uzyj extractora Multipart. Pamietaj o ograniczeniu rozmiaru przez RequestBodyLimitLayer.

use axum::extract::Multipart;

async fn upload_file(mut multipart: Multipart) -> impl IntoResponse {
    while let Some(field) = multipart.next_field().await.unwrap_or(None) {
        let name = field.name().unwrap_or("unknown").to_string();
        let filename = field.file_name().map(str::to_string);
        let data = field.bytes().await.unwrap_or_default();

        tracing::info!("Pole: {name}, plik: {:?}, rozmiar: {}", filename, data.len());
        // zapis na dysk lub do cloud storage
    }
    StatusCode::OK
}
Extension<T> vs State<T>: State<T> jest zalecane dla stanu aplikacji — jest sprawdzane w czasie kompilacji i ma lepszą wydajnosc. Extension<T> uzywa TypeMap i jest przydatne gdy chcesz przekazac dane z middleware do handlera (np. zalogowanego uzytkownika po weryfikacji JWT).
