Actix-web

Jeden z najszybszych frameworkow webowych na swiecie. Oparty na aktorach i asynchronicznym modelu Tokio, z bogatym ekosystemem middleware.

HttpServer i App — punkt wejscia

HttpServer::new() tworzy serwer HTTP. Przyjmuje domkniecie (|| App::new()) — jest ono wywolywane osobno dla kazdego watku roboczego, dlatego stan musi implementowac Send + Sync lub byc opakowany w web::Data<T>.

use actix_web::{web, App, HttpServer, HttpResponse, middleware};

#[actix_web::main]
async fn main() -> std::io::Result<()> {
    dotenvy::dotenv().ok();
    tracing_subscriber::fmt::init();

    let db_pool = PgPoolOptions::new()
        .max_connections(20)
        .connect(&std::env::var("DATABASE_URL").unwrap())
        .await
        .expect("Nie mozna polaczyc z baza");

    let shared_pool = web::Data::new(db_pool);

    HttpServer::new(move || {
        App::new()
            .app_data(shared_pool.clone())
            .app_data(web::JsonConfig::default()
                .limit(1_048_576)                  // 1 MB limit body
                .error_handler(json_error_handler))
            .wrap(middleware::Logger::default())
            .wrap(middleware::Compress::default())
            .configure(user_routes)
            .configure(product_routes)
            .route("/health", web::get().to(health_check))
    })
    .bind("0.0.0.0:8080")?
    .workers(4)
    .run()
    .await
}

Handlery i rejestracja tras

Handlery to async funkcje zwracajace dowolny typ implementujacy Responder. Trasy rejestrujemy przez web::get().to(handler) lub makra atrybutowe #[get("/path")]. Funkcja .configure() pozwala grupowac trasy w osobnych modulach.

use actix_web::{get, post, put, delete, web, HttpResponse, Responder};
use serde::{Deserialize, Serialize};

#[derive(Deserialize)]
struct ListQuery {
    page: Option<u32>,
    limit: Option<u32>,
    search: Option<String>,
}

#[derive(Serialize)]
struct User { id: i64, name: String, email: String }

// GET /users?page=1&limit=10
#[get("/users")]
async fn list_users(
    db: web::Data<sqlx::PgPool>,
    query: web::Query<ListQuery>,
) -> impl Responder {
    let page = query.page.unwrap_or(1);
    HttpResponse::Ok().json(vec![/* users */])
}

// GET /users/{id}
#[get("/users/{id}")]
async fn get_user(
    db: web::Data<sqlx::PgPool>,
    path: web::Path<i64>,
) -> impl Responder {
    let id = path.into_inner();
    // ...
    HttpResponse::NotFound().json(serde_json::json!({"error": "nie znaleziono"}))
}

// POST /users
#[post("/users")]
async fn create_user(
    db: web::Data<sqlx::PgPool>,
    body: web::Json<CreateUserRequest>,
) -> impl Responder {
    // body.email, body.name
    HttpResponse::Created().json(/* nowy user */)
}

pub fn user_routes(cfg: &mut web::ServiceConfig) {
    cfg.service(list_users)
       .service(get_user)
       .service(create_user);
}

web::Data<T> — wspoldzielony stan

web::Data<T> to opakowanie na Arc<T>. Rejestrujemy je przez .app_data(web::Data::new(value)) na poziomie App. W handlerach extractujemy jako parametr funkcji — Actix automatycznie wstrzykuje odpowiedni typ.

Uwaga: Jesli twoj stan wymaga mutowalnosci, uzyj web::Data<Mutex<T>> lub web::Data<RwLock<T>>. Dla polaczen z baza danych pool (PgPool) jest juz wewnetrznie thread-safe.

Middleware — Logger, Compress, wrap_fn

Actix dostarcza wbudowane middleware przez .wrap(). Mozna tez tworzyc proste middleware przez wrap_fn:

use actix_web::dev::{ServiceRequest, ServiceResponse};
use actix_web::middleware::Next;

// Prosty timing middleware
App::new()
    .wrap_fn(|req, srv| {
        let start = std::time::Instant::now();
        let path = req.path().to_string();
        let fut = srv.call(req);
        async move {
            let res = fut.await?;
            let elapsed = start.elapsed().as_millis();
            tracing::info!("{path} — {elapsed}ms");
            Ok(res)
        }
    })
    .wrap(actix_cors::Cors::default()
        .allowed_origin("https://app.example.com")
        .allowed_methods(vec!["GET", "POST", "PUT", "DELETE"])
        .allowed_headers(vec!["Content-Type", "Authorization"])
        .max_age(3600))
    .wrap(middleware::Logger::new("%r %s %Dms"))
    .wrap(middleware::Compress::default())

ResponseError — obsluga bledow

Wlasne typy bledow musza implementowac trait ResponseError z actix-web. Zapewnia on metody status_code() i error_response().

use actix_web::{ResponseError, HttpResponse};
use thiserror::Error;

#[derive(Debug, Error)]
pub enum ApiError {
    #[error("Nie znaleziono: {0}")]
    NotFound(String),
    #[error("Blad bazy danych")]
    Database(#[from] sqlx::Error),
    #[error("Nieautoryzowany")]
    Unauthorized,
}

impl ResponseError for ApiError {
    fn status_code(&self) -> actix_web::http::StatusCode {
        match self {
            ApiError::NotFound(_)  => actix_web::http::StatusCode::NOT_FOUND,
            ApiError::Unauthorized => actix_web::http::StatusCode::UNAUTHORIZED,
            ApiError::Database(_)  => actix_web::http::StatusCode::INTERNAL_SERVER_ERROR,
        }
    }

    fn error_response(&self) -> HttpResponse {
        HttpResponse::build(self.status_code())
            .json(serde_json::json!({"error": self.to_string()}))
    }
}

// Handler moze teraz zwracac Result<HttpResponse, ApiError>:
async fn get_user(path: web::Path<i64>, db: web::Data<PgPool>)
    -> Result<HttpResponse, ApiError>
{
    let user = find_user(*path, &db).await?;  // ? konwertuje sqlx::Error
    Ok(HttpResponse::Ok().json(user))
}

web::scope — grupowanie tras

web::scope() pozwala nadac wspolny prefiks grupie tras i zastosowac do nich wspolne middleware (np. autoryzacje):

App::new()
    .service(
        web::scope("/api/v1")
            .service(
                web::scope("/admin")
                    .wrap(AdminAuthMiddleware)
                    .service(admin_routes())
            )
            .service(user_routes())
            .service(product_routes())
    )
    .route("/health", web::get().to(health))
