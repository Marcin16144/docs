SQLx

Asynchroniczny klient SQL z weryfikacja zapytan w czasie kompilacji. Wspiera PostgreSQL, MySQL i SQLite bez ORM — piszesz czyste SQL.

PgPool — pula polaczen

sqlx::PgPool to thread-safe pula polaczen do PostgreSQL. Tworzymy ja przez PgPoolOptions::new() z konfiguracja limitow. Pool implementuje Clone — klonowan jest tylko Arc wewnetrzny, nie samo polaczenie.

use sqlx::postgres::{PgPool, PgPoolOptions};
use std::time::Duration;

pub async fn create_pool(database_url: &str) -> anyhow::Result<PgPool> {
    let pool = PgPoolOptions::new()
        .max_connections(20)
        .min_connections(5)
        .acquire_timeout(Duration::from_secs(5))
        .idle_timeout(Duration::from_secs(600))
        .max_lifetime(Duration::from_secs(1800))
        .connect(database_url)
        .await?;

    // Sprawdz polaczenie zaraz po starcie
    sqlx::query("SELECT 1").execute(&pool).await?;
    tracing::info!("Polaczenie z PostgreSQL ustanowione");

    Ok(pool)
}

// Przekazywanie przez Arc lub bezposrednio (PgPool juz uzywa Arc wewnetrznie)
let pool = create_pool(&std::env::var("DATABASE_URL")?).await?;
let app_state = Arc::new(AppState { db: pool });

query! i query_as! — compile-time SQL

Makra query! i query_as! sa gwiazdami SQLx. Podczas kompilacji lacza sie z baza danych (przez DATABASE_URL), weryfikuja poprawnosc SQL i typy kolumn, a zwracany rekord ma pola z typami Rust dopasowanymi do schematu bazy.

Wymaganie: Zmienna DATABASE_URL musi byc dostepna podczas cargo build. W CI uzyj sqlx prepare do wygenerowania pliku .sqlx/ z cache zapytan — pozwala budowac bez dostepu do bazy (SQLX_OFFLINE=true). 
use sqlx::PgPool;

#[derive(Debug, sqlx::FromRow)]
pub struct User {
    pub id: i64,
    pub name: String,
    pub email: String,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub is_active: bool,
}

// query_as! mapuje wyniki na struct (musi implementowac FromRow)
pub async fn find_user_by_id(pool: &PgPool, id: i64) -> sqlx::Result<Option<User>> {
    sqlx::query_as!(
        User,
        "SELECT id, name, email, created_at, is_active
         FROM users
         WHERE id = $1 AND is_active = true",
        id
    )
    .fetch_optional(pool)
    .await
}

// query! — anonimowy rekord z polami
pub async fn count_users(pool: &PgPool) -> sqlx::Result<i64> {
    let row = sqlx::query!("SELECT COUNT(*) as count FROM users")
        .fetch_one(pool)
        .await?;
    Ok(row.count.unwrap_or(0))
}

// INSERT zwracajacy id
pub async fn create_user(pool: &PgPool, name: &str, email: &str) -> sqlx::Result<i64> {
    let row = sqlx::query!(
        "INSERT INTO users (name, email) VALUES ($1, $2) RETURNING id",
        name, email
    )
    .fetch_one(pool)
    .await?;
    Ok(row.id)
}

// UPDATE — sprawdzenie ile wierszy zmieniono
pub async fn deactivate_user(pool: &PgPool, id: i64) -> sqlx::Result<bool> {
    let result = sqlx::query!(
        "UPDATE users SET is_active = false WHERE id = $1",
        id
    )
    .execute(pool)
    .await?;
    Ok(result.rows_affected() == 1)
}

// Streaming duzych zbiorow
use futures::StreamExt;
pub async fn stream_all_users(pool: &PgPool) -> sqlx::Result<()> {
    let mut stream = sqlx::query_as!(User, "SELECT * FROM users")
        .fetch(pool);
    while let Some(user) = stream.next().await {
        let user = user?;
        process_user(user).await;
    }
    Ok(())
}

Transakcje

Transakcje startujemy przez pool.begin(). Zwracany obiekt Transaction implementuje Executor — uzywamy go zamiast poola w zapytaniach. Drop bez .commit() automatycznie wykonuje ROLLBACK.

pub async fn transfer_funds(
    pool: &PgPool,
    from_id: i64,
    to_id: i64,
    amount: i64,
) -> anyhow::Result<()> {
    let mut tx = pool.begin().await?;

    sqlx::query!(
        "UPDATE accounts SET balance = balance - $1 WHERE id = $2 AND balance >= $1",
        amount, from_id
    )
    .execute(&mut *tx)
    .await?;

    sqlx::query!(
        "UPDATE accounts SET balance = balance + $1 WHERE id = $2",
        amount, to_id
    )
    .execute(&mut *tx)
    .await?;

    sqlx::query!(
        "INSERT INTO transfers (from_id, to_id, amount) VALUES ($1, $2, $3)",
        from_id, to_id, amount
    )
    .execute(&mut *tx)
    .await?;

    tx.commit().await?;
    Ok(())
}

sqlx-cli — migracje

Narzedzie sqlx-cli zarzadza migracjami bazy danych. Instalacja: cargo install sqlx-cli --no-default-features --features postgres.

# Tworzenie nowej migracji
sqlx migrate add create_users_table

# Uruchomienie migracji (DATABASE_URL z .env)
sqlx migrate run

# Cofniecie ostatniej migracji
sqlx migrate revert

# Sprawdzenie statusu
sqlx migrate info

# Generowanie cache zapytan dla offline builds
sqlx prepare

# Plik migracji: migrations/20240101000000_create_users_table.sql
CREATE TABLE users (
    id         BIGSERIAL PRIMARY KEY,
    name       TEXT NOT NULL,
    email      TEXT NOT NULL UNIQUE,
    is_active  BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_users_email ON users (email);
CREATE INDEX idx_users_active ON users (is_active) WHERE is_active = true;

LISTEN / NOTIFY — real-time eventy

PostgreSQL LISTEN/NOTIFY pozwala na asynchroniczne powiadomienia miedzy polaczeniami. SQLx wspiera to przez PgListener:

use sqlx::postgres::PgListener;

async fn start_listener(database_url: &str) -> anyhow::Result<()> {
    let mut listener = PgListener::connect(database_url).await?;
    listener.listen("user_created").await?;
    listener.listen("order_completed").await?;

    loop {
        let notification = listener.recv().await?;
        tracing::info!(
            channel = notification.channel(),
            payload = notification.payload(),
            "Otrzymano notyfikacje"
        );
        // przetwarzanie eventu...
    }
}

// Wysylanie notyfikacji z handlera:
sqlx::query!("SELECT pg_notify('user_created', $1)", user_id.to_string())
    .execute(pool)
    .await?;
