SeaORM

Asynchroniczny ORM dla Rust oparty na SQLx. Oferuje model Entity, ActiveModel, relacje i wbudowany query builder — SeaQuery.

Entity — model danych

W SeaORM kazda tabela reprezentowana jest przez modul z kilkoma strukturami. Makro DeriveEntityModel generuje implementacje dla Model, ActiveModel, Entity i Column na podstawie jednej anotowanej struktury.

use sea_orm::entity::prelude::*;

// src/entities/user.rs
#[derive(Clone, Debug, PartialEq, DeriveEntityModel, Eq)]
#[sea_orm(table_name = "users")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: i64,
    pub name: String,
    #[sea_orm(unique)]
    pub email: String,
    pub is_active: bool,
    pub role: UserRole,
    pub created_at: DateTimeUtc,
}

// Enum mapowany na kolumne
#[derive(Clone, Debug, PartialEq, Eq, EnumIter, DeriveActiveEnum)]
#[sea_orm(rs_type = "String", db_type = "Text")]
pub enum UserRole {
    #[sea_orm(string_value = "admin")]
    Admin,
    #[sea_orm(string_value = "user")]
    User,
    #[sea_orm(string_value = "moderator")]
    Moderator,
}

// Relacje
#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {
    #[sea_orm(has_many = "super::post::Entity")]
    Posts,
    #[sea_orm(has_one = "super::profile::Entity")]
    Profile,
}

impl Related<super::post::Entity> for Entity {
    fn to() -> RelationDef { Relation::Posts.def() }
}

impl ActiveModelBehavior for ActiveModel {}

ActiveModel — zapis i aktualizacja

ActiveModel to wersja modelu do zapisu — kazde pole opakowan jest w ActiveValue: Set(value) (zostanie zapisane), NotSet (pomijane w UPDATE), Unchanged(value) (bez zmian). Dzieki temu UPDATE zmienia tylko wskazane pola.

use sea_orm::{ActiveModelTrait, ActiveValue::Set, TryIntoModel};
use crate::entities::user::{self, ActiveModel};

// INSERT — nowy rekord
pub async fn create_user(
    db: &DatabaseConnection,
    name: String,
    email: String,
) -> anyhow::Result<user::Model> {
    let new_user = ActiveModel {
        name: Set(name),
        email: Set(email),
        is_active: Set(true),
        role: Set(user::UserRole::User),
        ..Default::default()  // id i created_at generowane przez DB
    };

    let user = new_user.insert(db).await?;
    Ok(user)
}

// UPDATE — tylko zmienione pola
pub async fn update_user_name(
    db: &DatabaseConnection,
    id: i64,
    new_name: String,
) -> anyhow::Result<user::Model> {
    let user = user::ActiveModel {
        id: Set(id),
        name: Set(new_name),
        ..Default::default()
    };
    let updated = user.update(db).await?;
    Ok(updated)
}

// UPDATE z istniejacego modelu
pub async fn deactivate_user(db: &DatabaseConnection, id: i64) -> anyhow::Result<()> {
    let user = user::Entity::find_by_id(id)
        .one(db).await?
        .ok_or(anyhow::anyhow!("Nie znaleziono uzytkownika"))?;

    let mut active: user::ActiveModel = user.into();
    active.is_active = Set(false);
    active.update(db).await?;
    Ok(())
}

Zapytania — find, find_by_id, find_related

SeaORM oferuje bogaty API do budowania zapytan. Metody mozna laczyc w lancuch przed finalnym .all(), .one() lub .count().

use sea_orm::{EntityTrait, QueryFilter, QueryOrder, QuerySelect, ColumnTrait};
use crate::entities::user;

// Pobierz wszystkich aktywnych uzytkownikow
let users = user::Entity::find()
    .filter(user::Column::IsActive.eq(true))
    .filter(user::Column::Role.eq(user::UserRole::Admin))
    .order_by_desc(user::Column::CreatedAt)
    .limit(20)
    .offset(0)
    .all(db)
    .await?;

// Pobierz przez primary key
let user = user::Entity::find_by_id(42).one(db).await?;

// Relacje — posty uzytkownika
let user_with_posts = user::Entity::find_by_id(1)
    .find_with_related(post::Entity)
    .all(db)
    .await?;

// Wynik: Vec<(user::Model, Vec<post::Model>)>
for (user, posts) in user_with_posts {
    println!("{}: {} postow", user.name, posts.len());
}

Condition — zlozony filtrowanie

Condition::all() tworzy AND, Condition::any() tworzy OR. Mozna je zagniezdac dowolnie.

use sea_orm::Condition;

let condition = Condition::all()
    .add(user::Column::IsActive.eq(true))
    .add(
        Condition::any()
            .add(user::Column::Role.eq(user::UserRole::Admin))
            .add(user::Column::Role.eq(user::UserRole::Moderator))
    );

let users = user::Entity::find()
    .filter(condition)
    .all(db)
    .await?;

pub async fn list_users_paginated(
    db: &DatabaseConnection,
    page: u64,
    page_size: u64,
) -> anyhow::Result<(Vec<user::Model>, u64)> {
    let paginator = user::Entity::find()
        .filter(user::Column::IsActive.eq(true))
        .order_by_asc(user::Column::Name)
        .paginate(db, page_size);

    let total_pages = paginator.num_pages().await?;
    let users = paginator.fetch_page(page - 1).await?;  // 0-indexed!

    Ok((users, total_pages))
}

Migracje — MigrationTrait i SchemaManager

SeaORM dostarcza wlasny system migracji oparty na Rust (nie SQL). Migracje to struktury implementujace MigrationTrait z metodami up() i down().

use sea_orm_migration::prelude::*;

#[derive(DeriveMigrationName)]
pub struct Migration;

#[async_trait::async_trait]
impl MigrationTrait for Migration {
    async fn up(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        manager.create_table(
            Table::create()
                .table(Users::Table)
                .if_not_exists()
                .col(ColumnDef::new(Users::Id).big_integer().primary_key().auto_increment())
                .col(ColumnDef::new(Users::Name).text().not_null())
                .col(ColumnDef::new(Users::Email).text().not_null().unique_key())
                .col(ColumnDef::new(Users::IsActive).boolean().not_null().default(true))
                .col(ColumnDef::new(Users::CreatedAt).timestamp_with_time_zone().not_null())
                .to_owned()
        ).await
    }

    async fn down(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        manager.drop_table(Table::drop().table(Users::Table).to_owned()).await
    }
}

#[derive(Iden)]
enum Users { Table, Id, Name, Email, IsActive, CreatedAt }
