Rocket

Framework webowy stawiajacy na ergonomie i bezpieczenstwo typow. Od wersji 0.5 w pelni asynchroniczny, oparty na Tokio.

Punkt wejscia — #[launch] i #[rocket::main]

Rocket oferuje dwa sposoby uruchomienia aplikacji. #[launch] jest zalecany — funkcja zwraca Rocket<Build>, a Rocket sam uruchamia runtime. #[rocket::main] daje pelna kontrole nad inicjalizacja.

use rocket::{launch, routes, get, post, Build, Rocket};

// Zalecane — Rocket sam uruchamia runtime
#[launch]
fn rocket() -> Rocket<Build> {
    rocket::build()
        .mount("/", routes![index, health])
        .mount("/api/v1", routes![
            list_users, get_user, create_user, update_user, delete_user
        ])
        .attach(DbFairing::init())
        .attach(AdHoc::config::<AppConfig>())
        .manage(/* shared state */)
}

// Alternatywa z pelna kontrola
#[rocket::main]
async fn main() -> Result<(), rocket::Error> {
    let _rocket = rocket::build()
        .mount("/", routes![index])
        .launch()
        .await?;
    Ok(())
}

Route macros — #[get], #[post] i inne

Trasy definiujemy makrami atrybutowymi bezposrednio nad funkcjami. Rocket parsuje sciezke, metode HTTP i format w czasie kompilacji, wykrywajac konflikty i bledy przed uruchomieniem.

use rocket::{get, post, put, delete, patch};
use rocket::serde::json::Json;
use rocket::http::Status;

// GET /users — zwraca JSON
#[get("/users?<page><limit>")]
async fn list_users(
    db: &State<DbPool>,
    page: Option<u32>,
    limit: Option<u32>,
) -> Json<Vec<User>> {
    Json(vec![])
}

// GET /users/<id>
#[get("/users/<id>")]
async fn get_user(db: &State<DbPool>, id: i64) -> Option<Json<User>> {
    // None zwraca 404 automatycznie
    None
}

// POST /users — akceptuje JSON
#[post("/users", format = "json", data = "<body>")]
async fn create_user(
    db: &State<DbPool>,
    body: Json<CreateUserRequest>,
) -> (Status, Json<User>) {
    (Status::Created, Json(/* nowy user */))
}

// DELETE /users/<id>
#[delete("/users/<id>")]
async fn delete_user(db: &State<DbPool>, id: i64) -> Status {
    Status::NoContent
}

FromParam i FromForm — parametry sciezki i formularzy

Rocket automatycznie konwertuje segmenty sciezki na typy implementujace FromParam. Standardowe typy (i64, String, uuid::Uuid) sa juz obslugiwane. Wlasne typy wymagaja implementacji traitu.

use rocket::request::FromParam;
use rocket::http::RawStr;

struct UserId(i64);

impl<'r> FromParam<'r> for UserId {
    type Error = &'r str;

    fn from_param(param: &'r str) -> Result<Self, Self::Error> {
        param.parse::<i64>()
            .map(UserId)
            .map_err(|_| param)
    }
}

// FromForm — dla query params i form data
use rocket::form::{Form, FromForm};

#[derive(FromForm)]
struct SearchParams {
    q: Option<String>,
    #[field(validate = range(1..=100))]
    limit: Option<u32>,
    page: Option<u32>,
}

#[get("/search?<params..>")]
async fn search(params: Form<SearchParams>) -> Json<Vec<User>> {
    Json(vec![])
}

Request Guards — FromRequest

Request guards to mechanizm walidacji i ekstrakcji danych z requestu przed wywolaniem handlera. Jesli guard zawiedzie, Rocket zwraca blad lub przekazuje do nastepnego pasujacego routea (forward).

use rocket::request::{FromRequest, Outcome, Request};
use rocket::http::Status;

struct AuthenticatedUser {
    id: i64,
    email: String,
}

#[rocket::async_trait]
impl<'r> FromRequest<'r> for AuthenticatedUser {
    type Error = String;

    async fn from_request(req: &'r Request<'_>) -> Outcome<Self, Self::Error> {
        let token = req.headers()
            .get_one("Authorization")
            .and_then(|v| v.strip_prefix("Bearer "));

        match token {
            Some(t) => match verify_jwt(t) {
                Ok(claims) => Outcome::Success(AuthenticatedUser {
                    id: claims.sub,
                    email: claims.email,
                }),
                Err(e) => Outcome::Error((Status::Unauthorized, e.to_string())),
            },
            None => Outcome::Error((Status::Unauthorized, "Brak tokena".into())),
        }
    }
}

// Guard jako parametr handlera — Rocket wywola go automatycznie
#[get("/profile")]
async fn get_profile(user: AuthenticatedUser) -> Json<Profile> {
    Json(Profile { user_id: user.id, email: user.email })
}

Fairings — cykl zycia aplikacji

Fairings to odpowiednik middleware lifecycle hooks w Rocket. AdHoc pozwala definiowac je bez implementacji pelnego traitu.

use rocket::fairing::AdHoc;
use rocket::fairing::{Fairing, Info, Kind};

// Prosty fairing przez AdHoc
let timing_fairing = AdHoc::on_response("Timing", |_req, res| {
    Box::pin(async move {
        res.set_header(rocket::http::Header::new("X-Powered-By", "Rocket"));
    })
});

// Inicjalizacja bazy danych
let db_fairing = AdHoc::try_on_ignite("Database", |rocket| async {
    match PgPool::connect(&std::env::var("DATABASE_URL").unwrap()).await {
        Ok(pool) => Ok(rocket.manage(pool)),
        Err(e) => {
            eprintln!("Blad polaczenia z DB: {e}");
            Err(rocket)
        }
    }
});

rocket::build()
    .attach(timing_fairing)
    .attach(db_fairing)

Responders — Custom<T> i Json<T>

Kazdy typ zwracany przez handler musi implementowac trait Responder. Rocket dostarcza Json<T>, Html<&str>, Redirect, Status oraz Custom<T> do budowania odpowiedzi z dowolnym statusem.

use rocket::response::status::Custom;
use rocket::http::Status;
use rocket::serde::json::Json;

// Odpowiedz z dowolnym statusem
#[post("/resource")]
fn create_resource() -> Custom<Json<serde_json::Value>> {
    Custom(
        Status::Created,
        Json(serde_json::json!({"id": 42, "created": true}))
    )
}

// Wlasny Responder
use rocket::{Request, Response};
use rocket::response::{self, Responder};

struct ApiResponse<T: serde::Serialize> {
    status: Status,
    data: T,
}

impl<'r, T: serde::Serialize> Responder<'r, 'static> for ApiResponse<T> {
    fn respond_to(self, req: &'r Request<'_>) -> response::Result<'static> {
        let json = serde_json::to_string(&self.data).unwrap();
        Response::build()
            .status(self.status)
            .header(rocket::http::ContentType::JSON)
            .sized_body(json.len(), std::io::Cursor::new(json))
            .ok()
    }
}

Rocket.toml — konfiguracja

Rocket czyta konfiguracje z Rocket.toml lub zmiennych srodowiskowych z prefiksem ROCKET_. Profile [debug] i [release] pozwalaja na rozne ustawienia per srodowisko.

[default]
address = "0.0.0.0"
port = 8080
workers = 4
max_blocking = 512
keep_alive = 5
log_level = "normal"

[debug]
port = 8080
log_level = "debug"

[release]
port = 80
log_level = "critical"
secret_key = "$(ROCKET_SECRET_KEY)"
