Axum — podstawy

Framework webowy rozwijany przez zespol Tokio. Integruje sie bezposrednio z ekosystemem tower i hyper, oferujac ergonomiczne API oparte na extractorach.

Router i rejestracja tras

Centralnym elementem aplikacji Axum jest Router. Trasy laczymy metoda .route(), przekazujac sciezke i handler. Axum rozroznia metody HTTP przez get(), post(), put(), delete() itd.

use axum::{Router, routing::{get, post, put, delete}};

async fn main() {
    let app = Router::new()
        .route("/",                   get(root_handler))
        .route("/users",              get(list_users).post(create_user))
        .route("/users/:id",          get(get_user).put(update_user).delete(delete_user))
        .route("/users/:id/profile",  get(get_profile))
        .fallback(handler_404);

    let listener = tokio::net::TcpListener::bind("0.0.0.0:8080").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}

Metoda axum::serve() jest dostepna od Axum 0.7 i zastepuje przestarzale Server::bind() z hyper. Wymaga tokio::net::TcpListener.

Handlery — async fn

Handler w Axum to dowolna asynchroniczna funkcja, ktorej argumenty implementuja trait FromRequestParts lub FromRequest, a typ zwracany implementuje IntoResponse. Axum sam wyciaga argumenty z requestu — to sa extractory.

use axum::{
    extract::{Path, Query, State, Json},
    response::{IntoResponse, Json as JsonResponse},
    http::StatusCode,
};
use serde::{Deserialize, Serialize};
use std::sync::Arc;

#[derive(Deserialize)]
struct ListParams {
    page: Option<u32>,
    limit: Option<u32>,
}

#[derive(Serialize)]
struct User {
    id: i64,
    name: String,
    email: String,
}

// GET /users?page=1&limit=20
async fn list_users(
    State(state): State<Arc<AppState>>,
    Query(params): Query<ListParams>,
) -> impl IntoResponse {
    let page = params.page.unwrap_or(1);
    let limit = params.limit.unwrap_or(20);
    // ... logika pobierania
    JsonResponse(vec![/* users */])
}

// GET /users/:id
async fn get_user(
    State(state): State<Arc<AppState>>,
    Path(id): Path<i64>,
) -> Result<JsonResponse<User>, StatusCode> {
    // ...
    Err(StatusCode::NOT_FOUND)
}

// POST /users
async fn create_user(
    State(state): State<Arc<AppState>>,
    Json(payload): Json<CreateUserRequest>,
) -> impl IntoResponse {
    (StatusCode::CREATED, JsonResponse(/* nowy user */))
}

Extractory sa zadeklarowane jako argumenty handlerów. Axum wywoluje je w kolejnosci i zwraca 400 Bad Request jesli ktorys zawiedzie (chyba ze uzyjesz Option<T> lub Result<T, E>).

IntoResponse — typy odpowiedzi

Handlery moga zwracac dowolny typ implementujacy IntoResponse. Axum dostarcza implementacje dla krotek (StatusCode, T), (StatusCode, HeaderMap, T), Json<T>, Html<T>, Redirect, a takze prostych typow jak String, &str, StatusCode.

use axum::response::{Html, Redirect, Response};
use axum::http::{HeaderMap, header};

// Tuple response: status + body
async fn created() -> impl IntoResponse {
    (StatusCode::CREATED, Json(serde_json::json!({"ok": true})))
}

// Odpowiedz z naglowkami
async fn with_headers() -> impl IntoResponse {
    let mut headers = HeaderMap::new();
    headers.insert(header::CACHE_CONTROL, "max-age=3600".parse().unwrap());
    (StatusCode::OK, headers, "Hello!")
}

// Przekierowanie
async fn old_endpoint() -> impl IntoResponse {
    Redirect::permanent("/new-endpoint")
}

// HTML
async fn home() -> impl IntoResponse {
    Html("<h1>Witaj</h1>")
}

// 404 fallback
async fn handler_404() -> impl IntoResponse {
    (StatusCode::NOT_FOUND, Json(serde_json::json!({"error": "nie znaleziono"})))
}

Router::with_state i zagniezdzanie

Stan aplikacji przekazujemy przez Router::with_state(). Zagniezdzanie routerow pozwala grupowac trasy i nadawac im wspolny prefiks przez .nest().

use std::sync::Arc;

#[derive(Clone)]
struct AppState {
    db: sqlx::PgPool,
}

let user_router = Router::new()
    .route("/",    get(list_users).post(create_user))
    .route("/:id", get(get_user).put(update_user));

let api_router = Router::new()
    .nest("/users",    user_router)
    .nest("/products", product_router);

let app = Router::new()
    .nest("/api/v1", api_router)
    .route("/health", get(health_check))
    .with_state(Arc::new(AppState { db }));
Wskazowka: Jesli uzywasz .with_state(), stan musi byc ustawiony na glownym routerze (lub na kazdym sub-routerze osobno). Stan nie jest automatycznie propagowany do zagniezdzonych routerow budowanych osobno.

TypedHeader — niestandardowe naglowki

Extractor TypedHeader z crate axum-extra pozwala odczytywac naglowki HTTP w sposob typowany. Wymaga dodania zaleznosci: axum-extra = { version = "0.9", features = ["typed-header"] }.

use axum_extra::TypedHeader;
use axum_extra::headers::{Authorization, authorization::Bearer};

async fn protected(
    TypedHeader(auth): TypedHeader<Authorization<Bearer>>,
) -> impl IntoResponse {
    let token = auth.token();
    // walidacja tokena...
    Json(serde_json::json!({"token_len": token.len()}))
}

Fallback handler

Handler fallback jest wywolywany gdy zadna trasa nie pasuje do requestu. Rejestrujemy go przez .fallback() na routerze. Moze byc zwykla async fn lub pelnym handlerem z extractorami.

axum::serve() vs hyper Server: Od Axum 0.7 zalecane jest uzycie axum::serve(listener, app).await. Aby dodac graceful shutdown, uzyj axum::serve(...).with_graceful_shutdown(shutdown_signal()), gdzie shutdown_signal() to future czekajace na SIGTERM/SIGINT.
