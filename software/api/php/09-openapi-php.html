OpenAPI w ekosystemie PHP

OpenAPI Specification (OAS) to standard opisywania REST API w formacie JSON lub YAML. W PHP dokumentacje OpenAPI mozna generowac na trzy sposoby: przez atrybuty PHP 8 w kodzie (podejscie code-first), przez reczne pliki YAML/JSON (design-first) lub przez automatyczna introspekcje frameworka (jak API Platform). Kazdemu podejsciu odpowiada inny zestaw narzedzi.

L5-Swagger dla Laravel

L5-Swagger to pakiet integrujacy biblioteke zircote/swagger-php z Laravel. Umozliwia opisywanie API przez atrybuty PHP 8 bezposrednio w kontrolerach, modelach i klasach DTO. Generuje specyfikacje OpenAPI i wbudowany Swagger UI dostepny przez przegldarke.

Instalacja i konfiguracja L5-Swagger 
# Instalacja
composer require darkaonline/l5-swagger

# Publikacja konfiguracji
php artisan vendor:publish --provider="L5Swagger\L5SwaggerServiceProvider"

# Generowanie dokumentacji (uruchom po kazdej zmianie atrybutow)
php artisan l5-swagger:generate

# Swagger UI dostepny pod: /api/documentation
# JSON spec pod: /api/documentation.json

<?php

namespace App\Http\Controllers\Api;

use OpenApi\Attributes as OA;

// Globalna konfiguracja API (zwykle w osobnym pliku lub w glownym kontrolerze)
#[OA\Info(
    title: 'My Product API',
    version: '1.0.0',
    description: 'API do zarzadzania produktami',
    contact: new OA\Contact(email: 'api@example.com'),
    license: new OA\License(name: 'MIT'),
)]
#[OA\Server(url: 'https://api.example.com/v1', description: 'Produkcja')]
#[OA\Server(url: 'http://localhost:8000/api', description: 'Development')]
#[OA\SecurityScheme(
    securityScheme: 'bearerAuth',
    type: 'http',
    scheme: 'bearer',
    bearerFormat: 'JWT',
)]
class ApiDocController {}

// Kontroler produktow z atrybutami OpenAPI
class ProductController extends Controller
{
    #[OA\Get(
        path: '/products',
        operationId: 'listProducts',
        summary: 'Lista produktow',
        description: 'Zwraca paginowana liste produktow z opcjonalnym filtrowaniem.',
        tags: ['Products'],
        security: [['bearerAuth' => []]],
        parameters: [
            new OA\Parameter(
                name: 'page',
                in: 'query',
                description: 'Numer strony',
                schema: new OA\Schema(type: 'integer', minimum: 1, default: 1)
            ),
            new OA\Parameter(
                name: 'per_page',
                in: 'query',
                description: 'Liczba wynikow na strone',
                schema: new OA\Schema(type: 'integer', minimum: 1, maximum: 100, default: 15)
            ),
            new OA\Parameter(
                name: 'status',
                in: 'query',
                description: 'Filtr statusu produktu',
                schema: new OA\Schema(type: 'string', enum: ['draft', 'published', 'archived'])
            ),
        ],
        responses: [
            new OA\Response(
                response: 200,
                description: 'Sukces — lista produktow',
                content: new OA\JsonContent(ref: '#/components/schemas/ProductCollection')
            ),
            new OA\Response(response: 401, description: 'Brak uwierzytelnienia'),
            new OA\Response(response: 429, description: 'Przekroczono limit zapytan'),
        ]
    )]
    public function index(Request $request): JsonResponse
    {
        // implementacja...
    }

    #[OA\Post(
        path: '/products',
        operationId: 'createProduct',
        summary: 'Tworzenie produktu',
        tags: ['Products'],
        security: [['bearerAuth' => []]],
        requestBody: new OA\RequestBody(
            required: true,
            content: new OA\JsonContent(ref: '#/components/schemas/StoreProductRequest')
        ),
        responses: [
            new OA\Response(
                response: 201,
                description: 'Produkt utworzony',
                content: new OA\JsonContent(ref: '#/components/schemas/ProductResource')
            ),
            new OA\Response(
                response: 422,
                description: 'Blad walidacji',
                content: new OA\JsonContent(
                    properties: [
                        new OA\Property(property: 'message', type: 'string'),
                        new OA\Property(property: 'errors', type: 'object'),
                    ]
                )
            ),
        ]
    )]
    public function store(StoreProductRequest $request): JsonResponse
    {

    }
}

    schema: 'StoreProductRequest',

NelmioApiDocBundle dla Symfony

NelmioApiDocBundle integruje dokumentacje OpenAPI z Symfony, automatycznie wykrywajac trasy, kontrolery i typy PHP. Wspolpracuje z symfony/serializer, symfony/validator i API Platform. Dokumentacja generowana jest dynamicznie przy kazdym zadaniu (lub z cache).

Instalacja NelmioApiDocBundle 
composer require nelmio/api-doc-bundle

# config/packages/nelmio_api_doc.yaml
nelmio_api_doc:
    documentation:
        info:
            title: My API
            version: '1.0'
        components:
            securitySchemes:
                Bearer:
                    type: http
                    scheme: bearer
    areas:
        path_patterns:
            - ^/api
        host_patterns:
            - ^api\.

# routing.yaml
app.swagger_ui:
    path: /api/doc
    methods: GET
    defaults: { _controller: nelmio_api_doc.controller.swagger_ui }

Generowanie klientow z openapi-generator-cli

Posiadajac specyfikacje OpenAPI mozna automatycznie wygenerowac klientow SDK dla roznych jezykow. openapi-generator-cli obsługuje ponad 50 jezykow docelowych i frameworkow.

# Instalacja (npm)
npm install -g @openapitools/openapi-generator-cli

# Generowanie klienta TypeScript dla React SPA
openapi-generator-cli generate \
  -i http://localhost:8000/api/documentation.json \
  -g typescript-axios \
  -o ./frontend/src/api-client \
  --additional-properties=supportsES6=true,useSingleRequestParameter=true

# Generowanie klienta Python
openapi-generator-cli generate \
  -i ./openapi.yaml \
  -g python \
  -o ./sdk/python \
  --package-name myapi_client

# Generowanie klienta PHP (dla innych serwisow PHP)
openapi-generator-cli generate \
  -i ./openapi.yaml \
  -g php \
  -o ./sdk/php \
  --additional-properties=composerVendorName=mycompany,composerProjectName=my-api-client

# Walidacja specyfikacji przed generowaniem
openapi-generator-cli validate -i ./openapi.yaml

Stoplight Studio dla PHP teams

Stoplight Studio to wizualny edytor OpenAPI — design-first podejscie, gdzie zespol najpierw projektuje API w GUI, a potem generuje stubs serwera i klientow. Integruje sie z Git i umozliwia wspolprace wielu osob nad specyfikacja.

Workflow design-first z Stoplight + PHP
  1. Zaprojektuj API w Stoplight Studio (drag&drop, wizualny edytor schematow)
  2. Commituj openapi.yaml do repozytorium Git
  3. Wygeneruj kontrolery PHP z openapi-generator lub uzyj gotowych stubs
  4. Implementuj logike biznesowa w wygenerowanych handlerach
  5. Waliduj odpowiedzi API wzgledem specyfikacji w testach (league/openapi-psr7-validator)
  6. Opublikuj dokumentacje z Stoplight Docs (hosted)

Walidacja odpowiedzi API wzgledem specyfikacji

Mozna automatycznie weryfikowac, czy odpowiedzi serwera sa zgodne ze specyfikacja OpenAPI — zarywno w testach automatycznych jak i w trybie debug na srodowisku dev. Biblioteka league/openapi-psr7-validator waliduje obiekty PSR-7 wzgledem pliku OpenAPI.
