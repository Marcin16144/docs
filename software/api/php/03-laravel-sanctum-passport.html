Laravel Sanctum i Passport

Uwierzytelnianie SPA, API tokens, OAuth2 server i zarzadzanie tokenami w Laravel

Sanctum vs Passport — kiedy co wybrac?

Laravel oferuje dwa oficjalne pakiety do uwierzytelniania API: Sanctum (prostszy, lzejszy) i Passport (pelny serwer OAuth2). Wybor zalezy od wymagan projektu — Sanctum wystarczy dla wiekszosci aplikacji SPA i mobilnych, Passport jest potrzebny gdy budujesz publiczne API z trzecimi stronami lub potrzebujesz pelnego OAuth2.

Laravel Sanctum — instalacja i konfiguracja

Sanctum oferuje trzy mechanizmy uwierzytelniania: SPA authentication (cookie + CSRF), API tokens (opaque tokens w bazie danych) i mobile authentication (tokens dla aplikacji mobilnych). Kazdy z nich jest odpowiedni dla innego przypadku uzycia.

# Instalacja Sanctum
composer require laravel/sanctum

# Publikacja konfiguracji i migracji
php artisan vendor:publish --provider="Laravel\Sanctum\SanctumServiceProvider"

# Uruchomienie migracji (tworzy tabele personal_access_tokens)
php artisan migrate

# Model User musi uzywac traitu HasApiTokens
Model User z HasApiTokens 
<?php

namespace App\Models;

use Illuminate\Foundation\Auth\User as Authenticatable;
use Laravel\Sanctum\HasApiTokens;

class User extends Authenticatable
{
    use HasApiTokens;

    protected $fillable = ['name', 'email', 'password'];

    protected $hidden = ['password', 'remember_token'];
}

API Tokens — tworzenie i abilities

API tokens Sanctum to opaque tokeny przechowywane (zahashowane) w tabeli personal_access_tokens. Kazdy token moze miec zestaw abilities — uprawnien okreslajacych, co token moze robic. To uproszczona wersja OAuth2 scopes.

<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Hash;
use Illuminate\Validation\ValidationException;

class AuthController extends Controller
{
    // Logowanie — tworzenie tokenu
    public function login(Request $request): JsonResponse
    {
        $request->validate([
            'email'       => 'required|email',
            'password'    => 'required',
            'device_name' => 'required|string|max:255',
        ]);

        $user = User::where('email', $request->email)->first();

        if (!$user || !Hash::check($request->password, $user->password)) {
            throw ValidationException::withMessages([
                'email' => ['Podane dane logowania sa nieprawidlowe.'],
            ]);
        }

        // Tworzenie tokenu z abilities
        $token = $user->createToken(
            name: $request->device_name,
            abilities: ['read:posts', 'write:posts', 'read:profile'],
            expiresAt: now()->addDays(30) // wymagane Laravel 10.x+
        );

        return response()->json([
            'token' => $token->plainTextToken,
            'type'  => 'Bearer',
        ]);
    }

    // Wylogowanie — uniewaznie biezacy token
    public function logout(Request $request): JsonResponse
    {
        // Usuniecie tokenu uzytego w biezacym zadaniu
        $request->user()->currentAccessToken()->delete();

        return response()->json(['message' => 'Wylogowano pomyslnie.']);
    }

    // Wylogowanie ze wszystkich urzadzen
    public function logoutAll(Request $request): JsonResponse
    {
        $request->user()->tokens()->delete();

        return response()->json(['message' => 'Wylogowano ze wszystkich urzadzen.']);
    }
}

// Sprawdzenie abilities w kontrolerze
public function store(Request $request): JsonResponse
{
    if (!$request->user()->tokenCan('write:posts')) {
        return response()->json(['error' => 'Brak uprawnien.'], 403);
    }
    // ... tworzenie posta
}

SPA Authentication — cookie-based

Dla Single Page Applications Sanctum oferuje uwierzytelnianie oparte na sesjach i ciasteczkach (jak klasyczne aplikacje webowe) zamiast tokenow. SPA musi znajdowac sie na tej samej domenie lub subdomenej co API. Przed pierwszym logowaniem SPA musi wywolac endpoint /sanctum/csrf-cookie, aby otrzymac token CSRF.

Konfiguracja stateful domains (config/sanctum.php) 
'stateful' => explode(',', env('SANCTUM_STATEFUL_DOMAINS', implode(',', [
    'localhost',
    'localhost:3000',
    '127.0.0.1',
    '127.0.0.1:8000',
    'app.mysite.com', // domena SPA
]))),

Laravel Passport — OAuth2 Server

Passport implementuje pelny serwer OAuth2 z obsluga Authorization Code Grant, Client Credentials Grant, Password Grant (deprecated w OAuth 2.1) i Implicit Grant. Uzywa kluczy RSA do podpisywania JWT tokenow.

# Instalacja Passport
composer require laravel/passport

php artisan migrate
php artisan passport:install  # Generuje klucze RSA i domyslnych klientow

# Model User
use Laravel\Passport\HasApiTokens;

class User extends Authenticatable
{
    use HasApiTokens;
}

# config/auth.php — guard api
'guards' => [
    'api' => [
        'driver'   => 'passport',
        'provider' => 'users',
    ],
],

# AuthServiceProvider::boot() — rejestracja scopes
Passport::tokensCan([
    'read-posts'    => 'Odczyt postow',
    'write-posts'   => 'Tworzenie i edycja postow',
    'delete-posts'  => 'Usuwanie postow',
    'manage-users'  => 'Zarzadzanie uzytkownikami',
]);

# Opcjonalne — czas waznosci tokenow
Passport::tokensExpireIn(now()->addDays(15));
Passport::refreshTokensExpireIn(now()->addDays(30));
Passport::personalAccessTokensExpireIn(now()->addMonths(6));

Authorization Code Flow (Passport)

Authorization Code Flow to najbezpieczniejszy grant OAuth2 — uzywany gdy trzecia aplikacja chce uzyskac dostep do danych uzytkownika. Uzytkownik loguje sie na stronie aplikacji Laravel, a aplikacja trzecia otrzymuje kod, ktory wymienia na token.

Client Credentials Grant

Client Credentials Grant sluzy do komunikacji machine-to-machine (M2M) — gdy inna userwer chce wywolac API bez kontekstu uzytkownika. Token jest wydawany bezposrednio na podstawie client_id i client_secret.

Guards i middleware

Laravel Guards definiuja, jak uzytkownik jest uwierzytelniany dla danego zadania. Guard api konfiguruje sie w config/auth.php — dla Sanctum driver to sanctum, dla Passport to passport.

Middleware w routes/api.php 
// Sanctum — wymaga tokenu LUB sesji SPA
Route::middleware('auth:sanctum')->group(function () {
    Route::get('/user', fn(Request $r) => $r->user());
    Route::apiResource('posts', PostController::class);
});

// Passport — z weryfikacja scope
Route::middleware(['auth:api', 'scopes:read-posts'])->group(function () {
    Route::get('/posts', [PostController::class, 'index']);
});

// Passport — wystarczy jeden z zakresow (scope)
Route::middleware(['auth:api', 'scope:read-posts,write-posts'])->group(function () {
    Route::post('/posts', [PostController::class, 'store']);
});

Rewokacja tokenow

Rewokacja (uniewaznie) tokenow jest krytyczna dla bezpieczenstwa. Sanctum przechowuje tokeny w bazie danych — usuniecie rekordu natychmiast uniewa tokeny. Passport rowniez pozwala rewokac tokeny i refresh tokeny.

  • Uzyj krotkich czasow waznosci tokenow i refresh tokenow
  • Implementuj endpoint do wylogowania rewokujacy token
  • Regularnie czys przeterminowane tokeny (Sanctum: sanctum:prune-expired)
  • Dla Sanctum tokenow — rozwaz hashing SHA-256 dla dodatkowego bezpieczenstwa
  • Nie przechowuj plaintext tokenow po ich wydaniu
