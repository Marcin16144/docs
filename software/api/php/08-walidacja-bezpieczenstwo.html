Laravel Validation

Laravel oferuje bogaty system walidacji danych wejsciowych z dziesiatkami wbudowanych regul. Walidacje mozna definiowac inline w kontrolerze przez $request->validate(), przez Validator::make() lub przez dedykowane klasy Form Request.

<?php

namespace App\Http\Controllers\Api;

use App\Http\Requests\StoreProductRequest;
use App\Models\Product;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Validator;

class ProductController extends Controller
{
    // Metoda 1: inline validate() — najprostsza
    public function store(Request $request): JsonResponse
    {
        $validated = $request->validate([
            'name'        => ['required', 'string', 'min:2', 'max:255', 'unique:products'],
            'price'       => ['required', 'numeric', 'min:0.01', 'max:999999.99'],
            'category_id' => ['required', 'integer', 'exists:categories,id'],
            'description' => ['nullable', 'string', 'max:5000'],
            'tags'        => ['sometimes', 'array', 'max:10'],
            'tags.*'      => ['integer', 'exists:tags,id'],
            'status'      => ['required', 'in:draft,published,archived'],
        ]);

        $product = Product::create($validated);
        return response()->json($product, 201);
    }

    // Metoda 2: Validator::make() — reczna kontrola
    public function update(Request $request, int $id): JsonResponse
    {
        $validator = Validator::make($request->all(), [
            'name'  => ['sometimes', 'string', 'min:2', 'max:255', "unique:products,name,{$id}"],
            'price' => ['sometimes', 'numeric', 'min:0.01'],
        ]);

        // Dodanie wlasnej reguly warunkowej
        $validator->sometimes('discount', 'required|numeric|between:0,100', function ($input) {
            return isset($input->price) && $input->price > 100;
        });

        if ($validator->fails()) {
            return response()->json([
                'message' => 'Validation failed.',
                'errors'  => $validator->errors()->toArray(),
            ], 422);
        }

        $product = Product::findOrFail($id)->update($validator->validated());
        return response()->json($product);
    }
}

Form Request — dedykowane klasy walidacji

Form Request to klasy hermetyzujace logike walidacji i autoryzacji dla konkretnego zadania HTTP. Sa automatycznie wstrzykiwane przez kontener IoC — jesli walidacja nie przejdzie, Laravel zwraca 422 z bledam przed wywolaniem metody kontrolera.

Form Request z wlasna regula walidacji 
<?php
// php artisan make:request StoreProductRequest

namespace App\Http\Requests;

use App\Rules\NoOffensiveWords;
use Illuminate\Foundation\Http\FormRequest;

class StoreProductRequest extends FormRequest
{
    // Autoryzacja — czy uzytkownik moze wykonac to zadanie?
    public function authorize(): bool
    {
        return $this->user()->can('create', Product::class);
    }

    public function rules(): array
    {
        return [
            'name'  => ['required', 'string', 'min:2', 'max:255', new NoOffensiveWords()],
            'price' => ['required', 'decimal:0,2', 'min:0.01'],
            'sku'   => ['required', 'regex:/^[A-Z]{2}-\d{6}$/'],
        ];
    }

    // Wlasne komunikaty bledow
    public function messages(): array
    {
        return [
            'sku.regex' => 'SKU musi miec format XX-000000 (2 litery, 6 cyfr).',
        ];
    }

    // Wlasne nazwy pol w komunikatach
    public function attributes(): array
    {
        return ['category_id' => 'kategoria'];
    }
}

// Wlasna regula walidacji (php artisan make:rule NoOffensiveWords)
namespace App\Rules;
use Closure;
use Illuminate\Contracts\Validation\ValidationRule;

class NoOffensiveWords implements ValidationRule
{
    public function validate(string $attribute, mixed $value, Closure $fail): void
    {
        $blacklist = ['spam', 'scam', 'fake'];
        foreach ($blacklist as $word) {
            if (stripos($value, $word) !== false) {
                $fail("Pole :attribute zawiera niedozwolone slowo: {$word}.");
            }
        }
    }
}

Symfony Constraints

Symfony Validator uzywa ograniczen (constraints) definiowanych jako atrybuty PHP 8, adnotacje, YAML lub XML. Constraints mozna stosowac do wlasciwosci encji, DTO lub metod.

<?php

namespace App\Dto;

use Symfony\Component\Validator\Constraints as Assert;

class CreateProductDto
{
    #[Assert\NotBlank(message: 'Nazwa produktu jest wymagana.')]
    #[Assert\Length(min: 2, max: 255, minMessage: 'Nazwa musi miec co najmniej {{ limit }} znaki.')]
    public readonly string $name;

    #[Assert\Positive(message: 'Cena musi byc wieksza od zera.')]
    #[Assert\Type(type: 'float')]
    public readonly float $price;

    #[Assert\NotNull]
    #[Assert\Regex(pattern: '/^[A-Z]{2}-\d{6}$/', message: 'Nieprawidlowy format SKU.')]
    public readonly string $sku;

    #[Assert\Valid]  // Walidacja zagniezdzonego obiektu
    public readonly CategoryDto $category;

    #[Assert\All([
        new Assert\NotBlank(),
        new Assert\Length(max: 50),
    ])]
    public readonly array $tags = [];
}

// Wlasny ConstraintValidator
use Symfony\Component\Validator\Constraint;
use Symfony\Component\Validator\ConstraintValidator;

class UniqueSkuValidator extends ConstraintValidator
{
    public function __construct(private readonly ProductRepository $repo) {}

    public function validate(mixed $value, Constraint $constraint): void
    {
        if ($this->repo->findBySku($value)) {
            $this->context->buildViolation($constraint->message)
                ->setParameter('{{ sku }}', $value)
                ->addViolation();
        }
    }
}

CORS — Cross-Origin Resource Sharing

CORS to mechanizm przegladarki kontrolujacy, czy skrypt z domeny A moze wywolywac API z domeny B. Serwer musi zwrocic odpowiednie naglowki Access-Control-*. Bledna konfiguracja CORS to czesty problem przy integracji SPA z API.

Rate Limiting

Rate limiting chroni API przed naduzyciem — czy to przez ataki brute-force, denial of service, czy po prostu zbyt agresywnych klientow. Laravel i Symfony oferuja wbudowane mechanizmy ograniczania liczby zapytan.

NarzedzieLaravelSymfony
Wbudowany rate limiterRateLimiter facade + throttle middlewaresymfony/rate-limiter component
Backend storageCache (Redis, Memcached, DB)Cache (PSR-6), Redis
AlgorytmyFixed window (domyslny)Fixed window, Sliding window, Token bucket
Naglowki odpowiedziX-RateLimit-Limit/Remaining/ResetReczna konfiguracja
Konfiguracja trasthrottle:60,1 w middlewareAtrybut #[RateLimit] lub serwis
Per-user limitingby(userId) w RateLimiterKlucz oparty o user ID
 
// Laravel — konfiguracja rate limiter (AppServiceProvider)
use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Support\Facades\RateLimiter;

RateLimiter::for('api', function (Request $request) {
    return Limit::perMinute(60)->by($request->user()?->id ?: $request->ip());
});

RateLimiter::for('login', function (Request $request) {
    return [
        Limit::perMinute(5)->by($request->ip()),
        Limit::perMinute(3)->by($request->input('email')),
    ];
});

// routes/api.php
Route::middleware(['auth:sanctum', 'throttle:api'])->group(function () {
    Route::apiResource('products', ProductController::class);
});
Route::post('/login', [AuthController::class, 'login'])
    ->middleware('throttle:login');

OWASP API Security Top 10 w PHP

Najwazniejsze zagrozenia i ochrona w PHP
  • API1 — Broken Object Level Authorization: zawsze weryfikuj, czy uzytkownik ma prawo do konkretnego zasobu przez ID, nie polegaj tylko na uwierzytelnieniu
  • API2 — Broken Authentication: uzyj Sanctum/Passport, wymuszaj silne hasla, implementuj MFA dla wrazliwych operacji
  • API3 — Broken Object Property Level Authorization: uzyj $fillable w Eloquent i grup serializacji w Resources
  • API4 — Unrestricted Resource Consumption: rate limiting, walidacja rozmiaru uploadu, paginacja wynikow
  • API5 — Broken Function Level Authorization: osobne middleware dla ról, nie polegaj na ukrywaniu endpointow
  • API8 — Security Misconfiguration: wyłacz display_errors na produkcji, ustaw bezpieczne naglowki HTTP
  • API9 — Improper Inventory Management: wersjonuj API, wylaczaj stare endpointy, dokumentuj wszystkie trasy

SQL Injection — ochrona przez prepared statements

Eloquent i Doctrine uzywaja prepared statements domyslnie — interpolacja wartosci w zapytaniach jest automatycznie zabezpieczona. Niebezpieczne sa zapytania z interpolacja PHP bezposrednio w SQL lub niewalidowane kolumny sortowania.

Output Sanitization

API zwracajace JSON nie jest podatne na XSS w przegladarce jesli Content-Type jest ustawiony na application/json. Niebezpieczne jest zwracanie HTML generowanego z danych uzytkownika lub uzywanie echo $userInput bez escapowania.
