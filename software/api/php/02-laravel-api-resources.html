Laravel API Resources

Transformacja modeli Eloquent, Resource Collections, warunkowe atrybuty i routing API

Czym sa API Resources?

Laravel API Resources to warstwa transformacji miedzy modelami Eloquent a odpowiedziami JSON zwracanymi przez API. Zamiast serializowac modele bezposrednio (co ujawnia wszystkie kolumny, w tym wrazliwe dane), Resource definiuje dokladnie, jakie pola i w jakiej strukturze trafiaja do klienta.

Resources rozwiazuja kilka problemow naraz: ukrywanie wewnetrznej struktury bazy danych, formatowanie danych (np. daty), dolaczanie relacji tylko gdy sa zaladowane oraz dodawanie obliczonych pol (np. full_name z first_name + last_name).

Generowanie Resource przez Artisan 
# Resource dla pojedynczego modelu
php artisan make:resource UserResource

# Resource Collection (lista modeli)
php artisan make:resource UserCollection

# Alternatywnie — kolekcja z metoda collection() na Resource
php artisan make:resource UserResource
# i uzycie UserResource::collection($users)

Podstawowa struktura API Resource

Kazdy Resource rozszerza Illuminate\Http\Resources\Json\JsonResource i implementuje metode toArray(), ktora zwraca tablice reprezentujaca zasob. Wewnatrz metody dostep do modelu odbywa sie przez $this.

<?php

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\JsonResource;

class UserResource extends JsonResource
{
    /**
     * Transform the resource into an array.
     *
     * @return array<string, mixed>
     */
    public function toArray(Request $request): array
    {
        return [
            'id'         => $this->id,
            'name'       => $this->name,
            'email'      => $this->email,
            'created_at' => $this->created_at->toISOString(),

            // Pole obliczone — nie istnieje w bazie danych
            'initials' => strtoupper(substr($this->name, 0, 1)),

            // Warunkowe wlaczenie pola (tylko gdy zaladowane)
            'email_verified' => $this->when(
                $this->email_verified_at !== null,
                true,
                false
            ),

            // Relacja — dolaczana tylko gdy eager-loaded
            'posts' => PostResource::collection(
                $this->whenLoaded('posts')
            ),

            // Warunkowe dolaczenie wielu pol naraz
            $this->mergeWhen($request->user()?->isAdmin(), [
                'ip_address'    => $this->last_login_ip,
                'admin_notes'   => $this->admin_notes,
            ]),
        ];
    }
}

Resource Collection

Resource Collection sluzy do transformowania list modeli. Mozna uzywac anonimowej kolekcji (UserResource::collection($users)) lub dedykowanej klasy kolekcji, ktora pozwala dodac metadane na poziomie calej kolekcji (np. statystyki, linki paginacji).

<?php

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\ResourceCollection;

class UserCollection extends ResourceCollection
{
    // Typ elementu kolekcji (opcjonalne — domyslnie przez nazwe)
    public $collects = UserResource::class;

    public function toArray(Request $request): array
    {
        return [
            'data' => $this->collection,

            // Dodatkowe metadane na poziomie kolekcji
            'meta' => [
                'total'       => $this->total(),
                'per_page'    => $this->perPage(),
                'current_page'=> $this->currentPage(),
                'last_page'   => $this->lastPage(),
            ],

            'links' => [
                'self'  => $request->url(),
                'first' => $this->url(1),
                'last'  => $this->url($this->lastPage()),
                'prev'  => $this->previousPageUrl(),
                'next'  => $this->nextPageUrl(),
            ],
        ];
    }

    // Dodanie naglowkow do odpowiedzi kolekcji
    public function withResponse(Request $request, $response): void
    {
        $response->header('X-Total-Count', $this->total());
    }
}

// Uzycie w kontrolerze
public function index(Request $request): UserCollection
{
    $users = User::with('posts')
        ->latest()
        ->paginate(15);

    return new UserCollection($users);
}

Warunkowe atrybuty — when i mergeWhen

Metoda when() dolacza pole tylko gdy warunek jest spelniony. Jesli warunek jest falszywy, pole jest calkowicie pomijane w JSON (nie pojawia sie jako null). Metoda mergeWhen() dolacza tablice pol warunkowo — uzyteczne gdy chcemy dodac kilka pol dla konkretnej roli uzytkownika.

Metoda whenLoaded() to specjalny przypadek — dolacza relacje tylko jesli zostala juz zaladowana (eager loading). Dzieki temu unikamy N+1 problem i nie wymuszamy ladowania relacji, ktore moga nie byc potrzebne w danym endpoincie.

Routing API w Laravel

Laravel rozdziela routing webowy (routes/web.php) od API (routes/api.php). Trasy API domyslnie maja prefiks /api i korzystaja z middleware grupy api (stateless, bez sesji, z throttle).

routes/api.php — typowa konfiguracja 
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\Api\UserController;
use App\Http\Controllers\Api\PostController;

// Resourceful routes — generuje wszystkie 7 tras CRUD
Route::apiResource('users', UserController::class);
// GET    /api/users          → index
// POST   /api/users          → store
// GET    /api/users/{user}   → show
// PUT    /api/users/{user}   → update
// PATCH  /api/users/{user}   → update
// DELETE /api/users/{user}   → destroy

// Grupowanie z prefiksem i middleware
Route::prefix('v1')->middleware(['auth:sanctum', 'throttle:api'])->group(function () {
    Route::apiResource('posts', PostController::class);

    // Zagniezdzone zasoby (posts/{post}/comments)
    Route::apiResource('posts.comments', CommentController::class)
        ->shallow(); // shallow — komentarze maja wlasne routes bez posta
});

// Versjonowanie przez prefix
Route::prefix('v2')->group(function () {
    Route::apiResource('users', \App\Http\Controllers\Api\V2\UserController::class);
});

Response Macros

Response macros pozwalaja definiowac wlasne metody na obiekcie Response, ktore mozna potem wielokrotnie uzywac w calej aplikacji. Rejestruje sie je w ServiceProvider, najczesciej w AppServiceProvider::boot().

Dobre praktyki z API Resources

  • Zawsze uzywaj whenLoaded() dla relacji — chroni przed N+1
  • Nigdy nie zwracaj modelu bezposrednio z kontrolera — zawsze przez Resource
  • Uzyj dedykowanej klasy kolekcji gdy potrzebujesz metadanych poza data
  • Grupuj pola logicznie (dane podstawowe, relacje, metadane administracyjne)
  • Stosuj mergeWhen() dla pol zaleznych od uprawnien uzytkownika
  • Dodaj metode withResponse() w kolekcji, aby ustawic naglowki HTTP
