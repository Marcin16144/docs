PHP-FPM — konfiguracja pool

PHP-FPM (FastCGI Process Manager) to menazer procesow PHP obslugujacy zadania HTTP przez protokol FastCGI. Nginx odbiera zadania HTTP i przekazuje je do PHP-FPM przez socket Unix lub TCP. Konfiguracja puli procesow ma kluczowy wplyw na wydajnosc i stabilnosc serwera pod obciazeniem.

PHP-FPM wspiera trzy tryby zarzadzania procesami: static (stala liczba procesow), dynamic (elastyczna — skaluje miedzy min a max) i ondemand (procesy tworzone na zadanie, zabijane po idle_timeout). Dla API produkcyjnych zalecany jest tryb dynamic.

Konfiguracja puli PHP-FPM (/etc/php/8.3/fpm/pool.d/www.conf) 
[www]
user  = www-data
group = www-data

; Socket Unix — szybszy niz TCP dla komunikacji lokalnej
listen = /run/php/php8.3-fpm.sock
listen.owner = www-data
listen.group = www-data
listen.mode  = 0660

; Tryb dynamic — elastyczna liczba procesow
pm = dynamic

; Maksymalna liczba jednoczesnych procesow worker
; Regula: (RAM - system_overhead) / avg_process_memory
; Przyklad: (4096 MB - 512 MB) / ~35 MB = ~100 procesow
pm.max_children = 50

; Liczba procesow uruchamianych przy starcie FPM
pm.start_servers = 10

; Minimalna liczba procesow idle (oczekujacych)
pm.min_spare_servers = 5

; Maksymalna liczba procesow idle — nadmiarowe sa zabijane
pm.max_spare_servers = 20

; Liczba zapytan po ktorej worker jest restartowany (ochrona przed wyciekami pamieci)
pm.max_requests = 500

; Timeout dla pojedynczego zadania (sekundy)
request_terminate_timeout = 60

; Logowanie slow requests (powyzej N sekund)
slowlog = /var/log/php-fpm/www-slow.log
request_slowlog_timeout = 5s

; Zmienne srodowiskowe dla procesow worker
env[APP_ENV]  = production
env[APP_KEY]  = $APP_KEY
env[DB_HOST]  = $DB_HOST

; Status page (monitoring)
pm.status_path = /fpm-status
ping.path      = /fpm-ping

Nginx + PHP-FPM — konfiguracja

Nginx sluzy jako reverse proxy i serwer statycznych plikow. Przekazuje dynamiczne zadania PHP do PHP-FPM przez socket Unix. Prawidlowa konfiguracja Nginx obejmuje kompresje Gzip, caching naglowkow, timeouty i bezpieczne naglowki HTTP.

# /etc/nginx/sites-available/api.example.com

upstream php_fpm {
    server unix:/run/php/php8.3-fpm.sock;
    keepalive 32;
}

server {
    listen 443 ssl http2;
    server_name api.example.com;
    root /var/www/api/public;

    # TLS
    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;

    # Bezpieczne naglowki HTTP
    add_header X-Content-Type-Options    nosniff;
    add_header X-Frame-Options           DENY;
    add_header X-XSS-Protection          "1; mode=block";
    add_header Referrer-Policy           strict-origin-when-cross-origin;
    add_header Content-Security-Policy   "default-src 'none'";

    # Gzip dla API responses
    gzip on;
    gzip_types application/json application/javascript text/plain;
    gzip_min_length 1024;

    # Glowna lokalizacja — przekierowanie do index.php (Laravel/Slim)
    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    # Blokowanie dostepu do ukrytych plikow (.env, .git)
    location ~ /\. { deny all; }

    # Obsluga PHP przez FPM
    location ~ \.php$ {
        fastcgi_pass   php_fpm;
        fastcgi_index  index.php;
        fastcgi_param  SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include        fastcgi_params;

        # Timeouty
        fastcgi_read_timeout   60;
        fastcgi_send_timeout   60;
        fastcgi_connect_timeout 10;

        # Buforowanie odpowiedzi FPM
        fastcgi_buffer_size    32k;
        fastcgi_buffers        8 16k;
    }
}

# Redirect HTTP → HTTPS
server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}

Laravel Octane — serwer aplikacji PHP

Laravel Octane uruchamia aplikacje Laravel jako dlugozywy proces serwera, ladujac framework jeden raz i obslugujac wiele zapytan bez ponownego bootstrapowania. Eliminuje overhead inicjalizacji frameworka przy kazdym zadaniu — typowy wzrost wydajnosci to 5–20x wzgledem PHP-FPM.

FrankenPHP — all-in-one serwer

FrankenPHP to nowoczesny serwer PHP zbudowany w Go, bazujacy na Caddy. Laczy serwer HTTP (z HTTPS automatycznym przez Let's Encrypt), PHP runtime i Mercure w jednym binarnym pliku. Nie wymaga osobnego Nginx ani Apache.

FrankenPHP z Laravel Octane 
# Instalacja FrankenPHP (binary)
curl -L https://github.com/dunglas/frankenphp/releases/latest/download/frankenphp-linux-x86_64 \
  -o /usr/local/bin/frankenphp && chmod +x /usr/local/bin/frankenphp

# composer.json — Laravel z Octane i FrankenPHP
composer require laravel/octane
php artisan octane:install --server=frankenphp

# Uruchomienie
php artisan octane:frankenphp --workers=8 --max-requests=500

# Produkcyjne uruchomienie z Caddyfile
# Caddyfile
{
    frankenphp
    order php_server before file_server
}

api.example.com {
    root * /var/www/api/public
    php_server
    encode gzip
}

Docker multi-stage build

Multi-stage build pozwala zbudowac obraz produkcyjny bez narzedzi deweloperskich (Composer, dev dependencies). Kazdy stage zaczyna od osobnego obrazu bazowego — tylko artefakty z wybranych stagow trafiaja do finalnego obrazu.

# Dockerfile — multi-stage dla Laravel API

# Stage 1: Composer dependencies
FROM composer:2.7 AS composer_stage

WORKDIR /app
COPY composer.json composer.lock ./

# Instalacja zaleznosci produkcyjnych (bez dev)
RUN composer install \
    --no-dev \
    --no-scripts \
    --no-autoloader \
    --prefer-dist \
    --optimize-autoloader

COPY . .
RUN composer dump-autoload --optimize --no-dev

# Stage 2: Finalny obraz produkcyjny
FROM php:8.3-fpm-alpine AS production

# Instalacja rozszerzen PHP
RUN apk add --no-cache \
        libpng-dev libjpeg-dev libwebp-dev \
        libzip-dev oniguruma-dev icu-dev && \
    docker-php-ext-install \
        pdo_mysql mbstring zip intl opcache pcntl && \
    docker-php-ext-enable opcache

# Konfiguracja OPcache dla produkcji
COPY docker/php/opcache.ini /usr/local/etc/php/conf.d/opcache.ini

# Konfiguracja PHP-FPM
COPY docker/php/fpm-pool.conf /usr/local/etc/php-fpm.d/www.conf

WORKDIR /var/www/api

# Kopiowanie tylko potrzebnych plikow (bez docker/, tests/, .git/)
COPY --chown=www-data:www-data --from=composer_stage /app/vendor ./vendor
COPY --chown=www-data:www-data . .

# Optymalizacje Laravel
RUN php artisan config:cache && \
    php artisan route:cache  && \
    php artisan view:cache   && \
    php artisan event:cache

USER www-data
EXPOSE 9000

CMD ["php-fpm"]

Laravel Forge i Ploi — managed deployment

Laravel Forge to oficjalny panel do provisioningu i deploymentu serwerow Laravel. Automatycznie konfiguruje Nginx, PHP-FPM, SSL, baze danych i kolejki. Integruje sie z DigitalOcean, AWS, Hetzner i Linode. Ploi to tansza alternatywa z podobnymi funkcjami i wsparciem dla dodatkowych frameworkow PHP.

Zarzadzanie konfiguracja — .env i Vault

Konfiguracja srodowiskowa (klucze API, hasla bazy danych) nigdy nie powinna byc commitowana do repozytorium. W malych projektach wystarczy plik .env na serwerze. W wiekszych wdrozeniach (Kubernetes, multi-region) zalecany jest dedykowany system zarzadzania sekretami.

Hierarchia konfiguracji dla PHP API
  1. Development: plik .env lokalnie, .env.example commitowany do repo (bez wartosci)
  2. Staging/CI: zmienne srodowiskowe w ustawieniach CI (GitHub Actions secrets, GitLab CI variables)
  3. Produkcja (VPS): .env na serwerze poza katalogiem web, chmod 600, owner www-data
  4. Produkcja (Kubernetes): Kubernetes Secrets + External Secrets Operator z HashiCorp Vault lub AWS Secrets Manager
  5. Laravel Forge/Ploi: panel webowy do zarzadzania zmiennymi srodowiskowymi (szyfrowane w bazie panelu)

OPcache Preloading — optymalizacja startu

Preloading (PHP 7.4+) laduje klasy frameworka do OPcache przy starcie PHP-FPM. Laravel i Symfony maja wbudowane skrypty preload. Przy deploymencie nalezy zresetowac OPcache — najlatwiej przez restart PHP-FPM (systemctl reload php8.3-fpm lub kill -USR2 $(cat /run/php/php8.3-fpm.pid)).

Checklist deploymentu PHP API na produkcje
  • Wlacz OPcache z validate_timestamps=0
  • Uruchom composer install --no-dev --optimize-autoloader
  • Uruchom php artisan config:cache route:cache view:cache (Laravel)
  • Ustaw APP_ENV=production i APP_DEBUG=false
  • Skonfiguruj PHP-FPM pool z odpowiednia liczba procesow
  • Wlacz HTTPS z automatycznym odnowieniem (Let's Encrypt)
  • Skonfiguruj rate limiting i naglowki bezpieczenstwa w Nginx
  • Skonfiguruj logowanie bledow do centralnego systemu (Sentry, Datadog)
  • Uruchom migracje bazy danych (php artisan migrate --force)
  • Zrestartuj PHP-FPM po deploymencie (reset OPcache)
