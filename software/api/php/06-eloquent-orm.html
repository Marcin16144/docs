Eloquent ORM

Modele, migracje, relacje, eager loading, scopes, eventy i przetwarzanie duzych zbiorow danych

Czym jest Eloquent?

Eloquent to ORM (Object-Relational Mapper) wbudowany w Laravel, oparty na wzorcu Active Record. Kazdy model Eloquent reprezentuje tabele w bazie danych, a instancja modelu odpowiada pojedynczemu wierszowi. Eloquent oferuje bogaty, ekspresywny interfejs do operacji na danych — od prostych zapytan CRUD po zaawansowane relacje i zakresy zapytan.

W porownaniu do Data Mapper (jak Doctrine), Active Record laczy logike dostepy do danych z logika domenowa w jednej klasie. Podejscie to jest szybsze w implementacji, ale moze prowadzic do naruszen zasady Single Responsibility w duzych projektach.

Definicja modelu

Model Eloquent to klasa dziedziczaca po Illuminate\Database\Eloquent\Model. Eloquent automatycznie mapuje nazwe klasy na nazwe tabeli (konwencja snake_case plural), ale mozna to nadpisac. Klucz glowny domyslnie to id (auto-increment integer).

<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\SoftDeletes;
use Illuminate\Database\Eloquent\Casts\Attribute;
use Illuminate\Database\Eloquent\Relations\HasMany;
use Illuminate\Database\Eloquent\Relations\BelongsTo;
use Illuminate\Database\Eloquent\Relations\BelongsToMany;
use Illuminate\Database\Eloquent\Relations\MorphMany;

class Post extends Model
{
    use SoftDeletes;

    // Nadpisanie domyslnej nazwy tabeli (domyslnie: posts)
    protected $table = 'blog_posts';

    // Pola dozwolone do mass-assignment
    protected $fillable = [
        'title', 'slug', 'body', 'status', 'user_id', 'published_at',
    ];

    // Alternatywa — pola WYKLUCZONE z mass-assignment (uzyj jednego z dwoch)
    // protected $guarded = ['id', 'created_at', 'updated_at'];

    // Pola ukryte w serializacji (toArray, toJson)
    protected $hidden = ['deleted_at'];

    // Automatyczne rzutowanie typow
    protected $casts = [
        'published_at' => 'datetime',
        'is_featured'  => 'boolean',
        'metadata'     => 'array',       // JSON kolumna → PHP array
        'status'       => PostStatus::class, // PHP 8.1 Enum
    ];

    // Accessor (PHP 8 / Laravel 9+ syntax)
    protected function title(): Attribute
    {
        return Attribute::make(
            get: fn(string $value) => ucfirst($value),
            set: fn(string $value) => strtolower(trim($value)),
        );
    }

    // Pole obliczone (appended)
    protected $appends = ['reading_time'];

    protected function readingTime(): Attribute
    {
        return Attribute::make(
            get: fn() => (int) ceil(str_word_count($this->body) / 200) . ' min',
        );
    }
}

Migracje — Schema Builder

Migracje to wersjonowane skrypty zmian schematu bazy danych. Kazda migracja ma metode up() (aplikacja zmiany) i down() (cofniecie zmiany). Migracje sa uruchamiane przez php artisan migrate i sledzone w tabeli migrations.

<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('blog_posts', function (Blueprint $table) {
            $table->id();                                    // BIGINT UNSIGNED AUTO_INCREMENT PK
            $table->foreignId('user_id')                    // BIGINT UNSIGNED
                  ->constrained()                           // FK → users.id
                  ->cascadeOnDelete();                      // ON DELETE CASCADE
            $table->string('title', 255);
            $table->string('slug', 255)->unique();
            $table->longText('body');
            $table->enum('status', ['draft', 'published', 'archived'])->default('draft');
            $table->boolean('is_featured')->default(false);
            $table->json('metadata')->nullable();
            $table->timestamp('published_at')->nullable();
            $table->softDeletes();                          // deleted_at TIMESTAMP NULL
            $table->timestamps();                           // created_at, updated_at

            $table->index(['status', 'published_at']);      // indeks zlozony
            $table->fullText('body');                       // full-text search (MySQL)
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('blog_posts');
    }
};

class User extends Model
{
    // Jeden uzytkownik ma wiele postow
    public function posts(): HasMany
    {
        return $this->hasMany(Post::class);
    }

    // Wiele do wielu z tabelka posrednia roles_users
    public function roles(): BelongsToMany
    {
        return $this->belongsToMany(Role::class)
            ->withPivot('assigned_at', 'expires_at')  // dodatkowe kolumny w tabeli pivot
            ->withTimestamps();
    }
}

class Post extends Model
{
    // Kazdy post nalezy do uzytkownika
    public function author(): BelongsTo
    {
        return $this->belongsTo(User::class, 'user_id');
    }

    // Polimorficzne komentarze (Comment moze nalezec do Post lub Video)
    public function comments(): MorphMany
    {
        return $this->morphMany(Comment::class, 'commentable');
    }
}

// Eager Loading — ladowanie relacji w jednym zapytaniu
$posts = Post::with(['author', 'comments.author', 'tags'])
    ->where('status', 'published')
    ->latest('published_at')
    ->paginate(15);

Query Scopes — lokalne i globalne

Scopes to metody modelu enkapsulujace czesto uzywane warunki zapytania. Lokalne scopes sa wywoywane recznie (np. ->published()), globalne scopes sa stosowane automatycznie do kazdego zapytania na modelu.

Lokalne i globalne scopes 
class Post extends Model
{
    // Lokalny scope — ->published()
    public function scopePublished(Builder $query): void
    {
        $query->where('status', 'published')
              ->whereNotNull('published_at')
              ->where('published_at', '<=', now());
    }

    // Globalny scope — stosowany automatycznie
    protected static function booted(): void
    {
        static::addGlobalScope('active', function (Builder $query) {
            $query->whereNull('deleted_at'); // SoftDeletes juz to robi
        });
    }
}

// Uzycie lokalnego scope
$posts = Post::published()->latest()->get();

// Pominiecie globalnego scope
$posts = Post::withoutGlobalScope('active')->get();

Eloquent Events i Observers

Eloquent emituje eventy w kluczowych momentach cyklu zycia modelu: creating, created, updating, updated, deleting, deleted, saving, saved. Mozna je obsluzyc w modelu (metoda booted()) lub w dedykowanym Observerze.

chunk() — przetwarzanie duzych zbiorow

Ladowanie tysiecy rekordow naraz do pamieci moze spowodowac wyczerpanie limitu pamieci PHP. Metoda chunk() pobiera i przetwarza rekordy partiami, co utrzymuje stale zuzycie pamieci niezaleznie od rozmiaru zbioru.

Przetwarzanie duzych zbiorow danych 
// chunk() — pobiera partie rekordow
Post::where('status', 'draft')
    ->chunk(200, function (Collection $posts) {
        foreach ($posts as $post) {
            // Przetworzenie kazdego posta
            $post->update(['status' => 'archived']);
        }
    });

// chunkById() — bezpieczniejsze (nie resetuje offsetu po zmianach)
Post::where('status', 'draft')
    ->chunkById(200, function (Collection $posts) {
        // ...
    });

// lazy() — generator, jeden rekord na raz (PHP 8+)
foreach (Post::lazy() as $post) {
    // Minimalne zuzycie pamieci
    processPost($post);
}

// lazyById() — z kursorowym pobieraniem
Post::where('views', '>', 1000)->lazyById(100)->each(function (Post $post) {
    $post->increment('featured_score');
});
