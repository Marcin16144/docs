tRPC

End-to-end typesafe API bez generowania kodu — router, procedures, context, middleware i integracje

Czym jest tRPC?

tRPC (TypeScript Remote Procedure Call) to biblioteka umozliwiajaca tworzenie w pelni typowanych API bez potrzeby definiowania schematu (jak GraphQL SDL) ani generowania kodu (jak OpenAPI codegen). Typy sa wspoldzielone bezposrednio miedzy serwerem a klientem przez TypeScript — jezeli zmienisz sygnature procedury na serwerze, klient natychmiast zobaczy blad kompilacji.

tRPC nie jest protokolem — pod spodem uzywa HTTP (GET dla queries, POST dla mutations). Nie jest tez ORM ani frameworkiem — to warstwa transportu typow miedzy frontendem a backendem w monorepo lub fullstack frameworku (Next.js, SvelteKit).

Glowna zaleta tRPC

Refaktoring API jest bezpieczny — TypeScript wylapuje wszystkie niezgodnosci miedzy serwerem a klientem w czasie kompilacji. Zero schema drift, zero runtime surprises. Idealny dla zespolow pracujacych na fullstack TypeScript w monorepo.

Podstawowa konfiguracja — router i procedures

// === server/trpc.ts — inicjalizacja tRPC ===
import { initTRPC, TRPCError } from '@trpc/server';
import { z } from 'zod';
import superjson from 'superjson'; // serializacja Date, Map, Set, BigInt

// Typ kontekstu — dostepny we wszystkich procedurach
export type Context = {
  user: { id: string; role: 'admin' | 'user' } | null;
  db: PrismaClient;
  req: Request;
};

// Inicjalizacja tRPC
const t = initTRPC.context<Context>().create({
  transformer: superjson, // opcjonalnie: lepsza serializacja niz JSON
  errorFormatter({ shape, error }) {
    return {
      ...shape,
      data: {
        ...shape.data,
        zodError: error.cause instanceof ZodError
          ? error.cause.flatten()
          : null,
      },
    };
  },
});

// Eksportowane buildersy — uzyj ich zamiast bezposrednio t.*
export const router      = t.router;
export const publicProc  = t.procedure;           // publiczna procedura
export const middleware  = t.middleware;

// Middleware autentykacji
const isAuthed = middleware(({ ctx, next }) => {
  if (!ctx.user) throw new TRPCError({ code: 'UNAUTHORIZED' });
  return next({ ctx: { ...ctx, user: ctx.user } }); // user jest non-null po tej linii
});

export const protectedProc = t.procedure.use(isAuthed); // chroniona procedura

Router i procedury

// === server/routers/users.ts ===
import { router, publicProc, protectedProc } from '../trpc';
import { z } from 'zod';
import { TRPCError } from '@trpc/server';

const CreateUserSchema = z.object({
  name:     z.string().min(2).max(100),
  email:    z.string().email(),
  password: z.string().min(8),
});

const UpdateUserSchema = z.object({
  id:   z.string().uuid(),
  name: z.string().min(2).optional(),
  email: z.string().email().optional(),
});

export const usersRouter = router({
  // QUERY — odpowiednik GET (cacheowalny)
  list: protectedProc
    .input(z.object({ page: z.number().int().positive().default(1), limit: z.number().int().min(1).max(100).default(20) }))
    .query(async ({ ctx, input }) => {
      const { page, limit } = input;
      const [users, total] = await Promise.all([
        ctx.db.user.findMany({ skip: (page - 1) * limit, take: limit }),
        ctx.db.user.count(),
      ]);
      return { users, total, pages: Math.ceil(total / limit) };
    }),

  byId: protectedProc
    .input(z.string().uuid())
    .query(async ({ ctx, input: id }) => {
      const user = await ctx.db.user.findUnique({ where: { id } });
      if (!user) throw new TRPCError({ code: 'NOT_FOUND', message: `Uzytkownik ${id} nie istnieje` });
      return user;
    }),

  // MUTATION — odpowiednik POST/PUT/DELETE
  create: publicProc
    .input(CreateUserSchema)
    .mutation(async ({ ctx, input }) => {
      const existing = await ctx.db.user.findUnique({ where: { email: input.email } });
      if (existing) throw new TRPCError({ code: 'CONFLICT', message: 'Email juz zajety' });
      return ctx.db.user.create({ data: { ...input, password: await hash(input.password) } });
    }),

  update: protectedProc
    .input(UpdateUserSchema)
    .mutation(async ({ ctx, input: { id, ...data } }) => {
      const user = await ctx.db.user.update({ where: { id }, data });
      return user;
    }),

  delete: protectedProc
    .input(z.string().uuid())
    .mutation(async ({ ctx, input: id }) => {
      if (ctx.user.role !== 'admin') throw new TRPCError({ code: 'FORBIDDEN' });
      await ctx.db.user.delete({ where: { id } });
      return { success: true };
    }),
});

// === server/routers/index.ts — glowny router ===
import { router } from '../trpc';
import { usersRouter } from './users';
import { postsRouter } from './posts';

export const appRouter = router({
  users: usersRouter,
  posts: postsRouter,
});

export type AppRouter = typeof appRouter; // EKSPORTUJ TEN TYP DO KLIENTA

Adapter — Express, Fastify, Next.js

tRPC dostarcza adaptery dla popularnych frameworkow. Adapter montuje router tRPC jako middleware HTTP — procedury query sa dostepne pod GET /trpc/users.list, mutations pod POST /trpc/users.create.

Klient — TanStack Query (React Query)

Klient tRPC integruje sie z TanStack Query, dostarczajac typowane hooki. Nie trzeba recznie definiowac typow odpowiedzi — sa inferowane z AppRouter.

Setup monorepo — wspoldzielone typy

Typowy setup tRPC w monorepo (np. Turborepo, nx) uzywa paczki packages/api eksportujaccej AppRouter. Frontend importuje ten typ i tworzy klienta — bez generowania kodu, bez REST clienta, bez OpenAPI.

tRPC vs REST vs GraphQL

Cecha REST GraphQL tRPC
Typesafety end-to-end Manualna / codegen Codegen wymagany Automatyczna (TypeScript)
Schema / kontrakt OpenAPI (opcjonalne) SDL (wymagane) Brak — typy TS sa kontraktem
Klienci nieTS Dowolny jezyk Dowolny jezyk Tylko TypeScript
Cacheowanie HTTP Pelne (GET) Ograniczone (POST) Queries cacheowalny (GET)
Over/under fetching Over-fetching czesty Rozwiazany Nie dotyczy (full response)
Zlozonosc setup Niska Wysoka Srednia (wymaga monorepo)
Generowanie kodu Opcjonalne Czesto wymagane Zero codegen
Subscriptions SSE / WebSocket WebSocket natywnie WebSocket (tRPC subscriptions)
Kiedy tRPC jest idealne?

tRPC swieci w fullstack TypeScript monorepo: Next.js, SvelteKit, Remix z wspolnym backendem. Eliminuje caly boilerplate API clienta. Jesli Twoj frontend i backend to osobne repozytoria lub uzywasz roznych jezykow — wybierz REST z OpenAPI lub GraphQL.

Ograniczenia tRPC

tRPC nie generuje dokumentacji API (brak OpenAPI), nie wspiera klientow nieTypescript, trudniej uzyc z zewnetrznymi konsumentami API. Dla publicznych API lub mikroserwisow z roznym stackiem technologicznym lepiej sprawdza sie REST + OpenAPI.
