Podstawy Node.js v22

Event loop, silnik V8, libuv, system modulow oraz nowosci Node.js 22

Czym jest Node.js?

Node.js to srodowisko uruchomieniowe JavaScript zbudowane na silniku V8 z Chrome. Dziala poza przegladarka, umozliwiajac tworzenie aplikacji serwerowych, narzedzi CLI i systemow backendowych. Kluczowe cechy to jednowatkowos, nieblokujace I/O oraz model oparty na zdarzeniach (event-driven).

Node.js v22 (LTS od pazdziernika 2024) wprowadza natywne stripowanie TypeScript, wbudowany test runner w stabilnej wersji oraz klienta WebSocket bez dodatkowych bibliotek.

Node.js v22 — wazna wersja LTS

Node.js 22 jest aktualnym LTS (Long Term Support) — zalecana do produkcji do 2027 roku. Wspiera ESM jako domyslny system modulow i oferuje znaczace usprawnienia wydajnosci V8.

Event Loop — fazy wykonania

Event loop to mechanizm pozwalajacy Node.js realizowac nieblokujace I/O mimo jednowatkowosci. Libuv (biblioteka C) zarzadza kolejkami zdarzen i deleguje operacje do puli watkow systemowych. Event loop przechodzi przez szesc faz w kazdej iteracji (tzw. tick).

Faza Kolejka / zrodlo Przyklad operacji Priorytet
timers setTimeout, setInterval Callbacki zegarow, których delay minal 1 (najwyzszy w petli)
I/O callbacks Callbacki systemowe Bledy TCP, wyniki odczytu pliku (opoznione) 2
idle / prepare Wewnetrzna libuv Przygotowanie petli (wewnetrzne Node.js) 3 (niedostepna z JS)
poll Kolejka I/O Nowe zdarzenia I/O: odczyt pliku, socket, HTTP 4 (najdluzej blokuje)
check setImmediate Callbacki setImmediate — po poll 5
close callbacks Zdarzenie "close" socket.destroy(), zamkniecie strumieni 6

Przed kazda faza Node.js oproznia kolejki nextTick (process.nextTick) oraz microtask (Promise callbacks). Maja one wyzszy priorytet niz jakakolwiek faza petli.

Kolejnosc wykonania — przyklad

// Demonstracja kolejnosci: nextTick > Promise > setImmediate > setTimeout
console.log('1: synchroniczne');

process.nextTick(() => console.log('2: nextTick'));

Promise.resolve().then(() => console.log('3: Promise microtask'));

setImmediate(() => console.log('4: setImmediate (faza check)'));

setTimeout(() => console.log('5: setTimeout (faza timers)'), 0);

console.log('6: synchroniczne koniec');

// Wynik: 1, 6, 2, 3, 4, 5 (lub 4/5 zamienione — zalezne od OS)

Silnik V8 i libuv

V8 to silnik JavaScript rozwijany przez Google (uzywa Chrome i Node.js). Kompiluje JS do kodu maszynowego (JIT compilation), zarzadza sterta (heap) i odsmiecaniem pamieci (garbage collection — Generational GC z young/old space).

libuv to wieloplatformowa biblioteka C zapewniajaca: asynchroniczne I/O, pule watkow (domyslnie 4 watki dla operacji plikowych i DNS), implementacje event loop oraz abstrakcje dla systemow operacyjnych (epoll/Linux, kqueue/macOS, IOCP/Windows).

Pula watkow libuv

Domyslnie libuv utrzymuje 4 watki robocze (UV_THREADPOOL_SIZE=4). Mozna zwiekszyc do 1024. Operacje CPU-bound (np. kryptografia, kompresja zlib) korzystaja z tej puli — dlatego moze byc waskim gardlem pod obciazeniem.

CommonJS vs ESM

Node.js wspiera dwa systemy modulow. CommonJS (CJS) to klasyczny system z require(), obecny od poczatku Node.js. ES Modules (ESM) to standard ECMAScript z import/export, domyslny w przegladarkach i Node.js v22+.

// === CommonJS (plik .cjs lub bez "type":"module" w package.json) ===
const fs = require('fs');
const { join } = require('path');
const myModule = require('./myModule'); // synchroniczny odczyt

module.exports = { myFunction };
// lub: exports.myFunction = myFunction;

// Dostep do katalogu biezacego pliku (dostepne w CJS):
console.log(__dirname);   // np. /home/user/project/src
console.log(__filename);  // np. /home/user/project/src/app.js

// === ES Modules (plik .mjs lub "type":"module" w package.json) ===
import fs from 'fs';
import { join } from 'path';
import { myFunction } from './myModule.js'; // rozszerzenie wymagane!

export function hello() { return 'hello'; }
export default class App {}

// Odpowiednik __dirname w ESM:
import { fileURLToPath } from 'url';
import { dirname } from 'path';
const __filename = fileURLToPath(import.meta.url);
const __dirname  = dirname(__filename);

// Lub top-level await (tylko w ESM):
const data = await fetch('https://api.example.com/data').then(r => r.json());

package.json — kluczowe pola

Plik package.json steruje zachowaniem projektu Node.js. Pole type decyduje o domyslnym systemie modulow, exports pozwala zdefiniowac publiczne API paczki, a scripts definiuje skrypty uruchamiane przez npm run.

{
  "name": "my-api",
  "version": "1.0.0",
  "type": "module",            // domyslny system: ESM (pliki .js traktowane jako ESM)
  "main": "./dist/index.js",  // punkt wejscia dla CJS (stary interop)
  "exports": {
    ".": {
      "import": "./dist/index.js",  // dla: import x from 'my-api'
      "require": "./dist/index.cjs" // dla: require('my-api')
    },
    "./utils": "./dist/utils.js"    // subpath export: import { x } from 'my-api/utils'
  },
  "scripts": {
    "start":   "node dist/index.js",
    "dev":     "node --watch src/index.ts",  // --watch: hot-reload (v18+)
    "build":   "tsc -p tsconfig.json",
    "test":    "node --test",                // wbudowany test runner Node.js
    "lint":    "eslint src/"
  },
  "engines": {
    "node": ">=22.0.0"
  }
}

Nowosci Node.js v22

Natywne stripowanie TypeScript

Node.js v22.6+ (eksperymentalnie) i v23+ umozliwia uruchomienie plikow TypeScript bez transpilatora. Typy sa usuwane (strip), ale nie ma type-checkingu. Flaga --experimental-strip-types (v22) lub automatycznie w v23+.

// Uruchomienie pliku .ts bezposrednio (Node.js 22.6+ z flaga):
// node --experimental-strip-types src/server.ts

// Plik server.ts:
import { createServer } from 'http';

interface Config {
  port: number;
  host: string;
}

const config: Config = { port: 3000, host: 'localhost' };

const server = createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ status: 'ok', config }));
});

server.listen(config.port, config.host, () => {
  console.log(\`Serwer dziala na http://\${config.host}:\${config.port}\`);
});

Wbudowany test runner (stabilny od v20, ulepszony w v22)

Node.js ma wbudowany modul testowy dostepny przez node:test. Nie wymaga zewnetrznych bibliotek. Wspiera: describe/it, assert, coverage, mock functions, snapshots i subtesty.

Wbudowany klient WebSocket

Node.js v22 wprowadza globalny WebSocket (po stronie klienta) zgodny z API przegladarki. Wczesniej wymagane bylo ws lub undici.

process.env i zmienne srodowiskowe

Zmienne srodowiskowe sa dostepne przez obiekt process.env. Node.js v22.9+ laduje plik .env natywnie przy uzyciu flagi --env-file, bez potrzeby biblioteki dotenv.

Bezpieczenstwo zmiennych srodowiskowych

Nigdy nie commituj pliku .env do repozytorium. Dodaj go do .gitignore. W produkcji uzyj sekretow platformy (Kubernetes Secrets, Railway Variables, Fly.io secrets).

__dirname vs import.meta.url

W CommonJS dostepne sa globalne zmienne __dirname i __filename. W ESM nie istnieja — zamiast nich uzywamy import.meta.url, który zawiera URL biezacego pliku (file:///absolute/path/to/file.js).

Tip: pomocniczy snippet dla ESM

Umieszczony raz na gorze pliku ESM: import { fileURLToPath } from 'url'; import { dirname, join } from 'path'; const __dirname = dirname(fileURLToPath(import.meta.url)); — przywraca znane zachowanie.

Jednowatkowosc a wydajnosc

Node.js wykonuje kod JavaScript w jednym watku. Oznacza to, ze operacje CPU-intensive (np. szyfrowanie RSA, kompresja, parsowanie JSON ogromnych plikow) blokuja caly serwer. Rozwiazania:

  • Worker Threads (node:worker_threads) — osobne watki JS z wlasna sterta V8
  • Child Processes (node:child_process) — osobne procesy Node.js
  • Cluster mode (node:cluster) — wiele procesow Node.js na tym samym porcie (load balancing przez OS)
  • Offloading do mikroserwisow — ciezkie operacje w osobnym serwisie (np. Python, Go)
