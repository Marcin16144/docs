Uwierzytelnianie Node.js

passport.js, JWT, refresh tokens, sesje, Auth0, Lucia auth i bezpieczenstwo cookies

Przeglad metod uwierzytelniania

Uwierzytelnianie (autentykacja) to proces weryfikacji tozsamosci uzytkownika. W aplikacjach Node.js mamy kilka podstawowych podejsc: sesje po stronie serwera (tradycyjne, stanowe), JWT (bezstanowe tokeny), OAuth 2.0 (logowanie przez zewnetrznego dostawce) oraz rozwiazania managed (Auth0, Clerk, Firebase Auth — outsourcing calej warstwy auth).

Metoda Stanowos Skalowalnosc Zlozonosc Zastosowanie
Sesje + cookies Stanowa (serwer) Wymaga shared store (Redis) Srednia Tradycyjne aplikacje webowe, SSR
JWT (access token) Bezstanowy Doskonala (stateless) Srednia API, SPA, mobile, mikroserwisy
JWT + refresh token Polstanowy Dobra Wysoka Produkcja — kompromis bezp./UX

Managed (Auth0/Clerk) Zewnetrzna Doskonala Niska (dla dewelopera) Szybki start, MFA, enterprise SSO

JWT — jsonwebtoken

JWT (JSON Web Token) sklada sie z trzech czesci: header (algorytm), payload (claims — dane uzytkownika) i signature (podpis weryfikujacy autentycznosc). Payload jest zakodowany Base64, nie zaszyfrowany — nie przechowuj w nim hasel ani wrazliwych danych.

import jwt from 'jsonwebtoken';
import { randomBytes } from 'crypto';

const JWT_SECRET         = process.env.JWT_SECRET!;        // min 256-bit klucz
const JWT_REFRESH_SECRET = process.env.JWT_REFRESH_SECRET!;

// Typy tokenow
interface AccessTokenPayload {
  sub: string;         // user ID (subject)
  email: string;
  role: 'admin' | 'user';
  type: 'access';
}

interface RefreshTokenPayload {
  sub: string;
  jti: string;         // JWT ID — unikalny identyfikator tokena (do revokacji)
  type: 'refresh';
}

// Generowanie tokenow
function generateTokens(user: { id: string; email: string; role: string }) {
  const accessToken = jwt.sign(
    { sub: user.id, email: user.email, role: user.role, type: 'access' } satisfies AccessTokenPayload,
    JWT_SECRET,
    { expiresIn: '15m', algorithm: 'HS256' } // krotki czas zycia access tokena
  );

  const jti = randomBytes(32).toString('hex'); // unikalny ID refresh tokena
  const refreshToken = jwt.sign(
    { sub: user.id, jti, type: 'refresh' } satisfies RefreshTokenPayload,
    JWT_REFRESH_SECRET,
    { expiresIn: '7d', algorithm: 'HS256' }
  );

  return { accessToken, refreshToken, jti };
}

// Weryfikacja access tokena
function verifyAccessToken(token: string): AccessTokenPayload {
  try {
    const payload = jwt.verify(token, JWT_SECRET) as AccessTokenPayload;
    if (payload.type !== 'access') throw new Error('Nieprawidlowy typ tokena');
    return payload;
  } catch (err) {
    if (err instanceof jwt.TokenExpiredError) throw new AppError('Token wygasl', 401, 'TOKEN_EXPIRED');
    if (err instanceof jwt.JsonWebTokenError)  throw new AppError('Nieprawidlowy token', 401, 'INVALID_TOKEN');
    throw err;
  }
}

// Middleware Express — weryfikacja JWT z nagłówka Authorization
export const jwtMiddleware = async (req, res, next) => {
  const authHeader = req.headers.authorization;
  if (!authHeader?.startsWith('Bearer '))
    return res.status(401).json({ error: 'Brak tokena autoryzacji' });

  try {
    req.user = verifyAccessToken(authHeader.slice(7));
    next();
  } catch (err) {
    next(err);
  }
};

Refresh Token Rotation

Access token ma krotki czas zycia (15 min) — zmniejsza ryzyko naduzycia przy wycieku. Refresh token ma dlugi czas zycia (7 dni) i sluzy do generowania nowych access tokenow. Rotation oznacza, ze kazde uzycie refresh tokena generuje NOWY refresh token i uniewaznia stary — wykrywa krazenie skradzionych tokenow.

// Refresh token rotation z detekcja ponownego uzycia (reuse detection)
app.post('/auth/refresh', async (req, res) => {
  const { refreshToken } = req.cookies; // refresh token w httpOnly cookie
  if (!refreshToken) return res.status(401).json({ error: 'Brak refresh tokena' });

  let payload: RefreshTokenPayload;
  try {
    payload = jwt.verify(refreshToken, JWT_REFRESH_SECRET) as RefreshTokenPayload;
  } catch {
    return res.status(401).json({ error: 'Nieprawidlowy refresh token' });
  }

  // Sprawdz czy token istnieje w bazie (nie zostal uniewazniony)
  const storedToken = await db.refreshToken.findUnique({ where: { jti: payload.jti } });

  if (!storedToken) {
    // TOKEN REUSE DETECTED — ktos uzywa odwolane tokenow!
    // Uniewaznij WSZYSTKIE sesje tego uzytkownika
    await db.refreshToken.deleteMany({ where: { userId: payload.sub } });
    console.warn(`[SECURITY] Refresh token reuse detected for user ${payload.sub}`);
    return res.status(401).json({ error: 'Wykryto nieprawidlowa aktywnosc — zaloguj sie ponownie' });
  }

  // Uniewaznij stary token i wygeneruj nowy
  const user = await db.user.findUnique({ where: { id: payload.sub } });
  const { accessToken, refreshToken: newRefreshToken, jti: newJti } = generateTokens(user);

  await db.$transaction([
    db.refreshToken.delete({ where: { jti: payload.jti } }),
    db.refreshToken.create({ data: { jti: newJti, userId: user.id, expiresAt: addDays(new Date(), 7) } }),
  ]);

  // Refresh token w httpOnly cookie, access token w body (lub tez w cookie)
  res.cookie('refreshToken', newRefreshToken, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
    maxAge: 7 * 24 * 60 * 60 * 1000, // 7 dni w ms
    path: '/auth/refresh',            // cookie widoczne tylko dla /auth/refresh
  });

  res.json({ accessToken });
});

passport.js — strategie uwierzytelniania

Passport.js to middleware uwierzytelniania z ponad 500 strategiami. Abstrakcja pozwala uzyc tej samej logiki dla roznych metod logowania. Strategie: LocalStrategy (email/haslo), JWTStrategy, GoogleStrategy, GitHubStrategy, OAuth2Strategy.

express-session + connect-redis

Sesje serwerowe przechowuja dane uzytkownika na serwerze (Redis) i wysylaja klientowi tylko ID sesji w cookie. Bezpieczniejsze niz JWT gdy chodzi o natychmiastowa revokacje sesji, ale wymagaja wspoldzielonego store dla wielu instancji serwera.

Cookie Security — najlepsze praktyki

Atrybut cookie Opis Zalecana wartosc Chroni przed
httpOnly Cookie niedostepne dla JavaScript true XSS, kradziez tokena przez JS
secure Cookie tylko przez HTTPS true (produkcja) MITM, podsłuchiwanie

Lucia Auth — nowoczesna alternatywa (2025/2026)

Lucia to biblioteka zarzadzania sesjami skupiona na bezpieczenstwie i prostocie. Nie jest opiniujaca jesli chodzi o baze danych — wspiera Prisma, Drizzle, MongoDB, libSQL. W odroznieniu od Auth0/Clerk, Lucia jest self-hosted i open source. W wersji 3.x Lucia uproscila API i skupila sie wylacznie na sesjach (bez social OAuth — to robisz osobno przez Arctic).

Auth0 SDK dla Node.js

Auth0 to managed authentication platform. SDK auth0 (npm) umozliwia weryfikacje tokenow, zarzadzanie uzytkownikami przez Management API i integracje z Express przez express-oauth2-jwt-bearer. Idealny gdy potrzebujesz: MFA, enterprise SSO (SAML), zaawansowanego zarzadzania uzytkownikami bez budowania od zera.

Najczestsze bledy bezpieczenstwa auth

1. Przechowywanie refresh tokenow w localStorage (podatne na XSS) — uzywaj httpOnly cookies. 2. Zbyt dluga waznosc access tokenow — max 15-60 minut. 3. Brak rotacji refresh tokenow. 4. Slaby sekret JWT — min 256 bit losowych danych. 5. Brak rate limiting na endpointach auth — umozliwia brute force.
