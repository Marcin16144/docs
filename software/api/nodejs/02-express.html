Express.js

Najpopularniejszy framework webowy dla Node.js — routing, middleware, walidacja i bezpieczenstwo

Wprowadzenie do Express

Express.js to minimalistyczny, nieopiniujacy (unopinionated) framework HTTP dla Node.js. Nie narzuca struktury projektu — sam decydujesz, jak zorganizowac kod. Jest fundamentem dla wiekszosci frameworkow wyzszego rzedu (NestJS, LoopBack). Aktualna stabilna wersja to Express 4.x; Express 5 jest w fazie RC.

Express 5 — co nowego?

Express 5 (RC) wprowadza: automatyczna propagacje bledow z async handlerów (nie trzeba try/catch + next(err)), usunieto przestarzale metody (res.sendfile, req.param), lepsze wsparcie Promise.

Podstawowa konfiguracja

import express from 'express';
import cors from 'cors';
import helmet from 'helmet';
import compression from 'compression';
import { json } from 'express';

const app = express();

// --- Middleware globalne ---
app.use(helmet());            // Nagłówki bezpieczenstwa (CSP, HSTS, X-Frame-Options...)
app.use(cors({
  origin: ['https://myapp.com', 'http://localhost:3000'],
  credentials: true,          // pozwala na cookies cross-origin
  methods: ['GET','POST','PUT','DELETE','PATCH'],
}));
app.use(compression());       // Gzip/Brotli kompresja odpowiedzi
app.use(json({ limit: '1mb' }));  // Parsowanie JSON body

// --- Pliki statyczne ---
app.use('/static', express.static('public', {
  maxAge: '1d',               // Cache-Control: max-age=86400
  etag: true,
}));

app.listen(3000, () => console.log('Serwer na porcie 3000'));

Routing — metody i parametry

Express wspiera wszystkie metody HTTP. Parametry sciezki (:id) sa dostepne przez req.params, query string przez req.query, a body przez req.body (po uzyciu parsera).

import { Router } from 'express';
const router = Router();

// GET /users — lista
router.get('/', async (req, res) => {
  const { page = 1, limit = 20, sort = 'createdAt' } = req.query;
  const users = await userService.findAll({ page: +page, limit: +limit, sort });
  res.json({ data: users, meta: { page: +page, limit: +limit } });
});

// GET /users/:id — jeden rekord
router.get('/:id', async (req, res, next) => {
  try {
    const user = await userService.findById(req.params.id);
    if (!user) return res.status(404).json({ error: 'Nie znaleziono uzytkownika' });
    res.json(user);
  } catch (err) {
    next(err); // Przekaz do error middleware
  }
});

// POST /users — tworzenie
router.post('/', validateBody(createUserSchema), async (req, res) => {
  const user = await userService.create(req.body);
  res.status(201).json(user);
});

// PUT /users/:id — pelna aktualizacja
router.put('/:id', validateBody(updateUserSchema), async (req, res) => {
  const user = await userService.update(req.params.id, req.body);
  res.json(user);
});

// DELETE /users/:id
router.delete('/:id', async (req, res) => {
  await userService.remove(req.params.id);
  res.status(204).send();
});

export default router;
// Rejestracja: app.use('/users', router);

Middleware stack

Middleware to funkcje z sygnatura (req, res, next). Wykonuja sie po kolei — kazda musi wywolac next(), aby przekazac kontrole dalej, lub zakonczyc odpowiedz (res.send()). Kolejnosc rejestracji ma znaczenie krytyczne.

Rodzaj middleware Sygnatura Zastosowanie Przyklad
Aplikacyjne app.use(fn) Dziala dla wszystkich tras Logger, CORS, body parser
Routerowe router.use(fn) Dziala dla tras routera Autentykacja dla /api
Obslugi bledow app.use((err,req,res,next)) Przechwytuje bledy z next(err) Globalny error handler
Wbudowane express.json() Parsowanie body, pliki statyczne express.static, express.urlencoded
Zewnetrzne npm package Rozszerzenia spolecznosci helmet, cors, compression, morgan

Error handling middleware

Error middleware przyjmuje 4 argumenty — (err, req, res, next). Musi byc zarejestrowane po wszystkich routach. Gdy przekazujesz blad przez next(err), Express pomija normalne middleware i przechodzi wprost do error handlera.

// Niestandardowa klasa bledu
class AppError extends Error {
  constructor(
    public message: string,
    public statusCode: number = 500,
    public code?: string
  ) {
    super(message);
    this.name = 'AppError';
  }
}

// Middleware walidacji (przyklad z express-validator / Zod)
function validateBody(schema) {
  return (req, res, next) => {
    const result = schema.safeParse(req.body);
    if (!result.success) {
      return next(new AppError(
        'Blad walidacji danych wejsciowych',
        400,
        'VALIDATION_ERROR'
      ));
    }
    req.body = result.data; // nadpisz zwalidowanymi danymi
    next();
  };
}

// Globalny error handler — rejestruj PO wszystkich trasach
app.use((err, req, res, next) => {
  const isDev = process.env.NODE_ENV === 'development';

  if (err instanceof AppError) {
    return res.status(err.statusCode).json({
      error: { message: err.message, code: err.code }
    });
  }

  // Nieoczekiwany blad
  console.error('[ERROR]', err);
  res.status(500).json({
    error: {
      message: isDev ? err.message : 'Wewnetrzny blad serwera',
      stack: isDev ? err.stack : undefined,
    }
  });
});

Walidacja z Zod

Zod to biblioteka walidacji z doskonalym wsparciem TypeScript. Generuje typy automatycznie ze schematow, eliminujac duplication. Middleware walidacyjne mozna napisac ogolne i uzyc dla kazdej trasy.

Integracja Zod z Express

Schemat Zod definiuje ksztalt danych wejsciowych. Metoda safeParse nie rzuca wyjatku — zwraca obiekt z polem success, co umozliwia kontrolowane obsluze bledow.

Bezpieczenstwo — helmet i CORS

helmet ustawia kilkanascie nagłówkow HTTP poprawiajacych bezpieczenstwo: Content-Security-Policy, X-Frame-Options, Strict-Transport-Security, X-Content-Type-Options i inne. Kazdy mozna skonfigurowac osobno.

CORS — typowe pulapki

Ustawianie origin: '*' z credentials: true jest nieprawidlowe i odrzucane przez przegladarki. Przy cookies cross-origin musisz podac konkretne domeny w tablicy origin. Preflight OPTIONS musi byc obsluzony — cors() robi to automatycznie.

express-validator

Alternatywa dla Zod — middleware check() i validationResult() z pakietu express-validator. Starsza, ale bardzo popularna biblioteka, szczegolnie w projektach bez TypeScript.

Organizacja projektu Express

  • src/routes/ — definicje tras (Router instances)
  • src/controllers/ — handlery HTTP (req/res logic)
  • src/services/ — logika biznesowa (bez HTTP)
  • src/middleware/ — wspoldzielone middleware
  • src/models/ — definicje danych / ORM
  • src/utils/ — funkcje pomocnicze
Tip: async wrapper dla Express 4

W Express 4 niezlapany blad z async handlera nie trafia do error middleware. Uzywaj wrappera: const asyncHandler = fn => (req,res,next) => Promise.resolve(fn(req,res,next)).catch(next); lub pakietu express-async-errors. Express 5 rozwiazuje ten problem natywnie.
