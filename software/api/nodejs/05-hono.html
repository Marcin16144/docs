Hono

Ultra-lekki framework edge-first (~12 KB) dzialajacy na Cloudflare Workers, Deno, Bun i Node.js

Czym jest Hono?

Hono (po japonsku "plomien") to minimalistyczny framework HTTP zaprojektowany z mysla o edge computing. W odroznieniu od Express czy Fastify, Hono nie jest zwiazany z Node.js — dziala wszedie gdzie dostepny jest Web Standard API (Request/Response). Dzieki temu ten sam kod mozna uruchomic na Cloudflare Workers, Deno Deploy, Bun, AWS Lambda i Node.js bez zadnych zmian.

Dlaczego Hono zyskuje popularnosc?

W 2025/2026 edge computing staje sie standardem. Cloudflare Workers, Vercel Edge Functions, Deno Deploy oferuja niska latencje, globalna dystrybucje i model platnosci per-request. Hono to framework, który natywnie wspiera ten paradygmat — zero cold start na Workers, bundle size ponizej 15 KB.

Podstawowa konfiguracja i routing

import { Hono } from 'hono';
import { cors } from 'hono/cors';
import { logger } from 'hono/logger';
import { prettyJSON } from 'hono/pretty-json';
import { secureHeaders } from 'hono/secure-headers';
import { compress } from 'hono/compress';

// Typowanie zmiennych srodowiskowych i zmiennych kontekstu
type Env = {
  Bindings: {
    DATABASE_URL: string;    // Cloudflare Workers env bindings
    JWT_SECRET: string;
  };
  Variables: {
    userId: string;          // zmienne ustawione przez middleware
    userRole: 'admin' | 'user';
  };
};

const app = new Hono<Env>();

// Middleware globalne
app.use('*', logger());
app.use('*', secureHeaders());
app.use('*', cors({
  origin: ['https://myapp.com', 'http://localhost:3000'],
  credentials: true,
}));
app.use('*', compress());

// Trasy podstawowe
app.get('/', (c) => c.json({ status: 'ok', version: '1.0.0' }));
app.get('/health', (c) => c.text('OK', 200));

// Parametry i query
app.get('/users/:id', async (c) => {
  const id = c.req.param('id');
  const include = c.req.query('include'); // ?include=posts
  const user = await getUserById(id, include);
  if (!user) return c.json({ error: 'Nie znaleziono' }, 404);
  return c.json(user);
});

// Grupowanie tras
const api = new Hono<Env>().basePath('/api/v1');
api.route('/users', usersRouter);
api.route('/posts', postsRouter);
app.route('/', api);

export default app; // Cloudflare Workers export

Middleware i walidacja Zod

Hono dostarcza middleware walidacyjne @hono/zod-validator, które integruje Zod ze schematem zapytania. Bledy walidacji sa automatycznie formatowane i zwracane jako 400. Typy sa inferences do handlera — pelen end-to-end typesafety.

import { zValidator } from '@hono/zod-validator';
import { z } from 'zod';

// Schemat Zod
const CreateUserSchema = z.object({
  name:  z.string().min(2).max(100).trim(),
  email: z.string().email().toLowerCase(),
  role:  z.enum(['admin', 'user']).default('user'),
  age:   z.number().int().min(0).max(120).optional(),
});

const QuerySchema = z.object({
  page:  z.coerce.number().int().positive().default(1),
  limit: z.coerce.number().int().min(1).max(100).default(20),
});

const usersRouter = new Hono<Env>()

  .get('/', zValidator('query', QuerySchema), async (c) => {
    const { page, limit } = c.req.valid('query'); // w pelni typowane
    const users = await userService.findAll({ page, limit });
    return c.json({ data: users, meta: { page, limit } });
  })

  .post('/', zValidator('json', CreateUserSchema), async (c) => {
    const body = c.req.valid('json'); // typ: z.infer<typeof CreateUserSchema>
    const user = await userService.create(body);
    return c.json(user, 201);
  })

  .get('/:id', async (c) => {
    const user = await userService.findById(c.req.param('id'));
    return user ? c.json(user) : c.json({ error: 'Nie znaleziono' }, 404);
  })

  .delete('/:id', async (c) => {
    await userService.remove(c.req.param('id'));
    return c.body(null, 204);
  });

// Middleware autentykacji — ustawia zmienne w kontekscie
const authMiddleware = createMiddleware<Env>(async (c, next) => {
  const token = c.req.header('Authorization')?.replace('Bearer ', '');
  if (!token) return c.json({ error: 'Brak tokena' }, 401);

  try {
    const payload = await verifyJWT(token, c.env.JWT_SECRET);
    c.set('userId', payload.sub);
    c.set('userRole', payload.role);
    await next();
  } catch {
    return c.json({ error: 'Nieprawidlowy token' }, 401);
  }
});

Metody odpowiedzi — c.json, c.text, c.html

Kontekst Hono (c) dostarcza wygodne metody do tworzenia odpowiedzi zgodnych z Web Standard API. Kazda metoda ustawia odpowiedni naglowek Content-Type automatycznie.

Metoda Content-Type Zastosowanie Przyklad
c.json(data, status?) application/json Odpowiedzi API JSON c.json({ id: 1 }, 201)
c.text(text, status?) text/plain Proste odpowiedzi tekstowe c.text('OK')
c.html(html, status?) text/html Renderowanie HTML (SSR) c.html('<h1>Hello</h1>')
c.redirect(url) — Przekierowania HTTP c.redirect('/login', 302)
c.body(null, 204) — Odpowiedzi bez tresci DELETE, akcje bez body
c.stream(fn) Dowolny Streaming odpowiedzi (SSE, AI) OpenAI streaming, duze pliki

RPC Mode — hono/client

Tryb RPC Hono to jedna z najbardziej innowacyjnych funkcji. Klient (hono/client) generuje typowany klient API na podstawie definicji routera serwerowego — bez generowania kodu, bez OpenAPI, zero konfiguracji. Dziala jak tRPC, ale zachowuje standard HTTP.

// === server/routes/users.ts — definicja z typami ===
import { Hono } from 'hono';
import { zValidator } from '@hono/zod-validator';
import { z } from 'zod';

const usersRoute = new Hono()
  .get('/', async (c) => {
    return c.json({ users: await getUsers() });
  })
  .post('/', zValidator('json', z.object({ name: z.string(), email: z.string().email() })),
    async (c) => {
      const body = c.req.valid('json');
      const user = await createUser(body);
      return c.json(user, 201);
    }
  );

export type UsersRouteType = typeof usersRoute;
export default usersRoute;

// === client/api.ts — typowany klient bez generowania kodu ===
import { hc } from 'hono/client';
import type { UsersRouteType } from '../server/routes/users';

const client = hc<UsersRouteType>('https://api.myapp.com');

// Pelne typowanie — IntelliSense dziala automatycznie!
const res = await client.users.$get();
const { users } = await res.json(); // typ: { users: User[] }

const newUser = await client.users.$post({
  json: { name: 'Jan Kowalski', email: 'jan@example.com' }
});
const created = await newUser.json();

Kiedy wybrac Hono?

Hono to idealny wybor dla: API na Cloudflare Workers / Deno Deploy, projektow gdzie rozmiar bundle ma znaczenie, aplikacji wymagajacych dzialania na wielu runtime'ach, oraz gdy chcesz RPC client bez zlozonosci tRPC. Dla duzych monolitow enterprise lepiej sprawdzi sie NestJS lub Fastify.
