GraphQL w Node.js

Apollo Server v4, GraphQL Yoga, DataLoader, subscriptions, persisted queries i Pothos — code-first schema

Czym jest GraphQL?

GraphQL to jezyk zapytan dla API opracowany przez Facebook (2015). Klient precyzuje dokladnie jakich danych potrzebuje — nie wiecej, nie mniej. W odroznieniu od REST, GraphQL ma jeden endpoint (POST /graphql) i pozwala na pobieranie powiazanych danych w jednym zapytaniu, eliminujac problemy over-fetching i under-fetching.

GraphQL sprawdza sie szczegolnie w: aplikacjach mobilnych (ograniczone pasmo), BFF (Backend for Frontend), systemach z wieloma klientami o roznych potrzebach danych oraz szybko ewoluujacych API.

Apollo Server v4

Apollo Server v4 to najpopularniejsza implementacja serwera GraphQL dla Node.js. Wersja 4 wprowadzila uproszczone API, lepszy performance i separacje adapterow HTTP (standalone, Express, Fastify, Hono).

// === Standalone Apollo Server v4 ===
import { ApolloServer } from '@apollo/server';
import { startStandaloneServer } from '@apollo/server/standalone';
import { ApolloServerPluginLandingPageLocalDefault } from '@apollo/server/plugin/landingPage/default';
import { makeExecutableSchema } from '@graphql-tools/schema';
import depthLimit from 'graphql-depth-limit';

// Schema SDL (Schema Definition Language)
const typeDefs = `#graphql
  type Query {
    user(id: ID!): User
    users(page: Int = 1, limit: Int = 20): UserConnection!
    posts(userId: ID): [Post!]!
  }

  type Mutation {
    createUser(input: CreateUserInput!): User!
    updateUser(id: ID!, input: UpdateUserInput!): User!
    deleteUser(id: ID!): Boolean!
  }

  type Subscription {
    userCreated: User!
    postAdded(userId: ID): Post!
  }

  type User {
    id:        ID!
    name:      String!
    email:     String!
    role:      UserRole!
    posts:     [Post!]!
    createdAt: String!
  }

  type Post {
    id:      ID!
    title:   String!
    content: String!
    author:  User!
    tags:    [String!]!
  }

  type UserConnection {
    nodes:    [User!]!
    pageInfo: PageInfo!
    total:    Int!
  }

  type PageInfo {
    hasNextPage:     Boolean!
    hasPreviousPage: Boolean!
    currentPage:     Int!
  }

  enum UserRole { ADMIN USER MODERATOR }

  input CreateUserInput { name: String! email: String! password: String! }
  input UpdateUserInput { name: String email: String }
`;

// Resolwery
const resolvers = {
  Query: {
    user: async (_, { id }, context) => {
      if (!context.user) throw new GraphQLError('Nieautoryzowany', {
        extensions: { code: 'UNAUTHENTICATED' }
      });
      return context.dataSources.userService.findById(id);
    },
    users: async (_, { page, limit }, { dataSources }) => {
      const { nodes, total } = await dataSources.userService.findAll({ page, limit });
      return {
        nodes,
        total,
        pageInfo: {
          hasNextPage: page * limit < total,
          hasPreviousPage: page > 1,
          currentPage: page,
        },
      };
    },
  },

  User: {
    // Resolver pola — uzywany przez DataLoader
    posts: async (user, _, { dataSources }) => {
      return dataSources.postLoader.load(user.id); // DataLoader batching!
    },
  },

  Mutation: {
    createUser: async (_, { input }, { dataSources, pubsub }) => {
      const user = await dataSources.userService.create(input);
      await pubsub.publish('USER_CREATED', { userCreated: user }); // subscription
      return user;
    },
  },
};

// Inicjalizacja serwera
const server = new ApolloServer({
  schema: makeExecutableSchema({ typeDefs, resolvers }),
  validationRules: [depthLimit(5)], // max glebokos zapytania: 5 poziomow
  plugins: [ApolloServerPluginLandingPageLocalDefault({ embed: true })],
});

const { url } = await startStandaloneServer(server, {
  listen: { port: 4000 },
  context: async ({ req }) => ({
    user: await getUserFromToken(req.headers.authorization),
    dataSources: {
      userService: new UserService(),
      postLoader: createPostLoader(), // DataLoader instance per request!
    },
  }),
});
console.log(`GraphQL serwer na ${url}`);

GraphQL Yoga — framework-agnostic

GraphQL Yoga (Grafbase/The Guild) to alternatywa dla Apollo Server. Zbudowana na Web Standard API — dziala na Node.js, Deno, Bun, Cloudflare Workers. Ma wbudowane: subscriptions przez SSE (nie wymaga WebSocket dla prostych przypadkow), persisted queries, response caching i lepszą wydajnosc niz Apollo.

DataLoader — batching i caching

Problem N+1 to klasyczna pulapka GraphQL: zapytanie o 100 uzytkownikow z ich postami wykona 1 + 100 zapytan do bazy. DataLoader rozwiazuje to przez batching — zbiera wszystkie wywolania .load(id) w jednym ticku event loop i wykonuje jedno zapytanie do bazy z wszystkimi ID.

import DataLoader from 'dataloader';

// DataLoader musi byc tworzony PER REQUEST — nie wspoldzielony miedzy requestami
// (cache jest per-request, co zapobiega ujawnieniu danych miedzy uzytkownikami)

function createPostLoader() {
  return new DataLoader<string, Post[]>(async (userIds) => {
    // userIds to tablica wszystkich ID zebranych w jednym ticku
    // np. ['user-1', 'user-2', 'user-3', ...]
    const posts = await db.post.findMany({
      where: { authorId: { in: userIds as string[] } },
    });

    // DataLoader wymaga aby wyniki byly w tej samej kolejnosci co wejscie!
    return userIds.map(userId => posts.filter(p => p.authorId === userId));
  }, {
    cache: true,           // cache w ramach requesta (domyslnie true)
    maxBatchSize: 100,     // max batch size
    batchScheduleFn: (cb) => setTimeout(cb, 0), // lub process.nextTick(cb)
  });
}

// W resolwerze:
User: {
  posts: (user, _, { dataSources }) => dataSources.postLoader.load(user.id),
  // Przy 100 uzytkownikach: 100x .load() -> 1x zapytanie do bazy (batch)
}

Subscriptions — WebSocket

Subscriptions umozliwiaja real-time komunikacje. Apollo Server v4 wspiera subscriptions przez graphql-ws (WebSocket) lub @graphql-sse/server (Server-Sent Events). Wymagaja osobnego serwera WebSocket lub integracji z HTTP serverem.

Pothos — code-first schema builder

Pothos (dawniej GiraphQL) to code-first builder schematu GraphQL z najlepszym typowaniem TypeScript sposrod dostepnych opcji. Schemat jest definiowany w TypeScript — typy SDL sa generowane automatycznie. Pluginy rozszerzaja funkcjonalnosc: auth, relay, prisma, zod.

Zabezpieczenia GraphQL

Zagrozenie Opis Rozwiazanie Biblioteka
Depth attack Głeboko zagniezdzone zapytania wyczerpuja pamiec Limit glebokosci zapytania graphql-depth-limit
Complexity attack Zapytanie o duza liczbe pol/polaczen Limit zlozonosci zapytania graphql-query-complexity
Introspection w produkcji Ujawnienie schematu atakujacemu Wylacz introspection w produkcji Apollo config / custom rule
N+1 queries Nadmierna liczba zapytan do bazy DataLoader batching dataloader
Brak autentykacji Dostep do prywatnych danych Sprawdzanie kontekstu w resolwerach Pothos auth plugin

Persisted Queries

Persisted queries to mechanizm, w którym klient wysyla hash zapytania zamiast pelnego tekstu. Serwer przechowuje mapowanie hash -> zapytanie. Zalety: zmniejszone zuzycie pasma, mozliwosc whitelisty zapytan (bezpieczenstwo), mozliwosc cache'owania na poziomie CDN (GET z hashem).

Apollo vs Yoga vs Pothos — kiedy co wybrac?

Apollo Server — duzy ekosystem, dobra dokumentacja, najpopularniejszy wybor korporacyjny. GraphQL Yoga — edge-compatible, lepszy performance, aktywny rozwoj (The Guild). Pothos — najlepsze TypeScript DX, code-first, wymaga Pothos jako buildera schematu (nie standalone serwer).

GraphQL nie jest zawsze lepszy od REST

GraphQL dodaje zlozonosc: N+1 problem, trudniejsze cacheowanie (POST nie jest cacheowalny przez CDN), trudniejsza autoryzacja na poziomie pol. Dla prostych CRUD API z niezmiennym klientem — REST jest prostsza i lepsza opcja. GraphQL swieci w przypadku wielu klientow z roznymi potrzebami danych.
