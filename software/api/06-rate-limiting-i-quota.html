Rate limiting i quota

Algorytmy ograniczania ruchu, implementacja w Redis, naglowki HTTP i plany uzytkowania.

Dlaczego rate limiting jest konieczny

Rate limiting chroni API przed nadmiernym uzyciem — celowym (DoS, brute force, scraping) i niezamierzonym (bledy w kodzie klienta, petle requestow). Quota to miesięczny lub dobowy limit calkowity, rate limit to chwilowe ograniczenie predkosci.

Algorytmy rate limiting

Token Bucket

Wiadro zawiera tokeny. Kazdy request zuzywa jeden token. Tokeny sa uzupelniane ze stalym tempem (np. 10/s). Jezeli wiadro jest puste — request jest odrzucany. Pozwala na kratkotrefne bursts do maksymalnej pojemnosci wiadra.

Leaky Bucket

Zapytania wpadaja do kolejki (wiadra z dziura). Sa przetwarzane ze stalym tempem niezaleznie od liczby przychodzacych requestow. Wygladzа ruch — brak burstow wychodzacych. Uzywa sie go do ochrony downstream services.

Fixed Window Counter

Zlicza requesty w stale ustalonych oknach czasowych (np. 0-60s, 60-120s). Prosty w implementacji, ale podatny na efekt granicy okna — klient moze wyslac 2x limit na granicy dwoch okien.

Sliding Window Log

Przechowuje timestamp kazdego requestu w posortowanej liscie. Przy kazdym req sprawdza ile requestow bylo w ostatnich N sekundach. Dokladny, ale pamieciozierna przy duzym ruchu.

Sliding Window Counter

Kompromis miedzy fixed window a sliding window log. Uzywa dwoch licznikow (biezace i poprzednie okno) z wazonym interpolowaniem. Dokladny, wydajny, powszechnie stosowany w produkcji.

Implementacja Sliding Window w Redis

-- rate_limit.lua (Redis Lua script — atomowe wykonanie)
local key        = KEYS[1]          -- np. "rl:user:42:GET:/api/users"
local now        = tonumber(ARGV[1]) -- timestamp w ms
local window     = tonumber(ARGV[2]) -- okno w ms, np. 60000 (1 min)
local limit      = tonumber(ARGV[3]) -- maks requestow w oknie
local request_id = ARGV[4]           -- unikalny ID requestu

-- Usun stare wpisy (poza oknem)
redis.call('ZREMRANGEBYSCORE', key, 0, now - window)

-- Policz aktualne requesty
local count = redis.call('ZCARD', key)

if count >= limit then
  -- Pobierz najstarszy timestamp do obliczenia Retry-After
  local oldest = redis.call('ZRANGE', key, 0, 0, 'WITHSCORES')
  local reset_at = oldest[2] + window
  return { 0, count, reset_at }
end

-- Dodaj biezacy request
redis.call('ZADD', key, now, request_id)
redis.call('PEXPIRE', key, window)

return { 1, count + 1, now + window }

// rate-limiter.ts (Node.js + ioredis)
import Redis from 'ioredis';
import { readFileSync } from 'fs';

const redis = new Redis(process.env.REDIS_URL);
const script = readFileSync('./rate_limit.lua', 'utf8');

interface RateLimitResult {
  allowed:   boolean;
  count:     number;
  resetAt:   number;
  remaining: number;
}

async function checkRateLimit(
  userId:  string,
  method:  string,
  path:    string,
  limit:   number = 100,
  window:  number = 60_000,  // 1 minuta w ms
): Promise {
  const key = `rl:${userId}:${method}:${path}`;
  const now = Date.now();
  const requestId = `${now}-${Math.random()}`;

  const [allowed, count, resetAt] = await redis.eval(
    script, 1, key, now, window, limit, requestId
  ) as [number, number, number];

  return {
    allowed:   allowed === 1,
    count,
    resetAt,
    remaining: Math.max(0, limit - count),
  };
}

// Middleware Express
export async function rateLimitMiddleware(req: any, res: any, next: any) {
  const userId = req.user?.id ?? req.ip;
  const plan   = req.user?.plan ?? 'free';

  const limits: Record = {
    free:       100,
    pro:        1000,
    enterprise: 10_000,
  };

  const result = await checkRateLimit(
    userId, req.method, req.path, limits[plan]
  );

  // Zawsze ustawiaj naglowki
  res.set({
    'X-RateLimit-Limit':     limits[plan],
    'X-RateLimit-Remaining': result.remaining,
    'X-RateLimit-Reset':     Math.ceil(result.resetAt / 1000),
    'X-RateLimit-Policy':    `${limits[plan]};w=60`,
  });

  if (!result.allowed) {
    const retryAfter = Math.ceil((result.resetAt - Date.now()) / 1000);
    res.set('Retry-After', retryAfter);
    return res.status(429).json({
      error: {
        code:    'RATE_LIMIT_EXCEEDED',
        message: 'Too many requests. Please slow down.',
        retryAfter,
        resetAt: new Date(result.resetAt).toISOString(),
      }
    });
  }

  next();
}

Quota per plan

Quota to dlugoterminowy limit (dzienny, miesieczny) nalezacy do planu subskrypcji. Rate limit to chwilowe ograniczenie przepustowosci. Oba mechanizmy powinny dzialac jednoczesnie.

Plan Rate limit Dzienna quota Miesięczna quota Burst
Free 10 req/min 1 000 10 000 Nie
Pro 100 req/min 50 000 500 000 200 req przez 10s
Enterprise 1 000 req/min Bez limitu Bez limitu Negocjowalny

Obsluga bledu 429 po stronie klienta

Exponential Backoff z Jitter

Nie ponawiaj requestow natychmiast po 429. Uzyj exponential backoff z losowym jitterem, aby uniknac synchronized retry storm — sytuacji, gdzie wszyscy klienci probuja ponownie w tym samym momencie.

// retry-with-backoff.ts
async function fetchWithRetry(
  url: string,
  options: RequestInit = {},
  maxRetries = 3,
): Promise {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    const response = await fetch(url, options);

    if (response.status !== 429) return response;

    if (attempt === maxRetries) return response;  // ostatnia proba

    // Pobierz Retry-After z naglowka lub oblicz backoff
    const retryAfter = response.headers.get('Retry-After');
    const waitMs = retryAfter
      ? parseInt(retryAfter) * 1000
      : Math.min(1000 * 2 ** attempt + Math.random() * 1000, 30_000);

    console.warn(`Rate limited. Retry ${attempt + 1}/${maxRetries} in ${waitMs}ms`);
    await new Promise(resolve => setTimeout(resolve, waitMs));
  }

  throw new Error('Max retries exceeded');
}

// Przyklad uzycia
const data = await fetchWithRetry('/api/v1/users', {
  headers: { 'Authorization': `Bearer ${token}` }
});

API Gateway — rate limiting bez kodu

Kong, AWS API Gateway, Tyk i Azure APIM oferuja rate limiting jako wbudowane pluginy/polityki. Konfiguracja bez pisania kodu, centralne zarzadzanie, integracja z planami subskrypcji i dashboardem analitycznym.
