Czym jest proces?

Proces to dzialajaca instancja programu. Kazdy proces ma unikalny PID (Process ID), PPID (Parent PID), uzytkownika, grupy, otwarte deskryptory plikow, mape pamieci i stan. W Linuxie kazdy proces jest stworzony przez inny proces (poza init/systemd o PID=1).

StanSymbolOpis
RunningRWykonywany lub w kolejce do CPU
SleepingSCzeka na zdarzenie (przerywalne)
Disk SleepDCzeka na I/O (nieprzerywalne)
StoppedTZatrzymany sygnalem
ZombieZZakonczony, oczekuje na rodzica

ps - lista procesow

# Klasyczne BSD-style: wszystkie procesy systemu
ps aux

# UNIX-style: pelne argumenty komend
ps -ef

# Tylko procesy konkretnego uzytkownika
ps -u jkowalski

# Drzewo procesow z relacjami parent-child
ps auxf
pstree -p

# Sortowanie po zuzyciu CPU
ps aux --sort=-%cpu | head -10

# Sortowanie po pamieci
ps aux --sort=-%mem | head -10

# Konkretny proces po PID
ps -p 1234

# Format niestandardowy
ps -eo pid,ppid,user,%cpu,%mem,cmd --sort=-%mem

top, htop, btop

top to klasyczne narzedzie monitorowania w czasie rzeczywistym. htop to przyjazniejsza wersja z kolorami i obsluga myszki. btop to nowoczesny TUI z pieknym interfejsem (Python/C++).

# Instalacja
sudo apt install htop btop

# Uruchomienie
top
htop
btop

# Top - przydatne klawisze:
# M - sortuj po pamieci
# P - sortuj po CPU
# k - zabij proces (zapyta o PID)
# 1 - pokaz wszystkie rdzenie CPU
# h - pomoc
# q - wyjscie

# Htop - F-keys:
# F2 - setup
# F3 - search
# F5 - tree view
# F6 - sortowanie
# F9 - kill (wybor sygnalu)

Sygnaly i kill

Sygnaly to sposob komunikacji z procesami. Kazdy sygnal ma numer i nazwe. Najczesciej uzywane to SIGTERM (zakoncz grzecznie) i SIGKILL (zabij natychmiast).

SygnalNumerOpis
SIGHUP1Hangup - tradycyjnie reload konfiguracji
SIGINT2Interrupt - Ctrl+C
SIGQUIT3Quit z dump rdzenia
SIGKILL9Natychmiastowe zabicie (nie da sie zignorowac)
SIGTERM15Grzeczne zakonczenie (domyslny)
SIGSTOP19Wstrzymanie procesu (jak Ctrl+Z, ale nie da sie zignorowac)
SIGCONT18Wznowienie wstrzymanego
# Lista wszystkich sygnalow
kill -l

# Domyslnie SIGTERM
kill 1234
kill -SIGTERM 1234
kill -15 1234

# Reload konfiguracji (nginx, sshd reaguja na SIGHUP)
kill -HUP 1234

# Zabij na sile (uzywaj tylko gdy SIGTERM nie pomaga)
kill -9 1234
kill -SIGKILL 1234

# Zabij wiele procesow na raz
kill -9 1234 5678 9012

# pkill - zabij po nazwie
pkill firefox
pkill -9 chrome
pkill -u jkowalski    # wszystkie procesy uzytkownika

# pgrep - znajdz PID po nazwie
pgrep nginx
pgrep -u www-data

# killall - zabij wszystkie procesy o danej nazwie
killall firefox

Zarzadzanie zadaniami w shellu

# Uruchom w tle z &
./long-task.sh &

# Lista zadan w tej sesji
jobs

# Przesun zadanie na pierwszy plan
fg %1

# Wyslij do tla wstrzymane zadanie
bg %1

# Wstrzymaj biezacy proces (Ctrl+Z) i nastepnie:
bg          # uruchom w tle

# nohup - proces przezyje wylogowanie
nohup ./long-task.sh &

# disown - usun zadanie z listy jobs (przezyje wylogowanie)
./script.sh &
disown

nice i renice - priorytety

Wartosci nice okreslaja priorytet procesu w schedulerze. Zakres od -20 (najwyzszy priorytet) do +19 (najnizszy). Tylko root moze ustawiac wartosci ujemne. Domyslna nicea to 0.

# Uruchom z nizszym priorytetem (mniej zasobow CPU)
nice -n 19 ./compress-video.sh

# Wyzszy priorytet (wymaga roota)
sudo nice -n -10 ./important-task.sh

# Zmiana priorytetu juz dzialajacego procesu
renice -n 10 -p 1234

# Wszystkie procesy uzytkownika
sudo renice -n 5 -u jkowalski

screen i tmux

Multipleksery terminalowe pozwalaja uruchamiac procesy w sesjach, ktore przezywaja rozlaczenie SSH. tmux to nowoczesny standard, screen jest starszy ale wciaz uzywany.

# Instalacja
sudo apt install tmux

# Nowa sesja z nazwa
tmux new -s deploy

# Wewnatrz tmux uzywaj prefix Ctrl+b nastepnie:
# c - nowe okno
# n - nastepne okno
# % - podzial pionowy
# " - podzial poziomy
# d - detach (sesja zostaje w tle)
# x - zamknij okno

# Lista aktywnych sesji
tmux ls

# Powrot do sesji
tmux attach -t deploy

# Zabij sesje
tmux kill-session -t deploy

systemd - menedzer uslug

systemd to system init w Ubuntu (od 15.04). Zarzadza usluga (.service), timerami (.timer), socketami (.socket), targetami (runlevele). Glowne narzedzia: systemctl (zarzadzanie), journalctl (logi).

# Status uslugi
sudo systemctl status nginx

# Start, stop, restart, reload
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx       # bez przestoju (jesli wspierane)

# Wlaczenie autostartu przy boot
sudo systemctl enable nginx
sudo systemctl enable --now nginx  # enable + start

# Wylaczenie autostartu
sudo systemctl disable nginx

# Lista wszystkich uslug
systemctl list-units --type=service

# Lista uslug failed
systemctl --failed

# Lista uslug ktore beda startowac
systemctl list-unit-files --state=enabled

# Cell systemu uruchamiania
systemctl get-default       # zazwyczaj graphical.target
sudo systemctl set-default multi-user.target   # tryb tekstowy

Wlasna usluga systemd

# Plik /etc/systemd/system/myapp.service
[Unit]
Description=Moja aplikacja Node.js
After=network.target

[Service]
Type=simple
User=appuser
Group=appuser
WorkingDirectory=/opt/myapp
Environment="NODE_ENV=production"
ExecStart=/usr/bin/node /opt/myapp/server.js
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

# Limity zasobow
LimitNOFILE=65535
MemoryMax=512M
CPUQuota=50%

[Install]
WantedBy=multi-user.target
# Po utworzeniu pliku przeladuj systemd
sudo systemctl daemon-reload

# Wlacz i uruchom
sudo systemctl enable --now myapp

# Sprawdz logi
sudo journalctl -u myapp -f

journalctl - logi systemd

# Wszystkie logi systemu
journalctl

# Tylko z biezacego boot
journalctl -b

# Z poprzedniego boot (-1)
journalctl -b -1

# Logi konkretnej uslugi
journalctl -u nginx
journalctl -u nginx -f          # follow (jak tail -f)

# Z ostatniej godziny
journalctl --since "1 hour ago"

# Konkretny zakres czasu
journalctl --since "2026-05-01" --until "2026-05-07 12:00"

# Tylko bledy
journalctl -p err

# Logi konkretnego procesu po PID
journalctl _PID=1234

# Format JSON (do parsowania)
journalctl -u nginx -o json

# Rozmiar logow
journalctl --disk-usage

# Ograniczenie rozmiaru w /etc/systemd/journald.conf:
# SystemMaxUse=500M
# MaxRetentionSec=1month

cgroups v2

cgroups (control groups) to mechanizm jadra Linux do ograniczania zasobow grup procesow. systemd korzysta z cgroups v2 do nakladania limitow na uslugi. Docker, Kubernetes opieraja sie na cgroups.

# Sprawdzenie wersji cgroups (Ubuntu 22+ uzywa v2)
mount | grep cgroup

# Status uslugi - widac uzycie zasobow z cgroups
systemd-cgls
systemd-cgtop

# Limity ustawiane bezposrednio w pliku .service:
# MemoryMax=2G
# CPUQuota=50%
# IOWeight=100
# TasksMax=500

# Tymczasowa zmiana limitu uslugi
sudo systemctl set-property nginx.service MemoryMax=1G

Monitorowanie zasobow

# Instalacja narzedzi
sudo apt install sysstat iotop nethogs

# Aktywnosc CPU i pamieci (interwaly co 1s)
vmstat 1

# Statystyki I/O dyskow
iostat -x 1
iotop -o      # tylko aktywne procesy I/O

# Statystyki sieci per process
sudo nethogs

# Historyczne dane (sysstat)
sar -u 1 5    # CPU
sar -r 1 5    # pamiec
sar -n DEV 1  # siec

# Wolne miejsce na dyskach
df -h

# Rozmiary katalogow
du -sh /var/log/*

# Otwarte pliki przez proces
lsof -p 1234

# Otwarte porty
sudo lsof -i -P -n | grep LISTEN
sudo ss -tulpn

Stack monitoringu - Prometheus + Grafana

Standardem w monitoringu Linuxa jest stos Prometheus (zbieranie metryk) + Grafana (wizualizacja) + node_exporter (agent na serwerze).

# Instalacja node_exporter (eksporter metryk hosta)
wget https://github.com/prometheus/node_exporter/releases/download/v1.8.0/node_exporter-1.8.0.linux-amd64.tar.gz
tar xvfz node_exporter-1.8.0.linux-amd64.tar.gz
sudo cp node_exporter-1.8.0.linux-amd64/node_exporter /usr/local/bin/

# Stworzenie uslugi systemd
sudo tee /etc/systemd/system/node_exporter.service <<EOF
[Unit]
Description=Node Exporter
After=network.target

[Service]
User=nobody
ExecStart=/usr/local/bin/node_exporter

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable --now node_exporter

# Metryki dostepne pod http://serwer:9100/metrics
curl http://localhost:9100/metrics | head
Diagnostyka problemow z wydajnoscia:
  1. CPU bottleneck: top, htop - sprawdz load average
  2. Pamiec: free -h, vmstat 1 - obserwuj swap
  3. I/O dyskow: iotop, iostat -x 1 - patrz na %util
  4. Siec: iftop, nethogs - kto generuje ruch
  5. Konkretny proces: strace -p PID, ltrace -p PID
