Alpine.js

Minimal JS framework dla interaktywnosci bez SPA. x-data, x-bind, x-on, x-show, x-if, x-for. Idealny z HTMX.

1. Co to Alpine.js?

Alpine.js to minimalistyczny framework JavaScript (ok. 15 kB gzip) przeznaczony do dodawania interaktywnosci bezposrednio w HTML. Nie wymaga buildu, bundlera ani node_modules. Dziala jak "Tailwind dla JavaScript" — logike piszesz jako atrybuty HTML.

Cecha Alpine.js Vue 3 Vanilla JS React
Rozmiar ~15 kB ~33 kB 0 kB ~45 kB
Build step nie opcjonalnie nie tak
Reaktywnosc tak (Proxy) tak (Proxy) reczna tak (Virtual DOM)
SSR-friendly tak tak tak z Next.js
Przeznaczenie drobna interaktywnosc SPA / komponenty proste skrypty zlozony SPA
Integracja z HTMX idealna mozliwa reczna trudna

2. Instalacja

CDN (bez buildu — najszybszy start)

<script defer src="https://cdn.jsdelivr.net/npm/alpinejs@3.x.x/dist/cdn.min.js"></script>

Atrybut defer jest wymagany — Alpine inicjalizuje sie po zaladowaniu DOM. Wersje @3.x.x mozna przypiac do konkretnej wersji (np. @3.14.0).

npm / yarn / pnpm

# instalacja
npm install alpinejs

# import w pliku JS (np. main.js)
import Alpine from 'alpinejs'
window.Alpine = Alpine
Alpine.start()
Wskazowka: Przypisanie do window.Alpine jest opcjonalne, ale ulatwia debugowanie w konsoli przegladarki i dostep z zewnetrznych skryptow.

3. Core directives

Wszystkie dyrektywy Alpine.js to atrybuty HTML z prefiksem x-. Moga byc skracane: x-bind: → :, x-on: → @.

Dyrektywa Skrot Opis Przyklad
x-data — Definuje reaktywny stan komponentu (zakres danych) x-data="{ open: false }"
x-bind : Wiaze atrybut HTML z wyrازeniem JS :class="{ active: open }"
x-on @ Nasluchuje na zdarzenie DOM @click="open = !open"
x-show — Ukrywa/pokazuje element (display:none) na podstawie warunku x-show="open"
x-if — Dodaje/usuwa element z DOM (wymaga <template>) x-if="loggedIn"
x-for — Renderuje liste elementow (wymaga <template>) x-for="item in items"
x-text — Ustawia innerText elementu x-text="count"
x-html — Ustawia innerHTML (uwaga: XSS!) x-html="richContent"
x-model — Dwustronne wiazanie danych z polem formularza x-model="email"
x-transition — Animacje wejscia/wyjscia elementu (CSS classes) x-transition:enter="..."

Przyklad uzycia dyrektyw

<div x-data="{ count: 0, message: '' }">

  <button @click="count++"
           :class="{ 'bg-green-500': count > 5 }">
    Kliknieto: <span x-text="count"></span>
  </button>

  <template x-if="count > 10">
    <p class="text-red-500">Duzo klikniec!</p>
  </template>

  <input x-model="message" placeholder="Wpisz...">
  <p x-text="'Wpisales: ' + message" x-show="message.length > 0"></p>

</div>

4. Magiczne wlasciwosci

Magiczne wlasciwosci sa dostepne wewnatrz kazdego komponentu Alpine bez deklarowania. Maja prefix $.

  • $el — referencja do root elementu DOM komponentu
  • $data — reaktywny obiekt danych biezacego komponentu
  • $store — dostep do globalnych stores (Alpine.store)
  • $watch — obserwuje zmiany wlasciwosci: $watch('open', val => console.log(val))
  • $dispatch — emituje zdarzenie CustomEvent na element: $dispatch('modal-open', { id: 1 })
  • $nextTick — wywoluje callback po nastepnym cyklu reaktywnosci (jak Vue.nextTick)
  • $refs — dostep do elementow oznaczonych x-ref="nazwaRef"
  • $root — root element najblizszego x-data
  • $id — generuje unikalny ID dla dostepnosci (aria)

5. Stores — globalny stan

Alpine.store pozwala na wspoldzielenie stanu miedzy niezaleznymi komponentami na stronie, bez przekazywania props ani eventow.

// Rejestracja store (przed Alpine.start())
Alpine.store('cart', {
  items: [],
  get count() { return this.items.length },
  add(item) { this.items.push(item) },
  remove(id) { this.items = this.items.filter(i => i.id !== id) }
})

// Uzycie w HTML
<button @click="$store.cart.add({ id: 1, name: 'Produkt A' })">
  Dodaj do koszyka
</button>

<span x-text="$store.cart.count"></span> <!-- reaktywnie aktualizowany -->

6. Pluginy oficjalne

  • Focus (@alpinejs/focus) — zarzadzanie focusem klawiatury; x-trap zatrzymuje focus w modalu (dostepnosc)
  • Persist (@alpinejs/persist) — $persist automatycznie zapisuje stan w localStorage
  • Collapse (@alpinejs/collapse) — animacja rozwijania/zwijanieelementu z poprawna wysokoscia
  • Intersect (@alpinejs/intersect) — x-intersect wywoluje akcje gdy element wejdzie/wyjdzie z viewport (IntersectionObserver)
  • Morph (@alpinejs/morph) — inteligentna aktualizacja DOM zachowujaca stan (podobnie jak idiomorph/HTMX)

Przyklad — Persist

<div x-data="{ theme: $persist('light') }">
  <button @click="theme = theme === 'light' ? 'dark' : 'light'">
    Motyw: <span x-text="theme"></span>
  </button>
</div>
<!-- wartosc theme jest automatycznie zapisywana w localStorage -->

7. Integracja z HTMX

Alpine.js i HTMX sa naturalnymi partnerami — HTMX zajmuje sie HTTP requestami i aktualizacja DOM, Alpine dodaje reaktywna interaktywnosc po stronie klienta. Razem zastepuja ciezkie SPA frameworki dla wiekszosci przypadkow.

Zasada podzialu pracy: HTMX = communication (server round-trips, DOM swap). Alpine.js = behavior (animacje, walidacja kliencka, lokalny stan UI). 
<!-- HTMX ladownie formularz, Alpine animuje wynik i waliduje -->
<div x-data="{ loading: false, error: '' }">

  <form
    hx-post="/api/subscribe"
    hx-target="#result"
    hx-swap="innerHTML transition:true"
    @htmx:before-request="loading = true; error = ''"
    @htmx:after-request="loading = false"
    @htmx:response-error="error = 'Blad serwera — sprobuj ponownie'"
  >
    <input type="email" name="email" required>
    <button type="submit" :disabled="loading">
      <span x-show="!loading">Zapisz sie</span>
      <span x-show="loading">Ladowanie...</span>
    </button>
  </form>

  <p x-show="error" x-text="error" class="text-red-500"></p>
  <div id="result"></div>

</div>

HTMX wstrzykuje serwer-renderowany HTML do #result. Alpine zarzadza stanem ladowania i bledem — zero dodatkowego JS.

8. Kiedy uzywac Alpine vs Vue / React

Pytanie Czy strona jest server-rendered (PHP, Rails, Django, Laravel)?
TAK Alpine.js + HTMX — idealne dopasowanie. Nie potrzebujesz SPA.
Pytanie Czy potrzebujesz zlozone routing po stronie klienta, code-splitting, SSR z hydratacja?
TAK Vue 3 / Nuxt lub React / Next.js — potrzebujesz pelnego frameworku SPA.
Pytanie Czy to statyczna strona z kilkoma interaktywnymi elementami (modal, dropdown, tabs)?
TAK Alpine.js — mniej niz 15 kB, zero konfiguracji, czysty HTML.
Pytanie Czy potrzebujesz wspoldzielonego stanu miedzy wieloma niezaleznymi widgetami?
TAK Alpine.js + Alpine.store wystarczy. Ewentualnie Vue 3 dla bardziej zlozonych scenariuszy.
Pytanie Czy projekt to PWA / native-like mobile experience z gestures, offline, push?
TAK React Native / Capacitor / Ionic — Alpine nie jest przeznaczony do mobilnych aplikacji.

9. Przyklad kompletny: formularz z walidacja, modal, dropdown

Ponizej pelny przyklad strony demonstrujacej formularz z walidacja kliencka, modal oraz dropdown — wszystko w czystym HTML z Alpine.js, bez zewnetrznych zaleznoci poza CDN.

<!DOCTYPE html>
<html lang="pl">
<head>
  <script defer src="https://cdn.jsdelivr.net/npm/alpinejs@3.x.x/dist/cdn.min.js"></script>
</head>
<body>

<!-- DROPDOWN -->
<div x-data="{ open: false }" class="relative">
  <button @click="open = !open">Menu ▾</button>
  <ul x-show="open"
       @click.outside="open = false"
       x-transition
       class="dropdown-menu">
    <li><a href="#">Opcja 1</a></li>
    <li><a href="#">Opcja 2</a></li>
  </ul>
</div>

<!-- FORMULARZ Z WALIDACJA -->
<div x-data="formApp()">
  <form @submit.prevent="submit()" novalidate>

    <label>Email
      <input type="email" x-model="form.email"
             @blur="validate('email')"
             :class="{ 'border-red-500': errors.email }">
      <span x-text="errors.email" class="text-red-500 text-sm"></span>
    </label>

    <button type="submit" :disabled="!isValid">Wyslij</button>
  </form>
</div>

<!-- MODAL -->
<div x-data="{ showModal: false }">
  <button @click="showModal = true">Otworz modal</button>

  <template x-teleport="body">
    <div x-show="showModal"
          x-transition:enter="transition ease-out duration-200"
          x-transition:enter-start="opacity-0 scale-95"
          x-transition:enter-end="opacity-100 scale-100"
          class="modal-overlay"
          @keydown.escape.window="showModal = false">
      <div class="modal-box" @click.outside="showModal = false">
        <h2>Modal</h2>
        <button @click="showModal = false">Zamknij</button>
      </div>
    </div>
  </template>
</div>

<script>
function formApp() {
  return {
    form: { email: '' },
    errors: { email: '' },
    get isValid() { return !this.errors.email && this.form.email },
    validate(field) {
      if (field === 'email') {
        this.errors.email = !/^[^@]+@[^@]+\.[^@]+$/.test(this.form.email)
          ? 'Nieprawidlowy adres email' : ''
      }
    },
    submit() {
      this.validate('email')
      if (this.isValid) alert('Wyslano: ' + this.form.email)
    }
  }
}
</script>
</body></html>
x-teleport (Alpine 3.x) przenosi element do dowolnego miejsca w DOM (np. bezposrednio do body), co eliminuje problemy z z-index i overflow przy modalach.
