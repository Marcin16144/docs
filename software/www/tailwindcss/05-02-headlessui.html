Headless UI — unstyled accessible components

Oficjalna biblioteka headless komponentow od Tailwind Labs. Logika + accessibility, styling zostawia Tobie. React i Vue, free & MIT.

Czym jest Headless UI?

Headless UI to open-source biblioteka tzw. "headless" (czyli unstyled) komponentow UI od Tailwind Labs — tych samych ludzi co Tailwind CSS, Catalyst i Tailwind Plus. Wydana w 2020, w 2026 to v2.x (React, Vue) jako stable.

Kluczowe info w skrocie

  • Tworca: Tailwind Labs (Adam Wathan, Robin Malfait, Jonathan Reinink)
  • Wydany: 2020 (v0.1), v1.0 w 2021, v2.0 w 2024
  • Licencja: MIT (FREE, open source)
  • Frameworki: React (@headlessui/react), Vue 3 (@headlessui/vue)
  • TypeScript: Full support, type-safe API
  • Bundle size: ~10-20 KB (tree-shakeable)
  • Repo: github.com/tailwindlabs/headlessui
  • Docs: headlessui.com
  • Filozofia: "Logic + a11y, but you bring the styles"

Co znaczy "headless"?

W swiecie UI "headless" oznacza komponent bez wlasnej szaty graficznej. Headless UI dostarcza:

Co Headless UI DAJE:

  • ✓ Logika behavioru (state management, event handling)
  • ✓ Accessibility (a11y) — ARIA roles, ARIA labels, role="dialog", aria-expanded, etc.
  • ✓ Keyboard navigation — Tab, Arrow keys, Enter, Escape, Home/End
  • ✓ Focus management — focus trap w modalach, restore focus on close
  • ✓ Screen reader announcements
  • ✓ WAI-ARIA Authoring Practices compliance
  • ✓ Animations support (Transition komponent)
  • ✓ Click-outside-to-close w popovers/dialogs

Czego Headless UI NIE daje:

  • ✗ Stylingu — wyglad zerowy out-of-the-box
  • ✗ Animacji (poza Transition, ale tez minimalny)
  • ✗ Themes
  • ✗ Predefiniowanych "looks"
  • ✗ Color systems

Wszystko powyzsze Ty dodajesz przez Tailwind classes (lub jakikolwiek inny CSS).

Dlaczego headless approach?

Tradycyjne UI library (Material UI, Bootstrap) mieszaja logike + style. To powoduje:

  • Konflikty stylingowe (musisz nadpisywac CSS specificity)
  • Kazdy projekt wyglada podobnie (Material look, Bootstrap look)
  • Trudnosc tworzenia unique brand designs
  • Wieksze bundles (CSS-in-JS runtime)
  • Slabsze accessibility (czesto custom impl, nie WAI-ARIA standards)

Headless UI rozdziela te dwie warstwy:

Wymagania (2026)

  • React: 18+ (React 19 fully supported)
  • Vue: 3.x
  • TypeScript: 5.x (recommended)
  • Bundler: Vite, webpack, esbuild — wszystkie dziala

Przyklady uzycia

Menu (Dropdown)

Najpopularniejszy komponent. Klasyczny user menu, action menu:

import { Menu, MenuButton, MenuItem, MenuItems } from '@headlessui/react'
import { ChevronDownIcon } from '@heroicons/react/20/solid'

export function UserMenu() {
  return (
    <Menu>
      <MenuButton className="inline-flex items-center gap-2
        rounded-md bg-white px-3 py-1.5 text-sm font-semibold
        text-gray-900 shadow-sm ring-1 ring-gray-300
        hover:bg-gray-50">
        Account
        <ChevronDownIcon className="size-4" />
      </MenuButton>

      <MenuItems
        anchor="bottom end"
        className="w-52 origin-top-right rounded-md bg-white shadow-lg
          ring-1 ring-black/5 focus:outline-none p-1
          transition data-[closed]:opacity-0
          data-[enter]:duration-100 data-[leave]:duration-75"
      >
        <MenuItem>
          <a className="group flex w-full items-center rounded-md px-2 py-2
            text-sm text-gray-900 data-[focus]:bg-blue-500
            data-[focus]:text-white"
            href="/account">
            Account settings
          </a>
        </MenuItem>

        <MenuItem>
          <a className="..." href="/license">
            License
          </a>
        </MenuItem>

        <MenuItem disabled>
          <span className="opacity-50">Documentation</span>
        </MenuItem>

        <div className="my-1 h-px bg-gray-200" />

        <MenuItem>
          <button className="...">
            Sign out
          </button>
        </MenuItem>
      </MenuItems>
    </Menu>
  )
}

Co Headless UI obsluguje automatycznie:

  • Otwarcie/zamkniecie po kliknieciu w MenuButton
  • Zamykanie po kliknieciu poza menu
  • Zamykanie na Escape
  • Keyboard navigation (Up/Down arrows, Home, End)
  • Auto-focus na pierwszy item przy otwarciu
  • ARIA: role="menu", aria-labelledby, aria-orientation, role="menuitem"
  • Focus restoration po zamknieciu
  • Anchor positioning (od v2.0) — automatycznie reposition na malych ekranach

Listbox (Select replacement)

import {
  Listbox, ListboxButton, ListboxOption, ListboxOptions
} from '@headlessui/react'
import { CheckIcon, ChevronDownIcon } from '@heroicons/react/20/solid'
import { useState } from 'react'

const people = [
  { id: 1, name: 'Anna Kowalska' },
  { id: 2, name: 'Jan Nowak' },
  { id: 3, name: 'Tomasz Wisniewski' },
]

export function PersonSelect() {
  const [selected, setSelected] = useState(people[0])

  return (
    <Listbox value={selected} onChange={setSelected}>
      <ListboxButton className="relative w-64 rounded-md bg-white py-2
        pl-3 pr-10 text-left shadow ring-1 ring-gray-300">
        {selected.name}
        <ChevronDownIcon className="absolute right-2 top-2.5 size-4" />
      </ListboxButton>

      <ListboxOptions
        anchor="bottom"
        className="w-[var(--button-width)] rounded-md bg-white shadow-lg
          ring-1 ring-black/5 mt-1 p-1"
      >
        {people.map((person) => (
          <ListboxOption
            key={person.id}
            value={person}
            className="group flex items-center gap-2 rounded-md px-2 py-1.5
              cursor-pointer data-[focus]:bg-blue-100 data-[selected]:font-bold"
          >
            <CheckIcon className="size-4 invisible group-data-[selected]:visible" />
            {person.name}
          </ListboxOption>
        ))}
      </ListboxOptions>
    </Listbox>
  )
}

Combobox (Autocomplete)

import {
  Combobox, ComboboxButton, ComboboxInput,
  ComboboxOption, ComboboxOptions
} from '@headlessui/react'
import { useState } from 'react'

const people = [
  { id: 1, name: 'Anna Kowalska' },
  { id: 2, name: 'Jan Nowak' },
  // ... 100+ items
]

export function PersonCombobox() {
  const [query, setQuery] = useState('')
  const [selected, setSelected] = useState(null)

  const filtered = query === ''
    ? people
    : people.filter(p =>
        p.name.toLowerCase().includes(query.toLowerCase())
      )

  return (
    <Combobox value={selected} onChange={setSelected}>
      <ComboboxInput
        className="w-64 rounded-md border border-gray-300 px-3 py-2"
        displayValue={(person) => person?.name ?? ''}
        onChange={(e) => setQuery(e.target.value)}
      />
      <ComboboxOptions
        anchor="bottom"
        className="w-[var(--input-width)] rounded-md bg-white shadow mt-1"
      >
        {filtered.map((person) => (
          <ComboboxOption
            key={person.id}
            value={person}
            className="px-2 py-1.5 data-[focus]:bg-blue-100"
          >
            {person.name}
          </ComboboxOption>
        ))}
      </ComboboxOptions>
    </Combobox>
  )
}

Dialog (Modal)

import {
  Dialog, DialogPanel, DialogTitle, DialogBackdrop
} from '@headlessui/react'
import { useState } from 'react'

export function ConfirmDialog() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <>
      <button onClick={() => setIsOpen(true)}>Open</button>

      <Dialog open={isOpen} onClose={setIsOpen} className="relative z-50">
        {/* Backdrop overlay */}
        <DialogBackdrop className="fixed inset-0 bg-black/50" />

        {/* Centered panel */}
        <div className="fixed inset-0 flex items-center justify-center p-4">
          <DialogPanel className="max-w-md rounded-xl bg-white p-6 shadow-xl">
            <DialogTitle className="text-lg font-bold">
              Potwierdzenie
            </DialogTitle>

            <p className="mt-2 text-gray-600">
              Czy na pewno chcesz wykonac te akcje?
            </p>

            <div className="mt-4 flex gap-2 justify-end">
              <button
                onClick={() => setIsOpen(false)}
                className="px-3 py-1.5 rounded bg-gray-200">
                Anuluj
              </button>
              <button
                onClick={() => { onConfirm(); setIsOpen(false) }}
                className="px-3 py-1.5 rounded bg-red-600 text-white">
                Potwierdz
              </button>
            </div>
          </DialogPanel>
        </div>
      </Dialog>
    </>
  )
}

Headless UI Dialog automatycznie zarzadza:

  • Focus trap — Tab krazy w obrebie modal
  • Escape to close
  • Click backdrop to close
  • Body scroll lock (zapobiega scrollowaniu pod modal)
  • Restore focus na trigger button po zamknieciu
  • Portal — render w <body>, nie w parent component

Transition (animacje)

Headless UI posiada minimalny komponent Transition dla enter/leave animations:

import { Transition } from '@headlessui/react'
import { useState } from 'react'

export function FadeBox() {
  const [show, setShow] = useState(false)

  return (
    <>
      <button onClick={() => setShow(s => !s)}>Toggle</button>

      <Transition
        show={show}
        enter="transition-opacity duration-300"
        enterFrom="opacity-0"
        enterTo="opacity-100"
        leave="transition-opacity duration-200"
        leaveFrom="opacity-100"
        leaveTo="opacity-0"
      >
        <div className="bg-blue-500 text-white p-4">
          Hello!
        </div>
      </Transition>
    </>
  )
}

W v2.x wiele komponentow (Dialog, Menu, Listbox) ma data attributes dla animacji bez Transition komponentu:

<DialogPanel className="
  data-[closed]:opacity-0
  data-[closed]:scale-95
  transition duration-200
">
  ...
</DialogPanel>

Headless UI v2 — co nowego (od 2024)

Anchor positioning (najwazniejsza zmiana)

Komponenty floating (Menu, Listbox, Combobox, Popover) maja wbudowany floating-ui:

// v1 wymagal recznego positioning
<Menu>
  <MenuButton>...</MenuButton>
  <MenuItems>... bez auto-positioning ...</MenuItems>
</Menu>

// v2 — natywne anchor prop:
<MenuItems anchor="bottom end">
  ...
</MenuItems>

// Mozesz tez modyfikator:
<MenuItems anchor={{ to: 'bottom', gap: '8px', padding: '4px' }}>
  ...
</MenuItems>

Data attributes zamiast render props

// v1 wymagal render props dla state
<Menu>
  <MenuButton>
    {({ open }) => (
      <span className={open ? 'text-blue-500' : 'text-gray-700'}>
        Menu
      </span>
    )}
  </MenuButton>
</Menu>

// v2 — data attributes (cleaner)
<Menu>
  <MenuButton className="text-gray-700 data-[open]:text-blue-500">
    Menu
  </MenuButton>
</Menu>

Kiedy wybrac Headless UI vs Radix UI?

Headless UI gdy:

  • Uzywasz Tailwind CSS (data attributes idealnie integruje sie)
  • Potrzebujesz Vue support
  • Mniejszy bundle priorytet
  • Prostsze API jest preferowane
  • Buduje na Catalyst lub Tailwind UI

Radix UI gdy:

  • Uzywasz shadcn/ui (Radix to fundament shadcn)
  • Potrzebujesz wiekszej liczby komponentow (Slider, Toast, ContextMenu, NavigationMenu, Toolbar, Toggle, etc.)
  • Najwyzszy poziom a11y i mobile/touch behavior
  • Tylko React
  • Chcesz state machine visibility (Ark UI dla tego)

Headless UI w bibliotece komponentow

Wiele popular UI libraries w 2026 buduje na Headless UI:

  • Catalyst (Tailwind Labs) — application UI kit, oparty 100% na Headless UI
  • Tailwind UI — React/Vue snippets, czesto uzywaja Headless UI
  • Tailwind Templates (Studio, Salient, etc.) — templates z Headless UI
  • Plain Tailwind projects — najczestszy wybor dla custom components

Best practices

  1. Uzywaj data attributes (v2) zamiast render props gdzie mozliwe — cleaner code
  2. Combinuj z Tailwind — data attributes pasuja idealnie do Tailwind utilities (data-[focus]:bg-blue-500)
  3. Nazwaj swoje wrappery dla powtarzalnosci — np. <MyDialog> wrapper z domyslnymi stylami
  4. Heroicons — zalecana ikona library od Tailwind Labs (@heroicons/react)
  5. Nie nadmiernie animuj — Headless UI ma minimalne animacje, dodaj tylko gdy potrzebne
  6. Test keyboard — przejdz przez aplikacje tylko klawiatura
  7. Test screen reader — VoiceOver (Mac), NVDA (Windows)
  8. Use TypeScript — Headless UI ma excellent type inference
  9. Combobox dla wszystkich select-like — nawet z 5 options, lepsza UX niz native select
  10. Portal dla z-index issues — Dialog uzywa Portal automatycznie

Common pitfalls

Czego unikac

  • Zapominanie o stylach — Headless UI nie ma defaultow, musisz wszystko styliowac
  • Nieustawienie z-index dla Menu/Popover — moga byc pod innymi elementami
  • Mixed v1 i v2 imports — sprawdz wersje w package.json
  • Wlasny escape handler — Headless UI sam obsluguje, nie nadpisuj
  • Custom focus management — pozwol Headless UI to robic
  • Inline styles dla animations zamiast Tailwind classes — gorsza performance

Performance

  • Tree-shakeable — tylko uzywane komponenty w bundle
  • No runtime CSS-in-JS — caly styling przez Tailwind = static CSS
  • React 19 compatible — uzywa nowoczesne hooks
  • Virtualizacja dla bardzo dlugich list (1000+ items) — uzyj @tanstack/react-virtual z Listbox
  • Lazy load dialogs — uzyj React.lazy dla rzadko otwieranych modals

Podsumowanie

Headless UI to fundament nowoczesnego Tailwind ecosystem. Zapewnia logike + accessibility dla najpopularniejszych UI primitives, a styling pozostawia tobie. W 2026 to de facto standard dla React + Tailwind oraz Vue + Tailwind projektow.

Plusy: free, MIT, mala biblioteka, doskonala integracja z Tailwind przez data attributes, Vue support, sprawdzone w produkcji (Tailwind UI, Catalyst).

Minusy: mniej komponentow niz Radix UI, slabsze touch/mobile interactions niz React Aria, tylko 12 komponentow vs 30+ w konkurencji.

Dla wiekszosci Tailwind projektow Headless UI jest wystarczajacy. Jesli potrzebujesz wiecej (Slider, Toast, ContextMenu, NavigationMenu, Toolbar) — dodaj Radix UI obok Headless UI.
