Podstawy Tailwind CSS

Filozofia utility-first, instalacja, Tailwind v4, pierwszy projekt

Czym jest Tailwind CSS?

Tailwind CSS to framework CSS oparty na klasach utility — pojedyncze klasy odpowiadaja jednej wlasciwosci CSS. Zamiast pisac wlasne style, sklejasz interfejs z atomowych klockow w HTML. Powstal w 2017 roku, autor: Adam Wathan. Obecnie jest najczesciej wybieranym frameworkiem CSS w nowych projektach.

Filozofia utility-first

Klasyczne podejscie polega na pisaniu wlasnych klas semantycznych (np. .btn-primary, .card). Tailwind odwraca to: zamiast nazywac komponenty, opisujesz ich wyglad bezposrednio w HTML.

Tradycyjne CSS

<!-- HTML -->
<button class="btn-primary">Klik</button>

<!-- CSS -->
.btn-primary {
  padding: 0.5rem 1rem;
  background: #2563eb;
  color: white;
  border-radius: 0.5rem;
}

Tailwind

<button class="px-4 py-2 bg-blue-600 text-white rounded-lg hover:bg-blue-700">
  Klik
</button>

Plusy podejscia utility-first:

  • Nie martwisz sie o nazewnictwo (problem CSS naming jest legendarny)
  • Style sa lokalne — nie ma efektow ubocznych
  • Latwo edytowac — zmieniasz klase w HTML, a nie w odleglym pliku CSS
  • JIT generuje tylko wykorzystane klasy — bardzo maly bundle
  • Naturalna wspolpraca z komponentami React/Vue/Svelte

Wersja 4 (2024+)

Tailwind v4 (stable od 2024) wprowadzil duze zmiany:

  • CSS-first config — konfiguracja w CSS przez @theme zamiast tailwind.config.js
  • Lighter engine — Oxide (Rust) zamiast PostCSS, kompilacja 5-10x szybsza
  • Nowe wlasciwosci (CSS variables, container queries, P3 wide-gamut colors)
  • Zero-config import — @import "tailwindcss" wystarczy
  • Ulepszony JIT — mniejsze CSS, lepsze tree-shaking

Instalacja

Tailwind v4 z Vite

npm create vite@latest my-app -- --template vanilla
cd my-app
npm install
npm install tailwindcss @tailwindcss/vite

Plik vite.config.js:

import { defineConfig } from 'vite';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  plugins: [tailwindcss()]
});

Plik style.css:

@import "tailwindcss";

/* Optional: Twoje wlasne style */
@layer components {
  .btn {
    @apply px-4 py-2 rounded-lg font-semibold;
  }
}

Tailwind v4 z PostCSS

npm install tailwindcss @tailwindcss/postcss postcss

// postcss.config.js
export default {
  plugins: {
    "@tailwindcss/postcss": {}
  }
};

Tailwind CLI (najprostsze)

npm install -D tailwindcss
npx tailwindcss -i input.css -o dist/output.css --watch

CSS-first config (v4)

Zamiast tailwind.config.js uzywasz @theme bezposrednio w CSS:

@import "tailwindcss";

@theme {
  --color-brand: #ff6b35;
  --color-brand-dark: #cc4419;
  --font-display: "Cabinet Grotesk", sans-serif;
  --breakpoint-3xl: 1920px;
  --spacing-128: 32rem;
}

/* Generuje automatycznie:
   .text-brand, .bg-brand, .border-brand,
   .font-display, .max-w-128 itd. */

JIT compiler

Tailwind v3+ uzywa JIT (Just-In-Time) compilera. Skanuje pliki HTML/JSX/Vue/Svelte w projekcie i generuje TYLKO klasy, ktorych uzywasz. Dzieki temu finalny CSS to zwykle 10–30 KB, niezaleznie od ile klas oferuje framework.

Skanowane pliki

W v4 to dziala automatycznie — wszystkie pliki w projekcie sa skanowane bez konfiguracji content. W v3 trzeba bylo zdefiniowac:

// v3 tailwind.config.js
module.exports = {
  content: [
    "./src/**/*.{html,js,jsx,ts,tsx,vue}",
    "./pages/**/*.{js,jsx,ts,tsx}",
  ]
}

Editor support

  • Tailwind CSS IntelliSense (VSCode) — autocomplete, podglad kolorow, hover documentation
  • Prettier plugin (prettier-plugin-tailwindcss) — sortuje klasy w deterministycznej kolejnosci
  • JetBrains IDE (WebStorm, Rider) — wsparcie wbudowane

Wskazowka — sortowanie klas

Konwencja Tailwind: uzywaj Prettier plugin do sortowania. Bez tego klasy w HTML nieuporzadkowane — tym samym diff w PR jest bezsensowny. Plugin ustawia kolejnosc layout → spacing → typography → colors → states.
