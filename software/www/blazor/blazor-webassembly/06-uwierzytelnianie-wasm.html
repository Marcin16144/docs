Uwierzytelnianie Blazor WASM

OIDC, MSAL, OAuth 2.0 PKCE, BFF pattern, token storage

Wyzwanie WASM — bezpieczne tokeny

Blazor WASM dziala w przegladarce — cala logika i stan sa dostepne dla XSS. To zmienia podejscie do auth:

  • Tokeny w localStorage = nieuchronnie XSS-vulnerable
  • Tokeny w sessionStorage = jak wyzej, jeszcze gorzej (per zakladka)
  • Tokeny w pamieci JS = znikaja po refresh, niewygodne UX
  • Najlepiej: BFF pattern — tokeny w httpOnly cookie

OIDC z OpenID Connect (autoryzacja)

Standard branzy — OAuth 2.0 + OpenID Connect. Wspierany przez Auth0, Azure AD, Okta, Keycloak, IdentityServer.

// Program.cs
builder.Services.AddOidcAuthentication(options =>
{
    builder.Configuration.Bind("Oidc", options.ProviderOptions);
    options.ProviderOptions.ResponseType = "code";
    options.ProviderOptions.DefaultScopes.Add("openid");
    options.ProviderOptions.DefaultScopes.Add("profile");
    options.ProviderOptions.DefaultScopes.Add("email");
});
// appsettings.json
{
  "Oidc": {
    "Authority": "https://example.eu.auth0.com",
    "ClientId": "abc123",
    "RedirectUri": "https://app.example.com/authentication/login-callback",
    "PostLogoutRedirectUri": "https://app.example.com/"
  }
}

OAuth 2.0 PKCE flow

PKCE (Proof Key for Code Exchange) — standard dla SPA aplikacji. Eliminuje potrzebe client secret w przegladarce.

  1. WASM generuje code_verifier (random string)
  2. WASM oblicza code_challenge = SHA256(code_verifier)
  3. Wysyla user na /authorize z code_challenge
  4. Otrzymuje authorization_code z callback
  5. Wymienia kod na token wysylajac code_verifier
  6. Server weryfikuje hash — eliminuje interception attacks

OIDC handler w Blazor uzywa PKCE automatycznie.

BFF pattern (preferowany 2026)

Backend-For-Frontend — eliminuje tokeny z przegladarki.

Klient (Blazor WASM)
    | (cookies httpOnly)
    v
BFF API (ASP.NET Core)
    | (server-side tokens)
    v
Identity Provider (Auth0, Entra ID)

BFF API dziala jako proxy. WASM nie ma dostepu do tokenu — nie moze byc XSS-stolen.

Implementacja BFF z YARP

// BFF Program.cs
builder.Services.AddAuthentication(opts =>
{
    opts.DefaultScheme = CookieAuthenticationDefaults.AuthenticationScheme;
    opts.DefaultChallengeScheme = OpenIdConnectDefaults.AuthenticationScheme;
})
.AddCookie(opts =>
{
    opts.Cookie.HttpOnly = true;
    opts.Cookie.SecurePolicy = CookieSecurePolicy.Always;
    opts.Cookie.SameSite = SameSiteMode.Strict;
})
.AddOpenIdConnect(opts =>
{
    opts.Authority = "https://example.eu.auth0.com";
    opts.ClientId = "abc";
    opts.ClientSecret = builder.Configuration["Auth0:ClientSecret"];
    opts.SaveTokens = true; // server-side
});

// Reverse proxy do API
builder.Services.AddReverseProxy()
    .LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"))
    .AddTransforms(b => b.AddRequestTransform(async ctx =>
    {
        var token = await ctx.HttpContext.GetTokenAsync("access_token");
        if (token != null)
            ctx.ProxyRequest.Headers.Authorization = new("Bearer", token);
    }));

Custom AuthenticationStateProvider

Dla wlasnych systemow (legacy, custom JWT) tworzysz wlasny provider.

public class CustomAuthStateProvider : AuthenticationStateProvider
{
    private readonly ILocalStorageService localStorage;
    private readonly HttpClient http;

    public override async Task<AuthenticationState> GetAuthenticationStateAsync()
    {
        var token = await localStorage.GetItemAsync<string>("authToken");

        if (string.IsNullOrEmpty(token))
            return Anonymous;

        var claims = ParseClaimsFromJwt(token);
        var identity = new ClaimsIdentity(claims, "jwt");
        return new AuthenticationState(new ClaimsPrincipal(identity));
    }

    public void NotifyUserAuthentication(string token)
    {
        NotifyAuthenticationStateChanged(GetAuthenticationStateAsync());
    }

    private static AuthenticationState Anonymous =>
        new(new ClaimsPrincipal(new ClaimsIdentity()));
}

Refresh token rotation

Dla dlugotrwalych sesji uzywaj refresh tokens. Standardowo:

  • access_token — krotki (15 min - 1 godz)
  • refresh_token — dlugi (dni-tygodnie), uzywany do regeneracji access
  • Rotation — kazda regeneracja invaliduje stary refresh

Common security mistakes

  • Tokeny w localStorage — XSS storno
  • Brak HTTPS — man-in-the-middle
  • Brak walidacji audience na JWT
  • Liberalne CORS (allow any origin)
  • Polleganie tylko na walidacji client-side
  • Brak CSP header — XSS injection
  • Logowanie tokenow do console / Application Insights

Rekomendowany pattern 2026

  1. Pierwszorzednie: BFF pattern z httpOnly cookies
  2. Drugorzendnie: OIDC + MSAL/AddOidcAuthentication, ale w pamieci tokenu
  3. Authorization na komponencie i route
  4. Refresh token rotation
  5. HTTPS tylko, HSTS, CSP
  6. Walidacja na BFF/API tez (nie tylko WASM)
