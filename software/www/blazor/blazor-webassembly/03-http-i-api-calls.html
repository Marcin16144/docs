HttpClient w WASM

W Blazor WASM HttpClient jest wbudowanym serwisem — pod spodem uzywa Fetch API przegladarki. Wszystkie ograniczenia browsera obowiazuja: same-origin policy, CORS, brak dostepu do ciastek other origin (chyba ze withCredentials).

// Program.cs
builder.Services.AddScoped(sp => new HttpClient
{
    BaseAddress = new Uri(builder.HostEnvironment.BaseAddress)
});

Najczestsze operacje

@inject HttpClient Http

@code {
    private List<Product>? products;

    protected override async Task OnInitializedAsync()
    {
        // GET z deserializacja JSON
        products = await Http.GetFromJsonAsync<List<Product>>("api/products");
    }

    private async Task CreateProduct(Product product)
    {
        // POST z serializacja JSON
        var response = await Http.PostAsJsonAsync("api/products", product);
        response.EnsureSuccessStatusCode();
        var created = await response.Content.ReadFromJsonAsync<Product>();
    }

    private async Task UpdateProduct(int id, Product product)
    {
        await Http.PutAsJsonAsync($"api/products/{id}", product);
    }

    private async Task DeleteProduct(int id)
    {
        await Http.DeleteAsync($"api/products/{id}");
    }
}

Named HttpClients

Dla aplikacji wywolujacej kilka roznych API uzywaj IHttpClientFactory:

// Program.cs
builder.Services.AddHttpClient("PublicApi", client =>
{
    client.BaseAddress = new Uri("https://api.public.com/");
    client.DefaultRequestHeaders.Add("Accept", "application/json");
});

builder.Services.AddHttpClient("PrivateApi", client =>
{
    client.BaseAddress = new Uri("https://api.private.com/");
})
.AddHttpMessageHandler<AuthHandler>();
@inject IHttpClientFactory ClientFactory

@code {
    private async Task LoadData()
    {
        var publicClient = ClientFactory.CreateClient("PublicApi");
        var data = await publicClient.GetFromJsonAsync<List<Item>>("items");
    }
}

Typed clients

Najczystsza opcja — klasa serwisu przyjmujaca HttpClient w konstruktorze.

public class ProductApi
{
    private readonly HttpClient http;

    public ProductApi(HttpClient http)
    {
        this.http = http;
    }

    public async Task<List<Product>> GetAllAsync()
        => await http.GetFromJsonAsync<List<Product>>("api/products") ?? new();

    public async Task<Product> CreateAsync(Product product)
    {
        var res = await http.PostAsJsonAsync("api/products", product);
        return await res.Content.ReadFromJsonAsync<Product>() ?? product;
    }
}

// Program.cs
builder.Services.AddHttpClient<ProductApi>(client =>
{
    client.BaseAddress = new Uri("https://api.example.com/");
});

JWT token handling

Dla zabezpieczonych API Blazor WASM moze uzywac DelegatingHandler do dodawania bearer tokena.

public class AuthHandler : DelegatingHandler
{
    private readonly ILocalStorageService localStorage;

    public AuthHandler(ILocalStorageService localStorage)
    {
        this.localStorage = localStorage;
    }

    protected override async Task<HttpResponseMessage> SendAsync(
        HttpRequestMessage request, CancellationToken ct)
    {
        var token = await localStorage.GetItemAsync<string>("authToken");
        if (!string.IsNullOrEmpty(token))
            request.Headers.Authorization = new("Bearer", token);

        return await base.SendAsync(request, ct);
    }
}

// Program.cs
builder.Services.AddTransient<AuthHandler>();
builder.Services.AddHttpClient("Api", c => c.BaseAddress = new Uri(...))
    .AddHttpMessageHandler<AuthHandler>();

BFF pattern (preferowany 2026)

Backend-For-Frontend — Blazor WASM rozmawia tylko z wlasnym backend, ktory autentykuje przez httpOnly cookie. Backend dalej rozmawia z innymi serwisami uzywajac dlugotrwalych tokenow.

Klient (Blazor WASM)
     |
     |  cookie: SessionId (httpOnly)
     v
BFF (ASP.NET Core API)
     |
     |  bearer token (server-side)
     v
Identity Server / external API

Korzysci: token nie jest dostepny dla XSS (httpOnly), refresh logic na serwerze, zaden JWT w przegladarce.

CORS configuration

Jesli WASM hostowany jest na innej domenie niz API, musisz wlaczyc CORS na serwerze API:

// API Program.cs
builder.Services.AddCors(options =>
{
    options.AddDefaultPolicy(policy =>
    {
        policy.WithOrigins("https://app.example.com")
              .AllowAnyHeader()
              .AllowAnyMethod()
              .AllowCredentials();
    });
});

app.UseCors();

Polly — resilience patterns

Aby aplikacja byla odporna na chwilowe bledy sieci, retry, circuit breaker.

// Polly v8
builder.Services.AddHttpClient("Api")
    .AddResilienceHandler("api-pipeline", builder =>
    {
        builder.AddRetry(new HttpRetryStrategyOptions
        {
            MaxRetryAttempts = 3,
            BackoffType = DelayBackoffType.Exponential,
            UseJitter = true
        });

        builder.AddCircuitBreaker(new HttpCircuitBreakerStrategyOptions
        {
            FailureRatio = 0.5,
            SamplingDuration = TimeSpan.FromSeconds(10),
            MinimumThroughput = 10,
            BreakDuration = TimeSpan.FromSeconds(30)
        });

        builder.AddTimeout(TimeSpan.FromSeconds(10));
    });

Refit — deklaratywne API clients

Zamiast pisac HTTP calls recznie, Refit generuje implementacje z interface.

public interface IProductApi
{
    [Get("/api/products")]
    Task<List<Product>> GetAllAsync();

    [Get("/api/products/{id}")]
    Task<Product> GetByIdAsync(int id);

    [Post("/api/products")]
    Task<Product> CreateAsync([Body] Product product);

    [Delete("/api/products/{id}")]
    Task DeleteAsync(int id);
}

// Program.cs
builder.Services.AddRefitClient<IProductApi>()
    .ConfigureHttpClient(c => c.BaseAddress = new Uri("https://api.example.com/"));

Cancellation tokens

Dla wolnych zapytan z mozliwoscia anulowania (np. uzytkownik zmienil filtr w trakcie ladowania):

private CancellationTokenSource? cts;

private async Task Search(string query)
{
    cts?.Cancel();
    cts = new CancellationTokenSource();

    try
    {
        results = await api.SearchAsync(query, cts.Token);
    }
    catch (OperationCanceledException)
    {
        // ignore
    }
}

File downloads

Browser limity: nie mozna otworzyc duzego pliku w pamieci tylko aby go zapisac. Idealnie streamuj do nazwanego pliku.

// Najprosciej: link bezposredni
<a href="api/files/123/download">Pobierz</a>

// Lub via JS interop
private async Task DownloadFile()
{
    var bytes = await Http.GetByteArrayAsync("api/files/123");
    await JS.InvokeVoidAsync("downloadFile", "raport.pdf", Convert.ToBase64String(bytes));
}

SignalR z WASM

WASM moze byc klientem SignalR — np. dla notyfikacji push z servera.

using Microsoft.AspNetCore.SignalR.Client;

private HubConnection? hubConnection;

protected override async Task OnInitializedAsync()
{
    hubConnection = new HubConnectionBuilder()
        .WithUrl("https://api.example.com/notifications")
        .WithAutomaticReconnect()
        .Build();

    hubConnection.On<Notification>("OnNotification", n =>
    {
        notifications.Add(n);
        InvokeAsync(StateHasChanged);
    });

    await hubConnection.StartAsync();
}

Common gotchas

  • CORS errors — Najczesciej sprawcza brakujacy AllowOrigins
  • Cookies nie sa wysylane — Brakujaca SetBrowserRequestCredentials
  • Slow response — Brak gzip/brotli na API response
  • JSON serialization — Roznice w camelCase vs PascalCase
  • HttpClient not disposed — OK w WASM, ale w .NET native mozna miec problem

Cookies w fetch

// Aby cookies byly wysylane:
request.SetBrowserRequestCredentials(BrowserRequestCredentials.Include);

// Lub globalnie dla HttpClient:
client.DefaultRequestHeaders.Add("Cookie", "..."); // niezalecane
// Lepiej: handler ustawiajacy credentials

Recommended pattern 2026

  1. BFF pattern — httpOnly cookie auth na backend
  2. Refit interface dla API operations
  3. Polly v8 resilience pipeline
  4. Strongly-typed DTO z System.Text.Json
  5. CancellationToken dla wszystkich operacji search/list
  6. SignalR dla real-time push
