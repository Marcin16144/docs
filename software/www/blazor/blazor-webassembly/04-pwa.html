PWA — Progressive Web App

Service workers, offline, manifest.json, install jako app, push notifications

Czym jest PWA?

Progressive Web App to strona WWW, ktora dziala jak natywna aplikacja:

  • Mozna ja zainstalowac (ikona w start menu / dock)
  • Otwarcie bez paska przegladarki (chrome-less)
  • Dziala offline (service worker cache)
  • Push notifications (na desktop i Android)
  • Background sync
  • Dziala w iOS, Android, Windows, macOS, Linux

Blazor WebAssembly pasuje idealnie — jest static-host, dziala offline po pobraniu, ma .NET runtime w przegladarce.

Generowanie projektu z PWA

dotnet new blazorwasm --pwa -o MyPwaApp
cd MyPwaApp
dotnet run

Otrzymujesz dodatkowo:

  • wwwroot/manifest.json — metadata o aplikacji
  • wwwroot/service-worker.js — dev service worker
  • wwwroot/service-worker.published.js — production cache strategy
  • wwwroot/icon-192.png, icon-512.png — ikony aplikacji

Service worker — cache strategy

Plik service-worker.published.js generowany domyslnie:

self.importScripts('./service-worker-assets.js');

self.addEventListener('install', event => event.waitUntil(onInstall(event)));
self.addEventListener('activate', event => event.waitUntil(onActivate(event)));
self.addEventListener('fetch', event => event.respondWith(onFetch(event)));

const cacheNamePrefix = 'offline-cache-';
const cacheName = `${cacheNamePrefix}${self.assetsManifest.version}`;

async function onInstall(event) {
    const assetsRequests = self.assetsManifest.assets
        .filter(asset => /\.(html|js|json|css|wasm|dll|png|svg)$/.test(asset.url))
        .map(asset => new Request(asset.url, { integrity: asset.hash, cache: 'no-cache' }));

    await caches.open(cacheName).then(cache => cache.addAll(assetsRequests));
}

async function onActivate(event) {
    const cacheKeys = await caches.keys();
    await Promise.all(cacheKeys
        .filter(key => key.startsWith(cacheNamePrefix) && key !== cacheName)
        .map(key => caches.delete(key)));
}

async function onFetch(event) {
    let cachedResponse = null;
    if (event.request.method === 'GET') {
        const shouldServeIndex = event.request.mode === 'navigate';
        const request = shouldServeIndex ? 'index.html' : event.request;
        const cache = await caches.open(cacheName);
        cachedResponse = await cache.match(request);
    }
    return cachedResponse || fetch(event.request);
}

Strategie cache

Cache First (default Blazor PWA)

Najpierw szukaj w cache — dopiero przy braku idz po sieci. Idealne dla aplikacji bardziej offline-first.

Network First

Najpierw spytaj sieci, potem cache jako fallback. Idealne dla aplikacji wymagajacej zawsze swiezych danych.

async function onFetch(event) {
    try {
        const response = await fetch(event.request);
        const cache = await caches.open(cacheName);
        cache.put(event.request, response.clone());
        return response;
    } catch {
        return caches.match(event.request);
    }
}

Stale While Revalidate

Zwroc z cache, w tle pobierz aktualna wersje na nastepnym ladowanie.

Instalacja jako natywna aplikacja

Po spelnieniu kryteriow PWA przegladarka pokazuje install prompt (Chrome / Edge: ikona w pasku adresu). Mozesz tez programowo pokazac install button:

// js/pwa-install.js
let deferredPrompt = null;

window.addEventListener('beforeinstallprompt', e => {
    e.preventDefault();
    deferredPrompt = e;
    DotNet.invokeMethodAsync('MyApp', 'OnPwaInstallable');
});

window.installPwa = async () => {
    if (!deferredPrompt) return false;
    deferredPrompt.prompt();
    const choice = await deferredPrompt.userChoice;
    deferredPrompt = null;
    return choice.outcome === 'accepted';
};
@inject IJSRuntime JS

<button @onclick="Install" disabled="@(!isInstallable)">
    Zainstaluj aplikacje
</button>

@code {
    private bool isInstallable;

    [JSInvokable]
    public static void OnPwaInstallable()
    {
        // ustaw flag aby pokazac przycisk
    }

    private async Task Install()
    {
        await JS.InvokeAsync<bool>("installPwa");
    }
}

Push notifications

Wspolczesnie wspierane na: Chrome, Edge, Firefox (desktop + Android), Safari (iOS 16.4+).

Subscribe

// js
window.subscribeToPush = async (publicKey) => {
    const reg = await navigator.serviceWorker.ready;
    const sub = await reg.pushManager.subscribe({
        userVisibleOnly: true,
        applicationServerKey: urlBase64ToUint8Array(publicKey)
    });
    return JSON.stringify(sub);
};

Service worker handler

self.addEventListener('push', event => {
    const data = event.data?.json();
    event.waitUntil(self.registration.showNotification(data.title, {
        body: data.body,
        icon: '/icon-192.png',
        badge: '/badge.png',
        data: { url: data.url }
    }));
});

self.addEventListener('notificationclick', event => {
    event.notification.close();
    event.waitUntil(clients.openWindow(event.notification.data.url));
});

Background sync

Pozwala synchronizowac dane gdy uzytkownik wraca online.

// js
async function queueRequest(data) {
    const reg = await navigator.serviceWorker.ready;
    await reg.sync.register('upload-pending');
    // zapisz dane w IndexedDB
}

// service-worker.js
self.addEventListener('sync', event => {
    if (event.tag === 'upload-pending') {
        event.waitUntil(syncPendingData());
    }
});

Update strategy

Gdy publikujesz nowa wersje, service worker musi sie odswiezyc. Standardowy flow:

  1. Nowy SW pobiera sie w tle
  2. Stary SW dziala dalej (uzytkownik nie widzi zmian)
  3. Po zamknieciu wszystkich zakladek -> nowy SW aktywny
  4. Mozesz wymusic skipWaiting() aby od razu uzyc nowej wersji
self.addEventListener('install', event => {
    self.skipWaiting();
    event.waitUntil(/*...*/);
});

self.addEventListener('activate', event => {
    event.waitUntil(self.clients.claim());
});

Pokaz "Update available" bar

// js
navigator.serviceWorker.addEventListener('controllerchange', () => {
    DotNet.invokeMethodAsync('MyApp', 'OnNewVersionAvailable');
});

iOS limitations

Apple bardziej restrykcyjnie podchodzi do PWA:

  • Push notifications wspierane od iOS 16.4 (marzec 2023)
  • Brak background sync
  • Cache size limity (max ~50 MB)
  • SW timeoutuje po 30 sekundach inactivity
  • WebP nie jest preferowany — uzywaj JPEG/PNG dla ikon

Lighthouse audit

Sprawdz w Chrome DevTools -> Lighthouse -> PWA. Dobry score wymaga:

  • HTTPS only
  • Service worker zarejestrowany
  • manifest.json z 192x192 i 512x512 ikonami
  • Theme color w <meta> i manifest
  • Viewport meta
  • Apple-touch-icon (dla iOS)
