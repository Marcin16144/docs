Publikowanie projektu

# Standardowy publish
dotnet publish -c Release -o ./publish

# Self-contained (zawiera runtime, ~70 MB)
dotnet publish -c Release -r win-x64 --self-contained true

# Single-file
dotnet publish -c Release -r linux-x64 -p:PublishSingleFile=true --self-contained true

# Trimmed (mniejsze pliki, eksperymentalne)
dotnet publish -c Release -p:PublishTrimmed=true

IIS hosting (Windows)

IIS wymaga ASP.NET Core Hosting Bundle dla danej wersji .NET. Po jego instalacji konfigurujesz application pool i site.

Web.config (auto-generowany)

<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <location path="." inheritInChildApplications="false">
    <system.webServer>
      <handlers>
        <add name="aspNetCore" path="*" verb="*"
             modules="AspNetCoreModuleV2" resourceType="Unspecified" />
      </handlers>
      <aspNetCore processPath=".\MyApp.exe"
                  arguments=""
                  stdoutLogEnabled="false"
                  hostingModel="inprocess" />
    </system.webServer>
  </location>
</configuration>

WebSocket dla Blazor Server

IIS musi miec wlaczona role WebSocket Protocol. W IIS Manager: Server Roles -> Web Server -> Application Development -> WebSocket Protocol.

Azure App Service

Najprostszy hosting dla Blazor Server.

# Azure CLI
az webapp up --runtime "DOTNETCORE:9.0" --sku B1 --name my-blazor-app

# Lub z Visual Studio: Publish -> Azure App Service

Konfiguracja WebSocket

az webapp config set --name my-blazor-app --web-sockets-enabled true
az webapp config set --name my-blazor-app --always-on true

Azure Static Web Apps (Blazor WASM)

Idealne dla Blazor WASM — darmowy plan, integracja z GitHub Actions.

# .github/workflows/azure-swa.yml
- uses: Azure/static-web-apps-deploy@v1
  with:
    azure_static_web_apps_api_token: ${{ secrets.AZURE_STATIC_WEB_APPS_API_TOKEN }}
    repo_token: ${{ secrets.GITHUB_TOKEN }}
    action: "upload"
    app_location: "/MyBlazorWasm"
    output_location: "wwwroot"

Docker (multi-stage)

Blazor Server / United Dockerfile

FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
WORKDIR /src
COPY . .
RUN dotnet restore
RUN dotnet publish MyApp.csproj -c Release -o /app/publish

FROM mcr.microsoft.com/dotnet/aspnet:9.0 AS runtime
WORKDIR /app
COPY --from=build /app/publish .
EXPOSE 8080
ENTRYPOINT ["dotnet", "MyApp.dll"]
docker build -t my-blazor-app .
docker run -p 8080:8080 my-blazor-app

Blazor WASM Dockerfile (z nginx)

FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish MyWasmApp.csproj -c Release -o /app

FROM nginx:alpine
COPY --from=build /app/wwwroot /usr/share/nginx/html
COPY nginx.conf /etc/nginx/nginx.conf
EXPOSE 80

Sticky sessions dla Blazor Server

Blazor Server wymaga sticky sessions — uzytkownik musi trafiac na ten sam pod. W K8s ustaw:

apiVersion: v1
kind: Service
metadata:
  name: my-app
  annotations:
    service.beta.kubernetes.io/aws-load-balancer-type: nlb
spec:
  sessionAffinity: ClientIP
  sessionAffinityConfig:
    clientIP:
      timeoutSeconds: 10800

AOT compilation

Ahead-Of-Time compilation generuje natywny kod — szybszy start, lepszy throughput, mniejszy obraz Docker. Dla Blazor WASM wlasciwie wymagany w produkcji (5x mniejszy bundle).

<PropertyGroup>
  <RunAOTCompilation>true</RunAOTCompilation>
  <PublishTrimmed>true</PublishTrimmed>
</PropertyGroup>

AOT dla Blazor Server (.NET 9+)

<PropertyGroup>
  <PublishAot>true</PublishAot>
  <StripSymbols>true</StripSymbols>
</PropertyGroup>

Wymaga zgodnych zaleznosci. Niektore biblioteki (np. EF Core z lazy proxies) nie wspieraja AOT — zweryfikuj.

Prerendering (Blazor United)

W .NET 8/9 Blazor United domyslnie renderuje strony serwerowo (HTML), a interaktywnosc dochodzi po hydracji. To poprawia LCP i SEO.

// Komponent decyduje:
<Counter @rendermode="@(new InteractiveServerRenderMode(prerender: true))" />

Compression i caching

Dla Blazor WASM bardzo wazna jest kompresja Brotli/Gzip oraz dluzsze cache headers.

# nginx
location ~* \.(dll|wasm|js|css)$ {
    expires 365d;
    add_header Cache-Control "public, immutable";
    gzip on;
    gzip_types application/wasm application/dll;
}
# Azure Static Web Apps staticwebapp.config.json
{
  "globalHeaders": {
    "Cache-Control": "public, max-age=31536000, immutable"
  }
}

    .AddDbContextCheck<AppDbContext>()
    .AddRedis(redisConnectionString);

Checklist deployment

  • HTTPS only (HSTS)
  • Compression (Brotli/Gzip)
  • Health checks endpoint
  • Structured logging
  • Backup database przed migracja
  • Blue-green / canary deployment
  • Sekrety w KeyVault / parameter store, nie w appsettings
  • Rate limiting na public endpointach
  • CSP header
  • WebSocket support potwierdzony (dla Blazor Server)
