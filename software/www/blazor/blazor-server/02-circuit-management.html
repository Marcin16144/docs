Circuit management

Czym jest circuit, lifecycle, disconnection, reconnection UI, max circuits, memory

Czym jest circuit?

Circuit to logiczne polaczenie miedzy uzytkownikiem a serwerem w Blazor Server. Reprezentuje "zywe" sesje:

  • Stan wszystkich komponentow uzytkownika
  • Render tree (struktura UI)
  • Scoped services przypiete do tego uzytkownika
  • SignalR hub connection

Kazdy uzytkownik = jeden circuit. Nawet jesli ten sam czlowiek ma 2 zakladki, dostaje 2 osobne circuits.

Lifecycle circuita

FazaCo sie dzieje
1. ConnectionKlient laczy WebSocket, hub tworzy circuit
2. ActiveKomponenty zyja, eventy sa obslugiwane
3. DisconnectWebSocket zerwany (network drop, tab closed)
4. Hold (3 minuty default)Circuit czeka na reconnection, stan zachowany w pamieci
5. Reconnect (jesli udane)Klient wraca, stan przywracany
6. CleanupPo timeoucie circuit jest usuwany, GC zbiera obiekty

CircuitHandler — reagowanie na zdarzenia

Mozesz pisac handler reagujacy na lifecycle:

public class TrackingCircuitHandler : CircuitHandler
{
    private readonly ILogger<TrackingCircuitHandler> logger;

    public TrackingCircuitHandler(ILogger<TrackingCircuitHandler> logger)
    {
        this.logger = logger;
    }

    public override Task OnCircuitOpenedAsync(Circuit circuit, CancellationToken ct)
    {
        logger.LogInformation("Circuit opened: {Id}", circuit.Id);
        return Task.CompletedTask;
    }

    public override Task OnConnectionUpAsync(Circuit circuit, CancellationToken ct)
    {
        logger.LogInformation("Connection up: {Id}", circuit.Id);
        return Task.CompletedTask;
    }

    public override Task OnConnectionDownAsync(Circuit circuit, CancellationToken ct)
    {
        logger.LogInformation("Connection down: {Id}", circuit.Id);
        return Task.CompletedTask;
    }

    public override Task OnCircuitClosedAsync(Circuit circuit, CancellationToken ct)
    {
        logger.LogInformation("Circuit closed: {Id}", circuit.Id);
        return Task.CompletedTask;
    }
}

// Program.cs
builder.Services.AddScoped<CircuitHandler, TrackingCircuitHandler>();

Max circuits limit

Domyslnie kazdy serwer trzyma max 100 disconnected circuits. Po przekroczeniu najstarsze sa usuwane.

builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents()
    .AddCircuitOptions(options =>
    {
        options.DisconnectedCircuitMaxRetained = 100;
        options.DisconnectedCircuitRetentionPeriod = TimeSpan.FromMinutes(3);
        options.JSInteropDefaultCallTimeout = TimeSpan.FromMinutes(1);
        options.MaxBufferedUnacknowledgedRenderBatches = 10;
        options.DetailedErrors = false; // false in production!
    });

Memory per user

Typowa aplikacja Blazor Server uzywa:

ComponentMemory
SignalR connection~50 KB
Render tree~200 KB - 1 MB
Component stateZalezne od appki, ~100 KB - 5 MB
Scoped services (DbContext, etc)~100 KB - 1 MB
Cascading values~tens of KB

Lacznie: 1-5 MB per uzytkownik. Serwer z 4 GB RAM utrzyma ~1000-2000 aktywnych circuits.

Tipy zmniejszania memory footprint

  • Nie trzymaj duzych kolekcji w stanie komponentu — uzywaj paginacji
  • Dispose IDisposable services / subscriptions
  • Uzywaj OwningComponentBase dla DbContext (oddzielny scope)
  • Nie trzymaj surowych obrazow / plikow w stanie

Detekcja disconnected circuits

public class CircuitTracker : CircuitHandler
{
    private static readonly Dictionary<string, CircuitInfo> circuits = new();

    public override Task OnCircuitOpenedAsync(Circuit circuit, CancellationToken ct)
    {
        circuits[circuit.Id] = new CircuitInfo {
            Id = circuit.Id,
            OpenedAt = DateTime.UtcNow,
            IsConnected = true
        };
        return Task.CompletedTask;
    }

    public override Task OnConnectionDownAsync(Circuit circuit, CancellationToken ct)
    {
        if (circuits.TryGetValue(circuit.Id, out var info))
            info.IsConnected = false;
        return Task.CompletedTask;
    }

    public static int ActiveCount => circuits.Count(c => c.Value.IsConnected);
    public static int TotalCount => circuits.Count;
}

Authentication revalidation

Czesta potrzeba: re-walidacja tokenu/uprawnien co kilka minut na zywym circuicie.

public class IdentityRevalidatingAuthStateProvider
    : RevalidatingServerAuthenticationStateProvider
{
    public IdentityRevalidatingAuthStateProvider(...) : base(...) { }

    protected override TimeSpan RevalidationInterval => TimeSpan.FromMinutes(30);

    protected override async Task<bool> ValidateAuthenticationStateAsync(
        AuthenticationState authState, CancellationToken ct)
    {
        // sprawdz czy uzytkownik wciaz aktywny w bazie
        var user = await userManager.FindByNameAsync(authState.User.Identity!.Name!);
        return user != null && !user.IsLockedOut;
    }
}
