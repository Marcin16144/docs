Podstawy Blazor Server

Architektura SignalR, server-side rendering, plusy, minusy, dotnet new blazorserver

Architektura

Blazor Server to model, w ktorym logika komponentow zyje na serwerze. Klient utrzymuje stale polaczenie SignalR (najczesciej WebSocket), przez ktore przekazywane sa zdarzenia UI (klikniecia, focus, input) i odbierane sa diffy DOM do zastosowania.

Browser (klient)         SignalR connection         Server
  +------+                  +-------+                +---------+
  | DOM  | <-- DOM diff --- | hub   | <-- render --- | C# code |
  | UI   | --- event ---->  | /hub  | --- handle -->| state   |
  +------+                  +-------+                +---------+

Co to oznacza w praktyce

  • Cala logika i stan komponentow zyja na serwerze
  • Przegladarka pobiera tylko maly bootstrap (~250 KB) + cienkie wrapper JS
  • Kazdy klikniecie / input idzie przez WebSocket na serwer
  • Odpowiedz to diff drzewa renderowanego, nie pelny HTML
  • Stan jest "zywy" w pamieci servera per uzytkownik (circuit)

Plusy

  • Bardzo maly bundle — brak runtime .NET w przegladarce
  • Szybki startup — pierwsze ladowanie ~100-300ms
  • Pelny dostep do .NET — bezposrednio uzywasz EF Core, plikow, itp.
  • Zaden kod do klienta — bezpieczenstwo logiki biznesowej
  • Real-time UI — latwo aktualizowac zmiana z innego watku
  • Dobre dla aplikacji intranetowych z dobra siecia

Minusy

  • Latency — kazda interakcja round trip (50-200ms)
  • Persistent connection — klient musi miec WebSocket otwarty przez caly czas
  • Skalowanie — kazdy uzytkownik to ~1-5 MB pamieci na serwerze
  • Sticky sessions — load balancer musi trzymac uzytkownika na tym samym serwerze
  • Reconnection UX — przy disconnect uzytkownik widzi "Trying to reconnect..."
  • Nie dziala offline
  • Slabsze dla mobile (slabe sieci, polaczenia z latency)

Tworzenie projektu

# .NET 9 - aktualny szablon
dotnet new blazor -o MyApp --interactivity Server

# Stary szablon (.NET 7)
dotnet new blazorserver -o MyApp

cd MyApp
dotnet run

Program.cs

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents();

builder.Services.AddScoped<WeatherService>();

var app = builder.Build();

if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseAntiforgery();

app.MapRazorComponents<App>()
    .AddInteractiveServerRenderMode();

app.Run();

WebSocket connection requirement

Blazor Server wymaga WebSocket lub Server-Sent Events. Long-polling dziala jako fallback ale jest wolny.

  • IIS — trzeba wlaczyc rolu "WebSocket Protocol"
  • Nginx — proxy_set_header Upgrade $http_upgrade
  • Azure App Service — az webapp config set --web-sockets-enabled true
  • Reverse proxy musi przepuszczac WebSockets

SignalR config

builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents()
    .AddHubOptions(options =>
    {
        options.MaximumReceiveMessageSize = 1024 * 1024; // 1 MB
        options.KeepAliveInterval = TimeSpan.FromSeconds(15);
        options.ClientTimeoutInterval = TimeSpan.FromSeconds(30);
    });

Memory per user

Kazdy aktywny uzytkownik to circuit (logical connection). Trzyma:

  • Stan komponentow (~tysiace obiektow)
  • Render tree
  • Cascading values
  • Scoped services

Typowa aplikacja: 1-5 MB per user. Serwer 4 GB RAM = ~1000-2000 aktywnych uzytkownikow. Skalowanie wymaga sharding lub Azure SignalR Service.

Kiedy wybrac Blazor Server?

  • Aplikacje wewnetrzne, intranet, dobre lacze
  • Admin paneli, dashboardy biznesowe
  • Wymagana ochrona logiki biznesowej (kod nie idzie do klienta)
  • Latwa integracja z bazaa danych, plikami serwerowymi
  • Real-time aktualizacje (notyfikacje, czat, dashboard live)
  • Mniej niz ~5000 jednoczesnie aktywnych uzytkownikow

Kiedy NIE wybrac Blazor Server?

  • Public site z slabymi laczami (mobile, 3G)
  • Aplikacja musi dzialac offline
  • Setki tysiecy uzytkownikow jednoczesnie (drogi infrastructure)
  • Globalna dystrybucja — latency intercontinental

Werdykt

Blazor Server to perfekcyjny wybor dla aplikacji biznesowych zorientowanych na serwer (B2B, intranet, panele admin), gdy mozesz zalozyc dobre lacze. Dla aplikacji publicznych mobile-first lepiej wybrac Blazor WebAssembly lub Blazor United z auto mode.
