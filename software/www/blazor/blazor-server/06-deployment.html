Deployment Blazor Server

IIS, Kestrel + Nginx, Azure App Service, Docker, sticky sessions, WebSocket

Wymagania

Blazor Server wymaga zywego serwera, ktory:

  • Hostuje runtime .NET (in-process w IIS lub samodzielnie Kestrel)
  • Obsluguje WebSocket (lub fallback long-polling, ale wolny)
  • Pozwala na sticky sessions jesli skalujesz horyzontalnie
  • Trzyma stabilne polaczenia (timeout LB > 1 minuta)

IIS hosting (Windows Server)

Wymagania

  • Windows Server 2019+
  • IIS 10+ z rola "WebSocket Protocol"
  • ASP.NET Core Hosting Bundle dla danej wersji .NET

Kestrel + Nginx (Linux)

Setup Linux

# Ubuntu 22.04+
wget https://packages.microsoft.com/config/ubuntu/22.04/packages-microsoft-prod.deb
sudo dpkg -i packages-microsoft-prod.deb
sudo apt update
sudo apt install -y aspnetcore-runtime-9.0

systemd service

# /etc/systemd/system/myapp.service
[Unit]
Description=My Blazor App
After=network.target

[Service]
WorkingDirectory=/var/www/myapp
ExecStart=/usr/bin/dotnet /var/www/myapp/MyApp.dll
Restart=always
User=www-data
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=ASPNETCORE_URLS=http://localhost:5000

[Install]
WantedBy=multi-user.target
sudo systemctl enable myapp
sudo systemctl start myapp
sudo systemctl status myapp

Nginx reverse proxy

# /etc/nginx/sites-available/myapp
server {
    listen 443 ssl http2;
    server_name app.example.com;

    ssl_certificate /etc/letsencrypt/live/app.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

    location / {
        proxy_pass http://localhost:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Timeouts dla SignalR
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_connect_timeout 75s;

        proxy_cache_bypass $http_upgrade;
    }
}

map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}

Docker multi-stage

FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
WORKDIR /src
COPY ["MyApp/MyApp.csproj", "MyApp/"]
RUN dotnet restore "MyApp/MyApp.csproj"
COPY . .
WORKDIR "/src/MyApp"
RUN dotnet publish "MyApp.csproj" -c Release -o /app/publish

FROM mcr.microsoft.com/dotnet/aspnet:9.0 AS runtime
WORKDIR /app
COPY --from=build /app/publish .
EXPOSE 8080
ENV ASPNETCORE_URLS=http://+:8080
ENTRYPOINT ["dotnet", "MyApp.dll"]
docker build -t my-blazor-app .
docker run -d -p 8080:8080 \
  -e ASPNETCORE_ENVIRONMENT=Production \
  --name myapp \
  my-blazor-app

Kubernetes z sticky sessions

apiVersion: v1
kind: Service
metadata:
  name: blazor-app
spec:
  type: ClusterIP
  sessionAffinity: ClientIP
  sessionAffinityConfig:
    clientIP:
      timeoutSeconds: 10800
  selector:
    app: blazor-app
  ports:
    - port: 80
      targetPort: 8080

---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: blazor-app
  annotations:
    nginx.ingress.kubernetes.io/affinity: "cookie"
    nginx.ingress.kubernetes.io/session-cookie-name: "BLAZOR_AFFINITY"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "300"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "300"
spec:
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: blazor-app
                port:
                  number: 80

    .AddDbContextCheck<AppDbContext>()

Pre-deployment checklist

  • HTTPS dziala (cert valid, not expired)
  • WebSocket przepuszczany przez LB / firewall
  • Sticky sessions wlaczone
  • Sekrety w Key Vault, NIE w appsettings.json
  • Health endpoints zwracaja 200
  • Logging strukturalny dziala (sprawdz w Seq/AppInsights)
  • Backup database przed migracja
  • Smoke testy po deploy
  • Rollback plan
  • Monitoring uruchomione (memory, CPU, latency, errors)

CI/CD pipeline (GitHub Actions)

name: Deploy Blazor

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '9.0'
      - run: dotnet restore
      - run: dotnet build -c Release --no-restore
      - run: dotnet test --no-build
      - run: dotnet publish -c Release -o ./publish
      - uses: azure/webapps-deploy@v3
        with:
          app-name: my-blazor-app
          publish-profile: ${{ secrets.AZURE_PUBLISH_PROFILE }}
          package: ./publish

Najczestsze pulapki

  • WebSocket nie dziala (HTTP 400 Bad Request) — LB nie ma upgrade headers
  • Blazor Server na klastrze BEZ sticky sessions — reconnect issues, "circuit not found"
  • Long polling fallback uzywany — wolne, debug w devtools
  • Reconnect timeout zbyt krotki — uzytkownicy traca prace przy slabej sieci
  • Brak HSTS — man-in-the-middle podsluchuje SignalR
