Bezpieczenstwo Blazor Server

HTTPS, anti-forgery, CSP, rate limiting, DoS protection, sekrety

HTTPS only — podstawa

Blazor Server uzywa WebSocket (lub long-polling fallback). Bez HTTPS, dane w SignalR ida w czystej formie — przejmujesz cale UI uzytkownika.

// Program.cs
app.UseHttpsRedirection();
app.UseHsts(); // Strict-Transport-Security header

// HSTS option
builder.Services.AddHsts(options =>
{
    options.Preload = true;
    options.IncludeSubDomains = true;
    options.MaxAge = TimeSpan.FromDays(365);
});

Anti-forgery tokens

Blazor Server domyslnie zabezpieczone CSRF dla form posts. Wystarczy app.UseAntiforgery().

// Program.cs
app.UseAntiforgery();

// EditForm automatycznie dodaje token
<EditForm Model="@model" method="post" OnValidSubmit="Submit">
    ...
</EditForm>

Manualnie dla custom form

@inject AntiforgeryStateProvider Anti

<form method="post">
    <AntiforgeryToken />
    <input name="email" />
    <button>Wyslij</button>
</form>

Content Security Policy (CSP)

CSP chroni przed XSS — ogranicza skad mozna ladowac zasoby (skrypty, style, fonty).

app.Use(async (context, next) =>
{
    context.Response.Headers["Content-Security-Policy"] =
        "default-src 'self'; " +
        "script-src 'self' 'wasm-unsafe-eval'; " +
        "style-src 'self' 'unsafe-inline'; " +
        "connect-src 'self' wss:; " +
        "frame-ancestors 'none'; " +
        "form-action 'self'";
    await next();
});

Blazor Server wymaga niestety 'unsafe-inline' dla CSS i niektorych scripts — przyszle wersje pracuja nad tym.

Inne security headers

context.Response.Headers["X-Frame-Options"] = "DENY";
context.Response.Headers["X-Content-Type-Options"] = "nosniff";
context.Response.Headers["Referrer-Policy"] = "strict-origin-when-cross-origin";
context.Response.Headers["Permissions-Policy"] = "geolocation=(), camera=()";

Cookies

builder.Services.ConfigureApplicationCookie(opts =>
{
    opts.Cookie.HttpOnly = true;        // Brak JS access
    opts.Cookie.SecurePolicy = CookieSecurePolicy.Always;
    opts.Cookie.SameSite = SameSiteMode.Strict;
    opts.ExpireTimeSpan = TimeSpan.FromHours(8);
    opts.SlidingExpiration = true;
});

Rate limiting

Od .NET 7 wbudowany middleware rate-limiting.

builder.Services.AddRateLimiter(opts =>
{
    opts.AddPolicy("api", context =>
        RateLimitPartition.GetTokenBucketLimiter(
            partitionKey: context.Connection.RemoteIpAddress?.ToString() ?? "anonymous",
            factory: _ => new TokenBucketRateLimiterOptions
            {
                TokenLimit = 100,
                ReplenishmentPeriod = TimeSpan.FromMinutes(1),
                TokensPerPeriod = 100,
                AutoReplenishment = true
            }));

    opts.AddPolicy("login", context =>
        RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: context.Connection.RemoteIpAddress?.ToString() ?? "anonymous",
            factory: _ => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 5,
                Window = TimeSpan.FromMinutes(1)
            }));

    opts.RejectionStatusCode = 429;
});

app.UseRateLimiter();
app.MapPost("/login", LoginHandler).RequireRateLimiting("login");

DoS protection — circuit limit

Atakujacy moze otwierac wiele circuits aby zalac pamiec serwera. Dlatego ogranicz max disconnected circuits:

builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents()
    .AddCircuitOptions(opts =>
    {
        opts.DisconnectedCircuitMaxRetained = 100;
        opts.DisconnectedCircuitRetentionPeriod = TimeSpan.FromMinutes(3);
        opts.MaxBufferedUnacknowledgedRenderBatches = 10;
    });

SignalR limit message size

builder.Services.AddRazorComponents()
    .AddHubOptions(opts =>
    {
        opts.MaximumReceiveMessageSize = 32 * 1024; // 32 KB max
    });

Walidacja po stronie serwera

Klient moze wyslac dowolne wartosci. Zawsze waliduj na serwerze:

private async Task SubmitOrder(Order order)
{
    if (order.Quantity <= 0 || order.Quantity > 1000)
        throw new ArgumentException("Invalid quantity");

    if (!await IsUserAllowed(currentUser, order.ProductId))
        throw new UnauthorizedAccessException();

    await orderService.SubmitAsync(order);
}

Authorization

Per komponent

@page "/admin"
@attribute [Authorize(Roles = "Admin")]

Per akcja

private async Task DeleteUser(int userId)
{
    var authState = await AuthState.GetAuthenticationStateAsync();
    if (!authState.User.IsInRole("Admin"))
        return;

    await userService.DeleteAsync(userId);
}

Resource-based authorization

@inject IAuthorizationService Auth

private async Task EditDocument(Document doc)
{
    var result = await Auth.AuthorizeAsync(User, doc, "EditDocumentPolicy");
    if (!result.Succeeded) return;

    // edit
}

Logout i session expiration

@inject SignInManager<AppUser> SignIn
@inject NavigationManager Nav

private async Task Logout()
{
    await SignIn.SignOutAsync();
    Nav.NavigateTo("/", forceLoad: true);
}

Idle timeout zalecany ~30 minut dla biznesowych aplikacji, krotszy dla bankowych.

Sekrety — gdzie nie trzymac

  • NIE w kodzie zrodlowym
  • NIE w appsettings.json commitowanych do gita
  • NIE w environment variables na local dev (uzywaj user-secrets)

Dev: User Secrets

dotnet user-secrets init
dotnet user-secrets set "Db:ConnectionString" "Server=...;Password=..."

Prod: Azure Key Vault / AWS Secrets Manager

builder.Configuration.AddAzureKeyVault(
    new Uri($"https://{vaultName}.vault.azure.net/"),
    new DefaultAzureCredential());

Logging i audyt

// Loguj wazne akcje
public async Task DeleteUser(int userId)
{
    logger.LogWarning("User {Admin} deleted user {UserId}",
        currentUser.UserName, userId);

    await userService.DeleteAsync(userId);
}

Najlepsze praktyki:

  • Strukturalne logowanie (Serilog + JSON sink)
  • Persistowane logi (Seq, Loki, Datadog)
  • Audit log dla logowania, zmian uprawnien, dostepu do sensitive data
  • Nie loguj PII (haslo, PESEL, krew)

Security checklist

  • HTTPS only + HSTS
  • CSP + security headers
  • Anti-forgery tokens
  • Rate limiting (login, API endpoints)
  • Sekrety w Key Vault, NIGDY w repo
  • Server-side validation kazdego inputu
  • [Authorize] na chronionych komponentach
  • Audit log akcji wrazliwych
  • Aktualizacja .NET runtime do najnowszej patch version
  • Dependency scan (Snyk, GitHub Dependabot)
