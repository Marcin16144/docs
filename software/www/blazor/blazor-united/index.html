Blazor United (.NET 8/9)

Mix render modes per komponent — SSR + Server + WASM w jednej aplikacji

Co to jest Blazor United?

Blazor United to nazwa potoczna nowej zunifikowanej architektury Blazor wprowadzonej w .NET 8 (2023) i rozszerzonej w .NET 9 (2024). Pozwala mieszac modele renderowania w obrebie jednej aplikacji per komponent. To rewolucja — wczesniej musiales wybrac Server albo WASM, teraz mozesz mixowac.

4 render modes

ModeCo toKiedy
Static SSRHTML wygenerowany na serwerze, brak interaktywnosciStrony glowne, blog, marketing, SEO-critical
InteractiveServerSignalR connection, kazda interakcja round-tripForms, panele admin, real-time UIs
InteractiveWebAssemblyC# w przegladarce via WASM, autonomicznyHeavy interactive UIs, offline support
InteractiveAutoServer na pierwszy load, potem WASM po pobraniuBest of both: szybki LCP + autonomy

Default w .NET 9

Gdy uruchamiasz dotnet new blazor w .NET 9, dostajesz aplikacje Blazor United — wszystkie 4 modele dostepne, mozesz wybrac per komponent. To zastapilo dotychczasowe szablony blazorserver i blazorwasm.

Podstawowy setup

dotnet new blazor -o MyApp -ai
# -ai = include WebAssembly + Server interactive components

cd MyApp
dotnet run

Program.cs

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents()
    .AddInteractiveWebAssemblyComponents();

var app = builder.Build();

app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseAntiforgery();

app.MapRazorComponents<App>()
    .AddInteractiveServerRenderMode()
    .AddInteractiveWebAssemblyRenderMode()
    .AddAdditionalAssemblies(typeof(MyApp.Client._Imports).Assembly);

app.Run();

Wybor render mode per komponent

Globalnie dla aplikacji

<!-- App.razor -->
<Routes @rendermode="@InteractiveServer" />

Per komponent

<!-- Konkretny komponent renderowany na serwerze -->
<Counter @rendermode="@InteractiveServer" />

<!-- WebAssembly -->
<Editor @rendermode="@InteractiveWebAssembly" />

<!-- Auto: Server + later WASM -->
<Map @rendermode="@InteractiveAuto" />

W komponencie (top of file)

@page "/dashboard"
@rendermode InteractiveServer

<h1>Dashboard</h1>

Static SSR — podstawa

Domyslnie strona jest renderowana statycznie — HTML idzie do klienta, JS nie jest pobierany dla interaktywnosci. To bardzo szybkie (jak Razor Pages), ale komponenty sa "martwe" — @onclick nic nie robi.

@page "/blog"

<h1>Blog</h1>
@foreach (var post in posts)
{
    <article>
        <h2>@post.Title</h2>
        <p>@post.Excerpt</p>
    </article>
}

@code {
    private List<Post> posts = new();

    protected override async Task OnInitializedAsync()
    {
        posts = await PostService.GetAllAsync();
    }
}

Mixowanie w jednej stronie

Mozna miec strone glowna SSR z wyspami interaktywnosci.

@page "/"

<h1>Sklep</h1>

<!-- Statyczny katalog produktow -->
<ProductCatalog Products="@products" />

<!-- Interaktywny koszyk (Server) -->
<CartWidget @rendermode="@InteractiveServer" />

<!-- Interaktywne live-search (WASM) -->
<SearchBox @rendermode="@InteractiveWebAssembly" />

Forms w SSR

W static SSR dziala enhanced form — submit POST przez fetch i podmiana wynikowego HTML bez full reload.

<EditForm Model="@model" method="post" OnValidSubmit="HandleSubmit" FormName="contactForm">
    <DataAnnotationsValidator />
    <InputText @bind-Value="model.Email" />
    <button type="submit">Wyslij</button>
</EditForm>

@code {
    [SupplyParameterFromForm]
    public ContactModel Model { get; set; } = new();

    private async Task HandleSubmit() { /* ... */ }
}

Streaming rendering

Mozesz oznaczyc strone jako @attribute [StreamRendering] — HTML pojdzie kawalkami, "Loading..." zastapione faktyczna trescia gdy bedzie gotowa. Dziala bez WASM.

@page "/heavy-data"
@attribute [StreamRendering]

<h1>Raport</h1>
@if (data == null)
{
    <p>Ladowanie danych...</p>
}
else
{
    <DataTable Data="@data" />
}

@code {
    private List<Record>? data;

    protected override async Task OnInitializedAsync()
    {
        await Task.Delay(2000); // long query
        data = await Reports.GenerateAsync();
    }
}

Persistent state z prerendering

Czesty problem: prerender ladowal dane, potem WASM ladowal je ponownie. Rozwiazanie: PersistentComponentState.

@inject PersistentComponentState ApplicationState

@code {
    private List<Product>? products;

    protected override async Task OnInitializedAsync()
    {
        if (!ApplicationState.TryTakeFromJson<List<Product>>("products", out products))
            products = await Api.GetAllAsync();

        ApplicationState.RegisterOnPersisting(() =>
        {
            ApplicationState.PersistAsJson("products", products);
            return Task.CompletedTask;
        });
    }
}

InteractiveAuto — szczegolnie ciekawy

Pierwsze odwiedziny: komponent renderuje sie przez Server (szybko, brak czekania na WASM bundle). W tle pobierane sa pliki WASM. Kolejne odwiedziny: komponent dziala w WASM, brak round-tripow.

<Counter @rendermode="@InteractiveAuto" />

Werdykt

W .NET 9 Blazor United jest defaultem. Nie wybierajesz juz "czysty Server" lub "czysty WASM" — wybierajesz per komponent. To radykalnie podnioslo elastycznosc Blazor i pozwala na hybrydowe architektury bez kompromisow.
