Podstawy Blazor

Razor syntax, komponenty, parametry, eventy, two-way binding, lifecycle

Czym jest Blazor?

Blazor to framework od Microsoftu, ktory pozwala tworzyc interaktywne aplikacje webowe w C# zamiast w JavaScript. Komponenty pisze sie w plikach .razor — mieszanka HTML, C# i Razor syntax.

W .NET 9 (2024) i wkrotce .NET 10 Blazor zunifikowalo modele renderowania — mozna mieszac SSR, Server (SignalR) i WebAssembly w jednej aplikacji per komponent.

Razor syntax

Razor to silnik szablonow z prefixem @ oznaczajacym C#.

@page "/dashboard"

<h1>Witaj, @userName!</h1>

@if (isLoggedIn)
{
    <p>Masz @messageCount nowych wiadomosci.</p>
}
else
{
    <p>Zaloguj sie aby zobaczyc skrzynke.</p>
}

<ul>
@foreach (var item in items)
{
    <li>@item.Title - @item.Date.ToShortDateString()</li>
}
</ul>

@code {
    private string userName = "Marcin";
    private bool isLoggedIn = true;
    private int messageCount = 5;
    private List<Item> items = new();
}

Komponenty

Komponent to plik .razor — nazwa pliku staje sie nazwa komponentu (PascalCase). W innym komponencie uzywasz go jak HTML elementu.

<!-- Counter.razor -->
<h2>Licznik: @count</h2>
<button @onclick="Increment" class="btn btn-primary">+1</button>

@code {
    private int count = 0;
    private void Increment() => count++;
}
<!-- Page.razor -->
@page "/"
<h1>Strona glowna</h1>
<Counter />

Parametry

Komponent moze przyjmowac dane z rodzica przez atrybut [Parameter].

<!-- ProductCard.razor -->
<div class="card">
  <h3>@Name</h3>
  <p>Cena: @Price.ToString("C")</p>
  @if (IsOnSale)
  {
    <span class="badge bg-danger">Promocja</span>
  }
</div>

@code {
    [Parameter] public string Name { get; set; } = "";
    [Parameter] public decimal Price { get; set; }
    [Parameter] public bool IsOnSale { get; set; }
}
<!-- Uzycie -->
<ProductCard Name="Laptop" Price="3499.99m" IsOnSale="true" />

Eventy — EventCallback

Aby komponent dziecko mogl powiadomic rodzica o zdarzeniu, uzywamy EventCallback.

<!-- DeleteButton.razor -->
<button @onclick="HandleClick">Usun</button>

@code {
    [Parameter] public int Id { get; set; }
    [Parameter] public EventCallback<int> OnDeleted { get; set; }

    private async Task HandleClick()
    {
        await OnDeleted.InvokeAsync(Id);
    }
}
<!-- Rodzic -->
<DeleteButton Id="42" OnDeleted="HandleDelete" />

@code {
    private void HandleDelete(int id)
    {
        // ... logika
    }
}

Two-way binding (@bind)

Specjalna skladnia @bind automatyzuje synchronizacje wartosci miedzy modelem i kontrolka.

<input @bind="userName" />
<p>Witaj, @userName</p>

<!-- Domyslnie aktualizacja na onchange (po blur) -->

<!-- Aktualizacja na kazdy keypress -->
<input @bind="userName" @bind:event="oninput" />

@code {
    private string userName = "";
}

Mozesz tworzyc wlasne komponenty z dwukierunkowym bindingiem:

<!-- ColorPicker.razor -->
<input type="color" value="@Value" @oninput="OnInput" />

@code {
    [Parameter] public string Value { get; set; } = "#000000";
    [Parameter] public EventCallback<string> ValueChanged { get; set; }

    private async Task OnInput(ChangeEventArgs e)
    {
        Value = e.Value?.ToString() ?? "";
        await ValueChanged.InvokeAsync(Value);
    }
}

<!-- Uzycie -->
<ColorPicker @bind-Value="selectedColor" />

Lifecycle methods

MetodaWywolywana
OnInitialized / OnInitializedAsyncRaz, przy stworzeniu komponentu
OnParametersSet / OnParametersSetAsyncPo kazdej zmianie parametrow
OnAfterRender / OnAfterRenderAsyncPo renderze (firstRender = true tylko za pierwszym razem)
ShouldRenderCzy komponent ma sie ponownie wyrenderowac
Dispose / DisposeAsyncCleanup przy usuwaniu (IDisposable / IAsyncDisposable)
 
@implements IDisposable
@inject IDataService DataService

<h1>Lista produktow</h1>

@code {
    private List<Product> products = new();
    private Timer? refreshTimer;

    protected override async Task OnInitializedAsync()
    {
        products = await DataService.GetProductsAsync();
        refreshTimer = new Timer(_ => InvokeAsync(StateHasChanged), null, 0, 5000);
    }

    protected override async Task OnAfterRenderAsync(bool firstRender)
    {
        if (firstRender)
        {
            // np. inicjalizacja JS interop
        }
    }

    public void Dispose()
    {
        refreshTimer?.Dispose();
    }
}

StateHasChanged

Blazor automatycznie re-renderuje komponent po zdarzeniu @onclick, EventCallback, OnInitialized itp. Jednak gdy zmieniasz state z innego watku (Timer, callback z biblioteki JS), trzeba recznie:

await InvokeAsync(StateHasChanged);

@rendermode (od .NET 8/9)

W Blazor United mozesz zadeklarowac na kazdy komponent, w jakim modelu ma sie renderowac:

<!-- Statyczny SSR (default) -->
<ProductList />

<!-- Server (SignalR) -->
<CartWidget @rendermode="InteractiveServer" />

<!-- WebAssembly -->
<Editor @rendermode="InteractiveWebAssembly" />

<!-- Auto: Server na pierwszy load, potem WASM -->
<Map @rendermode="InteractiveAuto" />

Konwencje plikow Razor

  • Pages/ — komponenty z @page (routing)
  • Components/ lub Shared/ — reusable komponenty
  • _Imports.razor — globalne @using directives
  • App.razor — root komponent z routingiem
  • Program.cs — konfiguracja DI, builder.Services.AddRazorComponents itp.
