EditForm — podstawa

Komponent EditForm opakowuje formularz, podpiety do modelu. Generuje akcje submit, integruje walidacje, wystawia EditContext.

<EditForm Model="@product" OnValidSubmit="HandleSubmit" OnInvalidSubmit="HandleInvalid">
    <DataAnnotationsValidator />
    <ValidationSummary />

    <label>Nazwa</label>
    <InputText @bind-Value="product.Name" class="form-control" />
    <ValidationMessage For="() => product.Name" />

    <label>Cena</label>
    <InputNumber @bind-Value="product.Price" class="form-control" />

    <button type="submit">Zapisz</button>
</EditForm>

@code {
    private Product product = new();

    private async Task HandleSubmit() {
        await ProductService.SaveAsync(product);
    }

    private void HandleInvalid() {
        Console.WriteLine("Walidacja nieudana");
    }
}

Data Annotations

Walidacja deklaratywna na modelu — klasyczne podejscie .NET.

using System.ComponentModel.DataAnnotations;

public class Product
{
    [Required(ErrorMessage = "Nazwa jest wymagana")]
    [StringLength(100, MinimumLength = 3,
        ErrorMessage = "Nazwa musi miec 3-100 znakow")]
    public string Name { get; set; } = "";

    [Required]
    [Range(0.01, 999999.99, ErrorMessage = "Cena musi byc dodatnia")]
    public decimal Price { get; set; }

    [Required]
    [EmailAddress]
    public string ContactEmail { get; set; } = "";

    [Url]
    public string? Website { get; set; }

    [RegularExpression(@"^\d{3}-\d{3}-\d{3}$",
        ErrorMessage = "Format: 123-456-789")]
    public string Phone { get; set; } = "";

    [Compare(nameof(Password))]
    public string PasswordConfirm { get; set; } = "";
}

FluentValidation

Popularna alternatywa z lepsza ergonomika dla zlozonej walidacji. Nie miesza modelu z atrybutami.

using FluentValidation;

public class ProductValidator : AbstractValidator<Product>
{
    public ProductValidator(IProductRepository repo)
    {
        RuleFor(p => p.Name)
            .NotEmpty()
            .Length(3, 100);

        RuleFor(p => p.Price)
            .GreaterThan(0)
            .LessThan(1_000_000);

        RuleFor(p => p.Sku)
            .MustAsync(async (sku, ct) => !await repo.ExistsAsync(sku))
            .WithMessage("SKU juz istnieje");

        When(p => p.IsOnSale, () =>
        {
            RuleFor(p => p.SalePrice)
                .NotNull()
                .LessThan(p => p.Price);
        });
    }
}

Custom validators

Custom DataAnnotation attribute

public class FutureDateAttribute : ValidationAttribute
{
    protected override ValidationResult? IsValid(object? value, ValidationContext ctx)
    {
        if (value is DateTime dt && dt < DateTime.UtcNow)
            return new ValidationResult("Data musi byc w przyszlosci");

        return ValidationResult.Success;
    }
}

// Uzycie
[FutureDate]
public DateTime EventDate { get; set; }

EditContext custom validation

private EditContext? editContext;
private ValidationMessageStore? messages;

protected override void OnInitialized()
{
    editContext = new EditContext(model);
    messages = new ValidationMessageStore(editContext);
    editContext.OnValidationRequested += OnValidate;
}

private void OnValidate(object? sender, ValidationRequestedEventArgs e)
{
    messages!.Clear();
    if (!IsValidCustomLogic(model))
        messages.Add(() => model.SomeField, "Custom error message");
}

File upload

Pojedynczy plik

<InputFile OnChange="HandleFile" accept=".pdf,.jpg,.png" />

@code {
    private async Task HandleFile(InputFileChangeEventArgs e)
    {
        var file = e.File;
        Console.WriteLine($"Nazwa: {file.Name}, rozmiar: {file.Size}");

        // Streaming dla duzych plikow
        await using var stream = file.OpenReadStream(maxAllowedSize: 10_000_000);
        var buffer = new byte[file.Size];
        await stream.ReadAsync(buffer);
    }
}

<InputFile multiple OnChange="HandleFiles" />

@code {
    private async Task HandleFiles(InputFileChangeEventArgs e)
    {
        foreach (var file in e.GetMultipleFiles(maximumFileCount: 10))
        {
            await using var stream = file.OpenReadStream(maxAllowedSize: 5 * 1024 * 1024);
            // Upload na serwer
        }
    }
}

Submit z indykatorem ladowania

<EditForm Model="@model" OnValidSubmit="Submit">
    <DataAnnotationsValidator />
    <InputText @bind-Value="model.Email" />

    <button type="submit" disabled="@isSubmitting">
        @(isSubmitting ? "Wysylam..." : "Wyslij")
    </button>
</EditForm>

@code {
    private bool isSubmitting = false;

    private async Task Submit()
    {
        isSubmitting = true;
        try { await Api.SubmitAsync(model); }
        finally { isSubmitting = false; }
    }
}

Walidacja serwerowa

Po submit czesto trzeba zwrocic bledy z serwera (np. "email zajety"). Najlepiej rozszerzyc ValidationMessageStore.

private async Task Submit()
{
    var result = await Api.RegisterAsync(model);

    if (!result.Success)
    {
        messages!.Clear();
        foreach (var error in result.Errors)
            messages.Add(() => model.Email, error.Message);
        editContext!.NotifyValidationStateChanged();
    }
}

Form layout patterns

Typowe podejscia w 2026:

  • Bootstrap forms — klasy .form-control, .form-label
  • MudBlazor — MudTextField, MudSelect z built-in validation UI
  • Radzen Blazor — bogate komponenty z drag&drop
  • Custom Tailwind — opakowanie InputText we wlasny komponent

Best practices

  • Walidacja klienta + serwera — nigdy nie ufaj samej klienta
  • FluentValidation lepsze dla skomplikowanej walidacji warunkowej
  • Dla file upload zawsze ustawiaj maxAllowedSize — default 500 KB
  • Pokazuj walidacje on-blur, nie on-input (mniej irytujace)
  • Disable submit button w trakcie submitu — uniknij double-submit
