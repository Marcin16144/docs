Blazor WPF

WPF host z BlazorWebView, mixing XAML and Razor, modernization legacy

Co to Blazor WPF?

WPF (Windows Presentation Foundation) to platforma desktop UI od 2006 roku. Wciaz wykorzystywana w tysiacach aplikacji enterprise. Blazor WPF pozwala wstawic Blazor komponenty do istniejacej WPF aplikacji przez kontrolke BlazorWebView.

Kiedy uzyc?

  • Modernizacja legacy WPF — nowe ekrany w Blazor, stare zostaja w XAML
  • Reuse webowych komponentow w aplikacji desktop
  • Zespol C# zna lepiej Blazor niz XAML
  • Internal narzedzia Windows-only z modernym UI

App.xaml — rejestracja services

<Application x:Class="MyWpfApp.App"
             xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
             StartupUri="MainWindow.xaml">
    <Application.Resources>
        <ResourceDictionary>
            <!-- Default Blazor styles -->
        </ResourceDictionary>
    </Application.Resources>
</Application>
// App.xaml.cs
public partial class App : Application
{
    public IServiceProvider Services { get; private set; } = null!;

    protected override void OnStartup(StartupEventArgs e)
    {
        var services = new ServiceCollection();

        services.AddWpfBlazorWebView();
#if DEBUG
        services.AddBlazorWebViewDeveloperTools();
#endif

        services.AddSingleton<WeatherService>();
        services.AddSingleton<ICustomerService, CustomerService>();

        Services = services.BuildServiceProvider();

        base.OnStartup(e);
    }
}

Mixed UI — XAML + Blazor

Najczestszy use case — legacy WPF z nowymi sekcjami w Blazor.

<Window>
    <Grid>
        <Grid.RowDefinitions>
            <RowDefinition Height="Auto" />
            <RowDefinition Height="*" />
        </Grid.RowDefinitions>

        <!-- Stary XAML toolbar -->
        <ToolBar Grid.Row="0">
            <Button Content="Zapisz" Click="OnSave" />
            <Button Content="Odswiez" Click="OnRefresh" />
        </ToolBar>

        <!-- Nowy Blazor content -->
        <b:BlazorWebView Grid.Row="1"
                          HostPage="wwwroot/index.html"
                          Services="{x:Static local:App.Services}">
            <b:BlazorWebView.RootComponents>
                <b:RootComponent Selector="#app" ComponentType="{x:Type components:Dashboard}" />
            </b:BlazorWebView.RootComponents>
        </b:BlazorWebView>
    </Grid>
</Window>

Komunikacja XAML <-> Blazor

Z XAML do Blazor

// MainWindow.xaml.cs
private void OnSave(object sender, RoutedEventArgs e)
{
    // Wywoluj metode w Blazor komponencie
    var service = App.Services.GetService<ICommunicationService>();
    service?.TriggerSave();
}
// CommunicationService
public interface ICommunicationService
{
    event Action? OnSave;
    void TriggerSave();
}

public class CommunicationService : ICommunicationService
{
    public event Action? OnSave;
    public void TriggerSave() => OnSave?.Invoke();
}
@inject ICommunicationService Comm
@implements IDisposable

@code {
    protected override void OnInitialized()
    {
        Comm.OnSave += HandleSave;
    }

    private void HandleSave() { /* ... */ }

    public void Dispose() => Comm.OnSave -= HandleSave;
}

WebView2 control

Pod spodem Blazor WPF uzywa WebView2 (Chromium-based, czesc Edge). Wymaga zainstalowanego Edge / WebView2 runtime. Microsoft dystrybuuje to z Windows 11 i nowszymi.

Plusy i minusy

Plusy

  • Modernizacja bez przepisywania calej aplikacji
  • Reuse Blazor komponentow z webowej aplikacji
  • WebView2 Chromium — nowoczesny silnik HTML5/CSS3
  • Hot reload dla Blazor
  • WPF features (window, dialogi, native API) dalej dostepne

Minusy

  • Wymaga Windows + WebView2
  • Bundle wiekszy o WebView
  • Mixing dwoch UI paradigmatow moze byc mylace
  • WPF Designer nie pokazuje Blazor content
  • Theming — trudniej spojnie miedzy XAML i CSS

Migracja XAML → Blazor — strategia

  1. Stworz nowy ekran w Blazor (osobno od WPF)
  2. Wyodrebnij wspolne services do interfejsow
  3. Dodaj BlazorWebView do nowej zakladki / okna
  4. Migruj kolejne sekcje za sekcja
  5. Po migracji wszystkich ekranow — rozwaz Blazor MAUI dla cross-platform

Theming sync

Aby Blazor uzywal kolorow systemu Windows i wygladal spojnie z WPF:

// Detekcja system theme
public static bool IsLightTheme()
{
    using var key = Registry.CurrentUser.OpenSubKey(
        @"Software\Microsoft\Windows\CurrentVersion\Themes\Personalize");
    return (int?)key?.GetValue("AppsUseLightTheme") == 1;
}

// Przekaz do Blazor przez serwis
services.AddSingleton(new ThemeService { IsLight = IsLightTheme() });

Wskazowka

Dla nowego projektu desktop (bez legacy WPF) prawdopodobnie lepszy wybor to Blazor MAUI — cross-platform z jednym codebase. Blazor WPF ma sens glownie gdy modernizujesz istniejaca WPF aplikacje lub potrzebujesz konkretnych WPF features.
