Blazor MAUI

Single codebase: Windows, macOS, iOS, Android. BlazorWebView, MAUI APIs

Co to Blazor MAUI?

.NET MAUI (Multi-platform App UI) to nastepca Xamarin.Forms. Pozwala pisac aplikacje natywne dla 4 platform z jednego kodu. Blazor MAUI to specjalny tryb — uzywasz Blazor komponentow zamiast XAML do UI, a MAUI dostarcza native shell, plugins i deployment.

Kiedy Blazor MAUI?

  • Masz juz aplikacje Blazor (Server lub WASM) i chcesz desktop / mobile wersje
  • Zespol C# + Blazor, ale nie chce uczyc XAML
  • UI jest "web-like" — nie potrzebuje idealnie natywnych komponentow
  • Reuse webowych komponentow w aplikacji desktopowej

MauiProgram.cs

public static class MauiProgram
{
    public static MauiApp CreateMauiApp()
    {
        var builder = MauiApp.CreateBuilder();
        builder
            .UseMauiApp<App>()
            .ConfigureFonts(fonts =>
            {
                fonts.AddFont("OpenSans-Regular.ttf", "OpenSansRegular");
            });

        builder.Services.AddMauiBlazorWebView();

#if DEBUG
        builder.Services.AddBlazorWebViewDeveloperTools();
        builder.Logging.AddDebug();
#endif

        builder.Services.AddSingleton<WeatherForecastService>();

        return builder.Build();
    }
}

MainPage.xaml — host dla Blazor

<?xml version="1.0" encoding="utf-8" ?>
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             xmlns:b="clr-namespace:Microsoft.AspNetCore.Components.WebView.Maui;assembly=Microsoft.AspNetCore.Components.WebView.Maui"
             xmlns:components="clr-namespace:MyMauiApp.Components"
             x:Class="MyMauiApp.MainPage"
             BackgroundColor="{DynamicResource PageBackgroundColor}">

    <b:BlazorWebView x:Name="blazorWebView" HostPage="wwwroot/index.html">
        <b:BlazorWebView.RootComponents>
            <b:RootComponent Selector="#app" ComponentType="{x:Type components:Routes}" />
        </b:BlazorWebView.RootComponents>
    </b:BlazorWebView>
</ContentPage>

BlazorWebView

Sercem Blazor MAUI jest komponent BlazorWebView — widget XAML, ktory hostuje native WebView2 (Windows), WKWebView (iOS), WebView (Android) i renderuje w nim Blazor app.

Ekrany

Pojedyncze BlazorWebView

Najczesciej caly UI w jednym BlazorWebView, MAUI tylko shell.

Hybrid — XAML + Blazor

Mozesz miec rozne ekrany — jedne XAML, drugie Blazor. Idealne dla migracji legacy XAML aplikacji.

<TabbedPage>
    <ContentPage Title="Native">
        <StackLayout>
            <Label Text="Native MAUI tab" />
        </StackLayout>
    </ContentPage>
    <ContentPage Title="Web">
        <b:BlazorWebView HostPage="wwwroot/index.html">...</b:BlazorWebView>
    </ContentPage>
</TabbedPage>

Wywolywanie native APIs

W Blazor komponencie mozesz uzywac MAUI APIs przez DI — nie ma "sandboxa", to lokalna aplikacja.

Geolocation

@inject IGeolocation Geo

<button @onclick="GetLocation">Pobierz lokalizacje</button>
<p>@locationText</p>

@code {
    private string locationText = "";

    private async Task GetLocation()
    {
        try
        {
            var location = await Geo.GetLocationAsync(new GeolocationRequest
            {
                DesiredAccuracy = GeolocationAccuracy.Best,
                Timeout = TimeSpan.FromSeconds(10)
            });

            if (location != null)
                locationText = $"{location.Latitude}, {location.Longitude}";
        }
        catch (FeatureNotSupportedException)
        {
            locationText = "Brak wsparcia na tej platformie";
        }
    }
}

Sensors

@implements IDisposable

@code {
    protected override void OnInitialized()
    {
        Accelerometer.Default.ReadingChanged += OnAccelerometerReading;
        Accelerometer.Default.Start(SensorSpeed.UI);
    }

    private void OnAccelerometerReading(object? sender, AccelerometerChangedEventArgs e)
    {
        var data = e.Reading;
        InvokeAsync(StateHasChanged);
    }

    public void Dispose()
    {
        Accelerometer.Default.Stop();
        Accelerometer.Default.ReadingChanged -= OnAccelerometerReading;
    }
}

Plusy Blazor MAUI

  • Single codebase — Windows + macOS + iOS + Android
  • Reuse Blazor komponentow z webowej aplikacji
  • Native packaging (App Store, Play Store, Microsoft Store)
  • Pelny dostep do native APIs (camera, GPS, sensors, BLE)
  • Brak Internet potrzebny — aplikacja dziala offline
  • C# end-to-end

Minusy

  • Bundle size — aplikacja musi miec .NET runtime + WebView
  • iOS na 1 .NET version behind (czas certyfikacji)
  • Niektore komponenty webowe nie wygladaja idealnie native
  • WebView limitations: no DRM, restricted JS API
  • MAUI samo bywa niestabilne na niektorych edge case

Performance

PlatformStartupMemory baseline
Windows~1 sek~150 MB
macOS~1 sek~120 MB
iOS~2 sek~100 MB
Android~2-3 sek~150 MB

Hot reload

Hot Reload dziala dla Blazor MAUI — zmiany w .razor sa widoczne natychmiast bez restartu.

Use cases 2026

  • Aplikacje terenowe (inspekcje, formularze offline)
  • Wewnetrzne aplikacje firmowe na 4 platformy
  • Sklepy / kioski sprzedaz
  • POC mobile aplikacji bez angazowania React Native / Flutter teamu
  • Aplikacje z heavy BLE / sensors (idealne dla MAUI)
