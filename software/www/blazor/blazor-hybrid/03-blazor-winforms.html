Blazor WinForms

WinForms z BlazorWebView, modernizacja legacy bez full rewrite

Po co Blazor w WinForms?

WinForms to najstarsza desktopowa platforma .NET (od 2002). Setki tysiecy line-of-business aplikacji w Polsce dziala na WinForms. Migracja na nowoczesne stacki jest droga — Blazor WinForms oferuje sciezke gradalna: dodawanie nowoczesnych ekranow do legacy aplikacji bez przepisywania calosci.

Setup projektu

dotnet new winforms -n MyWinFormsApp
cd MyWinFormsApp
dotnet add package Microsoft.AspNetCore.Components.WebView.WindowsForms

Program.cs (.NET 9)

using Microsoft.Extensions.DependencyInjection;

namespace MyWinFormsApp;

internal static class Program
{
    public static IServiceProvider Services { get; private set; } = null!;

    [STAThread]
    static void Main()
    {
        ApplicationConfiguration.Initialize();

        var services = new ServiceCollection();
        services.AddWindowsFormsBlazorWebView();
#if DEBUG
        services.AddBlazorWebViewDeveloperTools();
#endif

        services.AddSingleton<DataService>();

        Services = services.BuildServiceProvider();

        Application.Run(new MainForm());
    }
}

public partial class MainForm : Form

    }
}

Hybrid scenario — jeden ekran legacy, drugi nowoczesny

// Tabbed approach
public partial class MainForm : Form
{
    public MainForm()
    {
        var tabControl = new TabControl { Dock = DockStyle.Fill };

        // Stary legacy ekran
        var legacyTab = new TabPage("Lista (legacy)");
        legacyTab.Controls.Add(BuildLegacyDataGrid());
        tabControl.TabPages.Add(legacyTab);

        // Nowy ekran w Blazor
        var blazorTab = new TabPage("Dashboard (Blazor)");
        var webView = new BlazorWebView
        {
            Dock = DockStyle.Fill,
            HostPage = "wwwroot/index.html",
            Services = Program.Services
        };
        webView.RootComponents.Add<Dashboard>("#app");
        blazorTab.Controls.Add(webView);
        tabControl.TabPages.Add(blazorTab);

        Controls.Add(tabControl);
    }
}

Komunikacja WinForms <-> Blazor

Shared service

public class AppContext
{
    public event Action<Customer>? OnCustomerSelected;

    public void NotifyCustomerSelected(Customer customer)
    {
        OnCustomerSelected?.Invoke(customer);
    }
}

// W Program.cs
services.AddSingleton<AppContext>();
// WinForms - wybor wiersza w GridView
private void OnGridSelectionChanged(object sender, EventArgs e)
{
    var customer = (Customer)dataGrid.SelectedRows[0].DataBoundItem;
    var ctx = Program.Services.GetService<AppContext>();
    ctx?.NotifyCustomerSelected(customer);
}
// Blazor reaguje
@inject AppContext Ctx
@implements IDisposable

@code {
    private Customer? selected;

    protected override void OnInitialized()
    {
        Ctx.OnCustomerSelected += HandleCustomerSelected;
    }

    private void HandleCustomerSelected(Customer c)
    {
        selected = c;
        InvokeAsync(StateHasChanged);
    }

    public void Dispose() => Ctx.OnCustomerSelected -= HandleCustomerSelected;
}

Dlaczego HtmlBlazorView a nie cos innego?

WinForms ma starszy WebBrowser control (IE-based) — przestarzaly, nie wspiera nowoczesnego HTML/CSS. BlazorWebView uzywa WebView2 (Chromium), wiec mozesz uzywac modernych framework UI (Tailwind, MudBlazor, Bootstrap 5).

Typowy modernization scenario

  1. Audit — ktore ekrany sa najbardziej "ostatnie", krytyczne, dotykane przez biznes?
  2. Wybierz pilot — jeden ekran do migracji jako proof of concept
  3. Wyodrebnij services — logika biznesowa do interfejsow
  4. Stworz Blazor komponent — nowy UI dla pilot screen
  5. Pokaz w nowej karcie / oknie — uzytkownicy maja wybor
  6. Migracja sekwencyjna — co miesiac jeden ekran wiecej
  7. Po migracji 80%+ — rozwaz Blazor MAUI dla cross-platform

Plusy

  • Niska bariera wejscia — nie zmienasz architektury aplikacji
  • WebView2 daje nowoczesny silnik HTML/CSS3
  • Mozesz uzywac istniejacych Blazor komponentow z webowej aplikacji
  • Hot reload dziala na komponentach .razor
  • Mieszanie z legacy WinForms (DataGrid, formularze) — bez stresu

Minusy

  • Tylko Windows (jak WinForms) — brak cross-platform
  • Wymaga WebView2 runtime u uzytkownika
  • Bundle wiekszy o WebView (mniejszy problem na desktopie)
  • Theming — trudno spojnie WinForms (system colors) i Blazor (CSS)
  • Hybrydowe debugging skomplikowane

Common scenarios

1. Modernizacja zakladek

Aplikacja ksiegowa z 30 zakladkami, 5 najwazniejszych w Blazor, reszta legacy WinForms.

2. Mieszany formularz

Lista po lewej (WinForms DataGridView z highly-tuned filtering), szczegoly po prawej (Blazor — modern UI z walidacja, fancy formy).

3. Wewnetrzne dashboardy

Aplikacje narzedziowe ze 100+ widokami, ale tylko kilka wymaga modernizacji — zostaje WinForms shell, nowe analytics w Blazor.

4. Pomost migracyjny

Plan: za 3 lata wszystko bedzie w Blazor MAUI. Dzisiaj — piszemy nowe ekrany juz w Blazor, mieszamy z WinForms.

Theming — sync z systemem

public static class ThemeHelper
{
    public static bool IsLightTheme()
    {
        using var key = Registry.CurrentUser.OpenSubKey(
            @"Software\Microsoft\Windows\CurrentVersion\Themes\Personalize");
        return (int?)key?.GetValue("AppsUseLightTheme") == 1;
    }
}

// Aplikacja zmiena theme przy starcie
<html data-bs-theme="@(ThemeHelper.IsLightTheme() ? "light" : "dark")">

Wskazowka

Dla nowych projektow desktop nie wybieraj Blazor WinForms — Blazor MAUI daje to samo + cross-platform. Blazor WinForms ma sens tylko gdy:

  • Masz istniejaca duza WinForms aplikacje
  • Targeting tylko Windows
  • Nie chcesz przepisywac calosci, tylko modernizujesz wybrane ekrany
