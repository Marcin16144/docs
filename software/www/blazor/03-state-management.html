Cascading parameters

Pozwalaja przekazywac dane od rodzica w dol drzewa bez explicite prop dla kazdego pomidnego komponentu.

<!-- ThemeProvider.razor -->
<CascadingValue Value="@theme">
    @ChildContent
</CascadingValue>

@code {
    [Parameter] public RenderFragment? ChildContent { get; set; }
    private Theme theme = new("dark", "#a855f7");

    public void ChangeTheme(Theme newTheme)
    {
        theme = newTheme;
        StateHasChanged();
    }
}
<!-- DeepNestedComponent.razor -->
<p style="color: @Theme.PrimaryColor">Stylowany przez cascading param</p>

@code {
    [CascadingParameter] public Theme Theme { get; set; } = default!;
}

Nazwane cascading parameters

<CascadingValue Value="@user" Name="CurrentUser">
    <CascadingValue Value="@settings" Name="Settings">
        @ChildContent
    </CascadingValue>
</CascadingValue>

@code {
    [CascadingParameter(Name = "CurrentUser")]
    public User? User { get; set; }

Dependency Injection

Najczestszy wzorzec dla zarzadzania stanem — scoped service jako "store".

// CartService.cs
public class CartService
{
    private readonly List<CartItem> items = new();

    public IReadOnlyList<CartItem> Items => items;
    public decimal Total => items.Sum(i => i.Price * i.Quantity);

    public event Action? OnChange;

    public void Add(Product product)
    {
        var existing = items.FirstOrDefault(i => i.ProductId == product.Id);
        if (existing != null)
            existing.Quantity++;
        else
            items.Add(new CartItem(product.Id, product.Name, product.Price, 1));

        OnChange?.Invoke();
    }

    public void Remove(int productId)
    {
        items.RemoveAll(i => i.ProductId == productId);
        OnChange?.Invoke();
    }
}
// Program.cs
builder.Services.AddScoped<CartService>();
<!-- CartWidget.razor -->
@inject CartService Cart
@implements IDisposable

<div>
    Koszyk: @Cart.Items.Count produktow
    Total: @Cart.Total.ToString("C")
</div>

@code {
    protected override void OnInitialized()
    {
        Cart.OnChange += StateHasChanged;
    }

    public void Dispose()
    {
        Cart.OnChange -= StateHasChanged;
    }
}

Service lifetimes

LifetimeBlazor ServerBlazor WASM
SingletonJeden dla calej aplikacji (wszystkie SignalR circuits)Jeden per uzytkownik (per WASM session)
ScopedJeden per circuit (per uzytkownik)Jak singleton (jeden per session)
TransientNowa instancja przy kazdej iniekcjiNowa instancja przy kazdej iniekcji

W Blazor Server nie uzywaj Singleton dla danych specyficznych uzytkownika — wszyscy zaloguja sie do tej samej instancji.

Fluxor — Redux-like

Fluxor to popularny library dla Blazor implementujacy wzorzec Redux/Flux. Daje predictable state, time-travel debugging, immutable state.

// State
public record CounterState(int Count);

// Feature
public class CounterFeature : Feature<CounterState>
{
    public override string GetName() => "Counter";
    protected override CounterState GetInitialState() => new(0);
}

// Action
public record IncrementAction;

// Reducer
public static class CounterReducers
{
    [ReducerMethod]
    public static CounterState OnIncrement(CounterState state, IncrementAction _) =>
        state with { Count = state.Count + 1 };
}

// Effect (np. async API)
public class CounterEffects
{
    [EffectMethod]
    public async Task HandleSaveAction(SaveAction action, IDispatcher dispatcher)
    {
        await api.SaveAsync(action.Data);
        dispatcher.Dispatch(new SaveSuccessAction());
    }
}
// Komponent
@inherits FluxorComponent
@inject IState<CounterState> State
@inject IDispatcher Dispatcher

<p>Count: @State.Value.Count</p>
<button @onclick='() => Dispatcher.Dispatch(new IncrementAction())'>+</button>

Persistent state — localStorage

Najpopularniejsza biblioteka: Blazored.LocalStorage.

builder.Services.AddBlazoredLocalStorage();
@inject ILocalStorageService LocalStorage

@code {
    protected override async Task OnInitializedAsync()
    {
        var saved = await LocalStorage.GetItemAsync<CartState>("cart");
        if (saved != null) cart = saved;
    }

    private async Task Save()
    {
        await LocalStorage.SetItemAsync("cart", cart);
    }
}

PersistentState (Blazor United)

W Blazor United (.NET 8/9) mozna persistowac stan z prerendering do interaktywnego trybu — eliminuje "double fetch".

@inject PersistentComponentState ApplicationState

@code {
    private List<Product>? products;

    protected override async Task OnInitializedAsync()
    {
        if (!ApplicationState.TryTakeFromJson<List<Product>>("products", out products))
        {
            products = await Api.GetProductsAsync();
        }

        ApplicationState.RegisterOnPersisting(() =>
        {
            ApplicationState.PersistAsJson("products", products);
            return Task.CompletedTask;
        });
    }
}

Wskazowka — antypattern

Nie uzywaj static fields jako "store" — w Blazor Server beda wspoldzielone miedzy uzytkownikami, w WASM dziala "ok" ale to nieczyste rozwiazanie. Uzywaj DI scoped service dla stanu specyficznego dla uzytkownika.
