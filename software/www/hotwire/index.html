Hotwire (Turbo + Stimulus + Strada)

Rails-inspired HTML-over-wire. Zero JS framework dla server-rendered apps.

1. Co to Hotwire?

Hotwire (HTML Over The Wire) to zestaw technik i bibliotek stworzony przez Basecamp (David Heinemeier Hansson — DHH) i uzywany w produkcji w Basecamp oraz HEY (email). Glowna idea: serwer zawsze wysyla HTML, nie JSON. Brak potrzeby pisania JS API ani oddzielnego frontendu SPA.

Hotwire sklada sie z trzech bibliotek:

  • Turbo — przyspiesza nawigacje i aktualizacje fragmentow strony bez pelnego przeladowania. Zawiera Turbo Drive, Turbo Frames i Turbo Streams.
  • Stimulus — minimalistyczny JS framework do dodawania zachowan do server-rendered HTML. Kontrolery przypisane do elementow DOM.
  • Strada — most miedzy webem a natywnymi aplikacjami mobilnymi (iOS/Android) przez Turbo Native.
Filozofia DHH: "You're not building a JavaScript app. You're building a web app that uses JavaScript." Hotwire pozwala pisac aplikacje webowe w jednym jezyku backendowym — Rails, Laravel, Django, Go — bez poswiecania UX.

2. Turbo Drive

Turbo Drive (nastepca Turbolinks) przechwytuje klikniecia w linki i submity formularzy, wykonuje je jako fetch requests zamiast pelnego przeladowania strony, a nastepnie zamienia <body> i aktualizuje <head>. Historia przegladarki i URL sa aktualizowane normalnie (History API).

Jak dziala

  • Uzytkownik klika link → Turbo przechwytuje event, wysyla GET fetch
  • Serwer zwraca pelny HTML (jak zawsze)
  • Turbo zamienia <body> bez mrugnięcia strony — brak bialego ekranu
  • CSS i JS z <head> sa porownywane — nowe pliki sa ladowane, powtarzajace sie pomijane

Wylaczenie Turbo Drive dla konkretnego linku

<!-- wylacz dla konkretnego linku -->
<a href="/pobierz/plik.pdf" data-turbo="false">Pobierz PDF</a>

<!-- wylacz dla calego formularza -->
<form action="/upload" method="post" data-turbo="false">
  ...
</form>

<!-- cache hints -->
<meta name="turbo-cache-control" content="no-cache">

3. Turbo Frames

Turbo Frames pozwalaja na aktualizacje tylko czesci strony — bez wpływu na reszte dokumentu. Kazda ramka jest niezalezna: klikniecia linkow i submity formularzy wewnatrz ramki aktualizuja tylko te ramke.

<!-- Strona glowna: ramka z lista zadan -->
<turbo-frame id="task-list">
  <ul>
    <li>Zadanie 1 <a href="/tasks/1/edit">Edytuj</a></li>
    <li>Zadanie 2 <a href="/tasks/2/edit">Edytuj</a></li>
  </ul>
</turbo-frame>

<!-- Lazy loading: zawartosc laduje sie po zaladowaniu strony -->
<turbo-frame id="stats" src="/stats/partial" loading="lazy">
  <p>Ladowanie statystyk...</p>
</turbo-frame>

Odpowiedz serwera dla /tasks/1/edit musi zawierac <turbo-frame id="task-list"> — Turbo wyszuka ramke po ID i zamieni jej zawartosc.

4. Turbo Streams

Turbo Streams to najpotezniejszy mechanizm Hotwire. Pozwala na granularne aktualizacje DOM przez WebSocket, SSE lub w odpowiedzi na submit formularza. Serwer wysyla specjalne tagi <turbo-stream> z akcja i celem.

append
Dodaje na koniec targetu
prepend
Dodaje na poczatek targetu
replace
Zamienia caly element
update
Zamienia innerHTML
remove
Usuwa element z DOM
before
Wstawia przed elementem
after
Wstawia za elementem
refresh
Odswieza strone (morph)
<!-- Serwer wysyla ten HTML przez WebSocket lub jako odpowiedz na POST -->
<turbo-stream action="append" target="messages">
  <template>
    <li id="message-42">Nowa wiadomosc od Alicji</li>
  </template>
</turbo-stream>

<turbo-stream action="remove" target="message-10"></turbo-stream>

<turbo-stream action="update" target="unread-count">
  <template>5</template>
</turbo-stream>

5. Stimulus

Stimulus to minimalistyczny framework JS (8 kB) do "skromnego" uzupelniania server-rendered HTML. Nie zarzadza stanem — zamiast tego laczy sie z istniejacym DOM przez konwencje nazewnicze. Kazdy kontroler to klasa JS z lifecycle callbacks.

Trzy podstawowe koncepcje

  • Kontrolery (data-controller) — klasy JS przypisane do elementow DOM. Automatycznie inicjalizowane/niszczone wraz z elementem.
  • Actions (data-action) — zdarzenia DOM podpinane pod metody kontrolera: click->modal#open
  • Targets (data-[controller]-target) — referencje do konkretnych elementow DOM wewnatrz kontrolera: data-modal-target="dialog"
  • Values (data-[controller]-[name]-value) — reaktywne dane przekazywane do kontrolera z HTML, obserwowane przez [name]ValueChanged()
// hello_controller.js
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static targets = ["name", "output"]
  static values  = { greeting: { type: String, default: "Czesc" } }

  connect() {
    console.log("Kontroler podlaczony do:", this.element)
  }

  greet() {
    this.outputTarget.textContent =
      `${this.greetingValue}, ${this.nameTarget.value}!`
  }
}
<div data-controller="hello" data-hello-greeting-value="Witaj">
  <input data-hello-target="name" type="text" placeholder="Twoje imie">
  <button data-action="click->hello#greet">Powitaj</button>
  <p data-hello-target="output"></p>
</div>

6. Strada — mobilna integracja

Strada to trzecia czesc Hotwire — most miedzy webowa aplikacja Turbo a natywnymi aplikacjami mobilnymi (Turbo Native dla iOS i Turbo Native dla Android). Pozwala na uzywanie jednej aplikacji webowej jako backendu dla natywnych aplikacji mobilnych.

  • Turbo Native iOS — Swift framework opakowujacy WKWebView. Natywna nawigacja, natywny tab bar, natywne gesty swipe.
  • Turbo Native Android — Kotlin framework z WebView. Integracja z Material Design, back stack, bottom navigation.
  • Strada Bridge Components — komunikacja miedzy JS (Stimulus) a natywnymi komponentami. Formularz na webview moze otworzyc natywny date picker.
Basecamp i HEY uzywaja Strada w produkcji — jedna aplikacja Rails, trzy platformy: web, iOS, Android. Minimalna ilosc kodu natywnego, maksymalna wspolna logika.

7. Integracja z rozными backendami

Ruby on Rails (natywne wsparcie)

Hotwire pochodzi z Rails — pelen support out-of-the-box. Gem turbo-rails i stimulus-rails. ActionCable do WebSocket. render turbo_stream: w kontrolerach.

PHP / Laravel

Pakiet tonysm/turbo-laravel dodaje Turbo::stream() facade, broadcastowanie przez Laravel Echo/Reverb, integracje z Livewire jest opcjonalna.

Python / Django

Pakiet django-turbo-response lub hotwire-django. Django Channels do WebSocket. TurboStreamResponse zamiast zwyklego HttpResponse.

Go

Brak oficjalnego pakietu — implementacja reczna jest prosta. Serwer wysyla HTML z naglowkiem Content-Type: text/vnd.turbo-stream.html. Mozna uzyc gorilla/websocket do Turbo Streams przez WebSocket.

Node.js / Express

Pakiet turbo-http lub reczna implementacja. Hotwire jest agnostyczne wobec backendu — potrzeba tylko poprawnych naglowkow i formatu HTML.

9. Kiedy uzywac Hotwire

Pytanie Czy uzywasz Ruby on Rails jako backendu?
TAK Hotwire to pierwszy wybor — natywna integracja, gem turbo-rails, ActionCable. Zero konfiguracji.
Pytanie Czy potrzebujesz natywnych aplikacji mobilnych iOS/Android ze wspoldzielonym webowym backendem?
TAK Hotwire + Strada + Turbo Native — jedno zrodlo prawdy, trzy platformy.
Pytanie Czy uzywasz Laravel i chcesz reaktywnych komponentow z logiką w PHP?
TAK LiveWire 3 moze byc lepszym wyborem niz Hotwire dla Laravel-first development.
Pytanie Czy backend jest w PHP/Django/Go i potrzebujesz prostych AJAX aktualizacji bez WebSocket?
TAK HTMX moze byc prostsze — mniejszy narzut, mniej konwencji do nauki.
Pytanie Czy aplikacja wymaga zlozonego stanu po stronie klienta, offline support, gestures, animacji SPA?
TAK React / Vue / SvelteKit — Hotwire nie jest przeznaczony do aplikacji SPA z rozbudowanym stanem klienta.

10. Przyklad: real-time notifications z Turbo Streams + ActionCable

Ponizszy przyklad pokazuje kompletna implementacje powiadomien w czasie rzeczywistym: Rails + ActionCable (WebSocket) + Turbo Streams. Klient subskrybuje kanal, serwer broadcastuje nowe powiadomienia jako Turbo Stream fragments.

1. Model i broadcasting (Rails)

# app/models/notification.rb
class Notification < ApplicationRecord
  belongs_to :user
  after_create_commit :broadcast_to_user

  private

  def broadcast_to_user
    # Turbo::StreamsChannel broadcastuje do streamu uzytkownika
    Turbo::StreamsChannel.broadcast_prepend_to(
      "notifications_user_#{user_id}",
      target: "notifications-list",
      partial: "notifications/notification",
      locals: { notification: self }
    )

    # Aktualizuj licznik
    Turbo::StreamsChannel.broadcast_update_to(
      "notifications_user_#{user_id}",
      target: "notifications-count",
      html: user.notifications.unread.count.to_s
    )
  end
end

2. Widok z subskrypcja streamu

<!-- app/views/notifications/index.html.erb -->

<%# Subskrybuj stream dla biezacego uzytkownika -->
<%= turbo_stream_from "notifications_user_#{current_user.id}" %>

<div class="notifications-header">
  <h2>Powiadomienia</h2>
  <span id="notifications-count" class="badge">
    <%= current_user.notifications.unread.count %>
  </span>
</div>

<ul id="notifications-list">
  <%= render @notifications %>
</ul>

3. Partial powiadomienia

<!-- app/views/notifications/_notification.html.erb -->
<li id="<%= dom_id(notification) %>"
     class="notification <%= 'unread' unless notification.read? %>">

  <span class="notification-message">
    <%= notification.message %>
  </span>

  <time datetime="<%= notification.created_at.iso8601 %>">
    <%= time_ago_in_words(notification.created_at) %> temu
  </time>

  <%= button_to "Oznacz jako przeczytane",
    mark_read_notification_path(notification),
    method: :patch,
    data: { turbo_stream: true } %>

</li>
Wynik: Gdy ktos tworzy powiadomienie dla uzytkownika (z dowolnego miejsca w aplikacji — background job, inny request), przeglądarka uzytkownika automatycznie i w czasie rzeczywistym pokazuje nowe powiadomienie na poczatku listy oraz aktualizuje licznik. Zero dodatkowego JS — czysty HTML renderowany przez serwer.

Integracja z non-Rails backendem (Go + WebSocket)

// Go: wysylanie Turbo Stream przez WebSocket
func broadcastNotification(conn *websocket.Conn, n Notification) error {
  html := fmt.Sprintf(`<turbo-stream action="prepend" target="notifications-list">
  <template>
    <li id="notification-%d">%s</li>
  </template>
</turbo-stream>`, n.ID, html.EscapeString(n.Message))

  return conn.WriteMessage(websocket.TextMessage, []byte(html))
}
