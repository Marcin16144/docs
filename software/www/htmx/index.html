HTMX

HTML attributes for dynamic UI — zero JS framework, perfect for PHP/Python/Go

Co to HTMX?

HTMX to biblioteka JavaScript, ktora pozwala robic AJAX, CSS Transitions, WebSockets i Server Sent Events bezposrednio z HTML — przez atrybuty. Filozofia "HTML jako hipermedium" — kazdy element moze stac sie interaktywny przez dodanie kilku atrybutow.

HTMX rosnie szybko od 2022 roku, glownie dzieki backend-heavy spolecznosciam (Django, Rails, Laravel, Go, ASP.NET MVC). Wystepuje czesto z Alpine.js dla logiki klienta i Tailwind dla stylow. Filozofia "no SPA" — serwer zwraca HTML, klient go zamienia.

Kluczowe cechy

  • Brak buildu — jeden script tag, dziala z CDN
  • Maly rozmiar — ~14 KB skompresowane
  • Server-driven — backend zwraca HTML, nie JSON
  • Progresywne enhancement — dziala bez JS (linki/forms standardowe)
  • Brak frameworka frontowego — mozna mieszac z czymkolwiek
  • WebSocket i Server-Sent Events out-of-box
  • Nie wymaga TypeScript, build, bundler

Instalacja

<!-- Po prostu CDN -->
<script src="https://unpkg.com/htmx.org@2.0.3"></script>

Przykladowy kod

<!-- Pobieranie tresci z serwera -->
<button hx-get="/api/products"
        hx-target="#products"
        hx-swap="innerHTML">
  Zaladuj produkty
</button>
<div id="products"></div>

<!-- Form submit z wynikem -->
<form hx-post="/api/contact" hx-target="#result">
  <input name="email" />
  <button type="submit">Wyslij</button>
</form>
<div id="result"></div>

<!-- Live search -->
<input type="search" name="q"
       hx-get="/api/search"
       hx-trigger="keyup changed delay:500ms"
       hx-target="#results" />

<!-- Polling co 5 sek -->
<div hx-get="/api/status"
     hx-trigger="every 5s"
     hx-swap="outerHTML">
  Status: ladowanie...
</div>

Atrybuty HTMX (najwazniejsze)

AtrybutCo robi
hx-get / hx-post / hx-put / hx-deleteWyslij request HTTP
hx-targetSelektor gdzie wstawic odpowiedz
hx-swapSposob wstawienia (innerHTML, outerHTML, beforeend, afterend, etc.)
hx-triggerWyzwalacz (click default, keyup, every Xs, revealed)
hx-confirmWyswietl confirm() przed wyslaniem
hx-valsDodatkowe wartosci do wyslania
hx-headersHeaders do dodania
hx-push-urlPush state historii
hx-boostKonwertuje <a> na hx-get
hx-wsWebSocket connection
hx-sseServer-Sent Events

Server response — HTML zamiast JSON

HTMX dziala z dowolnym backendem — sproszczona idea: zwracaj HTML zamiast JSON.

Python (Flask)

@app.post("/api/contact")
def contact():
    name = request.form["name"]
    return f'<div class="alert alert-success">Witaj {name}!</div>'

Go

http.HandleFunc("/api/products", func(w http.ResponseWriter, r *http.Request) {
    products := loadProducts()
    tmpl, _ := template.ParseFiles("products.html")
    tmpl.Execute(w, products)
})

Django

def products_partial(request):
    products = Product.objects.all()
    return render(request, "products_list.html", {"products": products})

ASP.NET Core (Razor)

// Controller
public IActionResult ProductsList() => PartialView("_ProductsList", products);

// _ProductsList.cshtml
@foreach (var p in Model)
{
    <div class="product">@p.Name - @p.Price</div>
}

Kombinacja z Alpine.js

HTMX = server interactions, Alpine = client interactions. Razem stanowia "lekki" zestaw alternatywny do React/Vue.

<div x-data="{ open: false }">
  <button @click="open = !open">Toggle</button>

  <div x-show="open" hx-get="/api/data" hx-trigger="revealed">
    Ladowanie z servera...
  </div>
</div>

Plusy

  • Zero JS frameworks ekspertyzy — jest backend dev = mozesz uzywac
  • Bardzo mae bundle (14 KB)
  • Aplikacja dziala bez JS (progressive enhancement)
  • SEO-friendly (server renderuje HTML)
  • Latwa migracja existing MVC apps
  • Brak buildu, brak node_modules

Minusy

  • Kazda interakcja = round trip do servera
  • Bardziej skomplikowane state management client-side
  • Animacje bardziej skomplikowane niz w SPA frameworks
  • Mniej skomplikowane interakcje (gry, edytory) sa trudne
  • Inny mental model niz React/Vue — wymaga zmian

Kiedy uzyc HTMX?

  • Aplikacje content-heavy (blogi, news, e-commerce)
  • Internal tools, dashboardy
  • Migrowanie z MVC bez przepisywania backend'u
  • Zespol backendowy bez frontendu specjalisty
  • Server-rendered apps (Django, Rails, Laravel, ASP.NET MVC)
  • Mae apki lokalne, prototyping

HTMX 2.0 zmiany

  • Drop wsparcia IE 11
  • Lepsza integracja Server-Sent Events
  • Nowy mechanizm extensions
  • Performance improvements
  • Mniejszy bundle
