SolidJS

JSX + reactive primitives — performance king z fine-grained reactivity

Co to SolidJS?

SolidJS to framework JavaScript stworzony przez Ryan Carniato. Polacza skladnie React (JSX) z modelem reaktywnoci znanym z Svelte i KnockoutJS — ale z lepsza performance i prostsza modelem mentalnym. W benchmarkach Solid stale zajmuje pierwsze miejsca (js-framework-benchmark).

Solid dziala fundamentalnie inaczej niz React — nie ma re-renderow komponentow. Komponent wykonuje sie tylko raz, a aktualizacje DOM ida bezposrednio do zmienionych miejsc przez sygnaly (signals).

Kluczowe cechy

  • JSX — znany z React, latwy dla migracji
  • Fine-grained reactivity — tylko zmienione DOM nodes sa update'owane
  • Signals — createSignal, createMemo, createEffect
  • Brak Virtual DOM — bezposrednie operacje na DOM
  • Performance king — benchmarki pokazuja Solid 2-3x szybszy od React
  • SolidStart — meta-framework (jak Next.js)
  • Mae bundle (~7 KB)
  • TypeScript-first

Instalacja

npm create solid@latest my-app
cd my-app
npm install
npm run dev

Pierwszy komponent

import { createSignal, createMemo } from 'solid-js';

function Counter() {
  const [count, setCount] = createSignal(0);
  const doubled = createMemo(() => count() * 2);

  return (
    <div>
      <h1>Count: {count()}</h1>
      <p>Doubled: {doubled()}</p>
      <button onClick={() => setCount(count() + 1)}>+</button>
    </div>
  );
}

export default Counter;

Roznica vs React

Solid wyglada jak React, ale dziala inaczej:

  • W React komponent re-renderuje sie kazda zmiana — w Solid komponent renderuje sie raz
  • W React props to obiekt — w Solid sa reactive getterami (props.x to actually getter)
  • W React useState ma value — w Solid signal to function (count() vs count)
  • W React useMemo memo'uje — w Solid createMemo to natywny part reactivity

Reactive primitives

// Signal
const [count, setCount] = createSignal(0);
count();          // czytaj
setCount(10);     // zapisz
setCount(c => c + 1); // updater

// Memo (computed)
const doubled = createMemo(() => count() * 2);

// Effect
createEffect(() => {
  console.log(`Count is ${count()}`);
});

// Stores (reactive objects)
const [state, setState] = createStore({
  user: { name: 'Anna', age: 30 }
});
setState('user', 'name', 'Bob');

Control flow components

import { Show, For, Switch, Match } from 'solid-js';

<Show when={count() > 0} fallback={<p>Empty</p>}>
  <p>Count: {count()}</p>
</Show>

<For each={items()}>
  {(item) => <li>{item.name}</li>}
</For>

<Switch>
  <Match when={status() === 'loading'}>Ladowanie...</Match>
  <Match when={status() === 'error'}>Blad</Match>
  <Match when={status() === 'success'}>OK</Match>
</Switch>

SolidStart — meta-framework

SolidStart to dla Solid co Next.js dla React. Cechy:

  • SSR / SSG / CSR per route
  • File-based routing
  • Server functions (jak React Server Actions)
  • Streaming responses
  • Vite-based build
  • Adapters dla Vercel, Netlify, Cloudflare, Node

Kiedy wybrac SolidJS?

  • Performance jest krytyczna — gry, real-time charts, edytory
  • Polubilas/es JSX, ale chcesz lepszej reactivity
  • Aplikacja na slabe urzadzenia mobile / IoT
  • Chcesz uczyc sie nowoczesnych paradygmatow reactive
  • Mae projekty — Solid latwiejszy od React'a w niektorych aspektach

Kiedy nie?

  • Job market — pracownikow Solid prawie nie ma
  • Ekosystem — mniej bibliotek niz React
  • Wiekszy zespol — trudniej znalezc senior'a
  • Wymaganie integracji z React-only librarames

Komponenty UI

  • SolidUI — oficjalny zestaw
  • Hope UI — design system
  • Solid Aria — accessibility primitives
  • Kobalte — headless components
  • shadcn-solid — community port shadcn/ui
