Uzytkownicy i uprawnienia w Linuxie

Zarzadzanie kontami, sudo, chmod, ACL, capabilities, AppArmor

Model uzytkownikow w Linuxie

Linux to system wieloosobowy, w ktorym kazdy proces dziala w kontekscie konkretnego uzytkownika i grup. Uzytkownik root (UID=0) ma pelne uprawnienia, zwykli uzytkownicy maja UID >= 1000 (na Ubuntu). Uzytkownicy systemowi (np. www-data, sshd) maja UID < 1000 i sluza do uruchamiania uslug.

PlikZawartosc
/etc/passwdLista uzytkownikow (login, UID, GID, shell, home)
/etc/shadowZaszyfrowane hasla i polityki (tylko root)
/etc/groupLista grup i ich czlonkow
/etc/gshadowZaszyfrowane hasla grupowe
/etc/sudoersKonfiguracja uprawnien sudo

Tworzenie i usuwanie uzytkownikow

Ubuntu ma dwa podobne narzedzia: useradd (niskopoziomowe, POSIX) i adduser (interaktywny skrypt Perl, latwiejszy w uzyciu). W skryptach uzywaj useradd, w pracy interaktywnej adduser.

# useradd - niskopoziomowe (musisz pamietac o flagach)
sudo useradd -m -s /bin/bash -G sudo -c "Jan Kowalski" jkowalski
sudo passwd jkowalski

# Wyjasnienie flag:
# -m - utworz katalog domowy /home/jkowalski
# -s /bin/bash - shell domyslny
# -G sudo - dodaj do grupy sudo
# -c - komentarz (zazwyczaj pelne imie i nazwisko)

# adduser - interaktywny, pyta o haslo i dane
sudo adduser jkowalski

# Usuniecie uzytkownika
sudo userdel jkowalski            # bez katalogu domowego
sudo userdel -r jkowalski         # razem z /home/jkowalski i mailbox

# Zmiana hasla
sudo passwd jkowalski             # ustawia haslo dla uzytkownika
passwd                            # zmiana wlasnego hasla

Grupy

# Lista grup uzytkownika
groups jkowalski
id jkowalski

# Tworzenie grupy
sudo groupadd developers

# Dodanie uzytkownika do grupy (DOPISANIE - flaga -a jest kluczowa!)
sudo usermod -aG developers jkowalski

# UWAGA: usermod -G bez -a NADPISZE wszystkie grupy uzytkownika!

# Usuniecie z grupy
sudo gpasswd -d jkowalski developers

# Usuniecie grupy
sudo groupdel developers

# Po dodaniu do grupy uzytkownik musi sie wylogowac/zalogowac
# lub uzyc 'newgrp developers'

Sudo i visudo

sudo pozwala uruchamiac komendy jako inny uzytkownik (najczesciej root). Konfiguracja w /etc/sudoers oraz /etc/sudoers.d/. Nigdy nie edytuj sudoers bezposrednio - uzywaj visudo, ktory waliduje skladnie i zapobiega zablokowaniu sie.

# Edycja konfiguracji sudo
sudo visudo

# Edycja konkretnego pliku w sudoers.d
sudo visudo -f /etc/sudoers.d/myrules

# Sprawdzenie aktualnych uprawnien
sudo -l

# Uruchomienie komendy jako inny uzytkownik
sudo -u www-data ls /var/www
sudo -u postgres psql

# Powloka roota (preferuj sudo -i nad sudo su)
sudo -i

Przyklady regul w sudoers

# Skladnia: KTO MA= (JAKO_KOGO) [NOPASSWD:] CO

# Pelne uprawnienia bez hasla (niebezpieczne, ale wygodne)
jkowalski ALL=(ALL:ALL) NOPASSWD:ALL

# Konkretny user moze restartowac nginx bez hasla
deploy ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx

# Cala grupa moze zarzadzac docker
%docker ALL=(root) NOPASSWD: /usr/bin/docker

# Uzytkownik moze uruchamiac konkretne komendy
backup ALL=(root) NOPASSWD: /usr/bin/rsync, /usr/bin/tar

# Standardowy sudo (pyta o haslo)
%sudo ALL=(ALL:ALL) ALL

Uprawnienia plikow - chmod

Kazdy plik w Linuxie ma trzy klasy uprawnien: user (u), group (g), others (o). Dla kazdej klasy mozliwe sa trzy uprawnienia: read (r=4), write (w=2), execute (x=1).

LiczbowoSymbolicznieZnaczenie
700rwx------Prywatny katalog uzytkownika
755rwxr-xr-xStandardowe uprawnienia katalogu/skryptu
644rw-r--r--Standardowe uprawnienia pliku
600rw-------Tylko wlasciciel czyta i pisze (np. klucze SSH)
777rwxrwxrwxWszyscy moga wszystko (NIEBEZPIECZNE)
# Notacja liczbowa
chmod 755 script.sh
chmod 644 document.txt
chmod 600 ~/.ssh/id_ed25519

# Notacja symboliczna - precyzyjne dodawanie/odejmowanie
chmod u+x script.sh        # dodaj wykonywalnosc dla wlasciciela
chmod g-w document.txt     # zabierz zapis grupie
chmod o=r config.conf      # ustaw 'others' wylacznie na odczyt
chmod a+r public.html      # all (ugo) - dodaj odczyt dla wszystkich

# Rekursywnie
chmod -R 755 /var/www/html

# Tylko katalogi 755, tylko pliki 644 (bezpieczna kombinacja)
find /var/www -type d -exec chmod 755 {} \;
find /var/www -type f -exec chmod 644 {} \;

chown - zmiana wlasciciela

# Zmiana wlasciciela
sudo chown jkowalski file.txt

# Zmiana wlasciciela i grupy
sudo chown jkowalski:developers file.txt

# Tylko grupa
sudo chgrp developers file.txt
sudo chown :developers file.txt

# Rekursywnie
sudo chown -R www-data:www-data /var/www/html

# Skopiowanie wlascicielstwa z innego pliku
sudo chown --reference=template.txt new.txt

umask - domyslne uprawnienia

umask okresla, ktore uprawnienia sa odejmowane przy tworzeniu plikow. Domyslnie 022 - nowe pliki dostaja 644, katalogi 755.

# Sprawdzenie aktualnej umask
umask

# Ustawienie restrykcyjnej umask (pliki 600, katalogi 700)
umask 077

# Trwale ustawienie - dodaj do ~/.bashrc lub /etc/profile
echo 'umask 027' >> ~/.bashrc

Specjalne bity: SUID, SGID, sticky

BitLiczbowoSymbolicznieDzialanie
SUID4xxxu+sPlik wykonywany z uprawnieniami wlasciciela (np. /usr/bin/passwd)
SGID2xxxg+sNa pliku - jak SUID dla grupy. Na katalogu - nowe pliki dziedzicza grupe katalogu
Sticky1xxx+tTylko wlasciciel pliku moze go usunac z katalogu (jak /tmp)
# SUID - pozwala zwyklemu userowi zmienic haslo
ls -l /usr/bin/passwd
# -rwsr-xr-x 1 root root  /usr/bin/passwd (litera 's' w polu wlasciciela)

# Ustawienie SGID na katalogu zespolowym (pliki dziedzicza grupe)
sudo chmod g+s /shared/team
sudo chmod 2775 /shared/team

# Sticky bit na /tmp
ls -ld /tmp
# drwxrwxrwt 1 root root  /tmp (litera 't' na koncu)

# Wyszukanie wszystkich SUID w systemie (audyt bezpieczenstwa)
sudo find / -perm -4000 -type f 2>/dev/null

ACL - rozszerzone uprawnienia

Standardowy model "user/group/others" jest ograniczony. ACL (Access Control Lists) pozwala nadawac uprawnienia konkretnym uzytkownikom i grupom poza wlascicielem.

# Instalacja narzedzi (zazwyczaj juz jest)
sudo apt install acl

# Sprawdzenie ACL pliku
getfacl document.txt

# Nadanie uzytkownikowi prawa odczytu i zapisu
setfacl -m u:jkowalski:rw document.txt

# Nadanie grupie prawa odczytu
setfacl -m g:developers:r document.txt

# Domyslne ACL na katalogu (dziedziczone przez nowe pliki)
setfacl -d -m g:developers:rwx /shared/projects

# Usuniecie konkretnego ACL
setfacl -x u:jkowalski document.txt

# Usuniecie wszystkich ACL
setfacl -b document.txt

# Plus '+' na koncu uprawnien w ls -l oznacza obecnosc ACL
ls -l document.txt
# -rw-rw-r--+ 1 root root

Capabilities

Capabilities rozbijaja uprawnienia roota na granularne flagi. Zamiast nadawac SUID, ktory daje pelne uprawnienia roota, mozesz nadac konkretna capability. Przyklad - ping potrzebuje tylko CAP_NET_RAW, a nie pelnego roota.

# Instalacja narzedzi
sudo apt install libcap2-bin

# Sprawdzenie capabilities pliku
getcap /usr/bin/ping

# Nadanie capabilities (np. uruchamianie procesu na porcie ponizej 1024)
sudo setcap 'cap_net_bind_service=+ep' /usr/bin/node

# Po tym Node.js moze nasluchiwac na porcie 80/443 bez sudo

# Lista wszystkich capabilities
capsh --print

# Usuniecie
sudo setcap -r /usr/bin/node

AppArmor (Ubuntu)

Ubuntu uzywa AppArmor jako Mandatory Access Control. AppArmor ogranicza co kazdy program moze zrobic - ktore pliki czytac, do ktorych sieci sie laczyc. Inne dystrybucje (RHEL, Fedora) preferuja SELinux. AppArmor jest prostszy w konfiguracji.

# Status AppArmor
sudo apparmor_status

# Lista zaladowanych profili
sudo aa-status

# Tryby dzialania profilu:
# enforce - blokuje niedozwolone akcje
# complain - tylko loguje (uzyteczne do tworzenia profili)

# Przelaczenie profilu w tryb complain
sudo aa-complain /etc/apparmor.d/usr.bin.firefox

# Powrot do enforce
sudo aa-enforce /etc/apparmor.d/usr.bin.firefox

# Logi naruszen w dziennikach
sudo journalctl -k | grep apparmor
sudo dmesg | grep DENIED

passwd i chage - polityki hasel

# Wymuszenie zmiany hasla przy nastepnym logowaniu
sudo passwd -e jkowalski

# Zablokowanie konta
sudo passwd -l jkowalski
sudo usermod -L jkowalski

# Odblokowanie
sudo passwd -u jkowalski
sudo usermod -U jkowalski

# Wyswietlenie polityki haslowej
sudo chage -l jkowalski

# Ustawienie maksymalnego okresu waznosci hasla na 90 dni
sudo chage -M 90 jkowalski

# Konto wygasa za 365 dni
sudo chage -E $(date -d "+365 days" +%Y-%m-%d) jkowalski
Najlepsze praktyki bezpieczenstwa:
  • Nie loguj sie jako root - uzywaj sudo
  • Stosuj zasade najmniejszych uprawnien (least privilege)
  • Regularnie audytuj pliki SUID/SGID
  • Hasla min. 12 znakow, polityka 90 dni dla kont uprzywilejowanych
  • Uzywaj kluczy SSH zamiast hasel (ed25519)
  • Konfiguruj fail2ban przy publicznym SSH
