Architektura Transformerow

Jak dziala Transformer - self-attention, multi-head attention i pelna architektura LLM.

Dlaczego Transformer?

Przed 2017 rokiem do przetwarzania jezyka uzywano glownie RNN i LSTM - sieci, ktore przetwarzaly tekst sekwencyjnie (slowo po slowie). Mialy dwa problemy:

  1. Wolne - nie da sie ich latwo zrownoleglic
  2. Slaba pamiec dlugoterminowa - gubily kontekst w dlugich tekstach

W 2017 zespol Google opublikowal artykul "Attention is All You Need" (Vaswani et al.), ktory wprowadzil architekture Transformer. Caly wspolczesny ekosystem LLM (GPT, Claude, Llama) opiera sie na tej architekturze.

Glowna idea: Self-Attention

Self-attention pozwala kazdemu tokenowi w sekwencji "zwracac uwage" na inne tokeny i obliczac, ktore z nich sa dla niego najwazniejsze.

Przyklad intuicyjny

Zdanie: "Kot siedzi na macie, poniewaz jest ona ciepla."

Pytanie: do czego odnosi sie slowo "ona"?

Self-attention przy slowie "ona" oblicza wagi:
- "Kot"      -> 0.05
- "siedzi"   -> 0.02
- "na"       -> 0.01
- "macie"    -> 0.85   <- najwyzsza waga!
- "poniewaz" -> 0.03
- "jest"     -> 0.02
- "ciepla"   -> 0.02

Wniosek: "ona" odnosi sie do "maty"

Mechanizm Q, K, V

Self-attention dla kazdego tokenu tworzy 3 wektory:

  • Q (Query) - "czego szukam?"
  • K (Key) - "co oferuje?"
  • V (Value) - "jaka jest moja zawartosc?"
Attention(Q, K, V) = softmax(Q . K^T / sqrt(d)) . V

Krok 1: Q . K^T  - porownanie zapytan z kluczami (podobienstwo)
Krok 2: / sqrt(d)- skalowanie (stabilnosc numeryczna)
Krok 3: softmax  - normalizacja do prawdopodobienstw
Krok 4: . V      - wazona suma wartosci

Multi-Head Attention

Zamiast jednego mechanizmu attention, uzywamy wielu glow (heads) rownolegle. Kazda glowa moze uczyc sie innego rodzaju relacji:

  • Glowa 1: relacje gramatyczne (podmiot-orzeczenie)
  • Glowa 2: relacje semantyczne (zaimek-poprzednik)
  • Glowa 3: relacje pozycyjne (sasiadujace slowa)
  • ...
MultiHead(Q, K, V) = Concat(head_1, ..., head_h) . W^O

gdzie head_i = Attention(Q . W^Q_i, K . W^K_i, V . W^V_i)

Typowo 8-128 glow w jednej warstwie.

Tokenizacja

Modele nie rozumieja surowego tekstu - pracuja na tokenach.

Byte Pair Encoding (BPE)

Najpopularniejszy algorytm tokenizacji (GPT, Llama):

  1. Zacznij od pojedynczych znakow
  2. Znajdz najczestsza pare sasiadujacych tokenow
  3. Polacz w jeden token
  4. Powtarzaj az osiagniesz docelowy rozmiar slownika (np. 100k)

Przyklad

"Hello world!"
-> Tokenizer
-> ["Hello", " world", "!"]
-> [9906, 1917, 0]  (token IDs)
"Programming is fun"  ->  ["Program", "ming", " is", " fun"]
"przeprogramowanie"   ->  ["prze", "program", "owanie"]

Specjalne tokeny

  • <|begin_of_text|> - start sekwencji
  • <|end_of_text|> - koniec sekwencji
  • <|im_start|> / <|im_end|> - granice wiadomosci w czacie
  • [PAD] - padding (wyrownanie batcha)

Positional Encoding

Self-attention sam w sobie nie zna kolejnosci tokenow. Trzeba dodac informacje o pozycji.

Sinusoidal (oryginalny Transformer)

PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))

Learned Positional Embeddings

Pozycje sa wyuczonymi wektorami (jak embeddingi tokenow).

RoPE (Rotary Position Embedding) - nowoczesny standard

Uzywany w Llama, Mistral. Pozwala na lepsze generalizowanie do dluzszych kontekstow niz widziane w treningu.

ALiBi (Attention with Linear Biases)

Alternatywa do RoPE, uzywana w niektorych modelach.

Encoder vs Decoder vs Encoder-Decoder

TypPrzykladyZastosowanie
Encoder-onlyBERT, RoBERTaKlasyfikacja, NER, embeddingi
Decoder-onlyGPT, Claude, LlamaGeneracja tekstu (autoregresyjna)
Encoder-DecoderT5, BARTTlumaczenie, streszczanie

Decoder-only dominuje obecnie w LLM. Generuje tekst token po tokenie, gdzie kazdy nowy token zalezy od wszystkich poprzednich.

Causal masking

W decoderze stosuje sie maske przyczynowa - token moze patrzyc tylko na tokeny przed soba, nigdy na te po nim. To kluczowe dla generacji.

Pozycja:    1  2  3  4  5
Token 1:    1  0  0  0  0     <- widzi tylko siebie
Token 2:    1  1  0  0  0     <- widzi 1 i 2
Token 3:    1  1  1  0  0     <- widzi 1, 2, 3
Token 4:    1  1  1  1  0
Token 5:    1  1  1  1  1

Feed-Forward Network (FFN)

Kazdy blok Transformer zawiera FFN - zwykle 2-warstwowa siec:

FFN(x) = activation(x . W_1 + b_1) . W_2 + b_2

W nowoczesnych modelach (Llama, Mistral) uzywa sie SwiGLU:

SwiGLU(x) = (Swish(x . W_1) (x) (x . W_2)) . W_3

FFN ma typowo 4x wiecej parametrow niz attention. To tu "mieszka" wiekszosc wiedzy modelu.

Mixture of Experts (MoE)

Zamiast jednego duzego FFN, uzywamy wielu mniejszych "ekspertow" i routera, ktory wybiera 1-2 z nich dla kazdego tokenu.

Zalety: wiecej parametrow bez zwiekszenia kosztu inferencji.

Przyklady: Mixtral 8x7B (47B params, ale tylko 13B aktywnych), GPT-4 (podejrzewane MoE), DeepSeek V3.

Skalowanie i Scaling Laws

Chinchilla scaling laws (DeepMind, 2022): aby model osiagnal optymalna wydajnosc, musi miec:

  • ~20 tokenow treningowych na kazdy parametr

Przyklad: Llama 3 8B trenowano na ~15T tokenow (znacznie wiecej niz Chinchilla-optimal - to "over-trained" model, lepszy w inferencji).

Warstwy nowoczesnych LLM

Nowoczesne LLM (Llama 3, Claude) wprowadzily ulepszenia:

  • Pre-Layer Norm zamiast Post-Layer Norm (stabilnosc treningu)
  • RMSNorm zamiast LayerNorm (szybsze)
  • SwiGLU zamiast ReLU (lepsza jakosc)
  • RoPE zamiast sinusoidal (lepsze dlugie konteksty)
  • Grouped-Query Attention (GQA) - kompromis miedzy MHA a MQA, oszczedza pamiec
