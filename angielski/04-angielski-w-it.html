Zwroty na Code Review

Code review jest prowadzony po angielsku nawet w polskich firmach. Ważne jest, by komentarze były konkretne, uprzejme i konstruktywne.

Prośba o zmianę / sugestia
  • Could you rename this variable to make its purpose clearer? — Czy mógłbyś zmienić nazwę tej zmiennej, żeby cel był jaśniejszy?
  • I'd suggest extracting this into a separate function. — Sugerowałbym wydzielenie tego do osobnej funkcji.
  • This might cause a race condition — consider adding a lock here. — To może spowodować wyścig — rozważ dodanie blokady.
  • Nit: can we remove the trailing whitespace? — Drobiazg: usuńmy spację na końcu wiersza? (Nit = nitpick, drobiazg)
  • This logic seems duplicated — there's already a helper for this in utils.ts. — Ta logika wygląda na zduplikowaną.
Pochwalenie / zatwierdzenie
  • LGTM! — Looks Good To Me — standardowy skrót zatwierdzający PR.
  • Great approach — this is much cleaner than the previous implementation.
  • Nice refactor! This will make testing much easier.
  • Approved with minor comments — feel free to merge after addressing them.
Pytania i prośba o wyjaśnienie
  • Can you explain the reasoning behind this approach? — Czy możesz wyjaśnić motywację tej decyzji?
  • What happens if the input is null here? — Co się stanie, jeśli wejście będzie null?
  • Did you consider using X instead? — Czy rozważałeś użycie X zamiast tego?
  • Is this intentional or a typo? — Czy to zamierzone, czy literówka?

Daily Stand-up

Stand-up (daily scrum) trwa 15 minut i każdy odpowiada na trzy pytania. Oto gotowe szablony po angielsku:

I finished the API integration and opened a PR for review.
I was in the design meeting for most of the day.

What am I doing today?		 Today I'm going to work on the payment service.
I'm planning to review Alice's PR and then continue with the dashboard.
My focus today is on performance testing.

I need clarification on the requirements for ticket #423.

Pisanie commitów po angielsku

Konwencja Conventional Commits i ogólna zasada: tytuł commita w trybie rozkazującym (imperative mood), maks. 72 znaki, bez kropki na końcu.

TypKiedy używaćPrzykład
feat:Nowa funkcjonalnośćfeat: add OAuth2 login via Google
fix:Naprawa błędufix: resolve null pointer in user service
refactor:Refaktoryzacja bez zmiany funkcjirefactor: extract payment logic into service class
docs:Dokumentacjadocs: update API endpoint descriptions
test:Dodanie/poprawa testówtest: add unit tests for order repository
chore:Konfiguracja, zależności, CIchore: upgrade dependencies to latest
perf:Poprawa wydajnościperf: cache database query results
style:Formatowanie, whitespacestyle: apply linter fixes across auth module
💡 Zasada trybu rozkazującego: wyobraź sobie, że commit uzupełnia zdanie "If applied, this commit will…" — np. "…add OAuth2 login", nie ~~"added OAuth2 login"~~.
