Svelte 5 + SvelteKit

Compile-time framework — runes reactive primitives, najmniejsze bundle w branzy

Co to Svelte?

Svelte to framework JavaScript stworzony przez Rich Harris (znany z konfliktow medialnych z React community, ale geniusz w designie). Powstal w 2016, ale prawdziwie zaczela rosnac od 2019. Wyroznia sie tym, ze jest compile-time framework — runtime jest minimalny, wiekszosc pracy wykonuje compiler.

Svelte 5 (2024) wprowadzilo "runes" — nowy system reactive primitives ($state, $derived, $effect), zastepujacy magiczne let z Svelte 3/4. To znaczacy redesign, ktory zachowuje DX ale poprawia clarity.

Kluczowe cechy

  • Compile-time — bundle nie zawiera frameworka, tylko twoj kod (najmniejsze bundle)
  • SFC (Single File Components) — .svelte z <script>, <style>, markup
  • Runes (Svelte 5) — $state(), $derived(), $effect()
  • Brak Virtual DOM — precyzyjne update'y na surface DOM
  • Built-in animations — transitions, motion
  • SvelteKit — meta-framework (jak Next.js dla React)
  • TypeScript-first w Svelte 5

Instalacja

npm create svelte@latest my-app
cd my-app
npm install
npm run dev

Pierwszy komponent (Svelte 5)

<!-- App.svelte -->
<script lang="ts">
  let count = $state(0);
  let doubled = $derived(count * 2);

  $effect(() => {
    console.log(`Count changed: ${count}`);
  });

  function increment() {
    count++;
  }
</script>

<h1>Count: {count}</h1>
<p>Doubled: {doubled}</p>
<button onclick={increment}>+</button>

<style>
  button { padding: 8px 16px; }
</style>

Reactive primitives (runes)

RuneCo robi
$state(value)Reactive variable
$derived(expr)Computed (jak useMemo)
$effect(() => ...)Side effect (jak useEffect)
$props()Component props
$bindable()Two-way binding props
$inspect()Debug logging

SvelteKit — meta-framework

SvelteKit dla Svelte to to, czym Next.js dla React. Daje:

  • File-based routing
  • SSR (Server-Side Rendering)
  • SSG (Static Site Generation)
  • Form actions (mutations bez API)
  • Adapters: Vercel, Netlify, Cloudflare, Node
  • Powerfull data loading (load functions)

Svelte wygrywa pod wzgledem bundle size dramatycznie — framework "rozpuszcza sie" w czasie kompilacji.

Kiedy uzyc Svelte?

  • Performance critical (mobile, e-commerce, edge computing)
  • Mniejsze projekty — szybkie iteracje, prosta DX
  • Marketingowe sites — krytyczny LCP
  • Embedded widgets / micro-frontends — mae footprint
  • Zespol ceniacy elegancje skladniowa

Kiedy nie?

  • Wieksza spolecznosc reactowa daje wiecej guidance dla skomplikowanych problemow
  • Job market w Polsce dla Svelte jest dosc maly
  • Mniej bibliotek komponentow niz dla React

Komponenty UI

  • shadcn-svelte — port shadcn/ui na Svelte (bardzo popularny)
  • Skeleton — design system z Tailwind
  • Flowbite Svelte
  • Carbon Components Svelte — IBM design system
  • Bits UI — headless components (jak Radix)
