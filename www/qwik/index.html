Qwik / QwikCity

Resumability zamiast hydration — instant page loads, performance focused

Co to Qwik?

Qwik to framework JavaScript stworzony przez Misko Hevery (autor Angular i AngularJS), powstaly w Builder.io w 2021. Wprowadza nowy paradygmat — resumability zamiast hydration. Standardowe SSR frameworki musza re-execute caly JS w przegladarce po pobraniu HTML — w Qwik aplikacja "wstaje" gdzie skonczyla na serwerze, bez powtarzania pracy.

QwikCity to meta-framework dla Qwik — jak Next.js dla React. Daje routing, data loading, SSR, server functions.

Resumability vs hydration

Klient: HTML loadedPokazuje statyczny HTMLAplikacja juz interaktywna

TTI (Time to Interactive)Po hydrationNiemal natychmiastowy

Kluczowe cechy

  • Resumability — zero JS na pierwszy load (oprocz handlerow)
  • Lazy loading granular — kazdy event handler to lazy chunk
  • JSX — znana skladnia z React
  • Signals — useSignal(), useStore()
  • QRL (Qwik URLs) — serializowane referencje funkcji
  • Edge-friendly — latwy deployment na Cloudflare Workers
  • QwikCity — meta-framework

Pierwszy komponent

import { component$, useSignal, $ } from '@builder.io/qwik';

export const Counter = component$(() => {
  const count = useSignal(0);

  return (
    <div>
      <h1>Count: {count.value}</h1>
      <button onClick$={() => count.value++}>
        +
      </button>
    </div>
  );
});

Note dolari ($): component$, onClick$ — znak $ oznacza, ze funkcja zostanie skompilowana do osobnego lazy chunku. Trzeba o tym pamietac dla wszystkich event handlerow i komponentow.

Signals

import { useSignal, useStore, useTask$ } from '@builder.io/qwik';

const count = useSignal(0);          // primitive
const user = useStore({              // reactive object
  name: 'Anna',
  age: 30
});

useTask$(({ track }) => {
  track(() => count.value);
  console.log(`Count changed: ${count.value}`);
});

Server functions (loaders i actions)

// products/index.tsx
import { routeLoader$, routeAction$ } from '@builder.io/qwik-city';

// Server-only data loading
export const useProducts = routeLoader$(async () => {
  return await db.products.findMany();
});

// Server-only mutation
export const useCreateProduct = routeAction$(async (data) => {
  return await db.products.create({ data });
});

export default component$(() => {
  const products = useProducts();
  const action = useCreateProduct();

  return (
    <div>
      {products.value.map(p => (
        <div>{p.name}</div>
      ))}
    </div>
  );
});

Qwik wygrywa dramatycznie w time-to-interactive — idealny dla mobile sites z wolna siecia.

Kiedy wybrac Qwik?

  • Performance-critical site — e-commerce, news, marketing
  • SEO matters — perfekcyjne Lighthouse scores
  • Edge deployment — Cloudflare Workers, Vercel Edge
  • Stronaa z duza iloscia tresci, malo interakcji
  • Builder.io ekosystem (visual editor)

Kiedy nie?

  • SPA z heavy interakcja — React/Vue lepiej pasuje
  • Mae statyczne strony — Astro / 11ty wystarczy
  • Job market — bardzo malo developerow Qwik
  • Steep learning curve — trzeba zrozumiec resumability i $
  • Ekosystem mniejszy niz React

Builder.io integration

Twórcy Qwik z Builder.io oferuja visual editor pozwalajacy non-coders edytowac strony Qwik. Idealne dla landing pages, marketingowych, content-heavy sites zarzadzanych przez marketing.
