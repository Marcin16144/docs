CV i portfolio

Jak napisać CV pod systemy ATS, zbudować portfolio projektów i wypełnić profil LinkedIn

Aktualizacja: 2026-06

CV to Twój pierwszy kontakt z rekruterem — i często z systemem ATS (Applicant Tracking System), który filtruje dokumenty, zanim człowiek je zobaczy. Dobrze napisane CV w IT różni się od CV w innych branżach: jest konkretne, techniczne i nastawione na wyniki, nie na opis obowiązków.

Systemy ATS — co musisz wiedzieć

ATS (Applicant Tracking System) to oprogramowanie do zarządzania rekrutacją używane przez większość średnich i dużych firm. Skanuje CV w poszukiwaniu słów kluczowych i często odrzuca dokumenty automatycznie, zanim trafi do rąk rekrutera.

Zasady ATS-friendly CV

  • Format PDF (generowany z Worda/LaTeXa, nie ze skanowania), ewentualnie DOCX.
  • Brak tabel, kolumn, grafik, nagłówków/stopek — ATS często je ignoruje lub błędnie parsuje.
  • Prosty układ: sekcje z wyraźnymi nagłówkami tekstowymi (Doświadczenie, Wykształcenie, Umiejętności).
  • Słowa kluczowe z ogłoszenia — wklej opis stanowiska do narzędzia chmury słów, wypisz powtarzające się terminy i upewnij się, że są w Twoim CV.
  • Czcionki standardowe: Arial, Calibri, Georgia, Times New Roman. Rozmiar 10–12 pt dla treści, 14–16 pt dla imienia.
  • Unikaj skrótów nieznanych ATS: pisz JavaScript zamiast JS (lub podaj obie formy).
⚠ Kreatywne CV z infografikami i wielokolumnowym layoutem wyglądają świetnie dla człowieka, ale systemy ATS często czytają je jako ciąg losowych znaków. Użyj kreatywnego szablonu tylko wtedy, gdy masz pewność, że CV trafi bezpośrednio do człowieka (np. przez polecenie).

Struktura CV developera

Optymalna kolejność sekcji dla specjalisty IT:

1. Nagłówek

Imię i nazwisko, tytuł zawodowy (np. Senior Backend Developer | Java · Spring · AWS), e-mail, telefon, miasto, linki do GitHub/LinkedIn/portfolio. Bez zdjęcia (w IT nie jest potrzebne, może wprowadzać bias).

Jan Kowalski · Senior Backend Developer · jan@example.com · GitHub: github.com/jkowalski · LinkedIn: linkedin.com/in/jkowalski

2. Podsumowanie zawodowe (opcjonalne, ale skuteczne)

3–5 zdań: kim jesteś, ile masz doświadczenia, co potrafisz najlepiej i czego szukasz. Pisz w pierwszej osobie, konkretnie.

Backend developer z 6-letnim doświadczeniem w Java/Spring. Specjalizuję się w systemach mikroserwisowych na AWS — zredukowałem czas odpowiedzi API o 40% w poprzedniej roli. Szukam projektu w skali co najmniej miliona użytkowników.

3. Doświadczenie zawodowe (chronologicznie od najnowszego)

Nazwa firmy, stanowisko, daty (MM/RRRR). Dla każdej roli: 3–6 punktów osiągnięć (nie obowiązków) w formule Zrobiłem X, co dało Y (mierzalny wynik) za pomocą Z (technologia/metoda).

· Zrefaktoryzowałem moduł płatności (Java/Spring), skracając czas przetwarzania z 800ms do 120ms (–85%). · Wdrożyłem monitoring (Prometheus + Grafana) dla 12 mikroserwisów, co skróciło MTTR z 4h do 45min.

4. Umiejętności techniczne

Pogrupowane kategorie: Języki, Frameworki, Bazy danych, Chmura, Narzędzia, Metodyki. Nie oceniaj się gwiazdkami — są subiektywne i bezużyteczne dla ATS.

Języki: Java, Python, SQL | Frameworki: Spring Boot, FastAPI | Bazy: PostgreSQL, Redis, Elasticsearch | Chmura: AWS (EC2, RDS, Lambda, S3) | Narzędzia: Docker, Kubernetes, Terraform, GitHub Actions

5. Wykształcenie

Uczelnia, kierunek, lata. Jeśli masz ponad 2 lata doświadczenia — ta sekcja jest mniej ważna niż projekty. Dyplom informatyki to plus, ale brak go nie dyskwalifikuje.

6. Projekty (portfolio)

2–4 najważniejsze projekty z krótkim opisem, stosem technologicznym i linkiem do kodu lub demo. To często ważniejsze niż wykształcenie!

7. Certyfikaty i kursy

AWS Certified Solutions Architect, Azure AZ-900/204, Google Cloud, CKA, certyfikaty Scrum/PMP jeśli relewantne. Podaj rok uzyskania.

Portfolio projektów

Portfolio to Twój dowód kompetencji — ważniejszy niż dyplom dla wielu pracodawców. Nie musisz mieć 20 projektów; 3–4 solidne, ukończone projekty są znacznie lepsze niż 20 repozytoriów z jednym commitem.

Co pokazać w portfolio

  • Realne aplikacje — coś działającego online (Vercel, Railway, Render, AWS Free Tier), nie tylko kod na GitHubie.
  • Różnorodność — projekt z REST API, projekt z frontendem, może coś z bazą danych lub ML.
  • README — każde repozytorium powinno mieć czytelne README z opisem projektu, stackiem, instrukcją uruchomienia i zrzutami ekranu.
  • Testy — przynajmniej kilka testów jednostkowych/integracyjnych pokazuje profesjonalizm.
  • Commit history — regularne commity (nie "initial commit" + "fixed all bugs") pokazują rzeczywisty proces pracy.
✅ Brak pomysłu na projekt? Zrób klon popularnej aplikacji (Trello, Reddit, Booking.com) z własnym twistem lub dodaj nową funkcjonalność do istniejącego open source projektu. Kontrybucje do OSS są bardzo dobrze odbierane przez rekruterów technicznych.

Profil GitHub

Profil GitHub to rozszerzenie CV. Rekruterzy techniczni i programiści prowadzący rozmowę często go sprawdzają.

Co zrobić

  • Wypełnij bio z tytułem zawodowym i e-mailem kontaktowym
  • Przypnij (pin) 4–6 najlepszych repozytoriów na profilu
  • Dodaj GitHub README (plik README.md w repozytorium o tej samej nazwie co login)
  • Regularne commity budują "zielony trawnik" — widoczny sygnał aktywności
  • Opisuj repozytoria (topic tags: #python, #api, #react)

Czego unikać

  • Repozytoriów bez README lub z pustymi plikami
  • Commitowania do cudzych forków (wygląda jak własna praca, a nie jest)
  • Commitów stylu "fix", "asdf", "test123" bez kontekstu
  • Kodu bez żadnych testów i bez struktury
  • Prywatnych repozytoriów jako głównego dowodu pracy (rekruter ich nie zobaczy)

List motywacyjny

W polskim IT list motywacyjny jest często opcjonalny — większość ogłoszeń go nie wymaga. Jeśli jednak pracodawca go prosi, napisz go porządnie — to szansa na wyróżnienie się.

Struktura skutecznego listu

  1. Akapit 1 — dlaczego ta firma? Wymień konkretny produkt, technologię lub wartość firmy, które Cię przyciągnęły. Nie pisz "zawsze chciałem pracować w dynamicznym środowisku".
  2. Akapit 2 — co wnosisz? 2–3 konkretne osiągnięcia z przeszłości powiązane z wymaganiami stanowiska.
  3. Akapit 3 — jak pasujesz? Pokaż, że rozumiesz rolę i jak Twoje kompetencje rozwiązują problem firmy.
  4. Zakończenie — CTA. Krótko: "Chętnie opowiem więcej podczas rozmowy" + podpis.
⚠ Nie generuj listu motywacyjnego wyłącznie przez ChatGPT bez edycji — rekruterzy rozpoznają szablonowy styl AI. Użyj AI jako punktu wyjścia, ale nadaj mu własny głos i konkretne fakty ze swojego doświadczenia.
