Bezpieczenstwo aplikacji C++

Memory safety, RAII, smart pointers, std::span, sanitizers, CFI, hardening flags, MISRA C++.

Memory safety - dlaczego C++ jest zagrozeniem

Statystyki Microsoftu i Google: ~70% wszystkich CVE w przegladarkach, jadrach systemow operacyjnych i aplikacjach C/C++ to bledy memory safety. Wiekszosc ich wynika z:

  • Use-after-free — uzycie wskaznika po zwolnieniu pamieci
  • Buffer overflow — zapis poza tablica/buforem
  • Double-free — dwukrotne zwolnienie tej samej pamieci
  • Out-of-bounds read/write — dostep poza granicami
  • Wild/dangling pointers — wskazniki do usunietej pamieci
  • Uninitialized reads — odczyt niezainicjalizowanej pamieci
  • Type confusion — reinterpret_cast bledne

RAII - zlota zasada

RAII jest jednym z najwazniejszych mechanizmow obrony przed memory bugs. Kazdy zasob (memory, file, mutex, socket) ma swojego "wlasciciela" - obiekt RAII zarzadza jego zyciem.

// ZLE - reczny memory management
void process() {
    auto* buffer = new char[1024];
    if (errorCondition()) {
        return;     // LEAK!
    }
    // ... uzycie
    delete[] buffer;
}

// DOBRZE - RAII
void process() {
    std::vector<char> buffer(1024);
    if (errorCondition()) {
        return;     // OK - vector destruktor zwolni pamiec
    }
}

Smart pointers - zamiast new/delete

Smart pointerSemantykaKiedy uzyc
std::unique_ptr<T>Wylaczna wlasnoscDomyslny wybor — jeden wlasciciel

// unique_ptr - z make_unique (C++14+)
auto sock = std::make_unique<Socket>("localhost", 8080);
sock->send("data");
// Automatyczne zamkniecie na koncu zakresu

// Move semantics - przekazywanie wlasnosci
auto inny = std::move(sock);  // sock teraz pusty
assert(sock == nullptr);

// shared_ptr - dla DAG, drzew
auto root = std::make_shared<Node>();
auto child = root->addChild();
// Refcount automatyczny

// weak_ptr - parent <-> child cycle
class Node {
    std::weak_ptr<Node> parent;     // weak - zapobiega cyklom
    std::vector<std::shared_ptr<Node>> children;
};

std::span - bezpieczne widoki na bufory (C++20)

span eliminuje "passing pointer + size" antywzorzec.

#include <span>

// ZLE - latwo o blad
void process(int* data, size_t size);

// DOBRZE - std::span
void process(std::span<int> data) {
    for (auto& x : data) {  // safe iteration
        x *= 2;
    }
    auto pierwszy = data.front();
    auto ostatni = data.back();
    auto kawalek = data.subspan(0, 10);  // bezpieczne wycieczki
}

// Wywolanie
std::vector<int> v = {1, 2, 3, 4, 5};
process(v);                              // OK
int arr[] = {1, 2, 3};
process(arr);                            // OK
process(std::span(v).subspan(1, 3));     // OK

Hardening flags - kompilacja

Flagi kompilatora znaczaco redukuja powierzchnie ataku:

# GCC/Clang - production hardening
-D_FORTIFY_SOURCE=3            # Runtime checks str/mem fns (FORTIFY_SOURCE=3 GCC 12+)
-fstack-protector-strong       # Stack canaries
-fstack-clash-protection        # Stack overflow detection
-fcf-protection=full            # Control Flow Integrity (Intel CET)
-D_GLIBCXX_ASSERTIONS           # libstdc++ assertions
-Wformat -Wformat-security      # printf format strings
-Wl,-z,relro,-z,now             # Read-only relocations
-Wl,-z,noexecstack              # No exec on stack
-fPIE -pie                      # Position Independent Executable
-fsanitize=cfi                  # Control Flow Integrity (Clang)

# CMake przyklad
target_compile_options(myapp PRIVATE
    -D_FORTIFY_SOURCE=3
    -fstack-protector-strong
    -fcf-protection=full
    -Wformat=2
    -Wformat-security
)
target_link_options(myapp PRIVATE
    -Wl,-z,relro,-z,now,-z,noexecstack
)

CFI - Control Flow Integrity

CFI to ochrona przed ROP/JOP atakami — weryfikuje, ze kazdy indirect call/jump idzie do legitnego celu. Clang ma najlepsze CFI w open-source.

// LLVM CFI
clang++ -flto -fvisibility=hidden \
        -fsanitize=cfi \
        -fsanitize-trap=cfi \
        main.cpp

// Wymaga LTO (Link Time Optimization) i hidden visibility

Sanitizers w runtime testach

# Use-after-free demo
#include <cstring>
int main() {
    char* buf = new char[10];
    delete[] buf;
    std::strcpy(buf, "AAAA");   // UAF!
    return 0;
}

# Kompilacja z ASan
clang++ -fsanitize=address -g main.cpp
./a.out

# Output:
# ==12345==ERROR: AddressSanitizer: heap-use-after-free
#   READ of size 1 at 0x60200000eff0
#   ...

# UBSan - integer overflow, null deref
clang++ -fsanitize=undefined main.cpp

# TSan - data races
clang++ -fsanitize=thread main.cpp

Static analysis - kompilator

# GCC -fanalyzer
g++ -fanalyzer -Wall -Wextra main.cpp

# Wykrywa: NULL deref, double-free, leak, infinite loop

# Clang static analyzer
clang++ --analyze main.cpp

# clang-tidy - dziesiatki check'ow
clang-tidy main.cpp -checks='-*,clang-analyzer-*,bugprone-*,cert-*'

Konkretne wzorce

Integer overflow

// ZLE - mozliwy overflow
int a, b;
int sum = a + b;

// DOBRZE - sprawdz przed
if (b > std::numeric_limits<int>::max() - a) {
    throw std::overflow_error("overflow");
}
int sum = a + b;

// LEPSZE - C++26 std::add_sat (saturated)
auto sum = std::add_sat(a, b);

// Built-ins (GCC/Clang)
int sum;
if (__builtin_add_overflow(a, b, &sum)) {
    // overflow!
}

String handling - bezpieczne

// ZLE - C-style
char buf[100];
strcpy(buf, source);            // moze przekroczyc
sprintf(buf, "%s", source);     // moze przekroczyc
gets(buf);                       // BARDZO ZLE - DEPRECATED

// DOBRZE - C++
std::string buf = source;
std::string formatted = std::format("{}", source);
std::string line;
std::getline(std::cin, line);

// Jesli C string konieczny:
strncpy_s(buf, sizeof(buf), source, _TRUNCATE);  // Windows
strlcpy(buf, source, sizeof(buf));                // BSD/Linux

Memory safety checklist

  • Uzywaj smart pointers, nie new/delete recznie
  • RAII dla wszystkich zasobow
  • std::vector / std::string / std::array zamiast surowych tablic
  • std::span zamiast pointer+size
  • .at() lub bounds-checked indexing
  • Hardening flags w produkcji
  • ASan + UBSan w CI debug
  • Fuzz testing dla parsers/network code
  • clang-tidy + clang-analyzer w pre-commit
