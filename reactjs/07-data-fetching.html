Data fetching

Tanstack Query, SWR, Server Components i Suspense

Co to znaczy "server state"?

Server state roznia sie od client state:

  • Trzymany na serwerze, klient ma cache — nie zrodlo prawdy
  • Moze sie zmienic bez wiedzy klienta — wymaga refetch/invalidation
  • Asynchroniczny — loading/error states
  • Wiele uzytkownikow moze go widziec/zmieniac

Nie traktuj go jako lokalnego state w Redux/Zustand — uzyj Tanstack Query lub SWR.

Tanstack Query (#1 w 2026)

Tanstack Query (dawniej React Query) to standardowy wybor. Cache, deduplication, background refetch, optimistic updates, infinite scroll.

# Instalacja
npm i @tanstack/react-query @tanstack/react-query-devtools

// main.tsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { ReactQueryDevtools } from '@tanstack/react-query-devtools';

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60_000,           // dane "swieze" przez 60s
      gcTime: 5 * 60_000,          // cache zywy 5 min
      refetchOnWindowFocus: true,  // refetch gdy okno znow ma focus
      retry: 2,                    // 2 retry przy bledzie
    },
  },
});

createRoot(document.getElementById('root')).render(
  <QueryClientProvider client={queryClient}>
    <App />
    <ReactQueryDevtools />
  </QueryClientProvider>
);

useQuery — pobieranie danych

import { useQuery } from '@tanstack/react-query';

function Posts() {
  const { data, isPending, error, isFetching, refetch } = useQuery({
    queryKey: ['posts'],
    queryFn: async () => {
      const r = await fetch('/api/posts');
      if (!r.ok) throw new Error('Blad ' + r.status);
      return r.json();
    },
  });

  if (isPending) return <p>Ladowanie...</p>;
  if (error) return <p>Blad: {error.message}</p>;

  return (
    <>
      {isFetching && <span>Odswiezam...</span>}
      <ul>{data.map(p => <li key={p.id}>{p.title}</li>)}</ul>
      <button onClick={() => refetch()}>Refresh</button>
    </>
  );
}

// Z parametrem
function Post({ id }) {
  const { data } = useQuery({
    queryKey: ['post', id],
    queryFn: () => fetch(`/api/posts/${id}`).then(r => r.json()),
    enabled: !!id, // nie odpalaj jesli id falsy
  });
  return data ? <h1>{data.title}</h1> : null;
}

useMutation — zmiana danych

import { useMutation, useQueryClient } from '@tanstack/react-query';

function NewPost() {
  const qc = useQueryClient();

  const mutation = useMutation({
    mutationFn: (post) => fetch('/api/posts', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(post),
    }).then(r => r.json()),

    onSuccess: () => {
      qc.invalidateQueries({ queryKey: ['posts'] }); // refetch listy
    },
    onError: (err) => {
      console.error('Blad:', err);
    },
  });

  return (
    <button
      onClick={() => mutation.mutate({ title: 'Nowy post' })}
      disabled={mutation.isPending}
    >
      {mutation.isPending ? 'Tworze...' : 'Utworz'}
    </button>
  );
}

Optimistic updates

const mutation = useMutation({
  mutationFn: updateTodo,
  onMutate: async (newTodo) => {
    await qc.cancelQueries({ queryKey: ['todos'] });
    const prev = qc.getQueryData(['todos']);
    qc.setQueryData(['todos'], (old) =>
      old.map(t => t.id === newTodo.id ? newTodo : t)
    );
    return { prev };
  },
  onError: (err, _newTodo, ctx) => qc.setQueryData(['todos'], ctx.prev),
  onSettled: () => qc.invalidateQueries({ queryKey: ['todos'] }),
});

Infinite Query

import { useInfiniteQuery } from '@tanstack/react-query';

const { data, fetchNextPage, hasNextPage, isFetchingNextPage } = useInfiniteQuery({
  queryKey: ['posts'],
  queryFn: ({ pageParam }) => fetch(`/api/posts?cursor=${pageParam}`).then(r => r.json()),
  initialPageParam: 0,
  getNextPageParam: (last) => last.nextCursor,
});

// Render
{data.pages.flatMap(p => p.items).map(item => ...)}
{hasNextPage && (
  <button onClick={() => fetchNextPage()} disabled={isFetchingNextPage}>
    Wiecej
  </button>
)}

SWR — alternatywa od Vercel

SWR ("stale-while-revalidate") — lekka biblioteka. Mniejsza, prostsza, mniej feature'ow niz Tanstack Query.

npm i swr

import useSWR from 'swr';

const fetcher = (url) => fetch(url).then(r => r.json());

function Profile() {
  const { data, error, isLoading, mutate } = useSWR('/api/user', fetcher);
  if (error) return <p>Blad</p>;
  if (isLoading) return <p>...</p>;
  return <h1>{data.name}</h1>;
}

Server Components — data fetching na serwerze

W Next.js App Router (React 19) komponenty serwerowe sa async. Pobieranie bezposrednio bez useEffect ani Tanstack Query.

// app/posts/page.jsx (Server Component)
async function getPosts() {
  const r = await fetch('https://api.example.com/posts', {
    next: { revalidate: 60 }, // ISR — cache na 60s
  });
  return r.json();
}

export default async function PostsPage() {
  const posts = await getPosts();
  return (
    <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>
  );
}

Suspense for Data

Suspense pozwala "zaczekac" na dane bez recznej obslugi loading state. Dziala z RSC i z use().

import { Suspense } from 'react';

export default function Page() {
  return (
    <>
      <h1>Strona</h1>
      <Suspense fallback={<p>Ladowanie postow...</p>}>
        <Posts />
      </Suspense>
      <Suspense fallback={<p>Ladowanie komentarzy...</p>}>
        <Comments />
      </Suspense>
    </>
  );
}

// Posts moze byc async server component — Suspense automatycznie zlapie

use() z promise

import { use } from 'react';

function PostList({ postsPromise }) {
  const posts = use(postsPromise);
  return <ul>...</ul>;
}

export default function Page() {
  const postsPromise = fetch('/api/posts').then(r => r.json());
  return (
    <Suspense fallback={<p>...</p>}>
      <PostList postsPromise={postsPromise} />
    </Suspense>
  );
}

Error Boundaries

React nie lapie domyslnie bledow z renderu. Trzeba uzyc Error Boundary (klasa lub biblioteka jak react-error-boundary).

import { ErrorBoundary } from 'react-error-boundary';

function ErrorFallback({ error, resetErrorBoundary }) {
  return (
    <div role="alert">
      <p>Cos poszlo nie tak: {error.message}</p>
      <button onClick={resetErrorBoundary}>Sprobuj ponownie</button>
    </div>
  );
}

<ErrorBoundary FallbackComponent={ErrorFallback}>
  <Suspense fallback={<Spinner />}>
    <Posts />
  </Suspense>
</ErrorBoundary>
