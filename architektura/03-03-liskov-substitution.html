Liskov Substitution Principle (LSP)

Obiekty klasy bazowej musza byc bezpiecznie zastepowalne obiektami klas pochodnych.

Czym jest LSP?

Zasada podstawienia Liskov (Barbara Liskov, 1987): jezeli S jest podtypem T, to obiekty typu T moga byc zastapione obiektami typu S bez zmiany pozadanych wlasciwosci programu. Kod kliencki nie powinien wiedziec ani dbac, czy pracuje z obiektem bazowym czy pochodnym.

Design by Contract

  • Warunki wstepne (preconditions) — klasa pochodna nie moze ich zaostrzac
  • Warunki koncowe (postconditions) — klasa pochodna nie moze ich oslabiac
  • Niezmienniki (invariants) — klasa pochodna musi je zachowywac

Klasyczny problem: Prostokat i Kwadrat

Zle — Kwadrat lamie kontrakt Prostokata

class Rectangle {
    protected width: number;
    protected height: number;

    setWidth(w: number): void { this.width = w; }
    setHeight(h: number): void { this.height = h; }
    getArea(): number { return this.width * this.height; }
}

class Square extends Rectangle {
    setWidth(w: number): void {
        this.width = w;
        this.height = w; // wymusza kwadrat
    }
    setHeight(h: number): void {
        this.width = h;  // wymusza kwadrat
        this.height = h;
    }
}

function resizeAndCheck(rect: Rectangle): void {
    rect.setWidth(5);
    rect.setHeight(4);
    console.assert(rect.getArea() === 20);
    // Rectangle: 5 * 4 = 20  — OK
    // Square:    4 * 4 = 16  — NARUSZENIE LSP!
}

Dobrze — wspolny interfejs tylko do odczytu

interface Shape {
    getArea(): number;
}

class Rectangle implements Shape {
    constructor(
        private width: number,
        private height: number
    ) {}
    getArea(): number { return this.width * this.height; }
    withWidth(w: number): Rectangle {
        return new Rectangle(w, this.height);
    }
    withHeight(h: number): Rectangle {
        return new Rectangle(this.width, h);
    }
}

class Square implements Shape {
    constructor(private side: number) {}
    getArea(): number { return this.side * this.side; }
    withSide(s: number): Square {
        return new Square(s);
    }
}

// Kod kliencki operuje na Shape — bezpiecznie
function printArea(shape: Shape): void {
    console.log(`Pole: ${shape.getArea()}`);
}

Przyklad 2: Storage z ograniczeniami

Zle — ReadOnly rzuca wyjatki w odziedziczonych metodach

class FileStorage:
    def read(self, path): ...
    def write(self, path, data): ...
    def delete(self, path): ...

class ReadOnlyStorage(FileStorage):
    def write(self, path, data):
        raise PermissionError("Zapis niedozwolony")  # BOOM!
    def delete(self, path):
        raise PermissionError("Usuwanie niedozwolone")  # BOOM!

def backup_files(storage: FileStorage, files):
    for f in files:
        data = storage.read(f)
        storage.write(f + '.bak', data)  # NARUSZENIE LSP!

Dobrze — segregacja interfejsow

from abc import ABC, abstractmethod

class ReadableStorage(ABC):
    @abstractmethod
    def read(self, path: str) -> bytes: pass

class WritableStorage(ABC):
    @abstractmethod
    def write(self, path: str, data: bytes): pass

class FileStorage(ReadableStorage, WritableStorage):
    def read(self, path):
        with open(path, 'rb') as f: return f.read()
    def write(self, path, data):
        with open(path, 'wb') as f: f.write(data)

class ReadOnlyFileStorage(ReadableStorage):
    def read(self, path):
        with open(path, 'rb') as f: return f.read()

# Funkcja wymaga tylko tego, czego potrzebuje
def backup_files(source: ReadableStorage,
                 target: WritableStorage, files):
    for f in files:
        data = source.read(f)
        target.write(f + '.bak', data)

Przyklad 3: Zaostrzanie warunkow wstepnych

Zle — podklasa dodaje nieoczekiwany limit

class PaymentProcessor {
    process(amount: number): Receipt {
        if (amount <= 0) throw new Error("Kwota dodatnia");
        return new Receipt(amount);
    }
}

class LimitedPaymentProcessor extends PaymentProcessor {
    process(amount: number): Receipt {
        if (amount > 1000)
            throw new Error("Limit!"); // ZAOSTRZENIE!
        return super.process(amount);
    }
}

Dobrze — limit jest czescia kontraktu

interface PaymentProcessor {
    process(amount: number): Receipt;
    getLimit(): number | null;
}

class StandardProcessor implements PaymentProcessor {
    process(amount: number): Receipt {
        if (amount <= 0) throw new Error("Kwota dodatnia");
        return new Receipt(amount);
    }
    getLimit(): null { return null; }
}

class LimitedProcessor implements PaymentProcessor {
    constructor(private limit: number) {}

    process(amount: number): Receipt {
        if (amount <= 0) throw new Error("Kwota dodatnia");
        if (amount > this.limit)
            throw new LimitExceededError(amount, this.limit);
        return new Receipt(amount);
    }
    getLimit(): number { return this.limit; }
}

// Klient swiadomie sprawdza limit
function chargeCustomer(proc: PaymentProcessor, amount: number) {
    const limit = proc.getLimit();
    if (limit !== null && amount > limit) {
        return splitPayment(proc, amount, limit);
    }
    return proc.process(amount);
}

Testowanie zgodnosci z LSP

# Testy kontraktowe — dzialaja dla KAZDEJ implementacji

class ShapeContractTests:
    """Kazda implementacja Shape musi przejsc te testy."""

    def test_area_is_non_negative(self, shape):
        assert shape.get_area() >= 0

    def test_area_is_deterministic(self, shape):
        assert shape.get_area() == shape.get_area()


class TestRectangle(ShapeContractTests):
    @pytest.fixture
    def shape(self):
        return Rectangle(5, 4)

    def test_area_calculation(self, shape):
        assert shape.get_area() == 20


class TestCircle(ShapeContractTests):
    @pytest.fixture
    def shape(self):
        return Circle(3)

    def test_area_calculation(self, shape):
        assert abs(shape.get_area() - 28.274) < 0.01
