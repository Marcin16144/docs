Balansowanie wymagan

Jak godzic wymagania funkcjonalne z niefunkcjonalnymi, gdy sie wzajemnie wykluczaja.

Wymagania funkcjonalne vs niefunkcjonalne

Funkcjonalne (FR) — co system robi

  • Uzytkownik moze zlozyc zamowienie
  • System wysyla potwierdzenie e-mail
  • Administrator generuje raport sprzedazy

Niefunkcjonalne (NFR) — jak system dziala

  • Strona laduje sie < 2s (wydajnosc)
  • 10 000 rownoczesnych uzytkownikow (skalowalnosc)
  • Dostepnosc 99.9% (niezawodnosc)
  • Szyfrowanie AES-256 (bezpieczenstwo)

Dlaczego balansowanie jest trudne?

Bezpieczenstwo  ←——→  Wygoda uzytkowania
Wydajnosc       ←——→  Spojnosc danych
Elastycznosc    ←——→  Prostota

2. Quality Attribute Scenarios

Zrodlo:      Uzytkownik
Bodziec:     Klika "Zloz zamowienie"
Artefakt:    Serwis zamowien
Srodowisko:  Normalne obciazenie (1000 req/s)
Odpowiedz:   Zamowienie przetworzone
Miara:       < 500ms w 99% przypadkow (p99)

3. Fitness Functions

Automatyczne testy weryfikujace atrybuty jakosciowe:

// Fitness function — wydajnosc
test("API < 200ms at p95", async () => {
    const results = await loadTest({
        url: "/api/orders",
        duration: "60s", rate: 1000
    });
    expect(results.p95).toBeLessThan(200);
});

// Fitness function — modularnosc
test("No circular deps", () => {
    const deps = analyzeModuleDependencies();
    expect(deps.circular).toHaveLength(0);
});
